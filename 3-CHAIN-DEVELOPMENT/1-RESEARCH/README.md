# 链路1 · 调研分析链（D系列）

> **定位**: 回答"问题是什么、为什么、有什么方案、选哪个"
> **出口**: 一份经过用户批准的 Spec 文档
> **方法论来源**: A1 三角准则 + A0 矛盾论 + A2 第一性原理 + A3 推演验证

---

## 接力流程

```
用户需求
    ↓
D1 深度调研 ─────────────────────────── 产出: 现状调查报告
官方身份: 调查官                            ↓ ❌ 用户确认调研OK
工具: read_file, search_files, web       ↓
                                        ↓
D2 分析诊断 ─────────────────────────── 产出: 根因分析与方案矩阵
官方身份: 分析师                            ↓ ❌ 用户确认分析方向
工具: read_file, write_file(.md)         ↓
                                        ↓
D3 推演验证 ─────────────────────────── 产出: 多方案推演报告
官方身份: 推演师                            ↓ ❌ 用户选择方案
工具: read_file, write_file(.md)         ↓
                                        ↓
D4 Spec合成 ─────────────────────────── 产出: 完整Spec文档
官方身份: 作者                              ↓ ❌ 用户批准Spec → 链路2
工具: read_file, write_file(.md)
```

---

## 何时不用全链

| 场景 | 启动什么 |
|:---|---|
| "这段代码有什么问题" | 只掉 D2（分析诊断） |
| "有没有现成的方案" | 只掉 D1（深度调研） |
| "帮我评估两种方案" | 只掉 D3（推演验证） |
| "把我的调研写成Spec" | 只掉 D4（Spec合成） |

## 何时用全链

| 场景 | 说明 |
|:---|---|
| 新功能设计 | 用户只说需求，让AI从调研到方案全链路 |
| 重大问题修复 | 需要先调查根因再设计方案 |
| 架构变更 | 影响面大，需要完整分析和推演 |
