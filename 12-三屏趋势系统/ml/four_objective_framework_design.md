# 四类目的 + 动态实践闭环 — 框架设计

> **版本**: v2.0 | **创建日期**: 2026-07-18 | **更新日期**: 2026-07-18
> **状态**: Phase 1-2 完成，Phase 3 进行中
> **基线**: V4减半周期逃顶策略（HalvingTopExitStrategy）
> **核心思想**: 理论指导 → 算法实现 → 回测验证 → 基线锚定 → 反馈修正理论
> **版本演进**: v1.0（基线V2）→ v2.0（基线升级为V4）

---

## 1. 背景与问题

### 1.1 现状

当前三屏趋势系统的特征和算法体系：
- **特征分类**：按来源分为三个管道（价格特征/阻力特征/集成推理）
- **标签定义**：单一二分类（未来N日涨跌）
- **回测方式**：全周期统一指标对比 + 分场景评估
- **基线策略**：V4减半周期逃顶（综合评分1.592，总收益1440%）
- **四类目的框架**：已搭建（DIP_BUY/TOP_EXIT/BEAR_SHORT/BEAR_EXIT）
- **闭环管理**：已实现（closed_loop_manager.py）

### 1.2 核心问题

1. **特征组织问题**：按来源组织特征，不便于针对性优化
   - 不知道哪些特征对"抄底"有效，哪些对"逃顶"有效
   - 全周期平均指标掩盖了特定场景下的特征价值

2. **标签粒度问题**：单一涨跌标签过于粗糙
   - 抄底、逃顶、做空、空平是四类完全不同的决策
   - 每类决策的最优特征集可能差异很大

3. **闭环缺失问题**：理论→算法→回测→基线之间缺少结构化迭代链路
   - 改进缺乏理论假设驱动，容易变成瞎试
   - 回测结果不能有效反哺理论和特征设计

### 1.3 设计目标

构建"**四类目的 + 动态实践闭环**"框架：
- 按交易目的（抄底/离场/做空/空平）组织特征和评估
- 建立理论假设 → 算法实现 → 回测验证 → 基线锚定的完整闭环
- 所有优化以v2增强版MA200为基线，不优则回退

## 2. 四类目的框架

### 2.1 四类目的定义

交易周期中存在四个关键决策点，每类决策有不同的特征需求和优化目标：

```
    熊市底部          牛市顶部          熊市顶部          熊市底部
  (抄底买入)   →    (逃顶卖出)   →    (做空开仓)   →    (做空平仓)
       │                │                  │                  │
       ▼                ▼                  ▼                  ▼
  ┌─────────┐      ┌─────────┐        ┌─────────┐      ┌─────────┐
  │ 目的1:   │      │ 目的2:   │        │ 目的3:   │      │ 目的4:   │
  │ DIP_BUY │      │ TOP_EXIT│        │BEAR_SHORT│      │BEAR_EXIT│
  │ 牛市抄底 │      │ 牛市离场 │        │ 熊市做空 │      │ 熊市空平 │
  └─────────┘      └─────────┘        └─────────┘      └─────────┘
```

### 2.2 四类目的详细定义

#### 目的1：DIP_BUY（牛市抄底）

| 维度 | 定义 |
|------|------|
| **场景** | 价格接近/跌破周线MA200，左侧或右侧底部区域 |
| **核心问题** | 现在是不是底部？该不该买？买多少？ |
| **标签定义** | 未来20日涨幅 > 15% 且期间最大回撤 < 10% → 1（优质抄底点） |
| **优化目标** | 更早识别底部、更高收益风险比、更低假阳性 |
| **基线参考** | v2策略周线MA200抄底4层触发点（跌破0%/5%/10%/15%） |
| **关键特征群** | MA200距离、抄底档位、左侧信号强度、双牛确认、量价背离 |

#### 目的2：TOP_EXIT（牛市离场）

| 维度 | 定义 |
|------|------|
| **场景** | 牛市末期/头部区域，趋势衰竭，即将转熊 |
| **核心问题** | 现在是不是顶部？该不该卖？卖多少？ |
| **标签定义** | 未来20日跌幅 > 15% 或期间最大回撤 > 20% → 1（优质逃顶点） |
| **优化目标** | 更早在顶部离场、减少利润回吐、避免假摔误判 |
| **基线参考** | v2策略MA200跌破 + 5日斜率转负（离场/转空信号） |
| **关键特征群** | 趋势衰竭、顶背离、量价不配合、超买程度、波动率扩张 |

#### 目的3：BEAR_SHORT（熊市做空）

| 维度 | 定义 |
|------|------|
| **场景** | 跌破MA200，下跌趋势确认，顺势做空 |
| **核心问题** | 下跌趋势确认了吗？该不该空？空多少？ |
| **标签定义** | 未来10日跌幅 > 10% 且期间反弹 < 5% → 1（优质做空点） |
| **优化目标** | 更早识别下跌趋势、更准的做空入场点、更低假突破风险 |
| **基线参考** | v2策略跌破MA200 + 5日斜率负 → 5成仓做空 |
| **关键特征群** | MA200斜率、下跌动能、反弹力度、熊市确认度、BTC/小币分化 |

#### 目的4：BEAR_EXIT（熊市空平）

| 维度 | 定义 |
|------|------|
| **场景** | 熊市末期/底部区域，下跌衰竭，空头止盈离场 |
| **核心问题** | 下跌是不是快结束了？该不该平空？平多少？ |
| **标签定义** | 未来10日反弹 > 10% 或 跌幅连续收窄 → 1（优质空平点） |
| **优化目标** | 更早平空、避免反弹回吐、保留下跌趋势中的利润 |
| **基线参考** | v2策略斐波那契止盈最后一档（61.8%全部平仓） |
| **关键特征群** | 底背离、下跌衰竭、量能萎缩、超卖程度、支撑位强度 |

## 3. 动态实践闭环架构

### 3.1 四层闭环模型

```
┌─────────────────────────────────────────────────────────────────────┐
│                     第一层：理论层 (Theory Layer)                     │
│                                                                     │
│  来源：交易经验、经典理论、哲学洞察、市场观察                         │
│  输出：可验证的假设 (Hypothesis)                                     │
│                                                                     │
│  理论库：                                                           │
│    ├─ 三重滤网理论 (Elder-ray)                                       │
│    ├─ 最小阻力方向理论 (五维阻力融合)                                 │
│    ├─ MA200牛熊经验法则 (v2基线)                                     │
│    ├─ 斐波那契止盈理论                                               │
│    ├─ 比特币减半周期理论 (V4新增：减半后18月见顶)                     │
│    └─ 七大哲学贡献 (V2四项 + V4三项新增)                             │
│       ├─ 分化对待/左侧抄底/分层管理/双牛过滤 (V2)                    │
│       └─ 减半锚定/四阶段递减/越高越卖 (V4新增)                       │
│                                                                     │
│  假设格式：                                                         │
│    "在[X场景]下，[Y特征]应该能[提升Z目的的预测准确率]"                │
│    例如："在TOP_EXIT场景下，减半周期阶段应该能提升逃顶时机准确率"     │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 假设输入
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    第二层：算法层 (Algorithm Layer)                   │
│                                                                     │
│  输入：理论假设                                                      │
│  处理：特征工程 + 模型训练 + 推理                                    │
│  输出：四类目的的预测结果 + 置信度                                    │
│                                                                     │
│  特征工程（22个哲学特征，V2十五个 + V4新增七个）：                   │
│    ┌────────────┬────────────┬────────────┬────────────┐            │
│    │ DIP_BUY    │ TOP_EXIT   │ BEAR_SHORT │ BEAR_EXIT  │            │
│    │ 特征组     │ 特征组     │ 特征组     │ 特征组     │            │
│    │ (~25维)    │ (~30维)    │ (~25维)    │ (~25维)    │            │
│    │            │ +减半周期  │            │            │            │
│    │            │ +MA128     │            │            │            │
│    └─────┬──────┴─────┬──────┴─────┬──────┴─────┬──────┘            │
│          └────────────┴────────────┴────────────┘                  │
│                                    │                                 │
│                                    ▼                                 │
│  模型架构：                                                         │
│    方案A：每类目的独立LightGBM模型（推荐，更灵活）                    │
│    方案B：多任务学习共享底层 + 各目的独立头部                        │
│    方案C：单一模型 + 目的注意力权重                                  │
│                                                                     │
│  输出：                                                             │
│    dip_buy_prob, top_exit_prob, bear_short_prob, bear_exit_prob     │
│    + 各自的置信度、特征重要性                                        │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 策略输出
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                   第三层：回测层 (Backtest Layer)                     │
│                                                                     │
│  输入：算法策略输出                                                  │
│  处理：分场景验证 + 消融实验 + 归因分析                              │
│  输出：各目的评分 + 特征贡献度 + 综合评分                            │
│                                                                     │
│  验证维度：                                                         │
│    1. 全周期综合评分（和V4基线对比）                                  │
│    2. 分场景评估（每类目的单独评估）                                  │
│    3. 特征消融实验（新增特征增量贡献验证）                            │
│    4. Walk-Forward滚动验证（避免过拟合）                             │
│    5. 样本内外验证（out-of-sample）                                 │
│    6. 多币种验证（BTC + ETH + 小币）                                 │
│    7. 减半周期覆盖验证（至少2个减半周期）                            │
│                                                                     │
│  评估指标体系：                                                     │
│    每类目的单独评估：                                                │
│      ├─ 准确率/召回率/F1（分类质量）                                 │
│      ├─ 盈亏比（按信号交易的收益）                                   │
│      ├─ 最大回撤（该类目的风险）                                     │
│      └─ 信号频率（合理性）                                          │
│                                                                     │
│    综合评分（和V4基线对比）：                                        │
│      score = 0.4×夏普比 + 0.3×卡玛比 + 0.15×回撤比 + 0.1×胜率 + 0.05×频率
│      V4基线值: 夏普0.900/卡玛0.680/回撤53.46%/胜率51.79%/交易57次    │
│      score > 1.0 → 优于V4基线                                        │
│      score ≤ 1.0 → 不优于V4基线                                      │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 验证结果
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    第四层：基线层 (Baseline Layer)                    │
│                                                                     │
│  锚点：V4减半周期逃顶策略（HalvingTopExitStrategy）                   │
│  功能：版本管理 + 回退机制 + 探索记录                                │
│                                                                     │
│  基线构成（V4 = V3做空优化 + 减半周期逃顶）：                        │
│    ┌──────────┬──────────┬──────────┬──────────┐                   │
│    │ 抄底基线  │ 离场基线  │ 做空基线  │ 空平基线  │                   │
│    │ 4层触发点 │ 减半周期  │ L2=0.6   │ 斐波那契 │                   │
│    │ (V2沿用)  │ +MA128   │ 斜率负   │ (V2沿用) │                   │
│    │           │ +反弹卖  │ (V3优化) │          │                   │
│    └────┬─────┴────┬─────┴────┬─────┴────┬─────┘                   │
│         └───────────┴──────────┴──────────┘                         │
│                                    │                                 │
│                                    ▼                                 │
│  迭代决策：                                                         │
│    ✓ 综合评分 > 1.0 且 各目的均有改善 → 采纳，更新基线                │
│    ⚠ 综合评分 > 1.0 但 某些目的劣化   → 评估，针对性优化              │
│    ✗ 综合评分 ≤ 1.0                  → 回退，保留探索记录              │
│                                                                     │
│  回退操作：                                                         │
│    1. 标记版本为"探索失败"                                           │
│    2. 策略配置回退到V4基线                                           │
│    3. 分析失败原因，形成经验教训                                     │
│    4. 反馈回理论层，修正假设                                         │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 反馈
                                └───────────────────────────────────────┐
                                                                      │
                                                                      ▼
                                              修正理论假设 → 进入下一轮循环
```

### 3.2 闭环运作流程

```
第1步：理论假设
   ↑    │
   │    ▼
   │  从理论库中提取假设，或从经验/观察中形成新假设
   │  格式："在[X场景]下，[Y特征]应该能[提升Z目的的预测准确率]"
   │
   │  第2步：算法实现
   │    ↑    │
   │    │    ▼
   │    │  设计特征 → 加入对应目的的特征组 → 训练模型 → 生成策略
   │    │
   │    │  第3步：回测验证
   │    │    ↑    │
   │    │    │    ▼
   │    │    │  分场景评估 + 消融实验 + 多维度验证
   │    │    │  输出：综合评分 + 各目的评分 + 特征贡献度
   │    │    │
   │    │    │  第4步：基线锚定
   │    │    │    ↑    │
   │    │    │    │    ▼
   │    │    │    │  和v2基线对比 → 综合评分 > 1.0?
   │    │    │    │    ├─ 是 → 采纳，更新基线，成功经验入理论库
   │    │    │    │    └─ 否 → 回退，失败教训入理论库
   │    │    │    │
   └────┴────┴────┘
             反馈修正 → 进入下一轮
```

### 3.3 关键机制

#### 机制1：假设驱动的迭代

每次特征/算法改进**必须**有明确的理论假设，不允许无方向的瞎试。

**假设模板**：
```
假设ID: HYP-YYYYMMDD-XXX
理论来源: [哪个理论/经验/观察]
适用目的: [DIP_BUY / TOP_EXIT / BEAR_SHORT / BEAR_EXIT]
假设内容: 在[X场景]下，[Y特征]应该能[提升Z指标]
预期效果: 该目的准确率提升X%，综合评分提升X%
验证方法: 消融实验 + 分场景回测
状态: [待验证 / 验证中 / 已采纳 / 已失败]
```

#### 机制2：分场景验证

- 全周期综合指标容易掩盖特定场景的问题
- 每类目的单独评估，知道"哪里好、哪里差"
- 针对性优化，而不是全局瞎调

#### 机制3：消融实验

新增特征**必须**做消融实验：
- 有这个特征 vs 没有这个特征
- 证明其**增量贡献**，而不是和其他特征冗余

#### 机制4：基线锚定与回退

- v2增强版MA200是永远的锚点
- 任何改进必须证明自己比基线强
- 不行就回退，保留记录用于学习

## 6. 关键设计决策

### 6.1 为什么选四类目的，而不是更多/更少？

- **四类覆盖完整周期**：抄底→持有→逃顶→做空→空平→等待，覆盖牛熊完整周期
- **不多不少**：太少（如只分多空）粒度不够；太多（细分10类）过于复杂，数据稀疏
- **和v2策略对齐**：v2策略本身就有这四类决策逻辑，映射自然

### 6.2 为什么用独立模型而不是多任务学习？

- **渐进式重构**：独立模型更容易逐步验证，不需要一次性重构整个模型架构
- **更灵活**：每类目的可以单独调参、单独消融、单独迭代
- **风险可控**：某个目的的优化不影响其他目的
- **后续可升级**：验证有效后再考虑多任务学习共享底层表示

### 6.3 为什么保留原有三个管道的分类？

- **向后兼容**：现有代码和文档不需要大改
- **双维度分类**：按来源（三个管道）+ 按目的（四类），交叉索引
- **渐进迁移**：逐步从"按来源组织"过渡到"按目的组织"
