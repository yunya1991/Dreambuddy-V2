# 残差记忆器 · 认知系统接入方案 v0.1

> **定位**：把 `06-逐层过滤设计` 接到既有认知/记忆系统上，明确接入点与重构边界
> **上游**：`06-逐层过滤-残差记忆器设计-v0.1`、`03-阶段结论-v0.2`、`05-残差记忆曲线`
> **现状依据**：`35-广义认知系统协作模块/SPEC-ResidualMemory-Admission.md`（2026-11-16）、`4-MEMORY/9-工具与接口/*`
> **日期**：2026-11-18

---

## 0. 结论先行

**不新建系统。** 既有的 `SPEC-ResidualMemory-Admission` 已覆盖准入（四禁入 / 四残差 / 三测试）、三形态（M1 指针 / M2 联想 / M3 零记忆）、分级 TTL、求解级联 D0→D4。本文只做三件事：

1. 明确三个接入点（写入 / 召回 / 治理）；
2. 补两个结构性字段（`subclass`、`source_anchor`）；
3. **修订分级 TTL 的判据**：从「时间 + 自报质量」改为「子类 + 事实源复核」。

---

## 1. 现状（三层事实）

| 层 | 位置 | 性质 |
|---|---|---|
| 契约层（SSoT） | `35-广义认知系统协作模块/README.md` L3-L21 | 只写 SPEC 与契约，**不移动实现代码** |
| 执行层 | `4-MEMORY/9-工具与接口/` | 真正跑的系统：MCP server、认知循环、向量接口、TTL 治理 |
| 分层模型 | `4-MEMORY/MEMORY_SYSTEM_ARCHITECTURE.md` L131-L166 | L0 元记忆 / L1 总记忆 / L2 应用记忆 / L3 即时记忆 |

当前治理实现（`memory_ttl_manager.py` L157-L203）：

```text
C 级 且 年龄 ≥ 30 天 且 verify_count == 0  → 降为 D 级
D 级 且 年龄 ≥ 7 天                        → 归档（移出主列表）
```

**这不是"简单按时间清理"**，它已经有质量分级和"未验证"条件。但它仍是**时间驱动 + 质量自报**：`quality_level` 由写入方自己填，`verify_count` 只统计被召回次数，两者都不回答"这条事实现在是否还成立"。

## 2. 三个接入点

| # | 接入点 | 位置 | 改什么 |
|---|---|---|---|
| **A 写入裁决** | `cognitive_mcp_server.py` L229-L296（`record`） | 在落库前调用 `gate()`：S0 敏感 → S1 分型 → S2/S3/S4 探针；把 `verdict` 映射为 M1/M2/M3 |
| **B 召回解码** | `cognitive_loop_entry.py` L453-L479（`recall`）、`cognitive_mcp_server.py` L203-L226 | 命中 M1 指针型时不直接返回内容，而是调用 `decode()` 现场重建；失败则回退为该条的记忆内容 |
| **C 定期治理** | `memory_ttl_manager.py` L157-L203（`expire_stale_c_memories`） | 替换判据：`age + quality` → `subclass + 事实源复核 + 可重建性` |

三个点的关系是：**A 决定形态，B 消费形态，C 维护形态**。少任何一个，另两个都会失真——只做 A 不做 B，指针存了也没人解；只做 C 不做 A，新写入继续污染。

## 3. 数据模型增补

现有字段（`vector_memory_interface.py` L187-L243）：`content`、`quality_level`、`confidence`、`tags`、`memory_type`、`source`、`verify_count`。

**新增四个字段**（缺一不可）：

| 字段 | 取值 | 为什么必需 |
|---|---|---|
| `subclass` | `code` / `config` / `runtime` / `D-tech` / `D-policy` | 治理时必须按类选规则；缺失则只能退回全局 TTL |
| `form` | `M1` / `M2` / `M3` | 召回时决定是否要解码 |
| `source_anchor` | `file:symbol` / 配置键 / 记录 id | R1 复核的唯一输入；缺失则无法判断"是否仍成立" |
| `verify_state` | `fresh` / `stale` / `degraded` | 表达"已失效但保留"，现有 `quality_level` 表达不了这个 |

`created_at` 保留，但**不参与删除决策**。

## 4. 与现有 SPEC 的四处冲突

| # | 现有 | 本方案 | 依据 |
|---|---|---|---|
| 1 | 分级 TTL：C 级 30 天未验证即降 D | **代码/配置类取消时间判据**，改事件驱动复核 | E5-F1：λ ≤ 1.4e-4/天，30 天 TTL 会降级 99.9% 仍有效的记忆 |
| 2 | `quality_level` 由写入方自报 | 用 `subclass` + `evidence` 快照替代自评 | 自报质量 = 自己给自己打分，与"真值不由 REA 单独裁定"同一条纪律 |
| 3 | 三形态 M1/M2/M3 已定义 | 保持不变，但 M1 必须带 `source_anchor` 才允许入库 | L2 的 5 个失败全是"命中但定位不唯一" |
| 4 | `memory_pointers` 表 150 条容量门 | 容量门改按子类配额（`π_c`），`D-policy` 不设上限 | 回退只升不降，全局容量会先挤掉最该保留的约定 |

**注**：现有 SPEC §3.7 标注「分级 TTL：记新不记旧（2026-11-16 用户裁定）」。本次修订即推翻该裁定——这本身又是一次 D-tech 被推翻的实例（E5-F3 结论的现场复现）。

## 5. 重构顺序

尊重既有交付状态（记忆树构建器、级联编排器、P4 再巩固均已交付），**不推倒重来**：

| 阶段 | 动作 | 前置 | 验收 |
|---|---|---|---|
| **P0** | 修 REVIEW 列出的 P0 缺陷（向量索引混维、双路径检索不一致、写索引脱钩） | 无 | 同一 query 两条检索路径结果一致 |
| **P1** | 补 `subclass` / `source_anchor` 字段，存量按规则回填 | P0 | 存量 100% 可分类，抽样人工核对 20% |
| **P2** | A 接入点：`record` 前挂 `gate()` | P1 | L1 集复测：误存 0/120、敏感 60/60 |
| **P3** | B 接入点：`recall` 对 M1 走 `decode()` | P1 | 召回准确率不低于内容基线 −5pp |
| **P4** | C 接入点：治理判据替换，先 dry-run | P2/P3 | dry-run 与人工判定一致率 ≥90% |
| **P5** | 删除（需删除测试集） | P4 + C6 | 删除测试通过率 ≥95% |

**P0 是硬前置**。REVIEW 指出的索引混维与双路径不一致，会让我们观察到的一切召回指标失真——这和实验里"仪器缺陷被当成'不可推导'"是同一类错误，必须先修仪器再议策略。

---

## 6. 风险

| 风险 | 表现 | 处置 |
|---|---|---|
| 字段回填错误 | 存量 `subclass` 判错 → 治理选错规则 | 先按 `source`/`tags` 规则回填，20% 人工盲评报 κ |
| 解码拖慢召回 | M1 每次召回都跑探针 | 只对 top-k 前 3 条解码；其余返回指针 |
| 复核触发过频 | 文件变更即全量复核 | 按 `source_anchor` 反向索引，只复核受影响的条目 |
| D-policy 误判 | 被归入 code → 自动降级 | 分型规则里 D-policy 优先，宁可错判为 policy |
