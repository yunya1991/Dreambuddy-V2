# 阶段结论 v0.2：残差记忆器能力评估

> **覆盖实验**：E1–E4、L2 / L2b / L2c / L2d / L2e、L3 / L3b、E5-F1 / F2 / F3
> **日期**：2026-11-18
> **取代**：`03-阶段结论-L1到L2-v0.1.md`（v0.1 保留，作修订痕迹）
> **一句话**：**准入层站住了，端到端能把成本降 34% 且不牺牲准确率；但"越老越该转指针"这一时间维度基本被证伪，设备的能力边界比最初设想窄得多。**

---

## 1. 四层能力（当前状态）

### 1.1 准入层 L1 —— 唯一全面达标的一层

| 指标 | 阈值 | 结果 |
|---|---|---|
| 可推导项误存率 | ≤10% | **0/120** |
| 不可推导项漏存率 | ≤5% | **0/120** |
| 敏感拒绝率 | 100% | **60/60** |
| p95 判定延迟 | ≤3 s | 达标（规则 + 探针） |

关键跃迁不是"更准"，而是**换了出错方向**：v0.2 的"关键词 + 符号探针"在对抗集上漏存 **56%（28/50）**，根因是"搜到符号就算可推导"；v0.3 改为**默认拒绝 + 结构谓语白名单**后归零。

**保留限制**：H-70 的谓语是在看过该集之后补的，已失去留出集资格；0% 是调参后结果。

### 1.2 解码层 L2 —— 单题可追平

| 方案 | 准确率 | 回退率 | 存储 | 读时 LLM |
|---|---|---|---|---|
| 内容记忆 | 100% | — | 23.0 tok | 0 |
| 纯指针 + grep | 80% | — | 3 tok | 0 |
| 指针 + REA | 45% | — | 3 tok | 0 |
| L2b 级联（分数 + margin 回退） | 97% | 37% | 11.8 tok | 0 |
| L2c 行内容校验 | 92% | — | — | **负结果，已回退** |
| **L2d 级联 + LLM 审 top-1** | **100%** | 57% | 15.2 tok | 38/60 题 |
| L2e LLM 从 top-3 选 | 95% | 47% | 13.8 tok | 38/60 题 |

两档配置并存：**成本优先 L2b（97% / 11.8 tok）** 与 **准确率优先 L2d（100% / 15.2 tok）**。

### 1.3 端到端 L3 —— 最硬的一条证据

30 任务 × 4 条件 × 3 种子（seeds 11/22/33，共 90 任务/条件）：

| 条件 | 成功率 | token/任务 |
|---|---|---|
| 内容记忆 | 100% | 46.4 |
| 纯指针 | 65.6% | 7.0 |
| RMD（无 LLM） | 93.3% | 27.4 |
| **RMD + LLM 校验** | **100%** | **30.5** |

**成本 −34%，准确率持平。** 同时暴露一个新机制：单题 97% 到任务级 93.3% 的落差，来自**误差按任务所需事实数 k 复利**（p^k）——此前完全未被考虑。

### 1.4 生命周期 —— 新增，结论是"被证伪"

| 类 | n | 事件 | λ | 判定 |
|---|---|---|---|---|
| F1 代码位置（本仓库） | 180 | 4（有效 ~2） | 2.51e-4 [6.8e-5, 6.4e-4] | K5，不可识别 |
| F1 代码位置（SQLAlchemy，冷抽） | 240 | **0** | ≤1.36e-4 | 1 年存活 ≥95.2% |

## 2. P1 判定：仍为"有条件成立"，但表述必须收紧

| 否证条件 | 结果 | 判定 |
|---|---|---|
| ① 指针/零记忆成功率比内容组低 ≥10pp | L2d 0pp；L3 的 rmd_llm 0pp，rmd −6.7pp | **不成立** |
| ② 综合成本高于内容组 | L3：30.5 vs 46.4 → **−34%** | **不成立** |
| ③ 重建成功率 < 80% | 纯 grep 80%，恰好压线 | **边界，不判定** |

**合法表述**：

> 在代码定位类问题上，**准入 + 指针 + 回退 + LLM 校验**可在不牺牲端到端准确率的前提下，把单位任务成本降低约 34%。

**禁止表述**：

- ❌ "指针/重建替代了内容记忆"——真实替代率只有 43%–63%，其余靠"判不准就存内容"。
- ❌ "记忆会随时间退化为指针"——见 §3。
- ❌ "适用于通用记忆"——全部证据限于 Python 代码工程事实。

## 3. 相对 v0.1 的三处实质修订

| # | v0.1 的判断 | v0.2 的修订 | 依据 |
|---|---|---|---|
| 1 | 成本论证停在单题（11.8 / 15.2 tok） | 补端到端：**−34%**，但需接受 57% 回退 + 一次 LLM 调用 | L3 |
| 2 | 未涉及时间维度 | **"越老越该转指针"对代码位置类被证伪**：λ ≤1.4e-4，一开始就该存指针 | E5-F1 |
| 3 | 把「偏好 / 否决 / 教训」统一标 λ≈0 | 拆为 **D-tech（λ 高，已证伪 ≈0）** 与 **D-policy（未检验）** | E5-F3 |

第 2 条的后果：曲线的三维里，**时间轴在代码域不参与决策**，实际只剩「结构可重建性」与「长度/片段成本」两轴。

第 3 条的后果：**不得把 D-tech 的高 λ 用到 D-policy 上**，否则会删掉最不该删的约定。

---

## 4. 仍站得住的四条结论

1. 对可由代码事实源恢复的信息，**准入 + 指针 + 回退**可在不降准确率下减少约 34% 存储（L2d / L3）。
2. **重建能力不是单一工具的函数**：REA 45%、grep 80%、LLM 语义校验把系统从 97% 推到 100%。级联价值 > 任何单一仪器。
3. **回退机制是必需的**：纯重建上限 80%，错误全部是"多个合理文件选错"，比"无结果"更危险。
4. 敏感信息必须走"拒绝"而非"记下来"，且拒绝规则要独立于能力强弱（60/60）。

## 5. 四个仍在的短板

| 短板 | 影响 | 现状 |
|---|---|---|
| REA 未修 I2/I3 | 调用链类重建仍为 0，仅覆盖符号定位 | 未动 |
| 57% 回退率 | 真正"省下来"的条目只有 43% | 结构性，非 bug |
| 读时依赖 LLM | 时延未实测（E4 无法测），成本随模型价浮动 | 未量化 |
| 时间维度失效 | 曲线降为两维 | 已接受 |

## 6. 结论边界（随论文一并声明）

1. **单领域**：Python 代码工程事实；不外推到偏好、世界状态、多模态。
2. **单模型家族、单次运行、无方差**：L2d 的 100% 含同源自证成分（校验器与判定器同家族）。
3. **题集同源**：L1 的可推导样本由 AST 生成，与探针同源；H-70 已污染，缺真正留出集。
4. **两个外部样本源都是低重构库**：高变更仓库三次克隆均失败，λ 的域外有效性未验。
5. **D-policy 的 `λ≈0` 是假设，不是结论**：全仓库无此类语料。
6. **λ 的最长观测窗 150 天**：无法区分 1e-4 与 1e-5。
