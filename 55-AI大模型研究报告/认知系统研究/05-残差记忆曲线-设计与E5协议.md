## 0. 一句话定义

**残差记忆曲线是一个时间-长度-结构三维的价值函数，输出"此刻存内容 / 存指针 / 不存"的三选一，判据是单位恢复成本下的期望收益，而不是"信息够不够重要"。**

它不解决"记什么"（那是 L1 准入层的事），只解决**已判定要记之后，以什么形态记、以及什么时候该换形态**。

## 1. 三个维度的判定结论

先把用户提出的三个维度逐条判定，避免把"听起来对"当成"成立"。

| 维度 | 判定 | 修正 |
|---|---|---|
| D1 时间：越久越该退化为指针 | **部分成立** | 机制是**风险率（hazard）**不是衰减；方向依赖该事实的易变率 λ_c，不是 age 单调 |
| D2 答案长度 / 定位片段长度 | **成立，已定量** | L3b 已给出盈亏平衡 `N* = 9.59/(s − 18.39)`，s 为片段 token 数 |
| D3 结构空间（工程类型 vs 文本类型） | **成立，但作用点不同** | 影响的是**可重建性 p_recon**，不是成本；文本类 p_recon 可能低到使曲线退化 |

### 1.1 D1 为什么不能写成"越老越该转指针"

用户的直觉在两处是对的：老记忆的上下文更可能过时、读取定位片段能让模型获得**当前**周边上下文。但只要存在一类事实，其**内容本身不会因为时间而失效**，方向就反了：

| 事实类别 | λ_c（失效风险率） | p_recon | 越老该…… | λ 的证据状态 |
|---|---|---|---|---|
| **D-policy** 偏好 / 组织约定 / 带代价教训（"不要用 X""必须走会签""X 曾导致事故"） | ≈ 0（**假设**） | ≈ 0 | **继续存内容**，永不转指针 | **未检验**：本仓库无此类记录（F3） |
| **D-tech** 技术方案决策（"采用 X 方案""X 优于 Y"） | **高（天级）** | 低 | 短期存内容；一经推翻即失效 | **已证伪 ≈0**：8 条中 5 条同日被推翻（E5-F3）；点值**不可估**（选择偏差） |
| 代码位置（"X 定义在 file:line"） | **≤ 1.4e-4** | 高 | 一开始就该存指针 | **已测**：SQLAlchemy 240 样本 0 事件（E5-F1） |
| 配置值 / 端口 / 版本 | 未识别 | 中 | 短期存内容，到期转指针 | 1 事件 / 130 样本（E5-F2a），不可识别 |
| 部署状态 / 外部世界状态 | 高（未测） | 中 | 几乎总该现查 | 未测 |

所以 `age` 不是独立自变量，它只是 `P(仍有效 | t)` 的积分变量。**曲线必须按子类分别拟合，不能有一个全局的"记忆半衰期"。**

**三条由 E5 直接得出的禁令**（2026-11-18 补记）：

1. **不得把 D-tech 的 λ 用到 D-policy 上。** 用天级的 λ 去衰减"不要用 X"这类约定，会删掉最不该删的东西——这是"越老越该转指针"最危险的失效模式。
2. **D-policy 的 `λ≈0` 目前只是假设，不是结论。** 全仓库没有这类记录，F3 无法检验；写作时必须标为"未检验"。
3. 原表把「偏好 / 否决 / 教训」合为一类并整体标 `λ≈0`。F3 证明其中"技术方案决策"必须独立为 D-tech（λ 高）；其余（偏好 / 约定 / 教训）仍合并为 D-policy，但证据状态从"已知 ≈0"降为"未检验"。**这条修订本身即为一次 D-tech 被推翻的实例。**

### 1.2 D1 的正确定义：hazard，不是 decay

指数衰减写法 `w(t) = w0·e^{-t/τ}` 隐含了"所有事实同一半衰期"，在生存分析里对应 λ 为常数。这在本问题里有两个问题：

1. 它把"很少发生但一旦发生就是灾难"的更新，和"每年必变一次"的配置混在一起；
2. 它无法处理**右删失**——今天仍成立的事实不是"永不过期"，只是"观测期内未失效"。

正确形式：

```text
P(仍有效 | t) = P(T_c > t) = exp(−λ_c · t)      # 指数（基线）
或 Weibull:     exp(−(λ_c · t)^β)                # β≠1 时允许风险率随时间变化
```

λ_c 按类别估，β 留给 E5 检验（若 β 显著偏离 1，说明存在"新写入事实更脆弱"的效应，不能当作同质总体）。

### 1.3 D2 已定量，可直接接入

L3b 的结论：存指针的盈亏平衡读次数是片段大小 s 的函数，不是固定常数。

```text
N*(s) = (w_r − 0.93·w_c) / (0.93·r_c − r_r)  ≈  9.59 / (s − 18.39)
```

含义：**片段越大，指针越划算**；因为每次读指针都要重付解析成本，而读内容的边际成本是常数。

这条给出的是"读频门槛"，不是"价值门槛"。两者在曲线里是相乘关系：读得越频，V_C 与 V_P 的差距被放大得越多。

### 1.4 D3 作用在可重建性上

结构空间不改变存储成本（一条内容就是一条内容），它改变的是**给定指针后能否重建出正确答案**。

| 结构档位 | p_recon 基准 | 依据 |
|---|---|---|
| 代码符号级（def/class/import） | ~0.80 | L2 纯 grep 80% |
| 代码调用链级 | ~0.45 | L2 指针 + REA 45% |
| 配置 / 环境变量 | 待估（E5） | 无数据 |
| 自然语言文档 | 待估，预期 <0.5 | 无结构锚点，grep 会大量假阳性 |
| 偏好 / 否决 / 教训 | ≈0 | 不在任何可解析载体里 |

**这一档是曲线的"斜率"**：p_recon 越低，越早该转成内容；低到 0 时曲线退化为"永远存内容"，也就是残差记忆的定义本身。

## 2. 与 Transformer 的类比边界

用户提出"参考 transformer 的方式"设计曲线。可以借用结构，不能借用机制。

### 2.1 可借用

1. **可加性偏置分解**：transformer 里是 `score = q·k + b_pos + b_type`；我们可以写成
   `logit = b_time(t) + b_len(ρ, s) + b_struct(c)`，三维各自独立进入，避免互相污染。
2. **单调基函数族**：ALiBi 用 `−m·(i−j)` 表达"越远越弱"，我们用 `−λ_c·t` 表达"越久越可能失效"，形式同源但含义不同（位置距离 vs 物理时间 + 变更事件）。
3. **按头/按层不同斜率**：不同 fact class 用不同 λ_c，等价于多头不同 m。

### 2.2 不可借用

| 不借 | 原因 |
|---|---|
| softmax 归一化 | 记忆写入是**逐条独立**的三选一，没有"总预算为 1"的约束；强行归一化会让"多存一条内容"挤掉另一条，与实际不符 |
| 多头加权求和 | 我们要求每个判定可解释、可审计；加权求和不给单条理由 |
| 梯度学出的隐式权重 | 样本量（首批 <500）不足以学，且违反"冻结版本 + 可复现"纪律 |
| 相对位置距离 | transformer 的"远近"是序列内序号；我们的 t 是墙钟时间且中间有外部变更事件，必须用生存分析 |

一句话：**借它的"可加单调偏置"骨架，不借它的"归一化分配"语义。**

### 2.3 QKV 的可用部分：eager V / lazy V

QKV 类比只在**读路径**成立（写侧无归一化，K/V 同源假设也不适用），但其中一条很硬：

| QKV | 记忆系统 |
|---|---|
| Q | 当前查询/任务意图（不可控） |
| K | 锚点：符号名、路径、模块名（**可控**） |
| V | 被取出的内容 |
| Q·K | 能不能被召回 → 召回率 R |
| softmax(QK) | 级联选择 + 回退 |

由此得到两个可用的东西：

1. **存内容 = 写入时求值 V（eager）；存指针 = 读取时求值 V（lazy）。** L3b 的 `N*` 本质就是 eager/lazy 盈亏平衡读次数——指针不是"少存了信息"，而是**把求值推迟到读时**。
2. **K 的质量独立于 V 的形态。** 这引出本文档此前缺失的维度 `R`（§3.6），并解释了 L2 的 80% 该怎么拆。

## 3. 曲线的正式形式

### 3.1 符号

| 符号 | 含义 | 量纲 |
|---|---|---|
| t | 距写入的时间 | 天 |
| λ_c | 类别 c 的失效风险率 | 1/天 |
| p_eff(t) | `exp(−λ_c·t)`，内容仍有效的概率 | — |
| R_C | 内容记忆的召回率（语义/模糊匹配能命中） | — |
| R_P | 指针记忆的召回率（锚点须精确对上） | — |
| p_recon | 给定指针**且召回成功后**重建出正确答案的概率（依赖结构档位与片段大小） | — |
| U | 一次成功使用带来的收益 | 任务成功率百分点 |
| c_stale | 使用过时内容导致的损失 | 同上，>0 |
| c_recon(ρ, N) | 每次重建成本，ρ 为答案/片段长度比，N 为读次数 | token 或时间 |
| w_C / w_P | 写入成本 | token |
| Δw | `w_C − w_P` | token |

### 3.2 两条价值函数

```text
# 逐条判定：记忆项 x 属于子类 c，所有参数按 c 取，不得用全局 λ
存内容:  V_C(t | c) = R_C,c · [ p_eff,c(t)·U − c_stale·(1 − p_eff,c(t)) ] − w_C
存指针:  V_P(t | c) = R_P,c · [ p_recon,c·U − c_recon(ρ, N) ]          − w_P

         p_eff,c(t) = exp(−λ_c · t)

# 系统级预算：只用于总容量/总成本估算，不参与单条判定
E[V] = Σ_c  π_c · V_c(t)        π_c = 子类 c 在写入流中的占比
```

两个式子不能混用：

- **单条判定必须按 `c` 取值**。一条记忆只属于一个子类，跨类求和没有意义；把 D-tech 的 λ 用到 D-policy 上，等于用"技术方案会过期"去衰减"不要用 X"，直接删掉最该留的东西。
- **`π_c` 只出现在系统预算里**。它回答"这批写入总共值多少"，不回答"这一条该不该存"。

`U_recover` 是"指针没重建出来、需要人再找一遍"的成本，暂并入 `c_recon`。

**R 为什么要乘在外面**：召回是求值的必要条件。召回不中，后面的 `p_eff` / `p_recon` 再好也用不上——这就是"答案在库里但没取出来"的情形。

**R_C 与 R_P 不相等**：内容靠语义匹配，问法变了也能命中；指针靠锚点精确匹配，问法一变就掉。所以 `R_C > R_P` 是常态，这一项会**系统性偏置向存内容**，需要在判读 `t*` 时扣除。

### 3.3 决策规则

```text
若 V_C(t) > V_P(t) 且 V_C(t) > 0  → 存内容
若 V_P(t) > V_C(t) 且 V_P(t) > 0  → 存指针
否则                              → 不存（留审计日志，不进记忆）
```

### 3.4 闭式切换时刻

令 `V_C(t | c) = V_P(t | c)`，代入 `p = e^{−λ_c·t}`（以下省略下标 c）：

```text
R_C·[p·U − c_stale·(1 − p)] − w_C = R_P·[p_recon·U − c_recon] − w_P

解出:
p* = [ R_P·(p_recon·U − c_recon) + R_C·c_stale + Δw ] / [ R_C·(U + c_stale) ]

t* = −ln(p*) / λ_c
```

`R_C = R_P = 1` 时退化为上一版：`p* = [p_recon·U + c_stale + Δw − c_recon] / (U + c_stale)`。

判读：

| 条件 | 结论 |
|---|---|
| `p* ≥ 1` | 从不值得存指针，永远存内容（偏好、否决、教训） |
| `0 < p* < 1` | **t* 之后转指针**——这正是用户直觉的适用区间 |
| `p* ≤ 0` | 一开始就该存指针（稳定的代码符号） |
| `λ_c → 0` | `t* → ∞`，永不转指针 |
| `R_P ↓` | `p* ↑`，**更早转内容**；`R_P` 低到 `V_P ≤ 0` 时直接排除指针，不看 `t*` |

最后一行是新增的保护：**召回不中的指针不是"便宜的指针"，是"零价值的指针"**，不能靠时间曲线救回来。

**这个式子把三条直觉统一了**：用户说的"越久越退化为指针"是 `0 < p* < 1` 且 `λ>0` 的特例，不是普遍规律。

### 3.5 各维度如何进入

| 维度 | 进入位置 | 形式 |
|---|---|---|
| 时间 | `p_eff(t)` | `exp(−λ_c t)`，λ_c 按类别估 |
| 长度比 ρ | `c_recon(ρ, N)` | `N·(s·k_parse + k_locate)`，s 与 ρ 反向相关 |
| 结构 | `p_recon` | 分档常数，E5 实测后按档取值 |
| 锚点质量（新增） | `R_C` / `R_P` | 与前三者正交，来自 QKV 分析（§2.3） |

前三个是用户提出的原始三维；`R` 是第四根正交轴，**它不属于"曲线"（不随时间/长度/结构变化），但决定曲线是否被采信**。

注意：`p_recon` 本身也可能随时间下降（目标是频繁重构的代码）。但通常 `λ_recon << λ_c`，E5 要分开估；若实测两者量级接近，说明"指针也会腐烂"，需要在指针里带版本号或漂移检测。

### 3.6 召回与重建的分解

此前 L2 的指标把两类失败混在一起，导致改进方向一直是瞎猜。用 R 拆开：

```text
单次指针读取的成功率  =  R_P（召回对了） × p_recon（重建对了）
```

L2 纯 grep 的 80%，是这两个概率的**乘积**，不是任何单一能力。

| 症状 | 根因 | 该改什么 |
|---|---|---|
| 答案在候选集里，但 top-1 是别的文件 | `p_recon` 低（排序/语义误判） | 改仪器：修 REA I2/I3、加调用链边、加 LLM 校验 |
| 答案根本没进候选集 | `R_P` 低（锚点歧义/问法漂移） | 改 K：加宽锚点、加同义符号、加路径别名 |

对 E5 的直接约束：**`R_P` 与 `p_recon` 必须分开测**——`R_P` 用"真值是否出现在候选集 top-k"判定，`p_recon` 用"给定正确候选后 top-1 是否正确"判定。合成一个"答案对不对"的指标，会让两者的修法互相掩盖。

## 4. E5：估计 λ_c

### 4.1 目标

给出三类事实的 `λ_c` 点估计 + 95% CI，并检验 `β`（Weibull 形状参数）是否显著偏离 1。

### 4.2 数据源与抽样

**只用真实历史，不用合成数据。** 来源：本仓库 git 历史（`git log --follow`、`git log -S`、blame）。

| 类别 | 构造方式 | 每格样本 | 判定方法 |
|---|---|---|---|
| F1 代码位置 | 从 t 时刻的 snapshot 提取"`sym` 定义在 `file:line`" | ≥40 | 当前 AST 自动判定 |
| F2 配置值 | 从历史文件中提取"端口/路径/阈值 = 值" | ≥40 | 当前文件 grep 自动判定 |
| F3 偏好与决策 | 从 commit message、研究文档、否决记录中提取"约定/禁止/放弃" | ≥40 | **人工盲评**（不可自动判定） |

时间窗口：`t ∈ {0, 30, 90, 180}` 天。四个窗口 × 三类 × ≥40 条 = ≥480 条。

### 4.3 关键：右删失处理

这是整个协议最容易出错的地方。

- 今天仍成立的事实是**删失观测**（censored），不是"永不过期"；
- 若把删失当"存活到底"，λ 会被系统性低估，`t*` 被系统性高估，导致"该转指针时没转"；
- 估计方法：Kaplan–Meier 曲线 + log-rank 检验（类别间差异）+ 指数/Weibull MLE 拟合；
- CI：bootstrap（1000 次重抽样），不用正态近似（样本小、删失比例高）。

### 4.4 真值纪律（沿用 `01a` 五条硬约束）

1. `λ` **不得**由 REA 重建结果反推——那会把"仪器看不到"误判成"事实已失效"。
2. F3 的 20% 由第二人盲评，报 Cohen's κ；κ < 0.6 先修判定手册，不进入拟合。
3. 冻结三件套：git commit、脚本 md5、抽样清单哈希；中途不换。
4. 失败/无法判定计入分母，不剔除。
5. 报告必须同时给点估计与区间；区间宽度 > 0.3（以 `1/λ` 的天数为单位）时只报区间。

### 4.5 产出

```text
E5-lambda.json      # 每类 λ 点估计、CI、β、删失比例
E5-km.png / .csv    # Kaplan-Meier 曲线
E5-report.md        # 判定：时间维度是否可识别
```

## 5. E5b：验证"重建片段带来上下文增益"

### 5.1 要验的命题

用户直觉：**读取定位片段不只是为了"定位"，它同时把当前真实周边上下文喂给模型，这是内容记忆给不了的。**

这个命题独立于准确率，必须单独测，否则会被"内容记忆准确率更高"掩盖。

### 5.2 设计

| 组 | 注入内容 | 控制 |
|---|---|---|
| A（对照） | 180 天前的内容快照 | token 数与 B 组对齐（按 B 的片段长度截断 A） |
| B（实验） | 指针 + 现场重建片段（当前真实代码） | — |

- 任务：10 个**依赖于周边上下文**的后续任务（如"在此处新增字段需要同步改哪几处"）；
- 指标：任务正确率（主）、引用过时事实的比例（次）、需要额外追问的次数（次）；
- 通过线：`B − A ≥ 10pp` 才认定上下文增益成立；
- 否证线：`B − A ≤ 0` 且 bootstrap CI 不跨 0 → 删掉曲线里的这一项。

### 5.3 为什么必须做这个

如果没有 E5b，曲线里"存指针"的唯一好处就是省 token。那么当 `s` 很大（片段很长）时，指针会被判为不划算，结论会退化成"全存内容"。用户指出的上下文收益，正是打破这个退化的唯一机制——**它必须被量化，否则不能写进公式。**

## 6. Kill criteria

| # | 条件 | 后果 |
|---|---|---|
| K1 | 所有类别的 λ 95% CI 跨 0 | 时间维度不可识别，曲线降为「长度 + 结构」二维 |
| K2 | 文本类 `p_recon < 0.5` 且工程手段无法提升 | 结论限制在代码域，`03` 的边界声明需加一条 |
| K3 | 曲线决策的后悔值不优于「全存内容」或「全存指针」中较优者 | 曲线无实用价值，退回简单规则 |
| K4 | E5b 的 `B − A < 0` 且显著 | 上下文增益假设被否证，从公式中删除该项 |
| K5 | 任一格样本 < 40 或删失比例 > 80% | 该格只报区间，不报点估计，不进入闭式解 |
| K6 | `R_P` 与 `p_recon` 在测量上不可分辨（同一批题上两者估计值差异 < 0.05，或无法构造只改变其一的子集） | §3.6 的分解退化为一个混合成功率，R 维度从公式中删除，回退到 `R=1` 的单因子版本 |
| K7 | E6 的 `B − A < 5pp`（写时残差无增益），或 `m` 低于预注册阈值（预期问法命中率不足） | §8 逆向路线作废，§8.3 的「带问法的指针」不纳入；曲线回退到无 `R_Q` 版本 |

K3 是总闸门：**如果一条按类别区分的曲线，效果还不如"一刀切全存内容"，那它就只是复杂度。**

K6 的判定必须用**可分离子集**，不能只看两个点估计接近：需要构造「真值进候选集但 top-1 错」与「真值未进候选集」两类样本各 ≥20 条。若样本自然分布里几乎没有第一类，说明当前仪器根本没有排序能力，`p_recon` 不可识别，此时把 `R_P × p_recon` 合并成一个观测成功率才对——**拆不开的指标不该假装拆开了**。

## 8. 逆向残差：用写时上下文替代写时猜测

> 本节回应"既然写是大模型在写，能不能逆向考虑"。结论：方向对，而且它补上了 RMD 当前最大的浪费；但成立与否全押在 `m`（预期问法命中率）上。

### 8.1 现状在丢信号

当前 gate 的流程是：

```text
写者上下文(完整) → 压成一句候选文本 → 丢掉上下文 → 探针猜"这能不能推导"
```

探针拿到的是**剥光的结论**，再反推这个结论值不值得记。但判断"能不能推导"所需的信息恰在写者手里——他刚做完这件事，知道为什么选 A 不选 B、哪条路试过失败、哪个约束是隐性的。

**写者的 Q 是免费的，现在被扔掉了。** 这是逆向路线的全部动机。

### 8.2 定义的反转

原定义把残差当作**事实的属性**：`H(x | K, D, R)`。逆向之后：

```text
残差属于 (x, writer_state)，不属于 x。

存什么 = argmax_s  I(s ; future_task)
          s.t.  s ∉ Closure(K, D, R)     # 可推导部分要减掉
               s ⊆ writer_state          # 只能从写者已有状态里取
```

两者的差别是**加法与减法**：现在的 gate 只做减法（"能推导就不记"），没有任何一项在问"这条对未来的任务有多少用"，所以它在偏好/否决上只能 fallback 到词表。

`I(s; future_task)` 不可直接计算，只能用 E6 的消融近似（§8.5）——这一点必须写明，否则它就是一句无法证伪的话。

### 8.3 第三种存储形态：带问法的指针

R 从常量变成设计变量，是逆向路线的实际收益：

| 形态 | K 的内容 | 写入成本 | 召回来源 |
|---|---|---|---|
| 纯指针 | 符号名 / 路径 | `w_P` | `R_P`（精确匹配） |
| **带问法的指针** | 符号名 + 3–5 条预期问法 | `w_P + w_Q` | `R_Q`（按问法匹配） |
| 内容 | 原文 | `w_C` | `R_C`（语义匹配） |

`R_P` 只能被动测量，`R_Q` 可以主动工程化。代价是 `w_Q > 0` 会推高 `N*`（更早就该放弃指针），所以这仍是一笔要算的账，不是免费的改进。

### 8.4 三个会翻车的地方

| 陷阱 | 表现 | 处置 |
|---|---|---|
| 自洽偏差 | 写者自造预期问法，再用同一模型评自己 → 必然 100% | 预期问法只能用**历史真实问法**校准（commit 后的追问、issue 文本），不得模型自造 |
| 写时上下文也有盲区 | 读者要的东西，写者当时没意识到 | 逆向不替代探针，二者取**并集** |
| 写放大 | 每条生成 5 个问法，存储近倍，命中率却可能很低 | 以 `m` 为硬指标，`m` 不达标就退回纯指针 |

第三条最可能致命：按 L3b 口径，写成本从 3 → 8 tok，`N*` 明显前移；`m` 不高则直接亏。`m` 的阈值须在跑 E6 前预注册（K7），不得事后按结果定。

### 8.5 E6 协议

不先改架构，只测一件事：**写者上下文里有多少是代码库无法恢复的**。

| 组 | 读者输入 |
|---|---|
| A（基线） | 代码库 + 空记忆 |
| B（实验） | 代码库 + 从 writer_state 提取的残差（决策 / 理由 / 否定路径） |
| C（上界锚） | 代码库 + 全量 writer_state |

- 任务：10–15 个**依赖"为什么"而非"是什么"**的后续任务；
- 指标：任务正确率、残差 token 量、`m`（生成的问法被真实后续问题命中的比例）；
- 通过线：`B − A ≥ 10pp` 且 `B` 的 token 量 ≤ `C` 的 30%；
- 否证：`B − A < 5pp` → 写者上下文对后续任务无增益，逆向路线作废（K7）；
- C 组不可省：没有上界锚就不知道 B 提取掉了多少有用信息，也无法判断是"提取差"还是"上下文本来就没用"。

### 8.6 与曲线的关系：串联，不是竞争

| 事实类型 | λ_c | p_recon | 曲线判定 |
|---|---|---|---|
| 决策理由 / 否决路径 | ≈0 | ≈0 | 永远存内容 |
| 隐式约束 | ≈0 | 低 | 存内容 + 适用条件 |
| 预期问法 | 随任务分布漂移 | — | 指针的附加 K，带过期 |

**逆向保证这类事实能被捕获；曲线决定它们以什么形态存。** 缺了逆向，曲线是在给一堆已经漏掉的候选打分。

## 9. 反循环约束（本文件专属）

1. λ 只能用外部真值（git 历史 + 人工）估计，**不得**用 REA 或 grep 的可解析性反推。
2. `p_recon` 的估计不得复用 L2 的 97%——那是"grep + 弱证据回退 + LLM 校验"的合成上限，不是单探针能力。
3. `U` 的尺度统一用"任务成功率百分点"，不用 token、不用钱，避免单位混用导致 `p*` 失真。
4. `c_stale` 目前无数据，只能由 E5b 的 A 组错误率反推，反推过程必须写进报告。
5. 曲线一旦用 E5 数据拟合，E5 数据集即退出"留出集"资格；后续验证需另一批时间窗口。

## 11. 未定问题

1. **`U` 的绝对尺度**：目前只有相对比较意义。若要让 `t*` 有"天数"的物理含义，需要把 U 与 c_stale 都锚到同一个可测指标（建议：任务成功率百分点 × 单任务成本）。
2. **Weibull 还是指数**：`β` 若显著 < 1，说明早期更脆弱（新写入的事实还没被验证），此时应分段拟合而非用单一 λ。
3. **指针腐烂**：若 `λ_recon` 与 `λ_c` 同量级，"指针"本身需要版本号；这会把问题从一维时间升级为两维（事实年龄 × 目标漂移）。
4. **跨项目外推**：本协议全部在本仓库上做；换仓库/换语言是否同 λ，属于第二篇的事，不在本文件范围。
