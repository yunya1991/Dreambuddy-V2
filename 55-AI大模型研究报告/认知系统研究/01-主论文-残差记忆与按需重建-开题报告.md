> **论文序列**：第一篇（主论文），后续三篇分别研究记忆巩固与遗忘、任务—成本联合基准、失败驱动能力获取

> **英文题目**：From Memory Accumulation to Residual Intelligence: A Memory–Capability Co-design for Long-Running LLM Agents  
> **备选英文题目**：Remember Less, Solve More: Residual Memory and On-Demand Reconstruction for Long-Running LLM Agents  
> **研究对象**：DreamBuddy 认知记忆系统  
> **版本**：v0.1（开题稿）  
> **日期**：2026-11-16

## 摘要

长期运行的大语言模型智能体需要跨会话保留经验、用户偏好、历史决策与任务状态，但以自动捕获和向量检索为主的记忆方案容易产生写入膨胀、过程噪声积累、近似误召回、上下文成本上升及过期信息残留等问题。记忆数量的增长并不必然带来智能体能力的增长，如何决定“什么值得记忆、以何种形态记忆、何时遗忘，以及何时应由现场求解替代记忆”，成为记忆原生智能体架构中的关键问题。

本研究以 DreamBuddy 认知记忆系统为研究对象，提出“残差记忆—记忆树—现场重建”协同框架：仅将不可由基础模型、单一事实源或现场求解能力再推导的信息作为内容型记忆候选；以指针型记忆树承载长期定位信息；以 REA 逆向解析等工具承担可重建知识的按需求解；通过检索、使用、验证、升级和分级遗忘构成记忆生命周期闭环。研究采用横向跨系统比较与纵向长周期任务流评估相结合的方法，检验残差准入、指针表示、按需重建和使用驱动遗忘对任务成功率、记忆污染率、检索有效性、Token 成本、存储增长及重建成本的影响。

本研究拟形成一套可操作的智能体记忆价值判据、一种记忆与能力协同的架构，以及一套兼顾任务效果与长期维护成本的评测方法。所有性能主张均以后续可复现实验为依据，不将工程设计本身视为先进性已经得到证明的证据。

**关键词**：大语言模型智能体；认知记忆；残差记忆；短期记忆；长期记忆；可控遗忘；按需重建；记忆治理

## 一、研究背景与问题提出

### 1.1 研究背景

大模型应用正在由单轮问答向持续执行任务的智能体演进。智能体需要在多轮交互和跨会话任务中保留信息，并将历史经验用于后续规划、决策和反思。早期方案主要依赖外部检索增强生成，将历史文档或会话切分后进行向量检索；进一步的研究与工程实践开始引入工作记忆、情景记忆、语义记忆、程序记忆、分层存储、摘要巩固、知识图谱和遗忘机制。

这一演进表明，记忆正在从计算的附属产物转变为智能体架构的重要组成部分。然而，当前研究仍较多关注“如何保存更多”和“如何检索更准”，对记忆准入、记忆形态选择、使用后的验证、退出机制及记忆与求解能力之间的替代关系，缺少统一的分析和长期实证。

### 1.2 工程问题与研究动机

DreamBuddy 的内部工程审计为上述问题提供了现实案例。2026-11-15 的内部扫描中，认知记忆库共有 315,471 条记录，其中 `source=rag-bridge` 的检索轨迹为 305,930 条，占 96.98%；`verify_count=0` 的记录占 98.4%。该现象说明，检索轨迹被反复写回记忆库后，可能形成“读取—写回—再读取”的写放大循环，使记忆规模增长偏离真实经验积累。

这些数据属于内部系统的问题基线，不代表本研究方案已经有效，也不能直接外推至其他记忆系统。它们主要用于提出研究问题：如果缺乏写入准入、实际使用反馈和受治理的遗忘机制，记忆库是否会随着运行时间增加而退化？

### 1.3 核心问题

本研究将宏观的“大模型记忆系统研究”收敛为三个相互关联的问题：

1. **写入问题**：什么样的信息才值得进入长期记忆？
2. **表示问题**：长期记忆是否必须保存完整内容，能否由指针或现场重建替代？
3. **演化问题**：如何依据真实使用与验证结果进行巩固、降级和遗忘，使记忆系统长期保持有效？

### 1.4 研究意义

#### 理论意义

- 将记忆价值从“历史相关性”转向“不可再推导性”，补充以检索相似度为中心的记忆定义。
- 建立内容记忆、定位记忆与现场求解能力之间的统一分析框架。
- 将记忆规模与求解能力纳入同一优化目标，探索“减少记忆、增强能力”的适用条件与边界。

#### 工程意义

- 降低无效写入、重复存储、误召回和上下文注入成本。
- 提高用户偏好、历史否决和有代价教训等关键经验的可持续复用能力。
- 为长期运行智能体提供可解释、可审计、可删除的记忆治理路径。

## 二、研究现状与横向比较框架

### 2.1 主要研究路线

本研究将现有大模型记忆方案归纳为以下路线：

| 路线 | 基本思路 | 需要重点考察的问题 |
|---|---|---|
| 检索增强记忆 | 对历史内容建立向量、全文或混合索引，按需检索 | 是否缺少写入准入，是否把过程轨迹误作经验 |
| 分层／操作系统式记忆 | 将上下文、核心记忆与外部归档分层管理 | 层间迁移依据、长期维护成本、信息保真度 |
| 摘要与巩固 | 将会话压缩为摘要，逐步沉淀高层经验 | 摘要损失、错误累积、来源追溯 |
| 图谱与时序记忆 | 以实体、关系、事件及有效时间组织记忆 | 构建成本、冲突处理、时间一致性 |
| 认知架构式记忆 | 区分工作、情景、语义和程序记忆 | 类型边界、跨类型协作、实际任务收益 |
| 自我进化与技能记忆 | 将成功过程转化为技能、程序或工具能力 | 验证门禁、负向经验、能力与内容记忆的边界 |

MemGPT/Letta、Mem0、Zep/Graphiti、Claude mem 及其他代表性方案将作为后续调研候选。正式比较前须核验版本、论文、代码、接口和公开证据；对任何系统失败模式的描述均须来自可追溯资料或本研究复现实验，不以个案印象替代结论。

### 2.2 横向比较维度

横向研究不采用功能数量评分，而采用统一机制矩阵：

| 比较维度 | 核心观察项 |
|---|---|
| 写入 | 全量捕获、规则筛选、模型筛选或价值准入 |
| 表示 | 原文、摘要、向量、图、指针、程序或参数 |
| 检索 | 相似度、时间、频率、图遍历、确定性定位或混合路由 |
| 巩固 | 摘要压缩、反馈验证、使用驱动升级或技能化 |
| 遗忘 | 永久保留、时间衰减、容量淘汰或分阶段退出 |
| 冲突 | 来源、版本、有效时间、矛盾检测与仲裁 |
| 重建 | 是否支持不依赖保存答案的现场求解 |
| 评价 | 检索准确率、任务成功率、成本与长期漂移 |

### 2.3 现有研究的待补充空白

本研究重点检验一个尚缺少充分联合实证的命题：一条信息是否值得写入、应以何种形态保存、何时退出，以及何时应由能力替代记忆，可能需要统一的记忆—能力协同机制，而不能分别由写入器、检索器和遗忘器独立决定。

## 三、核心概念与理论框架

### 3.1 残差记忆

设基础模型能力为 \(K\)，代码与文档等单一事实源为 \(D\)，现场检索、重算和逆向解析能力为 \(R\)。信息的不可再推导性表示为：

\[
H(x\mid K,D,R)
\]

进一步考虑写入、存储、检索、误召回和维护成本 \(C(x)\)，可将记忆价值的概念模型表示为：

\[
V(x)=H(x\mid K,D,R)-C(x)
\]

该公式是理论抽象，不直接假设能够计算真实信息熵。实验中通过删除测试、重推测试、现拆测试、后续任务引用率及单位成功任务成本进行操作化。

### 3.2 记忆准入分类

**默认拒绝的四类信息**：

1. 基础模型能够直接推导的通用知识；
2. 单一事实源已经承载且可直接读取的事实；
3. 检索结果、搜索结果和工具调用日志等过程轨迹；
4. 可以通过读代码、运行程序或逆向解析现场恢复的实现细节。

**允许进入候选的四类残差**：

1. 用户偏好与用户否决；
2. 附实际成本的经验教训；
3. 无法由当前上下文持久保存的外部世界状态；
4. 带适用条件的负向决策，即“曾经尝试且不可行”。

### 3.3 三种记忆形态

| 形态 | 保存内容 | 求解方式 | 研究意义 |
|---|---|---|---|
| 指针型 | 问题签名、项目／目录／章节锚点、模块入口 | 定位后读取或调用工具 | 以较少内容维持长期可定位性 |
| 联想型 | 核心节点及相邻／相似案例关系 | 图扩散或相似检索 | 支持跨任务经验迁移 |
| 零记忆 | 不保存答案，仅保留可调用的求解方法 | 现场重建 | 用能力替代可再推导的内容记忆 |

对于确实不可再推导且必须原样保留的信息，仍允许内容型记忆。三种形态并非绝对替代关系，而是按“能现场重建则不写、能定位则只存指针、必须原样保留才存内容”的顺序选择。

### 3.4 短期与长期记忆的系统映射

| 层次 | 主要载体 | 核心职责 |
|---|---|---|
| 当前工作上下文 | 会话状态与任务状态 | 支撑当前任务推理与执行 |
| 短期／近期经验 | 原认知经验库 | 快速复用近期且可能再次使用的经验 |
| 长期定位记忆 | 记忆树 | 保存“去哪里找”的稳定结构 |
| 长期内容记忆 | 高置信、不可再推导的残差 | 保存用户否决、代价教训和外部状态 |
| 长期记忆替代能力 | REA 逆向解析及其他现场工具 | 对可重建信息不保存答案，按需恢复 |

本研究认为，短期与长期的区别不应只有保存时长，还包括表示形态、检索路径、验证方式和退出机制。

### 3.5 记忆—能力替代关系

记忆数量与现场求解能力可能互为替代：工具能力增强后，一部分原本需要保存的实现细节可以退出内容记忆；记忆树保留定位信息，现场工具负责恢复细节。该关系不是“所有记忆都应删除”，其边界由重建成功率、重建成本、错误代价和任务时限共同决定。

## 四、研究目标、研究问题与假设

### 4.1 总体目标

构建并验证一套面向长期运行智能体的残差记忆架构，使系统能够依据信息的不可再推导性选择记忆形态，通过短期经验、长期定位和现场重建协同完成任务，并依据真实使用反馈持续巩固或遗忘。

### 4.2 具体目标

1. 建立可执行、可审计的记忆准入判据。
2. 建立内容、指针、联想与零记忆之间的选择机制。
3. 建立记忆检索与现场求解协同的分层级联。
4. 建立使用驱动的质量升级和分阶段遗忘机制。
5. 建立横向跨系统与纵向长周期结合的评测方法。

### 4.3 研究问题与假设

| 研究问题 | 研究假设 | 主要验证方式 |
|---|---|---|
| RQ1：残差准入能否减少无效记忆？ | H1：与全量捕获相比，残差准入能够降低噪声接纳率和存储增长，并提高记忆实际引用率 | 写入对照、人工标注、后续任务流验证 |
| RQ2：指针与现场重建能否替代内容记忆？ | H2：对可再推导信息，删除内容记忆不会显著降低任务成功率，且综合成本可接受 | 删除测试、重推测试、现拆测试及消融实验 |
| RQ3：使用驱动的巩固与遗忘是否优于永久保留？ | H3：使用反馈与分级遗忘能够降低过期记忆残留，同时控制有用记忆误删率 | 长周期任务流与不同遗忘策略比较 |
| RQ4：记忆与能力能否形成正向协同？ | H4：记忆规模下降与现场重建成功率提升可以共同改善单位成功任务成本 | 联合趋势分析与组件消融 |

H4 是探索性总假设，不预设“记忆越少越好”。若实验表明某些内容必须长期保存，应据此修正理论边界。

## 五、主要研究内容

### 5.1 残差准入机制

研究删除测试、重推测试和现拆测试的自动化判定方法，分析误接纳与误拒绝的代价，形成可审计的准入日志。重点避免将检索和工具调用过程再次写回记忆库形成写放大。

### 5.2 记忆表示与转换

研究内容记忆向指针、联想关系或零记忆转换的条件，以及指针失效、代码变化和文档迁移后的更新方法。对必须原样保存的用户偏好、否决和高代价教训，保留来源与适用条件。

### 5.3 D0—D4 求解级联

1. **D0：经验检索**——从短期／近期记忆中检索可复用经验；
2. **D1：长期定位**——命中记忆树节点，展开对应文档或模块；
3. **D2：邻近扩展**——沿同项目、同目录或相邻节点进行确定性扩展；
4. **D3：现场重建**——调用逆向解析、代码阅读或运行实验恢复答案；
5. **D4：外部求解**——仍无法解决时开展外部调研，并分流为工具能力增强或记忆树更新。

研究重点包括级联的停止条件、误命中处理、路径成本及各层对最终任务结果的贡献。

### 5.4 记忆巩固与可控遗忘

研究记忆被检索、实际引用和验证后的质量更新，比较永久保留、单一时间衰减和使用驱动的分级遗忘。遗忘过程分为退出检索索引、宽限观察、树梢痕迹保留和主记录删除，并测量误遗忘、重学收益与审计可追溯性。

### 5.5 失败驱动的能力缺口闭环

当现场重建失败或成本超过任务约束时，不自动把答案写入记忆，而是将同类失败聚合为能力缺口。研究“应当补记忆还是补工具”的决策边界，以及工具增强后历史内容记忆的退出机制。

## 六、研究方法与技术路线

### 6.1 总体研究策略

采用“内部案例审计—理论建模—对照实验—纵向任务流—消融分析—跨系统比较”的组合方法。先明确构念和评测协议，再积累数据，避免根据已有系统倒推不可证伪的结论。

### 6.2 任务集设计

第一阶段以真实软件工程智能体任务为主，覆盖：

| 任务类型 | 主要考察能力 |
|---|---|
| 重复缺陷修复 | 高价值教训复用与重复错误抑制 |
| 用户偏好延续 | 不可推导偏好的跨会话保存 |
| 历史负向决策遵守 | 已否决方案的检索与适用边界 |
| 跨会话模块定位 | 记忆树与指针型记忆效果 |
| 无内容记忆重建 | 现场工具替代能力 |
| 外部状态查询 | 世界状态的真实性与时效性 |
| 冲突／过期信息处理 | 版本、有效时间与冲突仲裁 |
| 长周期混合任务流 | 记忆增长、遗忘、成本和性能漂移 |

任务应同时包含必须记忆、可以重建和不应写入三类样本，否则无法评价准入机制。

### 6.3 对照组与基线

拟设置以下对照：

1. 无长期记忆；
2. 全量历史或全量自动捕获；
3. 普通检索增强记忆；
4. 摘要式分层记忆；
5. 至少一种可复现的代表性智能体记忆系统；
6. 残差记忆完整方案。

外部系统基线的选择以可安装、可固定版本、可运行任务和可采集指标为准。无法公平复现的系统仅进入定性机制比较，不进入数值排名。

### 6.4 消融实验

- 去除残差准入；
- 去除记忆树；
- 去除现场重建；
- 去除使用反馈与验证；
- 去除分级遗忘；
- 仅保留内容记忆；
- 仅保留指针与现场重建；
- 将能力缺口工单改为普通失败记忆。

### 6.5 指标体系

| 维度 | 指标示例 |
|---|---|
| 写入质量 | 残差保留率、噪声接纳率、重复率、写入拒绝准确率 |
| 检索质量 | 有用召回率、误召回率、实际引用率、上下文有效率 |
| 任务效果 | 任务成功率、重复错误率、人工接管率、偏好遵守率 |
| 成本 | Token、延迟、存储、工具调用次数、单位成功任务成本 |
| 遗忘 | 有用记忆误删率、过期记忆残留率、重学成本 |
| 重建 | 重建成功率、重建耗时、失败类型及成本分布 |
| 长期演化 | 记忆规模增长率、性能随任务轮次变化、长期漂移 |

### 6.6 纵向研究设计

纵向研究同时跟踪单条记忆与整个系统：

- 单条记忆：产生原因、检索次数、实际采用次数、验证结果、质量变化、形态转换、退出时间和删除后的可重建性；
- 整个系统：任务成功率、记忆规模、误召回、存储与 Token 成本随连续任务轮次的变化；
- 能力变化：同类问题由“依赖内容记忆”转为“现场重建”的比例及其净收益。

### 6.7 统计与复现

- 固定模型、系统提示、工具版本、任务集和上下文预算；
- 对随机性任务进行多次独立运行；
- 对相同任务的不同方案采用配对比较；
- 报告置信区间、效应量和失败案例，不只报告平均值；
- 预先区分验证性假设与探索性发现；
- 保存代码提交号、配置、数据快照标识、原始输出和评价记录；
- 对涉及多重比较的指标进行相应校正。

## 八、预期创新点

1. **记忆价值定义创新**：以不可再推导性而非历史发生或语义相似度作为记忆准入的核心依据。
2. **记忆形态创新**：将内容、指针、联想与零记忆纳入统一选择框架，长期记忆不再等同于长期保存全文。
3. **架构创新**：通过短期经验、记忆树和现场重建的级联，实现记忆检索与求解能力协同。
4. **治理创新**：将真实使用、验证、升级、退出索引和痕迹保留纳入同一生命周期。
5. **评价创新**：同时衡量任务效果、记忆污染、长期维护成本和现场重建能力，避免只用检索准确率评价记忆系统。

上述内容为拟验证的创新点，最终贡献以文献查新和实验结果为准。

## 九、研究基础与可行性

### 9.1 已有基础

DreamBuddy 已形成认知记忆工具链，包括记忆检索、记录、验证、质量分级、遗忘调度和逆向解析等组件；现有残差记忆设计进一步明确了四禁入、四残差、三测试、三种记忆形态、D0—D4 级联和分级 TTL，为研究提供了可操作的工程对象。

### 9.2 数据基础

系统持续运行能够产生跨会话任务、记忆检索、实际引用、验证和失败归因数据。已有异常记忆库可作为污染与写放大问题的历史案例，但后续实验需要单独建立干净、可追溯的数据快照，避免将历史污染与实验处理混杂。

### 9.3 风险边界

部分机制已经实施，部分仍处于设计或待验证状态。研究记录必须逐项标注“已实现、已接线、已验证、待实施”，不得把 SPEC 中的目标状态直接写成实验结果。

## 十、数据采集与管理方案

每次实验保留以下最小记录：

```text
任务输入与任务类型
→ 系统／模型／工具版本
→ 记忆候选与准入决策
→ 检索和求解路径
→ 记忆是否实际使用
→ 任务输出与成功判定
→ Token、延迟、存储和工具调用成本
→ 验证、失败归因与人工复核
→ 升级、形态转换、遗忘或能力缺口
```

数据管理要求：

- 对任务、记忆和运行分别设置稳定标识；
- 保存原始记录，不只保存聚合指标；
- 评价集与调参集分离；
- 用户偏好及外部状态数据按需脱敏；
- 公开数据前进行隐私、密钥和专有代码检查；
- 所有图表能够追溯到原始实验记录。

## 十三、可能风险与应对措施

| 风险 | 具体表现 | 应对措施 |
|---|---|---|
| 研究范围过大 | 同时覆盖架构、治理、遗忘、隐私和全部外部系统 | 主论文聚焦 RQ1—RQ3，其余形成后续研究 |
| 基线不公平 | 外部系统版本、任务接口和预算不一致 | 固定版本与预算，不能复现者只做定性比较 |
| 残差判定主观 | 不同评价者对“可再推导”判断不一致 | 制定操作手册，抽样人工复核并报告一致性 |
| 重建成本过高 | 现场解析耗时或工具调用过多 | 记录完整成本，比较保存与重建的盈亏平衡点 |
| 误遗忘关键经验 | 用户否决和负向决策被错误删除 | 高价值残差保护、宽限期、删除测试与可审计机制 |
| 评价器偏差 | 自动评价偏向本系统输出风格 | 盲评、人工抽样、多指标与失败案例分析 |
| 历史数据污染 | 既有噪声影响新实验 | 隔离实验快照，区分历史审计与正式实验数据 |
| 结论外推过度 | 软件工程结果直接外推所有智能体 | 明确领域边界，后续增加其他任务域验证 |

## 十四、伦理、隐私与结论边界

本研究涉及用户偏好、外部世界状态和历史决策等敏感记忆，应支持来源追踪、访问控制、脱敏和可删除机制。对外公开数据时必须移除身份信息、凭证和专有内容。

第一阶段结论仅适用于所选模型、工具、预算和软件工程任务分布。记忆减少不必然带来性能提升，现场重建也不必然优于内容检索；研究应报告不利结果和失败条件。对于高错误代价任务，应优先保证可靠性与可恢复性，而非单纯追求记忆规模下降。
