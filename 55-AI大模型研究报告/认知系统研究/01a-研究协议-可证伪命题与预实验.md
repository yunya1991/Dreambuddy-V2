# 第一部分：可证伪命题

> 规则：每条命题必须同时给出「否证条件」。没有否证条件的表述不进入本文件。
> 阈值均为预实验阶段的暂定值，正式实验前须在预注册中固定，不允许看到结果后再调。

## P1（表示）：指针 / 零记忆在可再推导信息上不劣于内容记忆，且综合成本更低

- **来源**：文献矩阵 §2.1 第 1 条——三篇均未把指针与零记忆作为一等形态。
- **自变量**：记忆形态（内容型 / 指针型 / 零记忆）。
- **因变量**：任务成功率、综合成本（Token + 工具调用次数 + 时延 + 存储）、重建成功率。
- **适用子集**：信息满足「可由事实源或现场求解恢复」的任务，不含用户偏好与负向决策。
- **否证条件（任一成立即否定）**：
  1. 在可再推导子集上，指针组或零记忆组成功率比内容组低 **≥10 个百分点**；
  2. 即使成功率非劣，综合成本中位数**高于**内容组；
  3. 重建成功率低于预注册下限（暂定 80%），说明「重建」尚不构成可用替代。
- **最小实验**：CASE-20261117 的 T-B / T-C / T-D（见第二部分）。
- **当前证据**：1 个定性案例，仅能支持「内容型复制会漂移」，不能支持成功率差异。

## P2（遗忘）：在存在过期信息时，使用驱动分级遗忘降低过期残留，且不显著提高误删

- **来源**：文献矩阵 §2.1 第 2 条——Zep 只失效不删除、Mem0 仅显式覆盖、A-MEM 无遗忘，三篇均未度量误遗忘。
- **自变量**：遗忘策略（永久保留 / 单一 TTL / 使用驱动分级遗忘）。
- **因变量**：过期记忆残留率、有用记忆误删率、任务成功率、重学成本。
- **操控**：向记忆库注入约 20% 已过期条目（由事实源变更造成，可判定真值）。
- **否证条件（任一成立即否定）**：
  1. 分级遗忘相对永久保留的残留率下降 **<5 个百分点**（低于噪声/实施成本）；
  2. 分级遗忘导致任务成功率下降 **>3 个百分点**，且下降来自误删有用记忆；
  3. 误删率与残留率同向上升（说明策略无法区分二者）。
- **最小实验**：后续论文 02 的长周期任务流；本阶段只做协议与注入工具，不跑正式实验。
- **当前证据**：CASE-20261117 提供一次「过期结论主动致害」的观察，不构成策略比较。

## P3（准入）：以不可再推导性为准入判据，相比显著性抽取降低噪声接纳与写放大

- **来源**：文献矩阵 §2.1 第 3 条——Mem0 以显著性与互补性为准，无系统采用不可再推导性判据。
- **自变量**：准入规则（全量捕获 / 显著性抽取 / 残差准入）。
- **因变量**：噪声接纳率、后续任务实际引用率、存储增长率、有用召回率。
- **真值来源**：人工标注 + 事实源复核（每条候选标注「可再推导 / 不可再推导 / 过程轨迹」）。
- **否证条件（任一成立即否定）**：
  1. 残差准入的**有用召回率**下降幅度大于噪声接纳率下降幅度，导致净任务成功率下降；
  2. 实际引用率相对显著性抽取**无提升**（差异 <3 个百分点）；
  3. 存储增长率的下降主要来自误拒绝不可再推导信息（误拒绝率 >10%）。
- **最小实验**：三组写入对照 + 同一批后续任务流；指标沿用开题报告 §6.5。
- **当前证据**：内部基线（315,471 条中 96.98% 为检索轨迹）支持「问题存在」，不支持方案有效。

## P4（评价）：联合成本口径会改变系统排序，存在「准确率更高但单位成功任务成本更差」的系统

- **来源**：文献矩阵 §2.1 第 4 条——现有基准以 accuracy/F1 为主，Zep 另报延迟与上下文 Token，但无人做排序对比。
- **自变量**：评价口径（单一准确率 / 单位成功任务成本）。
- **因变量**：系统排序、排序反转数量（Kendall τ）。
- **否证条件（任一成立即否定）**：
  1. 所有被测系统在两口径下排序完全一致（τ = 1）；
  2. 出现的反转全部落在置信区间内（不可区分），即「反转」是噪声。
- **最小实验**：同一任务集跑 ≥3 个基线 + 本方案，双口径排序；样本量与任务集在阶段二固定。
- **当前证据**：无。这是方法论命题，需要多系统数据，优先级低于 P1。

## 统计与预注册纪律

- 每条命题的否证阈值、样本量、随机化方式在运行前写入预注册文件，运行后不得修改。
- 配对比较优先（同一任务不同条件）；报告 Wilson 置信区间与效应量，不只报均值。
- 多命题共用同一任务集时，对 p 值做 Holm 校正。
- 预实验只判定「是否具备区分度」与「日志是否完整」，**不用于确证命题**。

# 第二部分：预实验协议 T-A ~ T-D

## 2.1 目的

把 CASE-20261117 从「单案例叙事」升级为「可复现的 RQ2 对照任务」：检验记忆**形态**（而非数量）是否影响诊断正确率与修复成本。主检验 P1，附带观察 P3。

## 2.2 任务定义

给智能体一个运维诊断任务（**等价变体**，非原生产环境）：

> 某前端服务被观测到「同一页面时好时坏、部分接口 400、卡片一直骨架屏」。请在只读事实源中定位原因，并给出修复动作。

**正确答案的四项事实**（评分锚点）：

1. 存在两个前端实例，分别监听 3101 / 3102；
2. 其中一个实例的进程早于最新构建启动（旧代码在服务）；
3. 直接原因是请求被负载均衡分到未更新的实例；
4. 正确修复是**同时重启两个实例**，并核对各自启动时间。

## 2.3 四种记忆条件（自变量）

| 条件 | 提供给智能体的记忆 | 预期 |
|---|---|---|
| T-A | 过期内容记忆：「前端只有 3101 单实例，重启 `db-frontend.service` 即可」 | 误判为单实例，修复不完整 |
| T-B | 指针记忆：「先读 `systemctl list-units 'db-frontend*'`、`ss -ltnp`、Nginx upstream，再判断」，附 3 条校验清单 | 现场读取后正确 |
| T-C | 正确内容记忆：完整正确结论（两实例、需同时重启、某模板单元不可启动） | 正确，但换环境即失效 |
| T-D | 无记忆：只给任务，允许读取事实源 | 正确但探索成本高 |

**防泄题设计**：所有条件使用同一套等价变体（端口 3101/3102、单元名 `db-frontend@`、路径替换），且每轮随机更换变体参数；T-B 与 T-C 不出现与评分锚点逐字相同的表述。

## 2.4 实验环境

- 不接触生产：在本地容器/沙箱中提供只读 CLI（如 `envq`），返回预先录制的真实状态快照（unit 列表、监听端口、进程启动时间、Nginx upstream）。
- 修复动作通过沙箱内 `svc` 命令模拟，记录动作序列，不实际启停任何服务。
- 每个 run 使用独立工作目录与独立记忆目录，运行间不共享状态。

## 2.5 控制变量

- 同一模型版本、同一温度、同一上下文预算、同一提示模板、同一工具集；
- 每条件 **5 次独立运行**（预实验规模），条件顺序随机化；
- 记录每轮的变体参数与随机种子。

## 2.6 观测与评分

| 指标 | 定义 | 归属 |
|---|---|---|
| 诊断正确率 | 四项事实全部命中记为 1，否则 0 | 任务效果 |
| 修复动作正确性 | 是否同时重启两个实例且未触碰禁用单元 | 任务效果 |
| 误操作数 | 触发了错误单元的重启/启用次数 | 任务效果 |
| 事实源读取次数 | `envq` 等只读命令调用次数 | 成本 |
| 完成耗时 | 从任务下达到给出结论 | 成本 |
| Token 消耗 | 输入+输出总量 | 成本 |

- 双人盲评 20% 样本（评分者不知道条件分组），报告 Cohen's κ；κ < 0.6 时先修评分手册再继续。

## 2.7 日志字段（对齐开题报告 §10）

```text
run_id, task_variant, condition, model_version, temperature, seed
→ 提供的记忆快照（哈希）
→ 工具调用序列（命令、返回摘要、时间戳）
→ 诊断结论原文
→ 四项事实命中情况（逐项布尔）
→ 执行的动作序列
→ 成功判定、误操作数
→ token、耗时、读取次数
→ 评分者、评分时间、分歧备注
```

## 2.8 分析与判定

- 主分析：T-B / T-C / T-D 与 T-A 的诊断正确率配对差异（McNemar 或 Fisher 精确检验），报告 Wilson CI。
- 预实验通过标准（仅判区分度）：T-A 的错误率明显高于 T-B/T-C/T-D，且差异大于同一条件下 5 次运行的波动。
- **Kill criteria**：若 T-A 与 T-B 无差异，说明任务对记忆形态不敏感 → 优先怀疑任务过易或提示过强，改任务后再试；连续两轮仍无区分度，则本案例不能作为 P1 的支撑证据。

## 2.9 伦理与安全

- 全程只读优先；任何写动作只在沙箱模拟器内生效。
- 不使用真实凭证、不接入生产主机、不记录密钥。
- 案例中涉及的主机与 unit 名在对外材料中做匿名化替换。

## 2.10 局限声明

- 单案例、单领域（软件工程运维），不能外推到其他任务域；
- 任务规模小，可能受模型先验影响（预训练中见过类似 systemd 排障模式），需通过等价变体与盲评降低；
- 预实验结论只用于决定「是否值得进入阶段四正式实验」，不作为论文主结果。

# 第三部分：REA 逆向解析在研究中的角色

> 结论先行：REA 适合做**测量工具与任务生成器**，不适合做**效果证明**。它是 P1「零记忆/指针记忆」能否被实验的前提，但一旦同时充当处理与评分，就会形成自证循环。

## 3.1 三种角色

| 角色 | 用途 | 对应位置 |
|---|---|---|
| 仪器（instrument） | 作为 D3 现场重建的可执行实现，测量重建成功率、证据定位率、Token 与时延 | P1；T-B / T-D 条件 |
| 任务生成器 | 从真实代码库生成「可再推导事实」题目与真值（调用链、字段来源、配置生效点），避免人工编题偏差 | 阶段二任务集 |
| 案例来源 | 把 CASE-20261117 的等价变体迁移到代码事实域（如「某状态字段由谁写入」），扩大样本 | 案例库 |

**为什么必须有仪器**：若「零记忆」条件没有可调用的重建能力，P1 无法被检验——它退化成「不给信息也不给工具」，测到的是信息缺失而不是重建能力。REA 的 submit/poll/snapshot 接口可以直接充当该仪器。

## 3.2 反循环约束（硬性）

1. **真值不由 REA 单独裁定**：题目真值来自代码、测试或人工标注；REA 输出只作为「候选重建结果」参与评分。
2. **独立校验**：20% 样本由人工或独立脚本（grep/AST）盲评，报告与 REA 评分的一致性（Cohen's κ）。
3. **失败必须报告**：重建失败、证据定位错误、超时全部计入分母，不允许只报成功案例。
4. **冻结版本**：记录 REA 版本、代码 snapshot 哈希、索引时间；跨实验不得升级。
5. **不得作为 Related Work 的比较对象**：REA 是内部工具，不能与其他记忆系统并列排名，否则违反开题报告 §6.3 的公平性要求。

## 3.3 指标接入

| 指标 | 定义 | 数据来源 |
|---|---|---|
| 重建成功率 | 重建结果与真值一致的比例 | REA 输出 + 独立校验 |
| 证据可定位率 | 给出的 file:line 能直接支撑结论的比例 | 人工抽样 |
| 重建成本 | Token、时延、工具调用次数、索引/扫描开销 | REA 运行日志 |
| 失败类型分布 | 未找到 / 找到但错 / 超时 / 需要运行实验 | 人工归类 |

## 3.4 可复现性要求

外部无法运行 REA，因此论文必须公开：任务集、真值、提示模板、评分脚本与判定标准；REA 只作为「本研究的一种实现」披露，允许他人用等价工具替换。否则 P1 的结论不可复现。

## 3.5 适用边界

REA 只覆盖**代码与工程事实**（调用链、数据来源、配置生效、依赖关系），不覆盖用户偏好、历史否决与外部世界状态。论文中 P1 的结论必须限定在这一子域，不得外推到全部记忆类型。
