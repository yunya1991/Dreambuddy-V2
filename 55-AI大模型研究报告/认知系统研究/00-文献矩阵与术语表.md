### 2.1 与本研究的关键差异（精读后修订）

1. **表示维度**：MemGPT、Mem0、Zep、A-MEM、Claude 五项均未把指针型、零记忆作为一等形态。最接近「可重建」的有三条：MemGPT 被驱逐消息仍永久留在 recall 可读回、Zep 的 episode 非失真落库、Claude 的 just-in-time `view`。但三者都是「保存内容再取回」，不是「不保存答案、按需重建」。
2. **遗忘维度**：Zep 只做失效（`t_invalid`）不删除，失效边仍进入检索；Mem0 只有显式 DELETE/UPDATE，无 TTL/衰减/淘汰；A-MEM 完全没有遗忘机制且存储 O(N)；MemGPT 驱逐后原文仍可读回；Claude Memory Tool 无 TTL，仅建议定期手动清理。五项**都未把「过期记忆主动致害」作为设计前提**，也未度量误遗忘率与过期残留率。唯一的版本/并发机制出现在 Claude Managed Agents（不可变版本 + `content_sha256` 乐观并发），但那属于数据完整性，不是遗忘。**例外**：MemOS 文档给出五态遗忘（Generated→Activated→Merged→Archived→Expired）与版本链/回滚，是目前唯一显式设计遗忘生命周期的候选；但其论文与实现一致性未核验、未复现，论文中应表述为「少数例外」而不是「无人研究」。
3. **准入维度**：Mem0 的四操作以「显著性与互补性」为准，A-MEM 由 LLM 生成关键词/标签后建链，Zep 由 episode 全量入图；MemGPT 由模型自主决定写什么，Claude 默认把工具结果写入记忆文件。**没有一项以「不可再推导性」作为准入判据**，也没有对检索轨迹、工具调用日志设置禁入约束——恰恰相反，Claude 的 context editing 会把工具结果转存进记忆。
4. **评价维度**：DMR / LongMemEval_s / LoCoMo 均以 accuracy / F1 / BLEU / LLM-judge 为主；Zep 额外报告延迟与上下文 token，但仍无「单位成功任务成本」「过期残留率」「重建成功率」的联合口径。

以上四条即主论文 §8 创新点的差异化依据。它们现在有原文支撑，但仍属**设计动机**，不是效果证明。

### 2.2 精读补记（供 Related Work 直接引用）

**MemGPT（arXiv:2310.08560）**

- 分层：§2.1/§2.2 主上下文 = 只读 system instructions + 固定大小读写 working context + FIFO queue（首位放 recursive summary）；外部 = recall（"entire history of events"）+ archival（可读写溢出）。
- 自编辑：§2.3 记忆编辑与检索 "entirely self-directed"；工具为 working_context append/replace 与 recall/archival search（Fig.2/4/6）。recall 由 queue manager 写入（§2.2），archival 在实验中靠文档上传。
- 冲突：**无**判定、无版本、无有效性字段，working context 仅 "unstructured text"（§2.1）；纠正靠模型自行 replace。
- 遗忘：超过 warning token count 发 memory pressure，达 flush token count 驱逐 50% 窗口并生成新 recursive summary（§2.2）；被驱逐消息 "stored indefinitely in recall storage"，可读回。遗忘未被作为独立问题研究。
- 检索：archival 走向量（cosine + pgvector HNSW），recall 走关键词 + 时间戳；结果分页（"10 of 124 results"），无 top-k、无 rerank。
- 空白：TTL、容量淘汰、误遗忘、过期检测、冲突消解、摘要保真均未涉及。

**Claude Memory Tool / Managed Agents Memory（官方文档，2026）**

- Memory Tool 是 **client-side**：Claude 只发操作请求，应用负责实际存储；`/memories` 只是前缀。命令 `view/create/str_replace/insert/delete/rename`，模型自主调用，API 自动注入 system prompt 要求先 `view`。
- 冲突与遗忘：**无**冲突检测、版本、有效性时间；`str_replace` 要求 `old_str` 唯一。**无** TTL/淘汰/自动清理，官方仅建议 "Periodically delete memory files that haven't been accessed in a long time"。
- 检索：just-in-time，不预加载；与 context editing 配合，接近清理阈值时自动告警，可先把工具结果写入 memory 再清理（`clear_tool_uses_20250919`）。
- Managed Agents 不同：memory store 挂载 `/mnt/memory/{slug}/`，单条 ≤100 kB、每 store ≤10,000 条、每 session ≤8 store；**有**不可变版本 `memver_` 与 `content_sha256` 乐观并发，可回溯/回滚/`redact`；无 validity time；满 10,000 条后写入失败，版本保留 30 天。
- 安全边界：`read_write` store 被注入会污染后续 session，参考类建议 `read_only`；路径必须拒绝 `/memories` 外与 `../`、`%2e%2e%2f`；size cap 与过期需客户端自行实现。

**Zep / Graphiti（arXiv:2501.13956）**

- 冲突处理：§2.2.3 的 Edge Invalidation，用双时间轴四字段 `t_valid/t_invalid`（事件轴）与 `t'created/t'expired`（事务轴）；"The system employs an LLM to compare new edges against semantically related existing edges to identify potential contradictions." 判定后置 `t_invalid`，**不删除旧边**，冲突以「新信息在事务轴优先」解决。
- 遗忘实现：无删除、TTL、容量淘汰或衰减，只保留关系演化史（§2.2.3）。构建提示中失效边仍与 `t_valid,t_invalid` 一起交给 LLM（§3），即**失效不等于退出检索**。
- 空白：无 invalidation 单独消融、无误遗忘度量、原文回取「not directly examined in this paper's experiments」（§2.1）。

**Mem0（arXiv:2504.19413）**

- 冲突处理：§2.1 四操作 ADD/UPDATE/DELETE/NOOP；UPDATE 为 "augmentation of existing memories with complementary information"，DELETE 为 "removal of memories contradicted by new information"；判定前取 top s=10 相似记忆交 LLM 工具调用，不用独立分类器。基础版仅文本时间戳 +「优先最新」，无有效性区间。
- 遗忘实现：仅由显式 DELETE/UPDATE 覆盖，**无时间衰减、TTL、容量淘汰**；§5 把更完善的巩固机制列为未来工作，遗忘未被当作独立问题。
- 图变体：§2.2 两阶段抽取实体与关系；冲突由 "LLM-based update resolver" 判定，旧关系 "marking them as invalid rather than physically removing"。

**A-MEM（arXiv:2502.12110）**

- 记忆结构：§3.1 笔记 `m_i={c_i,t_i,K_i,G_i,X_i,e_i,L_i}`，写入时 LLM 生成关键词、标签与上下文描述，向量由内容+属性拼接。
- 冲突处理：§3.3 **无显式判定**；记忆演化后 "The evolved memory m_j* then replaces the original memory m_j"，旧笔记被直接替换，无版本留痕。
- 遗忘实现：**未涉及**；§4.6 承认存储随规模线性增长 O(N)。附录提示词出现 `prune` 动作枚举，但正文未定义、未实现。
- 空白：冲突消解、容量淘汰、级联错误、指针型记忆与按需重建均未讨论。

## 3. 术语表（本项目口径）

| 术语 | 定义 | 明确不指 | 来源 |
|---|---|---|---|
| 残差记忆 | 仅保留不可由基础模型 K、单一事实源 D、现场求解能力 R 再推导的信息 | 不是「记忆越少越好」 | 本研究 |
| 不可再推导性 H(x｜K,D,R) | 给定模型、事实源与求解能力后，信息 x 仍未被确定的部分 | 不等同香农熵的可计算量 | 本研究（理论抽象） |
| 记忆价值 V(x) | H(x｜K,D,R) − C(x)，C 为写入/存储/检索/误召回/维护成本 | 不是线上可直接测量的分数 | 本研究 |
| 内容型记忆 | 直接保存答案或原文 | 不包括「保存去哪找」 | 本研究 |
| 指针型记忆 | 保存问题签名、锚点、模块入口等定位信息 | 不是向量索引本身 | 本研究 |
| 联想型记忆 | 保存核心节点及相邻/相似关系，供图扩散 | 不等于知识图谱全部 | 本研究 |
| 零记忆 | 不保存答案，仅保留可调用的求解方法 | 不是「没有记忆系统」 | 本研究 |
| 现场重建 | 通过读代码、运行程序、逆向解析在需要时恢复答案 | 不是向量检索 | 本研究 |
| D0—D4 级联 | 经验检索→长期定位→邻近扩展→现场重建→外部求解 | 不是固定五步流程，允许提前终止 | 本研究 |
| 记忆准入 | 决定一条信息是否进入长期记忆的判定过程 | 不是写库前的格式校验 | 本研究 |
| 写放大 | 检索/工具轨迹被反复写回，导致库规模偏离真实经验增长 | 不是普通日志冗余 | 本研究（工程观测） |
| 误召回 | 检索命中但内容不适用于当前情境 | 不是「没检索到」 | 本研究 |
| 过期记忆残留 | 已被事实源推翻但仍参与检索/注入的记忆 | 不等于「长期未使用」 | 本研究 |
| 记忆漂移 | 内容型记忆与事实源不一致后仍被信任的现象 | 不是模型幻觉 | 本研究（案例归纳） |
| 巩固 | 依据使用与验证结果提升记忆质量或抽象层级 | 不是简单摘要压缩 | 本研究 |
| 分级遗忘 | 退出索引→宽限观察→痕迹保留→主记录删除的分阶段退出 | 不是直接物理删除 | 本研究 |
| 重建成功率 | 零记忆/指针路径下现场恢复正确答案的比例 | 不是检索命中率 | 本研究 |
| 单位成功任务成本 | 总成本 / 成功任务数，含 Token、延迟、工具调用、存储 | 不是单次请求成本 | 本研究 |
| 记忆流（memory stream） | Generative Agents 的全量经验记录结构 | 不等同于本研究的短期经验库 | Park et al. 2023 |
| 反思（reflection） | 由记忆流生成的更高层结论并写回 | 不等同于本研究的巩固 | Park et al. 2023 |
| 双时间轴（bi-temporal） | 同时记录事件发生时间与系统获知时间 | 不是简单时间戳 | Zep/Graphiti 2025 |
| 虚拟上下文（virtual context） | 用外部存储模拟更大上下文窗口 | 不是扩大真实上下文 | MemGPT 2023 |

## 5. 可复现性核验（R1 / R2 / R3）

分级标准：

- **R1 数值基线**：可固定版本、可离线自托管、可注入同一模型、有稳定 API，且论文与实现有版本绑定。
- **R2 定性比较**：可安装运行、可固定版本，但结果依赖 LLM 抽取、无版本绑定基准，只能做机制对照。
- **R3 不可用**：无公开实现或依赖闭源托管服务。

| 对象 | 版本·许可 | 运行门槛 | 可复现结论 | 关键理由 |
|---|---|---|---|---|
| Letta（MemGPT 工程化） | v0.16.8（2026-05-14），Apache-2.0；PyPI `letta` 最新版已变为 Letta Code CLI 包装器 | 可 pip（含 sqlite extra）或 Docker（内置 Postgres）；可接 Ollama/vLLM | **R2** | V1 server 已归档至 `archive` 分支，活跃开发迁往 letta-code；写入由 agent 自主决定，无版本/有效性字段，server 停更难以产出稳定数值 |
| LangMem | 0.0.30（2025-10-28），MIT | `pip install langmem`；store 用 InMemoryStore 或 Postgres；模型可本地 | **R2** | 无论文、无标准基准；0.0.x 且依赖区间宽松；默认内存存储、LLM 抽取非确定 |
| MemOS | v2.0.36（2026-11-09），Apache-2.0；PyPI `MemoryOS` 2.0.33 | 需 Neo4j + Qdrant（新版支持 Postgres 图存储），可 Ollama | **R2** | 有论文 arXiv:2507.03724，但论文数值未绑定 release/配置，无官方复现脚本、无第三方复现 |
| Cognee / Memobase 等 | 未核验 | — | **未评级** | 留待后续 |

**结论**：三个候选均未达到 R1，因此开题报告 §6.3 的「至少一种可复现的代表性记忆系统」应改为**机制级对照 + 统一自测基线**，不承诺复现他方数值。若要升 R1，唯一路径是固定 commit + 本地模型 + 自建评分器，且只能称「自测基线」。

**新发现（需回写矩阵）**：MemOS 文档描述五态遗忘（Generated→Activated→Merged→Archived→Expired，按访问频率与时间衰减）与冲突版本链/回滚。这是目前唯一显式给出遗忘生命周期的候选，虽然未复现，但**削弱了「现有系统都不研究遗忘」的强表述**；论文中应改为「主流开源方案以失效/覆盖为主，MemOS 是少数例外，但其论文与实现一致性未核验」。
