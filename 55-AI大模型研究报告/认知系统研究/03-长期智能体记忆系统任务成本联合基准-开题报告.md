# 后续论文二开题报告：长期智能体记忆系统的任务—成本联合基准

> **论文序列**：第三篇（后续论文二），与主论文及记忆治理论文相互独立  
> **研究题目**：Beyond Retrieval Accuracy：长期运行智能体记忆系统的任务—成本联合评测  
> **英文题目**：Beyond Retrieval Accuracy: A Task–Cost Benchmark for Long-Running LLM Agent Memory Systems  
> **研究对象**：代表性大模型记忆系统及 DreamBuddy 认知记忆系统  
> **版本**：v0.1（开题稿）  
> **日期**：2026-11-16  
> **研究阶段**：评测框架设计阶段，尚未开展系统排名或形成比较结论

---

## 摘要

现有智能体记忆系统评价常侧重检索准确率、单次问答正确率或特定长期对话数据集，但检索到相关信息并不等于智能体能够正确使用信息，也不反映持续写入、记忆污染、遗忘、冲突处理和长期运行成本。不同系统若在模型、上下文预算、工具权限、任务接口和调参程度上不一致，简单数值排名容易产生误导。

本研究拟构建面向长期运行智能体的任务—成本联合基准，将记忆系统置于连续任务流中，统一测量任务成功率、记忆实际贡献、错误记忆干预、用户偏好遵守、冲突与过期信息处理、Token、延迟、存储和人工接管成本。基准包含单任务对照、跨会话依赖、长周期演化和压力测试，并采用资源预算约束、配对实验、消融分析和 Pareto 前沿，而非以单一综合分数掩盖系统取舍。DreamBuddy 将作为参评系统之一，接受与外部系统相同的任务、预算和评价协议。

研究预期形成一套可复现的任务集、运行协议、指标体系和评价工具，为记忆系统研究提供超越检索准确率的比较基础。

**关键词**：大模型智能体；记忆系统；基准评测；长期任务；任务成功率；运行成本；可复现性

## 一、研究背景与问题提出

### 1.1 研究背景

记忆系统评价需要同时回答三个层次的问题：

1. **信息层**：正确信息是否被保存和检索？
2. **行为层**：智能体是否因该信息采取了更合适的行动？
3. **系统层**：这种行为收益需要多少存储、Token、延迟和维护成本？

仅在信息层评价，可能高估“检索到但未使用”的价值，也可能遗漏“未检索到但可现场重建”的能力。仅在单次任务评价，则无法观察记忆积累、冲突、遗忘和长期漂移。

### 1.2 现有比较的潜在失真

- 不同系统使用不同基础模型和提示词；
- 一方可以调用代码工具，另一方只能回答文本；
- 检索预算、上下文长度和写入权限不一致；
- 测试任务来自系统自身日志，存在适配偏差；
- 只报告成功样例或最优参数；
- 将功能列表比较等同于实证性能比较；
- 以单一平均分掩盖高成本、高误删或高风险失败。

### 1.3 研究意义

本研究将评价对象从“记忆检索器”扩展为“记忆增强的智能体系统”，建立任务效果与综合成本的联合评价方法。该基准既用于检验 DreamBuddy 的真实优势和劣势，也用于识别不同记忆架构各自适用的任务类型。

## 二、相关研究与评价路线

后续综述拟覆盖长期对话记忆、个性化问答、事件时序、跨会话任务、软件工程智能体和资源受限智能体等评测方向。重点关注：

| 评价路线 | 主要优点 | 需要补充的维度 |
|---|---|---|
| 检索召回评价 | 能直接测量信息定位能力 | 记忆是否被正确使用及其最终任务贡献 |
| 长上下文问答 | 数据构造和自动评分相对容易 | 行动、工具使用、连续写入和长期维护 |
| 个性化记忆评价 | 能测量用户偏好与历史事实复用 | 偏好变化、冲突、删除和隐私 |
| 智能体任务基准 | 能测量真实行动结果 | 记忆组件的独立贡献和长期成本 |
| 系统性能评价 | 能测量延迟、吞吐和资源消耗 | 与任务成功、记忆污染和遗忘联合分析 |

本研究不替代已有问答或检索基准，而是补充跨会话行动和长期维护维度。

## 三、核心概念与评测原则

### 3.1 联合评价对象

一个参评单元定义为：

\[
S=\langle M,A,T,W,B\rangle
\]

其中：

- \(M\)：基础模型及推理配置；
- \(A\)：智能体编排与提示策略；
- \(T\)：可用工具及权限；
- \(W\)：记忆写入、表示、检索、巩固和遗忘机制；
- \(B\)：上下文、时间、存储和工具调用预算。

比较记忆系统时应尽量固定 \(M,A,T,B\)，仅改变 \(W\)。若外部系统无法拆分智能体框架与记忆组件，应明确其评价粒度为“完整系统”，不得将结果全部归因于记忆模块。

### 3.2 评测原则

1. **任务结果优先**：检索指标作为诊断指标，而非唯一终点。
2. **预算透明**：公开模型、上下文、工具、时间和存储约束。
3. **公平适配**：为每个系统提供等价接入和合理调参机会。
4. **纵向观察**：测量连续任务中的写入、复用、冲突和遗忘。
5. **成本联合**：报告任务—成本 Pareto 前沿，不强行合并为单一总分。
6. **失败可见**：保留高风险失败、人工接管和不可恢复错误。
7. **可复现**：版本、配置、数据、原始输出和统计代码可追溯。

## 四、研究目标、问题与假设

### 4.1 总体目标

构建一套公平、可复现、能够区分信息检索、实际任务贡献与长期维护成本的智能体记忆系统评测框架。

### 4.2 研究问题与假设

| 研究问题 | 假设 | 验证方式 |
|---|---|---|
| RQ1：检索准确率能否代表最终任务效果？ | H1：检索指标与任务成功率仅具有限相关性，记忆实际采用和上下文干扰能够解释部分差异 | 联合测量检索、采用和任务结果 |
| RQ2：联合成本评价是否会改变系统比较结论？ | H2：仅按成功率排序与任务—成本 Pareto 分析可能得到不同的最优系统集合 | 多预算、多成本维度比较 |
| RQ3：单次任务能否代表长期记忆能力？ | H3：长期任务流能够揭示单次评测无法观察的污染、冲突和性能漂移 | 单任务与连续任务结果对照 |
| RQ4：统一协议能否提高跨系统比较的可复现性？ | H4：固定模型、预算、工具和评价流程能够降低重复实验间的不一致 | 重复运行与跨环境复现 |

以上均为待验证假设，不预设 DreamBuddy 或任何外部系统排名领先。

## 五、基准任务体系

### 5.1 基础任务类型

| 任务域 | 示例 | 核心测量 |
|---|---|---|
| 用户偏好 | 跨会话遵守表达、工具和决策偏好 | 偏好保持与不可推导信息记忆 |
| 偏好变化 | 用户更新或撤销历史偏好 | 新旧冲突和最新指令优先级 |
| 情景事件 | 复用历史任务中的具体事件与条件 | 时间、来源和细节保真 |
| 负向决策 | 避免重复推荐已否决方案 | 否决原因和适用边界 |
| 外部状态 | 查询会变化的环境事实 | 新鲜度、有效期和更新 |
| 程序性经验 | 复用已验证的问题解决方法 | 经验迁移与技能化 |
| 模块定位 | 在大型工程中定位相关文档或代码 | 指针记忆和确定性定位 |
| 现场重建 | 无保存答案时恢复实现细节 | 工具替代记忆的能力 |
| 干扰与噪声 | 加入相似、重复和无关历史 | 误召回及上下文干扰 |
| 遗忘与删除 | 信息到期、撤销或要求删除 | 检索不可见和物理删除合规 |

### 5.2 长周期任务流

任务流按阶段注入：

1. 新信息写入；
2. 相似噪声干扰；
3. 跨会话复用；
4. 信息更新或冲突；
5. 长时间未使用；
6. 再次出现相关任务；
7. 删除、重建或重学。

通过任务顺序控制，区分写入失败、检索失败、使用失败和求解失败。

### 5.3 压力测试

- 记忆规模持续增长；
- 大量重复内容；
- 近似但冲突的信息；
- 上下文预算受限；
- 工具调用受限；
- 记忆库部分损坏或索引脱钩；
- 用户显式撤回历史信息。

## 六、参评系统与运行协议

### 6.1 候选系统

候选包括 MemGPT/Letta、Mem0、Zep/Graphiti、Claude mem、普通 RAG、摘要式记忆和 DreamBuddy。最终纳入取决于：

- 是否可获取并固定版本；
- 是否具备合法、稳定的使用接口；
- 是否可在统一模型和工具条件下运行；
- 是否能采集必要的写入、检索和成本日志；
- 是否允许重复实验和公开配置。

无法公平复现的系统只进入机制分析，不进入数值榜单。

### 6.2 对照层级

1. **记忆模块对照**：在同一智能体框架中替换记忆组件；
2. **完整系统对照**：保留各系统推荐架构，但统一模型和预算；
3. **无记忆对照**：测量基础模型和工具自身能力；
4. **Oracle 对照**：提供正确记忆或定位信息，估计任务性能上界；
5. **全量历史对照**：检验简单增加历史信息的收益与干扰。

### 6.3 公平性要求

- 为各系统提供相同的任务信息和外部工具；
- 不在测试阶段向 DreamBuddy 暴露额外内部答案；
- 统一最大上下文、检索条数和工具调用限制；
- 分别报告默认配置和调优配置结果；
- 调优任务与测试任务严格分离；
- 记录失败重试，避免只保留成功运行。

## 七、指标体系与分析方法

### 7.1 任务效果

- 任务成功率与高质量完成率；
- 用户偏好遵守率；
- 历史负向决策遵守率；
- 冲突和过期信息处理正确率；
- 重复错误率；
- 人工接管率与不可恢复失败率。

### 7.2 记忆过程

- 写入准确率与噪声接纳率；
- 有用召回率、误召回率和实际采用率；
- 记忆归因贡献；
- 陈旧记忆残留与高价值误删；
- 记忆树或指针定位成功率；
- 现场重建成功率。

### 7.3 成本

- 输入／输出 Token 与记忆注入 Token；
- 端到端延迟和检索延迟；
- 存储规模及增长率；
- 工具调用次数；
- 人工审阅和接管成本；
- 单位成功任务综合成本。

货币成本仅在价格、模型和调用条件一致时报告，同时保留原始 Token 与延迟数据，避免价格变化影响结论。

### 7.4 联合分析

- 任务成功率—成本散点图；
- 多预算下的 Pareto 前沿；
- 不同任务类型的分层表现；
- 随任务轮次变化的性能与记忆规模曲线；
- 检索、采用和任务结果的关联分析；
- 失败模式和错误代价分析。

不以未经验证的加权总分替代原始指标。若提供综合分数，必须公开权重并进行敏感性分析。

### 7.5 统计方法

- 对相同任务和相同初始状态进行配对比较；
- 多次独立运行并报告方差、置信区间和效应量；
- 对多系统和多指标比较进行多重检验控制；
- 评价器与参评系统隔离，采用人工盲评抽样；
- 公开所有排除样本及排除理由。

## 八、基准数据与复现管理

每次运行保存：

```text
任务与数据版本
→ 系统、模型、提示和工具版本
→ 资源预算及初始记忆快照
→ 写入、检索、采用和行动日志
→ 最终输出及任务判定
→ Token、延迟、存储和接管成本
→ 失败归因、人工复核和统计结果
```

数据集划分为开发集、调参集和测试集；持续运行产生的数据必须按时间切分，防止未来信息泄漏。公开前进行隐私、凭证和专有信息检查。

## 十三、风险、伦理与结论边界

- **接入不公平**：系统架构差异可能使完全统一不可实现，应分别报告模块级和系统级结果。
- **评价污染**：任务不得来自某一系统独有训练或调参数据，测试集需隔离。
- **自动评价偏差**：采用盲评、人工抽样和基于行动结果的客观评价。
- **成本口径漂移**：保留原始资源数据，避免仅用变化中的货币价格。
- **隐私与删除**：公开任务不包含真实敏感信息，删除测试须区分检索不可见与物理删除。
- **结论边界**：结果只对所选模型、版本、预算和任务分布有效，不形成永久系统排名。
