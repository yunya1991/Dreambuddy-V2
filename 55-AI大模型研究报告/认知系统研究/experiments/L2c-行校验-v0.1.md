# L2c：行内容校验 + import 跟随 v0.1

> **改动**：decode 出的证据先做行内容校验（def / class / 赋值 / import），定义类问题遇到转发行时跟随 import 一跳
> **日期**：2026-11-17
> **产物**：`l2c_runner.py`、`L2c-runs.jsonl`

---

## 0. 结论先行：这是一次**负结果**，该方案应当回退

| 方案 | 正确率 | 回退率 | 平均存储 |
|---|---|---|---|
| L2b 控制组（top1<1.0，无 margin、无校验） | **95%** | 33% | 11.2 |
| L2b 采用口径（top1<1.0 且 margin<0.5） | **97%** | 37% | 11.8 |
| **L2c（加行校验 + import 跟随）** | **92%** | 43% | 13.1 |

三个指标同时变差：准确率 −3pp、回退率 +10pp、存储 +1.3 tok。

---

## 1. 两次迭代的中间数据

| 迭代 | 正确率 | 回退率 | 存储 | 说明 |
|---|---|---|---|---|
| 全类型都按"定义"校验 | 93% | 58% | 15.7 | 把"使用类"问题也按定义查，误删大量正确证据 |
| 按问题类型分流 | 90% | 43% | 13.1 | 使用类只要求"该行出现符号"，不再跟随 |
| 定义类接受 def 或 assign | 92% | 43% | 13.1 | 变量型符号不作为定义被拒 |

三次都不如不加校验的 95–97%。

---

## 2. 为什么失败

1. **"这一行是不是定义"不等于"这一行是不是答案"**。E1 的 20 题问的是调用链、字段来源、配置生效点，真值文件往往是**使用处**；按定义校验会把正确答案丢掉，再补上一个"定义正确但与问题无关"的文件。
2. **符号身份不唯一**：`adapters/base.py` 这类文件里，符号可能以参数、类属性、别名出现，正则无法区分"定义"与"提及"。
3. **import 跟随只修正了 3 题**，却因为改变了排序引入了新的错误。
4. 校验把"证据不足"变成"证据被删"，触发更多回退——回退本身不降准确率，但存储上升。

一句话：**语法级校验解决的是"这一行像不像定义"，而问题问的是"这一行能不能回答我"。**

---

## 3. 保留什么、丢掉什么

| 组件 | 处置 | 理由 |
|---|---|---|
| 行内容校验（判定证据是否相关） | **丢弃** | 对使用类问题有害，且符号别名无法处理 |
| import 跟随（仅定义类 + 纯转发行） | 可保留为窄规则 | 修正 3 题，但需限定在"该行只有 import 语句"时 |
| L2b 的分数 + margin 回退 | **保留为当前最优口径** | 97% / 37% / 11.8 |

---

## 4. 真正的修法

剩余错误（A1、A3、E2、D067、D068）都是同一类：**证据里有多个合理文件，选错了**。这不是语法问题，是"哪一行回答了这个问题"的语义问题。

可行方向按成本排序：

1. **只在非弱证据时，用 LLM 校验 top-1**（每次 1 次调用、约 300 tokens）：让它回答"这个文件/行能否支撑问题"，不行就回退。E3 已证明这类判断准确率高。
2. 用 E3 的 4 类判定结果**先确定问题类型**（定义 / 使用 / 赋值 / 依赖），再选对应的排序特征——而不是用一个统一的校验器。
3. 放弃"总能重建"的目标，接受 37% 回退率，把 RMD 定位为"该存才存"的准入器，而不是"全部都能重建"的求解器。

---

## 5. 局限

- 单次运行、60 题、40 题为模板问句。
- 行校验只做了 Python 语法的粗分类，未处理装饰器、多行赋值、`__all__` 转发。
