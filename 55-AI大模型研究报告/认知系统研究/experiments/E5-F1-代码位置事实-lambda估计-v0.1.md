# E5-F1：代码位置事实的失效风险率 λ

> **协议**：`05-残差记忆曲线-设计与E5协议` §4
> **日期**：2026-11-18
> **数据**：本仓库 git 历史，1321 commits，2026-06-09 → 2026-11-18（162 天）
> **产出**：`experiments/E5-f1.json`
> **一句话**：**代码位置事实在可观测窗口内几乎不失效（λ≈2.5e-4/天，1 年存活 91%），但事件只有 4 个且聚簇，时间维度对本类不可识别——只能报区间，不能报半衰期。**

---

## 1. 口径（先固定，否则不可复现）

| 项 | 定义 |
|---|---|
| 事实 | "符号 X 定义在文件 F 中" |
| 失效事件 | X 不再定义于 F（被移走或删除） |
| 行号漂移 | **不算失效**——grep 可给出当前行号，指针仍然可用 |
| 删失 | 到 HEAD 仍成立 |
| 时间 | 天，从快照 commit 起算 |

行号漂移不计入，是因为指针真正需要的是"去哪个文件找"，而不是"第几行"。若把行号漂移也算失效，λ 会被严重高估。

---

## 2. 抽样

| 项 | 值 |
|---|---|
| 时间窗 | t = 0 / 30 / 90 / 150 天（180 超出仓库历史 162 天，故取 150） |
| 每窗样本 | 60 |
| 总样本 | 240（其中 t=0 窗 60 条曝光为 0 天，**不进入 λ 估计**） |
| 有效样本 | 180 |
| 抽样方式 | 快照内唯一符号名，随机抽样（seed=20261118），排除 `__init__`、测试、`node_modules` |
| 目录分布 | 6-TRADING 54、11-易经推理系统 43、1-ARCHITECTURE 19，其余分散，无明显单点偏置 |

## 3. 结果

| 指标 | 值 |
|---|---|
| 事件数 / 删失数 | **4 / 176**（删失率 97.8%） |
| 总曝光 | 15,961 天 |
| λ 点估计 | **2.51e-4 / 天**（半衰期 2,766 天 ≈ 7.6 年） |
| λ 95% CI（泊松精确） | **[6.8e-5, 6.4e-4]**（半衰期 3.0–27.8 年） |
| 1 年存活 `p_eff(365)` | 0.913（区间 0.791–0.975） |
| KM 曲线 | t=32 时 S=0.983；t=145 时 S=0.966 |

分窗：

| 窗（天） | n | 事件 | λ | 说明 |
|---|---|---|---|---|
| 0 | 60 | 0 | — | 曝光 0，剔除 |
| 30 | 60 | 0 | 0 | 30 天内零失效 |
| 90 | 60 | 0 | 0 | 90 天内零失效 |
| 150 | 60 | 4 | 4.6e-4 | 全部事件集中在最老一窗 |

## 4. 判定

| 判据 | 结果 |
|---|---|
| K1（λ 的 CI 跨 0） | **未触发**——区间不含 0 |
| K5（删失 > 80%） | **触发**（97.8%）→ 只报区间，**不报半衰期点估计** |
| 时间维度是否可识别 | **不可识别**：区间跨 3–28 年，闭式解 `t*` 无法给出 |

按 K5 的纪律，本类只能表述为：**"在 1 年尺度内，代码位置事实的存活率不低于 79%（点估计 91%）"**，不能表述为"半衰期 7.6 年"。

---

## 5. 三条必须随结论一起声明的局限

1. **仓库年轻且处于高速增长期。** 162 天历史、1321 次提交，绝大多数文件是新建而非迁移。成熟代码库（有周期性重构）的 λ 会显著更高——本估计是**下界**。
2. **事件聚簇，不是 4 个独立事件。** 4 个事件中 3 个发生在同一时刻（t=32），且 2 个来自同一个文件 `scripts/sync_artifact.py`，很可能是同一次重命名/重构。有效独立事件 ≈ 2–3 个，实际不确定性比给出的 CI 更宽。
3. **最老一窗贡献了全部信息。** t=30/90 两窗零事件，说明短周期上本类事实稳定得无法测量；λ 完全由 t=150 一窗的 4 个事件撑起。

---

## 6. 对曲线的含义

`p_eff(t) ≈ 1` 在实用时间尺度上成立 → 时间项对 F1 实际上是常数。于是闭式解落在 §3.4 的 `p* ≤ 0` 分支：

> **代码位置事实一开始就该存指针，且永不转内容。**

这与设计稿的预测一致，但它**不是曲线区分能力的证据**——恰恰相反，F1 这类事实根本不需要曲线，规则「符号级代码事实 → 指针」就够了。曲线的价值只能在 λ 明显 > 0 的类别上体现（F2 配置值、F3 决策/偏好中易变的那部分）。

| 优先 | 事项 | 理由 |

| 1 | F2 配置值（`getenv` 默认值、yml/toml 键值） | 预期 λ 比 F1 高一到两个数量级，是检验时间维度的真正样本 |
