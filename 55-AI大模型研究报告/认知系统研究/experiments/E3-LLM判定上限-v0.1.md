## 1. 方法

- 输入只给 `id` 与 `text`，按固定种子打乱；判分者看不到标签、看不到 id 前缀含义。
- 四类定义与 4 条域外示例写在提示里；明确要求"不要因为出现代码符号就判 code_fact"。
- 判分者为独立上下文中的模型实例，同模型家族，未参与样本构造。
- 判定输出 `label + confidence + reason`，reason 抽查显示基于语义而非标签（如 HB19 判"函数入参个数"、A046 判"服务内网地址"）。

---

## 2. 关键发现：准确率不是问题，置信度校准才是

按置信度阈值决定"升级到更强裁决"的比例：

| 阈值 | 升级比例 |
|---|---|
| 0.80 | 12.0% |
| 0.85 | 15.2% |
| 0.90 | 29.6% |
| 0.95 | 55.2% |

原方案要求"升级比例 <5%"。用 LLM 自报置信度做路由，**做不到 5%**：要压到 5% 以下，阈值需低到 0.55 左右，等于放弃路由。

结论：**LLM 适合当 L2 的执行者，不适合当 L2 的触发器**。触发信号应来自别处（规则覆盖度、分类器 margin、OOD 检测），或干脆全量走 LLM。

---

## 3. 必须披露的四个局限

1. **同家族模型**：判分者与本研究的分析模型同源，100% 不能外推到其他模型。
2. **样本可分性过强**：125 条里没有"一句话同时断言决策与代码位置"的混合句。真实写入常是混合的，本轮没测。
3. **单次运行**：没有重复采样，无法给出方差；100% 也可能是这一次的运气。
4. **可能存在指令泄漏**：虽然已禁止判分者读取其他文件，但无法在机制上证明它没有读到标签。若要发表，应换成隔离环境重跑。

---

## 4. 对架构的含义

| 决策 | 结论 |
|---|---|
| 是否训练 L1 分类器 | **暂不训练**。上限已确认有空间，但当前瓶颈是路由而不是准确率 |
| 是否引入 LLM 做写入判定 | **可以，全量走**。写入是低频操作，不像检索在热路径 |
| 是否保留 L0 规则 | 保留。规则负责高置信段与可解释性，模型负责兜底 |
| 证据链 | 不变。判定结果仍只是路由，最终由 grep/AST/REA 探针裁定 |

成本估算（待实测）：若全量走 LLM，按每条候选 150–250 input tokens、20 output 计，日写入 1,000 条约 20 万 tokens；需在接入时用真实写入量核算。

## 7. 第二批：15 条混合句（同日补测）

### 7.1 结果

| 指标 | 结果 |
|---|---|
| 与人工主断言一致率 | **14/15 = 93.3%** |
| 唯一分歧 | M11：人工标 code_fact，判分者标 decision，置信度 0.55 |
| 低置信（<0.7） | 4/15，且**全部是人工标注时也觉得边界模糊的句子** |
| 0.7 阈值升级率 | 混合集 26.7%；E3 易集 6.4%；两批合计 8.6% |

### 7.2 对上一节结论的修正

上一节说"置信度压不到 5%"，只在**易集**上成立（0.7 阈值下为 6.4%）。加入混合句后：

- 唯一错判（M11）置信度 0.55，**会被 0.7 阈值拦下进入升级**；升级后该批可达 15/15。
- 混合集的升级率 26.7%，说明成本与"混合句占比"成正比，而不是固定 5%。

修正后的结论：

1. LLM 自报置信度**可以**做边界检测，但阈值要按类型分层，且升级预算应按任务分布估算，不应预设 5%。
2. "低置信 → 升级"能兜住实际错判，这是支持三层架构的直接证据。
3. 混合句是主要风险来源：占写入流 10% 时，升级率约 (0.064×0.9 + 0.267×0.1) ≈ 8.4%；占 30% 时约 12.5%。

### 7.3 局限

- 15 条样本量小，"主断言"由本研究单方标注，存在可争议性（M11 即为例证）。
- 判分者仍与本研究同模型家族，且为同一实例的第二轮，存在上下文延续偏差。
