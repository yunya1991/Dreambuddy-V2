## 方法评审
1. P3 直接调 SACG：C 段若返回决策但未真实调用任何能力，仍会“绿”。必须断言 C 阶段产生 ≥1 次真实业务工具调用 → P0。
2. `l2.dreamos` 默认 mock 引擎、SACG 的 C 段可能 stub：模拟结果不能计入“真实触达”，证据需 `simulated:true` 并在 AC 中排除 → P0。
3. 故障注入（S13）只写“超时/401”，未定义注入点与复现方式 → P1。
4. P1 降级到 bridge 直调后与 P2 边界模糊，需单独标记 `P1b`，且不得与 P1 合并统计 → P1。
5. S14 并发/调度场景未定义 Ticket 四模块的开启方式与“丢单”判定 → P1。

## 统计评审
1. 8 题 × 单次样本的时延对比只能作描述性报告，不能支撑“更快/更慢”的结论；若要多点估计需 n≥3 → P0（与 24 次调用上限冲突，上限需调整）。
2. 六维中 D1/D3/D4 对基线结构性为 0，合成总分必然偏向系统；**禁止总分**，必须六维分列 → P0。
