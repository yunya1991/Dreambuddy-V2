## §2 阻断项（已修复）

### B1 自检规模口径错误（文档 vs 代码）

- **现象**：文档写 17 项 / 11/11 / 8/8 三种口径；评审时点代码 `expect_ok=8`、`expect_fail=17`，合计 25 项；D1/D2 落地后为 28 项。
- **证据**：`grep -c 'expect_ok('` / `expect_fail(`；静态计数。
- **风险**：验收时无法判断「全绿」到底代表多少用例，属于可机器发现的口径漂移。
- **修复**：`total = len(ran)` 动态计数；文档统一为「四契约 20 项 + 台账/插件 8 项 = 28 项」（评审时点为 25，裁决后 +3）。
- **状态**：✅ 已修。

### B2 交易工具可绕过 Mandate（违反 ADR-04）

- **现象**：`effect=trade` 只约束 `approval ∈ {human,deny}`，`requires_mandate=false` 仍能通过。
- **证据**：构造 `effect=trade, approval=human, requires_mandate=false`，schema 校验 0 错误。
- **风险**：与 ADR-04「写操作一律 Mandate + 预算 + trace」直接冲突；G-L2-11 形同虚设。
- **修复**：`effect=trade` 的 `then` 增加 `requires_mandate: true`；新增负例 16 锁定。
- **状态**：✅ 已修（复算：该构造现被拒）。

### B3 `format: date-time` 不生效

- **现象**：`generated_at="not-a-date"` 通过 schema 校验。
- **原因**：`Draft202012Validator` 默认不启用 `FormatChecker`；span 靠自定义解析兜底，tool_set 没有。
- **风险**：时间字段可写入垃圾值，span/账本无法按时间对账。
- **修复**：`validate_tool_set` 增加 RFC3339 解析；新增负例 17 锁定。未全局启用 FormatChecker，避免影响存量台账/插件文档。
- **状态**：✅ 已修（复算：非法时间被拒）。

### B4 复算口径不一致

- **现象**：报告写「8/8」，TECHNICAL_DESIGN 写「11/11」，changelog 写「17 项」。
- **修复**：统一为「四契约 20 项正负例只读复算通过」；全量 28 项待跑。
- **状态**：✅ 已修。
