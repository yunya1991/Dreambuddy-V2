# REVIEW-CHECKLIST v0.1 — SPEC 评审六维检查清单

- 状态：✅ v0.1 落盘
- 日期：2026-11-05
- 来源：v0.3 评审（25/30）与 v0.4 双维评审（P0×5 + P1×7）的复盘结论——v0.3 评审遗漏的 5 项 P0 全部属于『资产层风险』，本清单用于堵住该盲区
- 适用范围：48-涌现架构 SPEC 每次升版评审必跑；同类跨域 SPEC（46/47/35）评审建议参照

## 0. 为什么需要本清单

v0.3 评审做的是『文档 vs 文档』一致性检查，v0.4 双维评审做的是『文档 vs 仓库现实』核验。两者差距：

| v0.4 发现的 P0 | v0.3 评审为何漏掉 |
|---|---|
| K 线停滞近 4 个月 | 未下探 19 域数据资产健康度 |
| 全仓无 polling_trader 决策回放器 | 未盘点主链可观测性基础设施 |
| workspace_bus.py 已实现但闲置 | 接受了 SPEC『未落地』自述，未做存量考古 |
| head ckpt（10-06）早于 regime 修复（11-04） | 未核对模型-数据版本时序 |
| OOD 隔离无代码强制点 | 只验证门禁『写没写』，未验证『能否被绕过』 |
| ablation gate 引用幻觉 | 未对 SPEC 引用模块做存在性核验 |

**结论：设计层风险靠读文档能发现，资产层风险必须下探仓库才能发现。**

## 1. 六维检查清单

每维含核查问题与可执行验证动作，评审时逐项打勾并留证据（命令输出/文件路径）。

### 维度 1：引用存在性

- 核查问题：SPEC 引用的模块/工具/接口是否真实存在？
- 验证动作：对 SPEC 中每个『引用现有机制』的表述，逐个 grep/ls 核验实现文件与入口函数；引用不存在的记为 P0（引用幻觉）。
- v0.4 实例：ablation gate 全仓 grep 无实现 → 从『引用』改为『明确新建』。

### 维度 2：数据资产健康度

- 核查问题：SPEC 依赖的数据源是否新鲜、连续、完整？
- 验证动作：查数据文件最新时间戳与历史覆盖区间；对时序数据跑缺口扫描（时间戳连续性）；缺口清单落盘。
- v0.4 实例：1H K 线止于 07-08 月，停滞近 4 个月 → E0b/E3/E5 公共前置。

### 维度 3：模型-数据版本一致性

- 核查问题：checkpoint 训练时间是否晚于其依赖数据的最后修复时间？
- 验证动作：比对模型文件 mtime 与数据 artifact 日期；ckpt 早于数据修复的，标记『训练好模型 + 修复后数据』组合不成立，补重训前置。
- v0.4 实例：neural_sde_v1_dim64.pt（10-06）早于 regime artifact（11-04）→ E3 先补 head 重训。

### 维度 4：存量资产盘点

- 核查问题：SPEC 计划新建的东西，仓库里是否已有闲置实现？
- 验证动作：对每个『新建/实现』条目先做全仓搜索（按功能关键词 + 接口签名）；已有实现则改为『接线复用』并核验兼容性（闲置模块有依赖漂移风险，接线前先 shadow 冒烟）。
- v0.4 实例：workspace_bus.py（10-12 创建，从未被生产 import）→ E1 从零实现改为接线复用。

### 维度 5：门禁强制等级

- 核查问题：每道门禁是代码强制（参数/hook/黑名单）还是文档自律？
- 验证动作：检查门禁对应的接口是否有强制点（如入库函数的排除参数、升级路径的区间 hook）；无强制点的门禁降级为风险项——验收时会被判定为 P0 缺陷。
- v0.4 实例：OOD 隔离原为自律口号 → evolution-case-ingest 加 exclude_out_of_sample_interval 参数 + bayesian_memory_updater 加 is_in_oos_interval hook。

### 维度 6：主链可观测性

- 核查问题：归因实验（消融对照/双跑对比）所需的日志与回放链路是否存在？
- 验证动作：盘点 joinable 事件链（写→召回→行动→结果各环节是否有持久化日志可 join）；缺链路的标为公共瓶颈，优先补齐（回放器与度量埋点建议合并设计，一次建设两用）。
- v0.4 实例：recall 无持久化日志 → readout_rate 不可算；全仓无决策回放器 → 消融归因无载体。
