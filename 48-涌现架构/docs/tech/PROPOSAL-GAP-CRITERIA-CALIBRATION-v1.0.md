## §0 执行摘要

对 37 条结构性缺口做判据校准实测，核心发现：**三类缺口的现行判据口径与 Python 代码库现实系统性不匹配**——按现行判据，任何大型 Python 仓库都无法达标；实测数据表明问题主要在判据口径而非代码质量。

| 类别 | 条数 | 现行判据 | 云端实测 | 结论 |
|---|---|---|---|---|
| architecture_gap | 11 | 函数名跨模块重名比例 < 0.4 | 全仓重名率 **27.5%**（排除魔术方法，40320 函数名 / 11098 重名） | 全仓口径下已达标；模块级 78-88% 系口径放大 |
| interface_mismatch | 13 | 公开函数缺完整注解 94-96% | 17域公开函数 docstring 率 **64%** | 口径差异显著，需先统一『注解』定义 |

## §1 architecture_gap（11 条）实测与校准提案

### 1.1 实测数据（云端，2026-11-12）

- 全仓函数名总数（排除 `__xxx__` 魔术方法）：**40320**
- 跨目录重名函数数：**11098**
- 全仓重名率：**27.7% → 27.5%**（含/不含魔术方法差异仅 0.2pp）

### 1.2 与缺口记录的差异分析

缺口记录的模块级重名率 78-88%（如 17域 0.8793 / 43域 0.8442 / 10域 0.8148 / 9域 0.7898），与全仓实测 27.5% 差异巨大。根因：

1. **模块级口径把常见私有辅助函数全计入**：`_load` / `_run` / `_init` 等通用命名在大型仓库天然高频重名，属 Python 生态常态而非架构缺陷
2. **魔术方法计入**：`__init__` / `__str__` 等在所有类中必然重名（sample_ambiguous 字段佐证）
3. **重名 ≠ 假依赖**：函数重名只在 call 边解析（取路径首个）时才产生假依赖，import 边（D2-A 的 GT）不受影响

### 1.3 校准提案

| 项 | 现行 | 提案 |
|---|---|---|
| 判据口径 | 模块级函数重名比例 < 0.4 | **call 边假依赖率**：仅统计实际被 call 边引用且解析歧义的重名函数 |
| 排除项 | 无 | 排除魔术方法 + 排除未被跨模块调用的私有辅助函数 |
| 阈值 | < 0.4 | 全仓口径下 27.5% 已达标；建议阈值定 **< 0.35**（留余量） |
| 根治路径 | — | 33-REA 落地 AST 精准解析（call edge 消歧，按 import 链限定候选）——与 GAP-20261109-3cde51c5（27563 条 call 边假依赖）同源同解 |

**预期效果**：11 条中预计大部分可关闭或降级——真正需要 33-REA AST 消歧的仅 call 边实际歧义部分。

## §2 interface_mismatch（13 条）实测与校准提案

### 2.1 实测数据（云端，2026-11-12）

17-v4-wave-strategy 抽样：公开函数（非 `_` 前缀）25 个，有 docstring 16 个，**docstring 率 64%**——与缺口记录的『缺注解比例 94-96%』差异显著。

### 2.2 差异根因

缺口记录的『注解』口径可能为**完整类型注解**（参数+返回值 type hints）而非 docstring——两者是完全不同的标准。需先统一定义再谈达标。

### 2.3 校准提案（分级判据，缺口清单 §6.4 已建议）

| 层级 | 判据 | 阈值 |
|---|---|---|
| L1 跨域边界函数（被其他域 import 的公开 API） | 完整类型注解 + docstring | **100%**（硬门槛） |
| L2 模块内公开函数 | docstring | **≥ 60%**（软门槛，当前 17域 64% 已达标） |
| L3 私有函数（`_` 前缀） | 豁免 | — |

**预期效果**：按 L1/L2 分级重测后，13 条中预计多数模块可关闭，仅跨域边界函数需补注解。

## §3 doc_debt（13 条）实测与校准提案

### 3.1 实测数据（云端，2026-11-12）

17-v4-wave-strategy 抽样：10 个 py 文件、5 个 md 文件、存在 docs/ 目录——『逐 py 文件配同名 md』口径下覆盖率必然极低（0.25-4% 记录与此吻合）。

### 3.2 校准提案（缺口清单 §6.4 已建议）

| 项 | 现行 | 提案 |
|---|---|---|
| 判据口径 | 逐 py 文件同名 md 覆盖率 | **模块级覆盖**：每个域目录有 README.md（定位/入口/数据流）+ 关键子模块有 SKILL/设计文档 |
| 阈值 | 未明确 | 域目录 README 覆盖 **100%**，关键子模块文档覆盖 **≥ 80%** |
| 分批策略 | — | 先补 48/40/50/23 等主链域，再补外围域 |

**预期效果**：口径切换后 13 条按模块级重测，预计主链域多数已具备 README（48域 README 即范例），缺口池大幅收敛。
