## §0 Executive Summary

### 0.1 做什么

把已采集的多源文章（odaily 深度文章 63750 篇存量 + newsflash + cointelegraph_cn / theblockbeats / panewslab / cryptopanic / gdelt / tavily / okx_announcement 等 10+ 源）转化为 48 D1 交易轨的**叙事原语（Narrative Primitives）训练数据**，直接补强当前两个已证伪/受阻的根因：

| 现有瓶颈（实证） | 本方案的补强路径 |
|---|---|
| **E5 组合泛化证伪根因 = 原语预测力弱**（kNN 53.6%，组合 45-50%，MLP 50.2%） | 模式库产出的"经验证为真"的模式 = **更强的新原语**，注入 E5 原语库 |
| **E2 做梦器 32 变体 0 准入**（稳定性不足，分片非负率 0.33<0.6） | 模式库提供"有叙事依据的初始种群"，变体生成从纯结构扰动升级为**有因果锚点的扰动** |

### 0.2 不做什么

| 禁止 | 原因 |
|---|---|
| 不改 33-REA dreaming.py | 做梦器属 33 域，本方案只在上游新增组件，通过接口对接 |
| 不用大语言模型做核心抽取 | 用户明确"做梦器等模型（Transformer 架构，非大语言）"——核心抽取用 encoder 微调/IE 技术 |
| 不做"文章→次日涨跌"的简单事件研究 | 用户已否定该路径；行情反应只用于**历史事件库**的标注，不用于当篇文章打分 |
| 不放宽 D1 多重比较三层防线 | 批内 Holm → 批级 PBO/CSCV → 胜出者 SPA/DSR，全部预注册冻结（SPEC-EMERGENCE-3D §2.1） |
| 不进生产链路 | 全部 shadow / FAIL-OPEN，模式库只读侧输出 |

### 0.3 核心判断

1. **价值在命题，不在文本**。一篇文章的价值 = 它包含的可证伪逻辑命题数量 × 命题被历史验证为真的比例。广告/软文在命题层天然被过滤（无因果链）。
2. **历史事件库是本方案的真正地基**。文章只是"命题来源"，验证必须落在"事件类型 × 市场状态 → 历史行情反应"的条件分布上。没有事件库，命题抽取只是文本游戏。
3. **模式库 = 可证伪的条件分布表**，天然对齐 D1 三层统计防线，也天然是 E5/CBR 可消费的原语格式。
4. **素材充足是真优势**：63750 篇 odaily 存量 + 10+ 源持续采集，中文加密领域深度文本规模罕见；但**正文二次爬取是 P0 硬前置**（列表端点无 content 字段）。

## §2 关键组件设计

### 2.1 C1 广告剔除（升级：从规则到命题密度）

初版方案的广告剔除是纯文本特征（含"注册/返佣/交易所推广"等关键词）。内生逻辑路径下升级为**双判据**：

1. **推广特征**（既有）：关键词、外链域名、免责声明模板；
2. **命题密度**（新增）：全文可抽取因果命题数 / 字数。软文特征 = 命题密度≈0（只有断言没有论证）。

判据：任一命中即剔除；边界样本（密度低但无推广特征）保留并标 `low_density`，留给下游自行降权。**剔除决策落盘可审计**（哪些文章被剔、命中哪条判据）。

### 2.2 C2 多维打标

五维标签（可叠加）：`macro / trading / technical / event / project`。技术选型见 §3.1——用 encoder 多标签分类（微调 RoBERTa-wwm-ext 级模型），训练集从人工标注 200-500 篇 bootstrap。标签不是终点，是**事件类型归类的前置**（事件库按标签 × 细分类型组织）。

### 2.3 NPE 叙事原语提取器（本方案核心）

**目标**：从中文金融文本抽取**可证伪的逻辑命题**，不是摘要、不是情感标签。

**命题 schema**：

```json
{
  "proposition_id": "NP-...",
  "condition_event": "美联储降息50bp",
  "event_type": "macro.rate_cut",
  "market_state_qualifier": "risk_off 环境 / BTC 处于 MA128 下方",
  "conclusion": {"direction": "bullish", "target_scope": ["BTC","ETH"], "magnitude_hint": null},
  "time_window": "T+7d",
  "confidence_in_text": "strong|hedged",
  "evidence_spans": [{"doc_id": "odaily:xxx", "start": 128, "end": 210}],
  "extractor_version": "npe-v0.1"
}
```

**抽取什么**（三类，按优先级）：

| 类型 | 例 | 可证伪性 |
|---|---|---|
| 因果命题 | "降息 → 风险资产上涨" | 强：事件库可直接验证 |
| 条件模式 | "当资金费率>0.1%且OI创新高时，短期回调概率大" | 强：纯行情数据即可验证（不需要事件库） |
| 类比命题 | "本次 ETF 通过类似 2024 年 1 月" | 中：需对齐历史锚点 |

**技术路线（非 LLM，§3.1 详评）**：pipeline = 句法分析（条件/因果触发词 + 依存）召回候选 → encoder 序列标注精化（命题边界 + 论元角色）→ 分类头（方向/置信/时间窗）。**召回优先**——漏抽可接受，错抽污染模式库。

### 2.4 历史事件数据库（地基）

**事件 schema**：

```json
{
  "event_id": "EV-...",
  "event_type": "macro.rate_cut | listing.okx | hack.cex | etf.approval | ...",
  "asset_scope": ["BTC"],
  "trigger_ts": 1704844800,
  "market_state": {"regime": "bull|chop|bear", "psi": ..., "funding": ..., ...},
  "reaction": {"T+1h": 0.012, "T+4h": 0.021, "T+24h": 0.035, "T+7d": -0.008},
  "source": "article_backfill | kline_detected | announcement"
}
```

**三条回填路径**（P2 并行）：

1. **文章回溯**：历史深度文章提到的已发生事件（命题的 condition_event 在文章发布日之前）→ 直接入库；
2. **公告/快讯对齐**：okx_announcement / newsflash 历史存量本身就是带时间戳的事件流 → 与 K 线 join 生成 reaction；
3. **行情反查**：异常波动检测（3σ 突刺，复用 48 E1 anomaly_probe 思路）→ 反查当日新闻归因（弱标注，标 `attribution: weak`）。

市场状态向量复用 E5 强原语复测的 6 维口径（含 regime/funding/quality_score），保证与 48 域既有实验可比。

### 2.5 模式库（验证层）

**模式 = 命题模板 × 事件库证据的条件分布**：

```
pattern = (event_type, market_state_bucket) → {
    reaction_dist: {T+24h: {mean, std, n}},
    significance: {holm_p, pbo, spa_p},
    status: candidate | verified | falsified,
    n_events: int,
    trials_count: int   // 必须写入，供三层防线
}
```

**与 D1 三层防线对齐**（预注册冻结，禁止事后选口径）：

1. **批内**：同一事件类型下多个市场状态桶比较 → Holm 校正；
2. **批级**：模式发现过程本身有选择偏差 → PBO/CSCV（PBO>0.5 整批拒入）；
3. **胜出者**：verified 模式 vs 人工策略基线 → SPA/DSR。

**status 流转**：候选（n_events ≥ 8 且 holm_p<0.05）→ verified（三层全过 + 方向稳定 ≥2 个独立时间窗）→ falsified（任一复测方向翻转即降级，不留情面）。

### 2.6 对 48 D1 的只读接口

| 消费端 | 接口 | 预期效果 |
|---|---|---|
| E5 原语库 | verified 模式 → 新原语（方向 + 状态限定 + 时间窗） | 替换/补强弱原语后重测组合泛化（当前 kNN 53.6% 是天花板证据） |
| E2 做梦器 | 模式 → 初始种群 + 变异先验（33-REA 侧实现，本方案只供数据） | 变体从"纯结构扰动"升级为"有因果锚点"，稳定性判据（分片非负率≥0.6）有望改善 |
| CBR | 模式实例 → evolution-case-ingest（复用既有 SKILL） | 定向补案例，缓解案例稀疏 |

**硬边界**：所有输出 shadow 只读；做梦器侧改造由 33-REA 域评审决定，本方案不越界。

## §3 技术选型评估

### 3.1 逻辑命题抽取（中文金融 IE）三路线对比

| 路线 | 方案 | 优点 | 缺点 | 判定 |
|---|---|---|---|---|
| R1 规则+依存 | 因果触发词典 + DDParser/LTP 依存句法 | 零训练成本、可解释、当天能上 | 召回低（口语化表达多）、维护词典是体力活 | **P1 基线**，必须做（给 R2 产标注数据 + 兜底） |
| R2 Encoder 微调 | RoBERTa-wwm-ext / 中文 FinBERT 级模型，序列标注（命题 span + 论元）+ 分类头 | 精度上限高、符合"非 LLM Transformer"要求 | 需 500-1000 条人工标注；训练/推理成本小但非零 | **P1 主线**，R1 预标注 + 人工修订 bootstrap |
| R3 小 LLM SFT | Qwen 级小模型微调 | 抽取质量最高 | 用户明确排除 LLM 路线 | 排除（仅留作未来上限对照，不进主线） |

**结论**：R1 先行（第 1-2 周可出 v0），R2 用 R1 的产出做远程监督 + 人工修订扩标注集，双路并行取并集（R2 高精度结果优先，R1 兜底召回）。

### 3.2 事件研究法对齐

历史事件的 reaction 计算 = 经典 event study 的 CAR（累计异常收益）：以事件窗口收益减去同时期基准（BTC 或对应资产 regime 均值）。**已知坑**：加密市场 24/7、事件时间戳精度（快讯精确到秒，深度文章只到天）——深度文章回填的事件统一用"日"粒度，标注 `ts_precision: day`，reaction 窗口只用 T+24h/T+7d。

### 3.3 数据现实核验（已知缺口）

- **正文爬取**：odaily 列表端点无 content，P0 必须先落 HTML 二次爬取器（复用采集规范 BaseCollector，TDD）；panewslab/theblockbeats 同需核验。
- **63750 篇存量**多为列表元数据，正文回填是大工程——**分批回填 + 按深度板块（depthPlateId）优先**。
- 市场状态向量部分字段（funding/OI）历史覆盖度未核验 → P2 启动时先跑覆盖率盘点，缺则降级用 regime/波动率先行。
