## §0 Executive Summary

### 0.1 做什么

**一句话**：深度文章只用于**训练**；48 涌现架构才是**输出口**，且输出必须经 40 神经传递下传，**不直连 50**。

**主线（训练侧，离线，一次性）**：**深度文章 → 因素识别（F1）→ 单因素方向（F2）→ 主导因素主张（F3）→ 样本门控 → 训练 48 涌现架构**（详见 §2.5 / §2.7）。
目标是**深度文章的交易逻辑抽象**——抽取"文章关注哪些因素、哪个因素主导、指向哪个方向"，而非文本语义；假设只能来自深度文章，不能来自快讯事件标签（快讯无论证链，只有事实陈述）。

**辅助（服务主线，不得替代）**：
- **9 域 `DimensionContext`** → 训练侧提供历史维度特征矩阵，推理侧提供实时维度状态（§2.6）
- 39 域聚合算子 → 提供**离散度 / 事件化采样**（不产生交易逻辑）
- 快讯主题热度 → 仅作**辅助状态维** `narrative_heat`（衡量市场关注度）

**训练期（离线，一次性）**

```
深度文章 500 篇（正文齐备，2026-05-30→11-09）──→ F1（99.6% 覆盖，3.8 类/篇）
                                                        ↓
                               F2 单因素方向 → F3 主导因素主张（claim）
                                                        ↓
9 域 DimensionContext 历史矩阵（8 维 × 日，滚动归一，严格 t 截断）
                                                        ↓
                          样本门控（一致 / 背离但有效 / 无信号）→ 样本权重
                                                        ↓
                        三层防线验证（Holm → PBO/CSCV → SPA/DSR，代码不动）
                                                        ↓
                        训练 48 涌现架构（学"什么维度组合下、谁主导"）
```

**推理期（在线，文章不参与）**

```
9 域 DimensionContext 实时矩阵
        ↓
48 涌现架构（预测：主导维度 + 方向 + 强度 + urgency / impact）
        ↓
40 周期神经网络（周期约束 + 神经传递）
        ↓
50 主矛盾评估器（D1/D2/D4 力量对撞 → 主矛盾裁决）
```

**硬约束**：48 **禁止直连 50**。48 的预测必须经 40 携带维度力与紧迫性进入 50 的仲裁器（`identify_primary_contradiction`）；直连会绕过周期约束，并形成两套裁决。

| 禁止 | 原因 |

### 0.3 核心判断（三条，全部有实测依据）

1. **v0.1 失败不是"事件方法"的错，是状态表征太粗**
   3 档 regime × 5 类事件 = 15 格，格内异质性（降息 25bp vs 100bp）远大于格间差异。
   数值证据：三个 regime 桶的 cell 均值几乎相同（bull +0.30~0.39% / chop +0.37~0.39% / bear −0.02~0.06%，μ0=+0.14%），PBO 0.816~0.969 全灭。

2. **9 域的价值在 state vector 的"形状"，不在它当前的分数**
   8 维连续 + 自适应权重（flow 1.5 / valuation 1.4 / onchain 1.3 / macro 1.2 / news·sentiment·breadth 1.0 / intermarket 0.8 / narrative 0.7 / calendar 0.6）+ 贝叶斯置信 + 跨模块一致性，是**连续状态空间**的正确骨架。
   但当前分数是 mock，历史是合成的 → 只能借设计，不能借数据。

3. **39 域的价值在聚合算子，但分子层输入错位**
   它的原子层（变化驱动 `{layer,category,metric,timestamp,value,prev_value,reasons,source}`）与细胞层聚合（单因子序列 / 跨因子活跃状态 / 多因子离散度 CV）是正确的「事件→状态」转换机制。
   但它的分子层输入是 `trader.log`（系统内部判断事件），**与叙事无关** → 需换输入源为新闻/文章，不能直接复用产物。

### 0.4 最大的现实约束（先摆在前面）

**所有多维数据的真实历史都只有约 1 个月**，除了 K 线（2023-01 起）与 newsflash 文本（2018/2023-01 起）。因此本方案的第一块工作不是建模，是**回填**（§4）。回填可行性已逐维实测分级：3 维可回填、2 维需补源、2 维不可回填。

## §1 失败复盘：v0.1 事件断点为什么被证伪

### 1.1 三层防线的最终数值（6,697 事件 / 3.7 年 / 15 cell）

| 防线 | 判据 | 结果 |
|---|---|---|
| 批内 Holm | ≥3 candidate | **0**（最优 holm_p=0.256） |
| 批级 PBO/CSCV | ≤0.50 | **5/5 family 全灭**（0.816~0.969） |
| 胜出者 SPA/DSR | — | 无胜出者，未执行 |

### 1.2 根因分解（三条，互不排斥）

| # | 根因 | 证据 | 本 SPEC 的应对 |
|---|---|---|---|
| R1 | **状态表征粗**：3 档 regime 抹平了状态差异 | 三桶均值几乎相同 | §5 连续状态向量 |
| R2 | **事件标签丢强度**：同类型事件按二值等同 | 格内方差 ≫ 格间 | §5.3 因素取值按滚动分位量化 |
| R3 | **单点窗口**：只取 T+24h，丢失路径 | 未直接检验（潜在） | §5.4 多窗口（T+24h / T+72h / T+7d）+ 累积异常收益 |

### 1.3 一条必须记住的方法论

**PBO > 0.8 意味着"发现过程本身无信息"，不是"某个模式运气差"。**
v0.1 在 160 事件时曾判断"样本不足"，扩样 42 倍到 6,697 事件后结论不变且更干净 → 下次遇到高 PBO，先怀疑表征/假设空间，不要先扩样。

### 1.4 主线链路验证实测（2026-11-10，500 篇文章）

用 500 篇试爬正文跑通「文章 → C1 → NPE → 命题」全链路（首次落盘校验，非冒烟）：

| 指标 | 实测 | 判定 |
|---|---|---|
| 文章 | 500 篇 / fetch_ok 482 / 平均 3,303 字 | ✅ |
| 时间跨度 | 2026-05-30 → 2026-11-09（138 唯一日，5.4 个月） | ⚠️ 偏短 |
| C1 v0.1 | keep 487 / drop 13 | ✅ |
| 命题数 | **533 条（1.11/篇）** | ✅ 量足 |
| direction | bullish 346 / bearish 187 | ✅ |
| confidence_in_text | hedged / strong 正常 | ✅ |
| **event_type** | **other 469/533 = 88%** | ❌ **不可用** |
| **time_window** | **空 482/533 = 90%** | ❌ **不可用** |
| **condition_event** | **碎片化**（"我们深入研究了可能" / "前水平下跌 5% 至 10%"） | ❌ **不可映射谓词** |

**结论：链路是通的，瓶颈在 NPE 环节，不在文章数量。** 三个具体缺陷：

| 缺陷 | 代码位置 | 后果 |
|---|---|---|
| 触发词典仅 15 个（11 因果 + 4 条件） | `_CAUSAL_TRIGGERS` / `_CONDITIONAL_TRIGGERS` | 条件从句漏抽；非条件触发时 `_extract_condition` 取"触发词左侧全部"→ 碎片 |
| 事件类型仅 6 类 + 首个关键词命中 | `_EVENT_TYPE_RULES` | 88% 落 `other` |
| 时间窗线索仅 5 个词 | `_TIME_WINDOW_RULES` | 90% 为空 |

**方向修正**：当前优先级不是扩文章（500 篇已产 533 条），也不是先回填 3 年序列，而是**提升 NPE 命题质量（P0.5，前置门禁）**——命题的 `condition_event` 不可映射为可计算谓词时，后续所有验证都无输入。

## §2.5 文章因素抽象（Factor Abstraction）—— 训练样本构建

> 用户方法论（2026-11-10 确认）：**交易涌现不需要文本语义分析，只需要「什么因素 → 价格往哪走」**。因此放弃"句子级因果命题"（现 NPE v0.1，88% 落 `other`），改为**因素级抽象**。
>
> **本节全部位于训练侧（离线、一次性）**：产物是训练样本，不是运行时证据。文章不进入推理链路（§0.1 / §2.7）。

### 2.5.1 三层流水线（训练样本构建）

| 步骤 | 做什么 | 结合哪个域 | 输出 |
|---|---|---|---|
| **F1 因素识别** | 文章涉及哪些维度（技术 / 资金流 / 链上 / 宏观 / 事件 / 情绪） | **39 域分类体系 + 术语表** 作别名词典 | `factors: [{factor_id, evidence_spans, count}]` |
| **F2 单因素方向** | 每个因素指向多还是空 | **9 域 `DimensionContext`**（§2.6）提供同窗口客观方向做对照 | `{factor_id, direction, strength, consistency}` |
| **F3 主导因素主张（claim）** | 多因素叠加时，作者认为**哪个因素主导**、指向哪个方向、在什么时间窗 | 文章内部显著度 + 9 域实测强度分布 | `DominanceClaim`（见下） |

**F3 是主张提取，不是信号合成**（用户 2026-11-10 确认，D8）。三条理由：

1. **不与 50 抢裁决层**——最终方向裁决属于 50；48 若自己合成方向，就形成两套裁决。
2. **可验证的对象是"作者主张"**，不是"我们的权重猜得准不准"——后者正是 v0.1 的失败路径（PBO 0.816~0.969，发现过程本身无信息）。
3. **urgency / impact 是正文独有的信息增量**——恰是 50 仲裁器当前硬编码为常数的两个参数（§2.7.3）。

`DominanceClaim` schema：

```json
{
  "claim_type": "dominance",
  "dominant_factor": "flow.funding",
  "dominant_dimension": "D2",
  "direction": "short",
  "horizon": "days",
  "confidence_in_text": 0.72,
  "urgency": 0.6,
  "impact": 1.5,
  "supporting_factors": ["sentiment.cycle:long"],
  "opposing_factors": ["macro.rate:long"],
  "salience_distribution": {"D1": 0.10, "D2": 0.45, "D3": 0.05, "D4": 0.25, "C6": 0.0, "C7": 0.10, "C8": 0.0, "NEWS": 0.05},
  "evidence_spans": [{"doc_id": "...", "start": 120, "end": 168}]
}
```

- `urgency`：由 `time_window` 映射（日内 0.9 / 短期 0.6 / 中长期 0.3）
- `impact`：由因素类先验映射（flow 1.5 / onchain 1.3 / macro 1.2 / technical 1.1 / event·sentiment 1.0）
- `salience_distribution`：8 维软标签，定义见 §2.7.2

### 2.5.2 实测可行性（482 篇文章，2026-11-10）

| 指标 | 现 NPE 句子级命题 | **因素抽象** |

六类因素提及率：`sentiment` 88% / `event` 85% / `onchain` 64% / `macro` 58% / `flow` 50% / `technical` 37%。

### 2.6 9 域通用能力：`DimensionContext` API（新增，D9）

**定位**：9 域补齐"逐指标历史归一 → 方向 + 强度"的对外接口，作为**通用能力**长期沉淀。这是重要工程实现项，不是本 SPEC 的临时脚手架。

**为什么不直接复用现有实现**（实测，§2.1）：

| 现有能力 | 局限 |
|---|---|
| `SignalEngine.generate_composite_signals` 的 `score_z` / `score_percentile` | 只作用于**综合分**（`_score_history` ≤200），不是逐指标 |
| `_adaptive_weight` / `_bayesian_confidence` | 需要 `update_module_performance` 回灌真实对错，当前无人调用 |
| `_pct_rank_last` / `_zscore_last_s` | 位于 embedded 生成副本，属选币风控私有特征，未对外 |
| 8 维模块分 | mock（§2.1） |
| `compute_resistance_3d(raw_score, historical_scores)` | **范式正确**（direction + 历史归一 velocity + 数据点置信），但需外部喂真实序列 |

**契约（冻结）**：

```python
# 9-基本面分析/engines/dimension_context.py
@dataclass(frozen=True)
class DimensionContext:
    dimension: str        # D1/D2/D3/D4/C6/C7/C8/NEWS
    as_of: str            # ISO 日期；严格 t 截断
    direction: str        # up / down / neutral
    strength: float       # [0,1]
    z: float              # [-3,3]
    percentile: float     # [0,1]
    data_points: int
    availability: str     # long / short / none（复用 P2 分级）
    series_id: str        # factor_series_map 的 series 标识

def get_dimension_context(dimension: str, as_of: str, window: int = 60) -> DimensionContext
def get_dimension_matrix(as_of: str, dimensions: list[str] | None = None) -> dict[str, DimensionContext]
```

**口径对齐**（与 9 域既有语义一致，便于未来互认）：

| 项 | 口径 | 依据 |
|---|---|---|
| `direction` | ±0.3 阈值 | `least_resistance.py` L28-L33 |
| `strength` | `abs(tanh(z))` clamp [0,1]，**不用** 0-100 展示值 | 与 50 `DimensionForce.strength` 同量纲 |
| 归一 | 滚动窗口 z / 分位，**不用全历史** | 防参数随未来数据漂移 |
| 前视 | `as_of` 严格截断，只用 t 及之前 | §5.2 |
| 置信 | 数据点数 + `availability` 分级 | 对齐 9 域，并复用 P2 |

**维度映射**（对齐 50 已冻结口径，SPEC-M1 §M4）：

| 我们的因素类 | 50 维度 | 备注 |
|---|---|---|
| `technical` | D3 | 50 规定不得用资产类信号冒充每币 D3 |
| `flow` | D2 | 资金力 |
| `sentiment` | D4 | 情绪力 |
| `macro` | D1 | 走 40 的 macro_force，不产逐币 path |
| `onchain` | C6 / C7 | **唯一硬缺口**：50 无链上专维，暂归 C7（隐性），待 50 侧确认 |
| `event` | NEWS / C7 | 事件 |

**落地顺序**：契约先冻结 → P3 用 18 域临时 adapter 实现同 schema → 9 域官方实现上线后按 provider 替换（调用方零改动）。**P3 不被 9 域工期阻塞。**

### 2.7 训练 / 推理分离与样本门控（新增，D10）

#### 2.7.1 两个阶段

| 阶段 | 输入 | 输出 | 频次 |
|---|---|---|---|
| **训练（离线）** | 500 篇文章 claim + 9 域历史 `DimensionContext` 矩阵 | 训练样本 `(X = 维度状态矩阵, y = 软标签)` → 训练 48 | 一次性，可迭代重训 |
| **推理（在线）** | 9 域实时 `DimensionContext` 矩阵（**不含文章**） | 48 预测：主导维度 + 方向 + 强度 + urgency / impact → 40 | 持续 |

**48 的预测能力来源**：训练时从文章学到"什么维度组合下、什么因素主导"；推理时只看维度状态即可判断，不依赖文章。

#### 2.7.2 训练标签：软标签（Q1 结论）

不把 claim 打成"唯一主导维度 + 方向"的硬标签，而是 **8 维显著度分布**：

```
salience[d] = Σ_{factor ∈ d} ( sign(factor) × evidence_span_len × class_weight )  →  归一化到 [0,1]
```

理由：60 细类归并到 8 维后，"唯一主导"这一假设经常不成立（实测 3.8 类因素/篇，多类并列）；硬标签会把"并列"变成错误标签。软标签还能直接作为 48 的回归目标，与连续输出同构。

#### 2.7.3 样本门控：解决"文章多为事后分析"

**问题**：深度文章常在价格走完之后撰写，作者会挑当时表现最强的维度解释——这是事后归因（hindsight / post-hoc rationalization）。直接入训会把"结果"教成"原因"。

**门控规则**（用 9 域实测做一致性检验，**只影响训练，不进 50**）：

| 档 | 判定 | 处置 | 佐证 |
|---|---|---|---|
| **一致** | 文章主导维 = 9 域实测最强维，且方向一致 | 正常入训，权重 1.0 | 事前可得的因素，作者强调合理 |
| **背离但有效** | 主导维 ≠ 实测最强维，但该维当时确实显著变化（`abs(z) ≥ 1` 且方向一致） | 入训，权重 1.5 | 作者看到了别人没看到的——**这才是 alpha 来源** |
| **无信号** | 主导维 `abs(z) < 0.5` 或方向相反 | 降权 0.3 或剔除 | 事后编故事 |

**阈值（0.5 / 1.0 / 方向一致）必须在跑门控前冻结进预注册文档**，不得按验证结果回调。

#### 2.7.4 与 50 的关系（修正原「第四类矛盾」）

- 50 **不读文章**，也不新增 `narrative_fact_conflict` 矛盾类型
- 50 `identify_primary_contradiction` 当前的 `DEFAULT_URGENCY = 0.5` / `DEFAULT_IMPACT = 1.0`（`50-NN主矛盾评估器/core/contradiction.py` L32-L33）由 **40 下传时携带**填补：48 在推理时输出 urgency / impact，经 40 进入 50 仲裁
- 一致性检验的产物是**训练样本权重**，不进入运行时

### 3.2 39 域结合方案：定点复用四个算子（不整体采纳四层架构）

**原则**：借算子不借架构。39 域定位是"描述性观察"，本 SPEC 也不做因果推断——两者边界一致，因此**只复用计算算子**，不迁移其四层体系，不修改其源码（复制进 18 域并做 parity 测试，与三层防线的复用方式一致）。

| # | 复用对象 | 改造方式 | 解决什么 | 阶段 |
|---|---|---|---|---|
| **S1** | **L2 事件线聚合**（`gen_event_lines.py`） | 数据源 `dc_pg` → `newsflash_history.jsonl`；情绪由关键词词表 → FinBERT；锚点 6 → 12 | **仅作辅助状态维** `narrative_heat`（市场关注度/叙事聚焦度）；**不产生交易逻辑假设**——交易逻辑只从深度文章命题来 | **P1** |
| **S2** | **L3 多因子离散度**（`_dispersion()` CV） | 输入从"原子事件计数"改为"8 维状态活跃度" | U3 组合条件的**分歧度门槛**（分歧大 → 不触发）；缓解 K6 样本重叠 | P2 |
| **S3** | **L1 原子层变化驱动规则**（`gen_atomic_events.py`：越线 / 转正负 / 分位跃迁 / 显著变动） | 规则套到日度状态序列上 | **事件化采样**：把连续日度验证改为突变点验证，提升样本独立性 | P3 |
| **S4** | **术语蒸馏**（9 张 `*_terms.json`） | 3 条占位 → 补齐 200-500 条（无需 1,454） | NPE `event_type` 从 5 类细化到数十类（携带强度），直接针对 P3 失败根因 R2 | 长期 |

**明确不采纳**：

| 不采纳项 | 原因 |
|---|---|
| 分子层产物（`semantic_events.jsonl`） | 来源是 `trader.log`（系统交易判断事件），与叙事无关 |
| 四层架构整体迁移 | 39 域自定位为描述性观察，本 SPEC 只需算子；整体迁移会引入无关复杂度 |

| 修改 39 域源码 | 39 域自行演进，本 SPEC 只读复用 |

### 4.2 回填设计要点

1. **统一日度粒度**（UTC 日界），与 v0.1 事件库 `ts_precision` 口径一致
2. **每条序列落盘必须带 provenance**：`{date, value, n_inputs, source, builder_version}`
   - `n_inputs` 是防伪关键：某日只有 3 条 newsflash 时，其 sentiment 不可与 300 条的日期等同
3. **覆盖率门禁**：`n_inputs < 阈值` 的日期标 `low_coverage`，验证时降权或剔除（口径预注册）
4. **无前视**：序列在日 D 的值只能由 ≤ D 日 23:59 UTC 的输入计算
5. **FAIL-OPEN**：单日计算失败写 `null` + 原因，不中断整批，不插值（插值=伪造观测）

### 4.3 回填产物体积预算

| 序列 | 行数 | 体积估算 |
|---|---|---|
| sentiment_daily | ~1,400 | < 1 MB |

### 5.1 状态向量定义（v0.1 冻结 8 维）

| # | 维度 | 信息族 | 计算 | 归一化 | 历史 |
|---|---|---|---|---|---|
| 1 | `sent` | 文本族 | newsflash FinBERT 日度均值 | 滚动 252 日分位 | ✅ 2023-01→今 |
| 2 | `narrative_heat` | 文本族 | 39 域主题聚类 → 当日最热主题热度 + 主题集中度 HHI（叙事是否聚焦） | 分位 | ✅ 2023-01→今 |
| 3 | `mom` | 价格族 | BTC 60 日收益率 | 滚动 252 日 z-score | ✅ 2023-01→今 |
| 4 | `vol` | 价格族 | 20 日已实现波动率 | z-score | ✅ 2023-01→今 |
| 5 | `breadth` | 价格族 | 上涨标的占比（多币 K 线；否则代理） | 分位 | ✅ 2023-01→今 |
| 6 | `macro_tight` | 宏观族 | 收益率曲线 T10Y2Y + 高收益利差 BAMLH0A0HYM2 合成 | 分位 | ✅ 1976→今 |
| 7 | `macro_risk` | 宏观族 | VIX 分位 + NASDAQ 60 日动量合成 | 分位 | ✅ 1971→今 |
| 8 | `macro_liq` | 宏观族 | RRP + WALCL + M2 同比合成 | z-score | ✅ 1959→今 |

**设计意图**：三族各占席位（文本 2 / 价格 3 / 宏观 3），使 §6.4 的 U2 真交叉验证在 v0.1 就具备可执行条件。

**降级备选（不进 v0.1 状态向量）**：`sent_disp`（日度情绪标准差，与 sent 高度相关，仅作 U1 校验）、`topic_sent`（各主题独立情绪，作 U3 组合用）、`fg`（fear_greed，41 天）、`lsr`（多空比，2 天）、`tvl_chg`（TVL，40 天）、`mvrv/sopr`（6 天）——历史不足或信息重复，不用于主检验。

**可用性降级**：任一维历史缺失时，状态向量自动降维并在产物标 `dims_effective`。**不允许用 mock 或插值补齐。**

### 5.2 归一化的前视防护

- 滚动窗口严格用 `[t-252, t-1]`，**不含 t 日**
- 分位计算用 `rank < target` 的比例（处理并列值）
- 每维落盘同时存 `raw_value` 与 `normalized`，便于审计

### 5.3 假设来源：因素 × 方向（防止维度组合爆炸的核心设计）

**不做**全空间搜索（8 维 × 若干分位档 = 组合爆炸，多重比较必然爆表）。

**只验证两类有来源的对象**：

| 类型 | 来源 | 规模 | 用途 |
|---|---|---|---|
| **H-L1 单因素方向** | P2 的 24 个可验证细类 × 2 方向 | ≤48 条，预注册冻结 | 因素是否真有预测力（**不依赖文章**） |
| **claim 方向** | 500 篇文章的 `DominanceClaim` | 每篇一条 | 作者主张是否有 alpha（**样本级评估，不构成假设空间**，不进 Holm 批内多重比较） |

```
示例（H-L1）:
  因素: flow.funding（P2 可验证）
  取值: DimensionContext.z(funding) 的滚动分位
  假设: P(forward_7d > 0 | funding 分位 > 0.8 且 direction = up)
        > P(forward_7d > 0 | 同期非条件日)
```

**数量控制**：
- H-L1 全集 = 24 × 2 = 48 条，**预注册文件冻结**，验证过程中不得增删（否则 PBO 无意义）
- claim 不产生组合爆炸：它是逐篇文章的观测，不是谓词空间
- 无可用序列的 30 个细类标 `unverifiable`，不进假设集（诚实暴露覆盖缺口）

**降级方案**：若 H-L1 全部不显著，退化为**单维极端分位**假设（8 维 × 双尾 = 16 条），作为 fallback 而非主线。

### 5.4 反应定义（事件研究 → 条件分布对比）

| 项 | 口径 |
|---|---|
| 反应变量 | 条件日的 `forward_return[T+24h]`（BTC 收盘对收盘） |
| 对照组 | 同窗口内非条件日的 forward return（**不是 μ0 全局均值**，消除 regime 漂移） |
| 检验 | 两组差异的 Welch t 检验 / 置换检验（n 小用置换） |
| 多窗口 | T+24h（主）/ T+72h（佐证）/ T+7d（佐证，不进主检验） |
| 重叠校正 | 条件日连续时 forward return 重叠 → 用 **block bootstrap**（块长 = 窗口长度） |

**关键改进 vs v0.1**：v0.1 用全局 μ0 做基准，导致 regime 漂移被误记成效应；本 SPEC 用**同期非条件日**做对照，这是正确的反事实。

### 6.4 多维交叉验证（回填的第二个用途，用户强调）

回填的价值不只是「维度更多」，更是**相互验证**。三类用途必须分开，不可混用：

| 用途 | 做法 | 产出 | 判据 |
|---|---|---|---|
| **U1 数据质量校验** | 同一构念用两个独立源计算，偏差超阈值即标记可疑 | 数据可信度报告 | 偏差 > 3σ 标 `suspect`，验证时剔除 |
| **U2 假设稳健性** | 同一命题在**不同独立信息族**内分别找代理谓词，检验是否同向 | 弱 / 中 / 强证据分级 | 三族同向=强，两族=中，单族=弱 |
| **U3 组合条件模式** | 多族状态同时极端时的条件收益 vs 单族极端 | 组合条件模式 | 需样本 n≥30 |

#### 信息族与独立性声明（**关键约束，防止虚假交叉**）

| 族 | 数据源 | 与加密行情的独立性 |
|---|---|---|
| **宏观族** | fred 20 序列（美债 / VIX / 美元 / 收益率曲线 / 高收益利差） | ✅ **真独立**（外部宏观，加密不驱动） |
| **加密价格族** | BTC K 线派生（momentum / vol / breadth） | — 基准 |
| **加密文本族** | newsflash → FinBERT sentiment | ⚠️ **非独立**（新闻被价格驱动，反向因果） |
| **事件流族** | newsflash `od_event_type` → co-occurrence | ⚠️ **与文本族同源**（同一批 newsflash） |

**结论（必须写进预注册）**：
- **U2 假设稳健性只能用「宏观族 vs 加密价格族」做真交叉**——这两族信息源独立
- **加密文本族与事件流族同源**，只能做 U1 一致性校验，**不可当作两条独立证据**（否则 n 条新闻被误算成 n 重验证）
- 情绪族与价格族同向，只能说明"价格与新闻同步"，**不构成因果证据**

#### 交叉验证是加严，不是放松

| 层级 | 原判据 | 本 SPEC 追加 |
|---|---|---|
| candidate | holm_p < 0.05（不变） | 无追加 |
| **verified** | 三层全过 + 方向稳定 ≥2 独立时间窗 | **+ 跨族一致**：宏观族与加密族同向 |

即交叉验证只用于**晋级门槛加严**，绝不用于放宽 p 值阈值。

### 6.5 四层验证（P3-a 前置门控 + L1/L2/L3，因素抽象版）

| 层 | 验证什么 | 输入 | 输出 | 依赖文章 |
|---|---|---|---|---|
| **P3-a 主导因素一致率** | 文章 claim 的主导维 vs 9 域实测最强维 | claim + 当日 `DimensionContext` | 一致率 + 三档分布（一致 / 背离但有效 / 无信号） | ✅ |
| **L1 因素预测力** | 因素客观取值 → 后续收益 | 历史维度状态序列（3 年） | 每因素每方向的胜率 / 期望收益 / p 值 | ❌ **不依赖** |
| **L2 作者方向准确度** | 文章给的因素方向 vs 因素客观方向 | 文章因素 + 当时客观取值 | 准确率矩阵（作者在哪些因素上判断更准） | ✅ |
| **L3 主张预测力** | claim 方向 → 后续收益（**不是**合成方向） | claim.direction + 价格 | 胜率 / 期望收益 vs 基准 | ✅ |

**分工**：
- **P3-a 是前置门控**——一致率接近随机说明 9 域与文章讲的不是一回事，后续不必做；成本最低（500 篇即可算，不需回测）
- **L1 是知识积累主渠道**——样本不受 500 篇限制（可用 3 年历史），产出即 E5 原语；但只覆盖长历史可验证的因素类（technical / macro / event / narrative）
- **L2 回答"作者在哪些因素上可信"**——可产出作者/来源加权先验
- **L3 回答"作者主张有没有 alpha"**——是训练样本质量的最终判据，**不是运行时信号**
- 四层**均走同一套三层防线**（Holm → PBO/CSCV → SPA/DSR），只是对象从"事件 cell"变为"因素方向 / claim"
