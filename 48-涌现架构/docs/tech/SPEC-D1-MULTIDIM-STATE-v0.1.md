## §0 Executive Summary

### 0.1 做什么

**主线（不可让渡）**：**深度文章 → 因素识别（F1）→ 单因素方向（F2）→ 多因素合成（F3）→ 历史状态验证**（详见 §2.5）。
目标是**深度文章的交易逻辑抽象**——抽取"文章关注哪些因素、每个因素指向哪个方向"，而非文本语义；假设只能来自深度文章，不能来自快讯事件标签（快讯无论证链，只有事实陈述）。

**辅助（服务主线，不得替代）**：
- 9 域 8 维状态向量 → 提供验证用的**状态空间**（不是假设来源）
- 39 域聚合算子 → 提供**离散度/事件化采样**（不是假设来源）
- 快讯主题热度 → 仅作**辅助状态维**（衡量市场关注度，不是交易逻辑）

```
深度文章 500 篇（正文齐备，2026-05-30→11-09）──→ 因素识别 F1（99.6% 覆盖，3.8 类/篇）
                                                        ↓
                                          单因素方向 F2 → 多因素合成 F3
                                                        ↓
1,385 天 BTC 日 K ─────────┐
fred 宏观 20 序列（1962起）─┼→ 8 维状态序列（辅助：提供样本与状态）
19.3 万条 newsflash ───────┘   ← 9 域聚合设计 + 39 域算子
                                                        ↓
                                        条件分布验证（三层防线，代码不动）
                                                        ↓
                                verified 命题 → E5 原语 / E2 种群 / CBR 案例
```

### 0.2 不做什么

| 禁止 | 原因 |
|---|---|
| 不废弃 P0/P1/P2 已有产出 | 正文爬取器、C1 v0.1、NPE v0、事件库 6,697 事件全部可复用 |
| 不用 9 域现有 mock 分数 | 实测 `_generate_mock_*` 11 函数 + 130 处 `random.`，时序为随机游走合成（§2.1） |
| 不直接修 9 域服务层 | 9 域 mock 链路服务前端展示，动它牵动前端契约；改为 18 域并行建真实序列 |
| 不做维度组合全空间搜索 | 维度组合爆炸 → 多重比较必然爆表；假设必须**预注册且有命题来源**（§5.3） |
| 不放宽三层防线 | 同 v0.1：Holm → PBO/CSCV → SPA/DSR，全部预注册冻结 |
| 不产生交易信号 | 全部 shadow 只读；39 域既有定位也是"只做描述性观察"（39/SPEC.md §8.2） |

### 0.3 核心判断（三条，全部有实测依据）

1. **v0.1 失败不是"事件方法"的错，是状态表征太粗**
   3 档 regime × 5 类事件 = 15 格，格内异质性（降息 25bp vs 100bp）远大于格间差异。
   数值证据：三个 regime 桶的 cell 均值几乎相同（bull +0.30~0.39% / chop +0.37~0.39% / bear −0.02~0.06%，μ0=+0.14%），PBO 0.816~0.969 全灭。

2. **9 域的价值在 state vector 的"形状"，不在它当前的分数**
   8 维连续 + 自适应权重（flow 1.5 / valuation 1.4 / onchain 1.3 / macro 1.2 / news·sentiment·breadth 1.0 / intermarket 0.8 / narrative 0.7 / calendar 0.6）+ 贝叶斯置信 + 跨模块一致性，是**连续状态空间**的正确骨架。
   但当前分数是 mock，历史是合成的 → 只能借设计，不能借数据。

3. **39 域的价值在聚合算子，但分子层输入错位**
   它的原子层（变化驱动 `{layer,category,metric,timestamp,value,prev_value,reasons,source}`）与细胞层聚合（单因子序列 / 跨因子活跃状态 / 多因子离散度 CV）是正确的「事件→状态」转换机制。
   但它的分子层输入是 `trader.log`（系统内部判断事件），**与叙事无关** → 需换输入源为新闻/文章，不能直接复用产物。

### 0.4 最大的现实约束（先摆在前面）

**所有多维数据的真实历史都只有约 1 个月**，除了 K 线（2023-01 起）与 newsflash 文本（2018/2023-01 起）。因此本方案的第一块工作不是建模，是**回填**（§4）。回填可行性已逐维实测分级：3 维可回填、2 维需补源、2 维不可回填。

## §1 失败复盘：v0.1 事件断点为什么被证伪

### 1.1 三层防线的最终数值（6,697 事件 / 3.7 年 / 15 cell）

| 防线 | 判据 | 结果 |
|---|---|---|
| 批内 Holm | ≥3 candidate | **0**（最优 holm_p=0.256） |
| 批级 PBO/CSCV | ≤0.50 | **5/5 family 全灭**（0.816~0.969） |
| 胜出者 SPA/DSR | — | 无胜出者，未执行 |

### 1.2 根因分解（三条，互不排斥）

| # | 根因 | 证据 | 本 SPEC 的应对 |
|---|---|---|---|
| R1 | **状态表征粗**：3 档 regime 抹平了状态差异 | 三桶均值几乎相同 | §5 连续状态向量 |
| R2 | **事件标签丢强度**：同类型事件按二值等同 | 格内方差 ≫ 格间 | §5.3 命题谓词携带方向/阈值 |
| R3 | **单点窗口**：只取 T+24h，丢失路径 | 未直接检验（潜在） | §5.4 多窗口（T+24h / T+72h / T+7d）+ 累积异常收益 |

### 1.3 一条必须记住的方法论

**PBO > 0.8 意味着"发现过程本身无信息"，不是"某个模式运气差"。**
v0.1 在 160 事件时曾判断"样本不足"，扩样 42 倍到 6,697 事件后结论不变且更干净 → 下次遇到高 PBO，先怀疑表征/假设空间，不要先扩样。

### 1.4 主线链路验证实测（2026-11-10，500 篇文章）

用 500 篇试爬正文跑通「文章 → C1 → NPE → 命题」全链路（首次落盘校验，非冒烟）：

| 指标 | 实测 | 判定 |
|---|---|---|
| 文章 | 500 篇 / fetch_ok 482 / 平均 3,303 字 | ✅ |
| 时间跨度 | 2026-05-30 → 2026-11-09（138 唯一日，5.4 个月） | ⚠️ 偏短 |
| C1 v0.1 | keep 487 / drop 13 | ✅ |
| 命题数 | **533 条（1.11/篇）** | ✅ 量足 |
| direction | bullish 346 / bearish 187 | ✅ |
| confidence_in_text | hedged / strong 正常 | ✅ |
| **event_type** | **other 469/533 = 88%** | ❌ **不可用** |
| **time_window** | **空 482/533 = 90%** | ❌ **不可用** |
| **condition_event** | **碎片化**（"我们深入研究了可能" / "前水平下跌 5% 至 10%"） | ❌ **不可映射谓词** |

**结论：链路是通的，瓶颈在 NPE 环节，不在文章数量。** 三个具体缺陷：

| 缺陷 | 代码位置 | 后果 |
|---|---|---|
| 触发词典仅 15 个（11 因果 + 4 条件） | `_CAUSAL_TRIGGERS` / `_CONDITIONAL_TRIGGERS` | 条件从句漏抽；非条件触发时 `_extract_condition` 取"触发词左侧全部"→ 碎片 |
| 事件类型仅 6 类 + 首个关键词命中 | `_EVENT_TYPE_RULES` | 88% 落 `other` |
| 时间窗线索仅 5 个词 | `_TIME_WINDOW_RULES` | 90% 为空 |

**方向修正**：当前优先级不是扩文章（500 篇已产 533 条），也不是先回填 3 年序列，而是**提升 NPE 命题质量（P0.5，前置门禁）**——命题的 `condition_event` 不可映射为可计算谓词时，后续所有验证都无输入。

## §2.5 文章因素抽象（Factor Abstraction）—— 替代句子级命题抽取

> 用户方法论（2026-11-10 确认）：**交易涌现不需要文本语义分析，只需要「什么因素 → 价格往哪走」**。因此放弃"句子级因果命题"（现 NPE v0.1，88% 落 `other`），改为**因素级抽象**。

### 2.5.1 三层流水线

| 步骤 | 做什么 | 结合哪个域 | 输出 |
|---|---|---|---|
| **F1 因素识别** | 文章涉及哪些维度（技术 / 资金流 / 链上 / 宏观 / 事件 / 情绪） | **39 域分类体系 + 术语表** 作别名词典 | `factors: [{factor_id, evidence_spans, count}]` |
| **F2 单因素方向** | 每个因素指向多还是空 | **9 域趋势/方向判定**（提供客观方向做对照） | `{factor_id, direction, strength}` |
| **F3 多因素合成** | 综合方向 + 与当时价格走势对齐 | 9 域模块权重（flow 1.5 / valuation 1.4 / onchain 1.3 / macro 1.2 / …） | `composite_direction, horizon, context_vector` |

### 2.5.2 实测可行性（482 篇文章，2026-11-10）

| 指标 | 现 NPE 句子级命题 | **因素抽象** |
|---|---|---|
| 可用产出率 | event_type 仅 12% 可用（**88% 落 other**） | **99.6%（480/482 篇至少命中 1 类）** |
| 平均产出 | 1.11 命题/篇（condition 为碎片） | **3.8 类因素/篇**（中位 4） |
| 方向可判 | 有 direction 但 condition 不可映射 | **70% 文章含明确方向词**（338/482） |
| 可映射数据序列 | ≈0（碎片无法映射） | 因素本体直接对应数据序列（见 2.5.4） |

六类因素提及率：`sentiment` 88% / `event` 85% / `onchain` 64% / `macro` 58% / `flow` 50% / `technical` 37%。

### 2.5.3 因素本体（6 大类 → 约 60 细类）

| 类 | 细类示例 | 对应历史数据 | 长历史可验证 |
|---|---|---|---|
| `technical` | trend / momentum / level / volume / pattern | 价格族派生（mom / RSI / 波动） | ✅ 2023-01 起 |

### 4.2 回填设计要点

1. **统一日度粒度**（UTC 日界），与 v0.1 事件库 `ts_precision` 口径一致
2. **每条序列落盘必须带 provenance**：`{date, value, n_inputs, source, builder_version}`

3. **覆盖率门禁**：`n_inputs < 阈值` 的日期标 `low_coverage`，验证时降权或剔除（口径预注册）
4. **无前视**：序列在日 D 的值只能由 ≤ D 日 23:59 UTC 的输入计算
5. **FAIL-OPEN**：单日计算失败写 `null` + 原因，不中断整批，不插值（插值=伪造观测）

| 5 | `breadth` | 价格族 | 上涨标的占比（多币 K 线；否则代理） | 分位 | ✅ 2023-01→今 |
| 6 | `macro_tight` | 宏观族 | 收益率曲线 T10Y2Y + 高收益利差 BAMLH0A0HYM2 合成 | 分位 | ✅ 1976→今 |

**设计意图**：三族各占席位（文本 2 / 价格 3 / 宏观 3），使 §6.4 的 U2 真交叉验证在 v0.1 就具备可执行条件。

**降级备选（不进 v0.1 状态向量）**：`sent_disp`（日度情绪标准差，与 sent 高度相关，仅作 U1 校验）、`topic_sent`（各主题独立情绪，作 U3 组合用）、`fg`（fear_greed，41 天）、`lsr`（多空比，2 天）、`tvl_chg`（TVL，40 天）、`mvrv/sopr`（6 天）——历史不足或信息重复，不用于主检验。

**可用性降级**：任一维历史缺失时，状态向量自动降维并在产物标 `dims_effective`。**不允许用 mock 或插值补齐。**

### 5.2 归一化的前视防护

- 滚动窗口严格用 `[t-252, t-1]`，**不含 t 日**
- 分位计算用 `rank < target` 的比例（处理并列值）
- 每维落盘同时存 `raw_value` 与 `normalized`，便于审计

### 5.3 假设来源：命题谓词（防止维度组合爆炸的核心设计）

**不做**全空间搜索（8 维 × 若干分位档 = 组合爆炸，多重比较必然爆表）。

**只验证有命题来源的假设**：

```
NPE 命题: "资金费率>0.1% 且 OI 创新高时，短期回调概率大"
   ↓ 人工/半自动映射（预注册，可审计）
谓词:    sent_disp > 0.9 且 mom > 0.8
   ↓
假设 H:  P(forward_24h < 0 | 谓词为真) > P(forward_24h < 0 | 谓词为假)
```

**假设数量控制**：
- 来源限定为 NPE 在 500 篇试爬文章上抽出的命题（冒烟 0.40 命题/篇 → 约 200 条，去重后约 30-60 条）
- **预注册文件冻结**假设全集，验证过程中不得增删（否则 PBO 无意义）
- 无法映射到可计算谓词的命题标 `unmappable`，不计入假设集（诚实暴露映射损失率）

**降级方案（若命题映射不可行）**：退化为**单维极端分位**假设（8 维 × 双尾 = 16 条），数量可控，但失去了叙事语义——作为 fallback 而非主线。

### 5.4 反应定义（事件研究 → 条件分布对比）

| 项 | 口径 |
|---|---|
| 反应变量 | 条件日的 `forward_return[T+24h]`（BTC 收盘对收盘） |
| 对照组 | 同窗口内非条件日的 forward return（**不是 μ0 全局均值**，消除 regime 漂移） |
| 检验 | 两组差异的 Welch t 检验 / 置换检验（n 小用置换） |
| 多窗口 | T+24h（主）/ T+72h（佐证）/ T+7d（佐证，不进主检验） |
| 重叠校正 | 条件日连续时 forward return 重叠 → 用 **block bootstrap**（块长 = 窗口长度） |

**关键改进 vs v0.1**：v0.1 用全局 μ0 做基准，导致 regime 漂移被误记成效应；本 SPEC 用**同期非条件日**做对照，这是正确的反事实。

### 6.4 多维交叉验证（回填的第二个用途，用户强调）

回填的价值不只是「维度更多」，更是**相互验证**。三类用途必须分开，不可混用：

| 用途 | 做法 | 产出 | 判据 |
|---|---|---|---|
| **U1 数据质量校验** | 同一构念用两个独立源计算，偏差超阈值即标记可疑 | 数据可信度报告 | 偏差 > 3σ 标 `suspect`，验证时剔除 |
| **U2 假设稳健性** | 同一命题在**不同独立信息族**内分别找代理谓词，检验是否同向 | 弱 / 中 / 强证据分级 | 三族同向=强，两族=中，单族=弱 |
| **U3 组合条件模式** | 多族状态同时极端时的条件收益 vs 单族极端 | 组合条件模式 | 需样本 n≥30 |

#### 信息族与独立性声明（**关键约束，防止虚假交叉**）

| 族 | 数据源 | 与加密行情的独立性 |
|---|---|---|
| **宏观族** | fred 20 序列（美债 / VIX / 美元 / 收益率曲线 / 高收益利差） | ✅ **真独立**（外部宏观，加密不驱动） |
| **加密价格族** | BTC K 线派生（momentum / vol / breadth） | — 基准 |
| **加密文本族** | newsflash → FinBERT sentiment | ⚠️ **非独立**（新闻被价格驱动，反向因果） |
| **事件流族** | newsflash `od_event_type` → co-occurrence | ⚠️ **与文本族同源**（同一批 newsflash） |

**结论（必须写进预注册）**：
- **U2 假设稳健性只能用「宏观族 vs 加密价格族」做真交叉**——这两族信息源独立
- **加密文本族与事件流族同源**，只能做 U1 一致性校验，**不可当作两条独立证据**（否则 n 条新闻被误算成 n 重验证）
- 情绪族与价格族同向，只能说明"价格与新闻同步"，**不构成因果证据**

#### 交叉验证是加严，不是放松

| 层级 | 原判据 | 本 SPEC 追加 |
|---|---|---|
| candidate | holm_p < 0.05（不变） | 无追加 |
| **verified** | 三层全过 + 方向稳定 ≥2 独立时间窗 | **+ 跨族一致**：宏观族与加密族同向 |

即交叉验证只用于**晋级门槛加严**，绝不用于放宽 p 值阈值。

### 6.5 三层次验证（因素抽象版，替代"命题谓词"验证）

| 层 | 验证什么 | 输入 | 输出 | 依赖文章 |
|---|---|---|---|---|
| **L1 因素预测力** | 因素客观取值 → 后续收益 | 历史状态序列（3 年） | 每因素每方向的胜率 / 期望收益 / p 值 | ❌ **不依赖** |
| **L2 作者方向准确度** | 文章给的因素方向 vs 因素客观方向 | 文章因素 + 当时客观取值 | 准确率矩阵（作者在哪些因素上判断更准） | ✅ |
| **L3 合成方向预测力** | 文章综合方向 → 后续收益 | 文章 composite + 价格 | 胜率 / 期望收益 vs 基准 | ✅ |

**分工**：
- **L1 是知识积累主渠道**——样本不受 500 篇限制（可用 3 年历史），产出即 E5 原语；但只覆盖长历史可验证的因素类（technical / macro / event / narrative）
- **L2 回答"作者在哪些因素上可信"**——可产出作者/来源加权先验
- **L3 回答"整体观点有没有 alpha"**——最接近用户目标的"交易涌现输入"
- 三层**均走同一套三层防线**（Holm → PBO/CSCV → SPA/DSR），只是对象从"事件 cell"变为"因素方向"

## §8 风险与已识别坑

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| K1 | `sentiment` 回填质量受 newsflash 短文本限制（无正文） | 情绪信号噪声大 | ①`n_inputs` 门禁 ②与文章级 sentiment 做一致性校验（500 篇有正文的样本） |
| K2 | 条件日样本稀疏（谓词苛刻时 n<30） | 统计功效不足 | 预注册最小样本 n≥30；不达标假设标 `insufficient_n` 不晋级 |
| K3 | 谓词映射主观性（人工映射可被事后调整） | p-hacking 风险 | ①预注册冻结 ②映射由独立于验证的人员/进程执行 |
| K4 | 8 维中 4 维历史不足 | 状态向量退化 | 降级为 4 维，如实标注 `dims_effective`，不补齐 |
| K5 | 39 域术语表仅 3 条占位 | 分子层不可用 | 本 SPEC 不走 39 分子层，改用 newsflash `od_event_type` 作原子事件源 |
| K6 | forward return 重叠 | p 值偏乐观 | block bootstrap（块长=窗口） |
| K7 | 情绪序列与价格同源（newsflash 受价格驱动） | 反向因果 | 谓词只用 t-1 及更早的状态；反应只看 t+1 之后 |
