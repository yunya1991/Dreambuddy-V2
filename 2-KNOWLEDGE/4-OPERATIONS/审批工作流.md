# 审批工作流 — 审批生命周期管理

> 审批创建、超时自动批准、OKR-Base同步链的完整规则。
> 源：lark-approval, approval-timeout-check

## 审批生命周期

```
审批模板定义(后台创建)
    → 创建审批实例(POST /instances)
    → 审批人处理(同意/拒绝/超时)
    → 结果查询(GET /instances/{code})
    → 结果落地(OKR进度/Base记录/知识库更新)
```

## 创建审批实例

```bash
lark-cli api POST /open-apis/approval/v4/instances \
  --data '{
    "approval_code": "模板code",
    "open_id": "发起人open_id",
    "form": "[{\"id\":\"widget_id\",\"type\":\"radioV2\",\"value\":\"option_value\"}]",
    "title": "📋 审批标题",
    "node_approver_open_id_list": [{
      "key": "node_id",
      "value": ["ou_xxx"]
    }]
  }'
```

### 关键参数

- `approval_code` — 审批模板code（从管理后台URL获取）
- `form` — JSON字符串数组，每个元素含id/type/value
- `title` — 可选，覆盖模板默认标题
- `node_approver_open_id_list` — 当前节点审批人

### 常见Widget类型

| type | 描述 | value格式 |
|:---|---|:---|
| input | 文本输入 | 字符串 |
| textarea | 多行文本 | 字符串 |
| radioV2 | 单选 | option的value |
| number | 数字 | 数字 |
| fieldList | 明细表格 | []或子字段数组 |

## 超时自动批准

非交易类审批实例超时30分钟后触发AI兜底决策：

1. `approval-timeout-check` cron每10分钟扫描PENDING审批单
2. 超时≥30分钟 → 查询审批详情
3. AI评估是否可自动批准（基于审批类型+表单内容）
4. 自动批准 → 走完审批流程
5. 落地变更：Base记录更新+进展推送

**不自动处理的审批**：涉及资金/仓位/策略变更的交易类审批（需要人工确认）。

## OKR-Base-Knowledge 同步链

审批通过后的自动落地链：

```
审批通过
   ↓
① 飞书Base更新记录（状态字段→已批准）
② OKR进展推送（记录本次审批决策）
③ 知识库更新（涉及规则变更时更新对应文件）
④ Trading-Research群通知变更落地
   ↓
同步完成（回写审批备注：已同步四组件）
```

## 查询审批状态

```bash
# 获取审批实例详情
lark-cli api GET /open-apis/approval/v4/instances/{instance_code} --format json

# 同意（bot作为审批人时）
lark-cli api POST /open-apis/approval/v4/tasks/approve \
  --data '{"approval_code":"...","instance_code":"...","user_id":"ou_xxx","comment":"同意"}'
```
