# 索引体系 — 系统索引架构

> 系统知识索引三级分层架构，确保快速定位、深度搜索、自动审计。
> 源：index-ops v1.7.0

## Z轴三层索引层级

```
Z轴索引体系
┌───────────────────┐
│ L1：系统主索引     │  → SYSTEM_INDEX.md（全局导航入口）
├───────────────────┤
│ L2：目录级INDEX   │  → 每个子系统/域的 INDEX.md
├───────────────────┤
│ L3：文件内锚点    │  → 每个知识文件的内部章节/TOC
└───────────────────┘
```

### L1：系统主索引

位置：`archives/Dreambuddy-V2-main/SYSTEM_INDEX.md`

作用是全系统目录导航入口，指向所有子系统的顶级INDEX：
- 1-ARCHITECTURE/ → 架构归档
- 2-KNOWLEDGE/ → 知识库（三层存储：交易/技术/理论/运营）
- 知识库 0-哲学/ / 1-理论/ / 2-经验/ → 分类知识

### L2：目录级 INDEX

每个子系统目录下必须有一个INDEX.md，包含：
- 本目录文件列表（含说明+来源Skill）
- 目录间的知识流/数据流
- 使用指南

### L3：文件内锚点

每个知识文件内部使用章节标题作为导航锚点。

## 51 INDEX/README 覆盖

系统现有索引覆盖目标：所有顶层及二层子目录需有INDEX.md或README.md。

健康度评分标准：
| 等级 | 条件 |
|:---:|:---|
| A | 有独立INDEX + 有README + 子目录全覆盖 |
| B | 有INDEX或README |
| C | 有索引但内容陈旧/不完整 |
| D | 无任何索引 |

## 每日审计（index-ops）

cron任务 `index-ops-daily-audit` 每日23:00运行：

1. 扫描项目物理目录结构
2. 对比飞书Base中的「索引清单」记录
3. 计算覆盖率 + 健康度评分
4. 生成优化建议（新目录无索引→建议创建、索引陈旧→建议更新）
5. 飞书Base同步差异
6. 推送审计摘要到Trading-Research群

### 审计规则

- 连续3次评分不变 → 降级为「需关注」
- 连续7次无变化 → 降级为「待优化」+ 标记死索引
- 新目录检测到无INDEX → 自动标记「需关注」

## 铁律：本地修改后必须同步飞书Base

飞书Base中的数据是用户唯一看到的系统状态面板。本地修改不同步Base = 工作没做完。同步方法见 index-ops SKILL。
