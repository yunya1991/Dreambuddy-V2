# 三段式门禁 — Governance Meta Chain v3.2

> 系统元认知架构的严格门禁规则。三段链路依次执行，不可跳过，除非用户明确授权。
> 源：governance-meta-chain v3.2
>
> ⚠️ **Rule 0（跳步门禁）** 高于一切规则——详见 5-METHODOLOGY/三链接力协议.md

## 架构总览

```
用户需求 → 链路1(脑暴) → Spec(文档固化) → 链路2(执行进化)
                          ↑
                     默认走完整链
                     用户授权→可跳过
```

三段职责分离：
- **链路1** = 想清楚、做决策，不产出文档
- **Spec** = 把链路1思考写成完整逻辑链，可审查可追溯
- **链路2** = 按Spec落地，归档进化认知

### 跳步规则（高于一切）

| 情况 | 行为 |
|:---|---|
| 用户说"跳过""直接执行""授权跳过" | ✅ 可跳过，记录 override + 用户授权证据 |
| 用户说"好的""嗯""继续" | ❌ 这是同意当前步骤，不是授权跳过后续步骤 |
| 用户不回复 | ❌ 默认走完整链路 |
| 系统自行推断"这个简单" | ❌ 严重违规 |

详见 `5-METHODOLOGY/三链接力协议.md` 的 Rule 0。

## 链路1：认知获取链

### 核心纪律

1. **先调查** — 理解用户想干什么，不默认理解意图
2. **验证假设** — 形成根因假设后必须用工具验证
3. **善用索引** — 通过INDEX.md快速定位问题领域
4. **择优决策** — 列出至少2个方案，理论框架比较后选择
5. **哲学约束** — 最终选择不违反最高原则（V9规则/宪法）

### 联网自学兜底

当知识库+记忆+理论三层都找不到可行方案时：
- 默认允许联网搜索
- 搜索到的知识必须回补到四层体系（记忆→经验→理论→哲学）
- 标注来源URL+日期

## Spec：文档固化

Spec是链路1脑暴结果的完整文本化，6要素缺一不可：

| 要素 | 内容 | 对应链路1步骤 |
|:---|---|:---:|
| ① 用户需求 | 用户想做什么 | 调查结论 |
| ② 问题诊断 | 症状+根因+影响范围 | 索引定位结论 |
| ③ 多个方案 | 至少2个可选方案 | 知识库+记忆结论 |
| ④ 推荐方案 | 推荐 + 理由 + 不选原因 | 理论择优结论 |
| ⑤ 执行计划 | 具体执行步骤 | 方案设计 |
| ⑥ 风险与回退 | 风险点+回滚/降级措施 | 哲学约束结论 |

**门禁**：链路1未完成 → 不写Spec | Spec 6要素不全 → 不进链路2

## 链路2：执行进化

```
Plan → 测试 → 执行 → 归档进化
```

### 执行纪律

1. **测试强制** — 功能验证必须实际执行，不得伪造
2. **多端到端验证** — ≥2个子系统时检查组件间连接，不只检查独立可用
3. **验证先于归档** — 不验证就归档=严重违规
4. **执行后确认回滚路径就绪**

### 回滚规则

| 失败场景 | 回滚操作 |
|:---|---:|
| 组件连接验证失败 | 保留原有连接，新建的连接回退 |
| 审批超时未处理 | 30分钟后AI自动审批（非交易类） |
| 脚本执行超时 | no_agent → AI驱动模式降级 |
| 数据写入冲突 | 保留旧数据，新写入标记为失败 |
