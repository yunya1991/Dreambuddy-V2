# 交易执行链路

> 从信号生成到OKX下单的完整链路。

## 链路总览

```
[1] 数据采集 → [2] 特征计算 → [3] 战略层评估 → [4] BCRM推理 → [5] 风控门禁 → [6] 下单执行
      │              │              │              │              │              │
   launchd       macro_feat     五计庙算      344+278模型    三层过滤      OKX API
   调度器        .py计算        五维评分      CBR检索        仓位/熔断      现货
```

## 详细步骤

### Step 1: 数据采集（launchd调度）
- panewslab_all: 每4小时，route='all'
- theblockbeats_dataview: 每30分钟
- stablecoin_latest: 每1小时
- 存入SQLite，Bronze层保留原始

### Step 2: 特征计算（macro_features.py）
- 输入：Gold层干净数据
- 输出：13+宏观特征（btc_etf_flow_3d, stablecoin_minus_rwa, whale_netflow_pulse等）
- 配置：configs/macro_features.yaml（YAML覆盖+硬编码fallback）
- 质量门禁：nonnull ≥3 通过，≥40 bars才可WalkForward验证

### Step 3: 战略层评估（五计庙算）
- **五维评分**: 道30%/天15%/地25%/将15%/法15%
- **总分分档**: ≥75进攻 / 60-74防御 / 50-59轻仓防守 / <50全禁
- **仓位映射**: ≥85→80-100% / 75-84→50-80% / 60-74→20-50% / <60→0-20%
- **否决规则**: 道<40→≤30% / 将<40→≤30% / 法<40→不开新仓 / 地<40且天<40→只对冲
- **Shadow模式**: force_vector只审计不注入（观察期7天）

### Step 4: BCRM2.0推理
- **L1模型**: 344个二元矛盾推理单元
- **L2模型**: 278个融合模型
- **CBR检索**: θ_match*=0.71 top-3历史案例权重融合
- **卦象映射**: 易经64卦 → 方向/置信度
- **输出**: 交易信号（做多/做空/空仓）+ 置信度

### Step 5: 通用风控门禁
- **第一层**: 仓位限制（单币种+组合上限）
- **第二层**: 单笔风险（SL/TP空间下限：常规SL≥1.5%/TP≥3.0%）
- **第三层**: 组合熔断（可用金额亏损>20%触发）
- **保护期**: 开仓后6小时内仅硬离场生效
- **离场确认**: 2次连续触发才执行（300秒窗口）

### Step 6: 交易执行（OKX API）
- **交易所**: OKX现货
- **下单类型**: 市价单
- **杠杆**: 无（现货）
- **持仓同步**: 每轮询周期同步实际持仓
- **轮询间隔**: 5分钟（生产环境）

## 离场决策链路

```
持仓监控 → EV雷达7子分 → EV<-0.35？ → 强制离场
                │
                ├→ 信号反转？ → EXIT_ACT_SIGNAL_REVERSE
                ├→ 易经强制？ → EXIT_ACT_YIJING_FORCE_CLOSE
                ├→ P3提前？ → EXIT_ACT_P3_EARLY_EXIT
                ├→ EV强制？ → EXIT_ACT_EV_FORCE_CLOSE
                └→ 排名止盈？ → EXIT_ACT_RANKED_TP
```

