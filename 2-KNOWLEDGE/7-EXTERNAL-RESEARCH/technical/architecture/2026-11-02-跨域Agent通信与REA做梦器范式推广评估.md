## §0 Executive Summary

### 0.1 我们已经有 3 条跨域通信路径，全部是**点到点硬接线**

| 路径 | 载体 | 状态 | 覆盖率 | 核心问题 |
|---|---|---|---|---|
| WorkspaceBus（GWT Pub/Sub） | `workspace_bus.py` broadcast/subscribe | ✅ 已落地 | 仅 4-MEMORY 内部订阅者 | **广播信号只含 intent/memory/skill/knowledge**，不含域内 agent 的分析结论/反思结果/做梦路径 |
| record_hook / verify_hook | `cognitive_mcp_server.py._handle_record/_handle_verify` 末尾调 `skill_indexer.record_hook()` | ✅ P0-1 已接线 | **cognitive_links 覆盖率 26% 停滞** | 只覆盖 SKILL system，不覆盖 REA/评测/语义域的 agent 输出；hook 触发 tags 判断含 "SKILL" 才调，窄触发条件 |
| Evidence Ledger + PoE | `cognitive_loop_entry.record()` 末尾追加 EvidenceEntry → `verify()` 开头 `_check_poe_trust()` | ✅ 已落地 | REA → Ledger → record 闭环 ✅ 三模式（light/heavy/sample） | PoE 是**事后审计链**，不是 Agent 间实时/准实时通信通道 |

**结论**：我们没有一个**统一的 Agent 间消息路由层**。每个域的 agent 自己去 recall/record，别人自己也去，没有协调者。

### 0.2 REA 做梦器是**单域自改进**，范式可推广

REA 做梦器的核心机制（SPEC-33-反思层）：

```
发现树 T（完整分析轨迹 JSON，agent_id + task_type + nodes + evidence_refs + cost）
       │
       ▼ 回放模拟器（Replay Simulator）
候选策略 π = {analyzer_sequence, depth_params, stop_conditions, parallelism, budget}
       │
       ▼ 确定性重放（不调分析器，只回放 children_record）
V(π, T) = 归一化 hypervolume(质量-成本点集) − λ × 并行度惩罚
       │
       ▼ argmax V 选 π_{t+1}
改进策略重新部署在线
```

**为什么能推广到跨域 Agent 通信**：REA 做梦器的本质是「**基于历史交互轨迹 → 生成候选策略 → 回放评估 → 选最优**」——这个范式不依赖 REA 特定的分析器，通用化后可变为「**基于跨域 Agent 交互轨迹 → 生成候选通信策略 → 回放评估 → 选最优**」。

### 0.3 影子双跑是唯一正确的第一步

任何跨域通信方案如果直接切流，最坏情况：
- Agent 消息风暴（每个 agent 想知道所有域的信号）
- context window 被外部信号淹没，REA 做梦路径被干扰
- Mandate 写门控被绕过（agent 间传递的信息触发写路径但没经过宿主）

**影子双跑模式**：新通信策略并行跑，但**不影响线上 agent 行为**。影子只观察、评估、产出报告，不注入决策链。

## §2 统一 Agent 通信路由层设计（Draft，影子模式验证先行）

### 2.1 定位：**AgentMail** — 不替代 MCP 壳，壳后路由层

```
[IDE / DSH / 外部系统]
        │  MCP stdio JSON-RPC（壳层，不变）
        ▼
┌ MCP 壳 ───────────────────┐
│ envelope.data 业务体透传   │ ← 本 SPEC-L0 壳
└──────────┬────────────────┘
           │ 调用返回 envelope
           ▼
┌ AgentMail 通信路由层 ──────┐
│ 影子模式：观察 + 评估 + 报告 │ ← 本评估要设计的
│ 激活模式：消息路由 + 触发 + 学习 │
└──────────┬──────────────────┘
           │ AgentMail 传递的 envelope.data + 反射指令
           ▼
┌ 各域内 Agent ─────────────┐
│ 认知 / REA / 评测 / 语义 / 数据 │
└──────────────────────────┘
```

**关键**：AgentMail 不是 MCP 壳的替代品，而是壳**之后**、agent 之前的一层。壳的 envelope.data 是契约边界（H1），AgentMail 传递的也是 envelope.data（零 schema 变化）。

### 2.2 三种通信模式 + 影子验证方案

#### 模式 A：事件订阅-触发（Event Subscription）

```
域 B agent 订阅域 A 的特定事件类型
    │
    │  A 域产出 envelope.data 含 event.type
    │  AgentMail 匹配 → 通知 B 域 agent
    │
    ├─ 影子模式：只记录"如果通知会触发 B 域什么行为"，不真正触发
    └─ 激活模式：通知 B 域 agent 执行（B 域 agent 需有 handle_trigger 接口）
```

**用例 C1**：REA agent 订阅 `"knowledge_retrieval.new_doc"` 事件 → AgentMail 观察到知识库新入库 → 影子报告 "如果触发，会对 project_x 跑 s33_rea_analyze" → 人工确认后激活。

**影子实现**：
```python
# AgentMail 影子观察器（不影响线上行为）
class AgentMailShadow:
    def observe(self, domain, envelope_data):
        """影子模式：只观察 + 匹配 + 生成报告"""
        matches = self._match_subscriptions(domain, envelope_data)
        for m in matches:
            report = self._generate_projected_behavior(m)
            self.shadow_reports.append(report)
        # 绝不触发 B 域 agent！
```

#### 模式 B：最优路径蒸馏（Dream Path Distillation）

```
REA 做梦器产出 V(π, T) 最优策略配置
    │
    │ AgentMail 提取策略配置 + V 值 + 证据链
    │
    ├─ 影子模式：① 把策略配置广播给其他域 agent 的 shadow 实例
    │          ② shadow 实例用历史轨迹回放策略
    │          ③ 报告"该策略在本域 V 值 = X，是否有推广价值"
    └─ 激活模式：V 值达标 + PoE 信任达标 → 策略配置自动注入其他域 agent
```

**用例 C5**：REA 做梦器发现 `π = {call_chain_tracer → python_analyzer → design_decision}` 在 7 棵发现树中 V > 0.85 → 影子模式：把 π 给评测 45 shadow → 45 用历史评测轨迹回放 π → 报告 V=0.72（略低但可接受）→ 激活模式：自动注入评测域 agent 策略配置。

**核心机制复用 REA 做梦器**：
- 发现树 T → **跨域交互轨迹**（agent_id + domain + task_type + interaction_nodes + evidence_refs + cost）
- 策略配置 π → **通信策略**（subscriptions + trigger_conditions + handler_sequence + stop_conditions + budget）
- V(π, T) 目标函数 → **跨域通信质量-成本评估**（可直接复用 REA Dream-RSI 的 hypervolume 公式，换成本/质量维度）

#### 模式 C：主动反思闭环（Proactive Reflection）

```
域 A agent 反思产出 envelope.data 含 reflection.verdict="needs_improvement"
    │
    │ AgentMail 匹配 → 判断是否跨域问题
    │
    ├─ 影子模式：只记录"如果通知下游域 B 会触发什么"
    └─ 激活模式：自动触发 B 域的主动监控（如 PSI drift_detector 跑一次）
```

**用例 C3**：评测 45 反思"实体解析漂移了" → AgentMail 匹配到语义 39 agent → 影子报告"如果触发，会跑一次 PSI 漂移监控" → 人工确认后激活。

## §3 REA 做梦器范式推广为 Agent 间学习算法

### 3.1 推广映射表

| REA 做梦器概念 | 跨域 Agent 通信推广 | 当前已实现 | 影子验证要做什么 |
|---|---|---|---|
| 发现树 T（JSON，agent 分析轨迹） | **Agent 交互轨迹树**（agent_id + domain + interaction_type + cost + evidence_refs） | ❌ 无，WorkspaceBus 广播只有 intent/memory/skill/knowledge，不含 agent 交互节点 | 影子只记录，不急着全量持久化 → 先跑 1 周收集 ≥ 10 棵轨迹树 |
| 策略配置 π（JSON，分析编排） | **通信策略配置**（JSON，订阅关系 + 触发条件 + handler 顺序 + 停止条件 + 预算） | ❌ 无统一策略，各域硬编码触发 | 影子先人工写 3-5 个候选 π → 回放评估 → 选最优 |
| 回放模拟器（Replay Simulator） | **跨域交互回放引擎**（确定性重放，不真正触发 agent，只回放记录） | ❌ REA 内部有但只回放 REA 发现树 | 先复用 REA replay_simulator 做基础，扩展跨域 tree schema |
| V(π, T) 目标函数（hypervolume） | **跨域通信 V 函数**（质量=PoE evidence_chain_score × 跨域引用数；成本=消息数 × 平均处理时间） | ❌ 无 | 先人工定义初始 V 函数，影子跑完 1 周后调整 |
| argmax V 选 π_{t+1} | **跨域通信策略自动选择**（argmax V → 自动更新通信策略） | ❌ | 影子 1 周后 V 有统计意义时启用自动 argmax |
| 外部路径获取（成熟项目解析） | **跨域经验注入**（A 域的"成熟交互"→ B 域的先验） | ❌ REA 内部有 external replay pool | 影子 1 周后如果有跨域交互 > 3 次，记录为"成熟交互案例" |
| Dream-RSI 不劣化保证（当前策略在候选集） | **通信策略不劣化保证**（当前硬编码策略保留在候选集，改进策略仅在 V 优于当前时采纳） | ❌ | 影子阶段**不切换**，V 统计显著优于当前才激活 |

### 3.3 跨域通信 V 函数初版（影子阶段）

```python
def V_communication(tree, strategy):
    """
    跨域通信质量-成本目标函数（影子阶段初版，1 周后调优）
    
    质量 = 跨域交互产生的 PoE evidence_chain_score 之和 × 跨域引用数
    成本 = 消息数 × 平均处理时间（毫秒）
    V = 归一化(质量) / max(归一化(成本), 1)
    """
    # 质量：每条跨域交互的 PoE 评分
    quality = sum(
        node.get("poe_score", 0.5) * (1 + 0.1 * node.get("cross_domain_refs", 0))
        for node in tree["trajectory"]
    )
    # 成本：消息数 × 平均处理时间
    cost = sum(
        node.get("cost", {}).get("messages_sent", 1) * node.get("cost", {}).get("latency_ms", 100)
        for node in tree["trajectory"]
    )
    # 归一化 + hypervolume 结构保留（REA 范式复用）
    return quality / max(cost, 1)
```

## §4 影子双跑方案（Phase 0，1-2 周，零切流）

### 4.1 影子的三条硬约束（不突破任何红线）

| # | 约束 | 含义 |
|---|---|---|
| **S1** | AgentMail 影子模式**绝不触发**任何域内 agent 的实际行为 | 只观察、记录、评估、产出报告。不调 s33_rea_analyze、不跑 PSI drift、不写 cognitive record |
| **S2** | 影子观察器的 trace_id **必须区分** | 影子模式 trace_id 前缀 `shadow-`，可事后区分线上 vs 影子轨迹 |
| **S3** | 影子模式零资源开销 | 不新增 DB 表、不新增进程、不新增网络连接。影子报告落 `47-MCP管理系统/shadow_reports/` 本地 markdown |

### 4.2 影子验证清单（按优先级）

| # | 验证项 | 目标 | 验证方法 | 周期 |
|---|---|---|---|---|
| **V-S1** | 事件订阅-触发影子匹配 | 至少 3 次跨域事件被正确匹配 | 人工在各域 agent 执行典型任务 → 影子报告匹配的 projected action 是否合理 | 1 周 |
| **V-S2** | 交互轨迹树收集 | ≥ 10 棵有效跨域交互轨迹 | 影子模式记录自然发生的跨域调用 → 检查 tree schema 是否可用 | 1 周 |
| **V-S3** | 通信 V 函数初版有效性 | V 值分布合理（0.3-0.9 区间，区分度足够） | 10 棵轨迹树算 V → 看是否能区分"好的跨域交互"和"差的" | 1 周 |
| **V-S4** | REA 做梦器策略跨域 V 值测试 | REA 最优策略（V=0.87）在其他域影子回放 V ≥ 0.6 | 取 REA 外部路径池中 V>0.85 的策略 → 影子给其他域回放 → 看 V 值 | 2 周 |
| **V-S5** | 影子模式零副作用 | 线上行为零变化 | 前后对比 cognitive_links 覆盖率、verify 命中率、recall 延迟 | 全程 |

### 4.3 影子 → 激活 升级判据

| 升级条件 | 含义 | 升级内容 |
|---|---|---|
| V-S1 通过（≥3 次正确匹配）+ 人工确认 projected action 合理 | 事件订阅-触发的影子观察足够可信 | 激活模式 A，先在 REA→评测 跨域试点 |
| V-S3 通过（V 值区分度好）+ REA 最优策略跨域 V ≥ 0.6 | 跨域通信 V 函数和策略蒸馏范式可用 | 激活模式 B，先在 REA→评测 试点 |
| S1/S2/S3 三条硬约束始终满足 | 影子零副作用可保证 | 任何阶段激活都保留影子 fallback |
| bcrm2 切流完成后 | 避免与实盘切流并行 | 激活时间点在 bcrm2 切流后 |

## §6 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 影子观察本身引入延迟 | 低 | 中 | 影子观察异步，不阻塞主路径，延迟 < 1ms |
