## §0 架构纠正（之前完全搞反了）

**正确的三层定义**（SPEC-v1.3-L0L1L2-architecture.md L10-18）：

| 层级 | 定义 | 驱动方式 | 成本 |
|---|---|---|---|
| **L0 基础能力层** | 数据存储/采集/结构化 + 经验沉淀 + 逆向工程 | 数据库/采集管线/规则/贝叶斯 | 零 token |
| **L1 基础智能层** | **不依赖大模型的金融能力** | 算法/规则/统计/意图识别/专属金融 Transformer | **零 token，本地小模型/向量检索** |
| **L2 大模型驱动层** | 语义理解/推理/生成 | DreamOS C层 + SACG + DSH 子Agent | token 成本 |

**关键纠正**：
- 47-MCP 模块、dreambuddy_l0/envelope、REA 做梦器、TB1-TB5 训练基座 → 全部 **L0**
- 23-四层闭环自进化（NeuralSDE/路径发现/因果检查）、40-周期系统（sector_transmission.json 跨资产传导图）、34-SACG 训练编排器 → **L1**
- SACG 四层编排（S→A→C→G）、DSH 多子Agent、生成式 LLM 推理 → **L2**

**用户的核心想法**：L0 REA 严谨通信层的反馈信号（verify 评分/PSI 漂移/AlphaPareto 奖励/做梦器 V 值）→ 标注数据 → 训练 L1 专属金融 Transformer → L1 推理做 L0 跨 domain 关系发现 → AgentMail 消费 → 闭环。

```json
// 现有：跨加密资产传导
{
  "layers": { "L1_anchor": ["BTC/USDT"], "L2_major": ["ETH/USDT"], ... },

    "L2_active": ["rea", "search"],     // REA 逆向工程和 Search 活跃
    "L3_sensitive": ["semantic", "data", "eval"]  // 语义/数据/评测对漂移敏感
  },
  "domain_transmission": {
    "state": "expanding",               // expanding/contracting/neutral
    "drift_coupling": {                 // 跨 domain PSI 漂移耦合度
      "cognition↔rea": 0.72,
      "rea↔search": 0.58,
      "semantic↔data": 0.41
    },
    "regime": "bull_consolidation"      // 美林时钟四段，TB4 Thompson Sampling 联动

  "domain_breadth": {

    "state": "strong",

  }

```

**结论**：结构**完全同构**，只是 token 从资产代码换成 L0 domain 名。

## §2 L0 REA 反馈信号 → L1 训练标注的可行性

### 2.1 TB1-TB5 输出与训练标注的对齐

| TB | 输出信号 | 格式 | 作为什么标注 | 标注 L1 做什么 |
|---|---|---|---|---|
| **TB1 PSI+KS** | `{domain, drift_level, psi_value, ks_pvalue, timestamp}` | 结构化 JSON | **监督学习标签**：哪些 domain 在同一时间漂移 | 训练 L1 识别漂移耦合模式（"cognition drift → rea drift 滞后 30min"） |
| **TB2 Beta verify** | `{memory_id, success_rate, alpha, beta, confidence_mean}` | 结构化 JSON | **奖励信号/权重**：哪些跨域关系更可信 | 训练 L1 给跨域边加权（"rea→semantic 边权重 0.82 高可信"） |
| **TB3 AlphaPareto** | `{p_verify_success, p_recall_hit, psi_stability, citation_diversity, process_reward, transition_smoothness}` | 六维向量 | **多目标奖励信号** | 训练 L1 的路径评分器（类似 path_discovery_service.select_optimal_path 的评分函数） |
| **TB4 Thompson** | `{regime, arm_count, posterior_alpha, posterior_beta}` | 结构化 | **条件先验**：不同 regime 下哪些关系成立 | 训练 L1 的条件推理（"bull 周期 rea→semantic 传导增强，bear 周期减弱"） |
| **TB5 GRPO** | `{strategy_config_version, field_order, known_gaps_threshold, evolved_from}` | JSON schema 约束 | **策略效果标签**：哪种通信策略在什么条件下效果好 | 训练 L1 做策略推荐（类似 GRPO 冻结权重调格式，但由 L1 推理产出候选） |
| **REA 做梦器** | `{discovery_tree, V_pi_T, call_chain_trace, hypothesis_id}` | 轨迹树 + V 值 | **路径发现 ground truth**：什么路径在哪种条件下 V 值高 | 训练 L1 的路径生成器（类似 discover_paths 但扩展到跨 domain） |
| **AgentMail 影子** | `{trajectory_entry[], V_hypervolume, config_version}` | 轨迹序列 + V 值 | **跨域关系有效性标签**：哪些跨域通信实际提升了 V 值 | 训练 L1 做跨域通信建议器 |

### 2.2 标注数据的具体格式（从 L0 反馈到 L1 训练）

```jsonl
// L1 训练标注数据（domain_discovery_training.jsonl，每条一个样本）
{"input": {"domain_states": {"cognition": {"drift": "low", "confidence": 0.78}, "rea": {"drift": "medium", "confidence": 0.65}, ...}, "regime": "bull_consolidation", "t": "2026-11-03T14:30"}, 
 "target": {"coupling_edges": [{"from": "cognition", "to": "rea", "weight": 0.72, "lags_min": 30}, {"from": "rea", "to": "semantic", "weight": 0.58, "lags_min": 15}]},
 "reward": {"V_value": 0.83, "verify_success_rate": 0.88, "dreamer_V": 0.79},
 "source": "REA_dreamer_verify",
 "timestamp": "2026-11-03T14:30"}
```

**产出位置**：可以在 TRAIN-BASE Phase 0 落地后，由 `AgentMailShadow.observe()` 旁路直接写入。

## §3 闭环架构设计

### 3.1 完整闭环图

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ L0 严谨通信层（零 LLM，H2 硬约束）                                              │
│                                                                              │
│   TB1 PSI+KS ──┐                                                             │
│   TB2 Beta verify ──┤                                                         │
│   TB3 AlphaPareto ──┤  反馈信号（verify/PSI/V/轨迹树）                          │
│   TB4 Thompson ──┤     ↓                                                     │
│   TB5 GRPO ──┤  AgentMailShadow.observe() 旁路采集                              │
│   REA 做梦器 V(π, T) ──┤     ↓                                               │
│                          trajectory_store/*.jsonl                              │
└──────────────────────────┬───────────────────────────────────────────────────┘
                           │ 标注数据
                           ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ L1 专属金融 Transformer（DreamOS SACG + DSH 训练框架，零外部 token）             │
│                                                                              │
│   训练：金融语料 + 系统日志 + 实盘数据 + ← L0 反馈标注                           │
│   模型：NeuralSDE v1 + 矛盾论 CrossAttention + sector_transmission 架构        │
│   训练频率：每周一次（非实时），增量式更新（online_trainer.py 已存在）             │
│                                                                              │
│   推理产出（domain_transmission.json，与 sector_transmission.json 同构）：        │
│     - domain_layers（跨 domain 分层：anchor/active/sensitive）                  │
│     - domain_transmission.state（expanding/contracting/neutral）                │
│     - drift_coupling（跨 domain PSI 漂移耦合度矩阵）                              │
│     - regime（美林时钟四段，TB4 Thompson Sampling 联动）                          │
│     - suggested_policies（2-3 个 π 候选，符合 STRATEGY_CONFIG_SCHEMA）           │
│                                                                              │
│   推理频率：每小时一次（cron），写入 40-周期系统目录                              │
│   推理算力：CPU 4C16G 跑几秒（Transformer 推理 on CPU）                         │
└──────────────────────────┬───────────────────────────────────────────────────┘
                           │ domain_transmission.json
                           ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ AgentMail 建议层（原来想的外部 LLM API → 换成 L1 推理结果）                       │
│                                                                              │
│   消费方式：                                                                    │
│     - observe() 内部读 domain_transmission.json 做跨轨迹关系发现                 │
│     - generate_report() 内部引用 drift_coupling 矩阵做建议章节                    │
│     - candidate_policies/ 里的 π 候选可以由 L1 推理产出（替代硬编码 JSON）          │
│                                                                              │
│   硬约束（保持 §5.5 的建议-执行分离）：                                           │
│     - L1 产出的 π 候选必须过 STRATEGY_CONFIG_SCHEMA 校验                         │
│     - 必须过 V 函数 hypervolume 评估（不比硬编码 π 差才入池）                      │
│     - 零执行权：L1 只给建议，REA 严谨通信层做最终执行决策                           │
│     - L1 推理失败 → 回退硬编码 π（FAIL-OPEN）                                    │
└──────────────────────────┬───────────────────────────────────────────────────┘
                           │ 建议输入
                           ▼
              REA 严谨通信层执行（已落地 Dream-RSI）
                           │
                           ▼
                     域内 Agent
                           │
                           ▼
               ┌───────────────────┐
               │ 新反馈信号 → 标注  │  ← 闭环完成
               └───────────────────┘
```

### 3.2 与之前设计的关系

| 之前设计 | 现在设计 | 改进 |
|---|---|---|
| COMM-SHADOW §5.5 的"外部 LLM API 建议层" | **L1 专属金融 Transformer 推理层** | 零 token 成本 / 金融领域知识已内嵌 / 可审计 / 更快 |

| OracleVerificationLayer PERSPECTIVES 注册 | **L1 drift_coupling 可以直接作为 Oracle 视角** | PERSPECTIVES 自动扩展，不用硬编码 |

## §4 可行性评估（五维度）

### 4.1 算力

| 阶段 | 算力需求 | 我们有没有 |
|---|---|---|
| L1 推理 | CPU 4C16G 跑几秒/次（每小时 1 次） | ✅ 云端已有 |
| L1 增量训练 | 需要 GPU（RTX 2060 或 T4 起步）1-2 小时/周 | ⚠️ 云端无 GPU，本地 Mac 也没 |
| L0 反馈采集 | observe() 旁路，零额外开销 | ✅ TRAIN-BASE Phase 0 落地后自然有 |
| 标注数据处理 | Python pandas，CPU | ✅ 已有 |

**GPU 解决路径**：
- 选项 A：本地 Mac Mini M1/M2 训练（Metal 加速，~4-6 小时/周增量训练，免费）
- 选项 B：腾讯云 GPU 实例（T4 ¥2.4/小时，按需开）
- 选项 C：Colab/Kaggle 免费 GPU（每周 12 小时足够）

### 4.2 时间线

| 阶段 | 前置条件 | 产出 | 时间 |
|---|---|---|---|
| **Phase 0**：标注数据管线 | TRAIN-BASE Phase 0 落地 + AgentMail 影子 Phase 0 | 标注数据 JSONL 自动生成 | TRAIN-BASE 并行，~7 天 |
| **Phase 1**：L1 增量训练 MVP | sector_transmission.json 已有 + 标注数据 100+ 条 | domain_transmission.json 初稿 | GPU 可用后 ~3 天 |
| **Phase 2**：AgentMail 消费集成 | Phase 1 产出 + COMM-SHADOW Phase 0 基线 | observe() 读 domain_transmission + generate_report 建议章节 | ~2 天 |
| **Phase 3**：闭环验证 | COMM-SHADOW Phase 1 观察期 + L1 跑满 2 周 | V 函数提升 ≥ 10% + BC 模型能识别 L1 产出的 coupling | 影子观察期 2 周 + 验证 1 周 |

**总时间**：TRAIN-BASE 7 天 + GPU 3 天 + 集成 2 天 + 验证 3 周 ≈ **40 天**（部分并行）

### 4.3 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| L1 推理产出的 domain_transmission.json 质量不够（比硬编码 π 差） | 中 | 影子验证 V 函数无提升 | 继续用硬编码 π 作为 fallback；L1 不阻塞 |
| GPU 资源不可用 | 低 | 训练延迟 | 本地 Mac Metal 或 Colab 免费 GPU |
| TB1-TB5 落地慢（M1④→M2-M3 被打断） | 中 | 标注数据断供 | 先用 40-周期系统的 sector_transmission.json 架构 + 手工造 100 条标注做 MVP |
| L1 训练引入 H2 硬约束冲突（"权重微调"） | 极低 | 架构冲突 | **不微调原有模型权重**，只加一个轻量 output head（线性层或小 MLP）做跨 domain 预测；原有 Transformer 权重冻结 |

### 4.4 不突破的硬约束

| 硬约束 | 如何保证 |
|---|---|
| **H2 无神经网络权重微调** | L1 推理是推理，不是训练。训练时只加一个轻量 output head（< 1MB 参数），冻结原有 Transformer 权重。这与 TRAIN-BASE TB5 GRPO 冻结权重调格式同属"策略格式调优"范畴 |
| **H3 可审计** | L1 推理产 trace_id（前缀 `l1-infer-`），domain_transmission.json 落盘可回溯，标注数据 JSONL 完整保留 |
| **H4 FAIL-OPEN** | L1 推理失败 → AgentMail 回退硬编码 π；L1 训练失败 → 继续用上一版 model.pt |
| **H8 PSI 阈值硬编码** | L1 推理只读 TB1 PSI 值，不碰阈值常量 |
| **H9 影子三条** | AgentMail observe() 内部读 domain_transmission.json 是旁路，零触发 agent |
| **PACKAGING Mandate** | 不修改壳 envelope.data schema，所有 L1 产出走 envelope.meta 扩展 |

### 4.5 与外部 LLM API 方案的对比

| 维度 | L1 专属金融 Transformer（推荐） | 外部 LLM API（之前 §5.5 的想法） |
|---|---|---|
| token 成本 | **零** | ¥10-100/月（随调用量线性增长） |
| 金融领域知识 | **已内嵌**（sector_transmission 架构 + 矛盾论 CrossAttention） | 通用 LLM 瞎猜，可能输出荒谬关系 |
| 可审计 | **100%**（模型权重 + 训练数据全在本地/云端） | API 黑盒，无法审计推理过程 |
| 推理延迟 | **CPU 几秒** | API 几十秒（取决于网络） |
| 可复现 | **完全确定**（相同输入 → 相同输出） | 有随机性，相同输入可能输出不同 |
| 硬约束冲突 | 无（推理 = 策略格式建议） | 需额外论证"不违反 H2" |
| 维护成本 | 增量训练每周 1 次，自动跑 | API key 管理 + rate limit + 费用监控 |

## §6 核心洞察总结

| # | 洞察 |
|---|---|
| 1 | **L1 已经在做跨资产传导（sector_transmission.json），扩展到跨 L0 domain 是同构问题** |
| 2 | **TB1-TB5 输出格式与 L1 训练标注数据高度对齐**（PSI 漂移→标签、Beta verify→权重、AlphaPareto→奖励、REA 做梦器 V 值→ground truth） |
| 3 | **闭环不是"加新模型"，是"已有模型换数据源"**——NeuralSDE v1 的 output head 加几个维度就做 domain coupling 预测 |
| 4 | **零外部 token 成本**——比外部 LLM API 方案更经济、更安全、更可审计 |
| 5 | **不违反任何硬约束**——推理不是训练；训练只加轻量 output head 冻结主体权重；AgentMail 消费保持建议-执行分离 |
| 6 | **最适合先做的 MVP**：静态写一版 domain_transmission.json（从 sector_transmission 改字段），让 AgentMail observe() 先消费，验证链路通了再上 L1 训练 |
