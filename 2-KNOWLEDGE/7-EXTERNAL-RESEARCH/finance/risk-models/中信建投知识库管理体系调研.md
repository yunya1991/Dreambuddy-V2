## 调研结论

中信建投证券的知识库管理体系核心是**三层融合 + 持续进化闭环**，已在15万文档/60万条目/28业务域上验证有效，幻觉率从38%降至4-7%。

## 调研路径

### 1. 中信建投三层融合架构

```
┌─────────────────────────────────────────────┐
│  RAG层（检索增强生成）                        │
│  大语言模型 + 外部知识源 → 可溯源生成          │
│  解决幻觉问题，引用来源透明                     │
├─────────────────────────────────────────────┤
│  向量检索层                                  │
│  高性能向量数据库 → 语义化索引 + 相似度检索     │
│  支持自然语言精准知识获取                      │
├─────────────────────────────────────────────┤
│  知识图谱层                                  │
│  实体关系网络（公司/行业/产品/规则）            │
│  为智能体提供结构化关联推理能力                 │
└─────────────────────────────────────────────┘
```

### 2. 知识驱动持续进化机制

```
采集 → 清洗 → 标注 → 索引 → 反馈 → 进化
  │       │       │       │       │       │
  │       │       │       │       │       └→ 知识库持续丰富，数智员工提升
  │       │       │       │       └→ 人机协同反馈，纠正纳入知识库
  │       │       │       └→ 向量化+图谱化索引
  │       │       └→ 自动标注+人工审核
  │       └→ 去重/归一化/消歧
  └→ 多源异构数据采集
```

### 3. RAG技术四代演进

| 代际 | 架构特征 | 幻觉率 | 适用场景 |
|------|---------|--------|---------|
| 第一代Naive | 单次向量检索+直接生成 | 38-45% | 简单问答 |
| 第二代Advanced | 查询改写+多路召回+重排序 | 18-22% | 企业知识库 |
| 第三代Modular | 模块化管线+自适应路由+多模态 | 8-12% | 复杂业务推理 |
| 第四代GraphRAG | 知识图谱+向量混合+因果推理 | 4-7% | 多跳推理/决策支持 |

### 4. 六层架构模型

| 层 | 职责 | 技术选型 |
|---|---|---|
| 数据接入层 | 多源异构数据采集解析 | PyMuPDF/python-docx/BeautifulSoup |
| 文本分块层 | 语义分块（非固定token） | SemanticChunker（BGE嵌入相似度） |
| 向量化层 | 文本块→高维向量 | BAAI/bge-large-zh（1024维） |
| 向量存储层 | 混合检索（全文+向量） | Qdrant/Weaviate |
| 检索层 | 多路召回+重排序 | BM25+向量+图查询 |
| 生成层 | 检索结果→LLM生成 | RAG prompt工程 |

### 5. Hermes Agent LLM Wiki三层架构

| 层 | 目录 | 职责 |
|---|---|---|
| Layer 1 | raw/ | 不可变源材料，Agent只读 |
| Layer 2 | entities/concepts/comparisons/queries/ | Agent创建/更新/互联 |
| Layer 3 | SCHEMA.md | 知识库"宪法"，定义规范 |

### 6. DySECT自进化抽取系统

- 抽取→知识库增长→反馈机制闭环
- KB积累→反馈到LLM抽取器→prompt调优/few-shot采样/微调
- 共生闭环：抽取改善知识，知识改善抽取

## 在DreamBuddy中的应用

### 现状对比

| 维度 | 中信建投 | DreamBuddy-V2现状 | 差距 |
|------|---------|-------------------|------|
| 知识库规模 | 15万文档/60万条目 | 57个md文件 | 规模小但结构清晰 |
| 向量检索 | 高性能向量数据库 | 无 | **完全缺失** |
| 知识图谱 | 28业务域实体关系网络 | 无 | **完全缺失** |
| RAG生成 | 可溯源生成 | 无 | **完全缺失** |
| 持续进化 | 采集→清洗→标注→索引→反馈→进化 | recall→record→verify闭环 | **已有认知记忆闭环，缺知识库闭环** |
| 反馈机制 | 人机协同知识反馈 | verify贝叶斯升级 | **已有，但未连接知识库** |

### 落地路径建议

分3阶段逐步实施：
1. **阶段1（向量检索层）**：为2-KNOWLEDGE的57个md文件建立向量索引
2. **阶段2（知识图谱层）**：构建交易域实体关系网络
3. **阶段3（RAG融合层）**：三层融合 + 持续进化闭环
