# 知识库缺口分析 — 三链对齐方案

> D2 产出：当前知识库 vs 三链逻辑的缺口矩阵

## 一、当前状态

| 域 | 文件数(声称/实际) | 内容质量 | 三链对齐度 |
|:---|---:|:---|:---:|
| 1-TRADING | 10/6 | ✅ 充实 | 交易域知识，供 D 链调研使用 |
| 2-TECHNICAL | 7/5 | ✅ 充实 | 技术域知识，供 Z/E 链使用 |

## 二、缺口矩阵

### 缺口 A：无三链开发知识域（🔴 P0）
三链开发的方法论（D/Z/E 系列）存在于 `3-CHAIN-DEVELOPMENT/` 目录，但**未被蒸馏进知识库**。这意味着：
- 知识库同步到飞书时，三链知识不包含
- 其他 Agent 无法通过知识库学习三链方法论
- 三链是"藏在文件里"而非"沉淀为知识"

### 缺口 B：INDEX 失准（🔴 P1）
根 INDEX 引用 28 文件，7 个实际不存在（25% 失准）
1-TRADING/INDEX 引用 10 文件，5 个不存在（50% 失准）

### 缺口 C：同步链路未验证（🟡 P2）
knowledge-sync cron 从未执行，飞书 KB 与本地 KB 的同步链路未验证。

### 缺口 D：跨域交叉引用缺失（🟡 P2）
现有 4 个知识域之间无显式交叉引用。例如：
- 交易参数速查 → 应该引用 部署与维护 中的配置说明
- 三段式门禁 → 应该引用 三链开发知识 中的门禁机制

## 三、三链对齐方案

### 方案：新增 `5-CHAIN-DEVELOPMENT/` 域

```
2-KNOWLEDGE/
├── 1-TRADING/        ← 交易知识（供 D 链调研消费）
├── 2-TECHNICAL/      ← 技术知识（供 Z/E 链消费）
├── 3-THEORY/         ← 理论知识（供 D 链分析消费）
├── 4-OPERATIONS/     ← 运营知识（供治理消费）
└── 5-CHAIN-DEVELOPMENT/   ← 三链开发方法论（新增）
    ├── INDEX.md
    ├── D-调研方法论.md    ← 蒸馏自 D1-D4
    ├── Z-规划方法论.md    ← 蒸馏自 Z1-Z4
    ├── E-执行方法论.md    ← 蒸馏自 E1-E3
    ├── 三链接力协议.md    ← 蒸馏自 PROTOCOL/
    └── 场景速查.md        ← 阈值表 + 场景决策树
```

**各文件蒸馏来源**：

| 知识库文件 | 源文件 | 核心内容 |
|:---|---:|:---|
| D-调研方法论.md | D1-D4 + A系列引用 | 四准调研法/三问分析/三景推演/Spec写法 |
| Z-规划方法论.md | Z1-Z4 | 四维扫描/边界划分/路径设计/验收矩阵 |
| E-执行方法论.md | E1-E3 | 六步执行/抗降级/可逆部署 |
| 三链接力协议.md | PROTOCOL/ + guard | 接力协议/Guard规则/文件契约 |
| 场景速查.md | README + SPEC | 5级阈值/场景决策/Agent身份表 |

### 与现有 4 域的关系

```
5-CHAIN-DEVELOPMENT (过程知识)  
        │ 消费
        ▼
1-TRADING ← D链调研时查交易知识
2-TECHNICAL ← Z/E链执行时查技术知识
3-THEORY ← D链分析时用理论框架
4-OPERATIONS ← 治理时用运营规则
```
