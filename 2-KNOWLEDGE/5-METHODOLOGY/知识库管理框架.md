# 知识库管理框架 — Knowledge Management Framework

> **定位**：定义知识库的完整生命周期管理体系
> **版本**：v1.0
> **更新**：2026-06-13
> **源**：实践经验蒸馏

---

## 一、架构总览

```
┌─────────────────────────────────────────────────────────┐
│              知识库管理框架（三环架构）                    │
├─────────────┬────────────────┬──────────────────────────┤
│  知识生命周期  │  治理与质量     │  工具与自动化              │
│             │                │                          │
│  创建 → 审核  │  INDEX审计     │  knowledge-sync cron     │
│  → 发布       │  引用准确率     │  本地 ↔ Wiki 同步        │
│  → 更新       │  内容新鲜度     │  双链交叉引用检查         │
│  → 归档       │  跨域一致性     │  OKR进展记录             │
│  → 淘汰       │  版本管理       │  元链治理审计             │
└─────────────┴────────────────┴──────────────────────────┘
```

## 二、核心原则

### 1. 源出 Skill 原则
知识库是 **蒸馏产物**，不是原始来源。每个文件标注来源 Skill：
```markdown
_最后更新：YYYY-MM-DD | 来源：<skill_name>_
```
好处：Skill 更新时能追溯哪些知识库文件需要同步更新。

### 2. 原子化原则
每文件只解决一个独立概念/规则/模式。不写"大而全"文档。
- ✅ `V9-马丁基线.md` — 只讲V9
- ❌ `交易系统全攻略.md` — 不创建

### 3. 双向同步原则
```
本地 2-KNOWLEDGE/ (权威源)
      ↕ knowledge-sync cron (每日22:00)
飞书 Wiki (消费端)
```
本地是**写入口**，飞书是**读入口**。不双写、不反向同步（避免冲突）。

### 4. 版本标记原则
每个文件必须包含：
- 最后更新日期
- 来源 Skill
- INDEX 引用同步更新

## 三、知识生命周期

```
创建 (Create)
  │ 提交者创建 → 内容基于 Skill 蒸馏
  ▼
审核 (Review)
  │ 自动检查：INDEX 引用、版本标记、来源标注
  │ 人工检查（可选）：内容准确性、交叉引用完整性
  ▼
发布 (Publish)
  │ 写入本地 2-KNOWLEDGE/
  │ 更新对应 INDEX.md
  ▼
更新 (Update)
  │ 原始 Skill 变更 → 手动更新知识库文件
  │ 或：定期治理审计发现过期内容
  ▼
归档 (Archive)
  │ 内容已过时但仍有参考价值 → 移至 _archive/ 子目录
  ▼
淘汰 (Retire)
  │ 内容完全无效 → 删除文件 + 更新 INDEX
```

### 创建规范

| 规范 | 要求 |
|:---|---|
| **文件名** | 短横线分隔中文：`Screen1-七维牛熊评分.md` |
| **首行** | `# 标题 — 副标题` |
| **第二行** | `> 一句话摘要` |
| **签名** | `_最后更新：YYYY-MM-DD \| 来源：<skill>_` |
| **行数** | 30-120 行为佳（过短无内容，过长分散） |

## 四、5域职责与边界

| 域 | 职责 | 什么不放这里 |
|:---|---:|:---|
| **1-TRADING** | 交易规则、参数、信号体系 | 行情数据、回测结果 |
| **2-TECHNICAL** | 系统架构、部署、工具链 | 依赖版本号、日志文件 |
| **3-THEORY** | 哲学原则、方法论框架 | 交易策略代码 |
| **4-OPERATIONS** | 运营流程、索引、OKR、审批 | 具体审批实例数据 |
| **5-METHODOLOGY** | **过程知识**：D/Z/E三链方法论 | 具体代码实现 |

### 域间交叉引用模式

```
|1-TRADING ← 引 → 5-METHODOLOGY（D链调研用到交易知识）
|2-TECHNICAL ← 引 → 5-METHODOLOGY（E链执行用到技术知识）
|3-THEORY ← 引 → 5-METHODOLOGY（D链分析用到理论框架）
|4-OPERATIONS ← 引 → 5-METHODOLOGY（治理用到门禁协议）
```

## 五、质量指标体系

| 指标 | 目标 | 当前值 | 检查方式 |
|:---|---:|---:|:---|
| INDEX引用准确率 | 100% | ✅ 100% | `search_files` 对比 INDEX vs 实际文件 |
| 文件版本标记率 | 100% | 待查 | `grep "最后更新"` |
| 来源标注率 | 100% | 待查 | `grep "来源："` |
| 文件行数合理率 | 80%+ (30-120行) | 待查 | `wc -l` 统计 |
| 跨域交叉引用覆盖率 | 每个域≥2条 | 待查 | 搜索 `../` 引用 |
| Wiki同步延迟 | <24h | ✅ 立即 | `last_run_at` |
| 内容过期率 (>30天未更新) | <10% | 待查 | `find -mtime +30` |

## 六、治理流程

### 每日 (22:00) — 自动
```
knowledge-sync cron 运行：
1. 检测 2-KNOWLEDGE/ 变更
2. 追加变更摘要到飞书 Wiki
3. 创建 OKR 进展记录
4. 更新演化日志
```

### 每周 (周日 22:00) — 自动审计
```
元链治理 cron 运行：
1. INDEX引用准确率检查
2. 文件新鲜度检查
3. 跨域交叉引用检查
4. 生成治理报告
```

### 每月 — 人工治理
```
1. 淘汰过时文件（>90天未更新且无引用）
2. 合并重复/相似内容
3. 优化目录结构
4. 更新管理框架本文档
```

## 七、故障处理

| 故障 | 处理方式 |
|:---|---|
| INDEX 引用丢失 | `search_files` 查找所有 INDEX → 对比实际文件 → patch 修复 |
| Wiki 同步失败 | 查 cron `last_status` → 手动 `cronjob run` 重试 → 查看输出日志 |
| 文件内容过期 | 查 Skill 最新版本 → 蒸馏更新 → 更新 INDEX 日期 |
| 交叉引用断裂 | 文件被删但仍有引用 → 补上说明或删除引用 |
