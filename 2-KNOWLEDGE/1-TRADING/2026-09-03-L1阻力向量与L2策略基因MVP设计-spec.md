## 1. 边界与成功标准

### 1.1 MVP 目标

产出两个可独立验证、对现有交易链零侵入的中间产物：

- **产物 A** `resistance_features.py` — 从现有 FeatureHub/行情数据输出标准化的 **5 维阻力向量特征**
  `R = [R_up, R_down, R_smooth, R_flow, R_reflexivity]`，归一化 [0,1]，每条 K 线/币种一行。
- **产物 B** `strategy_gene_schema.py + strategy_genes/` — 把现有 4 条核心策略（V9 马丁基线、V15 马丁、三屏趋势、易经推理）拆解为 **条件基因 × 动作基因** 的结构化片段库，每条基因带元数据（命中频率、历史夏普、ESS 稳定性得分）。

A 与 B 不直接修改现有 A 系列调度链、不开仓、不接入实盘。产出物写入 Gold 层可用数据/知识库，**供后续 L3 RL 探索、CBR 检索升级直接消费**。

### 1.2 非目标（明确排除）

- ❌ 不改造 v15_signal.py、易经推理、三屏信号等现有生产代码
- ❌ 不接入 RL 训练、不做 V(s) 价值函数求解（L3/L4 留给下一期）
- ❌ 不做执行端的滑点冲击优化（那是 rl-order-execution 的课题）
- ❌ 不引入 PyTorch/TensorFlow 等重型依赖（MVP 只用 numpy+pandas+现有 talib）

### 1.3 成功标准

| 度量 | 阈值 | 验证方法 |
|:---|:---|:---|
| 阻力向量覆盖度 | ≥ 95% 交易币种有 ≥ 30 天历史特征 | Silver→Gold 质量门禁 quality.py |
| 阻力方向准确率 | 真实突破日 `R_up−R_down < −0.4`（向下阻力小）或 `> 0.4`（向上阻力小）的样本中，次日沿方向延续比例 ≥ 62% | 离线回测 vs 随机 50% 基准 |

| FAIL-OPEN 覆盖率 | 异常路径 100% 中性兜底 + 6 层堆栈日志 | 单元测试 + 故障注入 |

## 2. L1 阻力向量特征 — 5 维公式与数据源

### 2.1 设计理念

每维对应一条来自传统金融调研的理论：

- **R_up / R_down** ← Wyckoff 供需律 + 利弗莫尔关键位（显性阻力：筹码 / 均线 / 密集成交区）
- **R_smooth** ← 利弗莫尔「走势流畅度」（真趋势干脆、震荡拉锯阻力大）
- **R_flow** ← Wyckoff 努力 vs 结果（量价背离 = 阻力增加）
- **R_reflexivity** ← 索罗斯反身性双层（隐性阻力 = 共识分歧度）

5 维都是 **[0, 1] 归一化**。数值越高 = 对应方向阻力越大（R_up 高 = 上涨越困难）。

### 2.2 单维定义与公式

#### ① R_up：向上阻力（显性）

当前价格向上移动到「下一个显著供给区」需要克服的压力。权重默认 `w₁:w₂:w₃ = 5:3:2`，MVP 先固定，后续 Bayesian 校准：

$$R_{up} = 0.5\cdot R_{chip} + 0.3\cdot R_{ma} + 0.2\cdot R_{vol}$$

| 子项 | 公式 | 数据来源 |
|:---|:---|:---|
| R_chip 筹码阻力 | `1 − exp(− 加权套牢盘比例)`，套牢盘 = 近 90 日 volume_profile 中 cost_basis > 当前价的成交量占比 | FeatureHub volume_profile；缺失兜底 `R_chip=0.5` |
| R_ma 均线阻力 | `上方 0~5% 区间 MA200/MA50/MA20 条数 / 3`；MA200 缺失 → Fib 0.786 替代（遵循项目硬约束） | talib.MA / 经典指标 |
| R_vol 放量滞涨 | 近 5 日「涨幅 < 1% 且成交量 > MA(vol,20)·1.5」的天数 ÷ 5（Wyckoff「努力无结果」） | Silver OHLCV |

加权后 clamp `[0, 1]`。

#### ② R_down：向下阻力（显性）

R_up 镜像：筹码改为盈利盘支撑；均线改为下方 0~5% 条数；**R_vol 分量改为「放量止跌」**：近 5 日「跌幅 < 1% 且成交量 > MA(vol,20)·1.5」的天数 ÷ 5（价不跌但放量 = 下方有承接买单，下跌阻力大）。兜底 `R_down = 0.5`。

#### ③ R_smooth：走势流畅度（利弗莫尔质感）

越大表示路径越不流畅（阻力越大）：

$$R_{smooth} = \tfrac{1}{2}\left[(1 - HHLL\_score) + \min\left(\tfrac{fractal\_ratio}{3}, 1\right)\right]$$

- **HHLL_score**：近 20 K 线内连续「HH+HL」或「LH+LL」结构的占比（1=完美单边，0=全拉锯）
- **fractal_ratio**：`Σ|C[i]−C[i−1]| / |C[0]−C[19]|`，越大 = 来回锯齿越严重
- 兜底 `R_smooth = 0.5`

#### ④ R_flow：努力 vs 结果（Wyckoff 第三定律）

$$R_{flow} = \sigma\left(\tfrac{\bar V_5/\bar V_{20} - 1}{vol\_norm} - \tfrac{|C_t - C_{t-5}| / C_{t-5}}{ATR_{14}/C_t}\right)$$

σ = sigmoid 映射 [0, 1]；`vol_norm=0.4` 是成交量比率的历史分布 std 离线估计常量（MVP 固定，后续 Bayesian 校准）。努力 > 结果（放量没位移，两项为正差）→ 高；努力 < 结果（缩量创新高，两项为负差）→ 低。兜底 `R_flow = 0.5`。

#### ⑤ R_reflexivity：反身性共识分歧度（索罗斯）

隐性阻力 = 市场参与者预期是否一致。默认权重：`0.4·(1−corr) + 0.3·(1−liq) + 0.3·(1−sentiment_agreement)`。

严格对齐 9-基本面 **SentimentEngine 三层 FAIL-OPEN 机制**（项目硬约束要求）：

1. **L1 环境级**：`USE_FINBERT=0` → 整项跳过 sentiment，按比例归一化为 `0.55·(1−corr) + 0.45·(1−liq)`，`_meta.quality_score` 扣 0.15
2. **L2 会话级**：FinBERT 模型导入/加载失败 → 会话期持续降级为 L1 同等公式（不每次重试）
3. **L3 单条级**：单条推理异常 → 仅本条 `sentiment_agreement = 0.5`（最大分歧中性），质量扣 0.02 / 条

| 子项 | 定义 | 数据源 |
|:---|:---|:---|
| corr_symbol | 近 20 日对 BTC 滚动相关系数，相关高 = 大盘共识强 | 行情数据 |
| liquidity_index | bid/ask 深度 ÷ 24h 成交额；无深度 → `1 − bid_ask_spread_pct` | 18-OKX 客户端 |
| sentiment_agreement | FinBERT 近 50 条 `1 − std(情绪分)`；命中降级时按上表处理 | 9-基本面 signal_engine |

## 3. L2 策略基因编码 — Schema + 拆解规则 + ESS 得分

### 3.1 设计理念

genetic-stock（条件 × 动作 基因交叉） + Schluter G-Matrix（沿 gmax 增量探索） + Maynard Smith ESS（抗入侵权重）三条合并落地。

核心抽象：**任意策略 = 有序 [条件基因₁, 条件基因₂, …] AND/OR → 触发 [动作基因]**

MVP 做「拆解 + ESS 打分 + 索引 + CBR 加权预埋」，**基因交叉生成新策略留到下一期**。

### 3.3 ESS 得分公式（Maynard Smith 两条件）

$$ESS\_score = 0.4 H + 0.4 S + 0.2 \min\left(\sqrt{\tfrac{N}{500}},\ 1.0\right)$$

| 符号 | 含义 | 权重 |
|:---|:---|:---:|
| H historical_hitrate | 按基因组合入场，达到 TP 或到期的胜率 | 40% |
| S ess_stability_ratio | `E(S,S) / E(rand_T, S)`：S 对自身 vs 随机参数 T 对 S 的胜率比；≥1.0 是纳什均衡，≥1.15 优先检索 | 40% |
| √(N/500) 样本规模项 | N≥500 得满 1.0；样本不足自动降权（防过拟合） | 20% |

每 7 天重算一次，Bayesian 更新 → 写入 `4-MEMORY/2-交易记忆单元/bayesian_memories.json`，与现有蒸馏链对齐。

### 3.4 4 条基线拆解规则（MVP ≥ 40 条片段）

| # | 基线策略 | 最少条件 | 最少动作 | 重点拆解来源 |
|:-:|:---|:-:|:-:|:---|
| 1 | V9 马丁基线 | ≥ 8 | ≥ 4 | 2-KNOWLEDGE/1-TRADING/V9-马丁基线.md + 代码 NEUTRAL 场景路由 |
| 2 | V15 马丁 v15 | ≥ 10 | ≥ 5 | 14-V15/v15_signal.py · timing_gate · coin_selector · SLTP 模板 |
| 3 | 三屏趋势系统 | ≥ 8 | ≥ 3 | 12-三屏/core/fusion.py 三层融合 + risk_control.py |
| 4 | 易经推理系统 | ≥ 10 | ≥ 4 | 11-易经/engine.py · 五计庙算 75/60/50 档 + MA200/Fib 兜底 + 道/天 τ=24h 情绪衰减 |

**拆解铁律**：
1. 每个条件基因必须指向一个可独立开关的 if 分支，需填 `code_ref.file + lines`（审计可追溯）
2. 每个动作基因必须指向执行端可独立调用的 API（开/平/加减/WAIT）
3. `parameters` 必须是可调数值，才能做 Schluter gmax 轴的增量变异；纯枚举不参与 gmax
4. **跨策略复用的基因共享 id**（同一 MA200>Fib 只拆一次，多策略引用，ESS 样本叠加更准）

```

  ├─ strategy_gene_schema.py        ★ 消费端入口模块（读 library.json + index）
```

**CBR 加权预埋（MVP 不执行）**：后续 CBR 检索距离函数改为

### 3.6 质量门禁（quality.py 硬拦截）

- **schema_pass_rate ≥ 95%**（jsonschema；分母 = `len(conditions) + len(actions) + len(strategy_combinations)`，即所有基因+组合文件总数，允许最多 5% 标注为 BROKEN 并在日志中列明）
- 片段总数 ≥ 40（conditions + actions）
- ≥ 30% 策略组合回测样本 N ≥ 500，达不到的标记 `BETA`，下游检索加权时 × 0.5 折扣
- `code_ref.file` 覆盖 100%（每条 CONDITION / ACTION 基因必须填，组合可缺）
