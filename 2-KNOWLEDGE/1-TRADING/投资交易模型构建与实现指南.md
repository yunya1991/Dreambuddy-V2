# 投资交易模型构建与实现指南

> **版本：** v1.0
> **日期：** 2026-08-30
> **适用范围：** DreamBuddy v2 全系统（加密货币/美股/贵金属）
> **定位：** 从0到1构建工业化量化交易模型的完整落地手册，涵盖哲学→数据→战略→策略→风控→执行→验证全链路

---

## 核心结论（先看这个）

本系统的投资交易模型不是单一算法，而是一套**七层工业化流水线**：

```
L0 哲学方法论 → L1 数据基础设施 → L2 战略层 → L3 策略层
      → L4 风控层 → L5 执行层 → L6 离场与进化层
```

**构建顺序铁律：** 必须从L0→L6逐层构建，不可跳层。跳过数据层直接做策略 = 空中楼阁。

**三条不可动摇的工程原则：**

| 原则 | 含义 | 违反代价 |
|------|------|---------|
| **Shadow模式先于生产** | 任何新模块必须先跑7天Shadow审计，通过门槛才注入决策 | 无门槛直接上线 = 资金裸奔 |
| **FAIL-OPEN热路径** | 交易热路径（每轮开/平判断）异常时必须中性兜底，不阻塞 | 一个异常导致全天停摆 |
| **字节等价验证** | 新开关关闭时，系统输出必须与开关不存在时字节级等价 | 隐性回归 = 慢性失血 |

**验收标准（严格型）：** 任一指标不低于基线且**至少2项显著提升**（Sharpe+0.2 / 胜率+2% / 收益+5% / 回撤-3% / 利润因子+0.1），否则丢弃。

## 第零章 L0：哲学方法论 — 模型的根

> 没有正确的交易哲学，模型只是随机数生成器。

### 0.1 两大公理（第一性原理）

| 公理 | 内容 | 模型映射 |
|------|------|---------|
| **公理1：阻力最小路径** | 市场如流水，从阻力最小处通过 | 力向量系统（force_vector）、最小阻力引擎（A6 least_resistance） |
| **公理2：趋势延续性** | 趋势形成后延续至反向阻力出现 | EMA多空排列、MA200三日确认、波浪策略 |

**阻力分解公式：**
```
总阻力 = 成本摩擦(手续费/滑点) + 流动性摩擦(深度/价差)
       + 拥挤摩擦(资金费率/OI变化率) + 波动摩擦(ATR/波动率Regime)
```

### 0.2 矛盾论方法论（A0统一框架）

蒸馏《矛盾论》+《孙子兵法》+《战争论》，形成交易决策的统一操作系统：

| 原理 | 交易映射 | 代码对应 |
|------|---------|---------|
| 矛盾普遍性 | 利好利空永远共存，信号不足≠等待 | 力向量contradiction_transform_detector |
| 矛盾特殊性 | 顶部/底部同类事件结果不同 | RegimeConditionalCalibrator |
| 主要矛盾 | 只需主要矛盾方向明确即可行动 | IC/MI特征相关度Top8识别 |
| 矛盾主要方面 | 优势方即方向，量化力量对比 | 五维力向量方向+强度计算 |
| 矛盾转化 | 设定转化监控点，触发则调整 | ElasticityBetaCalculator + 6类转化检测 |

**A0三步法铁律：**
```
Step1 发现矛盾（A1）→ 至少2个矛盾对，禁止"无矛盾"
Step2 抓住矛盾（A2）→ 4维评分法识别1个主要矛盾，禁止"多主"
Step3 利用矛盾（A3）→ 必须输出UP/DOWN方向，禁止"等待"（用PROBE小仓试探替代WAIT）
```

### 0.3 8大矛盾维度

| 维度 | 多方信号 | 空方信号 | 战略层对应 |

| C1 资金面 | ETF净流入、OI增仓 | ETF净流出、OI减仓 | 地维度 |
| C2 情绪面 | FGI贪婪、费率正 | FGI恐惧、费率负 | 道维度（SentimentEngine） |

| C5 地缘 | 紧张=避险 | 缓和 | 天维度S4事件映射 |

### 3.2 力向量系统（Force Vector System）

> 9模块架构，计算市场最小阻力方向和强度。Shadow模式审计中。
> 核心代码：`11-易经推理系统/scripts/memory_l4/force_vector/`

**9模块全景：**

| 模块 | 职责 | 核心算法 | 输出 |
|------|------|---------|------|
| force_vector_calculator | 五维力向量 | Z-Score/分位数/MA/Sharpe/IC | 5组(direction, magnitude) |
| feature_correlation_calculator | 特征-价格关联度 | IC(Spearman) + MI(互信息) | Top8特征排序+权重 |
| pca_resonance_analyzer | 共振分析 | sign_alignment同向比例 | 共振强度+冲突检测 |
| cycle_comparator | 7d/30d周期比对 | MA7/MA30类均线 + 6态判定 | 金叉/死叉/背离信号 |
| elasticity_beta_calculator | 弹性系数β | β = ΔPrice% / ΔForce% | 弹性衰减/放大判定 |
| contradiction_transform_detector | 矛盾转化检测 | 6类转化条件监控 | 转化事件+置信度调整 |
| regime_conditional_calibrator | 状态条件校准 | E[r\|event,regime] vs E[r\|all] | 阶段依赖性修正 |
| strategic_mapper | 战略层映射 | 力向量→war_state/cap/mask | 决策修正建议 |
| adapters | 方向映射适配 | 符号/量纲统一 | 标准格式输出 |

**核心算法详解：**

#### ① 五维力向量计算

| 维度 | 算法 | 方向判定 |
|------|------|---------|
| 道 | Z-Score标准化 + OLS斜率 | Z>0且斜率>0 → 多 |
| 天 | P25/P75条件期望分带 | 当前值>P75 → 多 |
| 地 | 百分位排名 + MA5均线 | rank>50且MA5上升 → 多 |
| 将 | Sharpe比率 + 偏度 | Sharpe>0且偏度>-0.5 → 多 |
| 法 | 滚动IC + IR | IC>0且IR>0.5 → 多 |

Kalman平滑：F/H/Q/R矩阵按Spec配置，初始P=diag(1.0, 0.001)，跳变比<50%。

#### ② 主要矛盾识别（替代PCA的新方案）

PCA静态快照无法检测矛盾转化、阶段依赖性和价格响应衰减，改用**IC/MI特征-价格关联度**：

```python
# 滚动窗口计算
IC = Spearman(特征t, 价格t+1)     # 信息系数，线性关联
MI = MutualInfo(特征t, 价格t+1)   # 互信息，非线性关联

# 权重分配：|IC|^α归一化，α=1.5
weight_i = |IC_i|^α / Σ|IC_j|^α

# 双权重融合（与signal_engine后验权重）
final_weight_i = IC_weight_i × signal_engine._adaptive_weight(predictions≥5)
# 约束：Σ=1.0 且 each≤0.40（防止单个特征统治）
```

#### ③ 弹性系数β与矛盾转化

```
β = Cov(ΔPrice, ΔForce) / Var(ΔForce)
当Var(Force)≈0时，β取1.0（无弹性定义）
```

| 共振破裂 | sign_alignment < 0.25 | ×0.7 |
| CBR背离 | 案例预期与实际背离 | ×0.8 |
| 数据质量预警 | pass_rate<0.7持续3天 | ×0.7 |

## 第八章 构建与验证流程

> 从想法到生产的工业化流水线，TDD + Shadow + 回测三位一体。

### 8.1 TDD开发节奏

每个新模块必须按以下顺序开发：

```
Step1 写Spec文档 → 明确输入输出契约、算法公式、边界条件
Step2 写测试用例 → 覆盖：正常路径、边界值、异常处理、字节等价
Step3 测试全红 → 确认测试能正确捕捉"未实现"状态
Step4 写实现代码 → 逐模块编码
Step5 测试全绿 → 确认所有用例通过
Step6 回归测试 → 确认未破坏现有功能
```

### 8.2 验证门槛矩阵

| 验证类型 | 通过标准 | 未通过处理 |
|---------|---------|-----------|
| 单元测试 | 100%覆盖核心路径 | 修复后重测 |
| 字节等价 | 开关关断时，输出与开关不存在时一致 | 修改实现，不得影响原链路 |
| FAIL-OPEN | 异常注入时返回中性兜底，不阻塞交易 | 修复异常处理逻辑 |
| Shadow 7天 | 健康率≥95%，与原系统差异<15% | 延长观察期或修改算法 |
| 严格型特征验收 | 任一≥基线 且 至少2项显著提升 | 丢弃该特征，不可上线 |
| WalkForward | 滚动窗口外表现≥样本内80% | 过拟合，重新调参 |

**显著提升定义（满足任一即可）：**
- Sharpe比率 +0.2
- 胜率 +2%
- 总收益 +5%
- 最大回撤 -3%
- 利润因子 +0.1

### 8.3 回测方法论（WalkForward + 贝叶斯优化）

**禁止：**
- 全样本训练+全样本测试（数据泄露）
- 单一参数集（过拟合单点）
- 无未来信息检查（look-ahead bias）

**必须：**
```
WalkForward滚动窗口：
  训练窗=180天，测试窗=30天，滚动步长=30天
  每窗口重新训练模型，确保完全样本外验证

贝叶斯参数优化：
  先验分布：基于前一窗口最优参数±20%
  采集函数：Expected Improvement
  样本数≥50，防止局部最优

SL/TP硬约束：
  所有回测参数必须通过价格空间下限+爆仓安全边际双重验证
```

### 8.4 生产上线检查清单

上线前必须逐项确认：

- [ ] 单元测试100%通过，覆盖率≥80%
- [ ] 字节等价验证通过（开关关闭=开关不存在）
- [ ] FAIL-OPEN异常注入测试通过

- [ ] 回滚方案就绪（一键关闭开关+恢复旧版本）
- [ ] PR+CR代码评审通过
- [ ] 文档更新完毕（Spec + 知识库 + CHANGELOG）
- [ ] 相关人员已review

## 第九章 常见坑与反模式

> 基于系统实践的血泪教训，避免重复踩坑。

### 反模式 1：跳过数据层直接做策略

**症状：** 用CSV或手工整理数据，跳过Silver清洗和质量门禁
**后果：** 异常值/缺失值/未来信息 → 回测很漂亮，实盘大亏
**正确做法：** 所有数据必须走Bronze→Silver→Gold奖章架构，quality.py是硬门禁

### 反模式 2：新模块直接上线无Shadow

**症状：** 觉得自己的算法很对，跳过7天Shadow观察期
**后果：** 边界case没覆盖，极端行情下异常，直接亏大钱
**正确做法：** 强制Shadow 7天，JSONL审计+健康率≥95%才注入

### 反模式 3：单指标优化无全局约束

**症状：** 只优化Sharpe，忽略最大回撤/胜率/收益平衡性
**后果：** 某项指标虚高，其他维度崩溃，实盘无法坚持
**正确做法：** 多目标优化 + 严格型验收（任一≥基线，至少2项显著）

### 反模式 4：无FAIL-OPEN机制

**症状：** 一个feature计算异常导致全系统停摆
**后果：** 错失机会或更糟，持仓无法监控管理
**正确做法：** 交易热路径try/except兜底→中性值+6层堆栈日志+飞书告警（5分钟≥3次触发）

### 反模式 5：马丁策略无止盈无限加仓

**症状：** 马丁加仓无时间限制，总仓位无限放大
**后果：** 大单边行情直接爆仓
**正确做法：** 回测马丁最优持有时间，超过该时间即使盈利也平仓；设置爆仓安全边际（SL在爆仓价+0.3%安全侧）

### 反模式 6：SL/TP过紧被随机扫损

**症状：** ATR极低时，SL=0.5ATR → 0.2%就止损
**后果：** 方向看对了，被随机波动扫损，频繁小亏
**正确做法：** SL/TP价格空间下限（常规SL≥1.5%，TP≥3.0%；轻仓SL≥2.0%，TP≥4.0%）

### 反模式 7：字节等价破坏

**症状：** 新开关关闭时，输出与开关不存在时不一致
**后果：** 隐性回归，不知道亏是因为新模块还是市场变化
**正确做法：** V2字节等价验证必须通过，开关关闭时所有决策字段按原规则输出

### 反模式 8：时间对齐使用未来信息

**症状：** 用线性插值/backward fill填充缺失值
**后果：** 回测有未来信息，实盘没有，收益暴跌
**正确做法：** Forward fill only，max_gap=4 bar，打印交集范围/条数/首尾时间戳三要素证据
