### 0.5.2 为什么是工程杠杆（不是概念分类）

没有层级约束时，搜索空间是笛卡尔积 10^(k+m+n) = 天量。有层级后：

```
4阶 只取 1 个原理（最小阻力）            → 剪枝 99.9%
   ↓（规定3阶必须输出"在阻力更小的方向开仓"）
3阶 五计庙算 4档 × 方案C8 1态             → 再剪枝 95%（war_state=BAN 时 2阶全沉默）
   ↓
2阶 只取 ESS 前 20% 组合 × 沿 gmax 扰动   → 再剪枝 80%
   ↓
1阶 只取 2阶实际用到的指标参数轴           → 90% 指标组合根本不生成
总计：相比无层级笛卡尔积 10^(k+m+n)，层级约束后实际搜索空间缩减为
      10^1 × (4×1) × (20%×gmax扰动) × (10%指标轴)
      = 10 × 4 × 0.2 × 0.1 = 0.8 → 相比 10^(k+m+n) 的缩减倍数依赖 k/m/n 实际值。
      若 k=5, m=10, n=20 → 原始空间 10^35，层级后 ~10^1 → 理论缩减 ~34 个数量级。
      但此为理论上限（假设各阶剪枝完全有效），实际缩减受限于剪枝条件命中率。
      **保守声明**：层级约束可显著缩减搜索空间（具体倍数依赖实际 k/m/n 值和剪枝命中率），Phase 2 V5 消融实验将定量验证实际缩减倍数。
```

> **物理术语严格性标注（2026-09-04 学术审查 P2 补入）**：上表物理类比分属三个严格性层次，不可混用：
> - **① 数学形式同构**（严格）：Bellman ↔ HJB（§1.5.1 已标注）、Feynman-Kac 路径积分公式（§1.5.5 Level 2，V(s)=-T·log(Σexp(-S/T)·π) 是 Feynman-Kac 定理的直接应用）
> - **② 变分结构共享**（较严格）：最小作用量 ↔ 最小阻力（都是求泛函极值，但不同问题域）、Riemann 度规 g_ij（正定对称，定义"代价"而非几何距离）
> - **③ 概念借用**（非严格）："牛顿万有引力"/"海森堡测不准原理"/"波粒二象性"仅为**术语借用**，无严格数学对应。Quantum 档的"测不准"指 MEME 币情绪波动不可精确预测（信息不足），非量子力学 Δx·Δp≥ℏ/2 的不确定性关系。读者应将其理解为"高波动+信息不足"，而非量子叠加态。
>
> **ESS 术语澄清**：本架构中 ESS（Evolutionary Stable Strategy，进化稳定策略）借用自 Maynard Smith 进化博弈论术语，但**非严格 ESS 定义**。Maynard Smith 的严格 ESS 要求：策略 S 对任意变异 T 满足 u(S,S)>u(T,S) 或 u(S,S)=u(T,S)∧u(S,T)>u(T,T)。我们的 ESS_score = 0.4·H + 0.4·S + 0.2·min(√(N/500),1) 是一个**启发式稳定性评分**（综合历史胜率 H + 纳什均衡指标 S + 样本充分性 N），用于策略基因排序和检索优先级。两者共享"稳定性"概念但数学定义不同。

### 1.5.0 Markov 假设与状态充分性讨论（2026-09-04 学术审查 P0 补入）

> **审稿背景**：Bellman 方程和 HJB 方程都依赖 Markov 性质（未来只依赖当前状态 s_t，不依赖历史 s_{t-1}, s_{t-2}, ...）。金融市场已被学术界广泛证明是非平稳的（non-stationary），存在潜在波动率（latent volatility）和状态切换（regime shift）。本节讨论 R 向量是否构成充分统计量，以及 Markov 假设的边界与缓解措施。

#### 1.5.0.1 R 向量的充分性分析

**严格 Markov 条件**：状态 s_t 是充分的，当且仅当 P(s_{t+1} | s_t, a_t, s_{t-1}, ...) = P(s_{t+1} | s_t, a_t)。

**我们的 s_t = (R_up, R_down, R_smooth, R_flow, R_reflexivity, u_t, symbol)** 的充分性评估：

| 维度 | 是否捕获历史信息 | Markov 充分性 | 缺失信息 |
| :-- | :-- | :-- | :-- |
| R_up / R_down | 筹码分布 + 爆仓密度 + MA/FIB 趋势 → **隐式编码了近期价格路径** | 部分充分 | 远期历史筹码迁移（>7d） |
| R_smooth | R²(linear_fit) → **编码了近期路径锯齿度** | 充分（滑动窗口已覆盖） | — |
| R_flow | Wyckoff effort/result → **编码了近期量价关系** | 充分（5:3:2 加权覆盖） | — |
| R_reflexivity | 价格-情绪 corr + spread + sentiment → **情绪有滞后性** | **部分充分** | 情绪的动量效应（情绪峰值后 1-3h 才反映到价格） |

**结论**：5 维 R 向量在 1h-4h 时间尺度上**近似充分**（捕获了 80%+ 的状态信息），但在以下边界条件下 Markov 假设被破坏：

1. **极端行情**：闪崩/暴涨后 1-2h 内，市场存在"创伤记忆"（流动性恢复滞后），R 向量无法编码 → 需 ScaleClassifier 的"流动性挤兑熔断 FAIL-CLOSED"作为补充。
2. **叙事驱动的 MEME 行情**：叙事传播有时间滞后（Twitter 热度 → 价格），R 向量只看当前量价，不编码叙事传播阶段 → 需 §1.9 三修饰子中的 R_narrative 作为外部补充。
3. **跨日周期效应**：亚洲/欧洲/美洲交易时段切换产生结构性断点，R 向量不编码时段 → 需 ScaleClassifier 或时间特征作为补充。

#### 1.5.0.2 KMeans 聚类作为非 Markov 信息的隐式编码

**关键洞察**：虽然 R 向量本身是当前快照（Markov），但 §1.6.2 的 KMeans 7 维签名 s1-s7 隐式编码了部分历史信息：

- s1 = sign(R_down - R_up) × min(...) → 方向 + 置信度（编码了当前方向选择）
- s2 = fractal_ratio → **路径锯齿度**（编码了近期价格路径形态，不是单一快照）
- s4 = R_soros_stage → **Soros 阶段**（隐藏/加速/高潮/崩溃 = 编码了趋势生命周期位置，需要历史判断）

因此，**KMeans 签名是 R 向量的"历史增强"**——通过结构签名将部分历史路径信息压缩到当前状态中，使得 s_t' = (R_vector, cluster_id) 比 s_t = R_vector 更接近 Markov 充分性。

#### 1.5.0.3 Markov 假设破坏时的缓解措施

| 破坏场景 | 缓解措施 | 实现位置 |
| :-- | :-- | :-- |
| 情绪滞后 | R_sentiment 修饰子（§1.9）的非线性设计：极端值逆向 → 用情绪极值预测反转 | §1.9.4 |
| 闪崩创伤 | ScaleClassifier "流动性挤兑熔断 FAIL-CLOSED" → 168h 锁仓 | §0.6.3 |
| 叙事滞后 | RippleEngine 四阶段涟漪 → 检测叙事传播阶段 | §0.7.2 |
| 跨日时段 | Phase 2+ 可选添加时段特征（不在 MVP 范围） | Phase 2+ |
| 潜在波动率 | KMeans 签名 s2（路径锯齿度）隐式捕获 → 签名变化率高 = 波动率切换 | §1.6.2 |

**总原则**：我们**不声称** R 向量严格满足 Markov 性质。我们声称 R 向量 + KMeans 签名 + ScaleClassifier 构成一个**近似充分的状态表示**，在 1h-4h 时间尺度和非极端行情下，近似误差可接受。极端行情下通过 FAIL-OPEN/FAIL-CLOSED 机制兜底。

### 1.5.1 根本锚点：Bellman ↔ 最小作用量 = 变分结构同构（深层数学联系，非诗意类比）

> **术语严格性标注（2026-09-04 学术审查 P0 修正）**：原版声明"数学等价（不是类比）"过强。Bellman 与 HJB 的关系是**特定条件下的极限收敛 + 变分结构同构**，不是普遍意义的数学等价。以下精确标注每个对应关系的严格性层次。

```
 经济学"最优路径=阻力最小"          ↔        物理学"最小作用量原理 δS=0"
    交易沿最小阻力演化                       粒子在流形上沿极值路径运动
    阻力 = L1 R 向量 加权                     阻力 = 黎曼度规张量 g_ij（各向异性缩放）
    索罗斯反身性（价格改阻力）                粒子能量改变时空弯曲（Einstein半经典近似）
    Bellman 方程 V(s) 反向更新         ↔     HJB 方程 = Bellman 的连续时间极限
```

**三个严格性层次（学术审查 P0 标注）**：

| 对应关系 | 严格性层次 | 精确描述 | 限制条件 |
| :-- | :-- | :-- | :-- |
| Bellman ↔ HJB | **① 数学形式同构** | Bellman 离散时间递归在 Δt→0 极限下收敛到 HJB 连续时间 PDE | 需要：连续时间近似 + Markov 假设（§1.5.0）+ 平稳转移核 |
| 最小阻力 ↔ 最小作用量 | **② 变分结构共享** | 两者都是求某泛函的极值（Bellman 求值函数极大，作用量求轨迹极小），共享变分形式的数学结构 | 但解决不同问题：RL 求值函数，物理求轨迹。不是"同一方程" |
| 反身性 ↔ 时空弯曲 | **③ 概念类比** | Soros"价格改变阻力"与 Einstein"质量弯曲时空"在概念上类似（场影响几何） | 但无严格数学对应：Soros 无 Ricci 张量/Riemann 张量等曲率不变量 |

**工程含义（修正版）**：L4 Bellman/V(s) 和物理最小作用量**共享变分结构**（都是求泛函极值），这使得"按最小阻力推算"在数学上**有根据**（不是诗意类比），但不是"严格等价"（它们在不同问题域、不同假设条件下运作）。工程上可安全使用该结构作为设计指导，但不应声称数学等价性。

未来 N 根 K 线最优仓位序列 {u\_t\*} = argmin 总作用量 S\[u]：

```
L(q,u,t) = α_kin · |u_t − u_{t-1}|^2                              动能（剧烈调仓扣分）
        + α_pot · u_t · (d^T g d)                                   势能（沿阻力持仓持续扣分）

        + α_reg · (1 − ESS_t)                                      进化不稳定扣分
α_kin:α_pot:α_fric:α_reg = 1 : 3 : 2 : 1（MVP固定，Bayesian校准）
S[u] = Σ_t L(q_t, u_t, t)；u* = Ritz-Galerkin Chebyshev K=3 基展开 → numpy.linalg.solve
```

**输出**：u\_t\* 序列、SL/TP 测地带（非固定百分比）、confidence = 1 − S\*/S\_random\_mean（≥1.5=显著）。这就是"模拟推演比较"的精确实现：对比1000条随机路径S值分布，u\_t\* 需在前5%分位否则退回WAIT。

#### 1.7.7.3 收敛性证明

**定理**：紧耦合回路增益 G_open_max = 0.0197 < 1，因此回路**绝对稳定**（不发散振荡）。

**证明**：
1. G₁ = 1.08（双起点 RI→三层仓位增益，probe 档为主，加权平均）
2. G₂ = 0.55（仓位→TP 概率 ≈ 随机，因为小仓不影响市场方向）

四个环节增益的乘积 = 0.0030，远小于 1。

**即使最坏情况**（所有环节同时取最大值且同向）：
- G₁ 取 trend 档上限 = 1.43
- G₂ = 0.55（不变）
- G₃ 五倍（CS≤-0.2 & SL → -0.05 而非 +0.02）= 0.10
- G₄ = 0.25

G_open_worst = 1.43 × 0.55 × 0.10 × 0.25 = 0.0197 < 1 ✅

#### 1.7.7.4 振荡阻尼分析

回路的**延迟环节**（τ_delay = 6h 批周期）提供额外阻尼：

- ESS 更新每 6h 批量执行（不是每笔交易立即更新）
- RippleEngine 每 K 线（1h）读 ESS 快照，但 ESS 6h 才变一次
- → 回路有效周期 = 6h + 1h = 7h
- 在 7h 周期内，市场状态已变化 → G₄（ESS→RI 回馈）的实际相关性更低

**时间延迟阻尼比** ζ = τ_delay / τ_market = 6h / 24h（市场周期）= 0.25 > 0（有阻尼）

#### 1.7.7.5 稳定性保证设计约束

1. **ESS 更新幅度硬上限 ±0.02/−0.05**：这是回路增益 <1 的核心保证。如果 ESS 更新幅度增大到 ±0.2，G₃ = 0.2，G_open = 0.36 × 0.55 × 0.2 × 0.25 = 0.0099 仍 < 1（安全），但接近 0.01 量级 → 必须维持 ±0.02 上限。
2. **6h 批周期是稳定性下限**：缩短到 1h 批 → τ_delay 降低 → 阻尼比 ζ 降低 → 可能振荡。6h 是回路稳定性的硬下限。
3. **三层仓位分级是稳定性保证**：probe 档 ×0.4 → G₂ ≈ 0.55（接近随机）。如果 trend 档 ×1.0（趋势加仓）→ G₂ = 1.0（确定性更高），G_open 增大 1.8 倍。虽然仍 <1，但安全裕度降低。**trend 档仅在 ri≥0.70 强趋势确认时启用**，pro/standard 档仍保持小仓探测的稳定性。
4. **反例库保护是二次稳定**：CS≤-0.2 & TP → ESS 不更新（反例库保护）。这切断了"运气赚的→ESS+0.02→更激进→更多运气→..."的正反馈路径，是额外的稳定性保证。

#### 1.9.4 修饰子公式设计

```python
# 三修饰子 ∈ [0, 1]，各有独立 FO-1 try/except，crash → 0.0（不增强，等价 baseline 5 维）

# === R_capital → 修饰 R_up / R_down（方向阻力增强）===
# 资金流入方向 = 多头方向 → 降低上涨阻力
# 资金流出方向 = 空头方向 → 降低下跌阻力
capital_dir = R_capital * sign(net_inflow)  # [-1, +1]
R_up_mod   = R_up   * (1 - γ * max(0,  capital_dir))  # 资金流入→降低上涨阻力
R_down_mod = R_down * (1 - γ * max(0, -capital_dir))  # 资金流出→降低下跌阻力

# === R_narrative → 修饰 R_flow（动力源增强，需资金验证）===
# 叙事 = 额外动力源，但需资金验证（三角验证①）
capital_validation = 1.0 if R_capital > 0.5 else 0.3  # 资金不足→叙事打折
R_flow_mod = R_flow * (1 + α * R_narrative * capital_validation)

# === R_sentiment → 修饰 R_reflexivity（非线性：80/20 逆向）===
if R_sentiment > 0.8:    # 极度贪婪 → 逆向减分（巴菲特：别人贪婪我恐慌）
    sent_mod = -β * (R_sentiment - 0.8) / 0.2   # 越贪婪减越多
elif R_sentiment < 0.2:  # 极度恐慌 → 逆向加分（巴菲特：别人恐慌我贪婪）
    sent_mod = +β * (0.2 - R_sentiment) / 0.2   # 越恐慌加越多
else:                     # 正常区间 [0.2, 0.8] → 顺向增强（趋势确认）
    sent_mod = +β * (R_sentiment - 0.5)         # 偏离中性→增强反身性
R_refl_mod = R_reflexivity * (1 + sent_mod)

# 权重上限冻结
# α, β, γ ∈ [0, 0.2]  # 修饰子权重硬上限 20%，防止喧宾夺主
```

**R_sentiment 非线性设计核心**：80% 时间（[0.2, 0.8] 区间）情绪是趋势确认信号——顺向增强 R_reflexivity。20% 时间（极端值 >0.8 或 <0.2）情绪是反转信号——逆向修正。这就是巴菲特法则的数学形式化。

1. **修饰子不进入 g_diag 对角阵**：三修饰子是 R_up/R_down/R_flow/R_reflexivity 的外部增强项，不是独立对角维度。g_diag 永久保持 5×5。

### 1.10 自动标注与噪音处理（2026-09-04 用户深化 · 核心创新点）

> **用户洞察**：交易盈亏通过两条正交认知轴实现自动标注 → 模型朝对的方向进化。但噪音处理需要好好考虑。
>
> **核心创新**：传统 ML 需要人工标注数据（label），我们的系统通过**交易盈亏 + 两条认知轴**实现**自动标注**——无需人工标注，每笔交易自动产生带标签的训练样本。

#### 1.10.1 自动标注机制

```
  交易 close (TP/SL) → 自动产生 1 条标注样本
  │
  ├── 标签 = f(盈亏, CS, 两条链路对齐度)
  │
  │  ① 盈亏标签 (ground truth):
  │     TP → positive (1)
  │     SL → negative (0)
  │
  │  ② CS 一致性标签 (认知质量):
  │     CS ≥ 0.7 → "判断对了" (high-quality positive)
  │     CS ≤ -0.2 → "判断错了" (high-quality negative)
  │     -0.2 < CS < 0.7 → "不确定" (low-confidence, 降权使用)
  │
  │  ③ 两条链路对齐标签 (来源追溯):
  │     RippleEngine.RI ≥ 0.55 AND ReflectionEngine.CS ≥ 0.7 → "外察+内省双确认" (gold standard)
  │     RippleEngine.RI ≥ 0.55 AND ReflectionEngine.CS ≤ -0.2 → "外察推断被证伪" (反例样本)
  │     RippleEngine.RI < 0.55 AND ReflectionEngine.CS ≥ 0.7 → "非涟漪驱动的正确交易" (正常样本)
  │     RippleEngine.RI < 0.55 AND ReflectionEngine.CS ≤ -0.2 → "非涟漪驱动的错误交易" (反例样本)
  │
  └── 样本写入 → L3 ShadowRL 训练集 + L4 Bellman V 更新
```

**关键**：标注质量取决于两条链路对齐度——双确认样本（RI≥0.55 ∩ CS≥0.7）权重最高（×1.5），单确认样本权重正常（×1.0），不确定样本降权（×0.3）。

#### 1.10.3 噪音处理硬约束

1. **单笔交易不更新 ESS**：ESS 更新必须 6h 批聚合（§1.7.6 已冻结）。单笔交易的 TP/SL 可能是噪音，6h 批内多笔交易的方向一致性才是有效信号。
2. **不确定样本降权而非丢弃**：CS 在 \[-0.2, 0.7] 区间的"不确定"样本不丢弃，而是 ×0.3 降权使用。丢弃会丢失边界案例的分布信息，降权更合理。
3. **反例库不奖励运气**：CS ≤ -0.2 & TP = "方向错碰运气赚的" → 写入反例库，**不奖励 ESS**（防 MEME 反模式）。这是噪音处理的核心——防止噪音驱动假进化。
4. **OOD 标签隔离**：极端行情样本标 "OOD" 标签，单独存放不混入常规训练集。混入会污染常规分布的学习。
5. **噪音处理优先级**：市场随机波动 > 叙事标签噪音 > 跨币关联误判 > 情绪滞后 > 小样本偏差 > 极端行情 > 反身性自激。前 3 个是 MVP-Phase2 主要风险，后 4 个是 Phase3+ 风险。

#### 1.10.4 信噪比（SNR）量化分析（2026-09-04 学术审查 P3 补入）

> **审稿意见**：§1.10 的噪音处理是定性矩阵，需要量化信噪比（SNR）和最低样本量。

**SNR 定义**：

```
SNR = P_signal / P_noise

其中：
  P_signal = P(双确认 ∩ 方向正确) × |CS_mean(双确认)|
  P_noise  = P(双确认 ∩ 方向错误) × |CS_mean(噪音)|

  双确认 = RI ≥ 0.55 ∩ CS ≥ 0.7（§1.10.1 自动标注双确认机制）
  方向正确 = TP（或 SL 但 CS≥0.7 方向对被扫损）
  方向错误 = SL 且 CS ≤ -0.2
```

**估计值**：

| 场景 | P_signal | P_noise | SNR | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| BTC/ETH（Classical） | 0.12 | 0.04 | **3.0** | 大币信噪比高，信号清晰 |
| 主流 Alt（Meso） | 0.10 | 0.06 | **1.7** | 中等，趋势 + 噪音混合 |
| MEME/新币（Quantum） | 0.05 | 0.15 | **0.33** | 信噪比 < 1，噪音主导 → 靠 FAIL-OPEN 兜底 |

**最低样本量推导**（中心极限定理）：

```
N_min = (z_{α/2} × σ / δ)²

其中：
  z_{α/2} = 1.96 (95% 置信)
  σ = ESS 更新标准差 ≈ 0.02 (±0.02 奖惩幅度)
  δ = 最小可检测效应 = 0.01 (ESS 变化 1pp)

N_min = (1.96 × 0.02 / 0.01)² = (3.92)² ≈ 15.4 → 16 笔交易
```

但 16 笔是**单簇单方向**最低样本量。考虑 10 簇 × 2 方向 = 20 个子分类：

```
N_total_min = 16 × 20 = 320 笔交易（覆盖所有簇×方向）
```

与 §1.11.2 的 CBR 样本门槛 ≥500 一致（500 留 36% 余量给噪声样本）。

**双确认对 SNR 的提升**：无双确认时 SNR_MEME ≈ 0.33（低于 1），双确认后 SNR ≈ 0.33 × 1.5（权重×1.5）≈ 0.50。仍低于 1 → MEME 币需更多样本（N ≥ 1000）才能可靠学习。

#### 1.11.2 SFT 先于 RL（第 2 条详述）

> **AI-Trading-Agent 发现**：先用监督微调(SFT)让模型模仿"金标"策略，再用 RL 微调，比直接 RL 训练快 10 倍且更稳定。他们的"微训练"实验显示 SFT 1 epoch 就足够启动 RL。

**我们的落地方案**：

```
Phase 2 (SFT 阶段):
  CBR 检索先验 → 选出 top1 策略 → 按策略 action 建仓
  每笔 close → pre_trade_snapshot 标注 → 积累样本

  约束：CBR 样本 ≥500 笔才解冻 RL
  约束：SFT 阶段 ESS 只允许 ±0.01 微调（RL 解冻后恢复 ±0.02）

Phase 3 (RL 解冻):
  L3 ShadowRL 使用 SFT 积累的样本做 RL 微调
  奖励函数 = 组件化三部分（见第 3 条）
  探索率 ε 由 Thompson sampling 自适应（样本稀疏区自动降低）
```

**工程约束**：
1. **CBR 样本门槛 ≥500**：Phase 3 解冻 RL 的前置条件。样本不足时 RL 会过拟合噪音。
2. **SFT 阶段 ESS 微调幅度 ±0.01**：小于 RL 阶段的 ±0.02，防止 SFT 阶段过度调整。
3. **SFT 样本质量 > 数量**：优先使用双确认样本（RI≥0.55 ∩ CS≥0.7，§1.10.1）做 SFT，单确认样本做 RL 探索。

#### 1.11.3 组件化奖励函数（第 3 条详述）

> **AI-Trading-Agent 发现**：奖励函数 R = R_trend + R_risk + R_pnl 比单一 PnL 奖励更稳定——分项奖励让模型理解"方向对但被扫损"vs"方向错碰运气"的区别。

**我们的落地方案**：

```python
# Phase 3 L3 ShadowRL 奖励函数设计约束
R_total = w_trend * R_trend + w_risk * R_risk + w_pnl * R_pnl

# R_trend = 方向正确性奖励（CS ≥ 0.7 → +1，CS ≤ -0.2 → -1，否则 0）
# R_risk  = 风控合规奖励（止损触发在预设区间内 → +0.5，超范围 → -0.5）
# R_pnl   = 盈亏奖励（TP → +1，SL → -1，按盈亏比例缩放）

# 权重约束
w_trend = 0.4  # 方向正确最重要（与 CS 权重一致）
w_risk  = 0.3  # 风控合规其次
w_pnl   = 0.3  # 盈亏最次（防 MEME 反模式：运气赚的不应高奖）
```

**工程约束**：
1. **R_pnl 权重 ≤ 0.3**：盈亏权重硬上限 = 0.3。盈亏是最强信号但也最多噪音（市场随机波动）。权重过高会导致模型追逐噪音。
2. **R_trend 权重 ≥ 0.4**：方向正确性权重硬下限 = 0.4。与 CS 一致性得分权重对齐。
3. **三组件必须可独立观测**：奖励函数日志必须分别输出 R_trend、R_risk、R_pnl 三值，不可只输出 R_total。用于调试和异常检测。
4. **R_risk 不可为负总和**：单笔交易 R_risk 可以是 -0.5（超范围止损），但 6h 批聚合后 R_risk 总和不可 < -1.0（否则触发风控熔断）。

#### 1.11.4 HJB 连续时间 Bellman（第 6 条详述）

> **学术论文发现**：Merton 的连续时间投资组合优化基于 HJB（Hamilton-Jacobi-Bellman）方程，是离散时间 Bellman 方程的连续极限。在高频交易场景下，离散时间近似（TD(0)）会丢失毫秒级信息。

**我们的评估结论**：

| 维度 | 离散 TD(0)（当前） | 连续 HJB（Phase 3+ 候选） |
| :-- | :-- | :-- |
| 时间分辨率 | K 线/交易 close 级 | 连续时间 |
| 状态转移 | s_t → s_{t+1} 离散 | ∂V/∂t + H(V, ∇V, ∇²V) = 0 |
| 计算复杂度 | O(n_states) | 需求解 PDE，O(n_states²) |
| 适用场景 | 1h/4h K 线交易（当前） | 高频/秒级交易（未来可选） |
| MVP/Phase2 | ✅ 足够 | ❌ 过度工程 |

**工程约束**：
1. **Phase 2 保持 TD(0)**：K 线级交易的时间分辨率与 TD(0) 离散近似匹配，HJB 连续时间是过度工程。
2. **Phase 3+ 评估触发条件**：仅当交易频率升级到分钟级或秒级时才评估 HJB。触发条件 = 日均交易笔数 ≥100（当前远未达到）。
3. **HJB 不替换 TD(0)**：即使 Phase 3+ 引入 HJB，也是 TD(0) 的补充而非替换——TD(0) 处理离散事件（交易 close），HJB 处理连续状态演化。
4. **算力约束**：HJB 求解 PDE 的算力需求是 TD(0) 的 O(n²) 倍。引入前必须评估算力预算。

#### 1.11.5 在线学习落地路径（第 5 条详述）

> **PopAgent 发现**：每根 K 线更新（every bar update）优于每日批量更新——市场状态变化快速，延迟更新导致策略滞后。

**Phase 2 升级路径**：

```
Phase 2 在线学习升级三步：

  Step 1: K 线事件触发（替换每日 cron）
    scheduler: schedule.every().day.at("00:05") → schedule.every(1).hours
    RippleEngine.detect() 每 K 线收盘自动触发
    L1 ResistanceVector.calculate() 同步更新

  Step 2: 交易 close 事件触发（已有 A8 hook，接入即可）
    ReflectionEngine.trigger() 挂到 A8 交易结算 hook
    L3 ShadowRLTracker.record() 同步写入
    L4 BellmanVTracker.td_update() 同步更新

  Step 3: 6h 批聚合（ESS 更新）
    schedule.every(6).hours.do(reflection_batch_update)
    ESS ±0.02/−0.05 批量应用
    gmax 变异批量执行
```

**工程约束**：
1. **K 线触发不可阻塞主交易链**：RippleEngine 和 L1 的 K 线级更新必须在独立线程/协程中执行，不阻塞 polling_trader 主循环。
2. **6h 批是 ESS 写入的下限**：K 线级只读 ESS（不写），6h 批才写 ESS。防止高频写入导致 ESS 振荡。
3. **Phase 2 上线前需 1 周 shadow 压测**：K 线级更新的性能影响必须先在 shadow 环境验证 7 天无资源竞争。

```
    → 对比下一根 K 线实际方向（涨幅>0.3%=多，跌幅>0.3%=空，否则 WAIT）
  验收标准：
    准确率 = 预测方向正确次数 / 总预测次数 ≥ 62%
    WAIT 不计入准确率分母（只计多空预测）
  消极基线：随机猜多/空 → 50%
  验收门槛：≥62% (比随机高 12pp)
```

### B.2 叠加规则三铁律（0 歧义，编码无争议）

1. **加法-乘法互不干扰律**：维度分加法 boost（天+5 / 道+3，在 0-100 分上操作）和 仓位比例乘法（总仓×1.25，在最终 0-100% 上限上操作）**操作对象完全不同**，从不叠加在同一数值上 → 不存在「先加后乘 vs 先乘后加」的歧义。
2. **会话临时不碰持久律**：Ripple CBR±25% / ESS×1.05 全部带 `session_scoped` 标记存进程内存，不写 SQLite。进程重启 = 自动丢弃。RE 公理1/2 的 ESS±0.02 / gmax×0.5 是**持久化写入**，走 P3/P4。两类**永不交合** → 不存在「临时ESS被错误持久化」的脏数据。
3. **门禁 AND 合取最保守律**：多门禁同时存在时，最终 `allow_open_position = (war_state ≠ BAN) AND ALL(方案C8开关=ON) AND (GLOBAL_MACRO_GATE=OFF OR (war_state≥75 AND |R_up-R_down|≥0.6))`。AND = 一门禁关 = 全关，保证最保守。AND 的短路求值顺序 = 从左到右按「计算便宜 → 计算贵」排列：BAN 判定 O(1) 最先，CMScore\<R 方向差 计算稍贵 放最后。短路优先省算力。
