# SPEC v1.2 — L2 层 SACG 编排架构优化（机械层抽象后的编排重构）

> 版本: v1.2.1 | 日期: 2026-10-16 | 状态: 评审修订完成（冲突消除，可作实施依据）
> 修订记录: v1.2 (差异分析与优化方向) → v1.2.1 (评审修订: 补入 C-drive 驱动位置/补入 DSH 子 agent/澄清 S 层先验关系/区分反思与验收粒度/统一外部调研归属)
> 前置: SPEC v1.1（L0/L1/L2 三层能力架构，定稿基线）
> 定位: L2 层内部编排（SACG 四层）的优化规范

## 1. 重构背景

机械层（数据存取、确定性金融能力）已抽象为 L0/L1 独立层后，SACG 的编排职责边界发生根本变化：
- **之前**: SACG 需要编排所有用户请求（含数据查询、指标计算等确定性需求），编排缺乏合理逻辑和规划，S 层意图识别与 L1 意图路由存在职责重叠；
- **现在**: L1 已拦截全部确定性请求（十意图零 token 秒回），SACG 只编排真正需要大模型推理的 L2 请求——编排逻辑从实践中总结重构。

## 2. 现有架构与新逻辑的差异分析

### 2.1 S 层（差异最大）

| 维度 | 现有实现 | 新逻辑 |
|---|---|---|
| 意图识别 | IntentEngine.recognize 纯本地分类（输出 intent_type/recommended_chain） | 接入广义认知系统（五类四层）做意图识别——recall 经验先验 + L4 元认知门控。**先验关系**: 以 L1 交接的 l1_intent_hint 为先验输入做深化识别（结合认知经验细分意图与场景），不重复 L1 已完成的粗分类 |
| 架构识别 | 无 | 逆向解析工程做工程架构识别（本地系统 + 外部调研项目的架构模式） |
| 知识拓展 | 无系统性外部调研 | 外部调研做能力拓展——**归属**: S 层识别调研需求并触发，C-drive 执行调研（能力在 C-drive，触发在 S 层，对齐 v1.1 §4.1-3） |
| 产出 | IntentResult（意图分类结果） | 通过开工 Skill（skill 管理系统）形成 Spec 和 Plan |

**核心变化**: S 层从『意图分类器』升级为『认知驱动的规划入口』——识别意图 → 调研架构 → 生成 Spec/Plan，产出物从分类标签变为可执行的规划文档。

### 2.2 A 层

| 维度 | 现有实现 | 新逻辑 |
|---|---|---|
| 职责 | GraphPlanner 动态组合 tool 集合（preset composer） | 依据 Spec 和 Plan 做整体与局部 OKR 节点验收体系 |
| 验收逻辑 | 无显式验收节点 | 每个 OKR 节点有明确验收标准（对齐 Spec/Plan 的目标分解） |

**核心变化**: A 层从『工具组合器』升级为『验收体系』——编排的每个节点不再是工具调用，而是带验收标准的 OKR 节点。

### 2.3 C 层（差异最小）

现有 GraphExecutor + Reflector 的执行驱动职责与新逻辑一致（执行驱动层），保持现有实现；增强点：执行结果回传 A 层做 OKR 节点验收。

**执行链路构成（对齐 v1.1 §4）**: C 层执行由 GraphExecutor 与 DSH 子 agent 协同承担——DSH 多子 agent 是主执行链路（isolated 默认/fork 继承），GraphExecutor 承担图节点级执行，Reflector 做执行内反思；子 Agent 协作贯穿执行过程。

**反思与验收的粒度区分**: Reflector 负责执行内反思（过程决策——单步执行的对错与调整，毫秒级），A 层 OKR 验收负责结果验收（目标达成——节点是否满足 Spec/Plan 的验收标准，节点级）——两者粒度不同、不重复检验。

### 2.4 G 层

| 维度 | 现有实现 | 新逻辑 |
|---|---|---|
| 存储 | GraphStore 消费 append-only 事件流，交易领域压缩投影 | 保持图架构压缩层和存储层职责 |
| 沉淀 | 无收尾联动 | 与收尾 Skill 联动做好认知沉淀（对齐 SPEC v1.1 沉淀分流语义） |

**核心变化**: G 层增加收尾 Skill 联动——执行图的压缩存储与认知沉淀（案例/认知/流程/文档四分流）衔接。

## 3. 优化后的 SACG 编排逻辑

```
L1 未命中请求（携带 l1_intent_hint 上下文，交接协议已落地）
  ↓
【C-drive】认知驱动路由 —— L2 全程调度者（对齐 v1.1 §4.1-3）
  贯穿 S→A→C→G 四层: 编排各层流转、调度子 Agent 协作、必要时执行外部调研
  ↓
【S 层】认知驱动规划入口（由 C-drive 驱动）
  ① 广义认知系统意图识别（以 l1_intent_hint 为先验深化识别，recall 经验先验 + L4 元认知门控）
  ② 逆向工程架构识别（本地系统依赖图/调用链 + 外部调研项目架构模式）
  ③ 必要时触发外部调研（C-drive 执行）
  ④ 开工 Skill（skill 管理系统）→ 形成 Spec 和 Plan
  ↓
【A 层】OKR 节点验收体系（由 C-drive 依据 Spec/Plan 编排）
  ⑤ 依据 Spec/Plan 分解整体与局部 OKR 节点
  ⑥ 每个 OKR 节点定义验收标准
  ↓
【C 层】执行驱动层（由 C-drive 调度）
  ⑦ DSH 子 agent + GraphExecutor 按 Plan 执行，Reflector 执行内反思（过程决策）
  ⑧ 执行结果回传 A 层做 OKR 节点验收（结果验收，与 Reflector 反思粒度不同不重复）
  ↓
【G 层】图压缩存储 + 认知沉淀
  ⑨ 执行图压缩投影存储（GraphStore）
  ⑩ 收尾 Skill 联动认知沉淀（四分流: 案例/认知/流程/文档）
```

## 4. 与 L0/L1/L2 三层架构的衔接

1. **入口衔接**: L1 路由器 handled=false 时，请求携带 l1_intent_hint 进入 S 层（交接协议已落地验证）；
2. **L0 供给**: S 层意图识别调用认知系统（L0 经验先验链路）、架构识别调用 REA（L0 逆向工程支柱）——均为 L0 fetchContext 的调用方；
3. **沉淀回流**: G 层收尾 Skill 的认知沉淀走 SPEC v1.1 沉淀分流语义（案例入案例库、有价值发现入认知系统、流程入 skill、文档入文档管理）；
4. **Skill 体系联动**: 开工 Skill（S 层产出 Spec/Plan）与收尾 Skill（G 层认知沉淀）首尾呼应，均位于 skill 管理系统（247 SKILL，active=207）。

## 5. 实施优先级（建议）

1. **P1 — S 层认知接入**: IntentEngine 接入广义认知系统 recall（经验先验）+ MCP 接口（已验证可用）——最小改动最大收益；
2. **P2 — 开工 Skill 标准化**: 定义开工 Skill 的 Spec/Plan 模板与触发条件（S 层产出规范）；
3. **P3 — A 层 OKR 验收**: GraphPlanner 改造为 OKR 节点验收（依据 Spec/Plan 分解，每节点验收标准）；
4. **P4 — G 层收尾联动**: 收尾 Skill 与沉淀分流对接（认知沉淀链路已验证，需 Skill 化封装）；
5. **P5 — REA 架构识别接入**: S 层调用 REA 依赖图/调用链做架构识别（工具已验证可用）。

## 6. 边界与非目标

- 本 SPEC 为 L2 层内部编排优化规范，不改变 L0/L1 已落地能力；
- C 层执行驱动保持现有实现，仅增加结果回传；
- 外部调研为必要时触发（对齐 SPEC v1.1 §4.1-3 C-drive 约束），不做常驻调研。
