## 1. 分层原则

按『是否依赖大模型』划分能力层级：

| 层级 | 定位 | 驱动方式 | 成本 |
|---|---|---|---|
| **L0 基础能力层** | 数据与事实的存储、采集、结构化 + 经验沉淀 | 数据库/采集管线/规则/认知记录 | 零 token，独立双向层 |
| **L1 基础智能层** | 不依赖大模型的金融能力 | 算法/规则/统计/意图识别 | 零 token，秒级响应 |
| **L2 大模型驱动层** | 语义理解、推理、生成 | LLM（DreamOS C层+DSH+子Agent） | token 成本 |

**路由逻辑**: 前端用户需求先过 L1 → 命中执行意图则直接返回（零 token 秒回）→ 未命中再走 L2。L0 不直接对外路由，由 L1/L2 在工作前调用（fetchContext）、工作后沉淀（settle）——详见第 3 节与第 5 节接口契约。

**判据边界定义（2026-10-16 评审新增）**: 本架构的"依赖大模型"特指**依赖生成式 LLM 推理**（语义理解 / 复杂推理 / 内容生成）。
- **不含**: 本地小模型、向量检索（embedding / 相似度召回）、确定性算法（规则 / 统计 / 贝叶斯）。
- **推论**: L1 的语义嵌入升级（SPEC-v0.6 的 TF-IDF + embedding 混合）**仍属 L1**——只要不调用生成式 LLM 推理。
- **目的**: 消除 L1 边界漂移。判据收敛为一条：**"确定性 + 本地模型/向量检索" → L1；"生成式 LLM 推理" → L2**。

## 3. L0 基础能力层（独立的双向层）

**定位修正**: L0 不是被动共享层，而是独立封装的双向层——
- **工作前调用**: L1/L2 执行任务前从 L0 获取数据、经验知识、工程检验结论；
- **工作后沉淀**: L1/L2 执行完成后把结果、新经验、验证结论沉淀回 L0（数据入库、经验入认知库、工程结论入 REA 检验体系）；
- **无大模型渐进降级**: L0 不依赖大模型，没有 AI 时能调用多少就调用多少（FAIL-OPEN 渐进可用，不因部分能力缺失而阻塞）。

**L0 构成**:
- **数据库系统**: 18-数据获取中心（采集管线+data_center.db）、19-数据访问层（DAL，成熟后作为统一数据底座）、20-数据清洗中心、21-特征工程中心；
- **广义认知系统（成熟子系统）**: 由 **35-广义认知系统协作模块** 统筹（跨系统协作设计的 SSoT，纯文档层）+ **4-MEMORY/9-工具与接口** 实现（cognitive_loop_entry.py / evidence_ledger.py 等保留原位）。**现状确认（2026-10-16）**: 该子系统**已相当成熟**——认知 C1-C4 四层闭环（五系统接线 / 三层记忆+ACT-R / Intent-Engine+RAG / GWT+HOT+预测误差门控）、统一 PoE 双模式框架、Evidence Ledger 均已落地并经验收（35 模块 SPEC-CognitiveSystem-Evolution.md 已标记"开发完成 P0-P3 24/24，2026-10-12 验收通过"）。**本架构与它之间缺的不是能力，而是接口**（record_hook/verify_hook 的 MCP 接线、fetchContext 的认知 scope 暴露）。参见 35 模块 SPEC-CognitiveSystem-Evolution.md / SPEC-Unified-PoE-Framework.md / COLLABORATION-CONTRACT.md / SPEC-CDrive-CognitiveSystem-Integration.md；
- **逆向工程（核心组件）**: 工程级反思进化检验系统（33-REA），L0 中的关键职责——
  - **系统运行工作解析**: 对系统运行过程做工程级解析（依赖图/调用链/覆盖率），沉淀运行事实；
  - **工程上寻找优雅路径**: 通过架构模式识别与算法归纳，为工程演进提供最优路径参考；
  - **把握风控安全**: 工程级安全检验（审计标准/失效条件），为 L1/L2 的执行提供安全边界。

**关键结论（主体能力唯一化，2026-10-16 评审修订）**: 广义认知系统与逆向解析工程均为混合体，其分层规则修正为**"主体唯一、形态可降级"**：
- **归属唯一**: 每个组件按其**主体能力**（是否依赖生成式 LLM 推理）**唯一归层**；不存在"同一组件多归属"，也不因暴露形态改变归属。
- **降级形态 ≠ 归属**: 组件的**无大模型子集**（依赖图、调用链、证据账本、确定性调度）可**降级封装**为 L1 意图、或作为 L0 供给接口被 fetchContext 调用——这只是"**没有大模型情况下**的降级可用形态"，**不改变组件的层归属**。
- **具体落地**: 33-REA 主体归 L0（逆向工程支柱）——其工程分析能力（依赖图/调用链/架构模式查询）以**降级形态**封装为 L1 意图对外（见第 2 节暂缓清单第 8 项）；其 ai_audit 深度审计属生成式推理，以 **L2 形态**暴露。
- 一句话: **主体唯一 · 形态可降级**（同一组件的三种暴露形态不冲突，归属始终唯一）。

## 3.5 L0 广义认知系统与 L1 的联系机制

**坐标系澄清（2026-10-16 评审修订）**: 广义认知系统内部四层已**改名 C1-C4**，与本架构 L0/L1/L2 彻底隔离，避免同号混淆：

| 认知系统内部层（新名） | 原名 | 职责 | 本架构对接 |
|---|---|---|---|
| **C1 基础层** | L1 | 五系统闭环（认知 18K / SKILL 247 / 知识库 / 文档 / 33-REA） | 本架构 L0 经验知识库组件 |
| **C2 记忆层** | L2 | 三层记忆（working/recall/archival）+ ACT-R + Evidence Ledger | L1 工作前调用的主要接口 |
| **C3 路由层** | L3 | Intent-Engine 加权召回 + **匹配度评分** | L1 意图识别的语义召回增强 |
| **C4 元认知层** | L4 | GWT + HOT + **预测误差门控（FOK/JOL）** | L1 置信度门控的实现 |

> 命名说明: 采用 C1-C4（Cognitive Layer 1-4）以区别于交易矛盾维度的 C1-C8；若后续发现与矛盾维度语境冲突，可进一步改为 CT1-CT4。

**联系机制 = 三条链路 + 一个门控**:

1. **经验先验链路（工作前，L0→L1）**: L1 执行意图前从认知系统 recall 相关经验（数据源历史质量、历史结论先验），recall + 贝叶斯能力全无大模型依赖；
2. **沉淀链路（工作后，L1→L0，按类型分流）**:
   - **案例沉淀**: L1 每次成功执行的 query→answer→intent→data 对写入案例库（l1_case_store，轻量 jsonl）——供相同问法缓存命中、意图训练正样本、执行质量统计；这是统计学习回路（案例→定时训练→强化意图），不是认知反思；
   - **认知沉淀**: 探索发现的有价值经验知识才 record 回认知系统——数据源的坑、有价值的发现、纠错、异常模式等（价值判断优先，异常只是触发源之一；避免高频案例污染经验库）；
   - **流程沉淀**: 可复用的执行流程入 skill 系统；**文档沉淀**: 数据源/接口/知识变化入文档管理系统；
3. **训练数据链路（持续，L0→L1）**: 认知系统记忆（当前 2 万+ 条）作为 L1 意图训练数据源（Cognitive 采集器每轮稳定供给 30 条，已在工作）；
4. **置信度门控（路由质量，2026-10-16 语义澄清）**:
   - **置信度定义**: 指**「用户问题 ↔ 广义认知（记忆库）之间的匹配度 / 涉及度评分」**——即用户问题是否被认知库覆盖、覆盖程度如何。由认知系统 **C3 路由层**的匹配度评分 + **C4 元认知层**的预测误差门控（FOK/JOL）共同产出，**全程无需大模型**。
   - **决策规则**: **高置信度**（用户问题被认知库明确覆盖）→ 直接 **L1** 零 token 秒答；**置信度不高**（涉及但不明确 / 未被覆盖）→ 推给**路由器** → 转 **L2**。
   - **定位说明**: 这是"**没有大模型情况下的最优路由方法**"——用认知匹配度做确定性分流，把 token 成本严格限制在真正需要生成式推理的场景。
   - **职责边界**: 门控**产出于 L0（认知系统），判决归路由器**——L0 提供置信度**信号**，路由器据此**决策**；L0 不承担路由决策本身（避免职责错位）。
   - **对接细则**: 该信号如何由 C3/C4 产出、阈值与降级契约，见 `35-广义认知系统协作模块/SPEC-CDrive-CognitiveSystem-Integration.md` §7「对接细则」——复用其 §2.2.1 `evaluate_match`（匹配度）= C3、§2.4.1 `jev_gate`（预测误差门控）= C4 的同一套零 token 确定性机制，仅下游消费方不同（C-Drive 反思决策 → 前端层路由 L1/L2）。

**认知系统四层与本架构的对接关系**:
| 认知系统内部层（C1-C4） | 对接本架构 |
|---|---|
| C1 基础层（五系统） | 本架构 L0 经验知识库组件 |
| C2 记忆层（三层记忆+Evidence Ledger） | L1 工作前调用的主要接口（fetchContext 的认知 scope） |
| C3 路由层（Intent-Engine 加权召回 + 匹配度评分） | L1 意图识别的语义召回增强 + 路由置信度信号来源 |
| C4 元认知层（预测误差门控） | L1 置信度门控的实现（信号产出，判决归路由器） |

**L0 三大支柱定位**: 数据库系统（数据供给）+ 广义认知系统（经验供给 / 结果沉淀 / 置信度信号）+ 逆向工程（工程检验 / 优雅路径 / 风控安全）。

## 4. L2 大模型驱动层

- **核心**: DreamOS 架构 C 层（反思决策）+ DSH 架构（执行路径）+ 子 Agent 协作；
- **定位**: 语义理解、复杂推理、内容生成、跨域综合——L1 未命中的需求由此承接；
- **L1/L2 协同关系**: L1 同样为 L2 提供参考——L1 的确定性结论（数据/指标/估值/事件评分）作为 L2 推理的上下文输入，L2 更多是优化和扩展多场景（在 L1 事实基础上做深度优化、多场景泛化、复杂推理），而非从零开始；
- **历史背景**: DreamOS 架构早期主要为 AI 大模型设计（SACG 架构），其工作逻辑与 L1 的『意图识别→能力查询』模式不同，这正是需要分层封装的原因。

### 4.1 L2 工作约束（2026-10-16 确认）

1. **前置接入广义认知系统（必要条件）**: L2 工作前必须从认知系统 recall 相关经验（历史教训、数据源的坑、领域先验），工作中受 Evidence Ledger 证据可信度与 PoE 信任机制约束，工作后有价值的推理结论 record 回认知系统——没有认知系统约束的 L2 是裸大模型，有约束的 L2 才是『有记忆、有边界的推理层』；
2. **金融工程用逆向解析工程解析 L1**: REA 对 L1 的十个意图闭环做工程检验——依赖图（意图→数据源依赖，故障影响面定位）、调用链追踪（问法→意图预测→执行器→数据源全链路，误路由定位）、架构模式识别（意图闭环同构模式归纳为可复用工程资产）、覆盖率分析（特征词盲区发现）——这是 L0 逆向工程支柱对 L1 层工程检验职能的落地；
3. **C-drive 驱动 + 必要时外部调研**: 系统核心由 C-drive（认知驱动路由）驱动 L2 的 C 层反思、DSH 路径与子 Agent 协作；外部调研（联网搜索/外部知识）作为 C-drive 的扩展能力，仅在必要时触发，避免每问必外查的成本浪费。

### 4.2 需明确的边界

1. **认知系统接入状态（2026-10-16 评审更新）**: 广义认知系统（35 模块统筹 + 4-MEMORY 实现）**主体能力已成熟**——C1-C4 四层闭环、PoE 框架、Evidence Ledger 均已验收；record_hook/verify_hook 的 MCP 接线已验证可用（cognitive_mcp_server 的 record/verify 工具通过 JSON-RPC 2.0 实测：memory_id 返回、receipt_hash 生成、L4 门控字段就位）。**真正的缺项是"接口暴露"而非"能力缺失"**：待实施项为 L2 链路（SSE/C-drive）实际调用该 MCP 接口 + fetchContext 的认知 scope 暴露；
2. **REA 解析 L1 的触发方式**: 持续性职责——L1 每新增一个意图，REA 的依赖图与调用链同步更新，而非一次性审计；
3. **C-drive 与 L1 路由器交接协议**: L1 返回 handled=false 时，C-drive 接管的请求应携带 L1 的意图预测结果作为上下文（L1 已算出的意图信息对 L2 有参考价值），避免 L2 从零理解问法。

### 4.3 分层驱动闭环

L1 确定性能力（零 token）→ REA 工程检验（保证 L1 正确性）→ L2 认知驱动推理（C-drive 调度，认知系统约束）→ 结果沉淀回 L0——自洽的、以金融为核心的分层驱动体系。

## 5. 三层抽象层设计（架构方向）

**动机**: 每层工作逻辑不一样（L0 数据存取、L1 意图→能力查询、L2 LLM 推理），为了便于管理并让意图识别系统直接路由到不同层，应将三层封装为统一抽象层。

**统一接口契约（每层实现同一接口）**:
```
interface CapabilityLayer {
  canHandle(intent: string, message: string): boolean   // 层能力声明
  execute(intent: string, message: string): LayerResult // 统一执行
  // LayerResult: { handled, answer, data, confidence, cost }
}

// L0 双向接口（独立层，被 L1/L2 调用，不直接对外路由）
interface FoundationLayer {
  // 工作前调用: 取数据/经验/工程结论（无大模型，能调用多少调用多少）
  fetchContext(scope: string, params?: object): FoundationContext
  // 工作后沉淀: 结果/经验/验证结论回写 L0
  settle(result: LayerResult, context?: FoundationContext): void
}
```

**路由器（意图识别系统）**:
1. 意图预测（S 层模型 + 关键词兜底）→ 得到 intent；
2. 按层优先级询问: L1.canHandle → L2.canHandle（L0 不直接对外，被 L1/L2 内部调用）；
3. 命中层执行并返回；L1 未命中走 L2（token 成本仅在此时发生）；
4. 置信度门控（2026-10-16 语义澄清）: 路由器读取 L0（认知 C3/C4）产出的**「用户问题 ↔ 认知库」匹配度信号**，**高置信 → L1 直答；低置信 → 转 L2**，避免错误命中。

**实现状态**: 三层路由器重构已完成（2026-10-16）——L1 意图注册表（单一事实源）+ /api/data/query 路由器（意图预测→注册表兜底→canHandleL1 判断→handled 返回）+ UI 还原为纯消费者（只消费 handled 字段）+ 通用意图执行前置校验（置信度门控的注册表侧实现）。后续增强: 接入认知系统 C4 元认知门控信号（替换当前注册表侧的静态置信度）。
