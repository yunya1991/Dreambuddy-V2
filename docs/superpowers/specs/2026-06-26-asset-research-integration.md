## 一、方案评估

### 1.1 资产调研的定位

| 维度 | 说明 |
|------|------|
| **核心价值** | 宏观经济周期判定 + 大类资产配置建议 |
| **时间尺度** | 月度/季度级（战略层） |
| **频率要求** | 低频，每月1-2次足够 |
| **覆盖范围** | 股票/债券/商品/现金/加密 5大类22子类 |
| **与交易的关系** | 上游战略输入，非直接交易信号 |

### 1.2 为什么不需要高频

1. **经济周期变化慢**：美林时钟的周期切换通常以**季度/年**为单位
2. **宏观数据发布频率低**：GDP（季度）、CPI（月度）、PMI（月度）
3. **交易系统已有高频模块**：第一屏（周线）、第二屏（日线）、第三屏（实时）
4. **避免信号噪音**：高频反而会产生错误信号，降低策略稳定性

### 1.3 现有系统架构回顾

## 二、集成方案设计

```
┌──────────────────────────────────────────────────────────┐
│                    资产调研引擎                             │

│  • 大类资产配置                                             │
│  • 周期展望预测                                             │
└──────────────────────────┬───────────────────────────────┘
                           │
                           │ 每月1号 + 季度深度报告
                           │ 写入: asset_research_latest.json
                           ▼
┌──────────────────────────────────────────────────────────┐
│              第一屏：周线决策（战略层）                      │
│  (周更，6大维度)                                           │
│  • E: 宏观金融 ←── 读取资产调研结果，作为宏观维度输入        │

│  • M: 矿工经济                                             │

│  • C: 跨市场对比                                           │
└──────────────────────────┬───────────────────────────────┘
                           │
                           ▼
              第二屏 / 第三屏（不变）
```

### 2.2 执行频率设计

| 执行类型 | 频率 | 触发时机 | 输出 |
|---------|------|---------|------|
| **月度常规调研** | 每月1号 09:00 | 自动（Cron） | 简版报告 + JSON数据 |
| **季度深度报告** | 每季度首月5号 | 自动（Cron） | 完整HTML报告 + 三版本对比 |
| **事件驱动触发** | 按需 | 重大数据发布/黑天鹅事件 | 快速调研 + 风险告警 |
| **手动触发** | 随时 | 用户指令 | 完整报告 |

### 2.3 数据流转

```
资产调研引擎
    │
    ├──→ 输出文件: asset_research/latest.json
    │       (机器可读，供第一屏读取)
    │
    ├──→ 输出文件: asset_research/reports/YYYY-MM.html
    │       (人可读，完整报告)
    │
    ├──→ 写入知识库: macro_cycle_knowledge
    │       (周期变化记录，供进化系统学习)
    │
    └──→ 飞书告警 (周期切换时)
            (仅在周期发生变化时触发)
```

## 三、与各模块的集成点

### 3.1 与第一屏（screen1-macro-finance）的集成

**集成方式**：作为宏观金融维度的「上游输入」

```
【第一屏 宏观金融维度】原有流程:
  1. Fed政策周期分析
  2. 全球M2流动性分析
  3. DXY + 10Y收益率分析
  4. ETF资金流分析
  5. → 输出宏观方向研判

【增强后】增加第0步：
  0. 读取资产调研结果（上月/当前周期判定）
     ├─ 当前经济周期（复苏/过热/滞胀/衰退）
     ├─ 大类资产配置建议
     └─ 周期展望与风险提示
  1~5. 原有分析不变，但参考资产调研的周期结论
  6. → 输出增强版宏观方向研判（含美林时钟视角）
```

**价值**：
- 第一屏的宏观分析从「零散指标」升级为「有理论框架的系统判断」
- 美林时钟提供了**统一的分析框架**，避免指标间矛盾

### 3.2 与 Regime Detector 的集成

**定位**：互补而非替代

| 维度 | Regime Detector | 资产调研引擎 |
|------|----------------|-------------|
| **时间尺度** | 日级（每日3次） | 月/季度级 |
| **分析维度** | 技术面为主 + 浅度基本面 | 深度宏观经济周期 |
| **核心方法** | 形态匹配 + 指标计算 | 美林时钟 + 多因子 + 情景模拟 |
| **输出** | 市场状态 + 交易建议 | 经济周期 + 大类配置 |
| **触发** | 高频自动 | 低频 + 事件驱动 |

**集成方式**：
- Regime Detector 在检测到「极端状态」时，可触发资产调研的「快速验证」
- 资产调研的「周期结论」可作为 Regime Detector 的「长期背景色」

### 3.3 与进化系统的集成

**集成点**：
1. **周期变化作为进化触发条件**：经济周期切换时，自动触发策略重评估
2. **历史周期数据入库**：每次调研结果写入知识库，供进化系统学习
3. **策略-周期匹配度评估**：评估各策略在不同周期下的表现

### 3.4 与回测系统的集成

**集成点**：
1. **周期分段回测**：按经济周期分段，评估策略在各周期的表现
2. **配置效果回测**：验证美林时钟配置建议的历史有效性
3. **多版本对比回测**：V1/V2/V3 三版本历史表现对比

## 四、接入方式（低侵入式）

### 4.1 原则

1. **低侵入**：不修改现有系统核心逻辑，只增加输入
2. **可插拔**：资产调研出问题时，第一屏可降级为原有模式
3. **异步解耦**：资产调研独立运行，结果写入文件/数据库
4. **渐进式**：先从「参考输入」开始，验证价值后再深度集成

### 4.2 分阶段实施路线图

#### 阶段一：独立运行 + 手动参考（当前）
- ✅ 资产调研作为独立模块运行
- ✅ 生成HTML/JSON报告
- ✅ 用户手动查看，作为交易参考
- **目标**：验证周期判定和配置建议的准确性

#### 阶段二：第一屏集成（读取 + 参考）
- 资产调研结果写入标准JSON文件
- 第一屏 `screen1-macro-finance` 读取并展示
- 作为宏观维度的「参考输入」，不影响原有逻辑
- **目标**：验证对第一屏分析质量的提升

#### 阶段三：深度集成（策略联动）
- 周期切换时自动触发策略重评估
- 根据周期调整仓位上限和风险参数
- 不同周期下启用不同的策略组合
- **目标**：实现「顺周期」的动态策略调整

#### 阶段四：全链路打通（进化闭环）
- 周期数据进入进化系统
- 策略-周期匹配度自动评估
- 基于周期的策略进化与优化
- **目标**：形成宏观→策略→执行→进化的完整闭环

## 六、风险与注意事项

### 6.1 局限性

1. **美林时钟是美国经验**：在中国等市场有效性可能降低
2. **后验性**：经济数据发布有滞后，周期判定可能滞后1-3个月
3. **简化模型**：真实经济远比四象限复杂
4. **黑天鹅**：地缘政治、疫情等突发事件无法预测

### 6.2 降级方案

- 资产调研模块故障时，第一屏自动降级为原有分析模式
- Tavily API不可用时，使用上次结果+默认值
- 置信度低于50%时，明确标注「仅供参考」

### 6.3 验证指标

上线后需跟踪验证：
1. **周期判定准确率**：与事后确认的经济周期对比
2. **配置建议收益率**：模拟配置的历史表现
3. **第一屏质量提升**：集成前后的分析质量对比
4. **交易策略改善**：顺周期策略 vs 原策略的表现对比
