## 一、核心思想

孙子计篇的核心是**"先胜而后求战"**——先评估胜算再行动。这与量化交易"先评估再下单"的核心理念高度一致。

五维度框架不是替代现有三层架构，而是为其提供一个**战略级评估层**（庙算引擎），在现有战术级引擎（BCRM 2.0 / 弹簧力场 / 五角校验）之上增加一层"战前评估"。

现有系统的决策链是：**前置层(L/T 评分) → 核心层(ML 方向预测) → 五角校验(风险评分) → 离场管理**。这条链缺一个"要不要打、值不值得打"的战略前置判断——当前直接从 L/T 评分跳到 ML 方向预测，跳过了"大局观"评估。

孙子五维度恰好填补这个缺口。最终输出不是单一买卖信号，而是**按三类资产（加密代币 / 美股 ADR / 黄金白银）互相独立**的 6 类决策（某类不出战不阻止其他类交易，对应 §5.3「三类不出战互相独立」原则）：

- **是否允许交易**（按资产类独立判断：war_state ∈ {FREEZE, COOLDOWN} → 不允许；加密熊市不阻止美股开仓）
- **允许哪类策略**（按资产类独立白名单：加密「地+天双差」只允许应急策略，美股可全开放）
- **允许多大仓位**（按资产类独立四档映射：加密总分 78 → 80% 仓位 cap；美股总分 48 → 20% cap，互不影响）
- **是否必须止损**（按资产类强制闸门：法<40 纪律崩溃 → 仅该类立即强平，不波及其他类）
- **是否需要降仓**（按资产类强制乘数：道<40 → 该类所有持仓压到 ≤30%；其他类不降仓）
- **是否需要空仓等待**（与「是否允许交易」同属 war_state 载体，额外带 5 分滞回冷却防抖动）

**"胜负在交易之前就已经决定了，系统做的只是执行预先计算好的最优决策。"**

## 二、五维打分体系总览

每个维度独立输出 0~100 分，最后加权汇总成庙算总分。

| 维度 | 对应投资含义 | 建议权重 |
|---|---|---|
| 道 | 政策、流动性、机构资金、市场方向一致性 | 30% |
| 天 | 宏观周期、季节性、波动率周期、时间窗口 | 15% |
| 地 | 价格位置、趋势结构、支撑阻力、成交量 | 25% |
| 将 | 决策质量、数据支撑、仓位管理、交易纪律 | 15% |
| 法 | 策略库调用、执行规则、风控、复盘迭代 | 15% |

**综合公式**：

```
庙算总分 = 道×0.30 + 天×0.15 + 地×0.25 + 将×0.15 + 法×0.15
```

初始权重只是起点，后续应通过样本外回测、滚动窗口和因子贡献分析动态校准。

### 三档决策

| 庙算总分 | 决策含义 |
|---|---|
| ≥ 75 | 可正常调用进攻型策略，但需满足风控条件 |
| 60~74 | 只允许低仓位、防御型或中性策略 |
| < 60 | 以防守为主，不建议开新仓 |

### 按资产类别区分权重

三类资产的市场结构、波动特征、驱动因素差异显著，五维度权重应按资产类别分别配置：

| 维度 | 加密资产 | 美股 | 黄金白银 | 差异理由 |
|---|---|---|---|---|
| 道 | 30% | 25% | 35% | 黄金对全球流动性/央行政策最敏感；加密次之（机构+政策）；美股企业盈利驱动更强 |
| 地 | 25% | 30% | 20% | 美股个股技术结构最关键；黄金趋势型商品，技术结构简单 |
| 天 | 15% | 20% | 25% | 黄金季节性最强（避险季/议息季）；美股有财报季+年底效应；加密季节性相对弱 |
| 将 | 15% | 15% | 10% | 加密/美股波动大→纪律更重要；黄金波动相对低 |
| 法 | 15% | 10% | 10% | 加密策略多样化空间大；美股/黄金策略相对标准化 |

三类资产的"不出战"判断**互相独立**——加密不出战不阻止美股正常交易。组合层面增加**跨类相关性约束**：当三类资产同时低分时，系统进入全面防御模式；当两类同时低分时，第三类仓位上限自动 ×0.8（系统性风险传染）。

## 三、逐维打分详解

### 道 — 方向一致性评分（0~100）

**定义**：机构资金流向与政策方向的一致性，判断牛市/熊市生命周期。

**现有覆盖**：
- 4 年大周期锚点（MorphCyclePredictor 16 锚点）
- 美林时钟（BTC.D 代理通胀、库存周期代理增长）
- 跨资产特征(~33)
- 八卦坎☵水(成交量~10)

**指标池**：

| 子指标 | 量化方式 | 评分逻辑 |
|---|---|---|
| 央行货币政策方向 | M2 增速/利率方向/央行资产负债表变化 | 宽松→加分，紧缩→减分 |
| 机构资金净流入 | 稳定币市值变化/ETF 流入流出/CEX 储备变化 | 净流入→加分 |
| 政策景气度 | 监管信号方向（SEC/CFTC 动向） | 友好→加分，敌对→减分 |
| 变化率（一阶差分） | 上述指标的增速变化方向 | 拐点捕捉，由正转负→减分 |
| 大周期位置 | 4 年周期锚点的当前 t_rel 位置 | 底部区域→加分 |

**三层道架构**：
- **宏观道**：全球流动性周期（M2/利率方向/央行资产负债表）
- **中观道**：国内政策周期（监管态度/产业政策）
- **微观道**：行业景气周期（链上活动/Gas 费趋势/DeFi TVL 变化）
- 三层共振时信号最强（"上下同欲者胜"）

**量化评分**：加权打分后输出 -100 到 +100 的"道分"，归一化到 0~100。道分低于阈值时系统自动降低整体仓位上限，甚至暂停开新仓。

**评估结论**：道维度是现有系统最大缺口，但也是潜力最高的方向。需接入外部数据源（稳定币市值/ETF 流入/CEX 储备），fail-open 设计（数据缺失时降级为中性评分）。

### 天 — 时间节奏因子（0~100）

**定义**：日历季节性 + 宏观周期位置 + 波动率周期 + 流动性周期。

**现有覆盖**：
- WDH 时间维度(~45 特征)→ 技术共振型，非日历型
- 美林时钟四阶段 → 宏观经济周期型
- 缺日历型季节性

**指标池**：

| 子指标 | 量化方式 | 评分逻辑 |
|---|---|---|
| 日历季节性 | Q1 效应/Q4 效应/周末效应/减半周期季节性 | 统计历史均值，正收益期→加分 |
| 美林时钟位置 | 复苏/过热/滞胀/衰退四阶段 | 复苏对风险资产利好→加分 |
| 波动率周期 | VIX/ATR 分位 | 高位适合趋势策略，低位适合均值回归 |
| 流动性周期 | QE/QT 阶段 | QE→加分，QT→减分 |

**输出**：`seasonality_score ∈ [-1, +1]`，叠加到前置层 Level 评分上。

**"天时"否定条件**：当"天"的评分为负时（比如高波动+紧缩周期+年底），即使"道"和"地"评分为正，也应降低仓位——**"不与天时对抗"**。具体：天分 < 阈值 → position_factor 上界 × 天分归一化系数。

**过拟合防护**：用滚动窗口回测验证稳定性（2017-2020 训练，2021-2024 样外验证），若样本外 IC < 0.02 则降权或剔除。

**评估结论**：天维度缺口明确但实现简单——不需要新的外部数据源（仅需日历+历史统计），工作量小，建议作为**第一个落地**的维度。

### 地 — 市场结构与价格位置（0~100）

**定义**：价格位置、趋势结构、支撑阻力、成交量。核心不是看单一指标，而是判断当前市场属于哪种地形，再决定调用哪类策略。

**现有覆盖**（最强项，约 80%）：
- 弹簧力场 5MA（MA30/65/128/200 + 1400 大周期）
- 八卦坤☷地（支撑阻力~15 特征）
- 斐波那契(~10) + 枢纽点(~10)
- 艮☶山（市场结构~14 特征）

**补强指标**：
- 盘整持续时间量化（价格振幅 / ATR 比值，持续低于阈值=盘整）
- Follow-through Day 确认（下跌→上涨转换信号）
- 价格 vs MA200 距离分位

**六种地形分类**（参考《孙子兵法·地形篇》）：

| 地形 | 孙子原文 | 市场状态 | 适用策略 |
|---|---|---|---|
| 通形 | "我可以往，彼可以来" | 趋势上行（MA128>MA200，ADX 上升） | 趋势跟踪 |
| 挂形 | "我可以往，难以返" | 趋势下行（价格跌破关键均线，反弹无力） | 防守或做空对冲 |
| 支形 | "我虽不利，敌虽不利" | 窄幅震荡（ATR 收缩） | 突破策略 |
| 隘形 | "我居之则盈" | 宽幅震荡（假突破多） | 均值回归 |
| 险形 | "我先居之" | 放量跌破支撑 | 暂停或减仓 |
| 远形 | "难以远挑战" | 缩量筑底（波动下降） | 小仓位观察 |

**多时间框架确认**：至少用三个时间框架（日线、周线、月线）交叉验证，只有多框架共振时才提高信号权重。

**成交量维度**：价格是"地形"，成交量是"兵力部署"。价量配合（放量突破、缩量回调）比单纯价格位置更有参考价值。

**评估结论**：地维度是现有系统的强项，只需做针对性补强（2-3 个指标 + 地形分类），是五维度的**基础层**。

### 将 — 决策质量与执行纪律评分（0~100）

**定义**：不是预测能力，而是系统是否具备智、信、仁、勇、严。

**指标池**：

| 子指标 | 量化方式 | 评分逻辑 |
|---|---|---|
| 智：多算程度 | 因子覆盖度、回测完整度、样本外验证 | 准备越充分加分 |
| 信：数据支撑 | 信号是否有历史统计、IC、胜率、盈亏比支持 | 有数据验证加分 |
| 仁：本金保护 | 单笔风险 ≤1%~2%，连续亏损自动降仓 | 风控严格加分 |
| 勇：执行果断 | 综合评分达标且风控通过时是否执行 | 不犹豫、不随意干预加分 |
| 严：纪律硬约束 | 止损、最大回撤、单日交易次数、仓位上限是否硬编码 | 规则不可人工覆盖加分 |

**打分公式**：

```
将 = 智×20% + 信×25% + 仁×25% + 勇×15% + 严×15%
```

**硬规则**（系统级，不可人工覆盖）：

- 单笔最大亏损不超过总资金 1%~2%
- 连续亏损 3 次，仓位上限下降 20%
- 连续亏损 5 次，暂停新开仓
- 单日最大交易次数设置上限
- 止损线触发后不可手动取消
- 最大回撤达到阈值后强制降仓
- 连续盈利 M 次后不自动加仓（防止过度自信），需"道/天/地"三维确认才可放大

**关键定位**：
- **"勇"不是重仓赌博**——当道、天、地评分足够高，且风控条件满足时，系统必须执行。勇评分高 → 提高自动化执行权限；勇评分低 → 增加人工确认环节。
- **"严"不是提醒**——触发风控规则后，系统自动执行，不允许人工覆盖。

**评估结论**：将维度的核心价值在于**将现有分散的风控/仓位/纪律逻辑统一为评分卡**，输出最终 position_factor 和 confidence_threshold。

### 法 — 策略库与执行规则评分（0~100）

**定义**：策略库、仓位规则、风控规则、复盘机制。

**指标池**：

| 子指标 | 量化方式 | 评分逻辑 |
|---|---|---|
| 策略库完备性 | 趋势、均值回归、突破、动量、对冲、应急策略是否齐全 | 策略覆盖越全加分 |
| 策略适配度 | 当前地形是否匹配策略类型 | 匹配加分 |
| 风控规则完整度 | 止损、回撤、仓位、相关性限制是否完整 | 规则越完整加分 |
| 回测验证度 | 样本外表现、夏普、最大回撤、换手率是否达标 | 验证越充分加分 |
| 复盘迭代机制 | 是否定期归因、降权、退役策略 | 有迭代机制加分 |

**打分公式**：

```
法 = 策略库完备性×20% + 策略适配度×25% + 风控规则×25% + 回测验证×20% + 复盘迭代×10%
```

**策略分层管理**（对应"以正合，以奇胜"）：

| 层级 | 定位 | 策略特征 | 兵法对应 |
|---|---|---|---|
| 核心策略 | 正兵 | 长期稳定收益（趋势跟踪/突破/均值回归） | "以正合" |
| 辅助策略 | 奇兵 | 捕捉阶段性机会（动量轮动/波动率） | "以奇胜" |
| 应急策略 | 败兵防线 | 极端行情下防守（对冲/减仓/空仓） | "先为不可胜" |

> 策略库详细设计见下方第四节"策略库详解"。

## 四、策略库详解

策略库不能脱离五维评分单独使用。最终系统不是"哪个策略最准"，而是：**在当前道、天、地、将、法环境下，哪类策略最匹配，允许多大仓位，是否必须止损，是否需要空仓等待。**

建议先不要全部上线，而是按以下顺序验证：

```
趋势跟踪 → 均线/通道突破 → 均值回归 → 动量轮动 → 波动率策略 → 对冲/空仓应急
```

每一类策略都要单独回测，再进入"五维庙算系统"做适配测试。

### 4.0 策略库总览

| 策略类型 | 适用环境 | 核心逻辑 | 优先级 |
|---|---|---|---|
| 趋势跟踪 | 道高、地高、波动适中 | 顺势持有，让利润奔跑 | 核心 |
| 均线/通道突破 | 横盘压缩后突破 | 等待结构启动 | 核心 |
| 均值回归 | 震荡市、超买超卖 | 价格偏离后回归 | 核心 |
| 动量轮动 | 板块/资产强弱分化 | 强者恒强，弱者淘汰 | 辅助 |
| 波动率策略 | 波动率周期变化 | 利用波动扩张或收缩 | 辅助 |
| 对冲/空仓应急 | 道低、地破、天差 | 防守优先，降低暴露 | 应急 |

### 4.1 核心策略

#### 策略 1：趋势跟踪

最适合作为底仓策略。不追求买在最低点，而是追求在趋势确认后参与，并在趋势破坏时退出。

**适用条件**：
- 道 ≥ 70
- 地 ≥ 70
- 价格位于 MA128、MA200 之上
- ADX 上升，趋势逐渐清晰
- 成交量配合，不是缩量假突破

**入场规则示例**：
```
价格 > MA50 > MA128 > MA200
AND ADX > 20
AND 20日涨幅为正
AND 成交量 > 20日均量
```

**出场规则示例**：
```
价格跌破 MA50
OR 价格跌破入场后最高价的 8%
OR ADX 从高位回落
OR 庙算总分跌破 60
```

| 优点 | 风险 |
|---|---|
| 适合牛市、强趋势行情 | 震荡市容易被反复止损 |
| 能抓住大波段 | 入场滞后，回撤较大 |
| 与"道""地"维度高度匹配 | 需要配合波动率和均线结构过滤 |

#### 策略 2：均线/通道突破

适合"地"维度中的支形/隘形/险形转通形——长期横盘压缩后的启动。

**适用条件**：
- 价格长期横盘
- ATR 收缩
- 布林带宽度收窄
- 成交量突然放大
- 突破关键阻力位

**入场规则示例**：
```
过去60日价格波动率低于近200日最低20%
AND 价格突破60日最高价
AND 成交量 > 2倍20日均量
AND 价格 > MA200
```

**出场规则示例**：
```
价格跌破突破K线低点
OR 价格回撤超过突破幅度的50%
OR 3日内没有继续创新高
OR 庙算总分下降
```

| 优点 | 风险 |
|---|---|
| 适合捕捉趋势起点 | 假突破较多 |
| 信号相对客观 | 需要成交量确认 |
| 可与横盘时间、成交量结合 | 突破后无法延续容易快速回撤 |

#### 策略 3：均值回归

适合震荡市，不适合强趋势市。逻辑是：价格短期偏离合理区间后，会向均值回归。

**适用条件**：
- 道中等，不是单边牛市或熊市
- 地处于宽幅震荡
- 没有明显趋势
- 价格出现超买或超卖
- 成交量没有极端放大

**入场规则示例**：
```
RSI < 30
AND 价格接近布林带下轨
AND 价格距离 MA200 不超过 -10%
AND ADX < 20
```

**出场规则示例**：
```
价格回到 MA20
OR RSI 回到50以上
OR 价格跌破前低
OR 庙算总分下降
```

| 优点 | 风险 |
|---|---|
| 震荡市胜率高 | 趋势行情中容易逆势接刀 |
| 持仓周期短 | 必须限制仓位 |
| 适合捕捉反弹和修复行情 | 必须严格止损，一次单边行情可能抹掉多次盈利 |

### 4.2 辅助策略

#### 策略 4：动量轮动

不预测单一资产涨跌，而是比较多个资产或板块的强弱，选择相对强者。

**适用条件**：
- 市场有结构性行情
- 板块轮动明显
- 道分中等以上
- 地分不要求特别高，但最好不是全面破位

**入场规则示例**：
```
计算每个板块/资产过去20日、60日涨幅
选择排名前20%的资产
要求该资产价格 > MA50
要求成交量不异常萎缩
```

**出场规则示例**：
```
排名跌出前30%
OR 价格跌破 MA50
OR 板块资金持续流出
OR 庙算总分下降
```

| 优点 | 风险 |
|---|---|
| 适合结构性行情 | 趋势反转时容易滞后 |
| 能自动切换强势方向 | 高波动市场中可能频繁换手 |
| 比单一标的预测更稳健 | 需要防止追高已经透支的板块 |

#### 策略 5：波动率策略

不看涨跌，而是看市场是否从压缩走向扩张，或从扩张走向收缩。

**适用条件**：
- ATR、布林带宽度、隐含波动率出现明显变化
- 市场经历长期低波动
- 即将进入方向选择阶段

**波动率状态与策略偏好**：

| 波动率状态 | 策略偏好 |
|---|---|
| 低波动压缩 | 准备突破策略 |
| 波动率扩张初期 | 趋势跟踪、突破加仓 |
| 高波动且无方向 | 降低仓位、均值回归谨慎 |
| 波动率回落 | 观察是否进入新平衡 |

**入场规则示例**：
```
过去60日ATR处于近250日最低20%
AND 价格突破近20日高点
AND 成交量放大
AND 庙算总分上升
```

**出场规则示例**：
```
波动率快速扩张但价格无法延续
OR 价格跌回突破区间
OR 庙算总分下降
```

| 优点 | 风险 |
|---|---|
| 能提前识别行情启动窗口 | 波动率压缩不等于马上突破 |
| 适合和突破策略组合 | 假突破会很多 |
| 可以过滤低效震荡 | 需要结合"道""地"判断方向 |

### 4.3 应急策略

#### 策略 6：对冲/减仓/空仓应急

应急策略不是用来赚钱，而是用来保命。当"道""天""地"同时恶化时，最优动作不是找买点，而是降低暴露。

**适用条件**：
- 道 < 50
- 天 < 50
- 地 < 50
- 庙算总分 < 60
- 账户回撤接近风控线
- 市场宽度快速恶化

**应急动作**：

| 条件 | 动作 |
|---|---|
| 庙算总分 < 60 | 不开新仓，仓位上限降至 20% |
| 道 < 40 | 仓位上限降至 30% |
| 地 < 40 且 天 < 40 | 只允许对冲或空仓 |
| 账户回撤达到阈值 | 强制降仓 |
| 连续亏损触发纪律 | 暂停新开仓 |

**对冲方式**：

| 方式 | 适用场景 | 注意事项 |
|---|---|---|
| 减仓 | 信号模糊 | 优先降低高波动仓位 |
| 空仓 | 道、天、地同时恶化 | 避免频繁抄底 |
| 股指期货对冲 | 股票组合暴露过高 | 注意基差和展期成本 |
| 期权保护 | 需要保留多头暴露 | 注意时间价值损耗 |
| 跨资产分散 | 单一资产风险过高 | 防止相关性突然上升 |

| 优点 | 风险 |
|---|---|
| 能显著降低极端回撤 | 过早空仓可能错过反弹 |
| 避免在恶劣环境中频繁交易 | 对冲成本会侵蚀收益 |
| 符合"先为不可胜" | 需要明确恢复条件，不能长期被动防守 |

### 4.4 策略与五维评分调用规则

| 五维状态 | 优先策略 | 禁止/降权策略 |
|---|---|---|
| 道高、地高、波动低 | 趋势跟踪、突破加仓 | 逆势抄底 |
| 道高、地震荡 | 动量轮动、均值回归 | 重仓突破 |
| 道中、地压缩 | 波动率突破、小仓位试探 | 满仓追涨 |
| 道低、地破位 | 减仓、对冲、空仓 | 趋势做多 |
| 天差、波动高 | 应急策略、降低杠杆 | 高频突破 |
| 信号冲突 | 降低仓位，等待共振 | 强行开仓 |

### 4.5 策略冲突处理规则

当多个策略给出矛盾信号时，不能简单平均，必须有优先级。

**优先级链**：

```
风控规则 > 应急策略 > 趋势策略 > 突破策略 > 动量轮动 > 均值回归
```

**冲突处理示例**：

| 策略信号 | 处理方式 |
|---|---|
| 趋势看多，均值回归看空 | 降低仓位，等待方向确认 |
| 突破看多，动量轮动看弱 | 小仓位试探，不重仓 |
| 均值回归看多，趋势看空 | 不做逆势重仓 |
| 多个策略同时看多 | 提高信号权重，但仍受仓位上限约束 |
| 风控触发 | 所有策略让步 |

### 4.6 策略回测指标清单

每个策略上线前，至少要统计以下指标：

- 年化收益率
- 最大回撤
- 夏普比率
- 卡尔玛比率
- 胜率
- 盈亏比
- 平均持仓周期
- 换手率
- 最大连续亏损次数
- 样本外表现
- 不同市场环境下的表现

**不能只看收益率**。一个策略如果收益高，但最大回撤大、样本外衰减严重、换手率过高，就不能作为核心策略。

### 4.7 MVP 策略库

如果刚开始落地，不要一次性做太多。先做一个 MVP 策略库：

| 层级 | 策略 | 覆盖场景 |
|---|---|---|
| 核心 | 1. 趋势跟踪 | 趋势行情 |
| 核心 | 2. 均线/通道突破 | 突破行情 |
| 核心 | 3. 均值回归 | 震荡行情 |
| 辅助 | 4. 动量轮动 | 结构轮动 |
| 应急 | 5. 减仓/空仓/对冲应急 | 极端防守 |

这五类已经足够覆盖主要场景。后续再逐步加入波动率策略、期权保护、跨资产对冲等复杂模块。

### 4.8 策略生命周期管理

每个策略都应有生命周期，不能上线后就不管。

```
上线 → 监控 → 评估 → 降权 → 迭代 → 退役
```

| 状态 | 触发条件 |
|---|---|
| 观察期 | 刚上线，小仓位运行 |
| 正式运行 | 样本外表现稳定 |
| 降权 | 夏普下降、回撤扩大、IC 下降 |
| 暂停 | 连续亏损或市场环境不匹配 |
| 退役 | 长期无效或逻辑失效 |

### 4.9 策略库模块化架构

建议把策略库写成独立模块：

```
庙算引擎      → 道、天、地、将、法打分
策略选择器    → 根据五维评分选择策略
仓位管理器    → 根据总分和风控决定仓位
风控否决层    → 止损、回撤、纪律、极端行情
执行引擎      → 下单、滑点、手续费、成交确认
复盘模块      → 归因、降权、迭代
```

**核心层（BCRM 2.0）通过相关特征计算触发币种信号，匹配相关的法（策略），对应需要一些策略性设置（后期需要详细调研探讨）。**

### 4.10 策略层插入评估：后置层与离场层之间

> 本节调研在"后置层"和"离场层"之间增加"策略层"对现有架构的影响，重点评估对离场层的改造需求。

#### 4.10.1 现有架构流程（实际代码路径）

```
前置层(MorphCyclePredictor)
  → L/T 评分 → ParameterMapper 转为 6 参数 + 5 板块权重
  → 注入核心层
        ↓
核心层(BCRM 2.0)
  → L1 方向预测 + L2 Meta-Labeling + L3 辩证裁决
  → 输出: direction + confidence + hexagram + risk_level
        ↓
后置层(RangingMarketEnhancer)              [polling_trader.py L6824]
  → 输入: direction, confidence, closes, ATR, is_ranging
  → 5 种市场状态识别 + 布林带确认 + 方向偏向(MA200)
  → 动态止损倍数(sl_atr_mult/tp_atr_mult)
  → 置信度阈值校准(recommended_long/short_threshold)
  → should_trade 综合判断
  → 输出: enhance_result → 写入 inference["enhance_result"]
        ↓
开仓(_open_position)                         [polling_trader.py L7085+]
  → 综合后置层 enhance_result + v4 风险评分 + P2 动态仓位

  → 6 策略按优先级链式评估:
    P3EarlyExit(10) → SignalReverse(20) → EvForceClose(30)
    → Timeout(40) → RankedTp(50) → EvAdjust(60)
  → force_close / adjust_sl_tp / hold / pass
  → 全部 pass → 核心层卦象主离场 + Classic 兜底
```

**关键发现**：后置层（校准下单参数）和离场层（管理持仓离场）之间，**缺少一个策略选择层**——当前所有信号都用同一套 SL/TP/离场策略链，没有按策略类型差异化。

#### 4.10.2 策略层插入位置

```
后置层(RangingMarketEnhancer)
  → enhance_result (regime + SL/TP + should_trade)
        ↓
策略层(新增) ← 庙算五计评分 + enhance_result.regime(地形)
  → 选择策略: 趋势跟踪/突破/均值回归/动量/波动率/应急
  → 输出: strategy_type + SL/TP 覆盖 + 仓位倍率 + 离场规则
        ↓
开仓(_open_position) → 综合策略参数 → 下单
        ↓
离场层(ExitManager) → 按 strategy_type 选择离场子链
```

#### 4.10.3 对核心层的影响

**基本无影响**。核心层 BCRM 2.0 继续输出 direction + confidence + hexagram，策略层在其下游消费这些信号，不改变核心层的推理逻辑。

唯一可能的交互：策略层判断"当前不适合某类策略"时（如庙算分低），可以反馈调低核心层的置信度阈值——但这属于庙算引擎的"不出战"机制，不需要修改核心层本身。

#### 4.10.4 对后置层的影响

**基本无影响**。后置层 RangingMarketEnhancer 继续做市场状态识别 + SL/TP 倍数推荐 + 阈值校准。策略层消费后置层的 enhance_result：

- 后置层的 `regime`（5 种市场状态）作为策略层"地形分类"的输入之一
- 后置层的 `recommended_sl_atr_mult` / `tp_atr_mult` 作为策略层的基准值，策略层可覆盖
- 后置层的 `should_trade` 判断与策略层的"不出战"机制叠加（两者都通过才执行）

后置层本身不需要改动，只是其输出被策略层消费。

#### 4.10.5 对离场层的影响和改造（重点）

这是策略层插入后影响最大的部分。当前离场层的核心问题：

**问题 1：ExitContext 缺少策略类型信息**

当前 [ExitContext](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/11-易经推理系统/scripts/memory_l4/bcrm2/exit_manager.py#L24-L42) 只有 coin/inference/pos_info/tracker_pos/in_protection/age_hours/ev/multi_horizon/confidence/all_inferences/held_coins/effective_threshold，没有 `strategy_type` 字段。所有持仓不分策略类型，用同一套 6 策略链评估。

**改造方案**：ExitContext 新增 `strategy_type` 字段：

```python
@dataclass
class ExitContext:
    # ... 现有字段 ...
    strategy_type: Optional[str] = None  # 新增: "trend_follow" / "breakout" / "mean_revert" / "momentum" / "volatility" / "emergency"
```

**问题 2：不同策略应有不同的离场规则**

当前 6 个 ExitStrategy 对所有持仓一视同仁。但不同策略的离场逻辑应该不同：

| 策略类型 | 离场侧重 | 应放权/收紧的离场策略 |
|---|---|---|
| 趋势跟踪 | 趋势破坏才离场，让利润奔跑 | SignalReverse 放宽阈值；EvForceClose 放宽；**不触发 TimeoutProfitSwitch**（趋势中不应超时换仓） |
| 突破策略 | 突破失败快速离场 | SignalReverse 收紧；**新增突破失败检测**（3 日未创新高 → force_close） |
| 均值回归 | 价格回归到均值即离场 | **新增回归达标检测**（RSI 回到 50 / 价格回到 MA20 → force_close）；Timeout 收紧 |
| 动量轮动 | 排名跌出 → 换仓 | TimeoutProfitSwitch 优先级提升；RankedTp 适配 |
| 波动率策略 | 波动率状态变化 → 离场 | **新增波动率转折检测**（ATR 从扩缩到收缩 → adjust） |
| 应急策略 | 防守优先 | 所有离场策略收紧；EvForceClose 阈值降低 |

**改造方案**（两种路径，建议先 A 后 B）：

**路径 A（轻量改造，推荐先做）**：
- ExitContext 新增 `strategy_type`
- 各 ExitStrategy 在 `evaluate()` 开头检查 `ctx.strategy_type`，按策略类型调整自身阈值
- 例如 SignalReverseStrategy：趋势跟踪策略用更高反转阈值（0.70），均值回归用更低阈值（0.55）
- 改动范围：[exit_strategies.py](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/11-易经推理系统/scripts/memory_l4/bcrm2/exit_strategies.py) 各策略类的 evaluate 方法

**路径 B（完整改造，后期可选）**：
- 按策略类型分组，每种策略类型注册不同的离场策略子链
- ExitManager 持有 `Dict[str, List[ExitStrategy]]` 映射表
- 调用时根据 `strategy_type` 选择对应子链
- 优点：隔离性好，可以为不同策略类型定制完全不同的离场逻辑
- 缺点：维护成本高，6 策略 × 6 类型 = 36 种组合

**问题 3：持仓元数据需要记录策略类型**

当前 [position_tracker](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/11-易经推理系统/scripts/memory_l4/polling_trader.py#L5933) 获取的 tracker_pos 没有 strategy_type 字段。开仓时需要记录策略类型到持仓元数据，离场时才能读取。

**改造方案**：
- 开仓时在 `_open_position` 中将 `strategy_type` 写入 `inference` 或 `position_tracker` 元数据
- 离场时从 `tracker_pos` 或 `inference` 中读取 `strategy_type`，传入 ExitContext
- polling_trader.py L5990 的 `exit_manager.evaluate()` 调用新增 `strategy_type=kwargs.get("strategy_type")`

#### 4.10.6 策略层数据流总结

```
                     ┌─────────────────────┐
```

#### 4.10.8 建议实施路径

4. **第四步**：回测验证——对比插入策略层前后的夏普/回撤/胜率
5. **第五步**：按策略类型定制专属离场逻辑（路径 B，可选）

### 4.11 架构冲突评估：与现有架构的兼容性逐项检查

#### 4.11.1 检查结论总览

#### 4.11.2 ExitContext 扩展的向后兼容风险

当前 ExitContext 字段：`coin, inference, pos_info, tracker_pos, in_protection, age_hours, ev, multi_horizon, confidence, all_inferences, held_coins, effective_threshold`。

**新增字段必须全部带 `Optional[...] = None` 默认值**，否则所有直接构造 ExitContext 的调用点会立即报错（包括测试用例、未来的外部调用方）。这是路径 A 改造中唯一的 breaking-change 控制点——**建议统一在 ExitContext dataclass 里声明，不在各策略 evaluate() 签名里零散增加参数**，避免签名漂移。

#### 4.11.3 TradeRecord / 持仓恢复兼容性（高风险但现状天然兼容）

- `TradeRecord` 已存在 `strategy_source: str = ""` 与 `enhance_info: Dict = {}`。策略层写入 `strategy_type` 有两种方式：
  - 方案 A（推荐，0 迁移风险）：写入 `enhance_info["strategy_type"] = "trend_follow"`，不落 schema。
  - 方案 B（强类型，推荐路径 B 阶段再做）：在 TradeRecord 新增 `strategy_type: Optional[str] = None` 字段。
- `_load_open_positions` 用 `{k:v for k,v in data.items() if k in TradeRecord.__dataclass_fields__}` 过滤（见 [trading_utils.py#L1015-L1016](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/11-易经推理系统/scripts/memory_l4/trading_utils.py#L1015-L1016)），**历史仓位 JSON 缺字段时不会报错；新增字段给默认值时也不会丢数据**。此机制为策略层新增字段提供了关键容错。
- 实盘如果要做 "旧持仓按默认策略类型处理"，规则必须明确：**建议把无 strategy_type 的历史持仓统一视为 `strategy_type=None`，由 ExitStrategy 按当前默认（等价于现状）行为评估**，避免中途切换策略规则把一笔趋势单提前止损。

#### 4.11.4 RankedTp 的特殊处理（容易踩坑）

代码现状（[polling_trader.py#L602-L615](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/11-易经推理系统/scripts/memory_l4/polling_trader.py#L602-L615)）：ExitManager 实盘仅注册 5 个策略：`P3 → SignalRev → EvFC → Timeout → EvAdj`，**RankedTpStrategy 不在链上**。跨持仓排名止盈由 `_handle_ranked_tp_top1` 独立调用（[L8129+](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/11-易经推理系统/scripts/memory_l4/polling_trader.py#L8129)），执行前会先 `if enable_ranked_tp` 开关 gate。

**冲突隐患**：§4.10 的路径 B 描述中把 RankedTp(50) 作为统一链的一环来按策略类型注册/放行，**这与实际运行架构不一致**。改造时需注意：

- 路径 A：在 `_handle_ranked_tp_top1` 入口读取持仓元数据里的 `strategy_type`，**对 trend_follow / breakout 类型默认跳过 RankedTp（或者降低其档位权重）**，让利润奔跑；对 mean_revert / momentum 类型保留。
- 路径 B：要么 **(1) 把 RankedTp 并入 ExitManager（需要重构其跨持仓 gap 计算依赖）**，要么 **(2) 继续保留 RankedTp 为外部循环，但在策略层统一输出 `enable_ranked_tp_allow: Dict[str, bool]` 路由表**。推荐 (2)，避免破坏现有已验证的排名止盈逻辑。

#### 4.11.5 开仓堆栈约束叠加顺序（避免双重计数 / 双重覆盖）

当前开仓约束链（自顶向下，取最严格）：

```
庙算引擎 "不出战" (战略否决)
  → CapitalControl.allowed / max_position_usdt (跨账户硬上限)
    → 后置层 should_trade + recommended thresholds
      → RiskManager.check_risk + 日损上限 min(dynamic_limit, daily_loss_limit)
        → P2 动态仓位 / 形态乘数 + 做多/做空分层
          → _open_position 最终 SL/TP/Size 计算
```

策略层应插入在 **"后置层之后、_open_position 最终计算之前"**（与 §4.10.2 插入位置一致），且必须遵守 "取更严格者" 的单调性原则：

- 仓位：`final_size = min( size_after_risk, strategy_layer.max_size )`
- SL：`final_sl_atr_mult = min( sl_after_enhance, strategy_layer.sl_mult )` （对突破/应急策略需要更紧）
- TP：趋势策略允许 `strategy_layer.tp_mult = None`（不封顶，使用移动止盈）；均值回归必须固定 `tp_mult`（回归边界）
- 否决：`should_trade_final = should_trade_from_enhancer AND NOT strategy_layer.veto`

**禁止做法**：策略层直接覆盖风控输出的日损上限 / 单票风险预算，否则会出现 "庙算高分 → 放大风险预算 → 单笔亏损超过日阈值" 的反模式。

#### 4.11.6 推理缓存 / State 持久化冲突

- 策略层的 `strategy_type` 必须是**开仓时刻一次性绑定**的属性（写进持仓元数据），不能在持仓期间每轮轮询重新评估庙算而切换 `strategy_type`，否则会出现同一笔交易 "先按趋势跟踪放跑、第 3 天突然按均值回归强制平仓" 的规则跳变。
- 允许的动态调整：离场策略在同一 `strategy_type` 内部，根据实时 EV / 卦象 / regime 调整阈值（例如 TimeoutProfitSwitch 的 timeout_hours 可延长 / 缩短）。**这属于参数漂移，不属于策略类型切换**。
- 推荐增加一个 `strategy_version` 标记字段（写进 enhance_info），确保策略代码升级后，旧持仓按旧版本行为离场、新开仓按新版本。

### 4.12 传统金融视角评估：可行性、风险与建议

> 本节站在传统量化资管（资产配置 / CTA / 多策略组合）视角，评估五计框架 + 策略层改造的**可实现性**、**统计稳健性**与**组合风险**。

#### 4.12.1 与传统金融范式的对应关系

| 本文概念 | 传统金融对应物 | 业界对标 |
|---|---|---|
| 庙算引擎（战略筛选） | Tactical Asset Allocation (TAA) / Regime Overlay | Bridgewater "Systematic Alpha"、AQR "Style Premia" 的 regime-aware 分配层 |
| 道/天 维度（政策 + 季节性 + 宏观） | 宏观因子 + 日历异象 | Fama-French 扩展因子（Mkt-RF、HML、QMJ）+ 年末/年初/议息窗口日历 |
| 地 维度（趋势结构 + 位置） | 风格因子：动量（Momentum）、价值（Value）、低波动（Low-vol） | 12-1 动量、MA128/MA200 趋势过滤器 |
| 策略层（按 regime 路由） | 多策略混合（Multi-strategy Mix） / CTA 子策略切换 | RegimeSense、Winton/AHL 的"动量-均值回归-波动率套利"混合权重 |
| 法 策略库（趋势/突破/均值回归/动量/波动率/应急） | Style Premia Toolkit | AQR 风格溢价 + CTA 经典动量突破（Turtle） |
| 不出战机制 | Risk Off Mode / Circuit Breaker | 组合最大回撤阈值熔断（15%/20%）、VIX>30 降仓 |

**结论**：方案整体符合传统多策略量化的标准分层范式（宏观 → 风格 → 子策略 → 风险 → 执行），不是反范式设计，具备架构合理性。

#### 4.12.2 可行性评估：逐维度打分

| 维度 | 可行性评级 | 关键论点 |
|---|---|---|
| 道（政策/资金一致性） | B（可实现，但噪音大） | 政策情绪可用 Fed/FOMC 文本 + 监管事件词典打分；机构资金可用 ETF 资金流、BTC 交易所净流量、稳定币净发行量等代理。风险是样本外事件（如黑天鹅监管）会让方向一致性评分失效。 |
| 天（季节性 + 周期） | A-（资料充分，需防过拟合） | 季节性因子（美股 1 月/12 月效应、加密四年度减半周期、黄金 9-10 月避险季）有大量文献支撑。**最大风险是过拟合**——同一数据被反复优化 p-hack 导致样本外反向。建议严格 Walk-Forward + 随机排列检验。 |
| 地（价格位置/趋势结构） | A（最稳健） | MA50/MA200、ADX、布林带、ATR 通道位置均为传统 CTA 的主流特征；五计框架中权重最高（25%）是合理的——这是数据最多、统计显著度最高的维度。 |
| 将（决策质量/纪律） | B-（难以直接量化，建议转为"系统行为审计分"） | 传统资管通常不在打分层显式放"纪律"，而是把它固化为风控否决（回撤阈值、隔夜限额、违规交易上报）。建议将维度改为 `audit_score`，量化检查项：实际仓位是否越界、是否触发超时未平仓、是否有异常退出原因。 |
| 法（策略库） | A-（策略本体成熟，路由是关键） | 6 类策略全部是经典且可编码。风险点不在单个策略，而在 **路由准确率**——如果 regime 判断错误，在趋势市场里调用均值回归会产生亏损。建议路由失败时回退到当前默认策略链（Fail-Open）。 |

**综合可行性评级：A-/B+ 级** — 可落地的核心前提是："地维度做锚、天/道做修正、将/法做约束"。不要把过多权重放在可观测性弱的维度（道、将）上。

#### 4.12.3 传统金融视角的改进建议（优先级从高到低）

1. **用"风格因子暴露"取代"策略类型单选"**（建议）
   传统量化很少把一笔交易强制绑定一种"策略类型"——而是把持仓拆解成若干风格暴露（β_mkt、β_mom、β_val、β_vol…），组合层面做净暴露约束。
   **建议路径 A 就引入 `style_exposures: Dict[str, float]`**：`strategy_type = "trend_follow"` 对应 `{momentum: 0.8, mean_revert: 0.1, volatility: 0.1}`，组合层做 aggregate exposure cap。这样能避免"路由判错一次整笔交易策略错"的单点风险。

2. **仓位 Sizing 采用"风险预算 + Kelly 半凯利"而非纯分数映射**
   庙算分直接乘 position_factor 的方式存在：分数波动 → 仓位大幅跳动 → 交易成本侵蚀。
   传统做法是：`position_risk_budget = max( 0.25% , min( 2% , equity * (庙算分/100) * risk_multiplier ) )`，单笔止损距离用 ATR × mult；**仓位 = risk_budget / stop_distance**。这种 ATR sizing 是 Turtle/AHL 的经典范式，比"仓位 = 默认仓位 × 分数倍数"更稳健。建议在策略层输出 `risk_budget_pct`，让 `_open_position` 里统一按 ATR 反算 size，与现有 `sl_atr_mult` 形成一致量纲。

3. **策略收益归因（Performance Attribution）必须是策略层的一等公民**
   传统多策略系统不会只看组合总净值——必须拆到：
   - 按策略类型：趋势/突破/均值回归 各自的 PnL、胜率、持仓时长、贡献度
   - 按维度：道高分/低分时期组合表现差、地维度 regime 下各策略盈亏
   - 按时间：白天/夜间、财报季/非财报季
   这也是为什么 §4.11.1 里建议 `_save_exit_strategy_decision` 增加 `strategy_type` 字段——归因做不起来，五计权重就永远校准不了。建议：**`exit_strategy_log` 表 schema 版本号 +1，新增 `strategy_type, regime_label, five_score_snapshot(五位分 json 可选)` 三列**，并配套月度归因报表。

4. **"不出战"熔断必须是双阈值（滞回），避免频繁开关仓**
   当前文档按 "总分<60 不交易、≥75 正常" 三档本身就带滞回带宽（60-75 的灰区），这点符合行业实践。建议再加 **冷却期**：触发不出战 → 连续 N 轮（N=3，按 interval=300s 即 15 分钟）评分 ≥60 才能恢复；或者按日级：当日触发不出战，则当日不再开新仓。这对应传统组合管理的 "Risk Off after breach, cool down before risk on" 纪律。

5. **策略层回测必须包含：滑点、手续费、延迟、资金曲线相关性三项现实摩擦**
   - 滑点：加密 2-5 bps、美股 1-3 bps；资金规模 > 10 万 USDT 时按流动性分层。
   - 手续费：现货 maker 0.1%、taker 0.4%；合约 maker -0.02% / taker 0.05%（OKX/币安档位）。均值回归和波动率策略换手高，手续费常常吃掉所有 α，必须显式模拟。
   - 相关性：如果策略层同时选了 "趋势 BTC / 趋势 ETH / 趋势 SOL"，三者相关性 > 0.85，本质是同一笔风险的三倍。传统金融的做法是：**按聚类（PCA / Hierarchical Clustering）限制同风格/同聚类的总仓位 ≤ 总仓位上限的 X%**。建议在 `CapitalControlComponent` 之后、`_open_position` 之前增加**"持仓聚类约束"作为新的硬约束**，这比单个策略的退出规则对组合回撤更有效。

6. **"法"维度的策略库应按"流动性池"分层**
   传统 CTA 会区分高流动性池（BTC/ETH/SPY/QQQ/GLD）、中流动性池（主流 alt/板块 ETF）、低流动性池（小币）。策略可用性不同：
   - 低流动性池不做突破/波动率策略（滑点大 + 冲击成本高），只做均值回归/动量（窄幅、低换手）。
   - 高流动性池允许所有策略，且仓位上限更高。
   建议在策略库 4.0 层增加 **LiquidityTier × StrategyType** 可用性矩阵，避免在不具备流动性的标的上调用高换手策略。

7. **路径 B 的多子链维护成本风险（经典反模式提示）**
   传统量化里，6 类策略 × 每个策略独立离场链（6×6=36）会产生**"配置漂移"风险**——某一条子链改了阈值、其他没改，导致回测与实盘不一致。业界更常用的是：
   - **一个统一的 Exit 引擎 + `strategy_type → 参数表（lookup dict）`**，即路径 A 的强化版。
   - 真正需要独立子链的，通常只有 "趋势 CTA 组合 + 中性套利组合 + 应急组合" 三个大组合级别，而不是单笔交易级别。
   因此**强烈建议路径 B 仅在"组合级"（整个账户的策略切换）使用，不要把单笔持仓拆成 6 条子链**，否则后续归因/回溯/调试成本会指数级上升。

### 4.13 业界 / GitHub 成功经验借鉴

> 以下 4 个开源项目/知识库代表了业界 "regime-aware 策略切换" 与 "经典策略退出规则" 的主流做法，可直接作为路径 A/B 改造的参考蓝本。

#### 4.13.1 RegimeSense（GitHub：moh1tt/RegimeSense，2026.03）—— 最直接对标

**核心做法**：
- 每日 regime 分类（4 态：bull / choppy / high-vol / bear）。
- 为每种 regime 维护一个策略权重表：牛市时提高 Momentum、Trend Following 权重；震荡市时提高 Mean Reversion 权重；熊市时切到 Cash / Low-vol。
- 连续重加权（Continuously reweighting）而不是硬切换，避免 regime 识别抖动带来的频繁换手。

**可借鉴点**：
- **不要做"单选 strategy_type"，做权重向量** — 即 §4.12.3 建议的 style_exposures：`weights={"trend": 0.7, "mean_revert": 0.2, "emergency": 0.1}`，用概率化分配替代 0/1 路由。
- RegimeSense 的 "choppy + trend 混合" 状态正好对应易经后置层 `regime_pred` 输出的 5 态分类——**可以把 5 态直接 map 到 4 态权重矩阵，作为策略层的第一个权重版本 baseline，不需要重新训练**。
- 权重更新频率：日级。加密 5 分钟级轮询可以在权重更新上做指数平滑（EMA α ≈ 0.15），避免每 5 分钟跳变。

#### 4.13.2 regime-aware-portfolio-risk-engine（GitHub：jimech/...，2026.06）—— 组合级风险动态调整

**核心做法**：
- Gaussian HMM + 多因子（VIX、信用利差、期限利差、10Y-3M 曲线斜率）识别 regime。
- 组合层面做 regime 条件方差-协方差矩阵估计（regime-conditional covariance），用于动态调整资产权重。
- 输出：组合风险暴露热力图、绩效归因报告。

**可借鉴点**：
- **五计的"不出战"阈值应当和 regime-specific covariance 挂钩**：比如高波动 regime 下，"高庙算分"对应的允许总仓位上限应该自动乘 0.5，而不是只看分数本身。
- 可以复用 §4.12.3 建议的 "聚类约束"：在高分时提高总上限、在低分时收紧上限 + 降低聚类同方向头寸的集中度。
- 归因报表模板：按 regime 分组的策略收益贡献柱状图、回撤贡献饼图、风格暴露雷达图，直接作为 `exit_strategy_log` + PnL 的月度报表输出样式。

#### 4.13.3 IssacWong0103 / Regime-Switching Hybrid Trading System（ADX 路由 + 两种退出）—— 最小可行范式

**核心做法**：
- 仅用一个指标 ADX(14) 路由：ADX ≤ 25 → Mean Reversion；ADX > 25 → Trend Following。
- 退出规则完全不同：
  - 均值回归：RSI>70 / 触布林上轨 → 止盈；固定 SL；短 Timeout。
  - 趋势跟踪：3×ATR Chandelier 移动止盈；长 Timeout；不设固定 TP。

**可借鉴点**：
- 这是路径 A 改造的**最小代码蓝本**。易经系统 ADX/ATR/布林指标（后置层里已大量使用）都是现成的，**可以直接把 `enhance_info["regime_pred"]` 当 ADX 的超集，映射到 6 类 strategy_type**。
- 退出规则对照表可直接挪用为 `ExitStrategy.evaluate()` 内部按 strategy_type 调整阈值的默认参数：

| strategy_type | 时间超时 Timeout | SignalReverse 置信度阈值 | EvForceClose EV 阈值 | RankedTp 是否参与 | TP 类型 |
|---|---|---|---|---|---|
| trend_follow | ×2（延长，如 58h） | 0.70（放宽反转） | 放宽到 EV<0.2 | 否（让利润跑） | 3×ATR Chandelier |
| breakout | ×1（默认） | 0.55（收紧反转，失败快跑） | EV<0.3（正常） | 是（部分止盈） | 固定 2×ATR + 部分 trail |
| mean_revert | ×0.5（缩短至 14h） | 0.55（收紧） | EV<0.4（严格） | 是（回到边界必走） | 固定 TP（回归到 MA/Boll 中线） |
| momentum | ×0.75（22h） | 0.65（中等） | EV<0.3（正常） | 是（排名优先换仓） | RankedTp + Timeout 联合 |
| volatility | ×0.75（22h） | 0.60（灵活） | EV<0.4（严格） | 否（不参与排名） | ATR 收缩/扩张反转触发 |
| emergency | ×0.25（7h 必走） | 0.50（最紧） | EV<0.5（最紧） | 否（优先现金） | 任意触发立即走 |

- 如果路径 A 只落地一张参数表（即上表），**改造量约 50~80 行代码**（仅 ExitStrategy 的 if-else 分支 + ExitContext 字段），即可获得 regime-aware exit 的 80% 收益。

#### 4.13.4 dotsystemsdevs / wolf-of-vibe-street knowledge.md — AI 交易系统三层架构 + 反模式清单

**核心价值**：
- 总结了 AI 交易系统的三层结构：规则风险层 + ML 信号层 + LLM 研究层。与易经系统的现有分层高度吻合：**风控否决层（规则） = 风险层，BCRM 2.0 + 核心推理 = ML 信号层，五计庙算（后续可引入 LLM 做宏观/政策文本解析）= LLM 研究层**。

**可借鉴点**：

## 五、系统性架构

### 5.1 庙算引擎 — 综合胜算分

**评分汇总**：每个维度独立打分（0~100），加权汇总为庙算总分。

**综合公式**：
```
庙算总分 = 道×0.30 + 天×0.15 + 地×0.25 + 将×0.15 + 法×0.15
```

**评分示例**：

假设某次评估：道=80, 天=65, 地=75, 将=85, 法=80

```
庙算总分 = 80×0.30 + 65×0.15 + 75×0.25 + 85×0.15 + 80×0.15
        = 24 + 9.75 + 18.75 + 12.75 + 12
        = 77.25
```

决策含义：
- 总分高于 75，可正常参与
- 但"天"只有 65，说明时间节奏一般
- 不宜激进满仓
- 可允许趋势策略或突破策略，但仓位上限应打折
- 若后续"道"或"地"转弱，应快速降仓

### 5.2 仓位映射规则

庙算总分不应只输出"买/不买"，而应映射成仓位上限。

| 庙算总分 | 建议仓位上限 |
|---|---|
| ≥ 85 | 80%~100% |
| 75~84 | 50%~80% |
| 60~74 | 20%~50% |
| < 60 | 0%~20%，以防守为主 |

**维度否决规则**（比单纯看总分更安全）：

| 条件 | 约束 |
|---|---|
| 道 < 40 | 仓位上限 ≤ 30% |
| 将 < 40 | 仓位上限 ≤ 30% |
| 法 < 40 | 不开新仓 |
| 地 < 40 且 天 < 40 | 只允许对冲或空仓 |

### 5.3 风控独立否决层

风控不应散落在各个维度中，应抽离为**独立模块**，作为所有策略的"否决权"层——**"先为不可胜，以待敌之可胜"**。

**否决规则**（硬编码，触发即执行，不可覆盖）：

| 规则 | 触发条件 | 执行动作 |
|---|---|---|
| 总回撤否决 | 总账户回撤 > X% | 强制减仓至 Y% |
| 单品种亏损否决 | 单品种亏损 > Z% | 自动止损 |
| 相关性否决 | 持仓相关性 > 阈值 | 限制总暴露 |
| 流动性否决 | 品种 24h 成交量 < 阈值 | 禁止开仓 |
| 天时否决 | 天分 < 阈值 | 降低仓位上限 |

**架构定位**：
```
庙算引擎（五计评分）→ 胜算分 → 策略选择 + 仓位基调
                                        ↓
                               核心层（BCRM 2.0）→ 入场信号
                                        ↓
                               风控否决层 → ✅ 通过 / ❌ 否决
                                        ↓
                               执行层 → 下单
```

风控否决层与五角校验的区别：五角校验是**风险评分调控**（调仓位系数 0.60-1.10），否决层是**硬性否决**（直接阻止交易）。两者互补，不冲突。

**风控否决层的独立性**：必须独立于五维度评分之外，不能被任何维度的"高分"覆盖。即使道/天/地/将/法五维度全满分，风控否决层触发时仍然必须执行减仓/止损。

### 5.4 回测与权重校准流程

初始权重不要直接固定死，建议分三步验证。

**第一步：样本内训练**

用 2015~2022 或 2016~2023 的数据训练五维指标和权重。重点观察：
- 各维度 IC（信息系数）
- 各维度与未来收益的相关性
- 不同市场环境下的稳定性
- 是否存在过拟合

**第二步：样本外验证**

用 2023~2025 或最近两年数据做样本外测试。重点看：
- 样本外是否衰减
- 牛熊切换时是否稳定
- 高波动阶段是否控制回撤
- 策略调用是否合理

**第三步：滚动窗口校准**

建议每季度或每半年重新评估一次权重。可以使用：

```
维度权重 = f(IC均值, IR, 最大回撤贡献, 样本外稳定性)
```

但不建议完全交给模型自动优化，否则容易把噪声当成规律。

**迭代节奏**：

| 频率 | 内容 | 输出 |
|---|---|---|
| 每日 | L4 复盘（已有） | 交易记录 + 反思 |
| 每周 | 五维度评分归因 | 各维度 IC 值 + 权重微调建议 |
| 每月 | 策略表现评估 | 策略生命周期状态更新（迭代/退役） |
| 每季度 | 全系统回测 + 蒙特卡洛 | 权重重校准 + 策略库更新 |

**蒙特卡洛模拟**：将交易信号随机打乱 1000 次，计算原始策略的夏普比率在随机分布中的分位数，p < 0.05 才认为策略有效。

**定期复盘**：每月检查——道是否预测了方向？天是否预测了节奏？地是否识别了结构？将是否守住了纪律？法是否选对了策略？

## 六、五维度之间的层次关系

```
道（战略层）  ──── 机构资金方向 + 政策一致性 + 大周期位置
  │                → 判断"牛市/熊市/震荡市"生命周期
  │                → 决定整体仓位上限和激进/保守基调
  │                → 三层道共振（宏观/中观/微观）时信号最强
  │
天（时机层）  ──── 日历季节性 + 美林时钟 + 波动率周期 + 流动性周期
  │                → 判断"当前时间是否适合行动"
  │                → 微调仓位和时间窗口
  │                → 天分为负时即使道/地为正也降低仓位
  │
地（战术层）  ──── 价格位置 + 地形分类 + 量价配合 + 多框架确认
  │                → 判断"当前价格是否适合入场"
  │                → 选择具体入场点和止损位
  │                → 六种地形（通/挂/支/隘/险/远）决定策略方向
  │
将（执行层）  ──── 智信仁勇严评分卡
  │                → 判断"是否执行、仓位多大"
  │                → 仁=爱惜本金、勇=果断执行、严=硬编码纪律
  │                → 最终 position_factor + confidence_threshold
  │
法（策略层）  ──── 经典策略库（核心/卫星/应急分层）+ 策略选择器
                   → 基于道/天/地/将四维度评分选择策略
                   → 输出具体入场/出场/仓位规则
                   → 冲突解决 + 生命周期管理
```

### 与现有三层架构的映射

| 层次 | 现有架构 | 孙子五维度映射 |
|---|---|---|
| **庙算引擎（新增）** | — | 道+天+地+将+法 → 综合胜算分 → 仓位上限 + 策略选择 + "不出战"判断 |
| **前置层（已有）** | Level/Trend/Consensus → 参数映射 | 地补强（盘整时长/Follow-through/MA 距离分位/地形分类） |
| **核心层（已有）** | BCRM 2.0 方向预测 → 入场信号 | 法 → 策略选择器叠加在市态切换之上 |
| **风控层（已有+新增）** | 五角校验 + Risk Manager | 将评分卡 + **风控独立否决层**（硬编码否决） |
| **离场层（已有）** | ExitManager 策略链 | 法 → 离场策略也纳入策略选择器 |

庙算引擎的输出是**战略级参数**（仓位上限、策略选择、激进/保守基调、是否出战），不直接干预战术级决策（入场信号、止损位），而是为战术级引擎设置"作战框架"。与现有 `enable_inject` 机制和 α blend 机制完全兼容——庙算评分可以作为一个更高层的 α 信号注入。

### 最终系统五层结构

```
第一层：道 → 决定大方向
第二层：天 → 决定时间窗口
第三层：地 → 决定价格结构和入场条件
第四层：将 → 决定仓位、纪律和执行质量
第五层：法 → 决定策略库调用和风控规则
```

最终输出不是单一买卖信号，而是：
- 是否允许交易
- 允许哪类策略
- 允许多大仓位
- 是否必须止损
- 是否需要降仓
- 是否需要空仓等待

## 八、落地关键建议

1. **每个子指标都要做标准化**：不同指标量纲不同，不能直接相加。建议统一用 Z-score、分位数或 tanh 映射到 0~100。

2. **避免等权拍脑袋**：初始可以用 30/15/25/15/15，但后续必须用 IC、IR、样本外表现校准。

3. **加入否决机制**：总分高不代表一定开仓。若"道""将""法"过低，应强制降权。

4. **不要把季节性权重给太高**：日历效应容易失效，建议作为辅助因子。

5. **多时间框架比单一指标更重要**：日线突破如果周线仍然空头，信号可靠性会下降。

6. **风控必须独立于策略层**：风控不是策略的一部分，而是所有策略之上的否决层。

7. **定期复盘五维预测准确率**：每月检查：道是否预测了方向？天是否预测了节奏？地是否识别了结构？将是否守住了纪律？法是否选对了策略？

## 九、风险与注意事项

1. **过拟合风险**：季节性效应和"道"维度评分容易在回测中过拟合。建议每个维度的评分因子都做 Walk-Forward 5 折验证 + 蒙特卡洛随机排列测试（p < 0.05），且回测时只用 2020 年之前的数据训练，2020 年之后数据做样本外验证。季节性因子用滚动窗口回测验证稳定性，而非固定参数。

2. **数据源依赖**：道维度的核心是外部数据（稳定币市值/ETF 流入/CEX 储备），这些数据源的稳定性和延迟需要评估。建议设计为 fail-open（数据缺失时降级为中性评分），与现有资金调控模块的 fail-open 设计保持一致。

3. **复杂度控制**：五维度 × 每维度 3-5 个子因子 = 15-25 个新评分因子，这个规模在可管理范围内。策略库建议先收录 5-6 个经典策略，按核心/卫星/应急三层分层管理。

4. **与现有市态切换的协调**：市态切换(8 种)和五计评分不冲突——市态是"当前市场处于什么状态"，五计是"当前值不值得打、怎么打"。两者是正交关系。

5. **与现有 BCRM 2.0 的协调**：庙算引擎不替代 BCRM 2.0 的方向预测，而是在其之上做战略筛选——胜算分低的市场环境，即使 BCRM 2.0 给出高置信度信号，也可以通过降低 position_factor 上界来限制风险暴露，甚至"不出战"直接暂停开新仓。

6. **风控否决层的独立性**：风控否决层必须独立于五维度评分之外，不能被任何维度的"高分"覆盖。"先为不可胜"——风控否决是系统的最后一道防线。

7. **维度权重动态调整的风险**：权重动态调整本身也可能过拟合。建议权重调整频率不低于季度（太频繁容易追逐噪音），且调整幅度有上下限约束（单次调整 ≤ ±5%）。不建议完全交给模型自动优化，否则容易把噪声当成规律。

## 十一、周期-职责边界矩阵：前置层 × 战略层 × 策略层 × 核心 × 后置 × 离场

## 十二、模块化开关架构：总开关/子开关/影子AB/降级回退

> 解决用户关注点 1：「现有策略稳定运行，新增战略层/策略层最好具备模块化和开关，关闭时保持原有链路；通过开关验证各自表现；为 Dream OS 调度留执行空间。」
> 复用现有 4 种开关模式（进程级 bool / 运行时文件 reload / Shadow 只记录不执行 / Alpha 渐进），新增 2 总开关 + 7 子开关 + 影子 AB + 降级回退链路。

### 12.1 开关设计原则（从现有机制抽象）

1. **字节等价原则（关闭=零影响）**：任何子系统的总开关关闭时，对应分支 100% 走旧路径，**所有中间计算完全跳过**（不留任何性能损耗或日志噪音），所有中间变量用默认值（等价于改造前硬编码）。
2. **Fail-Open 优先**：新子系统（五计/策略选择器）在初始化失败、外部数据缺失、内部抛异常时，自动降级为「开关关闭」状态，**绝不阻塞或破坏原有交易链路**。与 `CapitalControlComponent`、`CBR`、`A7`、`P3` 的 fail-open 设计保持一致。
3. **多层嵌套 gating**：总开关关断后，子开关不被读取。子开关关断后，对应功能在父系统内走旁路。
4. **ShadowLogger 复用**：新增战略层和策略层的影子记录，复用已有 `ShadowLogger` 存储/查询框架（不造新轮子）。新增 `strategy_shadow_records` 表（schema v2 升级，不破坏旧表）。
5. **为 Dream OS 留口**：所有开关均可通过外部配置文件 + runtime hot reload 切换（继承 `_enable_inject_runtime` 的 300s 重加载机制），后续 Dream OS 调度器可直接写配置文件调开关，无需改代码。开关的读取、状态日志、决策归因全部结构化，便于 OS 侧观测。

### 12.2 开关总表（2 总 + 7 子 + 3 模式）

### 12.3 降级回退链路（四层保险）

```
Layer 0 (最外层，最高优先级): 进程级 CLI 参数 → 如果明确 --no-strategy-layer / --no-five-domain → 强制关断，后续所有子开关不读
         ↓
Layer 1: .env / 配置文件 enable_* → 比 CLI 优先级低
         ↓
Layer 2: 运行时配置文件热加载（300s 重加载，继承 _enable_inject_runtime 机制）→ 覆盖 Layer 0/1 的默认值
         ↓
Layer 3 (最内层，最后保险): 单组件 fail-open try/except
         • _compute_five_domain_scores() 异常 → 返回默认中性高分 {dao:70, tian:70, di:70, jiang:80, fa:75}
           → 庙算总分 = 70×0.30 + 70×0.15 + 70×0.25 + 80×0.15 + 75×0.15 = 72.75（灰区 60-74 正常，不触发不出战）
         • StrategySelector.select() 异常 → 返回 StrategySelection() 默认值
         • _apply_regime_vol_cap() 异常 → 返回原值（不收紧）
         • ExitStrategy.evaluate() 内读 exit_config 异常 → 回退 strategy_type 默认分支 → 再回退 base_threshold
         • ExitContext 缺省字段 / 历史持仓无 strategy_type → 行为 = 完全等价改造前
```

| 全开 + 子开关组合测试 | **True**（子开关逐个开/关） | **True**（子开关逐个开/关） | 可独立验证「不出战机制贡献」「差异化离场贡献」「风险预算 sizing 贡献」「聚类约束贡献」等每一项的 Alpha / 回撤改善。 | （不追求等价，追求归因） |

### 13.4 风险提示与建议

1. **冷启动默认全部 False**：战略层和策略层的总开关默认全关，先用影子模式跑 2-4 周观测数据，再逐个子开关打开 → 最后开总开关。这个顺序比「先开总开关再关子开关」更安全（默认零影响，逐步放风险）。
2. **子开关的归因报表必须先做**：在开启任何一个子开关之前，先确保 G5（exit_strategy_log schema v2 + strategy_shadow_records）落地。否则开了之后无法判断这个子开关是贡献了 alpha 还是增加了噪音。
3. **路径 B 的聚类约束（G9）建议放到路径 A 全稳定之后再开**：聚类约束是组合级的硬约束（同方向同风格总仓 cap），会显著改变组合构建方式，应在单笔级的差异化离场（路径 A）稳定后再开。用独立子开关管理。

## 十四、策略算法层定位评估：参数路由表 vs 纯校准算法层（三方案对比 + 行业范式验证 + 战略层向下校准前置层归属）

> 解决用户新架构疑问：「五计庙算（战略层）得出趋势策略，入场信号仍是核心层（BCRM 2.0），趋势策略主要影响的位置应该是持仓管理以及配套的离场参数——即根据策略标签做离场参数放大/缩小（如最低持仓时间优化），避免策略类型很多需要匹配不同离场逻辑，不便于深度研发离场；策略层因此变成算法层；前置层参数也应接受战略层优化（需评估）。对比现有 v1.2 策略层实践，如有冲突调研 GitHub/传统金融做法。」
> 审查结论：**现有 v1.2 的「参数路由表 + 三级 fallback」定位与用户「策略算法层 = 统一基准 × 校准偏置」存在 3 处架构冲突（§14.2），不符合 Turtle/CTA 行业「一套统一规则 × 波动率/标签校准系数」的标准范式。三方案对比后推荐方案 B（纯参数校准算法层）。战略层向下校准前置层 L/T 参数可行，但必须遵守「单向依赖 + fail-open + 乘法校准 + 子开关独立关断」4 条约束。**

### 14.1 两种定位的本质差异（v1.2 vs 用户新目标）

| 维度 | 现有 v1.2 方案（参数路由表模式） | 用户提出的「策略算法层」定位 |
|---|---|---|
| **策略层输出** | `exit_config` 每策略类型一张完整参数表（6 策略 × 10+ 字段，含 `timeout_skip`/`use_chandelier_exit` 等布尔开关），v1.2 `_default_exit_params(main)` 独立查表 | 输出**统一结构的校准偏置向量 `calibration_biases`**（全部数值型乘法/加法系数，共享一套基准离场参数） |
| **ExitStrategy 内部逻辑** | `exit_config → strategy_type → base` 三级 fallback（每种策略类型/每个 exit_config 可以覆盖到具体字段） | 只有一级：`最终阈值 = 基准阈值 × 校准系数`。**所有策略类型共享同一个计算公式**，不需要查表分支 |
| **离场研发聚焦点** | 分散：6 策略独立参数表 × 6 ExitStrategy 各自的 base 调优 → 360+ 组合要验证回归 | 集中：深度研发一套 ExitStrategy 的基准阈值（base_threshold），策略差异只通过校准系数体现 → 复杂度 **O(Exit 数 + 校准算法数)** 线性可扩展 |
| **strategy_type 语义** | 一肩三挑：风格权重主风格（G9）+ exit 参数路由 key（G6）+ RankedTp allow-gate（R4） | 只作为：校准算法的**分类输入特征**（以及风格权重主风格 / RankedTp allow-gate）。不再是 exit 参数路由 key |
| **G6 对照表性质** | 「核心落地的参数表」（人工调 6 套独立参数） | 「6 组校准偏置的初始 Seed」，算法层基于 regime/五计分/流动性做统一公式的二次校准，不需要为每种策略独立维护公式 |
| **新增策略类型的边际成本** | 高：新增一张完整 exit_config 参数表 + 每个 ExitStrategy 验证该表的回归 + 回测验证新组合 → 多项式增长 | 低：新增一个策略类型 seed（8 个数值初始偏置 + 1 个布尔 gate）+ 校准算法自动复用 → 线性增长 |

### 14.2 现有 v1.2 与用户新目标的 3 处架构冲突

**冲突 1：复杂度爆炸风险（用户目标 = 离场深度研发，v1.2 = 离场研发被策略类型数量绑定）**
- v1.2：6 策略 × 6 ExitStrategy × 10+ exit_config 字段 = **360+ 组合**需要人工验证或回测覆盖；如果未来策略类型扩展到 10+，组合会超过 600。改一个 SignalReverse 的 base_threshold 需要回归验证 6 策略 × 10+ exit_config 覆盖的正确性 → 离场研发（核心资产）与策略表（算法资产）强耦合，无法独立深度推进。
- 用户目标：离场策略的深度研发（比如优化 SignalReverse 的判定逻辑、新增 ExitStrategy、调整 base_threshold）应该**完全独立于策略类型数量**，只需要验证一套基准，不需要 N 套回归。

**冲突 2：exit_config 的布尔开关无法用「放大/缩小系数」表达（与「策略算法层只做参数校准」的语义冲突）**
- v1.2 的 `exit_config` 有 `timeout_skip: True`（趋势策略跳过超时）、`use_chandelier_exit: True`（趋势策略启用 Chandelier）这种**布尔开关型参数**。这两种差异不是"基准 timeout_hours × 0.3"或"基准 SL × 1.1"这种校准系数能表达的。它们本质上是「某个 ExitStrategy 是否参与该笔持仓的评估链路」的结构性 gate，不是参数缩放。如果坚持用「参数路由表」模式，就必须保留这些布尔分支 → 无法退化为纯算法校准层。
- 用户目标：策略算法层的输出应该是**统一结构的校准系数**（8~10 个数值因子 + 最多 1-2 个结构性 gate），而不是每策略独立维护布尔开关组合。

**冲突 3：前置层参数校准的归属缺口（用户新提但 v1.2 未定义）**
- v1.2 架构中战略层（五计）与前置层（MorphCyclePredictor）是完全单向解耦：战略层可选读前置层 `regime_summary` 作为"地"维度子因子，但**战略层不向下输出任何东西给前置层**。
- 用户新需求：战略层五计输出后，应该可以给前置层参数加校准（比如道=90 大牛市 → L 参数放大 1.2 倍；地=30 → T 参数收缩 0.8 倍）。v1.2 没有定义这个路径，与 §11.3 的数据流图存在缺口。

### 14.3 传统金融 + GitHub 行业范式验证（6 个证据全部支持「统一基准 × 校准系数」）

> **结论**：从 Turtle Trading 经典 CTA → 现代 CTA 机构（AHL/Man）→ RegimeSense → QuantPulse v3 → 风险平价 → MarketRegimeNet 概率校准，**成熟系统没有一个采用「每策略类型一张独立完整参数表 + 三级 fallback 查表路由」的架构**，全部采用「一套统一基准规则 × 校准系数/算法」的范式。

| 证据来源 | 核心做法 | 对我们的启示 |
|---|---|---|
| **Turtle Trading（经典 CTA 教科书方法，GitHub ferkuellar/Turtle-Trading-v2 + meepoke/Quant.Strategy）** | 一套统一规则：Donchian 20/55 突破入场、2N 止损、10/20 日高低点离场；差异化只用 **ATR N 单位统一放大/缩小**：`Unit = (1% Account) / (N × Dollars_per_point)`；所有市场所有方向共用同一套 Unit 公式 + 同一套持仓约束（4/6/10/12 单位） | ✅ 完全对应用户目标：**统一基准离场规则**（不区分趋势/突破/均值回归写多套）+ 基于**波动率/标签**的校准系数做差异化。 |
| **现代 CTA 机构（AHL/Man/Winton 行业公开架构 + brainbytes-dev Trend Following skill 文档）** | 典型三层：Unified Signal Engine（统一入场信号）+ Unified Risk Engine（统一风控校准）+ Position Sizing Overlay（统一仓位校准）。管理 50-100 个期货市场，**不是每种策略×每个市场各写一套离场参数**，所有信号共享一套离场框架，差异化通过 volatility targeting / regime coefficient / signal strength multiplier 等**统一校准函数**实现 | ✅ 印证我们的冲突分析正确性：CTA 管 100 个市场如果用查表路由复杂度爆炸，只能走**统一公式×校准系数**。 |
| **RegimeSense（moh1tt/RegimeSense，我们已借鉴 G1-G3）** | 不是「切换到某 regime 就用该 regime 的完整独立策略参数表」，而是输出 `strategy_weights = f(regime)` **权重软分配**，4 种基础策略的**统一风险暴露计算**，不维护 4×N 套独立 SL/TP/timeout 表 | ✅ 策略标签/regime 输出的是校准权重/系数，不是独立参数路由表。 |
| **QuantPulse v3（Dharit13/QuantPulse，GitHub 新调研）** | 明确声明：**"Every parameter is a function of VolContext (VIX/term structure/ATR/correlation/breadth)"**。所有参数都是「波动率上下文的函数」——一套统一 Kelly 分档 sizing 公式（quarter-Kelly → half-Kelly），然后从 rolling 100-trade window 统一重新校准，**不是每种策略一张独立 sizing/exit 参数表** | ✅ 完全对应「策略算法层 = 统一校准算法，策略标签是算法的输入特征」的定位。 |
| **风险平价（Risk Parity，CSDN 实战指南 + 行业标准）** | 统一校准算法：`RC_i = w_i × MRC_i`，目标是所有资产风险贡献相等。**不是股票/债券/商品各写一套 risk 公式**，所有资产共享同一个优化目标与同一个求解算法，不同资产的波动率/相关性只是算法的输入矩阵 | ✅ 差异化来自输入特征（不同资产的协方差），不是独立公式（对应我们：差异化来自策略标签/regime/五计分，不是独立 exit_config 查表分支）。 |

### 14.4 三方案对比 + 推荐（方案 B 纯校准算法层）

| 方案 | 描述 | 优点 | 缺点 | 与用户目标匹配度 |
|---|---|---|---|---|
| **A：保留 v1.2 参数路由表** | `exit_config` 每策略独立完整参数表 + ExitStrategy 三级 fallback + G6 6×10+ 参数表人工调优 | v1.2 详细设计已完成，代码落地路径清晰；与 R1-R7/G1-G10 兼容性无需重新验证 | 3 处架构冲突不解决：① 离场研发复杂度 360+ 组合爆炸，与策略类型数绑定；② exit_config 布尔开关无法简化为校准系数；③ 前置层校准归属缺口仍存在 | ⚠️ **低**：与用户「策略算法层 = 便于离场深度研发 + 参数校准驱动」的核心目标存在结构性冲突 |
| **✅ B：纯参数校准算法层（推荐）** | ① 重命名 StrategySelector → **StrategyAlgorithmLayer**，不再输出 exit_config 查表，改为输出**统一结构 calibration_biases**（8 数值乘法系数 + 1 Chandelier gate）；② 每个 ExitStrategy 只有一套 `BASE_THRESHOLDS`（核心深度研发资产），最终阈值 = `base × calibration_biases.xxx_factor`，无三级 fallback；③ G6 退化为 6 组校准 Seed（算法初始偏置），算法层基于 regime/五计分/流动性用**统一公式做二次校准**；④ 新增战略层向下输出的 `front_layer_calibration`（L_factor、T_factor、sector_factor），归属约束见 §14.5 | ① **100% 匹配用户三大目标**：离场深度研发解耦（O(Exit) 线性）、策略层变成真正的算法层（统一校准算法）、支持战略层校准前置层；② **完全符合 Turtle/CTA/RegimeSense/QuantPulse/风险平价 6 大行业范式**；③ 复用已有 R1-R7 红线、开关架构（2总+7子+3模式）、G1-G3 权重向量、G2 风险预算 sizing、G5 归因、G7 Chandelier、G9 聚类，不需要推翻已有的模块设计；④ 策略类型增加只需补一个 seed，复杂度线性可扩展 | 需对 v1.2 的 StrategySelection 输出结构和 ExitStrategy 的阈值计算公式做一次结构性重写（不是新增代码，是改造结构），但工作量可控（核心是把参数路由表替换成校准算法，不新增组件） | ⭐⭐⭐ **高（完美匹配）** |
| **C：混合过渡** | 短期：保留 v1.2 exit_config 查表，但标注 G6 为「Seed 表」；中期：ExitStrategy 内部统一新增「校准系数层」= exit_config 查表值 × calibration_biases；长期：完全废除 exit_config 查表只留校准算法 | 平滑过渡：v1.2 代码框架可快速上线影子 AB，不需要立刻重构 | 过渡期存在两套逻辑（查表 + 校准）并存，维护成本暂时升高，归因时难以判断贡献来自 seed 还是校准算法 | ⭐⭐ 中（过渡可行，但长期应迁移到 B） |

### 14.5 战略层向下校准前置层参数的归属约束（★ 历史备选方案 A，**不推荐**，推荐见 §15 弹性约束闸门方案 B）

> **[标注：历史备选方案 A（不推荐）]** 本节为 v1.3 阶段评估的「精确乘法校准」方案（L_factor/T_factor 乘法系数 ±30% 封顶）。在用户提出「大周期-中周期-小周期弹性约束」的架构洞察后（见 §15 前言），经桥水 Dalio PMPT / AQR / 国泰海通 / QuantKernel / RegimeAwareML / 人大双层决策 **6 大行业范式全部反对**，已明确标记为历史备选，**不作为默认落地方案**。默认推荐方案请直接跳转到 **§15「弹性约束闸门 + 偏差带宽 clip」方案 B**。
>
> 本节保留的唯一意义：作为基线对比参考，可用于方案 B 回测时的 shadow 对照基线；或作为极端罕见场景下的「硬校准」应急手段（需投资委员会级审批，不纳入日常自动化链路）。
>
> **v1.3 阶段原评估结论**（历史归档，不代表当前推荐）：可行，但必须遵守 4 条红线约束，避免破坏 §11.2 定义的「前置层不依赖战略层」原则。

**归属定义**：
- 战略层新增输出：`front_layer_calibration: {L_factor, T_factor, sector_weights_factor}`（均为乘法系数，默认 1.0 = 无校准）
- 前置层 ParameterMapper 的 **L_effective / T_effective / 板块权重** 计算末尾，做 `× front_layer_calibration.xxx_factor`
- **方向严格单向**：战略层 → 向下输出校准系数给前置层；前置层**绝对不能向上依赖**战略层的任何输出做内部计算（FFT/Hermite/贝叶斯校正/三轨修正 100% 纯自洽，不读五计分或 war_state）

**4 条红线约束**：
| 编号 | 约束内容 | 原因 |
|---|---|---|
| F1 | **默认全 1.0，fail-open**：`enable_five_domain=false` 或五计抛异常 → `front_layer_calibration` 全 1.0 → 前置层字节等价「无校准」纯自洽路径 | 保证战略层关断/故障时，前置层完全不受影响（与 §12 字节等价关断原则一致） |
| F2 | **只能做乘法校准，不能做加法或覆盖原值**：`L_effective = reactive_L × α + forecast_L × (1-α) × L_factor`。禁止 `L_effective = L_factor（直接覆盖）` 或 `+ 偏移量` | 乘法校准保证相对比例不变；加法/覆盖会破坏前置层的形态预测语义（L/T 是分位评分，量纲敏感） |
| F3 | **校准幅度上下限**：`L_factor / T_factor ∈ [0.70, 1.30]`（±30% 封顶）；`sector_weights_factor ∈ [0.80, 1.20]`（±20% 封顶）。单次迭代因子漂移 ≤ 0.05 | 避免战略层低分/高分极端值导致前置层输出跳变太大，影响 BCRM 2.0 推理特征稳定性 |
| F4 | **独立子开关 `enable_five_domain_front_layer_calibration`**：默认 False（冷启动保守）；可独立关断，不影响战略层的不出战/仓位 cap/策略 mask 等其他子功能 | 与 §12 开关架构的细粒度关断原则一致，战略层校准前置层可以单独灰度上线，不绑定五计总分的其他机制 |

**典型校准规则示例（初始）**：
- 道 ≥ 80 且 地 ≥ 75（政策+资金+市场结构三击） → `L_factor=1.15, T_factor=1.10, sector_factor=1.10`（小幅放大 L/T 评分与板块权重的影响）
- 天 < 40（季节性极差，如圣诞前 1 周） → `L_factor=0.85, T_factor=0.85, sector_factor=0.90`（小幅削弱，降低前置层预测对核心推理的干扰）
- 道 < 40 或 将 < 40 → `L_factor=0.75, T_factor=0.75, sector_factor=0.80`（最多 30% 封顶收紧）
- 总分 < 60 不出战期间 → 前置层校准不生效（因为直接被不出战闸门跳过，不需要特殊处理）

**对 §11.3 数据流总览图的更新（战略层向下加一条校准箭头，其他不变）**：

```
战略层（五计庙算） enable_five_domain
    → five_scores + war_state + position_cap + style_mask + cross_asset_multiplier
    → 【NEW】front_layer_calibration (L_factor, T_factor, sector_factor)
                    ↓ F4 子开关 gate + F1 fail-open + F2 乘法 + F3 上下限
前置层（MorphCyclePredictor）  enable_inject_runtime
    → L / T / 板块权重 × calibration_factors  → 注入核心层（其余不变）
```

## 十五、战略层-前置层-核心层 大-中-小周期关系校正：从精确乘法校准到弹性约束闸门

> **响应用户核心架构洞察**：「五计庙算（战略层）——前置层（市场形态层）——核心层（BCRM 2.0 信号层）三者关系类似**大周期-中周期-小周期**，不是严格映射，而是弹性约束。战略层充当开关约束（不开战/选策略），视野更大更宏观，不应该精确对齐前置层参数公式。」
> **审查结论**：**§14.5 设计的「战略层→前置层 L_factor/T_factor 精确乘法校准（±30% 封顶）」（方案 A）违反桥水 Dalio PMPT、AQR、国泰海通 SAA/TAA、QuantKernel、RegimeAwareML、人大层次化决策 6 大行业分层范式，**存在「宏观层改中观层公式参数」的越位问题。推荐升级为方案 B（弹性约束闸门 + 偏差带宽 clip）：战略层只做 3 件事（veto 闸门/偏差带宽/策略 mask），绝不修改前置层形态学的内部计算公式参数。

### 15.1 行业范式映射：三层对应的金融标准做法

用户提出的「大周期-中周期-小周期」分层完全对应传统资管行业的 **SAA（战略资产配置）/TAA（战术资产配置）/Alpha（选股择时）** 三层标准架构，以及 Dalio PMPT 的 **Beta（宏观）/Beta（中观因子）/Alpha** 三层严格分离原则：

| 用户提出分层 | 时间粒度 | 传统金融映射 | 行业标准职责（只做这几件事） | 我们系统对应层级 |
|---|---|---|---|---|
| **大周期（战略层）** | 周级「道」/日级「天」/月级「地」宏观判断 | **SAA 战略资产配置**（5-10 年基准）+ **TAA 战术叠加层**（周到年，±5-15% 偏离带宽治理） | ① 大类资产/策略族基准权重；② 总风险预算 cap；③ 「不开战」veto 闸门；④ 允许策略族白名单 mask；⑤ **偏差带宽（允许偏离范围），不是精确乘系数改因子公式** | ✅ 战略层（五计） |
| **中周期（前置层）** | 4y 大周期 / 120d 小周期 / 20d forecast（形态学） | **TAA 因子层**（风格因子/宏观因子/形态学因子）+ 风险平价的因子暴露计算 | ① 因子计算公式完全自洽（FFT/Hermite/贝叶斯校正/三轨修正）；② 在 SAA 给的**偏差带宽内**自主优化权重/参数；③ 输出因子评分 → 注入下游；**绝不能被 SAA 乘法系数改公式内部参数** | ✅ 前置层（MorphCyclePredictor + ParameterMapper） |
| **小周期（核心层）** | 5min 轮询，ML 信号推理 | **Alpha 层**（选股/择时/事件驱动） | ① 具体币种方向预测；② 完全独立推理特征工程，只受上游「不开战」闸门和仓位 cap 约束；③ 策略内部的 SL/TP/入场公式完全自洽，不被上层改参数 | ✅ 核心层（BCRM 2.0 + 弹簧力场兜底） |

### 15.2 6 大行业证据全部反对「精确乘法校准」，支持「弹性约束闸门」

#### 证据 1：桥水 Dalio PMPT 三大分离原则（Dalio 2010《Engineering Targeted Returns & Risks》）
- **核心原则**：无风险回报 / Beta（市场回报）/ Alpha（超额回报）**三大来源严格拆开管理，互不修改公式**。Beta 层（战略层判断经济四象限）只给每个象限的子组合风险权重基准，不修改 Beta 子组合内部的久期/凸性/杠杆计算公式。
- **对我们的映射**：五计（经济大周期判断四象限）= Beta 层的风险权重基准；前置层的 L/T 形态学参数 = Beta 子组合内部的因子暴露计算。**战略层不应该乘 L_factor 改 L/T**，正如 Dalio 不修改久期公式的系数。

#### 证据 2：国泰海通 SAA/TAA 分层偏差带宽治理（§4.1 调研，gelonghui 5944686）
- **SAA 层的角色**：5 年长期基准，给出大类资产目标权重（如 60% 股票 / 30% 债券 / 10% 商品）。
- **TAA 层的角色**：周到年做阶段性偏离，但**偏差有硬上限（Deviation Limits，±5-15%）**，且必须通过投资委员会审批（对应我们的「滞回+冷却」机制）。
- **关键红线**：SAA 层**不修改 TAA 层内部的估值/动量因子计算公式**，只给允许偏离的带宽，TAA 层在带宽内自主判断具体调多少。

#### 证据 3：AQR Style Premia 四因子带宽治理（Cliff Asness，QSPRX 基金架构）
- **AQR 架构**：战略层只给 Value / Momentum / Carry / Defensive 四因子的**配置比例区间（20-40%、40-60%、20-30%）**，不修改每个因子内部的信号计算公式——Value 因子内部怎么算 PB/PER、动量因子内部怎么算 12-1 月收益率，**完全是因子层自主**。
- **对应我们**：五计层只给 trend_follow / breakout / mean_revert 等策略族的**允许仓位范围和 mask**，不修改前置层内部 FFT/Hermite 的 L/T 参数公式。

#### 证据 4：QuantKernel v6.2 RegimeGate 做法（quantkernel.io 官网，2026 v6.2）
- **宏观闸门（FinBERT + VIX）的角色**：「VIX > 28 或 macro sentiment 负面时，**把整个 watchlist 切换到防御板块（XLP/XLU/GLD）**」——是 watchlist 切换（策略 mask），不是修改 Trend Tracker AI 内部 Donchian 通道的 σ5/σ30 波动率比例参数。
- **对应我们**：五计「不出战」= 跳过所有币（veto 闸门），五计「地差+极差」= 只允许防御性空仓/对冲策略（mask），**绝不乘以一个系数去改前置层的 forecast_T**。

#### 证据 5：Regime-Aware-ML-Trading-System（SamarthGautam1，GitHub 2026）
- **Regime Detection 的唯一角色**：「用 rolling linear regression slope + R² 做**strategy gating**——市场结构支持策略假设时才允许开策略，否则关掉」，**完全不修改 backtest 引擎的 feature engineering、LightGBM 模型参数、SL/TP 倍数公式**。
- **对应我们**：五计的 regime 消费（「地」维度）只做「不允许某类策略/不开战」的 gating，不做形态学参数校准的乘法系数。

#### 证据 6：人大层次化双层决策架构实现（经管之家论文 16386417，2025-12）
- **宏观层输出**：`expansion/stagflation/recession/recovery` 四状态的**行业基准权重表**（如 expansion 下 cyclical 0.4 / growth 0.3 / defensive 0.2 / cash 0.1）。
- **微观层做什么**：GARCH-MIDAS 波动率估计后，只做**局部仓位优化 = 权重 × adjustment_factor**，而调整因子是 **`1 / (1 + risk_contribution)`（只 clip 到带宽内，不被宏观层乘一个外部系数）**。
- **两层融合**：贝叶斯概率融合分配置信权重，**宏观层不修改微观层 GARCH 的 p/q 参数、MIDAS window size**。

### 15.4 方案 B（弹性约束闸门）的代码落位设计（最小改动，零 breaking-change）

**战略层新增输出结构（替代 §14.5 的 front_layer_calibration）**：

```yaml

  L_min: 0.40                 # L_effective 允许下限（战略层低分收紧）
  L_max: 0.90                 # L_effective 允许上限（战略层高分放宽）

  T_max: 0.90                 # T_effective 允许上限

  sector_weights_max: 1.20    # 每个板块权重 × 允许放大倍数（max）
```

**战略层带宽映射规则（初始 seed，与 §14.5 F3 量级对齐但语义从「乘法」变「clip 范围」）**：

| 总分 60–74（低仓位防御） | [0.45, 0.85] | [0.45, 0.85] | [0.85, 1.15] | 中带宽，防御性收紧上限 |
| 总分 < 60（不出战） | （直接被 war_state veto 跳过，不需要带宽） | — | — | veto 闸门比带宽更高效 |
| 道 ≥ 80 且 地 ≥ 75（三击） | [0.55, 0.98] | [0.55, 0.98] | [0.90, 1.20] | 最宽：战略层高度信任前置层形态判断 |
| 道 < 40 或 将 < 40（否决） | [0.35, 0.70] | [0.35, 0.70] | [0.80, 1.10] | 最严带宽：前置层形态判断被宏观硬约束压在安全区 |
| 天 < 40（极差季节性） | [0.40, 0.80] | [0.40, 0.80] | [0.80, 1.10] | 季节性差时收紧带宽，防止前置层形态误判放大 |

**前置层消费逻辑（ParameterMapper 末尾加 6 行 clip，不影响任何内部计算）**：

```python
# ParameterMapper 内部：FFT/Hermite/贝叶斯校正/三轨修正 → 100% 自洽计算不变
L_raw = reactive_L * alpha + forecast_L * (1 - alpha)   # 现有逻辑（不改）
T_raw = reactive_T * alpha + forecast_T * (1 - alpha)   # 现有逻辑（不改）
sector_raw = compute_sector_weights(...)                # 现有逻辑（不改）

# ★ 新增：战略层带宽 clip（只有 6 行，front_layer_band=None 时等价不做任何事）
if front_layer_band:
    L_final = float(np.clip(L_raw, 
        front_layer_band.get('L_min', 0.0), 
        front_layer_band.get('L_max', 1.0)))
    T_final = float(np.clip(T_raw,
        front_layer_band.get('T_min', 0.0),
        front_layer_band.get('T_max', 1.0)))
    sector_final = [float(np.clip(w * s,          # 注意：sector 是倍数带宽（[min,max]不是绝对范围）
        w * front_layer_band.get('sector_weights_min', 0.0),
        w * front_layer_band.get('sector_weights_max', 2.0)))
        for w, s in zip(sector_raw, [1]*len(sector_raw))]
else:
    L_final, T_final, sector_final = L_raw, T_raw, sector_raw
```

## 十、总结

这套框架的核心不是"预测涨跌"，而是把投资决策变成五个问题：

- **方向是否清楚**（道）
- **时间是否合适**（天）
- **结构是否支持**（地）
- **纪律是否到位**（将）
- **策略是否匹配**（法）

如果五个问题都能得到数据支持，才提高仓位；否则宁可少做、慢做、不做。

**"胜兵先胜而后求战，败兵先战而后求胜"——胜负在交易之前就已经决定了，系统做的只是执行预先计算好的最优决策。**

> **本章节定位**：响应用户"战略层是否可以引入在线学习、根据历史决策反馈实现进化"的调研需求，通过检索 GitHub 成熟开源项目 + 量化学术文献，评估 5 类算法对「按资产类别独立 gate + 历史决策回报闭环」这一核心需求的匹配度。输出三阶段渐进进化路径；**阶段1保持启发式硬规则不变**（不影响当前阶段1影子模式时间表），阶段2/3仅当影子数据积累充分后再按需升级；同时明确哪些复杂方案因工程代价/样本量/可解释性问题**不推荐落地**，避免过度设计。

### 16.1 战略层在线学习的"决策-反馈"闭环是什么？（先定义再选算法）

```
                    ┌──────────────────────────────────────────────────────┐
                    │  在线学习闭环（只作用于战略层，不修改前置层/核心层）  │
                    │                                                      │
  日级批处理        │  ① 决策侧：bandit选臂 = 战略层6个输出的量化版本       │
 ────────────→      │     arm_k ∈ {                                        │
                    │       0: war_state=ALLOW + mask=全T + cap=1.0        │
                    │       1: war_state=ALLOW + mask=trend禁 + cap=0.8    │
                    │       2: war_state=ALLOW + mask=均值优先 + cap=0.5   │
                    │       3: war_state=FREEZE （极端熊市/纪律崩溃）      │
                    │     }  → arm_k 个数 = 按类独立 4~8 个（每类不互通）  │
                    │                                                      │
  轮询/日级          │  ② 奖励侧：reward_cls(t) = 后验计算该类决策的效果    │
 ────────────→      │     ╔════════════════════════════════════════════╗   │
                    │     ║  reward(t,cls) =                             ║   │
                    │     ║   + 该类持仓日收益率（正贡献）               ║   │
                    │     ║   - 最大回撤惩罚（风险厌恶）                 ║   │
                    │     ║   - war_state=FREEZE时躲过的损失（避免奖励） ║   │
                    │     ║   - 切换抖动惩罚（/τ_day>3时的频繁gate切换） ║   │
                    │     ╚════════════════════════════════════════════╝   │
                    │                                                      │
                    │  ③ 更新侧：arm后验分布 ← 观察到reward后做Bayesian   │
                    │     更新（Beta分布/高斯过程/LinUCB系数）             │
                    │     + CUSUM regime change检测→重置后验→避免陈旧知识│
                    └──────────────────────────────────────────────────────┘
```

**关键约束（直接决定算法选型）**：
- **按类完全独立**：crypto_usdt / us_stock / precious_metal 三个类各跑自己的独立 bandit，参数、arm、reward 完全不共享（避免美股牛市的高分错误传导到加密熊市）。
- **样本稀少**：日级打分 + 月度效应 → 每类每月最多 20-22 个有效样本 → **必须选择小样本快收敛算法，拒绝每类需要上千样本的深度学习/PPO**。
- **fail-open + 可解释性**：任何在线学习的异常输出必须可回退到"启发式硬规则"（§15.4.1 fail-open中性值）；每步为什么选这个arm必须能被人类审计（β 后验 α/β 比 或 LinUCB 可展开的特征权重），禁止黑盒。
- **依赖最小化**：尽量用 numpy/scipy 纯实现可跑；最多允许 1 个轻量纯 Python 库（contextualbandits，可无编译安装）；禁止 PyTorch/TensorFlow/GPy 等重型依赖。

### 16.2 5 类算法候选的完整评估（匹配度 10 分制）

| 候选 | 来源 / GitHub 参考 | 核心机制 | 对我们 4 条约束的匹配度 | 适用阶段 |
|---|---|---|---|---|
| **① Thompson Sampling β-Bandit + CUSUM 重置（★ 阶段2默认推荐，9/10）** | LedgerLens-core #62 Adaptive Ensemble Reweighter | 每 arm 维护 Beta(α_k, β_k) 后验；`sample_weights()` = 从 Beta 采样再归一化 → 选最大臂；reward ∈ [0,1] → 命中 α+=reward β+=1-reward；CUSUM 对误差率时序 → regime change True → 全部 reset 到 Beta(1,1) 均匀 | **4/4全满足**：① 按类独立（三类各开一组 Beta 数组）；② 小样本（Beta 贝叶斯共轭更新冷启动极快，arm=8时每类只需10-20样本即可拉开明显α/β差距）；③ fail-open（选arm后→用§15.5.2阈值查表映射，可解释=α/β比）；④ numpy/scipy无额外依赖。唯一扣分项：reward需要clip到[0,1]尺度，略损失信息。 | **阶段2落地（影子模式跑3个月，积累60+日样本后启用，默认先用Beta(1,1)=uniform等于启发式做冷启动，阈值设80%置信度才替换启发式）** |
| **② Contextual Bandits（BootstrappedTS / LinUCB）— contextualbandits库（7/10）** | github: david-cortes-straif/contextualbandits 库（纯Python可选版，无需编译） | Contextual = 每次决策前输入特征向量 x（即五维打分+宏观特征作为context）；然后用 LogisticRegression/DecisionTree 基分类器→BootstrappedTS 采样臂；支持 `partial_fit()` 增量更新；含离线策略学习（OffsetTree、Doubly-Robust Policy Eval）可从历史影子数据先离线预训练。 | **3/4满足**：① 按类独立（三类各跑自己的BootstrappedTS对象）；② 样本中等（比纯Bandit多但比RL少，预训练后冷启动约20-40样本）；③ fail-open+解释性尚可（但不如Beta分布直观）；④ 需加1个依赖（contextualbandits纯Python版本）。扣2分：依赖引入+特征工程成本（需把五维打分+MorphPhase+macro指标拼成固定维度x向量，漂移时需维护）。 | **阶段3升级（阶段2先积累离线影子数据≥200条，用OffsetTree离线评估比纯Bandit提升≥5%才上线；否则跳过直接停留在阶段2 Beta方案）** |

### 16.4 5 条工程红线（不满足的算法直接排除，避免过度设计）

> **为什么需要红线？**：2023-2026 年 GitHub 上"量化+RL/DL"项目的存活率低于 15%（引用 Laya-Myadam QuantitativeTradingSystem 作者的事后复盘：0.5-1% alpha 在 walk-forward 外 70% 消失），根本原因是**样本量喂不饱复杂模型**+**可解释性差导致交易员不敢用**。战略层是决定"是否开战"的闸门，出错代价远高于单笔SL，所以必须极度保守。

| 红线 | 检查项 | 对应5类候选的通过率 |
|---|---|---|
| R-OL-1 | **样本量要求**：每类每决策日1样本的前提下，用≤25个样本可以实现≥启发式60%的决策质量（冷启动速度） | ①TS Beta=通过；②Contextual=通过；③HMM=勉强；④Student-t=FAIL；⑤PPO=永久FAIL |
| R-OL-2 | **无重型依赖**：除 numpy/scipy/pandas/scikit-learn（已在系统依赖中）之外，新增依赖≤1个纯Python库，无编译要求，无C扩展 | ①TS Beta=通过（0新增）；②Contextual=通过（+1纯Python）；③HMM=勉强（+1 hmmlearn）；④=FAIL（+PyMC3/ArviZ≥4）；⑤=FAIL（+torch/sb3≥5） |
| R-OL-3 | **单步可解释性**：任意一次"为什么选arm_k=FREEZE而不是arm_0"可以用≤5个数值的不等式+50字以内中文说明白（审计要求） | ①TS Beta=通过（α_0/β_0 vs α_3/β_3 采样均值 + "FREEZE臂累计胜率83% vs ALLOW 47%"一句话解释）；②Contextual=勉强（可展开LR系数表但略长）；③HMM=FAIL（隐状态标签漂移需解释6维特征偏离表）；④⑤=永久FAIL |
| R-OL-4 | **fail-open字节等价**：开关enable_five_domain_ol=False时，输出与§15.4.1启发式**完全相同**（允许内部参数继续更新但输出不生效）；更新异常/依赖缺失时自动降级到启发式 | ①TS Beta=通过（开关关断时直接跳过beta采样→走原阈值查表）；②=通过；③=勉强（HMM异常时label回退到MorphCyclePredictor.phase输出）；④⑤=FAIL（概率编程框架抛错通常直接进程崩溃，降级链路难写） |
| R-OL-5 | **regime change稳健**：4y大周期切换（牛→熊→复苏）、黑天鹅（法<40纪律崩溃）后模型能在≤7个决策日恢复，不使用陈旧知识 | ①TS Beta + CUSUM=通过（CUSUM触发→7日内reset到Beta(1,1)均匀→冷启动重新学习）；②+ regime change detector=通过；③=勉强（HMM本身做regime，但label漂移需重新对齐）；④⑤=FAIL（层次先验和神经网络权重重置成本极高） |

### 16.5 对阶段1实施计划的零修改承诺

本节调研结论**不会改变阶段1（最小影子模式）的任何落位**，仅作为未来6-12个月的预研储备。阶段1 five_domain_scorer._apply_decision_rules() 中，预留两个结构化字段即可（不改任何逻辑，只加日志）：

```python
# five_domain_scorer.py （阶段1只记录，不做OL更新）
class DecisionAuditRecord:
    heuristic_arm_id: int           # §15.5.2查表映射到的arm编号（0-7）
    ol_arm_id: Optional[int] = None # 阶段2/3在线学习选的arm（阶段1=None）
    arm_reward_parts: Dict[str, float]  # reward = 持仓收益 - 回撤惩罚 + FREEZE躲过损失 - 切换惩罚（拆分为5项便于事后离线分析）
```

**离线预训练窗口**：影子模式跑满第3个月后，用已记录的arm_reward_parts直接做一次**离线评估脚本**：对"如果当时用TS Beta-Bandit，α/β序列会如何演化，reward累计是否超过启发式"做反事实模拟，输出《战略层在线学习可行性报告v0.1》→ 过了≥5%提升门槛才启动阶段2代码落地；否则无限期停留在阶段1启发式，不引入任何在线学习复杂度。
