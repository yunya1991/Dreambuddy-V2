## 2. 评估标准

| 约束 | 值 | 依据 |
|---|---|---|
| 语言 | `Python` / `TypeScript` | 现有分析器仅支持这两种（Go/Java/C++/C# 无分析器） |
| stars 下限 | **300** | 低于此视为小仓/玩具项目，不进主清单 |
| 许可证 | MIT / Apache-2.0 / BSD-2/3-Clause / ISC / MPL-2.0 | GPL/LGPL 只读不注入 |
| 归档仓库 | `archived=true` → 直接 reject | 不再维护 |
| 存在性 | GitHub API 200 | 404 = 转述名误匹配 |

分级定义：

| level | 判据 | 处置 |
|---|---|---|
| `qualified` | 语言 ✅ + 许可 ✅ + stars ≥ 300 | 写入主清单（`wave=4`、`priority=P3`、`verified=true`），允许注入 |
| `candidate` | 语言 ✅ + 许可 ✅ + stars < 300 | 留在 inbox，不进主清单 |
| `reject` | 语言 ❌ / 许可 ❌ / archived / 404 | 记入报告，不入库 |

## 4. 一次性注入方案

| 项 | 方案 |
|---|---|
| 执行体 | `scripts/oneshot_inbox_ingest.py` |
| 顺序 | ① 内存门禁 → ② 逐条 GitHub API → ③ 分级 → ④ 合并主清单（原子替换） → ⑤ 分批注入 |
| 批次 | 每批 1 条，批间二次内存检查（并发固定 1，避免峰值叠加） |
| 上限 | 单次注入 `--inject-max 5`；若 qualified > 5，分批续跑（每批独立门禁） |
| 幂等 | 注入前按 `source_label` 跳过池中已有树；主清单按 `location` upsert |
| 内存门禁 | `MemAvailable < 800MB` → 写 `reports/ALERT_mem_<ts>.json` + **exit 3 暂停**，主清单不改 |
| 失败策略 | 单条 API 失败记 `repo_not_found` 不阻断；注入失败记 `errors` 保留已完成部分 |
| 报告 | `reflection_data/reports/oneshot_ingest_2026-11-01.json` |
