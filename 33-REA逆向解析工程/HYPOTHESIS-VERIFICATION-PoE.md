## 假设 H1：poe_score 权重 w1=0.4 是否最优

### 1.1 假设陈述

> **H1**: 在 poe_score 计算公式中，evidence_chain_score 的权重 w1=0.4 是最优配置，能使 poe_score 与"代码实际可维护性"的相关性最高。

**当前公式**：
```
poe_score = 0.4*evidence_chain_score + 0.25*coverage_score + 0.2*(1-complexity_penalty) + 0.15*layer_bonus
```

### 1.2 可证伪性检验

**可证伪性**: ✅ 可证伪

**反驳条件**（满足任一即推翻 H1）：
1. 存在权重配置 w'，使 poe_score(w') 与人工标注的代码质量评分的 Pearson 相关系数显著高于 w1=0.4（p<0.05，配对 t-test）
2. w1=0.4 时，poe_score 对"高证据链但低覆盖率"的代码给出过高分数（>0.8），而人工标注为"不可维护"
3. w1=0.4 时，poe_score 对"低证据链但高覆盖率"的代码给出过低分数（<0.5），而人工标注为"可维护"

### 1.3 消融实验设计

#### 实验目的
验证 evidence_chain_score（w1）对 poe_score 区分"好/坏代码"能力的贡献度。

#### 实验组与控制组

| 组 | 配置 | 目的 |
|---|---|---|
| 完整组 | w1=0.4, w2=0.25, w3=0.2, w4=0.15 | 基准 |
| 消融A | w1=0.0, 其余归一化 | 移除 Evidence 层 |
| 消融B | w1=0.2, 其余归一化 | 降低 Evidence 权重 |
| 消融C | w1=0.6, 其余归一化 | 提高 Evidence 权重 |
| 消融D | 均匀权重 0.25×4 | 无偏好配置 |

#### 控制变量
- 相同的 AI 产出样本集（N≥100）
- 相同的人工标注（可维护性 1-5 分）
- 相同的 evidence_chain_score / coverage_score / complexity_penalty / layer_bonus 计算方式

#### 主要指标
- poe_score 与人工标注的 Pearson 相关系数 r
- 区分好/坏代码的 AUC（以人工标注≥4 为正例）

### 1.4 敏感性分析

对 w1 进行网格扫描（步长 0.05），固定其余权重归一化：

```
w1 ∈ {0.1, 0.15, 0.2, 0.25, 0.3, 0.35, 0.4, 0.45, 0.5, 0.55, 0.6, 0.65, 0.7}
```

记录每个 w1 下的：
- 相关性 r(w1)
- AUC(w1)
- 评分稳定性（变异系数 CV）

**预期曲线**：r(w1) 应呈倒 U 型，峰值在 w1∈[0.35, 0.5]。若峰值远离此区间，说明 w1=0.4 非最优。

### 1.5 推理初步判断

**支持 w1=0.4 的论据**：
- Evidence 层是 PoE 的核心（类比区块链的工作量证明），权重应最高
- 覆盖率和复杂度是辅助指标，权重应低于 Evidence
- layer_bonus 是激励项，权重应最低

**潜在反驳论据**：
- 若 AI 产出普遍证据链弱但代码实际可用，w1=0.4 会导致大量误拒
- 若 evidence_chain_score 本身计算不准（如 REA 分析器有 bug），高权重会放大误差

**初步结论**：w1=0.4 在 [0.35, 0.45] 区间内合理，但是否"最优"需数据验证。建议先以 w1=0.4 上线，收集 N≥100 样本后做敏感性分析回归。

### 1.6 结论边界

- **时间边界**：需在 REA 审计模块上线后收集至少 2 周数据
- **样本边界**：N≥100，覆盖不同 Agent、不同代码类型
- **参数边界**：w1 最优值可能在 [0.3, 0.5] 区间内
- **外推风险**：不同项目（交易系统 vs Web 应用）的最优权重可能不同

## 假设 H2：门禁阈值 0.8 是否合理

### 2.1 假设陈述

> **H2**: poe_score ≥ 0.8 作为 PASS（自动合入）阈值是合理的，能在"漏检坏代码"和"误拒好代码"之间取得最优平衡。

### 2.2 可证伪性检验

**可证伪性**: ✅ 可证伪

**反驳条件**（满足任一即推翻 H2）：
1. 阈值 0.8 的 F1 分数显著低于其他阈值（如 0.7 或 0.85）（p<0.05，bootstrap 配对检验）
2. 阈值 0.8 的误拒率（好代码被打回）> 30%，导致开发效率严重下降
3. 阈值 0.8 的误通过率（坏代码通过）> 10%，导致质量问题逃逸

### 2.3 对照实验设计

#### 实验目的
找到使 F1 分数最大化的 PASS 阈值。

#### 实验组

对阈值 T ∈ {0.6, 0.65, 0.7, 0.75, 0.8, 0.85, 0.9, 0.95} 分别计算：

| 指标 | 定义 |
|---|---|
| 精确率 Precision | TP / (TP + FP) — 通过的代码中实际好代码的比例 |
| 召回率 Recall | TP / (TP + FN) — 好代码中被通过的比例 |
| F1 | 2·P·R / (P+R) |
| 误拒率 FPR | FP / (FP + TN) — 好代码被打回的比例 |
| 误通过率 FNR | FN / (FN + TP) — 坏代码通过的比例 |

#### 控制变量
- 相同的 AI 产出样本集（N≥100，其中好代码:坏代码 ≈ 1:1）
- 相同的人工标注（好/坏二分类）
- 相同的 poe_score 计算方式

#### ROC 分析
绘制 ROC 曲线（FPR vs TPR），找到 AUC 最大点对应的阈值。

### 2.4 损益加权分析

门禁阈值的选择本质是**成本权衡**：

| 错误类型 | 成本 | 说明 |
|---|---|---|
| 误通过（坏代码合入） | 高 | 技术债累积、生产事故、认知债务 |
| 误拒绝（好代码打回） | 中 | 开发效率下降、Agent 挫败感 |

**加权 F1**：
```
weighted_F1 = (1+β²)·P·R / (β²·P + R)
其中 β = cost(误通过) / cost(误拒绝)
```

若 β=2（误通过成本是误拒绝的 2 倍），则更倾向高阈值（保守）。

### 2.5 推理初步判断

**支持阈值 0.8 的论据**：
- 类比区块链：区块验证应严格，宁拒勿放
- AI 编码的误通过成本远高于误拒绝（技术债难偿还）
- 0.8 是"优秀"门槛，保证自动合入的代码有充分证明链

**潜在反驳论据**：
- AI 产出初期普遍证据链弱，0.8 可能导致大部分产出被打回，降低自动化效率
- 若 evidence_chain_score 计算偏严，0.8 可能过高

**初步结论**：阈值 0.8 偏保守但合理。建议：
- 初期采用 0.75（略宽松，鼓励自动化）
- 收集数据后做 ROC 分析，根据 β（成本比）调整
- 若误通过率 > 10%，提高到 0.85；若误拒率 > 30%，降低到 0.7

### 2.6 结论边界

- **时间边界**：需在 REA 审计模块上线后收集至少 2 周数据
- **样本边界**：N≥100，好/坏代码各 ≥ 50
- **参数边界**：最优阈值可能在 [0.7, 0.85] 区间内
- **外推风险**：不同安全等级的项目（交易系统 vs 内部工具）最优阈值不同

4. **特征提取**：对每个样本跑 REA 审计，提取 evidence_chain_score / coverage_score / complexity_penalty / layer_bonus

### 验证脚本设计

```python
# 伪代码：H1 消融实验
def ablation_experiment(samples, weights_config):
    scores = [compute_poe_score(s, weights_config) for s in samples]
    labels = [s['maintainability'] for s in samples]
    r = pearsonr(scores, labels)
    auc = roc_auc_score(labels >= 4, scores)
    return r, auc

# H2 ROC 分析
def threshold_analysis(samples, thresholds):
    results = {}
    for T in thresholds:
        preds = [s['poe_score'] >= T for s in samples]
        labels = [s['is_good'] for s in samples]
        results[T] = {
            'precision': precision_score(labels, preds),
            'recall': recall_score(labels, preds),
            'f1': f1_score(labels, preds),
        }
    return results
```

### 统计检验合规性

#### 样本量计算（Power Analysis）

```
预期效应量 Cohen's d = 0.5（中等效应）
显著性水平 α = 0.05
统计功效 power = 0.8
双侧检验

所需样本量（每组）: N ≈ 64
（来源: G*Power 3.1, t-test, d=0.5, α=0.05, power=0.8）
```

实际取 N≥100（每假设），留有余量应对标注质量不均。

#### 多重比较校正

消融实验比较 5 组配置（完整 + 4 个消融组），需进行多重比较校正：

```
校正方法: Bonferroni 校正
校正后 α = 0.05 / 5 = 0.01

判定规则:
- 原始 p < 0.01 → 统计显著（*）
- 原始 p < 0.002 → 高度显著（**）
```

敏感性分析扫描 13 个 w1 值，采用 FDR（Benjamini-Hochberg）校正而非 Bonferroni（更宽松，适合探索性分析）。

#### 正态性检验与非参数备选

```python
# 1. 正态性检验（Shapiro-Wilk）
stat, p_normal = shapiro(scores)
if p_normal > 0.05:
    # 正态分布 → 使用配对 t-test
    t_stat, p_value = ttest_rel(scores_a, scores_b)
else:
    # 非正态 → 使用 Wilcoxon 符号秩检验
    w_stat, p_value = wilcoxon(scores_a, scores_b)
```

效应量报告：
- t-test → Cohen's d
- Wilcoxon → r = Z / √N
