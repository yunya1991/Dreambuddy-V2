## 三、冲突项(6 条,必须开工前修订)

### B1【高·行为】FAIL-OPEN 与「禁止伪装无结果」互斥

| 文档 | 现表述 |
|---|---|
| 35 §5 C2 | 认知 MCP 不可用 → 调用方返回空 `[]` 并继续(FAIL-OPEN) |
| 44 §3.1 组件③ | `unified_search` 全后端不可用时 **必须显式"全降级"错误码,禁止用 FAIL-OPEN 把故障伪装成"无结果"** |
| 47 §3.2 | 信封含 `error_code` 六值,`ok=true & data=None ≠ 错误` |
| SSoT H2(现行) | `degraded(reason)` 自由文本 + "MCP error/timeout ≠ degraded" |

**问题**:同一通道,三份文档给出三种失败语义。**主功能查询若沿用 35 的 FAIL-OPEN,会把"云端断了"显示成"无数据"**——这是最危险的静默错误,且与 44 硬规则直接冲突。

**修订要求(建议定稿口径)**:

| 场景 | 语义 |
|---|---|
| 增强型能力(recall 经验先验、投机预取) | 可 FAIL-OPEN 返回 `[]`,但 **meta 标 `degraded=true`** |
| 主功能(统一检索、数据查询、评测裁决) | **禁止 FAIL-OPEN**;不可用必须 `ok=false + error_code=unavailable` |
| 壳进程崩溃/超时 | 宿主侧兜底,但必须打 `degraded` + `error_code`;不得等同于"无结果" |
| 源可达无数据 | `ok=true + data=None`(唯一合法的"空") |

**改动**:35 §5 C2 拆为 C2a/C2b;SSoT H2 改 `degraded(reason)` 为 `degraded + error_code`(六值枚举,与 44 同源);47 §3.2 补"主功能禁 FAIL-OPEN"一句。

### B2【高·架构】认知写主体未定义 → settle 可能静默失败

- 47 D5 规定认知壳 **本地只读降级**(写工具本地禁用);P0④ 写默认禁。
- 46 DESIGN ADR-6 规定 **Worker 不自证**、验收外置;ADR-2 规定状态单一事实源。
- **但两套文档都没有回答:settle 的写操作由谁发起?**

若按"Worker 使用本地只读壳"推演,DSH 升级的 settle(G 层回写五系统)将**必然失败或被静默跳过**。这是 D5 与 46 闭环的直接矛盾。

**修订要求(建议定稿口径)**:引入**主体×权限矩阵**,并明确 settle 不许 Worker 执行。

| 主体 | read | write(record/verify/distill) | admin(migrate/sync) |
|---|---|---|---|
| Worker(DSH 会话) | ✅ 能力集内 | ❌ | ❌ |
| Router / Settle 节点(编排侧) | ✅ | ✅ 受 Mandate 约束 | ❌ |
| Verifier / 45 门禁 | ✅ | ✅ 仅记录裁决结果 | ❌ |
| 运维 CLI / CI | — | — | ✅ |

**改动**:46 DESIGN 增 ADR「写主体与 settle 归属」;47 §3.3 明确"Mandate 授予对象是编排侧,不是 Worker";35 §5 补 principal 字段。

### B3【高·容量】壳进程 × Worker 拓扑 → 连接数未闭合

- 47 §3.1 正确指出 **1 宿主 = 1 壳进程 = N×DB 连接**,并把治理下沉 19-DAL;
- **实证:19-DAL 当前无连接上限实现**(`grep max_conn/pool_size/连接上限` 0 命中);
- 46 目标为 **≥3 Ticket 并行**。

**结论**:P1 数据 MCP 一旦上多 Worker,**无上限的连接会成倍放大**;而 47 又禁止壳内自建连接池,治理是无处落地的。

**修订要求**:把"19-DAL 连接上限"升为 **P1 的开工前置**(不是 P1 内含项);P0 阶段先限制 1 Worker 试点规避。或明确 DSH 宿主内**按域共享单壳实例**(见 G2),把 N 降到 1。

### B4【中高·治理】能力集矩阵双重 ownership

- 46 DESIGN P0① 与 47 P0① 都交付"能力集设计"。
- 若两边各写一份,开工必然撞车。

**修订要求**:单一 owner + 单一载体。
- **46** 定「Worker 角色清单」与「角色→能力标签」;
- **47** 定「能力标签→工具集」,落 `47-MCP管理系统/registry/mcp_capabilities.yaml`;
- 46 DESIGN ADR-4 只引用该 yaml,**不再自建矩阵**。

### B5【中·术语】「45 门禁」与「45 契约评测」撞名

- 46 P2 的 **45 门禁** = 业务验收门禁(产出能否沉淀/上线);
- 47 P3 的 **45 契约评测** = MCP 壳的 schema 兼容性与 FAIL-OPEN 回归。

同名不同义,开工时极易混为一件事。

**修订要求**:46 统一称「45 业务门禁」,47 统一称「45 MCP 契约评测」;45 号域 SPEC 登记为两个独立评测维度。

### B6【中·状态】异步 job 状态与「状态单一事实源」的措辞冲突

- SSoT §1.8 / 46 ADR-2:状态单一事实源 = L0,禁止第二套权威状态;
- 47 §3.2:评测 job 落 45 PG 七表,REA job 落 `33-REA/.../mcp_jobs/<job_id>.json`。

**判定**:两者都属 L0 域内状态,**合法**;但当前没有任何文档把"异步 job 状态"登记进 L0 状态清单,读起来像第二事实源。

**修订要求**:SSoT §1.8 补一句"长任务 job 状态属 L0 域内状态,须登记于域内存储(45 PG / 33 JSONL),不构成第二事实源";46 ADR-3 补 `paused` 子因(见 G3)。

## 四、架构缺口(3 项,必须先决)

### G1 主体×权限矩阵(见 B2)——**这是最大缺口**
没有它,Mandate 授权、写工具禁用、settle 归属全部悬空。建议直接采用 B2 的四主体矩阵。

### G2 壳实例拓扑未定义
"1 宿主 = 1 壳进程"中的**宿主**是 DSH 进程,还是每个 Worker 会话?两种解释差 N 倍连接数:
- 若 **DSH 进程级共享**(推荐):1 进程内按域共享壳实例,Worker 会话复用 → 连接数 = 域数(3),不是 Worker 数;
- 若 **Worker 会话级**:每个 Worker 拉起独立壳 → 连接数 = Worker 数 × 域数。
**建议定稿**:壳实例按 **DSH 运行时进程级共享**,Worker 会话只持有"工具调用句柄";跨进程(云端/本地)才各自拉起。

### G3 Ticket 四态缺「等待异步任务」
46 ADR-3 四态 = live / paused / waitsForPerson / ended;47 的 submit/poll 长任务需要第五种语义。**建议不新增态,给 `paused` 加子因**:

| 子因 | 含义 | 唤醒 |
|---|---|---|
| `waiting_event` | 等外部事件 | 事件网关 |
| `waiting_job` | 等异步工具(poll) | job 完成事件 |
| `waiting_person` | 等人 | 人工操作 |

并**禁止忙轮询**——poll 由 job 完成事件驱动,否则 Router 常驻循环会被长任务占满。

## 六、合并开工顺序(单一 P0 清单)

两套文档各有 P0,合并后**只有一条关键路径**:

```
① 事件源盘点(46/SPEC#3 前置)          ─┐
② G0 prototype 契约核实(46/SACG_A M1)  ─┤ 可并行
③ Worker 角色清单(46) → 能力标签        ─┘
        ↓
④ 能力标签→工具集 + registry v1(47,含存量三面登记)
        ↓
⑤ 统一信封映射层 `mcp_shells/_shared/`(47,error_code 六值)
        ↓
⑥ 认知壳读写分 scope + 本地只读模式(47 P0④)
        ↓
⑦ Ticket→Mandate 翻译器 `okr_ticket_bridge.py`(46)
⑧ 事件网关 shadow(46,只记录不拦截)
        ↓
⑨ E2E:1 类事件 → Ticket → 1 Worker(只读) → 45 业务门禁 → Settle 节点写回
```

**关键路径**:④→⑤→⑥→⑨(47 侧)+ ⑦→⑧→⑨(46 侧);①③为两侧共同输入。

**P0 退出判据**(两侧合并):
1. E2E 跑通且 trace_id 全链一致;
2. 越权写被明确拒绝(非静默);
3. 信封三态可区分(ok+None / degraded / error);
4. 开关关断字节等价;
5. 壳实例数与 Worker 数的关系符合 G2 定稿。
