## 二、逐项明细（含闭环结果）

### C1. 中文分词方案指定【P0】✅

- **问题**: L2 倒排索引对中文文本必须分词，SPEC 未指定方案，直接阻塞 P1 实施。
- **闭环结果**: jieba 精确模式为默认分词器；英文空白+驼峰拆分；全小写归一化+中英文停用词表；分词器接口可替换（预留 HanLP 适配位）；架构新增 core/tokenizer.py。
- **落点**: SPEC v0.4 §2.2

### C2. 索引 schema 版本与迁移策略【P0】✅

- **问题**: 索引库升级无版本管理与兼容策略，升级即重建风险。
- **闭环结果**: meta 表记录 schema_version；初始化校验版本——不兼容触发自动全量重建（旧库保留 .bak），兼容走增量迁移；status() 返回 schema_version。
- **落点**: SPEC v0.4 §4.1

### C3. 并发写入模式定义【P0】✅

- **问题**: SQLite 单写者限制下，多调用方并发写索引行为未定义。
- **闭环结果**: WAL 模式；写操作经单写队列串行化（busy_timeout=5000ms）；读并发无限制；跨进程写文件锁互斥（.lock 文件）。
- **落点**: SPEC v0.4 §4.1

### C4. 增量触发机制决断【P1】✅

- **问题**: L1 更新频率『fs 事件或按需』二选一未决。
- **闭环结果**: 决断为『按需惰性校验 + 每小时定时对账兜底』，不引入 fs 事件监听；惰性校验仅 stat（<10ms/千文件），超预算（>50ms）降级跳过由对账修复；新增 scripts/reconcile_cron.py。
- **落点**: SPEC v0.5 §2.3

### C5. 权限模型定义【P1】✅

- **问题**: 『按调用方身份过滤』仅一句带过，身份来源与过滤规则未定义。
- **闭环结果**: 两类调用方——前端用户（NextAuth 会话，按可见范围过滤）与内部 Agent（FIS_AGENT_TOKEN 环境变量凭证，全量可见）；凭证校验失败 FAIL-OPEN 降级；可见范围规则与索引规则同文件维护。
- **落点**: SPEC v0.5 §5.5

### C6. 可观测性与测试计划章节【P1】✅

- **问题**: 无独立章节，仅风险表提及单测。
- **闭环结果**: 第 8 章可观测性（6 项健康度指标经 status() 暴露 + 结构化 JSON 日志按天滚动保留 14 天）；第 9 章测试计划（4 层测试矩阵 9 类关键用例，验收基线通过率 100%、核心路径覆盖率 ≥85%）。
- **落点**: SPEC v0.5 §8/§9

### A1. search_api 部署形态定义【P0】✅

- **问题**: Python 库直调 vs HTTP 服务未决，影响前端与 7 号中台接入方式。
- **闭环结果**: 双形态——内部 Agent/脚本/7 号中台 Python 库直调；前端经 Next.js API Route 封装；不独立部署 Python HTTP 服务。
- **落点**: SPEC v0.4 §3.2

### A2. 无标题文档分块兜底策略【P1】✅

- **问题**: chunker 依赖 markdown 标题结构，代码/纯文本无标题时行为未定义。
- **闭环结果**: 三级兜底——标题层级 > 空行段落 > 256 行窗口（重叠 16 行）；代码按 def/class/function/export 正则切分，超 512 行二次切分；chunks 表新增 boundary_kind 字段。
- **落点**: SPEC v0.5 §2.2

### M1. 两段式链路数据对象语义澄清【P0】✅

- **问题**: 41 索引案例文档（md），案例库精排结构化案例（TDR 记录），两者非同一数据集，链路存在实施歧义。
- **闭环结果**: 澄清为补充注入——CaseBankClient.retrieve 为主候选源；41 的 recall() 结果作为补充候选在 Soft Q 打分前合并去重（按案例 id/文档路径），不替代主链路。
- **落点**: SPEC v0.4 §7.6

### M2. TDR 豁免条款【P0】✅

- **问题**: §7.8『禁止自建全文索引』与案例库 solution_case_bank.db 自带检索能力冲突。
- **闭环结果**: 禁止范围精确定义为『对文件系统文档构建第二份全文倒排索引』；TDR 属结构化业务数据存储明确豁免；业务模块自持语义精排同样豁免。
- **落点**: SPEC v0.4 §7.8
