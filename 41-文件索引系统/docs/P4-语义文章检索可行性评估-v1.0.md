# P4 预研 — 语义文章检索可行性评估

> 日期：2026-11-15  
> 范围：评估 `doc_search` 的 top-50 语义精排，不在 SPEC-41-L1 P4 内实现。  
> 结论：**有条件可行，建议独立立项做对照 PoC；不建议直接改写 41 的现有混合召回。**

## 1. 现状核查

1. [searcher.py](../core/searcher.py) 已合并 L1 路径、L2 倒排/BM25 式、L3 ChromaDB 向量三路结果，再按合并后的 `Hit.score` 排序；当前不是“BM25 top-50 后独立语义精排”。
2. L3 已复用 9-RAG-INFRA ChromaDB，由 `FIS_L3_VECTOR=1` 开启，桥接异常返回空结果并降级；因此本项是评估新增精排的增益，不是从零建设向量检索。
3. `recall(query, topK=50)` 已提供 BM25 候选接口，但当前结果只含 snippet；L2 snippet 又截断为约 120 字符。真正精排需要补充候选 chunk 正文或可读取向量的桥接，不能直接拿截断 snippet 宣称完成语义精排。
4. [主 SPEC §7.8](../SPEC-41-文件索引系统-v1.1.md) 明确“语义精排由各业务模块自持，41 只到召回为止”；子 SPEC §6.5 的“41 做 top-50 精排”与该边界存在口径差异。

## 2. 职责边界结论

采用主 SPEC 的边界作为实施约束：

- **41**：提供可追溯候选召回、chunk 标识和必要正文/向量读取能力，不承担业务排序策略。
- **doc_search 消费方或 9-RAG-INFRA**：实现 embedding 精排、分数融合、阈值和评估。
- **禁止重复建设**：不新建第二套 ChromaDB collection，不另建全文倒排索引，不在 P4 修改 `search()` 默认排序。

后续独立 SPEC 应先修正文档口径，再确定精排宿主；在此决策前不应把 `doc_reranker` 写入 41。

## 3. 推荐 PoC 方案

```text
query
  → 41 BM25 recall(topK=50)
  → 按 chunk_id 补齐正文（或读取已缓存 embedding）
  → bge-small-zh-v1.5 query/chunk cosine
  → 语义分与 BM25 分归一化后融合
  → 返回带 path/line/score 的 Evidence
```

优先复用已缓存 chunk 向量，避免每次请求重算 50 篇文档 embedding；若桥接只能返回命中而不能按 ID 读向量，则把“桥接读取契约”列为 PoC 前置任务。保留 BM25-only 与现有 L1+L2+L3 混合召回两个基线，精排异常时原样返回 BM25 候选。

## 4. 评估设计与建议门禁

### 数据集

- 收集真实 `doc_search` 查询并标注相关 path/chunk，覆盖精确术语、同义改写、口语描述、跨模块检索和 OOS。
- 训练/调参集与测试集按查询分组隔离，避免同一问法变体泄漏。
- 未形成标注集前，不用 golden intent set 替代文档相关性数据集。

### 指标

- 召回：Recall@50，确认精排不会损害上游候选召回。
- 排序：MRR@10、nDCG@10，与两个基线做同查询对照。
- 工程：P50/P95 延迟、桥接失败率、降级率、50 候选额外耗时。
- 安全：OOS 查询的无效高置信命中数、路径/行号 Evidence 完整率。

建议后续 SPEC 将“nDCG@10 相对现有混合召回提升 ≥5%、Recall@50 不下降、失败时 100% 回退基线”作为 PoC 验收候选值；最终数值需在真实数据基线测量后确认。

## 5. 成本与风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 现有 L3 已提供语义收益 | 新增精排可能重复且增益不显著 | 必须保留现有混合召回基线，增益不足即停止 |
| 分数尺度不可比 | 直接比较 BM25/cosine 会误排序 | 分通道归一化，网格搜索融合权重并做 holdout |
| snippet 过短 | 精排只看见标题和片段，语义信息不足 | 补 chunk 正文或缓存向量读取契约 |
| top-50 推理成本 | 延迟超出现有搜索 SLA | 复用向量缓存、批处理、限制候选数并记录 P95 |
| 权限边界 | 精排绕开 search_api 过滤 | 权限过滤仍在 API 入口统一执行，精排只处理已授权候选 |

## 6. 决策

- **PoC：建议。** 现有召回与向量基础设施足以支持低成本验证。
- **直接进入生产：不建议。** 尚缺真实相关性标注、完整 chunk/向量读取契约和相对现有 L3 的增益证据。
- **P4 交付边界：已完成评估。** 本阶段不修改检索主链，不实现 `doc_reranker`。
