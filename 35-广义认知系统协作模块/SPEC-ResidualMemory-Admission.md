## 1.1 附加缺陷 F-0：写索引脱钩（2026-11-16 实测，P0）

> ⚠ **评审修订（REVIEW P0-1）**：本节根因判断**已被推翻**。不是"record 未写索引"，而是**向量化器静默降级导致 256/512 维混用**——实测 `memories.vector` 长度分布为 2048 字节（512 维）314,310 条 / 1024 字节（256 维）1,188 条，而 `meta.embed_dim=512`。本节数据保留作历史记录，P0.0 修复方案以 [REVIEW P0-1](./SPEC-ResidualMemory-Admission-REVIEW.md) 为准。

实施本 SPEC 时实测发现，**`memories` 表与向量索引 `vec_memories_rowids` 已脱钩**：

| 指标 | 实测 |
|---|---|
| `memories` 总数 | 315,489 |
| 向量索引条目 | 313,066（缺口 2,423） |
| 2026-11-14 之后新增记忆 | 1,998 |
| 其中已进向量索引 | **0** |

**后果**：近两天写入的**全部**记忆对 recall 不可见（含本次新增的硬约束 `VM-...-7af17f8c`）。系统呈现**反向选择性**——96.98% 的噪音可被检索到，最新的真实知识反而检索不到。

这说明"写放大"之外还有第二个独立缺陷：**`record()` 只写主表，不维护向量索引**，索引依赖事后 `rebuild_vector_index` 补建。两个缺陷叠加，使记忆系统在"读"和"写"两端同时失效。

**F-0 必须先于 P1 修复**，否则 P1 重建索引后仍会重新脱钩。

## 2. 第一性原理

### 2.1 记忆 = 残差

设 `K` 为模型能力、`D` 为仓库与文档 SSoT、`R` 为现算/现检索能力。则一条信息的记忆价值为其**不可推导性**：

```
mem_value(x) = H(x | K, D, R)
```

`H(x|K,D,R) ≈ 0` 的信息，记一百遍熵仍为零。**记忆库规模增长应视为缺陷，而非成绩。**

推论：**记忆库的合理规模随模型能力增强而缩小**，不应随运行时间增长而膨胀。

### 2.2 遗忘 = 检索失败，不是擦除

人类遗忘并非把记忆调暗，而是**检索不到**（savings effect：痕迹仍在，重学更快）。因此治理口径为：

- **移出向量索引**（不可检索）
- **树梢痕迹保留**（Tier 2 归档 → 记忆树**叶节点痕迹池**；可回溯"存在过"，**不可重建内容**）

→ 主表行最终物理删除，只留树梢痕迹（`id + 关键词 + 200 字摘要`），风险最低，且与 `MEMORY_SYSTEM_ARCHITECTURE.md §6` 的 Tier 2 设计一致。

### 2.3 顺序不可颠倒

人类认知的四个阶段，我们**只能在第四段补课，是在第一段就漏了 97%**：

| 阶段 | 人类机制 | 我们的问题 | 优先级 |
|---|---|---|---|
| 编码门 | 注意力筛选 + 工作记忆 4±1 chunk | **完全缺失** | P0 |
| 巩固 | 睡眠期选择性重放（只重放高预测误差） | 只覆盖 Markdown 层 | P2 |
| 遗忘 | 衰减 + 干扰 + 突触剪枝 | 机制存在但未运行 | P3 |
| 再巩固 | 检索时可被改写 | `verify` 只能升置信度，不能改内容 | P4 |

### 2.4 减记忆增能力（能力与记忆互为替代）

人的长期策略不是"记得更多"，而是"记忆下降 + 能力上升"：靠联想串联 + 熟能生巧（技能自动化）补位。年龄越大记忆越差，但解题反而更快——因为工具变锋利了，不是因为记得更多。

对应本系统：

- **记忆条目数 ↓ 与 现拆成功率 ↑ 是同一个目标**，必须同时考核；单看任一项都会跑偏。
- **现拆失败 ≠ 该记下来**；现拆失败 = **工具不够锋利**的信号。
- 因此"答案"和"失败案例"都不入记忆，只有**工具缺口**入账（见 §3.5）。

反模式：把"这次没解出来"逐次写成记忆（N 条失败案例）；正确做法是聚合成 **1 条**工具缺口。

## 3. 准入判定（四禁入 / 四残差 / 三测试）

### 3.1 四禁入（默认拒绝）

| # | 禁入类别 | 判据 | 典型 |
|---|---|---|---|
| N1 | 基座能力可现推 | 问模型即可得，且答案不依赖本仓库 | 怎么写 Python、怎么配 systemd |
| N2 | SSoT 已承载且可读取 | 仓库内文档/代码可直接读取 | 接口签名、配置项、部署步骤、端口号 |
| N3 | 过程轨迹 | 记录的是"我做了什么"而非"世界的状态或我的取舍" | RAG 检索结果、搜索结果、工具调用日志、job_run |
| N4 | 可现场逆向解析 | 33-REA / 读代码 / 跑一次即可复原 | 具体实现细节、调用链、参数取值、报错根因 |

**N3 为硬零**：任何 `source ∈ {rag-bridge, l0.scheduler, l1_router}` 且内容为轨迹的记录，准入直接拒绝，不进入队列。

### 3.2 四残差（允许入库）

| 类别 | 例 | 不可推导原因 |
|---|---|---|
| R1 用户偏好与否决 | "这个方案不用，原因 X" | 模型推不出未表达过的取舍 |
| R2 有代价的教训 | 事故复盘、踩坑记录（附成本） | 成本信息无法从代码反推 |
| R3 外部世界状态 | 属主、维护窗口、账号禁区 | 推理时无持久世界状态 |
| R4 负向决策 | "试过了，不行"（附失败条件） | 最贵且最易丢失 |

### 3.3 三测试（任一命中即拒绝）

- **删除测试**：删除该条后，未来 N 次任务（N≥3）行为无变化 → 可再推导，拒绝。
- **重推测试**：不提供该条，让 agent 重做同一任务，结果等价 → 可再推导，拒绝。
- **现拆测试**：能否通过逆向解析（33-REA / 读代码 / 跑一次）当场得到？能 → 拒绝，且**连"曾经解过"都不记**。

三测试均可自动化抽样（纳入 `test_p5_mcp_governance` 的准入用例族），不要求全量人工判定。

### 3.4 记忆三形态（形态决定容量与检索方式）

记忆不是单一"内容库"，按人类习惯分三形态，**能用前者就不用后者**：

| 形态 | 记什么 | 不记什么 | 容量 | 检索方式 |
|---|---|---|---|---|
| **M1 指针型** | 问题签名 → 项目 / 组件 / 文档章节锚点 / 入口文件:行 | 细节、代码、参数、步骤 | **硬上限 150 条** | 目录遍历 + 关键词定位 |
| **M2 联想型** | 核心节点 + 相邻节点 / 相似案例 id | 全文、推演过程 | 边数 ≤ 3×节点 | 图扩散 / 相似检索 |
| **M3 零记忆** | 不写记忆，只保留求解方法（REA 逆向解析口径） | 答案本身 | 0 | 现场解析 |

**判据顺序**：能 M3 → 不写；不能 M3 但可用 M1 定位 → 只写指针；只有"指针指向的内容会随外部世界变化、必须原样保留"时，才升到内容型记忆（四残差 R1-R4）。

**容量有限是特性，不是缺陷**。"整体记得住、细节记不住"对应工作记忆 4±1 与 chunking——M1 超过 150 条即触发**抽象合并**（把多个相似问题签名抽象为一类），这才是真正的 consolidation；当前的按比例衰减只是"把记忆调暗"，条数不变。

**检索形态改造（关键）**：`recall` 默认返回**指针/摘要（≤120 字）+ 路径锚点**，命中后按需二次展开，而不是一次灌入全文。对应人类"按目录找章节、看到了才读细节"。

### 3.5 能力缺口（Capability Gap）——不是记忆，是工单

**落点**：复用 `48-涌现架构/registry/capability_gaps.py` + `capability_gaps.jsonl`（open→claimed→resolved 状态机已可用），本 SPEC 只加薄适配层，**禁止**新建平行存储。

现拆失败或耗时超阈值（> 5 min 或 > 20 次工具调用）时，走**工单**而非记忆：

| 字段 | 说明 |
|---|---|
| 问题类别 | 归一化签名，同类聚合，不按实例 |
| 失败模式 | 找不到入口 / 依赖不明 / 跑不起来 / 推理链断 / 语义不理解 |
| 缺失工具 | REA 子命令缺 / 索引缺 / 脚本缺 / 观测缺 |
| 期望增强 | 一句话可验收的能力描述 |
| 复现次数 | ≥2 次即升级为工具增强任务 |

**硬约束**：同类缺口只允许 **1 条**（按问题类别聚合）；逐次记录失败案例属 N3 过程轨迹，直接拒入。

同时维护 **M1-T 路由表**（问题类别 → 工具链：REA 子命令 / agent-browser / 数据排查 / 回测验证），属指针型记忆，**计入 150 条上限**。这就是"记哪类问题该调哪类 REA"，记的是路由而不是答案。

### 3.6 记忆树与求解级联（默认求解器 = REA）

REA 逆向解析已封装 MCP，是**默认求解器**；记忆只负责**指路**。

**1+1 原则**：能由求解器直接得出答案的问题，**不查记忆**。1+1 不需要先翻乘法口诀表。记忆的价值只在于"知道去哪找、该调什么"，不在于"知道答案"。

**结构**：三级树，节点仅存 `项目 → 目录 → 章节` 关键词与位置指针（`doc_anchor` 或 `module_path`），**禁止**存细节内容。深度 3，**节点由现有索引自动生成**（`0-系统文档管理/INDEX.md`、`2-KNOWLEDGE/INDEX.md`、目录树），人工只维护 ≤150 个**高频根节点**；实测顶层编号目录 58 个，故**不采用**「项目 ≤10」的静态假设。

**求解级联（2026-11-16 用户裁定：记忆优先，严格顺序，命中即停）**：

| 级 | 动作 | 命中后 |
|---|---|---|
| D0 | **检索记忆库（向量 + 关键词），取短期/近期经验** | 直接给结论，不展开定位 |
| D1 | 记忆未命中 → 关键词命中记忆树节点 | 有技术文档 → 读文档锚点细节；无文档 → 调 REA 解析该模块 |
| D2 | 上下文邻近节点（同项目/同目录兄弟）扩展 → 沿树遍历目录/章节 | 同 D1 |
| D3 | 树亦无果 → **直接 REA 逆向解析整个工程** | 成功即回写树 |
| D4 | REA 不具备该能力 → 大模型调研解决 | 成功后**强制分流** |

**D4 分流（二选一，禁止跳过）**：
- a) 补 / 优化 REA 能力 → 落能力缺口工单（§3.5）
- b) 更新记忆树（属"逆向解析做不了"的认知类）→ 新增 / 修正节点

**三条不变式**：

1. 每次 D3 / D4 成功后**必须**回写记忆树，否则下次无法 D1 命中。
2. 树遍历是**确定性检索**（可解释、可复现、无误召回），与 D0 的向量检索互补——D0 解"我见过"，D1-D2 解"我知道在哪"。
3. 节点数天然有界（项目 / 目录 / 章节），**不需要压缩**；记忆库的淘汰由 §3.7 分级 TTL 承担，与树无关。

**两侧对齐**：树节点既要能指向文档章节，也要能指向代码模块。有文档看文档，没文档直接 REA——**同一节点两种展开方式**，这就是"两边对齐"。

### 3.7 分级 TTL：记新不记旧（2026-11-16 用户裁定）

> **作废** 原「清空重建」方案。原认知库（纵向经验）无设计问题，修好向量索引后继续作为**第一检索层**，现有架构维持。

三方分工：

| 系统 | 承担 | 淘汰方式 |
|---|---|---|
| 原认知库（纵向经验） | **短期记忆 + 可能用到的经验** | 分级 TTL |
| 记忆树 | **长期记忆的定位索引**（忘了细节，还记得去哪找） | 节点天然有界，不淘汰 |
| REA 逆向解析 | **长期记忆的替代**（记不住就现拆） | 无需淘汰 |

分级 TTL（硬阈值）：

| 等级 | 保留期 | 未升级后果 |
|---|---|---|
| C | **7 天** | 删除 |
| B | **14 天** | 删除 |
| A | 按**存量上限**控制 | 量满删最旧 / 最低频 |
| S | 长期保留 | 不淘汰 |

**升级途径 = 被使用**：每次 `recall` 命中且实际被引用或 verify，刷新 `access_count` / `last_used_at`；达阈值即升级 C→B→A。→ **按使用频率升级，按闲置淘汰**。

**生效前置（硬门禁，二审 R1 / R2）**：

1. `memories` 表**必须**先增 `access_count` / `last_used_at` 两列，且 recall 命中后**必须**回写（现 schema 无此字段，且 `cognitive_loop_entry.py` 全文无 `UPDATE memories`）——否则升级路径不可达，7 天 TTL 会连真实教训一起删掉。
2. 「被引用」信号未落地前，TTL **只对 `source ∈ {rag-bridge, l0.scheduler, l1_router}` 生效**，其余记忆一律不动。
3. 淘汰**两阶段**：阶段一移出检索索引（可逆）→ 宽限 7 天 → 阶段二**降为记忆树叶节点的痕迹池**（`id + source + tags + 关键词 + 200 字摘要 + last_used_at`）并物理删除主表行。**禁止**单阶段直接删行，**禁止**痕迹无归属堆放。
4. **痕迹必须挂到对应树梢**：按 `项目 → 目录 → 章节` 归位到叶节点；找不到归属时挂到该项目的 `_orphan` 叶节点，**禁止**建全局大池。
5. **痕迹池容量**：每叶节点 ≤ **20 条**（FIFO），全局 ≤ **5000 条**；超限先淘汰最旧、摘要最短者。
6. `source ∈ {rag-bridge, l0.scheduler, l1_router}` 的轨迹**不留痕**（它们本不该入库，属脏数据修复）。
7. 痕迹**不可作为答案被检索**，只能在 D1/D2 遍历时显示「此处曾有 N 条经验，已遗忘」，用于提示现拆方向。
8. 删除**必须**统一经 `VectorMemoryInterface.delete`（含 vec 表级联，**禁止** engine 分支跳过）；每次变更后跑 count 差 + 混维巡检，防 vec 孤儿。

**人类对应**：刚犯的错最容易记住（近期性），反复犯的记得最牢（频率），但脑容量有限，久不用的自然遗忘（闲置衰减）。AI 无先天记忆，因此"最近可能复用的"值得留，"长期没用的"直接交给现拆更省力。

**反模式**：把"长期不用但当初很难得到"的记忆当资产保留——它的存储与检索成本已高于重算成本。

## 4. 机制落地映射

| 层 | 动作 | 落点 | 变更性质 |
|---|---|---|---|
