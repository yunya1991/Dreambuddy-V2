## 0. 总原则

1. **先竖切，后横切**：先把一条端到端链路打通，再谈多节点/弹性扩展。
2. **当前不追调度智能**：弹性池、抢占、节点画像、成本感知等"横切能力"，在只有 1-2 个节点时**收益 < 复杂度**，一律暂缓。
3. **每阶段独立可用、独立回滚**：module_switches 默认 OFF；FAIL-OPEN；零回归（HC-1a / HC-9）。
4. **启动门禁**：阶段 N+1 的启动条件 = 阶段 N 稳定运行 + 验收通过。


## 3. 阶段 1 — 训练下沉 · 简单模式（P0-next）

### 3.1 目标

以**最小闭环**把训练下沉到本地：

```
云端下发 → 本地执行 → 模型回传 MinIO → 云端热加载
```

**不引入任何调度智能**（无能力路由、无心跳自动化、无弹性）。

### 3.2 范围（做）

| 项 | 取值 |
|---|---|
| 任务类型 | 仅 `evolution_train` + `bcrm2_optimize` |
| 节点 | 仅 **1 台**本地机（M3） |
| 并发 | **串行，单任务** |
| 触发 | **手动**（云端 CLI/API）或**半自动**（固定 timer） |
| 模型回流 | MinIO 上传 + 云端热加载 + 回滚（D-7 / D-21） |

### 3.3 明确不做（划界，防范围蔓延）

心跳自动纳管 · 能力路由 · 弹性 min:max · 抢占 / backfill · checkpoint 断点续传 · 多节点 · 推理下沉 · 成本感知 —— **全部属阶段 2+**。

### 3.4 最小实现集

| 组件 | 形态 | 复用 |
|---|---|---|
| 下发 | 写 **Redis Streams** 一条消息（或 `POST /api/task/create`） | SPEC §5 API 雏形 |
| WorkerAgent（最小版） | poll → `conda run`（**D-13** 环境路由）→ MinIO 上传 → report | — |
| 热加载 | 监听 MinIO 新模型 → **atomic swap** → **LKG 回滚** | **D-21** |

### 3.5 验收

- [ ] 云端下发 1 个训练任务 → 本地执行 → 产物回传 MinIO
- [ ] 云端**加载新模型成功**（推理用上新模型）
- [ ] 加载失败**自动回滚** LKG
- [ ] 关闭开关回退到"本地手工训练"，**无副作用**

## 5. 阶段 1 与既有编号的关系

- 阶段 1 ⊂ SPEC Phase 2'（**O1 / O2**）的**最小子集**：只做 O1 的"下发 + 执行 + 回传"，**不做** O2 的心跳自动化与能力路由。

- 阶段 1 **不触碰** **D-14~D-24** 同步语义（那是"两节点隔离单训"之后的下一步）。
