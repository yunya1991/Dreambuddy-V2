## 一、问题陈述

### 1.1 研究问题

DreamOs 分布式计算拟采用**三层异构协同架构**：

| 层级 | 机制 | 核心张力 |
|------|------|---------|
| 认知层 | 远端+本地广义认知最大化（多节点聚合） | 共享广度 vs 策略同质化 |
| 子系统层 | 回测表现竞赛择优权重参数（Competition Mode） | 局部最优 vs 全局最优 / 过拟合风险 |
| 前端层 | 协作训练，类大模型堆算力（联邦学习） | 通信开销 vs 算力扩展 |

**核心问题**：
1. 三层异构是否为当前阶段的最优架构？还是过度设计？
2. 与主从式、联邦式、对等网等范式相比，权衡在哪？
3. 从当前已实现状态到目标架构的演进路径如何规划，每步可验证、可回滚？

### 1.2 研究边界

- **聚焦**：分布式计算编排层（31-分布式计算部署）的架构范式选择
- **不涉及**：具体子交易系统的业务逻辑、具体策略参数
- **约束**：HC-1a（FAIL-OPEN）、HC-9（零回归）、模块化开关默认 OFF、云端 4C8G + 本地 M3

### 1.3 认知闭环说明

## 二、多 Agent 辩论记录

### 2.1 Agent 角色与立场

#### Agent 1：极简主义者（奥卡姆剃刀）

**立场**：三层异构是过度设计，应简化为**两层**（认知共享 + 执行择优）。

**论据**：
- 当前云端只有 4C8G，本地只有 M3，节点数=2。三层架构在 2 节点下的边际收益很低
- 联邦学习（N9）在 2 节点下退化为"两个模型取平均"，不如直接 MinIO 上传中心化
- 竞赛择优（N3）本质是已有 EntryModuleSelector 的跨节点扩展，不值得引入完整 Orchestrator
- 认知分层（N1）的 scope 字段增加了 schema 复杂度，但当前没有子系统私有认知的实际需求

**提案**：保留认知聚合（已实现）+ EntryModuleSelector（已实现），跳过 N1/N3/N8/N9，只做 N10（模型同步）。

---

#### Agent 2：复杂系统专家（涌现与非线性）

**立场**：**强烈支持三层异构**，这是复杂自适应系统（CAS）的正确分层。

**论据**：
- 交易市场是复杂自适应系统，子系统需要**自治性**（竞赛择优）才能涌现出多样性
- 多智能体论文（Shi & Hollifield 2025）证明：沟通结构需匹配市场特征，**一刀切的共享会导致收敛**
- 三层对应 CAS 的三个尺度：**认知=种群记忆**、**子系统=个体竞争**、**前端=基因交换**
- 联邦学习的本质是"保留局部数据异质性的同时共享模型参数"，这与生物进化的基因流高度同构
- 2 节点是起点，不是终态。架构必须为**多线下机器扩展**预留（O5）

**反驳极简主义者**：评分 3（不让步）。2 节点下边际收益低，但架构的**可演进性**比当前收益更重要。如果现在只做两层，将来扩展到多节点时需要重构。

---

#### Agent 3：风控优先者（稳健性与安全）

**立场**：支持三层，但**竞赛择优层风险最高**，必须加重风控。

**论据**：
- **过拟合风险**：Harvey-Liu-Zhu 2016 证明大多数已发表策略样本外失效。竞赛择优本质是多重检验，必然过拟合
- **认知同质化**：如果 scope 分层没做好，所有子系统读同一份认知，策略相关性趋近 1，分散化失效
- **单点故障**：CompetitionOrchestrator 如果挂了，所有子系统退化为默认参数，等于没有择优
- **数据漂移**：回测最优参数在 regime 变化后可能变成最差，在线权重学习（Bradley-Terry）必须能快速响应

**要求**：
1. N5（FDR 控制）必须与 N3 同步实施，不能后补
2. N1（scope 分层）必须先于跨节点竞赛，否则同质化
3. 竞赛结果必须有**回滚机制**（N7），优胜参数出问题能秒级回退

**反驳极简主义者**：评分 4（让步）。极简方案确实降低了复杂度，但也去掉了风控层。如果做极简，必须保留 FDR 和回滚。

---

#### Agent 4：性能追求者（收益与效率）

**立场**：支持三层，但**前端协作训练层优先级应提高**，因为算力是瓶颈。

**论据**：
- 自进化训练是整个系统最重的计算负载，当前全在本地 M3，云端 4C8G 浪费
- 联邦学习（N9）能让云端参与训练，相当于算力翻倍
- 竞赛择优（N3）的回测吞吐是瓶颈——同场景多参数并行回测，如果只在本地跑，串行回测一个场景可能要几小时
- 跨节点竞赛（N4）能把回测任务分发到云端，吞吐提升 2-3 倍

**要求**：
1. N10（模型同步）应立即做，这是算力利用的基础
2. N4（跨节点竞赛）的优先级应高于 N3 单节点版，因为单节点回测太慢
3. N8（权重 delta）应早于 N9（联邦学习），先降低通信量

**反驳复杂系统专家**：评分 3（不让步）。架构可演进性重要，但**当前算力瓶颈**更紧急。

---

#### Agent 5：维护工程师（可维护性与可扩展性）

**立场**：支持三层，但**必须严格执行模块化开关**，每层独立可降级。

**论据**：
- 三层架构意味着 3 倍的部署单元和监控点，可观测性必须跟上（N12）
- 当前 08-local-mirror.sh 是 bash 脚本，认知聚合逻辑硬编码，加 scope 字段要改多处，维护成本高
- CompetitionOrchestrator 如果作为新模块，必须复用 EntryModuleSelector 的打分逻辑，不能重复实现
- 联邦学习引入 Flower/NVFlare 依赖，增加了供应链风险

**要求**：
1. 每层必须有独立的 module_switch（L0 认知/L1 竞赛/L2 训练），默认 OFF
2. CompetitionOrchestrator 的打分逻辑必须**抽取共享模块**，不能复制 EntryModuleSelector
3. 08-local-mirror.sh 的聚合 SQL 应抽取为可配置模板，加 scope 只需改配置
4. 联邦学习优先用轻量方案（N8 权重 delta），不引入新框架依赖

**反驳性能追求者**：评分 4（让步）。算力重要，但可维护性是长期成本。跨节点竞赛（N4）依赖 O1（任务队列），而 O1 还没做，所以 N3 单节点版必须先做。

---

#### Agent 6：跨学科视角者（引入其他学科框架）

**立场**：三层异构与**生物进化的三层结构**高度同构，理论基础扎实。

**跨学科映射**：

| 本架构层 | 生物进化对应 | 经济学对应 | LLM 训练对应 |
|---------|------------|-----------|-------------|
| 认知层 | 种群基因库（gene pool） | 公共知识/公共品 | 预训练语料库 |
| 子系统层 | 个体间自然选择 | 市场竞争/锦标赛 | 多模型 ensemble 选择 |
| 前端层 | 基因流（gene flow）/有性生殖 | 产学研协作 | 数据并行/联邦学习 |

**关键洞察**：
1. **进化生物学**：种群基因库（认知）+ 个体选择（竞赛）+ 基因流（协作训练）是物种适应环境的标准三件套。缺少任何一层都会导致：缺认知→无记忆、缺竞赛→无选择压、缺基因流→近亲繁殖（过拟合）
2. **经济学**：公共品（认知）有搭便车问题，需要 scope 分层区分公共品和私有品；锦标赛（竞赛）有激励扭曲，需要 FDR 校正
3. **LLM 训练**：预训练（认知聚合）+ SFT/RLHF（竞赛择优）+ 数据并行（协作训练）是同一套架构

**结论**：三层异构不是拍脑袋，而是**跨学科收敛的架构范式**。

**反驳极简主义者**：评分 5（坚决不让步）。三层对应生物进化的必要结构，去掉任何一层都会导致系统无法适应环境变化。

### 2.3 妥协协商共识

经让步阈值协议（评分≥4 才让步），最终共识：

1. **三层架构保留**（跨学科视角者评分5，无异议）
2. **实施顺序调整**：
   - P0：N1（认知分层）+ N3（单节点竞赛）+ N10（模型同步）并行
   - P0：N5（FDR 控制）与 N3 同步（风控要求）
   - P1：O1+O2（任务队列）→ N4（跨节点竞赛）→ N7（版本管理）
   - P1：N8（权重 delta）→ P2：N9（联邦学习）
3. **风控硬约束**：竞赛层必须有 FDR + 回滚 + 多样性监控，缺一不可
4. **维护硬约束**：每层独立 module_switch，打分逻辑共享，不引入新框架依赖（N8 优先于 N9）

## 三、框架对比

### 3.1 候选框架

| 框架 | 核心思想 | 代表实现 |
|------|---------|---------|
| **A. 三层异构协同**（当前提案） | 认知聚合 + 竞赛择优 + 协作训练，三层各司其职 | DreamOs 本提案 |
| **B. 主从式（Master-Worker）** | 中心节点调度，Worker 执行，结果汇总 | Celery、Spark |
| **C. 联邦式（Federated）** | 各节点平等，共享模型参数不共享数据 | Flower、NVFlare |
| **D. 对等网（P2P）** | 无中心，节点间直接通信 | IPFS、Gossip 协议 |

### 3.2 对比维度与权重

| 维度 | 权重 | 说明 |
|------|------|------|
| 复杂度 | 0.15 | 组件数量、依赖关系、理解难度 |
| 性能（算力利用） | 0.20 | 回测吞吐、训练效率、推理延迟 |
| 稳健性（风控） | 0.20 | 抗过拟合、抗同质化、容错 |
| 可扩展性 | 0.15 | 多节点扩展难度 |
| 可维护性 | 0.15 | 部署、监控、回滚成本 |
| 理论基础 | 0.15 | 跨学科理论支撑 |

### 3.3 对比评分表

| 维度 | 权重 | A 三层异构 | B 主从式 | C 联邦式 | D 对等网 |
|------|------|-----------|---------|---------|---------|
| 复杂度 | 0.15 | 中(6) | 低(3) | 中(5) | 高(8) |
| 性能 | 0.20 | 高(8) | 中(6) | 高(8) | 中(5) |
| 稳健性 | 0.20 | 高(8) | 中(5) | 中(6) | 低(3) |
| 可扩展性 | 0.15 | 高(8) | 中(6) | 高(8) | 高(9) |
| 可维护性 | 0.15 | 中(6) | 高(8) | 中(5) | 低(3) |
| 理论基础 | 0.15 | 高(9) | 中(5) | 高(8) | 低(4) |
| **加权总分** | 1.0 | **7.75** | 5.55 | 6.65 | 5.10 |

### 3.4 对比结论

- **A 三层异构（7.75）**：综合最优，理论基础最扎实（跨学科收敛），稳健性最高，但复杂度中等、可维护性中等
- **C 联邦式（6.65）**：性能和扩展性好，但稳健性不足（无竞赛择优层，无法防过拟合）
- **B 主从式（5.55）**：最简单易维护，但中心化导致单点故障，且无认知共享和竞赛机制
- **D 对等网（5.10）**：扩展性最好，但无中心导致一致性难保证，维护成本极高

**推荐**：A 三层异构，但需注意：
1. 可维护性（6分）是短板，必须严格执行模块化开关和共享逻辑抽取
2. 复杂度（6分）中等，需通过分步实施控制风险

## 四、设计权衡分析

### 4.1 集中式 vs 分布式

| 方面 | 集中式 | 分布式（本架构） |
|------|--------|----------------|
| 控制 | 中心节点统一调度 | 子系统自治 + 认知共享 |
| 容错 | 中心挂=全挂 | 子系统独立运行，认知聚合容错 |
| 一致性 | 强一致 | 最终一致（10min 聚合窗口） |
| 适用场景 | 小规模、强实时 | 大规模、异步训练 |

**本架构选择**：**混合式**。实时推理走集中式（云端统一入口），训练/回测走分布式（本地+云端并行）。

**后悔点**：如果最终节点数始终=2，分布式的复杂性可能不值得。缓解：模块化开关允许随时回退到集中式。

### 4.2 认知共享 vs 子系统独立

| 方面 | 全量共享 | scope 分层（本架构） | 完全独立 |
|------|---------|-------------------|---------|
| 信息利用 | 最高 | 中（广义共享） | 最低 |
| 多样性 | 最低（同质化） | 中（私有保留） | 最高 |
| 过拟合风险 | 高（策略趋同） | 中 | 低 |
| 实现复杂度 | 低 | 中 | 低 |

**本架构选择**：**scope 分层**。广义认知（market/macro/lesson）全量聚合，子系统私有（gene/param/private）保留独立性。

**后悔点**：如果 scope 划分错误（把该共享的标为私有，或反之），会降低系统效率。缓解：scope 可在线调整，定期审计。

### 4.3 同步推理 vs 异步训练

| 方面 | 同步 | 异步（本架构） |
|------|------|--------------|
| 实时性 | 高 | 低（训练有延迟） |
| 资源利用 | 低（训练占资源影响推理） | 高（训练/推理分离） |
| 一致性 | 强 | 最终一致（模型版本有滞后） |

**本架构选择**：**推理/训练分离**。云端实时推理（秒级），本地异步训练（小时级），通过 MinIO 模型仓库同步。

**后悔点**：训练到推理的延迟可能导致模型过时。缓解：模型版本锁定 + 在线权重学习（Bradley-Terry）快速响应。

### 4.4 竞赛择优 vs 人工指定

| 方面 | 竞赛择优 | 人工指定 |
|------|---------|---------|
| 客观性 | 高（数据驱动） | 低（主观） |
| 过拟合风险 | 高（多重检验） | 低 |
| 适应性 | 高（自动适应市场） | 低 |
| 可解释性 | 中 | 高 |

**本架构选择**：**竞赛择优 + 人工兜底**。数据驱动择优，但保留人工 override 开关（module_switches L2）。

## 五、演进路径规划

### 5.1 起点与终点

- **起点**：Phase 1-7 已实现（云端全量运行 + 认知聚合 v2 + EntryModuleSelector 单节点择优）
- **终点**：三层异构协同完整形态（认知分层 + 跨节点竞赛 + 联邦学习）

### 5.2 分阶段路线图

#### 阶段 1：认知分层（N1）— P0，1.5 天

```
当前（全量聚合）→ scope 分层聚合
```
- **变更**：memories 表加 scope 列；08-local-mirror.sh 加 WHERE scope='global' 过滤；record() 加 scope 参数
- **风险**：schema migration 可能失败；scope 划分错误
- **验证**：本地写入 scope='subsystem' 的行不被聚合到远端；scope='global' 的行正常聚合
- **回滚**：ALTER TABLE DROP COLUMN scope；08 脚本回退（git revert）

#### 阶段 2：单节点竞赛框架（N3 + N5）— P0，3-4 天

```
EntryModuleSelector（单场景择优）→ CompetitionOrchestrator（多场景并行回测 + FDR）
```
- **变更**：新建 competition/ 模块，复用 EntryModuleSelector 打分公式，加 FDR 控制
- **风险**：打分逻辑重复实现；FDR 阈值设定不当
- **验证**：同一场景多参数回测，优胜者样本外 Sharpe 优于默认参数；FDR 控制后假阳性率<5%
- **回滚**：module_switch L1 关闭 CompetitionOrchestrator，回退到 EntryModuleSelector

#### 阶段 3：模型同步机制（N10）— P0，2 天

```
线下训练 → 手工上传 → MinIO 模型仓库 + 云端热加载 + 灰度切换
```
- **变更**：MinIO 建 model-registry bucket；训练脚本自动上传；云端推理端检测新版本+灰度加载
- **风险**：模型版本冲突；灰度比例不当
- **验证**：上传新模型后云端加载成功；灰度 10%→50%→100% 无异常
- **回滚**：云端回退到上一版本模型

#### 阶段 4：任务队列 + 跨节点竞赛（O1+O2+N4+N7）— P1，5-7 天

```
单节点竞赛 → Redis Streams 分发 → 本地+云端并行回测 → 统一打分 → 版本管理
```
- **变更**：实现 WorkerAgent + HeartbeatMonitor；竞赛任务走 Redis Streams；竞赛结果版本化
- **风险**：任务分发失败；心跳误判
- **验证**：竞赛任务在云端和本地都有执行记录；优胜结果可回滚
- **回滚**：关闭跨节点开关，回退到单节点竞赛

#### 阶段 5：权重 delta 传输（N8）— P1，1-2 天

```
全量模型上传 → 仅传权重差异
```
- **变更**：训练脚本计算新旧模型权重 delta，MinIO 只传 delta；云端合并
- **风险**：delta 合并错误；通信量不降反升
- **验证**：传输数据量降低>50%；合并后模型与全量上传一致
- **回滚**：回退到全量上传

#### 阶段 6：联邦学习（N9）— P2，3-5 天

```
中心化训练 → FedAvg 多节点协作训练
```
- **变更**：引入 Flower（轻量），本地+云端作为 client，云端作为 server
- **风险**：新框架依赖；通信开销
- **验证**：FedAvg 模型精度≥中心化模型；训练时间缩短
- **回滚**：关闭联邦开关，回退到中心化训练

## 六、决策建议

### 6.1 核心结论

1. **三层异构协同架构是当前阶段的最优选择**（加权评分 7.75，跨学科理论支撑，风控完备）
