## 1. 定位与目标

意图系统从『15 种固定意图 + 硬编码规则兜底』演进为**分层意图体系 + 双训练闭环驱动的自动扩展**：

- **意图分层**：从单一意图扩展到复杂意图，从直接可查到模仿解析寻优输出；
- **双训练闭环**：正向训练（主前端核心功能完整链路训练）+ 逆向训练（REA 解析寻优，细分为三大方向）；正向训练数据可用于反向训练；
- **驱动分工**：逆向工程训练是意图扩展、复杂意图实现与执行的核心驱动；更复杂的驱动由大模型实现正向驱动；
- **自动扩展**：意图类型库经『训练→测试→逆向验证→扩展→同步 41/38』闭环自动生长。

## 3. 训练体系设计

### 3.1 正向训练：主前端核心功能完整链路训练

正向训练不是单点意图识别训练，而是**主前端核心功能的完整链路训练**，覆盖：

1. **广义认知系统**（35）：认知协作与 C-Drive 决策链路；
2. **意图系统 + DreamOS 编排**：意图识别 → SACG 编排（sacg_orchestrator）→ DSH 训练数据源调度 → 子 agent 分派执行；
3. **完整三层金融语义**（39）：原子事件 → 复杂语义 → 三层综合的语义消费链路；
4. **前端三层架构体系**（PLAN-L0L1L2）：L0 基础/L1 应用/L2 编排三层的完整功能链路。

各环节案例采集点定义见 §9.1。

### 3.2 逆向训练：REA 解析寻优，细分为三大方向

| 方向 | 解析对象 | 解析输入（见 §9.2） | 产出 |
|---|---|---|---|
| R-1 子模块逆向 | 单个子模块（意图引擎/SACG/DSH/子agent/查询底座等） | 子模块代码路径（33 现有静态解析器直接可用） | 子模块级最优路径案例 → 意图扩展提案 |
| R-2 完整三层架构逆向 | 前端 L0-L2 三层架构的完整任务链路 | 双输入：①回放池发现树（执行轨迹，已有数据）②架构代码静态解析（41 文件索引系统预过滤：list_files/search 供给能力地图，缩小解析范围） | 跨层路径寻优案例 → 复杂意图库（一般复杂意图链路模板，直接驱动完整链路；条目含 capability_refs 引用 41 命中 source） |
| R-3 三层金融语义推理逆向 | 39 原子事件→复杂语义→三层综合的推理链 | 推理过程记录（**需新增采集点**，现有数据为统计快照） | 语义推理路径案例 → 金融语义类复杂意图 |

### 3.3 驱动分工

- **逆向工程训练**：意图扩展、复杂意图实现、执行的核心驱动；
- **大模型正向驱动**：更复杂的驱动（意图库外开放任务、生成式规划）走 L2 大模型正向驱动路径，案例双向回流。

## 4. 意图分层架构

```
L2 解析寻优层（复杂意图，逆向训练核心驱动 + 大模型正向驱动）
   复杂意图限定：系统内能力范围内为一般复杂意图（无 LLM）；超出系统内能力需大模型（L2 架构增强）
   ① 一般复杂意图（系统内能力，无 LLM）：复杂意图库命中（附带 41 能力边界校验：capability_refs 经 41 检索确认能力真实可解析）→ 按链路模板直接驱动完整链路执行
      （复杂意图库由 33-REA 离线训练寻优产出：R-2 交叉验证 → 跨层路径寻优案例 → 复杂意图库）
   ② 超出系统内能力（需 LLM）：L2 架构增强 → DreamOS SACG/DSH 正向编排驱动（大模型正向驱动路径）
   ③ 意图库外意图（unknown）：L2 澄清对话 / 生成式处理 → 案例回流（候选新意图）
   33-REA 链路（s33_rea_spec_enhance 增强 Spec → OKR 节点 → s33_rea_optimal_path 策略评估）
   定位为离线训练寻优链路（产出复杂意图库），非在线执行路径
L1 组合查询层（多意图）
   复合输入 → 意图拆分器 → 子意图编排执行 → 结果聚合
   （拆分置信度不足 → 降级 L2 澄清，FAIL-OPEN）
L0 直接可查层（单一意图）
   现有 15 种意图 + 查询底座适配器：行情 API / 38 data_center / 41 search_cli / 39 mcp
```

**分层判定**：意图识别输出 (intent, complexity)；simple→L0，compound→L1，complex→L2，unknown→L2 澄清。

## 5. 意图类型库自动扩展闭环

```
① 训练 ──→ ② 测试 ──→ ③ 逆向验证 ──→ ④ 扩展 ──→ ⑤ 同步 ──┐
  ▲                                                        │
  └────────────── 案例回流（正/负样本）◄────────────────────┘
```

### ① 训练
- 正向：主前端核心功能完整链路案例（§3.1 四大覆盖域，采集点见 §9.1）；
- 逆向：R-1/R-2/R-3 三大方向案例（33 REA Provider 已接入）；
- 正向训练数据可用于反向训练（同一案例双通道消费）。

### ② 测试（回归门禁）
- 意图回归测试集 intent-regression.jsonl：每意图 ≥3 正例 + ≥2 负例（含边界对抗用例）；
- **holdout 验证集**：每意图 1-2 例独立 holdout，不参与任何训练（含正向案例沉淀与逆向案例回流），仅用于回归测试，作为闭环自增强偏差的独立校验；
- **实体同义词归一化（v0.5 新增，源自 Rasa synonyms 机制）**：建立实体归一化表（symbol 同义词：BTC/比特币/btc→BTC 等），归一化在意图识别后、底座查询前执行；回归测试集用例覆盖同义写法变体（同一意图的同义词用例期望产出一致归一化实体）；
- **负例自动生长**：P2 起，③ 逆向验证的误识别归因产出自动转化为回归负例（误识别案例→期望意图标注→入集），人工仅审核；
- 双通道执行：jest 单测（前端）+ CLI 冒烟（服务端）；任一失败阻断扩展合入。

### ③ 逆向验证
- 自动化规则冲突检测（关键词重叠分析，防泛化词抢占复发）；
- 误识别归因（命中规则链路回放 → 定位冲突规则 → 修复建议）；
- 未覆盖意图发现（need_clarification/simple_qa 高频案例聚类 → 候选新意图提案）；
- **回放模拟训练（v0.5 新增，源自 FreqAI backtesting 机制）**：用历史案例库按时间序重放，模拟多轮扩展闭环运行，对比各轮回归通过率趋势，检测闭环持续运行后的模型退化与自增强偏差走向（与 holdout 互补：holdout 检测单点，回放检测趋势）；
- **规则命中率统计与废弃评审（v0.5 新增，源自 FreqAI 过期模型清理机制）**：统计各 hc_* 规则命中率，长期零命中规则进入废弃评审，防止意图库扩展多轮后旧规则成为死代码。

### ④ 扩展（提案-评审-合入）
- 新意图提案字段：id/name/description/keywords/examples/规则（hc_*）/澄清选项/所属分层（L0-L2）；
- 评审门禁：描述完备 + 与现有意图边界无重叠 + 回归测试全绿（含 holdout 集）；
- 合入点：intent-descriptions.ts + fallback-engine.ts（类型联合+规则表+澄清选项）三处同步；
- **扩展决策记录（v0.5 新增，源自 NIST AI RMF 治理职能，P6 实施）**：每次扩展合入生成决策记录（提案来源/评审依据/合入人/回滚条件），与 33 的 ADR 机制对齐，使意图库演化历史可追溯、可回滚。

### ⑤ 同步 41/38
- **权威源定义**：intent-descriptions.ts 为意图类型库**唯一权威源**；38 侧 intent_registry 表为**只读投影**，不直接写入；
- 38 侧：data_center PG 新建 intent_registry 表，扩展合入时由权威源导出自动 UPSERT；
- **一致性校验**：intent_registry 内容与 intent-descriptions.ts 导出（id/name/keywords/examples/layer）diff 为空才通过验收，diff 非空则告警并阻断该次扩展的同步完成标记；
- 41 侧：意图元数据文档自动生成，固定路径 2-KNOWLEDGE/6-PRODUCT-BUSINESS/INTENT-REGISTRY.md（确保落入 41 索引范围），生成后触发索引更新；
- 同步幂等，失败不阻断主链路（FAIL-OPEN）。

## 8. 风险与局限

- 正向完整链路训练案例体量庞杂：依赖 34 质量门控与 EWMA 衰减控制噪声；
- 闭环自增强偏差：holdout 验证集独立校验（单点）+ 回放模拟训练趋势检测（趋势）+ 人工合入批准 + EWMA 衰减四重缓解；
- 规则顺序匹配抢占风险：P2 冲突检测 + 回归测试集双保险；
- 意图库膨胀与死代码：规则命中率统计 + 废弃评审机制控制；
- R-2/R-3 逆向解析成本：重量层 <5s 预算，复杂意图走异步任务模式；
- 38/41 同步失败：FAIL-OPEN，仅告警不阻断；一致性校验失败阻断同步完成标记但不阻断主链路。

## 9. 薄弱点补强（调研结论）

### 9.1 薄弱点 1：案例覆盖率盘点与各域采集点定义

**调研结论**：settle_case_cli.py 当前仅采集 intent/message/answer/success 四字段，SACG/DSH/子 agent 环节无案例沉淀。『完整链路训练』若不补采集点会退化为『意图识别训练』。

**补强方案（P1.5 实施，前置 M1 桥接设计）**：扩展 settle 案例字段，按域定义采集点：

| 域 | 采集点 | 扩展字段 |
|---|---|---|
| 意图系统 | settle_case_cli（现有） | intent/message/answer/success（现有）+ complexity/entities |
| SACG 编排 | sacg_orchestrator 任务收尾处 | orchestration_plan/子任务分派/各子任务结果 |
| DSH 调度 | DSH 数据源消费处 | source/case_type/质量门控结果 |
| 子 agent | 子 agent 执行收尾处 | agent_id/任务/执行结果/耗时 |
| 三层金融语义 | 39 mcp 消费处（前端调用侧） | 语义层级/查询词/返回摘要 |
| 三层架构 | L0/L1/L2 各层任务收尾 | layer/node_id/验收结果 |

### 9.2 薄弱点 2：R-2/R-3 解析输入定义

**调研结论**：33 现有解析器输入为代码文件/目录（静态解析）；回放池已有执行轨迹类数据（发现树 dt_*.json）；39 的 l3_synthesis/complex_semantics 为统计快照，无推理过程记录。

**补强方案**：
- **R-2 双输入**：①回放池发现树（执行轨迹，数据已存在）②架构代码静态解析（33 现有解析器直接可用）——交叉验证产出跨层路径案例，无需新建解析器；
