## 1. 背景与目标

### 1.1 现状问题

1. 数据与图表页把 10 张图全部平铺：主览图、动态推荐、点亮投影、全景观图同屏，信息过载。
2. 同一张图重复出现：`series:core-assets` / `matrix:signals` 既在主览图，又进入全景观图。
3. 全景选择器按 `kind` 命名，4 张 `series` 都叫“曲线”，无法区分。
4. 统计层 93 个 `D-*` 能力只用了约 11 个，能力出口严重不足。
5. 美股龙头 Top3 已在后端 `stock_ranking.py` 算通，但没有进入统计层/图表层，前端看不到。

### 1.2 目标

- **G1**：一页拆成 8 个子 Tab，每个 Tab 有明确主题，不再全量平铺。
- **G2**：首屏是“能力地图”，展示子 Tab、能力出口与关系，点击节点直接跳转。
- **G3**：16 个标的默认全量计算；排行类卡片默认只展示前 3，可展开全部 16。
- **G4**：尽可能多地暴露能力出口（目标 30+ 个 `D-*` 能力），但不增加前端统计计算。
- **G5**：美股龙头 Top3 进入统计层：新增 `table:us-leaders`，并在 D-E17 类别看板中增加「美股龙头（周度）」分组。
- **G6**：保持 FAIL-OPEN 与数据诚实：样本不足、门禁不通过、降级都必须显式标注，不伪造图。

### 1.3 非目标

- 不新增前端统计计算、不在浏览器里排序/分位/聚合。
- 不新增 `visual.kind`（仍只用 `table/series/matrix/tree/graph`）。
- 不做买卖方向、仓位、交易建议。
- 不把美股龙头组强行合并进 D-E17 的 19 列固定表（列语义不同，会污染口径）。

## 6. 美股龙头专项设计（本次新增）

### 6.1 能力定义：D-E21

| 字段 | 值 |
|---|---|
| id | `D-E21` |
| name | 美股龙头动态排名（周度 Top3） |
| intent | `cross_check` |
| mode | `deterministic` |
| data_scope | `market.candles` |
| executor | `capabilities.us_leaders.us_leaders`（新增模块，内部调用 `l1agg.stock_ranking.compute`） |
| methods | `M01`（20 日动量） |
| min_n | 21 |
| method_binding | `compute` |
| notes | 候选池固定 7 只美股龙头；`rank_score = z(20日均成交额) + z(20日动量)`，截面 z-score 只做排序归一、不新增统计方法；周度 W-MON 冻结；`rank_degraded=true` 时 `rank_source=static` |

为什么必须是新能力而不是挂在 D-E17 下：
- `envelope.py` 强制 `source_capability == capability`、`quality_ref == "quality"`。
- `table:us-leaders` 的质量、样本、降级原因与 D-E17 不同；挂在 D-E17 下会造成质量口径错配。
- 新能力可以独立进地图、独立被推荐、独立降级，符合“能力出口尽可能多”。

### 6.3 `table:us-leaders` 视觉规格

| 项 | 值 |
|---|---|
| id | `table:us-leaders` |
| kind | `table` |
| source_capability | `D-E21` |
| title | `美股龙头（周度 Top3）` |
| n_scope | `per_row` |
| rows | 3 行（Top3）；不截断 |
| columns | `rank`、`symbol`、`score`、`momentum_20d`、`avg_amount_usd`、`pool_version`、`rank_degraded` |
| groups | `[]` |
| caveat | `周度 W-MON 冻结；pool_version=...；rank_source=dynamic/static；rank_degraded=true/false；历史统计，不代表未来。` |

列定义：

| key | label | type |
|---|---|---|
| rank | 排名 | number |
| symbol | 标的 | string |
| score | 综合分 | number |
| momentum_20d | 20日动量 | percent |
| avg_amount_usd | 20日均成交额（美元） | number |
| pool_version | 池版本 | string |
| rank_degraded | 排名降级 | string（`false`/`true`） |

实现要点：
- `visual.py` 的 `_table()` 增加可选 `caveat` 参数（默认仍为 `CAVEAT`），D-E21 producer 传入自定义 caveat。
- `rank_degraded` 用字符串列展示，避免 table schema 不支持 boolean；同时 caveat 中保留原始语义。
- `pool_version` 每行重复，保证单行可独立解释；不新增 table dataset 字段，避免改契约。
- `quality.status`：`rank_degraded=false` 且可用候选 ≥3 → `good`；否则 `partial` 并填 `degraded_reason`。
- `truncated=false`。

## 7. 16 标的池与折叠规则

### 7.1 池定义（待确认）

当前默认池 14 只：BTC、ETH、XAU、XAG、CL、BZ、NG、XCU、US500、US100、DJIA、NVDA、VIX、US10Y。

建议增加到 16 只：**+ SOL + AAPL**。

| 类别 | 标的 |
|---|---|
| 加密 | BTC、ETH、SOL |
| 避险 | XAU、XAG |
| 大宗 | CL、BZ、NG、XCU |
| 美股 | US500、US100、DJIA、NVDA、AAPL |
| 情绪/利率 | VIX、US10Y |

影响：
- `config/asset_pool.yaml` 的 `pools.default` 从 14 → 16。
- `leader_registry.DEFAULT_POOL` 同步。
- `config/chart_weights.yaml` 增加 SOL/AAPL 并重新归一（建议 BTC 0.17、ETH 0.08、XAU 0.10、XAG 0.04、CL 0.08、BZ 0.05、NG 0.03、XCU 0.03、US500 0.10、US100 0.08、DJIA 0.05、NVDA 0.05、AAPL 0.05、SOL 0.04、VIX 0.02、US10Y 0.03）。
- 现有断言 `len(pool) == 14` 需改为 16；`chart_weights` 成员与 `DEFAULT_POOL` 对齐测试同步。
- 如不希望改默认池，可退化为“页面级 16 池”：后端默认池仍 14，前端传 `symbols=` 16 只；但 D-E16 聚合只认 `chart_weights` 成员，SOL/AAPL 不会进入聚合曲线，需在口径中注明。**推荐直接改默认池。**

### 7.2 折叠规则

| 场景 | 默认 | 展开 |
|---|---|---|
| 排行表（16 标的） | 前 3 行 | “展开全部 16” → 16 行 |
| 时间序列（价格/回撤/EWMA） | 1 个主标的 | 主标的下拉切换，不画 16 条线 |
| 矩阵/网络 | 全量 16×16 | 不折叠（16×16 可读） |
| 美股龙头 | Top3 | 固定 3 行，不展开 |
| 点亮投影 | Top5 | “展开全部” |

实现约束：
- 后端负责排序并给 `rank`；前端只 `slice(0, preview_rows)`，不排序。
- `preview_rows` 放在 payload 层（`Record<visualId, number>`），不塞进 `visual.dataset`，避免改契约。
- 展开状态按卡片独立保存；切换 Tab 后可重置。
- 展开按钮带 `aria-expanded`；≤3 行时隐藏按钮。

## 8. 能力地图设计

### 8.1 结构

- 中心节点：`数据与图表`，显示 `16 标的 / 8 子页 / 30+ 能力`。
- 外圈 7 个节点：跨资产、趋势、波动、回撤风险、周期状态、资金拥挤、数据口径。
- 6 条关联虚线：
  1. 跨资产 ↔ 回撤风险（相关/尾部依赖）
  2. 趋势 ↔ 周期状态（斜率/周期相位）
  3. 波动 ↔ 回撤风险（波动/VaR）
  4. 跨资产 ↔ 资金拥挤（资金流/相关）
  5. 周期状态 ↔ 资金拥挤（状态/拥挤）
  6. 趋势 ↔ 波动（趋势/波动率）
- 节点显示：名称 + `N 项能力` + 状态点。
- 侧栏：选中节点的能力清单 + “进入该子页”按钮。
- 点击节点或侧栏按钮 → 切换对应 Tab。

### 8.2 状态诚实

- 首次进入地图时只显示“已接线能力数”，不伪造数据可用性。
- 访问某个 Tab 后，把该 Tab 的加载结果回填为状态点：绿=有数据、黄=部分降级、红=不可用、灰=未加载。
- 图例明确写明“状态在首次进入子页后回填”。

### 8.3 数据来源

- `GET /api/visual/overview?scope=map` 返回：
  ```json
  {
    "ok": true,
    "scope": "map",
    "map": {
      "tabs": [
        {"id": "cross", "label": "跨资产", "capabilities": ["D-E05", "D-E06", "D-E12", "D-E17", "D-E21", "D-J24"]}
      ],
      "relations": [
        {"from": "cross", "to": "risk", "reason": "相关/尾部依赖"}
      ]
    },
    "visuals": []
  }
  ```
- 地图的 3 张全局图（core-assets / signals / lights）由 `scope=map` 一并返回，或复用 `overview` 缓存。
- 能力数量来自后端注册表，前端不硬编码。

## 9. API 与数据契约

### 9.1 Scope

```
GET /api/visual/overview?scope=map&symbols=BTC,ETH,...&base=BTC
```

| scope | 内容 | 预算 |
|---|---|---|
| `map` | 地图元数据 + 3 张全局图 | < 2s |
| `cross` | D-E05/E06/E12/E17/E21/J24 | < 8s |
| `trend` | D-E15/A03/A04/B08/G08/J01 | < 8s |
| `vol` | D-A05/A06/A13/G14/G09 | < 8s |
| `risk` | D-E10/A07/B09/G16/G25/J14 | < 8s |
| `cycle` | D-E03/E07/J04/J05/J13 | < 12s |
| `flow` | D-E18/A14/A15/A16/E16 | < 8s |
| `quality` | D-E12/J29 + 元数据 | < 6s |
| 无 scope | 保持现有全量 payload | 兼容 |

### 9.2 Payload 增量

```json
{
  "ok": true,
  "scope": "cross",
  "symbols": ["BTC", "ETH", "..."],
  "base": "BTC",
  "preview_rows": {"table:volatility": 3, "table:us-leaders": 3},
  "primary": ["series:core-assets", "matrix:signals"],
  "visuals": [...],
  "recommended": [...],
  "unavailable": [...],
  "degraded": false
}
```

- `scope`、`preview_rows`、`primary` 都是 payload 层新增，不进 `visual` 契约。
- `preview_rows` 只对排行表生效；没有该键时前端显示全部。
- 缓存 key：`scope|symbols|base`；默认无 scope 仍用旧 key。

### 9.3 契约

- **不改** `capability_result.schema.json`：`table` 仍只允许 `columns/rows/groups`。
- 新增 D-E21 需要 manifest + executor + producer，属于能力层正常扩展。
- `table:us-leaders` 的 `pool_version` / `rank_degraded` 用列承载，不新增 dataset 字段。
- `_table` 增加可选 `caveat` 参数，属于内部 helper 扩展，不改契约。

### 9.4 性能

- 单资产批量统计在 Python 进程内循环 16 次，不逐资产 spawn。
- 重能力（季节/状态/变点/周期谱）只跑主标的，不做 16 份。
- 每个 scope 单独缓存 60s；地图与跨资产可预取，其余按 Tab 激活懒加载。
- 保持 25s 超时；若某 scope 超时，返回 503 + FAIL-OPEN 空态，不粘住缓存。

## 12. 风险与回滚

| 风险 | 应对 |
|---|---|
| 16 标的批量计算变慢 | 单进程循环；排行类只算轻量统计；重能力只跑主标的 |
| scope 超时 | 25s 超时 + 503 FAIL-OPEN；重能力拆 scope 或后续预计算 |
| 默认池从 14→16 影响回放 | `pool_version`/`chart_weights_hash` 更新；回放记录注明池版本 |
| 美股龙头候选缺失 | `rank_degraded=true` + 静态兜底；前端黄色标注 |
| D-E17 分组混淆口径 | 分组切换，不合并列；美股龙头独立 D-E21 |
| 地图状态伪造 | 首次只显示接线数，访问后回填；图例说明 |
| 文档漂移 | 实施时同步 `v3-frontend-architecture.md` 与 SPEC-54 |

回滚：
- 前端保留旧 `VisualWorkbench` 作为 fallback；`?tab=legacy` 或 feature flag 可回退单页。
- 后端 `scope` 为可选参数；旧调用不受影响。
- D-E21 产不出图时，`table:us-leaders` 不出现，D-E17 原表照常显示。
