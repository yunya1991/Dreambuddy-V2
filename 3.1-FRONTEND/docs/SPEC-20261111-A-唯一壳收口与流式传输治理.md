## 2. 总体设计

```
┌──────────────────────────────────────────────────────────┐
│ 唯一壳：src/app/dashboard/layout.tsx                      │
│  └─ 导航注册表 src/lib/navigation.ts（单一事实源）          │
│     ├─ /dashboard/*            业务面板（现有）             │
│     ├─ /dashboard/agent        Agent 工作台（迁入）         │
│     └─ /dashboard/board/*      审批/提案/评审（迁入）       │
├──────────────────────────────────────────────────────────┤
│ 视图组件：只读 store / 订阅 manager，不持有长连接           │
├──────────────────────────────────────────────────────────┤
│ 流层：task-stream-manager（模块单例，POST SSE）             │
│       monitor-stream-manager（模块单例，EventSource）       │
│       └─ 统一写入 session-store / monitor-store            │
├──────────────────────────────────────────────────────────┤
│ 传输层：api-client.ts（唯一 fetch 实现）                    │
│       └─ v3/api/client.ts（委托，不重复实现）               │
└──────────────────────────────────────────────────────────┘
```

设计原则：

1. **连接与组件解耦**：长连接由模块级 manager 持有，组件只订阅状态。
2. **单一事实源**：导航、错误信封、SSE 去重各自只有一个实现。
3. **最小改动**：不重写 ChatPanel UI，不触碰交易域 P0 组件，不新增依赖。
4. **FAIL-OPEN**：manager 初始化失败只降级为“无流”，不阻塞页面渲染。

### 3.1 导航注册表与壳收口

export type NavSection = 'trading' | 'cognition' | 'collab' | 'ops';

**路由迁移表**：

|---|---|---|

### 3.2 任务流管理器（task-stream-manager）

**新增** `src/lib/stream/task-stream-manager.ts`（无 React 依赖，模块单例）：

```ts
export interface TaskStreamRequest {
  message: string;
  session_id: string;
  thinking_mode?: 'deep' | 'fast';
  lang?: string;
  trading_mode?: string;
  l1_intent_hint?: string;
}

export interface TaskStreamOptions {
  onDone?: (data?: unknown) => void;
  onError?: (err: Error) => void;
}

export function startTaskStream(req: TaskStreamRequest, opts?: TaskStreamOptions): void;
export function abortTaskStream(): void;
export function isTaskStreaming(): boolean;
```

行为契约：

1. `startTaskStream` 先 `abortTaskStream()`，保证同一时刻只有一条任务流。
2. 内部复用现有 [`createSSEConnection`](../../3.1-FRONTEND/src/lib/sse-client.ts) 与 [`createTaskStreamHandlers`](../../3.1-FRONTEND/src/lib/sse-dispatcher.ts)，不重写事件映射。
3. 完成/失败时统一维护 `session-store`：`setStreaming(false)`、新增 `lastTaskError`（新增字段）并通知订阅者。
4. **任务流禁止自动重连**（重连会重复执行交易任务）；失败仅提示，由用户手动重发。
5. SSR 安全：`typeof window === 'undefined'` 时直接返回。
6. 页面卸载不关闭连接；仅 `onDone` / `onError` / 显式 `abortTaskStream()` 关闭。

**ChatPanel 适配**（diff 限定在连接生命周期）：

- 删除 `sseConnectionRef` 与直接 `createSSEConnection` 调用，改调 `startTaskStream`。
- 错误展示改为订阅 `session-store.lastTaskError`；L1 门控、消息写入、UI 结构不变。
- `handleSend` 的请求体字段与顺序保持不变。
- 验收：任务执行中切到 `/dashboard/monitor` 再返回，流式内容持续增长且最终完整；network 面板只有 1 条 `/api/task/stream`。

### 3.3 monitor 流管理器（monitor-stream-manager）

**新增** `src/lib/stream/monitor-stream-manager.ts`：

```ts
export interface MonitorStreamEvent { type?: string; id?: string; phase?: string; [k: string]: unknown }
export type MonitorHandler = (event: MonitorStreamEvent) => void;

export function subscribeMonitor(handler: MonitorHandler): () => void;
export function getMonitorStatus(): 'idle' | 'connecting' | 'open' | 'reconnecting';
```

行为契约：

1. 模块单例 `EventSource`，引用计数：首个订阅创建，最后一个退订关闭。
2. 重连：指数退避 1s → 30s（带抖动），`open` 后重置；`close` 状态不自动重连。
3. 去重：按 `event.id` 维护最近 200 条 LRU，重复事件不再分发。
4. 分发顺序：先分发给订阅者，再由订阅者决定是否写 store（保持现有 `useMonitorData` 的 store 映射逻辑）。
5. `useMonitorData` 改为订阅 manager；10s 轮询逻辑不变。
6. 删除 `useProactiveSSE.ts`（实测 0 引用）；如后续需要主动提醒，在 manager 上新增订阅者，不新建连接。

**验收**：同时打开 `/dashboard/monitor` 与 `/dashboard/trade`，DevTools 仅 1 条 monitor SSE；断网恢复后自动重连且事件不重复。

### 3.4 REST 传输统一

**`api-client.ts`（唯一 fetch 实现）增强**：

- 自动生成 `X-Request-Id`（`crypto.randomUUID()`，非安全上下文降级为时间戳随机串）。
- `ApiException` 增加 `status`、`code`、`traceId`，优先取响应体 `trace_id`/`error.trace_id`。
- 默认 `credentials: 'same-origin'`；保持现有超时与 408 映射。
- 保持 `api.get/post/put/patch/delete` 签名不变，避免业务改造。

**`v3/api/client.ts`**：

- 保留现有导出与调用方式，内部全部委托 `api-client`；删除重复的 `fetch`/错误解析。

**验收**：全仓 `grep -r "fetch(" src/lib src/app` 仅剩 `api-client.ts` 与明确的流式/第三方调用；现有 API 模块测试与页面冒烟通过。

### 3.5 构建门禁恢复

- `next.config.ts` 移除 `typescript.ignoreBuildErrors` 与 `eslint.ignoreDuringBuilds`。
- 先跑 `npx tsc --noEmit`（基线 0 error）→ 再 `npm run build`。
- 若构建暴露非本 SPEC 范围的存量错误：仅修复阻塞构建的最小项，单独提交并记录；不得用 `any`/`@ts-ignore` 掩盖。
