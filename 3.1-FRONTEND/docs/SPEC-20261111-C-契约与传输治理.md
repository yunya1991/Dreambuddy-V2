## 0. 背景与现状证据

| 编号 | 问题 | 证据 |
|---|---|---|
| P-C1 | 响应信封未统一，部分路由直接返回 JSON | [`api-client.ts`](../../3.1-FRONTEND/src/lib/api-client.ts) 同时兼容 `{success,data,error}` 与裸 JSON |
| P-C2 | 错误无统一错误码，前端只能按 HTTP 状态猜 | 同上，`ApiException` 无 `code` |
| P-C3 | SSE 事件字段不统一，去重/重连策略分散 | `monitor` 有 `id/phase`，`task` 无统一 `seq`；A 的 manager 仅做连接层收敛 |
| P-C4 | PlanCard 契约靠手写类型，存在漂移风险 | [`plancard.schema.json`](../../52-lobehub协议集成/schemas/plancard.schema.json) 与前端类型无自动校验 |
| P-C5 | 认知/DSH 通过 `child_process.spawn` 在 Next 侧执行 | [`cognitive-client.ts`](../../3.1-FRONTEND/src/lib/cognitive-client.ts)、`dsh-execution-engine.ts`；与“route.ts 禁止 child_process”硬约束冲突 |
| P-C6 | 无鉴权中间件，dashboard/board/agent 直接可达 | 仓库无 `src/middleware.ts`；原 SPEC §2.7 已列 P0-4 |
| P-C7 | 无版本化与写动作审计约定 | `api-client` 未发送版本头；交易写动作无统一 `trace_id` 留痕 |
| P-C8 | 无 `route.ts` 边界门禁，禁止项靠人工遵守 | 原 SPEC §2.8：基线 `fs` 36 / `child_process` 30，无自动“不得增加”校验 |

### 结论

A 解决了“连接归谁持有”，B 解决了“消息怎么渲染”。C 解决“跨端契约怎么不漂移、后端能力怎么以合规方式到达前端”。C 不改变交易业务逻辑，不新增交易写能力。

## 3. 详细设计

### 3.1 契约层（C-1）

**目录** `src/lib/contracts/`：

```ts
// envelope.ts
export const ERROR_CODES = [
  'AUTH_REQUIRED', 'VALIDATION_FAILED', 'NOT_FOUND', 'RATE_LIMITED',
  'UPSTREAM_TIMEOUT', 'UPSTREAM_ERROR', 'INTERNAL',
] as const;

export interface ApiEnvelope<T> {
  success: boolean;
  data?: T;
  error?: { code: (typeof ERROR_CODES)[number]; message: string; detail?: unknown };
  trace_id: string;
  version: 1;
}
```

- **PlanCard 镜像**：`plancard.ts` 用 `zod` 复刻 `52/schemas/plancard.schema.json` 的必填字段与枚举；不生成代码、不引新依赖。
- **漂移校验**：`tests/contracts/plancard-drift.test.ts` 读取 JSON Schema（测试环境允许 `fs`），断言必填字段集合、枚举值、类型一致；失败输出 diff。
- **脚本**：`npm run check:contracts` = `jest tests/contracts --runInBand`。
- 运行时**禁止**在 `route.ts` 读取该 JSON 文件；只 import zod 镜像。

### 3.2 REST 信封与错误码（C-2）

- `api-client.ts` 解析规则：
  1. 响应体符合 `ApiEnvelope` → 使用 `data/error/trace_id`。
  2. 旧裸 JSON → 包装为 `success:true,data:body`，`trace_id` 取 `X-Request-Id` 或本地生成，并 `console.warn` 一次（按 URL 去重）。
  3. HTTP 非 2xx → 映射错误码：401→`AUTH_REQUIRED`，404→`NOT_FOUND`，422→`VALIDATION_FAILED`，429→`RATE_LIMITED`，504→`UPSTREAM_TIMEOUT`，其余 5xx→`UPSTREAM_ERROR`/`INTERNAL`。
- `ApiException`：`status`、`code`、`traceId`、`detail`、`url`；`message` 保持人类可读。
- 新增/改路由必须返回统一信封；存量路由逐批迁移（P1），未迁移的走兼容分支。

### 3.3 SSE 协议 v1（C-3）

**事件结构**（服务端推送，字段可增不可删）：

```ts
export interface SSEEventV1<T = unknown> {
  id: string;            // 全局唯一，用于去重
  seq: number;           // 单会话单调递增，用于乱序检测
  type: 'started' | 'thinking' | 'progress' | 'step' | 'report' | 'done' | 'error' | 'heartbeat';
  trace_id: string;
  session_id?: string;
  ts: number;            // epoch ms
  payload: T;
}
```

客户端规则（在 A 的 manager 上扩展）：

1. **兼容**：缺少 `seq/type` 的旧事件按 `legacy` 处理，`id` 缺失时用 `type+ts+hash(payload)` 生成去重键。
2. **去重**：`id` LRU 200；同一 `session_id` 的 `seq` 回退视为乱序，丢弃并计数。
3. **心跳**：服务端每 15s 发送 `: ping`；客户端 45s 无任何消息判定半开，monitor 触发重连，task 标记失败（不自动重跑）。
4. **重连**：仅 monitor 使用 `Last-Event-ID`；task 永不自动重连（避免重复执行）。
5. **未知 `type`**：忽略并计数，不抛错。
6. **顺序**：`started → thinking/progress* → step* → report? → done|error`；越级不阻断渲染，只告警。

迁移策略：服务端**增量加字段**；客户端先兼容旧格式，待 v1 稳定后再要求必填。

### 3.4 缓存层（C-4）

- 新增依赖：`@tanstack/react-query`（仅此一个；不引 devtools）。
- Provider：在 `src/app/dashboard/layout.tsx` 的客户端边界挂 `QueryClientProvider`；`/chat`、`/agent` 兼容。
- 职责边界：

| 数据 | 归属 | 规则 |
|---|---|---|
| 列表/详情/统计等 REST 查询 | Query | `staleTime` 30s（行情类 5s），`retry: 1` |
| SSE 实时事件、流式内容 | zustand | 只写实时字段，不写 Query 缓存 |
| 交易持仓/余额 | Query（REST 拉取）+ zustand（SSE 增量） | 以 `updated_at` 较新者为准，禁止无条件双写 |

- 统一 query key：`['domain', 'resource', params]`；写操作后按 domain 失效，不做全量 `invalidateQueries()`。
- 验收：同一请求 5s 内重复挂载只发 1 次；任务流写入不触发 Query 重取。

### 3.5 认知 / DSH 代理化（C-5）

**目标**：前端 `route.ts` 只做 HTTP 转发，不 `spawn`、不直接 `fs`。

新增路由（仅 `fetch`）：

- `POST /api/cognitive/recall` → `{ context, top_k, min_quality }`
- `POST /api/cognitive/record` → `{ content, quality_level, tags, source }`
- `POST /api/cognitive/verify` → `{ memory_id, success }`
- `POST /api/dsh/execute` → `{ capability, payload, trace_id }`

环境变量：

- `COGNITIVE_API_BASE`、`DSH_API_BASE`（服务端读取；未配置返回 503 `UPSTREAM_ERROR` + `degraded:true`）。
- 超时：认知 10s、DSH 60s；失败 FAIL-OPEN，前端降级提示。

迁移：

1. 保留 `cognitive-client.ts` 的对外函数签名，内部从 `spawn` 改为 `api.post('/api/cognitive/*')`。
2. `dsh-execution-engine.ts` 同理改为 `/api/dsh/execute`。
3. 后端代理可用性由 `GET /api/cognitive/health` 探活；不可用时前端展示“认知服务未连接”。
4. **待确认**：后端是否已有 HTTP 入口（`dsh_frontend_bridge.py` 当前经 stdio/IPC）。若无，本项 P2 阻塞，需后端先提供 HTTP adapter。

### 3.6 鉴权中间件（C-6）

- 新增 `src/middleware.ts`，复用现有 NextAuth 配置（`next-auth` 已在依赖中）。
- `matcher`：`/dashboard/:path*`、`/agent`、`/board/:path*`；排除 `/_next`、`/api/auth`、`/login`、`/register`、`/verify-email`、静态资源。
- `AUTH_REQUIRED`：dev 默认 `false`，production 默认 `true`；未登录重定向 `/login?next=<path>`。
- 不改 API 内部鉴权；仅做页面级门禁。
- 验收：开关打开时未登录无法进入；登录后回跳原路径；公开页正常。

### 3.7 版本与审计（C-7）

- `api-client` 默认发送 `X-API-Version: 1`；响应 `version` 缺失视为 legacy，仅 warn。
- 写请求（POST/PUT/PATCH/DELETE）必须携带 `trace_id`（A 已生成）；响应回传同值，前端记录 `console.info`（dev）。
- 交易写动作审计字段（后端持久化，前端只传）：
  `trace_id / actor / action / resource / symbol? / result / ts`。
- 前端新增 `X-Audit-Source: web`；未知头对后端无副作用。
- 验收：下单/审批写请求可在后端日志按 `trace_id` 串起前后端。

### 3.8 边界门禁（C-8）

- 新增 `scripts/check-route-boundary.mjs`：
  - 扫描 `src/app/api/**/route.ts`，统计 `from 'child_process'` / `execFile|spawn|exec(` / `from 'fs'|'fs/promises'|readFile|writeFile`。
  - 基线：`fs=36`、`child_process=30`（原 SPEC §2.8）；**只允许下降，不允许增加**。
  - 输出新增文件与行号，退出码 1。
- 接入 `package.json`：`"check:boundary": "node scripts/check-route-boundary.mjs"`；CI 与 pre-commit 执行。
- 本 SPEC 新增的 cognitive/DSH 代理路由不得引入 `fs/child_process`。

## 7. 风险与开放问题

| 编号 | 风险 | 默认建议 |
|---|---|---|
| R-C1 | 后端短期不返回统一信封 | 前端兼容层 + 按 URL 仅 warn 一次；逐路由迁移 |
| R-C2 | SSE v1 服务端改造成本 | 先加字段不改旧字段；客户端兼容先行 |
| R-C3 | Query 与 zustand 双写冲突 | 明确字段所有权；以 `updated_at` 仲裁 |
| R-C4 | 认知/DSH 后端无 HTTP 入口 | P2 阻塞，不做前端 `spawn` 兜底；保持现有本地模式并记录债务 |
| R-C5 | 鉴权开启导致本地开发不便 | dev 默认关闭；文档写明开启方式 |
| R-C6 | 边界脚本误报（测试文件/注释） | 仅扫描 `src/app/api/**/route.ts`；忽略注释行 |
| R-C7 | `X-API-Version` 被网关丢弃 | 前端仅 warn，不阻断；版本以 URL/响应为准 |

### 开放问题（默认决策）

- O-C1：是否引入 Query？默认：引入 1 个依赖，仅 P1 启用；若包体预算紧张可延后。
- O-C2：认知/DSH 后端 HTTP 入口谁提供？默认：后端 `dsh_frontend_bridge` 暴露 HTTP adapter，前端只消费。
- O-C3：是否强制所有存量路由迁移信封？默认：不强制，新/改路由必须；存量按域逐步。
