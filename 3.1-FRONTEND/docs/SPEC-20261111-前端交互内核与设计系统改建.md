## §2 总体设计

### 2.1 分层

```text
┌──────────────────────────────────────────────┐
│ Shell 层：dashboard layout（侧栏/鉴权/错误边界/toast）│
├──────────────────────────────────────────────┤
│ 页面层：/dashboard/*（交易域，本期不改）              │
│         /dashboard/agent（协议层对话，本期重点）      │
├──────────────────────────────────────────────┤
│ 对话内核层（本期新建）：                              │
│   message-parts/（part 注册表 + 渲染器）              │
│   tool-card/ plan-card/ stream-state/              │
├──────────────────────────────────────────────┤
│ 设计系统层：V3 primitives + tokens + icons          │
├──────────────────────────────────────────────┤
│ 协议层：/api/agent/chat（AI SDK + MCP，已在）        │
└──────────────────────────────────────────────┘
```

**复用原则**：对话内核是“渲染器 + 状态机”，不绑定具体后端。交易域 ChatPanel（SSE `/api/task/stream`）与协议层 Agent（AI SDK `/api/agent/chat`）通过 **adapter** 各自喂入统一的 part 流，避免重写 ChatPanel。

### 2.2 路由与壳层

| 现状 | 目标 |
|---|---|
| `/agent`（独立 `h-screen`） | `/dashboard/agent`（dashboard layout 内） |
| 侧栏 12 项 | 新增第 13 项「Agent」，图标用 `V3InlineSVG` 扩展 |
| `/chat` | 保留（交易域旧入口），不新增导航 |

- `/agent` 保留 `redirect('/dashboard/agent')` 兼容旧链接。
- 侧栏导航数据抽为 `src/lib/navigation.ts`，layout 只负责渲染（降低 300 行单文件压力）。

### 2.3 消息 Part 契约（核心）

```ts
// src/types/agent-message.ts
export type AgentPart =
  | { type: 'text'; text: string }
  | { type: 'reasoning'; text: string; durationMs?: number }
  | {
      type: 'tool';
      callId: string;
      toolName: string;
      state: 'pending' | 'running' | 'success' | 'error';
      args?: Record<string, unknown>;
      result?: unknown;
      error?: string;
      durationMs?: number;
    }
  | { type: 'plan-card'; card: PlanCard }
  | { type: 'artifact'; artifactId: string; title: string; kind: 'report' | 'chart' | 'file' }
  | { type: 'verification'; verdict: 'PASS' | 'BLOCK' | 'INCONCLUSIVE'; evidenceRefs: string[] };
```

- 与 AI SDK `UIMessage.parts` 做**单向映射**（`text` / `reasoning` / `tool-*` 直接映射），不改造 AI SDK 类型。
- 渲染入口 `src/components/features/agent/PartRenderer.tsx`，按 `part.type` 查注册表；未知类型降级为 JSON 折叠块并记录 `console.warn`（FAIL-OPEN）。
- 交易域适配器 `src/lib/adapters/sse-to-parts.ts`：把现有 9 类 SSE 事件映射为 part（`thinking → reasoning`、`progress → tool(state=running)`、`done → text`）。P1 实施，P0 仅协议层使用。

### 2.4 工具调用卡片契约

| 状态 | 展示 | 交互 |
|---|---|---|
| pending | 灰色圆点 + 工具名 + “排队中” | 可展开看 args |
| running | 蓝色脉冲 + 工具名 + 已耗时 | 可展开看 args；不可折叠隐藏状态 |
| success | 绿点 + 工具名 + 耗时 + 结果摘要 | 默认折叠；展开看 result（Markdown / JSON 美化）；复制按钮 |
| error | 红点 + 工具名 + 错误首行 | 默认展开；展开看 error + args；重试按钮（仅协议层） |

- 组件：`src/components/features/agent/ToolCard.tsx`。
- 结果渲染复用 `react-markdown`；长结果折叠阈值 12 行。

### 2.5 PlanCard 渲染契约

- **单一事实源**：`52-lobehub协议集成/schemas/plancard.schema.json`。
- 3.1 侧新增脚本 `scripts/gen-plancard-types.mjs`（或 `zod` 手写等价 schema），生成 `src/types/plancard.generated.ts`；`npm run check:plancard` 做 drift 校验。
- 渲染组件 `PlanCardView`：
  - 头部：`intent` + `debate_meta.verdict` 徽标（WIN/LOSE/INCONCLUSIVE 三态配色）。
  - `plan_steps`：步骤列表，`tool` 必须显示注册名（未知工具标红，呼应 schema 硬约束）。
  - `risk_flags`：命中即红色分组。
  - `validation`：`evaluator_refs` 可点开证据（P0 先只展示文本）。
- 复用点：`chain/BullBearDebate.tsx` 增加“查看 PlanCard”入口（P1）。

### 2.6 设计 token 契约

在 `globals.css` 补全并在 `@theme inline` 映射（命名保持 `--color-*`）：

```text
背景：--color-bg-primary / --color-bg-secondary / --color-bg-elevated
文字：--color-text-primary / --color-text-secondary / --color-text-muted
边框：--color-border / --color-border-strong
状态：--color-status-success / --color-status-warning / --color-status-danger / --color-status-info
SACG：--color-sacg-s / --color-sacg-a / --color-sacg-c / --color-sacg-g（保留现值）
```

- 新增 `src/lib/design-tokens.test.ts`：正则扫描 `var(--color-*)` 引用，断言全部在 `globals.css` 有定义（防 P-01 复发）。
- 侧栏图标改为 `V3InlineSVG` 新增 13 个导航图标（不引图标库）。
- 本期不做明暗主题切换，但 token 分层必须支持后续接入。

### 2.7 稳定性与反馈契约

| 项 | 方案 |
|---|---|
| 错误边界 | `src/app/error.tsx`（路由级）+ `src/app/global-error.tsx`；展示错误摘要与“重试” |
| 统一反馈 | `src/components/feedback/ToastProvider.tsx` + `useToast()`；仅覆盖新改页面，不批量替换旧代码 |
| 构建门禁 | `ignoreBuildErrors: false`（基线 0 error）；`ignoreDuringBuilds` 先保留，lint 清单化后 P1 关闭 |
| 鉴权 | `src/middleware.ts`：保护 `/dashboard/*`、`/board/*`、`/agent`；公开 `/login`、`/register`、`/verify-email`、`/api/auth/*`；开关 `AUTH_REQUIRED=true`（dev 默认 false，生产 true） |

### 2.8 请求边界契约

- 新增/修改的 `route.ts` 禁止 `child_process`、禁止直接 `fs` 读业务数据；数据经 `l0_gateway`（MCP）或既有 HTTP 服务。
- 存量计数作为基线（`fs` 36 / `child_process` 30），CI 或脚本 `scripts/check-route-boundary.mjs` 只做“不得增加”校验。
- `/api/agent/chat` 维持只读：不新增写工具；写工具由服务端拒绝（现状保持）。
