# ADR-001：采用双层记忆架构（总记忆 + 应用记忆）

> **状态**: 提议中（Proposed）
> **日期**: 2026-07-26
> **决策者**: DreamBuddy v2 团队
> **影响范围**: 全项目记忆体系

---

## 1. 背景（Context）

### 问题陈述

随着项目规模扩大，积累的经验和教训越来越多，但面临以下问题：

1. **经验散落在各处**：每个子系统有自己的记忆和经验，但没有统一的入口和索引
2. **经验无法跨系统复用**：11 号系统踩过的坑，16 号系统可能再踩一遍
3. **没有阶梯式积累**：每次换环境、换人员，很多东西要从头来
4. **原则和方法论没有沉淀**：好的做法没有提炼成可复用的方法

### 已有基础

项目中已经有 4 处记忆相关实现：

| 实现 | 位置 | 成熟度 |
|------|------|--------|
| L4 记忆系统 | 11-易经推理系统/scripts/memory_l4/ | 高（标杆） |
| dreamos memory | 1-ARCHITECTURE/dreamos/core/memory/ | 中 |
| ab-trading memory | experiments/ab-trading/core/memory/ | 中 |
| 4-MEMORY 设计 | 4-MEMORY/ | 低（设计文档） |

---

## 2. 决策考虑（Decision Drivers）

1. **系统规模大**：20+ 子系统，不可能用单一记忆系统覆盖所有场景
2. **各子系统差异大**：交易、风控、运维、实验的记忆类型和结构完全不同
3. **需要独立性**：各子系统应该能独立演进自己的记忆体系
4. **需要统一性**：又需要有统一的入口和索引，方便跨系统查找
5. **需要阶梯式积累**：从具体经验 → 通用教训 → 方法论 → 原则

---

## 3. 考虑过的选项（Considered Options）

### 选项一：大一统记忆系统

一个中央记忆系统，所有子系统的记忆都存在里面。

**优点**：
- 统一管理，统一接口
- 跨系统检索方便

**缺点**：
- 系统太复杂，难以设计和维护
- 各子系统的记忆类型差异大，很难统一 schema
- 子系统记忆演进受总系统制约，不够灵活
- 单点故障风险

---

### 选项二：完全分散，各搞各的

每个子系统完全独立的记忆系统，互不干涉。

**优点**：
- 灵活性最高，各子系统自由发展
- 没有耦合，互不影响

**缺点**：
- 没有统一入口，找东西要到处翻
- 经验无法跨系统复用
- 没有全局视角，无法提炼通用方法论
- 重复造轮子，每个系统都要自己搞一套

---

### 选项三：双层架构（总记忆 + 应用记忆）← 推荐

总记忆系统管全局（索引、原则、方法论、通用经验），应用记忆系统管具体（各子系统自己的记忆）。

**优点**：
- 灵活性和统一性的平衡
- 总记忆轻量，应用记忆厚重
- 各应用记忆可以独立演进
- 又有统一的入口和索引
- 符合"瘦中枢，胖边缘"的设计理念

**缺点**：
- 需要设计清晰的边界和接口
- 需要维护索引和路由
- 蒸馏上升机制需要设计

---

## 4. 决策（Decision）

**选择选项三：双层记忆架构**

具体设计：

### 总记忆系统（Global Memory）

**定位**：全局索引 + 通用经验 + 原则方法论

**包含**：
- 原则记忆：工程原则、规范、工作流
- 方法论记忆：矛盾论、A1调研法、A8校验法
- 架构记忆：当前架构、演进历史、ADR
- 文档记忆：文档索引、文档债、对齐状态
- 通用经验：技术教训、流程教训、最佳实践、反模式
- 应用记忆索引：注册表、路由表、健康状态

**能力**：
- 只读索引
- 被动更新
- 蒸馏汇聚
- 统一检索入口

---

### 应用记忆系统（Application Memory）

**定位**：各子系统专属记忆，由子系统主动维护

**已知应用记忆**：
- 交易应用记忆（11 号 L4 记忆系统，标杆）
- 实验应用记忆（ab-trading memory）
- 编排应用记忆（dreamos memory）
- 风控应用记忆（待建设）
- 运维应用记忆（待建设）

**统一接口要求**：
- search（检索）
- add（添加）
- update（更新）
- get（获取单条）
- stats（统计）
- distill_candidates（蒸馏候选）
- healthcheck（健康检查）

---

### 协作机制

```
应用记忆产生新经验
        │
        ▼
  蒸馏候选生成（应用记忆侧）
        │
        ▼
  总记忆系统审核（人工/自动）
        │
        ├── 通过 → 提炼为通用经验，存入总记忆
        ├── 待定 → 标记观察，等更多验证
        └── 驳回 → 保留在应用记忆中，不上报
```

---

## 5. 后果（Consequences）

### 正面后果

- ✅ 各子系统可以独立演进记忆体系
- ✅ 又有统一的入口和索引，方便查找
- ✅ 经验可以从应用记忆蒸馏上升到总记忆
- ✅ 总记忆轻量，维护成本低
- ✅ 符合"瘦中枢，胖边缘"的架构原则
- ✅ 阶梯式积累：具体经验 → 通用教训 → 方法论 → 原则

### 负面后果

- ⚠️ 需要维护索引和路由，有一定维护成本
- ⚠️ 边界需要清晰划分，否则容易混乱
- ⚠️ 蒸馏上升机制需要设计和实现
- ⚠️ 初期需要投入精力搭框架
