## 什么是通用经验？

通用经验是从各子系统的具体经验中**蒸馏提炼**出来的、跨系统适用的共性经验。

```
具体案例（应用记忆）
    ↓ 蒸馏
通用经验（总记忆）
    ↓ 再蒸馏
方法论记忆
    ↓ 再蒸馏
原则记忆
```

越往上越抽象、越通用，但数量越少。

## 经验分类

### 技术教训（TECH_LESSONS.md）

从技术踩坑中总结的教训。

**示例**：
- subprocess + shlex.split 在设置 PYTHONPATH 时会失败
- launchd 任务 label 要从安装脚本中查，不要猜
- 高 CPU 进程要检查是不是崩溃重启循环

---

### 流程教训（PROCESS_LESSONS.md）

从工作流程中总结的教训。

**示例**：
- 改动之前先调研，不要上来就改
- 修复 bug 先复现再动手
- 上线之前想好回滚方案

---

### 最佳实践（BEST_PRACTICES.md）

经过验证的高效做法。

**示例**：
- 用 A1 调研法指导调研工作
- 用 A8 校验法检查文档-代码一致性
- 用矛盾论找主要矛盾

---

### 反模式（ANTI_PATTERNS.md）

经过验证的错误做法，要避免。

**示例**：
- 上来就改，从不调研
- 只看文档，不看代码
- 眉毛胡子一把抓，不分主次
- 发现问题不改，只写报告

## 经验质量分级

| 等级 | 说明 | 验证要求 |
|------|------|---------|
| A 级 | 经过多次验证，高度可信 | ≥3 次独立验证 |
| B 级 | 有一定证据，待更多验证 | 1-2 次验证 |
| C 级 | 初步观察，未验证 | 0 次验证 |
| D 级 | 已证伪，不可信 | 已发现反例 |

## 上升路径

### 从应用记忆到通用经验

1. 应用记忆中产生新的案例/经验
2. 应用记忆系统生成蒸馏候选
3. 总记忆系统审核候选
4. 审核通过 → 存入通用经验，初始等级 B 或 C
5. 持续验证 → 等级逐步提升

### 从通用经验到方法论

- 多条相关的通用经验可以提炼为方法论
- 方法论是更系统、更结构化的经验
- 例：多条调研相关的经验 → A1 调研方法论

### 从方法论到原则

- 经过大量验证的方法论核心，可以上升为原则
- 原则是最高层级的指导
- 例：多个方法论都强调调研 → "调研优先原则"
