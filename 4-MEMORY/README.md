# 4-MEMORY — DreamBuddy-V2 AI 记忆系统

> **版本**: v5.0 | **更新日期**: 2026-07-27
> **定位**: 面向 AI Agent 的记忆系统（AI Context Index）— V5 记忆单元分区
> **一句话**: 让 AI 具备阶梯式积累能力 — 记忆是 AI 开发的思维链路基础设施
> **核心闭环**: 传统文档(理论) → 蒸馏 → AI 记忆(上下文) → 代码实践 → A8校验 → 反哺文档

---

## 这是什么？

4-MEMORY 是 DreamBuddy-V2 的 **AI 专属记忆系统**，它不是给人读的文档，而是给 **AI Agent** 在开发时读取的**结构化上下文索引**。

它解决的核心痛点是：
- **防止 AI 失忆**：下次对话时 AI 能记住之前的开发原则和架构决策
- **提升开发效率**：AI 能直接检索到关键经验，而不必每次都从零开始调研
- **理论实践结合**：AI 基于“记忆”（理论）进行代码开发，开发完成后反向更新“记忆”（理论闭环）

详细闭环流程见 [MEMORY_SYSTEM_ARCHITECTURE.md §7](./MEMORY_SYSTEM_ARCHITECTURE.md)

## 核心设计：双层记忆架构

```
┌─────────────────────────────────────────────────────────┐
│  总记忆系统（4-MEMORY） — 全局索引 + 通用经验 + 原则方法  │
│  能力：只读索引 + 被动更新 + 蒸馏汇聚                     │
└───────────────┬─────────────────────┬───────────────────┘
                │ 索引/检索            │ 蒸馏/汇聚
                ▼                     ▲
┌───────────────┴───────┐  ┌──────────┴───────────────────┐
│  应用记忆：交易 L4     │  │  应用记忆：风控/运维/实验...  │
│  能力：读写 + 主动更新  │  │  能力：读写 + 主动更新        │
└───────────────────────┘  └──────────────────────────────┘
```

**关键原则**：
- 总记忆只管**索引和全局**，不管具体内容
- 应用记忆由**各子系统主动维护**，总记忆不越权
- 应用记忆 → 总记忆 是**蒸馏提炼**，不是简单复制
- 总记忆通过**索引被动感知**应用记忆的更新

详细设计见 [MEMORY_SYSTEM_ARCHITECTURE.md](./MEMORY_SYSTEM_ARCHITECTURE.md)

## 设计原则

1. **瘦中枢，胖边缘** — 总记忆轻量，应用记忆厚重
2. **被动更新** — 总记忆不主动修改应用记忆
3. **蒸馏不复制** — 上升到总记忆的是提炼的经验，不是原始数据
4. **来源可追溯** — 每条记忆有来源、有时间、有验证状态
5. **可证伪可更新** — 记忆不是真理，是可以被推翻的假设
6. **工具化优先** — 记忆的读写检索通过标准化接口
