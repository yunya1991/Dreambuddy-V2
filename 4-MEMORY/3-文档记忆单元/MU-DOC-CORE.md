# MU-DOC-CORE — 文档记忆单元核心

> 单元: MU-DOC | 容量: ≤ 1,000 字符 | 上次压缩: 2026-07-27 | 当前占用: ~60%
> 记忆类型: Procedural (程序记忆) + Semantic (语义记忆)

## 文档管理原则（S级 — 程序记忆）

- 文档先于代码：先形成技术文档，再开始落地实现
- 文档统一管理应先于代码重构：文档-代码对齐能发现隐藏缺陷
- 单一入口：全项目文档只有一个总入口（0-系统文档管理/README）
- SSoT：传统文档是唯一事实来源，AI记忆是其摘要和索引

## 文档规范要点（A级 — 语义记忆）

- 子系统docs/必须有：ENGINEERING_INDEX.md / TECHNICAL_DESIGN.md / API_SPEC.md / CHANGELOG.md
- 根目录README.md负责导航，详细内容指向0-系统文档管理
- 文档变更与代码变更在同一个PR中完成

## 文档治理经验（A级 — 情景→语义）

1. 子系统并行目录导致路径引用混乱，统一后须检查所有跨子系统引用
2. ENGINEERING_INDEX严重过时会导致开发误导，需定期审计
3. 索引断链（引用了不存在的文件）比内容缺失更隐蔽，危害更大
