# MEMORY_UNITS — 记忆单元管理规范

> **版本**: v1.0 | **更新日期**: 2026-07-27
> **定位**: 记忆单元分区的元规范，定义单元的创建、管理、容量与压缩规则

---

## 1. 什么是记忆单元？

记忆单元（Memory Unit, MU）是按**功能域**划分的记忆分区，借鉴人类大脑的分区记忆原理：

- 人类大脑中，海马体负责情景记忆，皮层负责语义记忆，小脑负责程序记忆
- AI 记忆系统中，不同功能域的记忆分离存储，避免检索干扰和容量竞争

---

## 2. 记忆单元清单

| 代码 | 名称 | 功能域 | CORE 容量 | 单元总容量 | 当前状态 |
|------|------|--------|-----------|-----------|---------|
| MU-DEV | 开发记忆单元 | 代码工程、开发流程、技术栈 | ≤ 2,000 字符 | ≤ 12,000 字符 | ✅ 已建立 |
| MU-TRD | 交易记忆单元 | 交易策略、信号规则、风控参数 | ≤ 2,000 字符 | ≤ 12,000 字符 | ✅ 已建立 |
| MU-DOC | 文档记忆单元 | 文档规范、治理流程、债务跟踪 | ≤ 1,000 字符 | ≤ 8,000 字符 | ✅ 已建立 |
| MU-INF | 信息记忆单元 | 数据源、信息分类、验证机制 | ≤ 1,000 字符 | ≤ 8,000 字符 | ✅ 已建立 |

**总 Tier 0 容量**: 2,000 + 2,000 + 1,000 + 1,000 = 6,000 字符 ≤ 8,000 字符上限

## 3. 单元内部结构

每个记忆单元必须包含以下子目录：

```
MU-xxx/
├── MU-xxx-CORE.md       # 单元核心记忆（程序记忆精华）
├── episodic/            # 情景记忆：具体案例、踩坑、事件
├── semantic/            # 语义记忆：知识、原则、架构决策
└── procedural/          # 程序记忆：流程、步骤、标准操作
```

### 记忆类型定义

| 记忆类型 | 人类对应 | 内容特征 | 示例 |
|---------|---------|---------|------|
| **episodic** | 情景记忆 | 具体、一次性的经历 | "某次subprocess失败"、"D048修复过程" |
| **semantic** | 语义记忆 | 抽象、可泛化的知识 | "subprocess+shlex.split会失败"、"文档先于代码" |
| **procedural** | 程序记忆 | 流程、步骤、肌肉记忆 | "开发前必须执行A1调研"、"A8校验5步法" |

### 记忆演化路径

```
episodic（情景） → 反复验证 → semantic（语义） → 反复验证 → procedural（程序）
   "某次踩坑"         提炼规律      "这个模式会失败"      内化为流程      "开发必须先调研"
```

## 4. 容量管理

### 4.1 三级容量体系

| 层级 | 范围 | 容量限制 | 触发动作 |
|------|------|---------|---------|
| **Tier 0** | MU-xxx-CORE.md | ≤ 2,000（DEV/TRD）/ ≤ 1,000（DOC/INF） | ≥ 80% 触发 consolidation |
| **Tier 1** | MU-xxx/ 下所有文件 | ≤ 12,000（DEV/TRD）/ ≤ 8,000（DOC/INF） | ≥ 80% 触发蒸馏归档 |
| **Tier 2** | archive/MU-xxx/ | 不限 | 定期清理超期记忆 |

### 4.2 Consolidation 规则

当 MU-xxx-CORE.md 达到 80% 容量时：

1. **压缩表达**：将长句压缩为短句，保留结论删除解释
2. **低等级让位**：episodic 记忆移入 semantic，semantic 移入 procedural
3. **跨单元协调**：如 MU-DEV 膨胀，优先压缩 MU-DEV 内部，不侵占其他单元配额
4. **归档释放**：D 级或过时记忆移入 archive/MU-xxx/

## 5. 记忆单元路由

AI Agent 读取记忆时，按以下优先级路由：

```
query → 判断功能域 → 定位记忆单元 → 读取 MU-xxx-CORE.md
                                    ↓
                            如需详细信息 → 检索 episodic/semantic/procedural/
                                    ↓
                            如需原始文档 → 根据索引路径读取 0-系统文档管理/
```

### 功能域判断规则

| 关键词/场景 | 目标单元 |
|------------|---------|
| 代码、开发、A1、A8、subprocess、launchd | MU-DEV |
| 交易、策略、信号、BCRM、离场、L4、case | MU-TRD |
| 文档、规范、API_SPEC、CHANGELOG、债务 | MU-DOC |
| 索引、路由、注册表、应用记忆、接口 | MU-INF |

---

## 6. 新增记忆单元流程

如需新增记忆单元（如 MU-RSK 风控记忆单元）：

1. 在 0-元记忆/MEMORY_UNITS.md 中注册单元代码和配额
2. 创建 `MU-xxx/` 目录及 `episodic/semantic/procedural/` 子目录
3. 创建 `MU-xxx-CORE.md` 初始版本
4. 更新 4-MEMORY/README.md 导航表
5. 更新 MEMORY_SYSTEM_ARCHITECTURE.md §6.2 单元配额表
