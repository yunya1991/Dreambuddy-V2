# 记忆生命周期 — MEMORY LIFECYCLE

> **版本**: v1.0
> **更新日期**: 2026-07-26
> **定位**: 元记忆 — 定义记忆从产生到消亡的全生命周期
> **等级**: S（公理级）

---

## 0. 生命周期总览

```
创建 → 验证 → 活跃 → 衰减 → 归档 → 删除
  │       │       │       │       │
  │       │       │       │       └── 超过保留期，移入归档
  │       │       │       └── 长期未被引用，降低优先级
  │       │       └── 被检索和引用，保持活跃
  │       └── 经过实践验证，标记为可信
  └── 从经验/案例/决策中产生
```

---

## 1. 各阶段详解

### 1.1 创建阶段（Created）

**触发条件**：
- 从具体案例/经验中提炼出可复用的结论
- 从架构决策/设计评审中产生
- 从复盘总结中提取

**进入标准**：
- 有明确的来源和背景
- 有清晰的内容描述
- 有初步的适用场景
- 已分配唯一 ID

**质量等级**：初始为 C（假设级）或 B（待验证），视来源可靠性而定

**输出**：一条完整的记忆条目（含元数据和正文）

---

### 1.2 验证阶段（Verifying）

**触发条件**：记忆被创建后，进入验证队列

**验证方式**：

| 验证方式 | 说明 | 适用类型 |
|---------|------|---------|
| 实践验证 | 在实际工作中应用并确认有效 | 方法论、最佳实践 |
| 交叉验证 | 多个独立来源得出相同结论 | 经验教训、反模式 |
| 逻辑验证 | 通过逻辑推理确认正确性 | 原则、架构决策 |
| A/B 验证 | 通过对比实验验证效果 | 策略、参数优化 |

**升级条件**：
- 从 C → B：至少 1 次有效验证
- 从 B → A：至少 3 次独立验证
- 从 A → S：至少 10 次独立验证 + 长时间有效

**降级/证伪条件**：
- 发现反例，证明记忆有误 → 降为 D（已证伪）
- 适用场景发生变化，记忆不再适用 → 标记为过时
- 有更好的替代方案 → 旧记忆标记为已替代

**退出标准**：
- 质量等级发生变化（升级或降级）
- 或验证周期超时（默认 90 天未验证，维持原等级）

---

### 1.3 活跃阶段（Active）

**触发条件**：记忆验证通过，进入活跃使用状态

**特征**：
- 可以被检索和引用
- 定期被访问和使用
- 持续接收新的验证反馈

**维护动作**：
- 每次被引用后更新 `last_used_at` 时间
- 收集使用反馈，评估是否需要更新
- 定期（每季度）回顾是否仍然有效

**质量等级**：B 级及以上

---

### 1.4 衰减阶段（Decaying）

**触发条件**：
- 长期未被引用（默认 180 天）
- 使用频率持续下降
- 有更新的替代记忆出现

**特征**：
- 仍然可检索，但优先级降低
- 搜索结果中排在活跃记忆后面
- 标记为"建议验证"，提醒使用者确认

**维护动作**：
- 降低检索权重
- 标记衰减状态
- 触发一次有效性复核

**退出条件**：
- 重新被频繁引用 → 回到活跃阶段
- 复核确认仍然有效 → 回到活跃阶段
- 复核确认已过时 → 进入归档阶段

---

### 1.5 归档阶段（Archived）

**触发条件**：
- 记忆已过时或不再适用
- 但仍然有历史参考价值
- 不适合直接删除

**特征**：
- 正常检索不返回（默认不显示）
- 需要显式查询归档才能找到
- 标记为归档状态，附带归档原因

**归档原因**：
- 技术演进：技术栈变化，记忆不再适用
- 架构变更：系统架构变化，相关记忆失效
- 更好替代：有更好的记忆替代了这条
- 适用场景消失：原适用场景不再存在

**保留期限**：
- S 级记忆：永久归档
- A 级记忆：归档保留 2 年
- B 级记忆：归档保留 1 年
- C 级记忆：归档保留 90 天

---

### 1.6 删除阶段（Deleted）

**触发条件**：
- 超过归档保留期限
- 确认完全没有价值（如错误记忆、重复记忆）

**删除前检查**：
- 是否有其他记忆引用了这条？
- 是否还有历史参考价值？
- 删除后会不会丢失重要信息？

**软删除**：默认采用软删除，保留删除记录，可恢复。

**硬删除**：确认完全无用后，物理删除。

---

## 2. 记忆更新规则

### 2.1 什么时候需要更新？

- 发现记忆内容不准确
- 有新的验证结果补充
- 适用场景发生变化
- 相关的其他记忆更新了

### 2.2 更新方式

| 更新方式 | 说明 | 适用场景 |
|---------|------|---------|
| 补充更新 | 在原有基础上补充新内容 | 增加验证案例、扩展适用场景 |
| 修正更新 | 修正错误或不准确的内容 | 发现部分错误但核心正确 |
| 版本更新 | 创建新版本，保留旧版本 | 重大变更，新旧版本差异大 |
| 替代更新 | 用新记忆替代，旧的标记过时 | 完全有更好的方案 |

### 2.3 更新记录

每次更新都必须记录：
- 更新时间
- 更新原因
- 更新内容摘要
- 更新前后的质量等级变化

## 3. 生命周期管理工具

### 3.1 定期回顾

| 周期 | 动作 | 范围 |
|------|------|------|
| 每周 | 新创建记忆审核 | 本周新增的所有记忆 |
| 每月 | 活跃记忆抽检 | 随机抽检 10% 的活跃记忆 |
| 每季度 | 全面审计 | 所有记忆的有效性、质量等级 |
| 每年 | 归档清理 | 检查归档记忆是否需要删除 |

### 3.2 自动化辅助

- 自动计算最后使用时间和使用频率
- 自动检测长期未使用的记忆，触发衰减提醒
- 自动统计验证次数，辅助质量等级评估
- 自动检测重复或相似的记忆
