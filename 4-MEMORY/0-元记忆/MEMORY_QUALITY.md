# 记忆质量标准 — MEMORY QUALITY

> **版本**: v1.0
> **更新日期**: 2026-07-26
> **定位**: 元记忆 — 定义记忆质量的评估标准和分级体系
> **等级**: S（公理级）

---

## 0. 质量分级体系

记忆质量分为 5 个等级，从高到低：

```
S — 公理级（Axiom）
    经过大量验证的基本原则，长期有效
A — 可信级（Trusted）
    经过多次验证的经验，置信度高
B — 待验证（Unverified）
    有一定证据但需更多验证，置信度中
C — 假设级（Hypothesis）
    初步观察或推测，未验证，置信度低
D — 已证伪（Disproved）
    被证明错误或过时，不可信
```

---

## 1. 各等级详细说明

### 1.1 S 级 — 公理级

**定义**：经过大量实践验证、被广泛认可的基本原则，在可预见的未来不会改变。

**置信度**：≥ 95%

**进入标准**：
- 至少 10 次独立验证
- 跨越多个场景和时间周期仍然有效
- 没有发现反例
- 经过至少 3 个月的观察期

**典型内容**：
- 工程基本原则（如"单一职责"）
- 经过长期验证的方法论核心
- 系统架构的核心原则

**维护要求**：
- 每年度回顾一次
- 任何变更必须有充分理由
- 降级需要多方确认

**示例**：
> GM-PRI-001: 代码变更必须同步更新文档
> 验证：无数次因文档不同步导致的问题反向验证
> 状态：S 级，长期有效

---

### 1.2 A 级 — 可信级

**定义**：经过多次实践验证的经验和方法，置信度较高。

**置信度**：70% ~ 95%

**进入标准**：
- 至少 3 次独立验证
- 在多个场景下有效
- 没有发现明显反例
- 经过至少 1 个月的观察期

**典型内容**：
- 经过验证的最佳实践
- 成熟的方法论应用
- 架构决策的经验总结

**维护要求**：
- 每季度回顾一次
- 发现反例及时降级
- 持续收集验证反馈

**示例**：
> GM-MTD-002: A1 调研法在技术债治理中效果显著
> 验证：3 次技术债治理项目均成功应用
> 状态：A 级，持续验证中

---

### 1.3 B 级 — 待验证

**定义**：有一定证据支持但验证次数不足，需要更多实践验证。

**置信度**：40% ~ 70%

**进入标准**：
- 至少 1 次有效验证
- 有合理的逻辑支撑
- 可能存在边界条件不清晰的情况

**典型内容**：
- 新总结的经验教训
- 新提炼的方法论
- 从案例中初步归纳的结论

**维护要求**：
- 每月回顾一次
- 主动寻找验证机会
- 明确标注"待验证"

**示例**：
> GM-LSN-015: subprocess + shlex.split 组合在 PYTHONPATH 设置时会失败
> 验证：1 次 L3 调度器崩溃案例验证
> 状态：B 级，待更多验证

---

### 1.4 C 级 — 假设级

**定义**：初步观察或推测，尚未经过实践验证。

**置信度**：< 40%

**进入标准**：
- 有合理的推测但未验证
- 从单一案例中归纳（可能是巧合）
- 或从理论推导而来但未实践

**典型内容**：
- 新提出的假设
- 待验证的猜想
- 初步的观察结果

**维护要求**：
- 每两周回顾一次
- 优先安排验证
- 明确标注"假设"，避免误用

**示例**：
> GM-LSN-020: 向量检索 + 知识图谱混合检索效果可能优于单一方式
> 验证：理论推导，尚未实际验证
> 状态：C 级，待验证

---

### 1.5 D 级 — 已证伪

**定义**：被证明错误或已经过时的记忆。

**置信度**：不可信

**进入标准**：
- 发现明确的反例
- 适用场景已经消失
- 被更好的方案完全替代

**典型内容**：
- 被推翻的假设
- 过时的技术经验
- 已替代的最佳实践

**维护要求**：
- 保留记录，避免重复踩坑
- 标注证伪原因和替代方案
- 正常检索默认不返回 D 级记忆

**示例**：
> GM-LSN-003: （已证伪）launchd 任务 label 是 com.l3.phase2
> 证伪：实际 label 是 com.l3.commandcenter.phase2scheduler
> 替代：GM-LSN-012（正确的 label 查找方法）
> 状态：D 级，已证伪

## 2. 质量评估维度

记忆质量从以下 5 个维度综合评估：

| 维度 | 权重 | 说明 | 评估问题 |
|------|------|------|---------|
| **准确性** | 30% | 内容是否准确无误 | 是否与事实一致？有没有反例？ |
| **完整性** | 20% | 内容是否完整全面 | 有没有遗漏重要信息？边界条件清楚吗？ |
| **可验证性** | 20% | 是否可以被验证或证伪 | 能设计实验验证吗？有明确的判断标准吗？ |
| **适用性** | 20% | 适用场景是否明确 | 什么时候用？什么时候不能用？ |
| **来源可靠性** | 10% | 来源是否可信 | 来源是什么？经过几层传递？ |

**综合得分 = Σ(维度得分 × 权重)**

| 得分区间 | 对应等级 |
|---------|---------|
| 90 ~ 100 | S 级 |
| 70 ~ 89 | A 级 |
| 40 ~ 69 | B 级 |
| 0 ~ 39 | C 级 |
| 被证伪 | D 级 |

## 3. 等级升降规则

### 3.1 升级规则

```
C → B：  至少 1 次有效验证 + 维度评估 ≥ 40 分
B → A：  至少 3 次独立验证 + 维度评估 ≥ 70 分
A → S：  至少 10 次独立验证 + 维度评估 ≥ 90 分 + 3 个月观察期
```

**有效验证**定义：
- 在不同场景下应用并确认有效
- 有明确的验证结果记录
- 不是同一事件的重复计数

**独立验证**定义：
- 验证者/场景/时间至少有一个不同
- 不是同一团队在同一项目中的反复应用

### 3.2 降级规则

```
S → A：  发现反例，但核心仍然有效
A → B：  验证次数不足（长期未新增验证）
B → C：  发现疑点，需要重新验证
任意 → D：发现明确反例，核心内容错误
```

### 3.3 升级/降级流程

1. **触发**：新验证结果、发现反例、定期审计
2. **评估**：对照评估维度打分
3. **决策**：是否升降级？升降到哪一级？
4. **记录**：更新记忆条目，记录变更原因
5. **通知**：如果影响范围大，通知相关方

## 4. 质量审计

### 4.1 审计频率

| 等级 | 审计频率 |
|------|---------|
| S 级 | 每年一次 |
| A 级 | 每季度一次 |
| B 级 | 每月一次 |
| C 级 | 每两周一次 |
| D 级 | 归档后每年检查是否可删除 |

### 4.2 审计内容

- 记忆内容是否仍然准确？
- 验证次数是否足够？
- 适用场景是否发生变化？
- 有没有新的反例？
- 是否需要调整等级？
- 是否需要更新内容？

### 4.3 审计结果

- **维持原判**：等级不变，内容不变
- **内容更新**：等级不变，更新内容
- **等级调整**：升级或降级
- **触发验证**：不确定，安排进一步验证
- **归档/删除**：不再需要，进入归档或删除流程
