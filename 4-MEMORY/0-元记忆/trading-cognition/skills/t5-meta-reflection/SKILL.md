# Meta-Reflection (元认知复盘)

## Overview

**核心职责**：记录 → 对比 → 归因 → 迭代 四步闭环。T5 是 A 系列决策链的"事后裁判 + 进化引擎"，不参与实时决策，而是把已结束的 episode 变成可复用的认知资产。

**来源**：从原 A8（知行合一）精简，剥离实时执行校验，聚焦"复盘 + 纸上谈兵检测 + 迭代"。

**铁律**：复盘必须基于实际 episode 数据，不允许凭记忆复盘。没有证据的反思 = 无效反思。

## When to Use

- **单笔 episode 结束后**：止损/止盈/超时平仓后立即复盘。
- **周期性回顾**：日/周/月汇总复盘，识别重复出现的认知偏差。
- **纸上谈兵检测**：怀疑 T0/T3 仅在文档声称已集成但实际未被调用时。
- **迭代验证**：上一次复盘提炼的 lesson 进入观察期后，验证其效果。
- **回滚评估**：改进措施上线后绩效恶化，判断是否触发回滚。
- **不适用**：实时决策纠偏（那是 T2/T4 的活）；从零设计战略（那是 T0 的活）。

## The Iron Law (HARD-GATE)

```
复盘必须基于实际 episode 数据，不允许凭记忆复盘。
认知偏差识别必须给出具体证据（哪笔交易/哪个决策点）。
迭代 lesson 必须可执行，不允许"以后要更谨慎"等模糊建议。
```

违反任何一条 = 该次复盘判定无效，必须重做。

## Core Steps

### Step 1 — 纸上谈兵检测

在复盘任何"系统改进"之前，先验证它是否真的被调用过。

**方法**：检查 `use_skill` 调用日志，对比"声称集成"与"实际调用"次数。

| 情况 | 判定 | 处理 |
|------|------|------|
| 文档声称集成，日志有调用 | 真集成 | 进入正常复盘 |
| 文档声称集成，日志零调用 | 纸上谈兵 | 标记为虚假集成，优先修复调用链 |
| 文档未提，日志有调用 | 隐式集成 | 补文档 |
| 文档未提，日志无调用 | 未集成 | 不纳入本次复盘 |

**输出**：纸上谈兵检测报告，列出每个 T0/T3 环节的"声称 vs 实际"对照。

### Step 2 — 四步复盘闭环

#### Step 2.1 记录

从 episode 数据中提取决策依据：

- 为什么进？（触发信号 / 逻辑链）
- 预期是什么？（目标位 / 持有时间 / 走势假设）
- 止损在哪？（止损位 / 止损逻辑）
- 仓位多大？（仓位比例 / 风险敞口）
- 信心度多少？（自评 0-100）

#### Step 2.2 对比

实际结果 vs 预期：

- 盈亏：实际 P&L vs 预期目标
- 持有时间：实际持有 vs 预期持有
- 命中条件：实际走势是否命中预期假设
- 执行偏差：计划 vs 实际执行差异（滑点、延迟、未执行）

#### Step 2.3 归因

识别认知偏差，**必须给出具体证据**：

| 偏差类型 | 检测点 | 证据要求 |
|----------|--------|----------|
| 确认偏误 | 只看支持自己判断的信号 | 列出被忽略的反向信号及时间点 |
| 损失厌恶 | 该止损未止损 | 给出该笔触发止损的时间点和未执行记录 |
| 过度自信 | 仓位/信心度高于信号支撑 | 对比信号强度与实际仓位/信心度 |
| 情绪化执行 | 偏离计划的非理性操作 | 给出操作时间点与计划偏差 |

#### Step 2.4 迭代

提炼可复用 lesson，注入下次决策：

- **格式要求**：`在 [条件X] 下，应该 [动作Y]，因为 [证据Z]`。
- **可执行性**：必须能在下一个 episode 中直接套用。
- **禁止**："以后要更谨慎"、"注意风险控制"等模糊建议。
- **绑定**：每个 lesson 绑定一个可观测的验证指标。

### Step 3 — 批评可信度评估

对 Step 2.3 的归因进行可信度打分：

- **自评**：自己给的归因可信度（0-100）。
- **独立验证加成**：有独立数据/日志佐证 +15；有第三方（另一个 T 或回测）佐证 +15。
- **门槛**：≥70% 才进入观察期；<70% 退回重做归因。

### Step 4 — 观察期验证

改进措施上线后进入观察期：

| 改进类型 | 观察期 | 验证方式 |
|----------|--------|----------|
| 认知 lesson | 14 天模拟盘 | 对比观察期前后指标 |
| Bug 修复 | 7 天 | 复现原 Bug 场景验证 |

观察期内 lesson 标记为"待验证"，不进入正式决策链。观察期通过后才升级为正式 lesson。

### Step 5 — 回滚机制

改进措施上线后，若出现以下任一情况，触发回滚：

1. P&L 回撤 > 3%
2. 知行合一度下降 > 15 分
3. 认知偏差增加（同类偏差次数上升）
4. 执行速度下降 > 50%

回滚动作：撤销改进措施，恢复上一稳定版本，重新归因。

### Step 6 — 绩效考核指标

T5 自身的绩效用以下指标衡量：

| 指标 | 目标 | 计算方式 |
|------|------|----------|
| 批评准确率 | ≥ 70% | 观察期验证通过的 lesson / 总产出 lesson |
| P&L 改善率 | ≥ 5% | 改进上线后 P&L vs 改进前 P&L |
| 偏差减少率 | ≥ 30% | 改进后偏差次数 / 改进前偏差次数 |

未达标 → T5 自身需要复盘（元复盘）。

## Checklist

### 纸上谈兵检测
- [ ] 是否检查了 T0/T3 的 use_skill 调用日志？
- [ ] 声称集成 vs 实际调用次数是否对照？
- [ ] 纸上谈兵项是否已标记并优先修复？

### 四步闭环
- [ ] 记录：决策依据五要素（进/预期/止损/仓位/信心度）是否齐全？
- [ ] 对比：实际 vs 预期四项（盈亏/时间/条件/执行）是否齐全？
- [ ] 归因：认知偏差是否给出具体证据（交易/决策点）？
- [ ] 迭代：lesson 是否符合 `条件→动作→证据` 格式？是否可执行？

### 质量门槛
- [ ] 批评可信度是否 ≥ 70%？是否有独立验证加成？
- [ ] 观察期是否设定（14 天 lesson / 7 天 Bug）？
- [ ] 回滚四条件是否持续监控？
- [ ] 绩效三指标（准确率/P&L/偏差减少）是否达标？

### 数据合规
- [ ] 复盘是否基于实际 episode 数据（非凭记忆）？
- [ ] 是否存在"以后要更谨慎"类模糊建议？（必须为零）
- [ ] 认知偏差是否有具体证据？（无证据即无效）

## 与其他 T 的关系

- **T0/T3**：T5 检测其是否被实际调用（纸上谈兵检测）；复盘其决策依据。
- **T1**：T5 复盘仓位/风险敞口是否合理。
- **T2**：T5 复盘执行偏差（滑点/延迟/未执行）；T2 的执行日志是 T5 的重要数据源。
- **T4**：T5 复盘告警是否被正确响应；T4 的告警记录是 T5 的输入。

## 反模式（禁止）

- 凭记忆复盘，不查 episode 数据。
- 归因只写"心态不好"不写具体证据。
- lesson 写"以后要更谨慎"等模糊建议。
- 跳过纸上谈兵检测直接复盘。
- 批评可信度 <70% 仍强行进入观察期。
- 改进措施上线后不监控回滚四条件。
- T5 绩效不达标却不做元复盘。
