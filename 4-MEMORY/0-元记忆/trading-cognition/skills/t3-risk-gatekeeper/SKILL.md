# Risk Gatekeeper (风控门禁)

风控门禁是交易决策链中的 HARD-GATE 守护者。本 Skill 本身就是硬约束，所有检查项均为不可协商的门禁。职责三段：事前门禁 → 事中熔断 → 事后归因。

## Overview

T3 不产出交易信号，也不执行下单。它的唯一职责是"放行 / 拦截 / 归因"：

1. **事前门禁**：在 T2 执行前，检查认识来源、验证设计、风险可控性、反馈机制、执行纪律。
2. **事中熔断**：在 T2 持仓期间，监控 C5 熔断四条件与止损状态。
3. **事后归因**：交易结束后，对比结果与预期，产出归因分析。

T3 的判定独立于执行者自评——从 episode 数据自动验证，不采信自评分。

## 三层脑风控映射（对齐 MacLean 三层脑理论）

> **理论**: MacLean 三层脑——爬行脑(本能/生存)→边缘系统(情感/记忆)→新皮质(理性/抽象)。现代修正：三层非严格进化叠加，情绪与理性是并行交互回路（Panksepp/Pessoa）。作为层级化控制隐喻仍有工程价值。
>
> **关键修正**: A8 偏差信号应作为**偏差信号双向反馈**给 A0 修正模型（Panksepp 视角），而非仅作为"被A0压制的噪声"。

| 脑层 | 认知功能 | T3 风控映射 | 响应速度 | 可否被上层否决 |
|------|---------|------------|---------|--------------|
| **爬行脑**（脑干/基底节） | 本能/生存/领地 | **硬熔断层**：10%日回撤熔断、Fail-Closed、杠杆>2x硬阻断 | <1ms 同步 | ❌ 不可否决 |
| **边缘系统**（杏仁核/海马） | 情感/记忆/社交 | **A8 损失厌恶/认知偏差检测层**：检测理论与实践的系统性偏差、过度自信、损失厌恶 | 异步 daily | 可上诉但需记录 |
| **新皮质**（前额叶） | 理性/抽象/规划 | **A0-A6 分析链**：矛盾分析→第一性原理→战略→战术→执行→监控 | 分钟级 | 可被门禁拦截 |

**双向反馈机制**（Panksepp 修正）：
- A8 检出偏差 → 不仅记录，还**双向反馈**给 A0 修正内部模型
- 反馈路径：A8 偏差信号 → A0 矛盾分析权重调整 → A2 阻力评分修正
- 目标：降低后续同类错误率（闭环验证）

## When to Use

- T2 准备进入大仓执行前，需要门禁放行时
- 持仓期间需要判定是否触发熔断、是否强制平仓时
- 交易结束后需要做归因分析时
- 需要独立验证某次交易的自评分是否可信时
- 触发词命中：风控检查 / 风控门禁 / 熔断 / 止损检查 / 仓位限额 / 风险预算 / 实践论门禁 / 独立验证 / 亏损熔断 / 强制平仓 / 风险审计 / 事后归因

不适用：行情研判（T1）、下单执行与离场判定（T2）。T3 只负责"是否允许、是否熔断、为什么这个结果"。

## The Iron Law (HARD-GATE)

<HARD-GATE>
1. **T3 即硬约束**：本 Skill 所有门禁检查项均为 HARD-GATE，不存在"软警告后放行"。
2. **FAIL 即拦截**：门禁 FAIL 时禁止执行，必须返回上游（T1/T2）修正后重新过门禁。
3. **独立验证不可覆盖**：独立验证结果从 episode 数据自动得出，不受执行者自评影响。自评与数据冲突时，以数据为准。
</HARD-GATE>

## Core Steps

### 事前门禁

#### 1. 执行前 5 项检查

在 T2 进入大仓执行前，逐项检查，任一 FAIL 即拦截：

| # | 检查项 | PASS 条件 | FAIL 处理 |
|---|--------|-----------|-----------|
| 1 | 认识来源充分性 | 有 ≥2 个独立信息源支撑当前判断 | 返回 T1 补充信息 |
| 2 | 验证设计合理性 | 已有模拟盘验证且通过验证前置检查 | 返回 T2 验证阶段 |
| 3 | 风险可控性 | 仓位在限额内且有止损设置 | 调整仓位 / 补止损 |
| 4 | 反馈机制完整性 | 已定义离场条件（四层离场预案齐备） | 返回 T2 补离场预案 |
| 5 | 执行纪律 | 遵循验证前置检查（实践≥2+盈利≥2+无单亏>5%） | 返回 T2 验证阶段 |

#### 2. 止损必检规则

扫描所有持仓：任一持仓无止损 = 整体 FAIL，强制要求补设止损后才放行。止损位不得为"心理止损"（必须可执行、可验证）。

#### 3. 4 小时窗口 episode 检查

检查最近 4 小时内是否有相关 episode（实践记录）：
- 无近期实践 = FAIL（说明判断未经过近期实践检验）
- 有近期实践但全部失败 = FAIL（说明当前判断方向有误）

#### 4. 仓位限额与风险预算

- 当前总仓位是否在风险预算上限内？
- 单标的仓位是否超限？
- 相关性叠加后实际风险敞口是否超限？（跨资产需折算）

### 事中熔断

#### 5. C5 亏损熔断监控

持仓期间持续监控四条件，任一触发即熔断：

| 条件 | 阈值 | 动作 |
|------|------|------|
| 单次亏损 | >15% | 平仓 + 反思 |
| 24h 累计亏损 | >25% | 平仓 + 反思 |
| 7d 累计亏损 | >40% | 全部平仓 + 深度反思 |
| 连续亏损次数 | ≥3 | 平仓 + 回到 T1 重新研判 |

熔断后强制进入闭环，期间禁止开新仓，直到闭环完成（平仓→反思→重新研判→重新验证）。

#### 6. 止损状态实时监控

- 止损是否仍有效（未手动取消）？
- 止损位是否需要随盈利收紧（trailing）？
- 是否有人为放宽止损的行为？→ 放宽即 FAIL。

### 事后归因

#### 7. 独立验证机制

从 episode 数据自动验证交易结果，不采信执行者自评分：
- 实际 entry/exit/regime/盈亏 从 episode 原始数据提取
- 与执行者声称的"盈亏 / 原因"对比
- 不一致时记录为"自评失真"，影响该执行者后续自评权重

#### 8. 归因分析

交易结束后对比"实际结果 vs 预期"：

| 差异类型 | 归因方向 |
|----------|----------|
| 盈利且符合预期 | 验证策略有效性，沉淀为成功案例 |
| 盈利但超出预期（运气成分） | 标注"幸存者偏差风险"，不沉淀为标准案例 |
| 亏损且符合预期（止损正常触发） | 验证止损机制有效 |
| 亏损且超出预期 | 深度归因：Regime 误判？止损过宽？情绪干扰？ |

#### 9. episode 沉淀

每笔交易结束必须沉淀 episode，供未来 recall 与 T3 独立验证：
- entry / exit / regime / 策略 / 结果 / 复盘
- 是否触发熔断、是否通过门禁、自评 vs 数据验证结果

## Checklist

事前门禁（任一 No = 拦截）：

- [ ] 是否有 ≥2 个独立信息源？
- [ ] 是否有模拟盘验证且通过验证前置检查？
- [ ] 仓位是否在限额内？是否有止损？
- [ ] 是否已定义四层离场预案？
- [ ] 最近 4h 是否有相关 episode？
- [ ] 跨资产相关性叠加后是否超限？

事中熔断（持续监控）：

- [ ] C5 四条件是否实时监控？
- [ ] 所有持仓止损是否有效未被放宽？
- [ ] 熔断触发后是否进入闭环且禁止开新仓？

事后归因：

- [ ] 是否从 episode 数据独立验证（非自评）？
- [ ] 是否产出"实际 vs 预期"归因分析？
- [ ] 是否沉淀 episode 供未来 recall？

## Anti-Pattern

- **自评即真相**：采信执行者自评分，不做数据独立验证。→ 必须独立验证。
- **软警告放行**：门禁 FAIL 但"这次特殊情况"放行。→ FAIL 即拦截。
- **事后不归因**：交易结束不分析原因，只记盈亏。→ 必须归因。
- **熔断不闭环**：触发熔断后不平仓或补仓摊平。→ 强制平仓 + 闭环。
- **心理止损**：止损位不可执行、不可验证。→ 必须可执行。
