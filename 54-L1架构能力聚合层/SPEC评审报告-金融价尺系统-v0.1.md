# 评审报告 — SPEC-54 金融价尺系统（FNS）

- **评审对象**: [SPEC-54-金融价尺系统.md](./SPEC-54-金融价尺系统.md) **v1.1**
- **代码对象**: 无（`l1agg/fns/` 尚未创建，本 SPEC 明确「未落地任何代码」）
- **评审日期**: 2026-11-15 ｜ **评审方式**: 独立复核（文档逐节 + 公式量纲推演 + 数据契约抽查 + 与母 SPEC/既有模块边界比对）
- **评审结论**: **不通过（2.95 / 5.0）** — **7 项阻断**，须出 v1.2 后复审
- **性质**: 本次为**纯 SPEC 评审**，未跑任何数值；标注「待证据」项不得在复审时被口头认定

> 核心判断：**理论骨架成立，但数学层与识别层有 3 处硬错误、契约层有 1 处逻辑错配**。这些不是措辞问题，会让第一版实现直接算错或算不出。

## §1 RFD（裁决理由）

**采纳理由（为何不整体否决）**

1. 定位与母 SPEC ADR-3（L1 不做预测）一致，输出为描述性量 + 状态机，未越界到 L2。
2. 把"不可观测的价值"拆成 λ / MELT / 标准商品 / 成本锚四个可算量，并给出**可证伪**验收（H1–H5），方法论姿态正确——不宣称真理，只做检验。
3. 资金流被明确定义为「验证器而非定义器」（ADR-F9），避免了用价格解释价格的循环论证，这是本 SPEC 最有价值的设计。
4. 风险表已覆盖 13 条，含长波不可推断、加密成本锚失效、口径污染等真实陷阱。

**保留理由（为何打回）**

- **B1** 声称"两种含义 SNLT 之差 = 库存周期数学来源"，但方法表里**没有任何方法计算第二含义 SNLT**，理论承诺未兑现。
- **B3** 生产价格公式 `p* = λ·MELT·(1+r̄)` **量纲/重复计算错误**，会系统性高估 p*。
- **B7** §2.2 明文"禁止把 p 与 λ 直接回归"，而 §7.1 的 H1 恰恰是 `log p ~ log λ`，**SPEC 自相矛盾**。
- **B5** 资金流 β 用同期回归估计，价格与流量互为因果，**系数不可解释为承接力**，H5b 设计上无法成立。
- **B2** MELT 分子（全国 GDP）与分母（非农企业工时）口径不一致，H3（唯一硬门禁）**必然失败**，等于自锁发布。

**结论**：以上 5 条任一单独都足以阻断；其中 B3/B7/B5 属数学与识别错误，不能靠"标注 caveat"绕过。

## §5 Devil's Advocate（反对意见与让步阈值）

**反对意见 1：整个模块建立在非共识理论上，投入 22 个方法风险过高。**
→ **让步阈值**：若 V0（尺子标定）阶段 H3 无法以 <1% 误差闭合，即证明"经济核算口径无法支撑 MELT"，则**终止**后续 V1–V3，只保留 V03 的描述性输出。这一条应写成路线图硬门禁，而不只是"阻塞发布"。

**反对意见 2：`value_regime` 状态机看似严谨，实则给了理论一个"免死金牌"——不通过就降级，用户永远看不到失败。**
→ **让步阈值**：每次运行必须输出 H1–H5 的**实测数值**（斜率、R²、半衰期、p_adj），即使 regime 降级也不得隐藏；且需保留历史 regime 变更日志。否则本模块无法被外部审计。

**反对意见 3：资金流"验证"价值，本质是用市场共识检验理论，而市场共识恰恰可能是错的（泡沫）。**
→ **让步阈值**：接受此批评，故 ADR-F9 已限定"只做同向确认、冲突时以价值尺为准"。但须补一条：当 `flow_confirm=conflict` 且持续 >N 期时，应触发"价值尺可能失效"的告警，而不是永远让价值尺赢。

**反对意见 4：复杂劳动折算用相对工资，等于用价格解释价值，循环。**
→ **让步阈值**：承认这是近似。要求做敏感性（工资率 ±20%）并输出区间；若结论在 ±20% 内翻转，则该结论标记为"不稳健"。
