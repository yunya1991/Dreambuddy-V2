## 三、P0 修复：QualityGate 硬门禁拦截

### 3.1 问题描述

**文件**: `18-数据获取中心/data_center/core/dispatcher.py`  
**原逻辑** (行 192-208):
```python
_silver = _pipe.clean(result, source=source, category=category)
if _silver.gate_passed:
    result = _to_recs(_silver.df, ...)
    DalSink().write_silver(_silver, ...)
# else: 保持原始 result 不变  ← P0 违规
```

**违规点**: 当 `QualityGate` 未通过（`gate_passed=False`）时，dispatcher 将原始 Bronze 脏数据直接返回给调用方，违反硬约束：
- "所有数据入库前必须经过Silver层清洗"
- "quality.py从监控报警升级为硬门禁拦截，异常数据仅保留在Bronze层用于审计"

### 3.2 修复方案

修改 dispatcher.py，当 `gate_passed=False` 或清洗链异常时，**返回空列表**而非 Bronze 脏数据：

```python
if _silver.gate_passed:
    result = _to_recs(_silver.df, ...)
    DalSink().write_silver(_silver, ...)
else:
    # ★ 硬门禁拦截：丢弃 Bronze 数据，返回空列表
    result = []  # SILVER_ALLOW_BRONZE_FALLBACK=true 时紧急回退
```

**新增环境变量**: `SILVER_ALLOW_BRONZE_FALLBACK`（默认 `false`），仅用于故障演练时紧急回退到 Bronze 数据。

### 3.3 验证结果

```
TEST 1: QualityGate hard-block behavior
  gate_passed (stale data): False  → 拦截
  gate_passed (valid data): True   → 放行
  PASS: Stale data correctly rejected by QualityGate
```

## 四、P1 修复：DalSink 路由表与字段映射

### 4.1 问题描述

**文件**: `20-数据清洗中心/data_cleaning/dal_sink.py`

**问题 1**: `FearGreedCollector` 产出的 `sub_category="crypto_fear_greed"`，但 DalSink `_ROUTE_MAP` 仅包含 `"fear_greed"`，导致恐惧贪婪指数数据无法写入 Gold 层。

**问题 2**: collector metrics 字段名为 `classification`，但 DalSink 期望 `value_classification`，字段不匹配。

### 4.2 修复方案

1. `_ROUTE_MAP` 增加 `"crypto_fear_greed"` 路由别名
2. 新增 `_FIELD_ALIASES` 字典：`{"classification": "value_classification"}`
3. `_build_kwargs` 中先应用字段别名（`row.rename(index=aliases)`）
4. `route_key` 判断条件改为 `in ("fear_greed", "crypto_fear_greed")`

### 4.3 验证结果

- `fib_retrace_0786` 由 swing high/low 计算
- 当 ma_200 不可用时，自动 fallback 到 fib_0786（项目硬约束）
- 两者都 NaN 时，trend_bias=0（中性）
