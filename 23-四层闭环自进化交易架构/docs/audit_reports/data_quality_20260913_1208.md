## 九、P1 数据质量问题：ccxt volume 恒为 0

### 9.1 问题描述

**文件**: `18-数据获取中心/data_center/collectors/chain/ccxt_collector.py` 行 45

**现象**: 所有 ccxt 记录的 `metrics.volume` 恒为 `0.0`（从 2026-08-25 至 2026-09-13，全部 5,113 条记录）

### 9.2 根因分析

ccxt 的 `fetch_ticker()` 返回的 ticker 字典中：
- `volume`: `None` ← collector 取的是这个字段
- `baseVolume`: `7918.40904` ← 实际基础货币成交量（BTC）
- `quoteVolume`: `611861331.71` ← 计价货币成交量（USDT）
- `info.volume`: `7918.40904` ← Binance 原始返回

collector 第 45 行 `"volume": _num(ticker, "volume")`，而 `_num` 函数把 `None` 转成 `0.0`，导致 volume 恒为 0。

### 9.3 影响范围

- `R_flow`（Wyckoff effort/result）依赖 volume，volume=0 导致 R_flow 计算失真
- 所有依赖 ccxt volume 的策略信号受影响
- 不触发 NaN 告警（0.0 是有效值），属于"静默错误"

### 9.4 修复建议

```python
# 修复前
"volume": _num(ticker, "volume"),

# 修复后：优先 baseVolume，回退 volume
"volume": _num(ticker, "baseVolume") or _num(ticker, "volume"),
```
