## 二 · Journal-Fit Reviewer（是否适合当前市场/目标）

**意见：** v4 的市场适配性**优于 v3**。真实数据已证明源B 对任何预注册 treatment 定义都给出**诚实零**（ate≈0.0016、CI 含 0、d≈0.006）；v4 不再幻想「喂样本就能出显著」，而是把目标重定义为「**诚实地估计 + 经济显著性判定 + 消除恒定偏置**」，这与「观察性数据本就不含强干预信号」的现实一致。

**保留意见（Minor m3）— A2 的净收益边界须在 SPEC 顶层声明：**
- v4 落地后，源B 恒落入**态B（no-op）**。也就是说 A2 的**实证净收益 = 消除「恒定 ×0.95 下偏」这一副作用**，而非「创造可用因果信号」。§1 目标仍写「以此因果先验调制主要矛盾 strength」，措辞易被误读为「能带来正向调制收益」。
- 建议在 §1/§9 显式声明：**A2 在源B 阶段的价值是「去偏 + 建立可估计/可复现/可审计的因果诊断管线」；真正的正向调制收益需等 P1（CATE/regime 分桶）或源A 累积到 ≥500。**
- 市场适配的正向面：v4 的 HAC/block bootstrap 与 positivity 诊断**恰好对症**源B 的「重叠 + 强自相关 + 零膨胀」，是必要的工程纠偏。

## 三 · 方法评审

**M1（Major）— `SESOI` 的取值有「结果导向」风险，必须独立预注册。**
v4 §6.2 取 `d_SESOI = 0.05`，并注明「观测 d≈0.006 ≪ 0.05 → 落入态B」。这读起来像**先知道结论、再挑一个恰好把估计推进态B 的阈值**——与 SPEC 反复强调的「treatment 预注册、不得事后挑选」是同一类方法论瑕疵（p-hacking 的阈值版）。
**必须改：** 给出 **τ 的独立经济来源**（如最小可交易收益 ≈ 换手成本 + 滑点 对应到 reward 尺度），并附**阈值稳健性**（τ ∈ {0.02, 0.05, 0.1} 三档结论一致才可宣称态B 稳健）；τ 必须**在观测 ate 之前**由经济理由确定，观测后不得调整。

**M2（Major）— HAC/block bootstrap 可行性未验证，可能反转整个门禁结论。**
§2.5 规定「SESOI 门禁**只采信非 asymptotic 口径**」，但 §9.4 又把「causalml `(te, lb, ub)` 零改造」作为主路径。若 causalml DML **不直接支持** HAC/分块自助，则 §2.5 与 §9.4 冲突：要么门禁因「无合规 CI」而**恒落态C → 一律 no-op**（则 A2 退化为「只会 no-op」），要么被迫自实现。两条路都是**重要结论变化**，不能悬置。
**必须改：** 在 T2 落地前**先核实 causalml 版本 API**；SPEC 须给出**明确降级路径**（自实现 stationary block bootstrap 或改挂 DoWhy/DoubleML），并声明「若三条路均不可行，则 A2 回退为仅报告、不调制」。

**M3（Major）— 三态门禁修改 A1 硬约束契约，须升为阻断项。**
§6.2 有「未裁决前不改 A1 契约行为」，但措辞是**软约束**，且 §8/T7 已把实现列入落地范围。鉴于 A1 契约（`VM-1791963721822-a7f9bae4`）是**已确认的硬约束**，任何「默认实现新契约」都构成对硬约束的静默改写。
**必须改：** 在 §4.2 降级矩阵与 §8 任务表**加入硬阻断**：`T3/T7 涉及 `_enhance_with_causal_ate` 判定分支的改动，**必须先取得用户对 §6.2 v4 门禁的显式确认**；未确认前该分支固定为 A1 原契约（含 ×0.95）」。并新增守门测试（见 §八）。

**Minor m1 — TOST 与「CI ⊆ (−τ, τ)」在统计上等价，注意不要「新增概念但无新信息」。**
若门禁实现只是检查 CI 是否整体落在 `(−τ,+τ)`，那它与 TOST 双单边检验同解；引入「TOST」概念应在 SPEC 中说明其**计算来源**（`statsmodels.stats.weightstats.ztost_mean` 或自实现），否则属术语堆叠。

**Minor m5 — 效应量口径需精确。**
`d = ate/std(y)` 对**二元 treatment**是近似标准化的均值差；建议 SPEC 明确「效应量以原始单位 `ate` + y 分布（std/非零占比）联合报告」，避免 d 被误当成可直接比较的效应大小。

**Minor m4 — §2.5 与 §9.4 的 CI 口径表述需统一（见 M2）。**

## 四 · 统计评审（调用 `dream-science-statistics-check` 视角）

**正面：** v4 采纳了三项统计合规动作且方向正确——① 弃二值 p 门槛改报效应量+CI（ASA 2016）；② 用等价性检验正面支持「零效应」（Lakens 2017）；③ 对多口径试错设 FDR 与 treatment 预注册（BH 1995 / 评审 m6）。这三条**同时解决**了 v0.1 的「结果幻觉（模式5）」与「逻辑跳跃（模式6）」的根源。

**遗留问题：**
1. **M1 复核（τ 预注册）**：统计评审与方法评审一致——τ 若在观测后设定，等价性检验反而成为「事后合理化」工具。
2. **多重比较的实际暴露面**：源B 上已试过 ≥5 个 treatment 定义；即便最终**预注册单一口径**，历史试错须在报告中**如实披露试错次数**并给 FDR/DSR 折减（Bailey & López de Prado；Harvey-Liu-Zhu t>3）。
3. **positivity 诊断的必要性**：源B「10 类 action × 低非零率」大概率重叠不良；诊断若显示极端权重样本占比高，应把结论上修为「**数据不支撑任何可比对照**」（这是比「效应≈0」更强的陈述，见 §9.1），并在证据报告显式声明。
4. **正向确认**：v4 不再要求 `significant=True`，**消除了「用显著性门槛驱动业务惩罚」这一根源反模式**，✅ 统计合规性较 v3 显著提升。

**Minor m2（引用核查）— 区分一手/二手来源：** v4 §9 的多数方法论来源可核（Lakens 2017、VanderWeele & Ding 2017、Newey & West 1987、BH 1995、Crump 2009 等），但调研线自标「待核实」的项（Wager & Athey 2018 原文链接、proximal CI 库、部分负对照库成熟度、causalml DML API）**不得作为落地依据**；须在 SPEC 或证据报告中**列出待核实清单并逐项落实**。
