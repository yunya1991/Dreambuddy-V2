## 0. 结论先行

| 维度 | 评分 | 说明 |
|---|---|---|
| 规则覆盖度（想做的） | 7/10 | 0-6 七条规则 + 软投票 + RL + 基因参数，纸面覆盖完整 |
| 实际生效度（真跑的） | 4/10 | 7 条主规则里 3 条在生产不可达；软投票 100% 死代码 |
| 正确性（做对没） | 4/10 | trailing 止损非单调，回撤时止损跟着价格往下走 |
| 可验证性 | 3/10 | 无离场归因指标（MFE/MAE 捕获率、退出后走势），回测口径与实盘不同源 |
| 进化有效性 | 2/10 | RL 默认开启但模型 loss 单调上升、Q 值发散；影子样本 next_state=None，无法做真实反事实学习 |

**综合：约 4/10。用户的直觉是对的——问题不在"规则少"，而在"纸面规则多、真实生效少、核心止损逻辑有方向性错误"。**

最关键的一条：**当前 trailing 不是移动止盈，而是"止损随价格下行而下移"**。一个盈利 8% 的仓位，如果价格是缓慢回撤而不是插针，止损会一路被改低，最终在 -2.6% ~ -4% 附近才离场，把全部利润还回去。这与模块 docstring 写的"peak tracking，回撤不退化"正好相反。

## 3. P0 级缺陷（会直接造成亏损）

### P0-1 trailing 止损非单调：价格回撤时止损跟着往下走

代码 [exit_engine.py#L424-L470](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/23-四层闭环自进化交易架构/dreambuddy_evolution/engines/exit_engine/exit_engine.py#L424-L470)：

```python
new_sl_px = current_price * (1 - retrace)   # retrace = 0.05
```

止损只由**当前价**算，从不与上一次 SL、peak 价做 max 约束；`_peak_upl_ratio` 仅用于"是否武装"，不参与定价。而 [exit_loop.py#L514-L537](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/23-四层闭环自进化交易架构/dreambuddy_evolution/execution/exit_loop.py#L514-L537) 每轮**先 cancel 全部 algo 再按新价重挂**，等于把交易所侧的低价保护也主动撤掉。

实跑模拟（entry=100，long，standard，atr=2%，匀速回撤）：

```
 upl%   action          new_sl   生效SL
   +4   trailing         98.80   -1.20%
   +6   trailing        100.70   +0.70%
   +8   trailing        102.60   +2.60%   ← 峰值
 +6   trailing        100.70   +0.70%   ← 止损下调
 +4   trailing         98.80   -1.20%   ← 继续下调
 +2.5 trailing         97.37   -2.63%   ← 继续下调
 +2    hold            0.00    -2.63%   ← 武装后不再更新，SL 停在 -2.63%
  -4   hold            0.00    -2.63%   最终在此附近离场
```

**结果：赚 8% → 亏着出来。** 只有"插针式"下跌（一个巡检周期内直接击穿）才能被交易所止损救回；慢回撤必被吃满。这解释了为什么体感"离场水平一般"。

### P0-2 武装 trailing 的瞬间把保本位退化成负值

`+2%` 时规则 6 把 SL 提到 100.00（保本），`+4%` 时规则 5 武装，直接把 SL 改成 `104×0.95 = 98.80`（-1.2%）。既有保护被**回退**。且此后规则 6 被 `not trailing_already_armed` 永久禁用，再也回不到保本。

### P0-3 分批止盈（规则 4）生产不可达

见上表。这意味着"锁定利润"这一层完全缺失，仓位只靠（有缺陷的）trailing 一次性了结。

## 5. 为什么体感"水平一般"——结构性判断

1. **规则是 if-else 顺序硬编码，不是状态机。** trailing / 保本 / 分批止盈三者共享一个 SL 字段，却没有单调约束与优先级仲裁，导致规则互相覆盖（P0-2 就是规则 5 覆盖规则 6）。
2. **"进化"没有闭环数据支撑。** 基因参数 12 个可进化，但离场没有归因：不知道每笔"离场早了/晚了多少"（MFE/MAE 捕获率），参数往哪调没有梯度。RL 侧的样本 reward 与 next_state 都是占位的，训练指标本身在发散。
3. **纸面设计 vs 真实接线脱节。** 软投票 657 行、规则 0、规则 4 三类能力全部写成"已实现 + 有单测"，但生产链路没有接线/没有数据源。单测覆盖的是"被直接调用时正确"，不是"链路里会被调用"——这是最容易骗过评审的形态。
4. **R 基准定义混乱。** R 应该由**结构止损距离**（entry−SL）定义，当前却从 TP 反算（`r_multiple` 依赖 `tp_decayed_pct`），而 TP 在实盘是 OKX OCO 挂单、不回落引擎，所以 R 体系天然断链。

## 6. 修复建议（按优先级）

**P0（先止血，改动小、收益直接）**

1. **加 SL 单调器**：所有产出 `sl_px` 的规则统一走 `sl_px = max(new_sl, current_sl_px)`（空头取 min），并在 `_apply_sl_tp` 落单前再校验一次；同时保留 `peak_price` 用于定价：`new_sl = max(prev_sl, peak_price × (1-retrace))`。
2. **规则 6 与规则 5 合并为单一"锁利水位"**：`waterline = max(break_even, peak×(1-retrace))`，去掉互斥守卫。
3. **把 `r_multiple` 接线**：在 enricher 里用 `(entry − stop_loss_px)` 作为 1R 计算并注入，让规则 4 真正可用；或直接删除规则 4，避免"假能力"。
4. **状态按持仓生命周期管理**：用 `inst_id + entry_time` 作 key，在 `on_closed` / 幽灵仓回调里清理 peak/partial/cooldown。
5. **RL 覆盖改为默认关闭 + 影子模式**，加"覆盖后 N 笔胜率劣于规则则自动回滚"的门禁。

**P1（结构性）**

6. 决策层抽象为显式状态机：`HOLD → BREAK_EVEN → TRAILING → PARTIAL → CLOSED`，每态只能单向推进，杜绝 SL 回退。
7. 补齐离场归因指标：每笔记录 MFE、MAE、退出后 1h/4h/24h 价格、`capture_ratio = realized/MFE`，作为参数进化的目标函数。
8. 软投票要么接线（并在 enricher 补 `recent_swing_low / nearest_support_level / atr_daily`），要么整体删除，避免维护幻觉能力。
9. 手续费/滑点进保本位与 R 计算；`position_age` 解析失败时显式走"无保护期"分支而不是永久保护。
