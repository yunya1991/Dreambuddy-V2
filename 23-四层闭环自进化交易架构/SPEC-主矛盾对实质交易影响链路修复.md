**硬约束**: HC-AGI-02（异常→中性兜底）、FAIL-OPEN 铁律；所有修复不得改变一致期间（conf_mult=1.0、strength=0）的既有交易行为。

## 1 · P1：弹性约束仓位乘数接入（通道②打通）

**文件**: `11-易经推理系统/scripts/memory_l4/polling_trader.py`（PhaseC 仓位调控段）

**接入点**: 三项乘积统一应用处：
```
_combined_mult = EG3L × WinProb × BTCλ × Elastic(新增)
```

**实现**:
```python
_elastic_pos_mult = 1.0
try:
    _el_res = (getattr(self, "_last_kline_result_by_coin", {}).get(coin) or {}).get("elastic_result") or {}
    _epm = float(_el_res.get("position_mult", 1.0))
    if 0.0 < _epm <= 2.0:
        _elastic_pos_mult = _epm
except Exception:
    _elastic_pos_mult = 1.0
if abs(_elastic_pos_mult - 1.0) > 1e-9:
    _combined_mult = _combined_mult * _elastic_pos_mult
```

**安全边界**: 乘数限定 (0, 2.0]；读取失败/缺失/越界保持 1.0（FAIL-OPEN）；数据源为每币种缓存的流水线返回值（`_last_kline_result_by_coin`，含 `elastic_result.position_mult`）。

**可观测性**: 仓位调控日志新增 `Elastic=x.xx` 字段，与 EG3L/WinProb/BTCλ 并列。

**部署验证**: 12:45:20 重启生效，日志零错误。

## 3 · P3：验证阈值与交叉验证乘数联动（通道③收紧）

**文件**: `dreambuddy_evolution/evolution_pipeline.py`（统计验证段）

**实现**:
```python
_cv_mult_v = float(cv_result.get("confidence_mult", 1.0))
_validate_threshold = 0.05 / _cv_mult_v if 0.0 < _cv_mult_v < 1.0 else 0.05
validated = best["score"] > _validate_threshold
```

**设计意图**: 分歧期间得分已被压低 ×conf_mult，若阈值不变则边缘路径仍会开仓；阈值按 1/conf_mult 上浮（例：conf_mult=0.90 → 阈值 0.05→0.056），使分歧的谨慎信号同时作用于得分与准入两道关口。一致期间阈值不变，零行为差异。

**部署验证**: 12:52:34 重启生效，日志零错误，识别与心跳输出正常。
