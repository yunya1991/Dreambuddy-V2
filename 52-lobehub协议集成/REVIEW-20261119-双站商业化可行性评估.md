## §0 结论

**技术上可行，成本很低（主站加 1 个只读接口，国内复用已有 `skillhub-audit-api` 扩成 SKU 网关）。但真正的门槛不在技术，而在三件事：经营性 ICP 许可、跨境数据合规、上游数据再分发授权。** 建议按"**先同步、后直连**"落地：主站只暴露一个批量快照接口，国内本地化后对外卖；实时透传作为增值项后置。

| 维度 | 判定 | 说明 |
|---|---|---|
| 技术可行性 | ✅ 高 | 主站是 nginx 1.24 + Next.js 自托管，加路由成本低；国内已有收费后端可扩展 |
| 工期/成本 | ✅ 低 | P0 只需 1 个主站接口 + 1 个同步任务 + 1 个 SKU 路由层 |
| 稳定性 | 🟡 中 | 跨境链路无 SLA；用"本地物化"规避，实时透传只做增值 |
| 合规可行性 | 🔴 待定 | 经营性 ICP 许可未取得前，向国内公众有偿提供在线数据服务有被认定非法经营的风险 |
| 数据授权 | 🔴 待定 | 上游数据"内部使用"≠"对外转售"，且叠加跨境流动 |

**一句话**：工程上今天就能做，法务上今天不能全量卖。

## §2 三种拓扑对比

| 方案 | 做法 | 延迟 | 主站暴露面 | 开发量 | 跨境依赖 | 结论 |
|---|---|---|---|---|---|---|
| **A 实时直连** | 国内同步调主站 `/partner/v1/*` | 30–80ms × 调用次数 | 中（需鉴权/限流/防刷） | 小 | 强（主站挂则全挂） | 仅作增值 |
| **B 批量物化** | 主站定时产快照，国内拉取落本地库 | 本地 <10ms | 极小（只读文件/单接口） | 小 | 弱（可容忍中断） | **主力** |

## §4 接口契约（主站侧）

| 项 | 设计 |
|---|---|
| 路径 | `GET /api/partner/v1/snapshot`（批量，返回预计算包）、`POST /api/partner/v1/compute`（参数化，白名单能力） |
| 鉴权 | `X-Partner-Id` + `X-Timestamp`（±300s）+ `X-Nonce`（Redis/内存去重 600s）+ `X-Signature=HMAC-SHA256(secret, method\npath\nbody_sha256\nts\nnonce)` |
| 网络 | nginx `allow 49.233.123.96; deny all;`；仅 HTTPS；强制 TLS1.2+ |
| 限流 | 20 QPS + 单日 10 万次；超限 429 |
| 白名单 | 只允许只读能力（54 manifest 中 `visibility=public` 且 `mode=deterministic`）；禁止任何写接口、禁止 `/api/cognitive/*` 写、禁止交易与执行 |
| 请求体 | ≤64KB；禁止传用户身份字段（见 §6 数据出境） |
| 响应信封 | `{ok, data, degraded, provenance:{method_id, sample_n, sources, ts}}` |
| 超时/降级 | 主站侧 ≤8s；国内侧 5s 超时 + 熔断（连续 5 次失败熔断 60s），熔断期间只走本地缓存 |
| 审计 | 每次调用记 `trace_id / partner / path / status / ms`，保留 ≥180 天 |

**"更简单方法"（如果连 HMAC 都不想写）**：主站只提供一个每日全量快照文件（`/partner/snapshot-YYYYMMDD.json.gz`）+ 一个静态 token，国内 cron `curl` 拉取。安全性靠"文件只读 + IP 白名单 + 无写能力"，足以支撑 P0 前两个 SKU。等有参数化需求再上 §4 的签名接口。

## §6 合规判定（关键，可能一票否决）

### 6.1 经营性 ICP 许可（最大阻塞）

- 国内站向境内公众**有偿**提供在线数据/信息服务，属"经营性互联网信息服务"，通常需 **ICP 经营许可证（B25 信息服务业务）**，而不只是 ICP 备案。
- 备案（`www.dreamos.online` 进行中）只解决"能不能开站"，不解决"能不能收费"。
- 常见门槛：注册资本 ≥100 万元、3 名以上人员社保、无外资成分等。周期以月计。

**可选路径（按风险从低到高）**

| 路径 | 做法 | 风险 |
|---|---|---|
| ① 先 B 端合同 | 不面向公众挂价，只与机构签技术服务合同，按项目/年框收费 | 低；但规模受限，且"B 端"仍可能被认定为经营性 |
| ② 平台代收 | 通过已持牌的第三方平台（如 SkillPay 生态内已有资质的主体）分销 | 低；抽成与自主性下降 |
| ③ 自建 + 拿证 | 备案 → ICP 经营许可 → 公开售卖 | 合规但慢 |
| ④ 无证直接卖 | 502 收款 + 公开挂价 | 🔴 不建议，属非法经营风险 |

> 建议：P0 走 ①+②（B 端合同 + SkillPay 分销），把"国内站公开挂价自助付费"放到 ③ 拿证之后。

### 6.2 跨境数据

- 判定核心是**是否传输个人信息/重要数据**。只传 `symbol / indicator / window / date` 这类公开市场参数，不构成个人信息出境。
- 规则：国内站**禁止**把 `user_id / 手机号 / 订单号 / Payment-Proof / client_session` 发往主站；主站响应不得包含任何用户维度数据。
- 若未来要做"个性化分析"（含用户画像），必须先做数据出境评估（标准合同/安全评估），当前不设计。
- 反方向（主站数据进国内销售）涉及**上游数据授权地域条款**，见 6.3。

### 6.3 数据再分发授权

主站数据来自 Tushare / Wind / 交易所 / 新闻 / 链上源。**跨境 + 转售 = 双重授权问题**。上架前必须逐源登记：`数据源 → 授权依据 → 允许地域 → 允许再分发`。未登记的一律不上架。

### 6.4 支付

- 402 收款方在境内（49.233.123.96 调 `openapi.alipay.com`），链路正常，无跨境收款问题。
- 主站不经手资金，只做数据供给，避免"境外主体向境内用户收款"的外汇与税务复杂度。
- 发票由境内主体开"信息技术服务费/数据服务费"。

### 11.8 个人商户确认后的路线（最终版）

| 项 | 实际状态（个人商户） | 影响 |
|---|---|---|
| 支付宝收款额度 | 无营业执照：单笔 ≤50 元、单日 ≤1000 元 | 与 402 单笔上限刚好吻合；**日流水 1000 元是硬顶** |
| 开票 | 不可开增值税发票 | B 端客户无法采购 |
| 可签产品 | 可建应用、可登记服务；402 收款受个人额度约束 | 已登记的 0.99 元服务可继续用 |
| SkillPay 入驻 | 可（实名认证 + 开通收款能力） | **这是当前唯一能立刻开卖的合规通道** |
| ICP 经营许可证 | 不可（须企业法人） | 国内站不能公开挂价自营 |

**唯一可立即执行路径**：

1. **收款**：个人实名入驻 SkillPay，商品走平台代收，日流水受 ¥1000 限制；
2. **履约**：Skill 直连境外主站（用户本地发起），国内节点只做免费加速/缓存，不收款不挂价；
3. **升级触发器**：日流水稳定接近 ¥1000，或出现第一个要求开票的客户 → 立即办个体工商户（营业执照可解额度与开票，仍不能解 ICP 证）；
4. **不要做**：现在就在国内站公开挂价自助收费——个人商户 + 无 ICP 经营许可，风险最高。

> 结论：主体从"个体户"修正为"个人商户"后，v0.2 的 SkillPay 路线不变，但"402 自营"从"可行但有风险"降为"暂不可行"。**先上 SkillPay，把真实付费跑通，再办执照。**
