## §0 结论摘要

### 0.1 一句话

**卖"可复现的数据事实与计算能力"，不卖"方向结论"；用 Machine Pay 收 API 的钱，用 SkillPay 收打包能力的钱，用同一个计费内核记一本账；认知系统不做商品，做溢价证据与续费理由。**

### 0.2 三条硬约束（决定了模式形状）

| # | 约束 | 事实来源 | 对模式的影响 |
|---|---|---|---|
| C1 | 402 单次金额 **0.01～50 元**，服务登记价固定；试运行期服务数上限约 10 个（已用 1 个） | Machine Pay 接入指南 + 支付宝服务登记表单 | SKU 必须少而稳，单价不能随参数浮动；第 10 个服务用完即无余量 |
| C2 | SkillPay「成交即到账」，退款由开发者手动发起；上架前须签 SkillPay + 即刻收协议并通过安全检测 | [skillpay.alipay.com](https://skillpay.alipay.com/) | 现金流好，但退款/客服/发票责任在我方，必须自建售后闭环 |
| C3 | 具备"具体品种分析 / 价格走势预测 / 品种选择建议 / 买卖时机建议"任一功能并收费 = 证券投资咨询业务，须持牌 | 证监会《关于加强对利用"荐股软件"从事证券投资咨询业务监管的暂行规定》（2012） | **模型方向判断不能作为 C 端付费商品**；这是一票否决项，不是文案问题 |

### 0.3 推荐模式（四层）

```text
免费层  →  计量层（Machine Pay 402）  →  订阅层（SkillPay 买断/订阅）  →  B 端层（合同）
引流        按次付费，Agent 自动结算          打包能力，复购               持牌机构技术供应商
```

### 0.4 不做什么

| 禁止 | 原因 |
|---|---|
| 对公众售卖"买卖点 / 目标价 / 涨跌预测 / 选股结果" | C3，无牌照即违法，声明"不构成投资建议"不能免责 |
| 售卖 `l1.trading.mcp` 与 49 §3.8 的 10 个交易工具 | 内部状态读取 + 执行类能力，manifest 要求 internal，且涉代客交易 |
| 把认知系统单独做成一个收费 SKU | 用户判断正确：单卖认知系统无意义；它应是证据层 |
| 未确认授权的数据源对外再分发 | 上游（Tushare / Wind / 交易所 / 新闻源）商用授权是独立红线 |
| 三个通道三套订单/对账 | 必然出现对账差异与重复履约 |

## §1 三来源调研结论

### 1.1 SkillHub 教程页（`skillhub.cn/tutorials`）

| 项 | 结论 |
|---|---|
| 发布入口 | CLI（`skillhub publish`）只能发**免费** Skill；付费走 SkillPay 网页向导 |
| 前置 | 手机号注册 → 实名认证（人脸核身）→ 创建 `skh_` API Token → CLI 登录 |
| 发布校验 | `SKILL.md` frontmatter 必填 `slug`（全网唯一）/`displayName`/`version`/`summary`/`license`；`--dry-run` 本地预检 |
| 审核 | 提交后 `status=pending_review`，详情页在审核通过前不可见 |
| 与我们的关系 | 已具备 CLI 发布链路；**付费上架不在 CLI 能力内**，必须走 SkillPay 后台 |

> 结论：SkillHub 是**分发渠道**，不是收款渠道；收款方是 SkillPay。两者不可混为一谈。

### 1.2 支付宝 AI 资源中心（`open.alipay.com/ai/ai-resource-center/welcome`）

页面本身是平台宣传页（资源统一注册 / 按需订阅 / 版本管理 / 多主体调用），真正的规则在 [aipay.alipay.com 产品矩阵](https://aipay.alipay.com/docs/overview.md)。完整矩阵与适配判断：

| 产品 | 收什么钱 | 是否适配我们 | 判断依据 |
|---|---|---|---|
| **Machine Pay** | API 按调用/用量 | ✅ 主通道 | 我们本就是"数据 + 计算"的 HTTP 能力 |
| **Skill Pay** | Skill 买断 / 订阅（周/月/季） | ✅ 副通道 | 把多个 API 打包成"可被 Agent 安装的能力" |
| Vibe Pay | 网页/移动应用（买断、次数包、积分包、时长包） | ⭕ 可选 | 自建工作台收款时用；需自建订单与权益 |
| Token Pay | 大模型 Token / 席位订阅 | ❌ 暂不 | 我们不是模型厂商 |
| Agent Pay | 让 Agent 代用户下单购买第三方商品 | ❌ 暂不 | 属"帮别人卖货"，与本次变现无关 |

> 关键结论：**Machine Pay 收"机器调用的钱"，SkillPay 收"Agent 商店里打包能力的钱"，二者共用同一笔交易事实，但订单模型不同**。前者基于 `out_trade_no + service_id + amount`，后者基于 `productId` 商品订单。

### 1.3 Machine Pay 技术契约（必须逐条满足）

| 环节 | 要求 | 我们的落点 |
|---|---|---|
| 预下单 | `alipay.aipay.agent.payment.precreate`，入参必填 `out_trade_no`（幂等）/`service_id`/`goods_name`/`amount`（≤50 元）/`pay_before`；币种仅 CNY | `skillhub-audit-api` 已实现 |
| 402 响应 | `HTTP 402` + 响应头 `amtPaymentLink: <amt_pre_pay_id>` | 已实测 `402 / amount=0.99 / payment-needed` |
| 验付 | 解析 `Payment-Proof`（base64：`payment_proof` + `trade_no` + `client_session`）→ `alipay.aipay.agent.payment.verify` | 已实现 |
| 验付通过条件 | `active=true` **且** `amount` 等于资源价 **且** `out_trade_no` 是我方单号 **且** `resource_id` 与本次资源一致 **且** `trade_no` 未被重复履约 | 五项缺一不可，当前已实现金额与幂等两项，需补齐 `resource_id` 校验 |
| 网关 | 生产 `https://openapi.alipay.com/gateway.do`，签名 RSA2 | 已配置 |

## §2 能力盘点：可卖 / 需改造 / 不可卖

按 [capability_manifest.yaml](file:///Users/zhangjiangtao/WorkBuddy/dreambuddy-v2/54-L1架构能力聚合层/capability_manifest.yaml) 的 `visibility_default: public` 与 intent 分布（metric_series 16、correlation_query 5、cross_section_query 5、metric_percentile 5、risk_allocation_query 5、trend_query 4、signal_decomposition 4、technical_indicator 2、seasonality_query 2、drawdown_query 2、event_study 2）划分：

| 层 | 内容 | 处置 |
|---|---|---|
| **A 可直接卖（事实层）** | 时序取点、变化率、CAGR、分位、Z-score、年化波动、回撤画像、同比/环比、同比实际利率、滚动相关、领先滞后相关、极值频率、ETF 资金流、稳定币增速、拥挤度、季节性、事件研究、条件收益、状态转移 | Machine Pay SKU 主体；全部输出"数值 + 样本量 + 降级原因" |
| **B 需改造才能卖** | 模型分析（归因/拆解）、报告生成、回测 | 只输出"解释已发生的事实"，删除前瞻方向词；报告模板化 |
| **C 不可卖** | `l1.trading.mcp` 10 工具、执行层 paper/live、策略参数写入、审批链、插件安装 | 内部专用；`visibility_internal` 兜底 |
| **D 免费引流** | 每日简报 `/api/briefings`、公开卡片、市场概览 | 获客 + 建立可信度，不计量 |

**认知系统的正确定位（回应用户"单纯一个认知系统似乎没有什么意义"）**

| 角色 | 做法 | 商业价值 |
|---|---|---|
| 证据层 | 每个付费结果附 `provenance`：method_id、样本量 n、降级原因、数据时间戳、血缘来源 | 结果可复核 → 支撑比同行更高的定价；B 端尽调可过 |
| 留存层 | 订阅用户的 watchlist、历史结论、变化提醒 | 提高续费率，降低"买一次就走" |
| 降本层 | 缓存复用已算过的统计量（现有 60s 缓存只是起点） | 提高毛利，允许低价高频 SKU |

## §3 合规红线（按"一票否决"排序）

### R1 荐股软件认定（最硬）

证监会 2012 年暂行规定：软件具备 **具体证券投资品种分析 / 价格走势预测 / 证券品种选择建议 / 买卖时机建议** 之一，并向投资者销售或提供且直接间接获取经济利益 → 属于证券投资咨询业务，须持牌。

落地规则：

| 禁止出现在付费输出 | 允许的替代表达 |
|---|---|
| "建议买入/卖出"、"目标价"、"明日看涨" | "近 250 日分位 87%，样本 250，方法 S25" |
| "推荐组合"、"优选 5 只" | "按你给定条件筛出 12 个满足项，条件如下" |
| "胜率 78%"、"稳赚" | "该形态历史出现 41 次，后续 5 日均值 +0.3%，标准差 2.1%" |
| "AI 判断该股将上涨" | "拆解：营收同比 +18%（来源 9-基本面），毛利率环比 -1.2pct" |

> 判定看**实质功能**而非免责声明。加"不构成投资建议"不能把荐股软件变成工具软件。

### R2 生成式 AI 备案

面向境内公众提供生成式 AI 服务需履行备案；具舆论属性/社会动员能力的算法需算法备案。金融属强监管领域。
**处置**：P0 阶段付费 SKU 只输出**确定性统计 + 模板化叙述**（不自由生成）；自由生成能力留在内部工作台，同时启动备案评估。

### R3 数据源再分发授权

18/19/20 层数据来自 Tushare、Wind、交易所、新闻与链上源。**"内部使用"与"对外转售"是两种授权**。处置：每个 SKU 上架前登记"数据源 → 授权依据 → 可再分发范围"，未确认的不上架。

### R4 支付合规

- 我方是**商户直收**（支付宝直连），不做资金归集，不构成二清；如需给渠道分账，须走持牌机构分账产品。
- 402 单笔 ≤50 元；超价需求只能拆单或转为订阅。
- 退款：Machine Pay 需自建退款流程；SkillPay 由创作者在产品页手动发起，周期付费整单全额退。
- 发票：以"信息技术服务费 / 数据服务费"开具，需具备开票能力。
- 支付凭证含 `client_session`，仅用于验付，不落明文、不进日志。

### R5 宣传与投资者适当性

不得承诺收益、不得暗示保本、不得使用"内幕/跟庄/稳赚"；页面须有风险提示与服务条款；C 端不得做"代客理财"。

## §4 商业闭环模型

### 4.1 一内核、三通道、四层产品

```text
                    ┌──────────── 计费内核（Billing Core）────────────┐
                    │ 订单状态机 · 幂等键 · 价格表 · CU 账本 · 对账 · 退款 │
                    └───▲───────────────▲────────────────▲───────────┘
                        │               │                │
        ┌───────────────┴──┐  ┌─────────┴────────┐  ┌────┴─────────────┐
        │ Machine Pay 402  │  │ SkillPay 商品订单 │  │ 对公合同/线下开票 │
        │ 面向 Agent 的 API │  │ 面向 Agent 商店   │  │ 面向持牌机构      │
        └───────────────┬──┘  └─────────┬────────┘  └────┬─────────────┘
                        │               │                │
  免费层 ──►  计量层（按次） ──►  订阅层（买断/月/季） ──►  B 端层（年框）
  简报/卡片      0.01–50 元/次        9.9–29 元/期          合同定价
                        │               │                │
                        └──────► 履约（L1 能力执行 + provenance）◄──┘
                                        │
                          认知层：记录 → 复盘 → 调价/换 SKU
```

### 4.2 闭环七步（每一步都要有可观测证据）

| 步 | 动作 | 证据 |
|---|---|---|
| 1 发现 | SkillHub / Agent 商店 / 官网落地页 | 曝光、点击 |
| 2 试用 | 免费层：每日简报 + 每 SKU 每月 N 次免费额度 | 试用转化率 |
| 3 付费 | 402 预下单 → 用户确认 → 验付；或 SkillPay 商品下单 | 402 次数、支付成功率 |
| 4 履约 | 执行能力 → 返回结果 + provenance | 履约成功率、P95 时延 |
| 5 记账 | 写 CU 账本（append-only），与支付宝流水日对账 | 对账差异 = 0 |
| 6 复购 | 用量阈值触发订阅推荐；订阅用户获得跟踪记忆 | 续费率、ARPU |
| 7 售后 | 退款、发票、客服；异常样本回灌认知层 | 退款率、投诉率 |

### 4.3 为什么这样切分

| 选择 | 理由 |
|---|---|
| API 走 Machine Pay 而非 Vibe Pay | Agent 调用场景不该跳转登录；402 是原生协议，链路最短 |
| 打包能力走 SkillPay | 用户买的是"装进 Agent 就能用"，订阅制可复用 |
| 不做一个"大而全"SKU | 402 单价上限 50 元 + 服务数上限 10 个，必须按"调用粒度"切 |
| 认知系统不单卖 | 单卖无意义；作为 provenance 与留存机制提升客单价与续费率 |

## §5 SKU 设计（9 个，正好用满剩余额度）

> 已用 1 个（Skill 上架体检 0.99 元），试运行期上限约 10 个 → **只有 9 个名额，一次性规划到位**。
> 单价必须固定，不能随参数浮动；需要变价的场景改为"拆分为两个 SKU"或"转订阅"。

| # | SKU | 方法与路径 | 输入要点 | 单价 | 类型 |
|---|---|---|---|---|---|
| 1 | 市场快照 | `GET /v1/market/snapshot` | symbol、fields | ¥0.05 | 同步 |
| 2 | 指标计算 | `POST /v1/metrics/compute` | capability_id（分位/Z-score/波动/回撤等）、series、window | ¥0.10 | 同步 |
| 3 | 技术分析包 | `POST /v1/technical/analyze` | symbol、period、indicators[] | ¥0.30 | 同步 |
| 4 | 基本面快照 | `GET /v1/fundamental/snapshot` | module、days | ¥0.50 | 同步 |
| 5 | 数据研究查询 | `POST /v1/research/query` | message、intent（L1 直答） | ¥0.20 | 同步 |
| 6 | 事件研究/相关性 | `POST /v1/analytics/event-study` | events[]、window、universe | ¥1.00 | 同步 |
| 7 | 报告生成 | `POST /v1/report/generate` | template、scope、date | ¥5.00 | 异步 |
| 8 | 回测 | `POST /v1/backtest/run` | strategy_ref、区间、成本假设 | ¥10.00 | 异步 |
| 9 | 事实问答 | `POST /v1/cognition/recall` | query（仅返回事实 + provenance） | ¥0.02 | 同步 |

**定价锚点**：终端数据产品年费数千元 → 单次 0.02–0.5 元对 Agent 场景是"零感知"；高价 SKU（报告/回测）用异步 + 失败退款兜住体验。

**异步 SKU 规则**：先收款 → 建任务 → 成功履约 / 失败 24h 内原路退款；同一 `out_trade_no` 严禁二次履约。

**SkillPay 商品（打包层，3 个起步）**

| 商品 | 内容 | 定价形态 | 合规要点 |
|---|---|---|---|
| 市场事实日报 Skill | SKU 1/2/5 打包 + 每日定时产出 | 买断 ¥0.99 / 月 ¥9.9 | 只陈述事实，无方向词 |
| 个股基本面体检 Skill | SKU 4/6 + 报告模板 | 买断 ¥19.9 | 不含评级/目标价 |
| 数据研究工具箱 Skill | SKU 2/3/6 全量 | 订阅 ¥29/月 | 参数化查询，结果可复现 |

### 6.2 订单状态机

```text
CREATED ──precreate──► PENDING_PAY ──verify(active)──► PAID ──fulfil──► FULFILLED
   │                        │                            │
   │                        └──超时/过期──► EXPIRED       ├──重复 trade_no──► REJECTED
   └──参数非法──► INVALID                                └──履约失败──► REFUNDING ──► REFUNDED
```

三个不变量：
1. `out_trade_no` 全局唯一，一单一资源；
2. `trade_no` 只允许履约一次（幂等表 + 唯一索引）；
3. 账本 append-only，任何修正以反向分录表达。

### 6.3 内部 CU 与外部价格的关系

`1 CU = ¥0.01`。外部 SKU 价固定，内部按实际资源消耗折算 CU 记入 `usage_ledger`，用于毛利分析与限流；**两套数字不互相推导**，避免出现"价格被内部成本反向绑架"。
