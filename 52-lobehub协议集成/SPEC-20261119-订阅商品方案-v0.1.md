## §0 结论

**两个订阅商品的商业逻辑成立，但"系统内数据整体打包对外"这一步今天做不了，缺的不是产品设计，是一个可被外部 Agent 访问的数据出口。** 因此拆成两层交付：

| 层 | 内容 | 今天可否上架 | 依赖 |
|---|---|---|---|
| **L1 本地取数** | Skill 内置**海外开放许可源**抓取 + 本地计算（同 market-facts 架构） | ✅ 可以 | 无后端 |
| **L2 网关取数** | 调我们自己的只读数据 API，覆盖行情类与高频模块 | ❌ 不能 | 需公网只读网关 + 商用行情授权 |

建议 **L1 先上（覆盖 3 个海外数据模块 / 3 类官方事件），L2 作为"行情增强版"增量**，用同一商品名做版本升级，而不是改商品形态。

## §1 硬约束（先定边界，再谈功能）

| # | 约束 | 事实 | 影响 |
|---|---|---|---|
| C1 | 买断/订阅**选定不可更改** | 商品页原文 | 必须是**新商品**，不能改现有 ¥0.99 那个 |
| C2 | 个人商户单笔 ≤ ¥50 | 支付宝个人主体 | **所有订阅价必须 ≤ ¥49.9**，季付不能简单做 3×月付 |
| C3 | 个人商户单日 ≤ ¥1000 | 同上 | 订阅制客单价高，正好用更少笔数做更高流水 |
| C4 | 订阅仅当期使用权，周期付费整单全额退 | SkillPay 规则 | 退款成本由我们承担，必须在商品页写清 |
| C5 | 无营业执照 → 不能开票 | 个人主体 | B 端采购不了，只能面向个人/Agent 用户 |
| C6 | 到期回收机制未验证 | 未实测 | 必须先跑一次到期场景，再规模化卖长期订阅 |

> C2 是定价设计里最容易被忽略的一条：常见做法是「¥29/月、¥99/年」，但 ¥99 直接撞上限。本方案所有价格都压在 49.9 以内。

## §2 商品 A：完整数据服务（订阅）

### 2.1 定位

面向 Agent 的**数据层订阅**：只提供**许可明确允许商用**的海外公开数据，以及基于其上的自算指标。输出恒为「数值 + 样本量 + 方法ID + 数据时间戳」，不含方向判断。

**判据是许可条款，不是"能不能打开"。** 公开可访问 ≠ 可商业再分发：腾讯/新浪/东财行情、上交所深交所行情、Yahoo Finance 均属公开但禁止商用再分发，一律不接。

### 2.2 模块划分（按许可确定性排序，不按系统菜单）

| # | 模块 | 内容 | 来源 | 许可 | 可否上架 |
|---|---|---|---|---|---|
| D1 | 海外宏观指标 | 利率、CPI、GDP、失业率、汇率 | FRED / World Bank / ECB | Public Domain / CC BY 4.0 / 免费使用 | ✅ |
| D2 | 美股公司披露 | 10-K / 10-Q / 8-K 的结构化字段 | SEC EDGAR | Public Domain | ✅ |
| D3 | 自算统计 | 分位、Z-score、年化波动、最大回撤、均线偏离、滚动相关 | 基于 D1/D2 派生计算 | 自有计算产物 | ✅ |
| D4 | 海外指数与 ETF 行情 | 收盘、涨跌幅、成交额 | 需商用许可的行情 API（Alpha Vantage premium / Polygon / EOD 等） | 付费许可 | 🟡 先买授权再上 |
| D5 | 区块链公开数据 | 区块高度、每日交易数、gas 消耗、出块间隔 | **自采**：公共 RPC / 自建节点 | 公有链数据自行采集，不依赖第三方再分发 | ✅ |

**结论：D1 / D2 / D3 / D5 当天可上**（D5 走自采，不依赖 CoinGecko 之类的第三方 API，因此无"免费档禁商用"问题）；**D4 海外指数与 ETF 行情仍需商用授权**，需先指定付费行情源。国内 A 股模块本期不做（交易所行情需信息经营许可）。

**数据商品的三块能力（本商品定位）**

| # | 能力 | 交付 | 说明 |
|---|---|---|---|
| A-1 | 开放数据接入 | 结构化原始序列 | D1/D2/D5，每条带来源与许可 |
| A-2 | 数据上下文 | 口径 + 历史分布 + 可比对象 | 「这个数字怎么读」，给分位不给判断 |
| A-3 | 交叉统计处理 | 分组均值、交叉表、条件分布、相关系数 | 只分组不排序，不输出优选名单 |

三块共用一套取数与计算内核，Agent 一次调用即可从"拿数"走到"可复核的上下文"。

商品页文案必须写"本期覆盖 D1–D3，行情类随授权进度开放"，不能承诺全模块。

### 2.3 交付形态

```text
data-service/
├── SKILL.md              # 模块清单、方法ID、口径、来源许可、红线
├── scripts/
│   ├── macro.py          # D1 海外宏观指标（FRED / World Bank / ECB）
│   ├── filings.py        # D2 美股披露结构化字段（SEC EDGAR）
│   └── stats.py          # D3 自算统计
└── references/
    ├── methods.md        # 每个指标的公式与样本量定义
    └── licenses.md       # 数据源 → 许可 → 可商用 → 署名要求
```

与现有 market-facts 一致：纯标准库、零依赖、单文件可跑、接口失败即标 `数据不可用`，不估算。

### 2.4 定价（全部 ≤ ¥49.9）

| 周期 | 价格 | 折算月价 | 说明 |
|---|---|---|---|
| 每月 | ¥19.9 | ¥19.9 | 主力入口 |
| 每季 | ¥49.9 | ¥16.6 | 相当于 8.4 折，卡在单笔上限内 |
| 每周 | ¥5.9 | ¥25.6 | 只做低门槛试水，不做主推 |

免费试用 **5 次**（平台下限）：让用户先看到真实数字再付费，转化率显著高于纯文案。

## §3 商品 B：事件上下文服务（订阅）

### 3.1 定位

面向 Agent 的**事件型订阅**：把公告/声明/披露装配成五层上下文，回答"发生了什么、牵扯谁、历史上同类出现过几次"。

**核心处理方法是本商品的壁垒**：实体映射、同类事件检索、频率分布、来源血缘——这几件恰好是 Agent 靠单次检索拼不出来的。

边界划分：**数字归商品 A（数据），事件归商品 B（新闻）**。数据上下文与交叉统计已并入商品 A，本文只做事件入口。

刻意不叫"热点解读"——"解读/热点"天然携带观点，会同时触发两条线：著作权上从"引用事实"变成"演绎作品"；合规上从"数据服务"滑向"投资建议"。

### 3.2 输出结构（五层）

```json
{
  "event": { "time": "2026-11-19", "source": "SEC", "type": "8-K", "subject": "AAPL", "headline_facts": ["..."] },
  "entities": { "tickers": ["AAPL"], "sector": "Tech Hardware", "supply_chain": ["TSMC", "Foxconn"] },
  "analogues": { "n": 37, "window": "T+5", "stat": { "mean": 0.004, "std": 0.021 } },
  "sources": [{ "title": "...", "url": "https://sec.gov/...", "license": "Public Domain" }],
  "limits": "仅提供已发生事实与历史分布，不含影响判断"
}
```

| 层 | 内容 | 明确不给什么 |
|---|---|---|
| event | 时间、发布主体、文件类型、事实要点 | 不做"利好/利空"定性 |
| entities | 涉及标的、行业、上下游 | 不做标的推荐、不做排序 |
| analogues | 同类事件次数 n、窗口、均值/标准差 | 不推"这次会怎样" |
| sources | 标题、链接、许可类型 | 不转载全文、不做超长引述 |
| limits | 固定声明 | — |

`analogues` 给的是**次数与分布**，不是结论。这既守住红线，也正好是 Agent 最需要的可比性。

### 3.3 来源与许可（只采官方源）

| 源 | 类型 | 许可 | 可商用 |
|---|---|---|---|
| SEC EDGAR | 公司公告、10-K/10-Q/8-K | Public Domain | ✅ |
| 美联储 FOMC 声明/纪要 | 货币政策 | Public Domain | ✅ |
| ECB 决议与统计 | 货币政策 | 免费使用，需署名 | ✅ |
| World Bank / IMF | 宏观 | CC BY 4.0 / 署名 | ✅ |
| 商业媒体（Reuters / Bloomberg 等） | 新闻报道 | 订阅协议禁止再分发 | ❌ 一律不采 |

**规则：只采政府/监管机构公开文件；每条输出必须带 `license` 字段；未登记来源的事件不进上下文包。**

### 3.4 与"新闻摘要"的差别（为什么这样更值钱）

| | 新闻摘要 | 事件上下文服务 |
|---|---|---|
| 著作权性质 | 复制/演绎作品，风险高 | 引用事实字段 + 链接，风险低 |
| 合规性质 | 易滑向解读与建议 | 只装配不评价 |
| Agent 可用性 | 需二次加工 | 可直接引用与串联 |
| 可复核性 | 弱 | 每条带源与许可 |
| 定价空间 | ¥9.9/月 | **¥19.9–29/月** |

**红线**：输出中不得出现"利多/利空/值得关注/影响有限/后续看涨"等定性词；`analogues` 只给次数与分布，不给方向结论。（交叉统计口径见 §2 A-3，已归入商品 A。）

### 3.5 定价

| 周期 | 价格 | 折算月价 | 说明 |
|---|---|---|---|
| 每月 | ¥19.9 | ¥19.9 | 主力 |
| 每季 | ¥49.9 | ¥16.6 | 卡在单笔上限内 |
| 每周 | ¥5.9 | ¥25.6 | 低门槛试水 |

组合：数据服务 ¥19.9/月 + 事件上下文 ¥19.9/月 = ¥39.8/月（平台暂不支持捆绑，需分两次购买）。

## §4 风险清单（不认同"没有风险"的部分）

| # | 风险 | 等级 | 依据 | 处置 |
|---|---|---|---|---|
| R1 | **行情类数据商用再分发** | 🟡 | D4–D5 需付费商用授权；腾讯/Yahoo 等公开接口明确禁商用 | 本期不上 D4–D5；逐源登记许可；取得书面授权后再开 |
| R2 | **事件内容著作权** | 🟡 | 只采官方文件后风险显著下降，但引述长度仍需控制 | 只采 SEC/美联储/ECB/世行/IMF；每条带 `license`；不存全文，引述控制在必要长度 |
| R3 | 荐股软件认定 | 🔴 | 证监会 2012 暂行规定 | 两商品均不含方向、评级、目标价、推荐；商品文案禁用"预判/看多/机会" |
| R4 | 生成式 AI 备案 | 🟡 | 面向公众提供生成式服务需备案 | 输出全部为确定性计算与模板化结构化字段，不自由生成 |
| R5 | 订阅到期回收未验证 | 🟡 | 未实测 | 上架后跑一次到期场景；未验证前不推年付（本方案本来就不做年付） |
| R6 | 个人主体无票/日限额 | 🟡 | 支付宝个人商户规则 | 定价 ≤49.9、日流水自我监控，接近 1000 即降速 |
| R7 | 数据接口不可用导致履约失败 | 🟡 | 公开源不稳定 | 失败即标 `数据不可用`，不重试不编造；连续失败在商品页公告 |

**结论：风险已从"一票否决"降为"可控"，但不是"没有风险"。** R1、R2 之所以降级，是因为我们主动放弃了行情类商用与商业媒体转述——这不是文案技巧，是产品边界。**上架前的硬门禁：每个模块/每类事件都必须有 `licenses.md` 登记行，未登记不上架。**

## §5 上线节奏

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 数据服务 L1（D1–D3：海外宏观 / SEC 披露 / 自算统计）+ 事件上下文服务（SEC、美联储、ECB 三类官方源） | 两个商品各自通过安全检测、可安装、能跑出真实输出 |
| P1 | 免费试用 5 次的实际体验；收集首批差评点 | 试用转化率、失败原因分布 |
| P2 | 到期场景实测（等一个完整周期） | 到期后 Skill 行为明确、无客诉 |
| P3 | L2 网关（只读 API + 备案） | D4–D5 补齐，商品升版 |

**P0 的第一个动作不是写商品，是给两个包各自写一版 SKILL.md 并本地跑通**——商品页文案从 SKILL.md 生成，包不成立则商品也不成立。
