## 1. 评审结论

v1.0 的方向（原地扩展、复用 27、三级权限、唯一新增表）成立，但**有 4 项 P0 问题会导致方案无法落地或产生事故**，主要集中在校验假设与实际代码不符：

- 鉴权方案与既有 `next-auth v5 + JWT` 事实冲突；
- 直写库会绕过 `classic-system-bridge`，造成"改成功但不生效"；
- 审计"失败回滚"与"先提交再推送"在事务语义上自相矛盾；
- 无 worker 载体，补偿/确认/限流无处落地。

## 4. 服务器负载评估（新增章节结论）

- 管理台复用现有 3456 Next 进程，**不新增进程**，增量内存 < 50MB，CPU 仅管理员请求时产生 → 同机增量 < 5%，可接受。
- 真实压力源是 `next dev` 常驻 300–800MB 与无连接池上限，属既有问题；本次一并修正为 `build/start` + `max_memory_restart=600M` + `connection_limit=5`。
- 不建议为隔离单开第二个 Next 实例（+150–250MB，收益低）；未来需要隔离时按 §12.2 预留方案。
