## 1. 配置文件优先级

### 1.1 优先级顺序（从高到低）

| 优先级 | 来源 | 说明 | 覆盖范围 |
|--------|------|------|----------|
| 1 | **环境变量** | 运行时通过 `export` 或命令行传入 | 全局覆盖所有配置文件 |
| 2 | **策略专属配置** | `.env.v15` / `.env.v15ct` 等 | 策略级覆盖公共配置 |
| 3 | **公共配置** | `.env.common` | 多策略共享的基础配置 |
| 4 | **代码默认值** | `get_config_*(key, default=xxx)` | 硬编码兜底值 |

### 1.2 加载流程

```
启动时
  ↓
加载 .env.common（基础配置）
  ↓
加载 .env.v15（策略配置，覆盖 common 中同名项）
  ↓
检查系统环境变量（已存在的不覆盖）
  ↓
写入 os.environ
  ↓
业务代码通过 get_config_*() 读取
```

### 1.3 关键规则

- **策略配置优先**: `.env.v15` 中的同名配置会覆盖 `.env.common`
- **环境变量最高**: 系统已存在的环境变量不会被配置文件覆盖
- **include 机制**: 配置文件支持 `include <file>` 语法，按 include 顺序合并
- **类型解析**: 自动解析 bool/int/float/none，其余保持字符串

## 3. 配置变更管理

### 3.1 变更流程

1. **评估影响**: 确认变更影响范围（是否需要回测验证）
2. **修改配置**: 修改对应配置文件
3. **更新文档**: 同步更新本文档
4. **验证生效**: 运行配置验证脚本
5. **记录变更**: 在 CHANGELOG 中记录

### 3.2 敏感配置管理

- API Key / Secret 等敏感配置禁止提交到代码仓库
- 敏感配置应使用 `.env.local` 或系统环境变量
- `.env.*` 文件中使用占位符或测试账户密钥

### 3.3 配置验证

运行以下命令验证配置：

```bash
cd 14-V15经典马丁策略
python3 -m lib.config_loader
```

或运行完整验证脚本：

```bash
make config-check
```

## 4. 常见问题

### Q1: 为什么修改了 .env.v15 但不生效？

**A**: 检查以下几点：
1. 是否有同名环境变量已设置（优先级更高）
2. 配置文件路径是否正确
3. 进程是否重启（配置启动时加载，运行中不动态刷新）

### Q2: LEVERAGE 在 common 和 v15 中都有，以哪个为准？

**A**: 以 `.env.v15` 为准。策略配置优先级高于公共配置。

### Q3: 如何临时修改配置测试？

**A**: 使用环境变量临时覆盖：
```bash
export V15_POLL_INTERVAL=60
python3 run.py
```
