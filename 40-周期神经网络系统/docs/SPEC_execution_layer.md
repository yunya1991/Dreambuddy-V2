# SPEC: 40-周期神经网络系统 — 独立执行层（模型预测能力验证场）

> 版本：v0.2（评审修复稿）
> 日期：2026-10-24
> 状态：终审通过（v0.2，2026-10-24；风控红线数值随终审冻结版本化）
> 上游：40-SPEC.md 主规格 v0.4（三路输出之路 3）
> 定位：40 系统专属验证场，不经 23 门禁，决策链路独立；主交易链路仍为 23 自进化系统

## 零 · 定位声明

1. **目的**：验证 40 周期理论的预测能力——通过小额真实交易采集反馈数据，形成『周期判定 → 策略映射 → 真实执行 → 反馈训练』闭环，为 P5/P6 阶段提供训练样本与晋级证据
2. **独立性**：不经 23 三步门禁（回测→影子→灰度），决策链路与 23 完全独立；23 门禁为正式策略晋升流程，本执行层为模型验证场，不占用门禁资源
3. **主交易链路不变**：23 自进化系统仍为主交易链路；本执行层任何表现不影响 23 决策
4. **风控边界仍在**：决策独立 ≠ 无风控——独立最小风控红线预注册（见第三章），无风控边界的『小额』会随验证推进而漂移

## 一 · 整体架构

```
40 主链路输出（cycle_state / strategy_mapping）
        ↓
【执行层】40-周期神经网络系统/execution/
  ├── 信号接收器：消费 40 产出物，生成验证交易意图
  ├── 龙头白名单过滤器：仅允许白名单标的（初期仅 BTC）
  ├── 风控红线检查器：单笔/总仓/日损三重上限（预注册）
  ├── 订单执行适配器：复用 22-执行引擎中心/30-真实环境交互系统既有能力
  └── 反馈数据采集器：成交/持仓/离场全量记录 → 标注 → 训练样本池
        ↓
  小额真实交易（龙头白名单内）
        ↓
  验证报告（准确率/IC/校准度/分段表现）→ 40 P5/P6 晋级证据
```

## 二 · 龙头白名单与验证锚点

**逻辑**：龙头是周期传导的起点（L4 板块传导层『龙头先行』），以龙头为验证对象 = 验证周期理论最上游的判定质量——龙头判不准，下游传导无从谈起。

| 阶段 | 白名单 | 扩展条件 |
|---|---|---|
| V1（初期） | 仅 BTC/USDT | — |
| V2 | + 黄金（GC=F）、标普500（^GSPC） | BTC 验证达标（见第六章）且对应数据源就绪 |
| V3 | + ETH/SOL（传导第二层） | V2 达标，验证板块传导层 |

**红线**：meme/增长型代币永不进入验证白名单（传导末端，噪声最大，验证价值最低）。

## 三 · 独立风控红线（预注册，禁止运行时调整）

| 项 | 上限 | 说明 |
|---|---|---|
| 单笔名义金额 | ≤ 100 USDT | 每笔订单名义价值上限 |
| 总仓位名义金额 | ≤ 300 USDT | 执行层全部持仓名义上限（v0.2 修正：原 500 与单笔 100×并发 3=300 不自洽，修正为 300 使三重上限自洽） |
| 日损上限 | ≤ 50 USDT | 触发后当日停止开新仓，仅允许平仓（含止损平仓与已持仓位的离场单，v0.2 明确） |
| 杠杆 | 禁用（1x 现货/逐仓） | 验证场不加杠杆 |
| 并发持仓数 | ≤ 3 | 同一时刻最大持仓标的数 |

> 注：以上数值为预注册建议值，终审时可调整一次，此后冻结版本化。触发任一红线时：拒绝新开仓 + 记录 violation 事件 + 通知（复用 15-监控告警系统，接口注入方式待 X0 阶段与 15 系统确认，v0.2 标注）。

## 四 · 验证指标（模型预测能力判定标准）

| 指标 | 定义 | 达标线（V1→V2 晋级） |
|---|---|---|
| 方向准确率 | UP/DOWN/NEUTRAL 判别 vs 实际方向（NEUTRAL 按波动率带内判定） | ≥ 55%（BTC，日线级别）且二项检验 p<0.10（v0.2 补充显著性要求） |
| 方向 IC | 判别置信度（校准后概率×方向符号）与未来 N 期收益的秩相关 | ≥ 0.05 且统计显著（p<0.05） |
| 概率校准度 | 置信 70% 的判别实际命中率应 ≈ 70%（可靠性曲线斜率） | 斜率 ∈ [0.85, 1.15] |
| 分周期段表现 | 牛熊段/震荡段分组准确率（分组标签来自 40 L2 周期状态） | 任一段不低于 45%，两段差 ≤ 20pp |

**统计效力说明（v0.2 新增）**：100 笔样本下 55% 准确率的二项检验 p≈0.16，单独不具显著性——因此达标判定以方向 IC 显著性（p<0.05）为主证据，准确率为辅助证据；若需准确率单独显著（p<0.05），样本量需 ≥ 160 笔（55% vs 50% 零假设）。验证报告须标注各指标的样本量与置信区间。

**持仓周期预注册（v0.2 新增）**：验证样本的目标持仓周期与判别时间框架对齐——日线级判别对应目标持仓 7 日（±2 日容差，由 strategy_mapping 输出的周期状态决定提前/延后离场）；周线级判别对应目标持仓 4 周。持仓周期写入交易意图，离场后按实际持仓时长分组统计。

**验证周期**：每笔交易从开仓到离场为一个验证样本；验证报告须满足运行 ≥ 8 周 **且** 样本 ≥ 100 笔（v0.2 修正：原『先到者为准』有统计效力缺陷——周期级信号 8 周内可能仅约 20 笔，样本不足即出报告无意义；改为双条件同时满足，以样本量为主要门槛）。

## 五 · 反馈数据闭环

```
真实交易（成交/持仓/离场）
   ↓ 反馈数据采集器全量记录
execution_trades.jsonl（逐笔：意图/信号快照/成交/离场/盈亏）
   ↓ 对接 12 系统 ml/label_samples.py 标注管道
标注样本（未来收益方向 + 40 判别快照对照）
   ↓
40 P5/P6 训练样本池（与主规格风险 7 样本量门槛并轨：矛盾事件 ≥ 200、语义事件 ≥ 1000、验证样本 ≥ 100 笔）
```

**数据格式**：execution_trades.jsonl 每行含 {ts, symbol, signal_snapshot（40 产出物完整快照+特征版本）, intent, fill, exit, pnl, validation_tag}——信号快照必须完整落盘，保证训练样本可复现。

**标注对接逻辑（v0.2 新增）**：execution_trades 的开仓时间戳 → 匹配 12 系统 label_samples 的最近 K 线（日线）→ 计算未来 7 日收益（与持仓周期预注册一致）→ 与 signal_snapshot 中的判别方向对照生成标注样本。转换脚本在执行层内实现，不改动 12 系统接口。

## 六 · 实施阶段

| 阶段 | 内容 | 通过标准 | 前置依赖 |
|---|---|---|---|
| X0 | 执行层骨架：信号接收 + 白名单过滤 + 风控检查 + 记录（不下单） | 意图流全量落盘 ≥ 2 周 | **代理信号源**：P1-P4 未实施期间，允许接入 12 系统信号作为代理信号源验证执行层管道本身（仅验证管道，不产生验证指标）；40 主链路 P1 产出后切换真实信号源（v0.2 新增） |
| X1 | 纸面验证：X0 意图流 vs 实际行情，计算四项验证指标 | 指标可计算且分布稳定（依赖 X0 真实信号源数据 ≥ 2 周，v0.2 明确） | X0 通过且已切换 40 主链路真实信号源 |
| X2 | 小额实盘：BTC 白名单，单笔 ≤ 100 USDT 真实下单 | 运行 ≥ 8 周且 ≥ 100 笔，无风控红线违规 | X1 通过 |
| X3 | 验证报告：出具模型预测能力验证报告 | 四项指标全部达标线以上（含统计效力说明） | X2 通过 |
| X4 | 白名单扩展：V2/V3 逐级扩展 | 上一级验证报告达标 | X3 通过 |

**红线**：X1 指标不达标不进入 X2；X2 期间任一风控红线违规 2 次即回退 X1 并复盘；验证报告未达标不扩展白名单。

## 七 · 与既有系统的接口

| 系统 | 接口 | 关系 |
|---|---|---|
| 40 主链路 | cycle_state/strategy_mapping → 信号接收器 | 输入（X1 起必须为真实产出） |

| 22-执行引擎中心 | 订单执行能力复用（复用不新建） | 执行 |

| 15-监控告警系统 | 风控红线违规通知（接口注入方式待确认） | 告警 |
| 23 自进化系统 | **无接口**（决策链路独立，主交易链路不变） | 无关 |

## 八 · 边界红线

1. 执行层是验证场不是盈利工具：任何以盈利为目标的参数调整均违规，参数只允许依据验证指标调整且需版本化
2. 风控红线预注册冻结，禁止运行时放宽
3. meme/增长型代币永不进入验证白名单
4. 验证数据不得用于向 23 门禁推荐策略（23 主链路决策不受执行层表现影响）
5. 执行层故障不影响 40 主链路产出（fail-open：执行层宕机时主链路照常输出）
6. X0 代理信号源仅验证管道，不得据代理信号出具任何验证指标或报告（v0.2 新增）

## 九 · 验收标准

1. X0：意图流落盘完整率 100%，信号快照可复现；代理信号源与真实信号源切换零代码改动（配置切换）
2. X2：风控红线零违规（或单次违规即整改复盘）
3. X3：验证报告四项指标全部达标（含样本量、置信区间与显著性标注），报告归档并作为 P5/P6 晋级证据
4. 反馈闭环：execution_trades.jsonl → 标注样本 → 训练样本池管道打通，样本可追溯
