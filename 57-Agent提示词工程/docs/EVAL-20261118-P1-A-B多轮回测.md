# EVAL-20261118 — 宪法注入 A/B 多轮回测（P1 前置验证）

> **版本**: v1.0 ｜ **日期**: 2026-11-18
> **归属**: [SPEC-57](../SPEC-57-Agent提示词工程.md) §8 P1 前置验证
> **脚本**: [run_prompt_ab.py](../evals/run_prompt_ab.py) ｜ **原始结果**: [evals/out/](../evals/out/)（`summary.md` / `summary.json` / 每轮明细）
> **结论一句话**: 宪法注入**稳定提升可审计性**（证据声明 0%→100%、C-05 违例归零），但**不提升内容命中率**，且带来 19%~248% 的 token 成本；因此 P1 必须**按任务类裁剪注入**，不能全局全量注入。

---

## §1 目的与预注册判据

问题：把 `PROMPT_CONSTITUTION.md` 的 P0 段追加到现行 prompt 尾部，是否带来可测提升？

A/B 唯一差异 = system prompt 尾部是否注入宪法段；模型、温度（0.1）、用例、顺序全部相同；宪法段由 md **现场提取**（不复制正文，避免双事实源）。

**预注册判定规则**（写进脚本，事后不改）：

1. 提升成立需同时满足：`Δ ≥ +3pp`、`McNemar p < 0.20`、护栏不破（JSON 可解析率不降、avg_tokens 涨幅 ≤ 40%）。
2. 违例下降但准确率/命中率下滑 = 退化，不判提升。
3. 同类任务至少两轮方向一致，才认定为稳定结论。

两个任务类：
- **意图识别**（结构化分类，55 例，主指标 joint = 一级+二级同时正确）——预期天花板效应；
- **开放分析**（56 评测集 `baseline: true` 的 8 题，主指标事实命中率）——宪法主战场。

## §2 结果

### 2.1 意图识别（55 例 × 3 轮）

| 轮次 | B 臂 | A joint% | B joint% | Δ(pp) | A json% | B json% | A evidence% | B evidence% | 违例 | A tok | B tok |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | full | 90.91 | 90.91 | 0.0 | 100 | 100 | 0 | 5.45 | 0/0 | 2446 | 3306 |
| 2 | lite | 92.73 | 90.91 | -1.82 | 100 | 100 | 0 | 0 | 0/0 | 2444 | 2877 |
| 3 | lite | 90.91 | 90.91 | 0.0 | 100 | 100 | 0 | 0 | 0/0 | 2446 | 2864 |

- 三轮 Δ 均 ≤ 0，`p=1.0`；**不判提升**。
- token +19%~+35%（full 更贵）。
- 分类任务输出无 `evidence` 字段，全量宪法里 C-04 的要求与既有输出 schema 冲突，full 臂只让 5.45% 的输出长出 evidence 字段 —— 说明「与输出契约冲突的条款不会被遵守」。

### 2.2 开放分析（8 题 × 3 轮）

| 轮次 | B 臂 | A fact% | B fact% | Δ(pp) | A 声明证据% | B 声明证据% | A 违例 | B 违例 | A tok | B tok |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | full | 75.00 | 66.66 | -8.34 | 0 | 100 | 1 | 0 | 292 | 1017 |
| 2 | full | 75.00 | 79.16 | +4.16 | 0 | 100 | 1 | 0 | 312 | 1021 |
| 3 | lite | 75.00 | 64.59 | -10.41 | 0 | 100 | 0 | 0 | 284 | 599 |

- 事实命中率 2/3 轮下降且幅度 8~10pp，`p=1.0`；**不判提升**。
- **证据声明率 0% → 100%，3/3 轮稳定**（确定性收益，来自 C-04）。
- **C-05 违例 1 → 0**（S4「主要矛盾」题，A 臂出现「预计」，B 臂无），2/2 有违例的轮次均消除。
- token 在极短基线 prompt（77 字符）下涨幅 111%~248%，属该实验设置放大；生产 prompt 约 5000 字符时，700~1500 字符宪法段对应 +14%~30%。

## §3 判定

| 维度 | 结论 | 证据 |
|---|---|---|
| 内容准确率/事实命中率 | **无提升**，分析任务有轻度退化风险 | 意图 Δ≤0；分析 Δ 两轮为负 |
| 证据分级合规（C-04） | **显著提升，稳定** | 0%→100%，3/3 轮 |
| 禁预言词（C-05） | **提升** | 1→0 例，2/2 轮 |
| JSON 稳定性 | 无退化 | 100% 维持 |
| token 成本 | 明显上升 | +19%~35%（长基线）/ +111%~248%（极短基线） |

**一句话**：宪法买到的是「可审计、可对账」，不是「更准」。用「准不准」验收宪法会得出错误结论；用「合规率 + 可溯性」验收才成立。

## §4 对 P1 的三条硬决策

1. **按任务类裁剪注入，禁止全局全量**：
   - 分类/路由类（`l2.intent.router`、3.1 技能提示）：只注入 **P4 输出契约 + C-11**，不注入 C-01/C-02/C-03（本就不产生执行语句），实测无收益且 +19~35% token。
   - 分析/研究/辩论类（`l2.app.trade_ops`、`l2.debate.core`、`l2.emergence.*`）：注入 **full**，收益集中在 C-04/C-05。
2. **宪法条款必须与输出 schema 对齐**：C-04 要求 `evidence` 字段，则对应 `output_contract` 必须显式声明该字段（否则模型 90%+ 概率忽略）。这写进 P2 的 `output_contract` 冻结项。
3. **成本预算**：注入段的 token 必须计入注册表 `token_budget.fixed`；P1 落地时把宪法段长度写进 `meta.constitution_tokens`，由 G-P-7 检查 `fixed + context ≤ 4000`。

## §5 局限（必须随结论一起读）

1. n 小：意图 55 例（每轮 1 次采样）、分析 8 题；p 值只能作为方向参考，不能当显著性证明。
2. 单一模型（DeepSeek）；跨模型可复现性未验证。
3. 「事实命中率」是关键词命中口径，不等于事实正确率；`must_have_facts` 中 3/8 题未签核（`signed_off: false`）。
4. 分析任务 A 臂基线 prompt 仅 77 字符，token 涨幅被放大；生产场景应按 5000 字符基线折算。
5. 未做「宪法段长度 → 事实命中率」的消融实验；第 2 轮 full 的 +4.16pp 是否为噪声，需在 P2 用 ≥20 例/任务类复核。
