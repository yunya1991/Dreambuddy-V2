## 零 · 定位声明

1. **协调而非执行**：本层只负责信号传递、状态共享、弹性约束参数下发、逆向权重反馈与开关治理。**订单出口保留在各子系统**（40执行层 / 23自进化主链路 / 29事件驱动等），本层不下单、不代理下单、不统一下单。
2. **零代码侵入**：本层通过参数与开关施加影响，**不修改任何子系统的代码**。子系统按自身节奏消费本层产出物；不消费时行为与现状完全一致。
3. **单向依赖不回写**：延续 40→23 宏观约束适配器的既有原则——本层只读取子系统产出物，绝不写回子系统内部状态。
4. **fail-open 回退**：本层任何组件异常时，子系统按本地默认参数独立运行，交易能力不受影响。协调层是『增益器』而非『必经路径』。
5. **即插即拔**：新子系统只需实现一个 Publisher（发布信号）和/或一个 Subscriber（消费参数），无需修改本层或其他子系统接口。

### 与 23 系统的分工边界

| 职责 | 归属 |
|---|---|
| 策略进化、三层准入、矛盾仲裁逻辑 | 23-四层闭环自进化交易架构（不变） |
| 信号汇聚、跨系统状态视图、参数/开关下发 | **42-本层** |
| 订单执行 | 各子系统 + 22-执行引擎中心（不变） |

本层消费 23 矛盾论仲裁结论作为弹性约束依据之一，**不重新发明仲裁逻辑**。

### 与 13-通用风控模块的分工边界

| 维度 | 13-通用风控模块 | 42-本层 |
|---|---|---|
| 管辖范围 | **单系统风控门禁**（事前门禁/仓位管理/事后离场） | **跨系统协调性约束**（跨系统多空比、全局总敞口、分支间风险预算） |
| 失效原则 | Fail-Closed（门禁失效则拒绝交易） | Fail-Open（协调失效则回退默认参数） |
| 紧急收紧 | 执行主体（日回撤熔断、连续亏损限制等既有机制不变） | 只做参数下发与通知，执行仍走 13 系统 |

**红线**：42 层不复制、不覆盖、不绕过 13 系统的任何门禁规则；13 系统门禁优先级永远高于 42 层参数。

## 二 · 信号汇聚总线（SignalBus）

### 2.1 统一 SignalSchema

所有子系统信号归一为统一 JSON Schema 后进入总线：

```json
{
  "signal_id": "sig_20261028_000001",
  "source": "40-cycle | 11-bcrm | 23-evolution | 29-event | ...",
  "ts": "2026-10-28T00:00:00+00:00",
  "symbol": "BTC/USDT",
  "direction": "long | short | neutral",
  "confidence": 0.0,
  "horizon": "hours | days | weeks",
  "risk_exposure_hint": 0.0,
  "expires_at": "...",
  "payload": {}
}
```

### 2.2 链式过滤器管道

信号进入总线后按序经过链式过滤器（对齐 Freqtrade Pairlist Handler 模式），每个过滤器独立可插拔、可配置启停：

```
原始信号 → [F1 新鲜度校验] → [F2 置信度过滤] → [F3 冲突检测]
         → [F4 数据健康校验] → [F5 归一化输出] → 总线
```

| 过滤器 | 职责 | 默认 |
|---|---|---|
| F1 新鲜度校验 | 超过 expires_at 的信号丢弃 | on |
| F2 置信度过滤 | 低于阈值的信号降级为 neutral | on |
| F3 冲突检测 | 标记同标的多源信号方向冲突，交由仲裁参考 | on |
| F4 数据健康校验 | 源数据缺失率/延迟超标的信号丢弃 | on |
| F5 归一化输出 | 统一量纲与格式 | on |

新增过滤器只需实现统一接口并注册，不修改其他过滤器。

### 2.3 接入方式（即插即拔）

- **Publisher（发布）**：子系统将既有产出物（如 40 的 cycle_state.json、29 的 EventSignal）通过适配器发布到总线。适配器只读源文件，不侵入子系统。
- **Subscriber（订阅）**：子系统按需消费总线上的信号与参数。不订阅 = 不受影响。
- **注册表**：`registry.yaml` 声明已接入子系统、其 Publisher/Subscriber 状态与启停开关（配置驱动声明，见第九章）。

### 2.4 一期接入清单

| 子系统 | 发布内容 | 消费内容 |
|---|---|---|
| 40-周期神经网络 | cycle_state + 执行层验证指标（准确率/IC/校准度） | 弹性约束参数、风险预算、协调开关 |
| 11-易经推理 | BCRM 信号 + conf | 弹性约束参数、风险预算 |
| 23-自进化 | 矛盾仲裁结论、进化决策、CS/ESS 表现 | 逆向反馈、弹性约束参数、风险预算 |
| 29-事件驱动 | EventSignal（落地 SubSystemBridge 的规划） | 弹性约束参数、风险预算、协调开关 |

## 三 · 共享状态存储（StateStore）

单一事实源，JSON 文件存储（与现有产出物风格一致），字段：

| 状态域 | 内容 | 更新来源 |
|---|---|---|
| main_network | 主网络准确率（滚动窗口+指数衰减）、IC、校准度 | 40 执行层验证报告 |
| branch_performance | 各分支回测/实盘表现、多空比、胜率 | 各子系统产出物 |
| contradiction | 主要矛盾、矛盾强度、仲裁结论 | 23 矛盾论产出 |
| global_exposure | 全局仓位、多空比、并发持仓数 | 各子系统持仓快照 |
| risk_budget | 各分支风险预算额度、已用额度、波动率贡献 | ParamGovernor + 各分支持仓快照 |
| data_health | 各数据源缺失率、延迟分布、异常值计数 | HealthCheck |
| governance | 当前生效的参数集、开关状态、变更历史 | ParamGovernor |

**时效规则（v1.0 冻结）**：所有状态带 `generated_at`，TTL 定稿为——**信号 24h、表现 7d、参数 72h**；超过 TTL 视为 stale，消费方按 fail-open 处理。

**原子写入与快照**：所有状态文件写入采用『写临时文件 + rename』原子操作，防止进程崩溃导致文件损坏；每日定期快照归档，支持状态恢复。

**数据健康检查**：HealthCheck 对进入 StateStore 的数据做缺失率、延迟分布、异常值三项检查，超标数据标记为 unhealthy 并隔离，不进入下游决策（对齐 Qlib 数据健康检查实践）。

## 四 · 弹性约束参数下发（ParamGovernor）

### 4.1 参数集（预注册，版本化，v1.0 冻结）

| 参数 | 作用对象 | 默认值 | 调节范围 |
|---|---|---|---|
| `long_threshold_multiplier` | 分支多头开仓阈值系数 | 1.0 | 1.0-2.0 |
| `position_size_factor` | 分支仓位系数 | 1.0 | 0.3-1.0 |
| `long_short_ratio_cap` | 多空比上限 | 各系统默认 | 只收紧不放宽 |
| `weight_adjust_limit` | 单次权重调整限幅 | ±5% | 固定 |
| `cooldown_period` | 权重调整冷却期 | 24h | ≥12h |
| `risk_budget_ratio` | 各分支风险预算占比 | 按初始分配 | 只收紧不放大 |

### 4.2 风险预算分配机制

对齐传统金融多策略基金的风险预算实践，各分支按**波动率贡献**分配风险额度，而非简单仓位系数：

```
总风险预算 R_total（全局，预注册）
分支 i 的风险预算 = R_total × w_i
  w_i ∝ 1 / 已实现波动率_i（波动率平价反比分配）
  约束：Σw_i = 1，单分支 w_i ≤ w_max = 40%（v1.0 冻结）

动态再平衡：每 T_rebalance = 7d（v1.0 冻结）或分支波动率突变超阈值时重算
超预算分支：position_size_factor 自动收紧至预算内
```

**与仓位系数的关系**：风险预算是『总量分配』，仓位系数是『方向约束』，二者独立生效、同时收紧时取更严者。

### 4.3 调节规则（示例：主网络置信度驱动）

```
主网络滚动准确率(指数衰减, 半衰期30天) 高 →
  看空资产类别：long_threshold_multiplier ↑（多头阈值抬高）
  position_size_factor 按分支与主网络方向一致性分档（对齐 23 系统既有 0.3/0.5/0.7 分层）
主网络准确率低（低于基线）→
  约束强度回落至 1.0（不反向放大，只收敛到默认）
```

**安全红线**：
1. 参数只做**收紧方向**的弹性约束，不做放大方向（multiplier ≤ 1.0、threshold ≥ 1.0）；
2. 单次变更不超过 `weight_adjust_limit`，冷却期内不重复调整；
3. 参数集版本化，每次变更记录变更原因（引用 StateStore 中的证据字段），可审计可回滚；
4. **13 系统门禁优先**：任何参数不得放宽或绕过 13-通用风控模块的门禁规则。

### 4.4 下发方式

`params_active.json`（当前生效参数集）+ `params_history.jsonl`（变更历史）。子系统适配器只读该文件；文件缺失/损坏/超期 → 子系统使用本地默认值（fail-open）。

## 五 · 逆向权重反馈通道（FeedbackLoop）

分支子系统的统计数据与回测/实盘表现，经本通道回传，用于调节主网络及各分支的权重：

1. **信号**：以『超额收益/预测误差』为反馈信号（对齐多巴胺奖励预测误差原理），而非绝对收益；
2. **路径**：分支表现 → StateStore.branch_performance → FeedbackLoop 计算 → 写入 params_active.json 的权重字段 → 主网络/分支消费；
3. **稳定性防护**：限幅（±5%/次）+ 冷却期（24h）+ 全局归一化（权重总和守恒，防止整体膨胀/萎缩，对齐生物稳态突触缩放）；
4. **熔断型抑制**：全局多空比或并发持仓触及红线时，本层向所有分支下发紧急收紧参数（对应生物抑制性中间神经元机制），防止主网络与分支同向共振放大仓位。**执行主体仍为 13 系统，本层只下发参数与通知**；紧急收紧触发红线**直接复用 13-通用风控模块既有阈值**（v1.0 冻结）；
5. **概念漂移检测**：持续监测主网络与各分支输入数据分布（特征分布、波动率结构、相关性矩阵），检测到显著漂移（**PSI > 0.25，v1.0 冻结**）时：自动降低该网络权重 → 触发告警（复用 15-监控告警系统）→ 标记待重训练，防止在线学习环境下的静默失效；
6. **MoE 式市态路由**：对齐专家混合（Mixture of Experts）门控思想——除权重调节外，可按市态（趋势/震荡/事件冲击）将信号路由给最擅长的分支（趋势市→趋势跟踪引擎、震荡市→网格引擎、事件窗口→事件驱动系统），门控器消费 23 系统的市态切换结论，不重新发明市态识别。**v1.0 冻结决策：P1-P3 阶段不启用（moe_routing.enabled 默认 off），P4 完成后基于运行数据评估是否开启**。

| `feedback_loop.enabled` | 逆向反馈通道开关 | off |
| `risk_budget.enabled` | 风险预算分配开关 | off |
| `moe_routing.enabled` | 市态路由开关（v1.0 冻结：P4 前不启用） | off |

## 七 · 回退与降级机制

1. **协调层整体故障**：子系统读不到 params_active.json / 状态过期 → 使用本地默认参数，行为等同协调层不存在；
2. **单子系统退出**：registry 中注销即可，其余子系统不受影响；
3. **参数异常**：子系统侧适配器对参数做范围校验（超出预注册范围即拒绝并回退默认值）；
4. **回退验证**：每次发布前执行『关闭协调层 → 各子系统冒烟测试』，确认独立运行能力未被破坏；
5. **状态恢复**：StateStore 损坏时从每日快照恢复；快照亦不可用时按全新初始化处理（各子系统本地默认参数兜底）。

## 十四 · 主/分支网络协调原理（v1.1 新增，2026-10-28）

### 14.1 核心关系：时标分离的双向调节

主神经网络（40，大周期）与分支神经网络（小周期直接信号）的核心关系为：

- **正向（大约束小）**：大周期弹性约束小周期——主网络周期判定经协调层下发弹性约束参数（多头阈值系数/仓位系数/风险预算调制），约束分支的资产类别、多空方向与仓位；
- **反向（小反思大）**：小周期量变引发反思，调整大周期权重以适应市场质变——分支表现的量变积累触发质变检测（结构性断裂），质变发生才调整主网络权重。

**时标分离原则**（v1.1 冻结）：两个方向工作在不同时间尺度——约束方向为连续、软性、慢变量（天-周尺度，带冷却期与限幅）；反思方向为事件触发、快变量（量变积累+质变触发）。快慢回路解耦，防止双向耦合震荡。理论依据：控制论时标分离（奇异摄动）+ 生物预测编码层级（高层先验约束低层，低层预测误差向上更新高层，两向异步）。

**质变检测为唯一反思触发器**（v1.1 冻结）：小周期量变引发反思的触发条件绑定 23 系统 ContradictionShiftAccumulator 的质变检测（连续 persistence 次力量对比 + dominance_gap + 方向变化 + 结构性断裂），**纯量变只记录不触发调整**。协调层不另建触发机制。

### 14.2 理论预期与实际信号的归一化裁决

主网络虽关注大周期，但大周期判定可向下延伸为小周期**理论预期**；分支神经产出**实际信号**。二者冲突时，归一化到矛盾系统时间框架下统一裁决：

- **本质**：理论预期=贝叶斯先验，实际信号=证据，矛盾系统=后验裁决器；
- **延伸函数显式预注册**（v1.1 冻结）：大周期判定到小周期预期的映射规则必须预注册版本化（如『周期看空→BTC小周期反弹预期衰减50%』），禁止事后解释。40系统板块传导层（L4龙头先行→传导第二层→末端）为延伸函数的既有结构基础；
- **theoretical_extension 独立路径注册**（v1.1 冻结）：理论预期作为独立路径来源注册进 23 系统矛盾识别器的 SOURCE_DIM_MAP，参与现有三步法（共振检测→冲突裁决→主导性评估），不绕过现有裁决体系；
- **裁决权集中**：所有主/分支冲突在矛盾系统一处裁决，协调层只消费结论。

## 十五 · 矛盾结论消费规则（v1.1 新增）

协调层消费 23 矛盾系统结论时遵循以下四条规则：

### 15.1 时间框架对齐规则

协调层建立信号时间框架注册表：各子系统在 registry.yaml 声明 horizon（40→long、29→short、11→short/medium）。矛盾结论的 timeframe 与子系统 horizon 匹配：同档或相邻档生效（相邻档约束强度×0.5），跨两档不生效。防止宏观长期矛盾错误压制事件驱动的短期脉冲策略。

### 15.2 验证成熟度门控

消费矛盾结论前检查 ContradictionWeightLearner 的 labeled_count：验证样本不足（<30）或该维度处于 long 档（验证窗口天然滞后）时，约束强度打折。

### 15.3 质变事件作为约束切换信号

质变检测结果（shifted_from/shifted_to + structural_break_type）是协调层调整约束的事件触发器：质变发生时，新主矛盾对应维度的子系统约束收紧、旧主矛盾对应维度回落默认值（1.0，受只收紧不放大红线约束）。量变阶段不做调整，避免高频震荡。

### 15.4 矛盾权重调制风险预算

23 系统已学出的各维度权重（get_weights）作为风险预算的二级调制因子：主矛盾指向看空的维度，其对应分支的风险预算 w_i 乘以衰减因子（下限 0.3，对齐 23 系统 WEIGHT_FLOOR），实现『矛盾结论→风险预算→仓位』传导链，衔接 4.2 节风险预算机制。

## 十六 · 矛盾 Transformer 演进路线（v1.1 新增，远期演进项）

### 16.1 双线分工

矛盾系统双线结构：
- **矛盾 Transformer（同步仲裁线）**：处理某时刻『多维度×多时间框架』矛盾的空间对撞（谁主导）——端到端学习维度×时间框架交互权重，引入时序注意力（矛盾历史演化路径参与当前裁决）。对应生物前额叶选择性注意；
- **量变质变（异步演化线）**：处理矛盾随时间的演化（何时转移）——现有 ContradictionShiftAccumulator 保持现状。对应生物神经系统相变临界点动力学。

一个管状态、一个管过程，互补而非替代。

### 16.2 三步影子演进（不可跳步）

1. **影子模式**：与现有三步法并行输出，用 contradiction_samples.json 历史样本（方向/置信度/实际收益三元组，管道已具备）回测比对两套裁决的一致率与各自实际收益，不替换现有逻辑；
2. **动态调制**：一致率与收益达标后，Transformer 输出作为 SOURCE_WEIGHT_MAP 的动态调制因子（手工权重兜底）；
3. **评估切换**：带标签样本量 >5000 且影子验证稳定后，评估完全切换。全程 fail-open：Transformer 异常回退三步法。

## 十九 · v1.1.2 勘误（架构与数据流一致性修订，2026-10-28）

> 本节为勘误增补，不改动 v1.0 冻结数值与既有章节正文；与既有章节冲突处，以本节为准。

### 19.1 实质矛盾修订（3 处）

**勘误 6：params_active.json 单写者原则（修订流转 2 × 流转 3）**

- **原冲突**：ParamGovernor 与 FeedbackLoop 双组件写同一文件，后写覆盖先写导致更新丢失；
- **勘误定稿**：**ParamGovernor 是 params_active.json 的唯一写入者**。FeedbackLoop 只向 ParamGovernor 提交权重调整提案（含证据引用），由 ParamGovernor 合并后统一写入。变更历史由此完整覆盖全部变更来源。

**勘误 7：F3 冲突检测输出的分类处理（修订流转 1 × 流转 4）**

- **原冲突**：F3 标记的方向冲突无明确消费者，主/分支冲突存在时序空转，分支间冲突无裁决路径；
- **勘误定稿**：分两类——
  - **主/分支冲突**：F3 标记后写入 StateStore.contradiction 域作为待裁决队列，23 系统按自身节奏消费该队列（属 23 系统自身演进，由其自主实现），42 层只保证标记可见；
  - **分支间冲突**：**不裁决、只记录**——分支间方向分歧是策略分散化的正常状态，由各自风控（13 系统）独立把关，强行统一反而破坏分散化价值。

**勘误 8：紧急收紧旁路通道（修订第六章开关治理 × 流转 2）**

- **原冲突**：coordination_enabled 默认 off（灰度期）时紧急收紧参数无法送达，而紧急事件不等灰度结束；
- **勘误定稿**：`emergency_tighten` 为**独立于总开关的旁路通道**——即使 coordination_enabled 为 off 仍可下发（执行主体本就是 13 系统，42 只做参数下发与通知，不违反灰度原则）。开关表补充：emergency_tighten 不受 coordination_enabled 级联控制。

### 19.2 边界澄清（3 处）

**澄清 7：参数心跳刷新义务**

## 二十 · v1.1.3 勘误（主网络权重调整建议制定稿，2026-10-28）

> 本节为勘误增补，不改动 v1.0 冻结数值与既有章节正文；与既有章节冲突处，以本节为准。

### 20.1 主网络权重调整采用建议制（勘误 9，定稿）

- **原冲突**：流转 3 规定质变事件触发主网络权重调整并写入 params_active.json 供主网络消费，但 40 系统执行层定位为独立验证场（决策链路独立、不经 23 门禁），且 40 模型权重由其自身 P5/P6 训练流程管理——若 40 不订阅权重字段，调整无落点；若强制生效，破坏 40 独立性与 42 零代码侵入原则；
- **勘误定稿**：主网络权重调整为**建议制**（对齐 16-调控系统建议制先例）——
  1. 质变事件触发 42 层生成**权重调整建议**（勘误 1 的语义相应明确为：质变事件是建议生成的唯一触发器）；
  2. 建议经 params_active.json 的建议字段下发，40 系统自主决定是否采纳；
  3. 40 不采纳时记录偏差即可，不构成违规；40 订阅与否均不影响其现有行为（fail-open）。

### 20.2 采纳路径约束（防归因污染）

- 40 采纳建议必须走其**自身晋级证据流程**：建议作为 P5/P6 阶段的候选输入参与验证，**不得直接修改模型权重**；
- 40 的独立验证场归因清晰性由此保留：验证的始终是 40 自身理论（建议只是候选输入之一）。

### 20.3 采纳率监控（独立性指标）

- 采纳率 = 已采纳建议数 / 已下发建议数（滚动窗口统计）；
- **采纳率 > 80%**：触发告警（复用 15-监控告警系统），提示归因污染风险（40 可能过度依赖外部建议，独立验证场价值退化）；
- **采纳率 < 20% 且建议事后被验证正确**：同样告警，提示 40 可能存在理论盲区；
- 采纳率指标写入 StateStore.governance 域，作为 40 独立性与 42 建议质量的双向监控。
