**分工边界要点**（验证对齐项 A1-A4）：
- A1 23系统：策略进化、三层准入、矛盾仲裁逻辑；42 只消费结论不重新发明；
- A2 13系统：单系统门禁（fail-closed）；42 只管跨系统协调约束（fail-open）；紧急收紧时 42 只下发参数、执行走 13；
- A3 22系统：订单执行，各子系统下单出口保留，42 不统一下单；
- A4 15系统：告警复用，不新建通道。

**组件要点**（验证对齐项 B1-B5）：
- B1 链式过滤器 F1-F5 各自独立可插拔、可配置启停；
- B2 StateStore 七状态域齐全，写入为『临时文件+rename』原子操作；
- B3 ParamGovernor 参数集预注册版本化，只收紧不放大；
- B4 FeedbackLoop 连续调节仅作用分支权重，主网络权重仅质变触发（勘误1）；
- B5 开关默认全 off，任何开关组合下子系统下单链路不变。

## 四 · 核心数据流转图

### 流转 1：信号汇聚流（子系统 → 42 → 状态）

```
40: cycle_state.json + 验证指标(准确率/IC/校准度)
11: BCRM信号 + conf
23: 矛盾仲裁结论 + 进化决策 + CS/ESS表现
29: EventSignal
        │
        ▼ （各适配器只读源文件，registry.yaml 声明接入）
[SignalBus 链式过滤器]
  F1 新鲜度（超 expires_at 丢弃）
  F2 置信度（低于阈值降级 neutral）
  F3 冲突检测（同标的多源方向冲突标记）
  F4 数据健康（源数据缺失率/延迟超标丢弃）
  F5 归一化（统一 SignalSchema）
        │
        ▼
[StateStore]
  main_network ← 40验证指标
  branch_performance ← 各分支表现
  contradiction ← 23仲裁结论
  global_exposure ← 各分支持仓快照
  data_health ← HealthCheck
```

### 流转 2：参数下发流（42 → 子系统，只收紧不放大）

```
[StateStore] ──证据──▶ [ParamGovernor]
                          │
        ┌─────────────────┼──────────────────┐
        ▼                 ▼                  ▼
  弹性约束参数        风险预算分配          紧急收紧参数
  (多头阈值系数/       (波动率平价反比,      (复用13系统阈值,
   仓位系数/多空比)     w_max=40%,7d再平衡)   人工/红线触发)
        │                 │                  │
        └─────────────────┼──────────────────┘
                          ▼
              params_active.json（当前生效）
              params_history.jsonl（变更历史，含变更原因引用）
                          │
            ┌─────────────┴─────────────┐
            ▼                           ▼
  子系统适配器只读消费          13-系统熔断执行支路
  （范围校验，超预注册范围        （紧急收紧参数下发后，
    拒绝回退默认）                 熔断执行主体为13系统，
                                  42只下发参数与通知）
```

### 流转 3：逆向反馈流（分支表现 → 42 → 权重，勘误1约束）

```
分支实盘/回测表现
        │
        ▼
[StateStore.branch_performance]
        │
        ▼
[FeedbackLoop]
  信号 = 超额收益/预测误差（非绝对收益）
  ├─ 连续调节（限幅±5%+冷却24h+归一化）→ 仅分支网络权重
  ├─ 漂移检测（PSI>0.25）→ 降权+告警(15系统)+标记重训练
  └─ 质变事件（23系统ContradictionShiftAccumulator）→ 唯一的主网络权重调整触发器
        │
        ▼
params_active.json 权重字段 → 主网络/分支消费
```

### 流转 4：矛盾裁决流（理论预期 vs 实际信号，勘误2归属）

```
40主网络大周期判定
        │
        ▼ （延伸函数由40系统自身实现并发布，L4板块传导层为基础）
小周期理论预期（贝叶斯先验）
        │
        ├──方向一致──▶ 无冲突，正常流转
        │
        └──方向冲突──▶ [23矛盾系统统一裁决]（theoretical_extension
                       由23系统自主决定注册为路径来源）
                          │
                          ▼
                     裁决结论（谁主导）
                          │
                          ▼
              [42层消费]（先裁决后消费，串联执行）
                时间框架对齐：同档生效/相邻档×0.5/跨两档不生效
                验证成熟度门控：labeled_count<30 打折
                质变事件：约束切换触发器
                矛盾权重调制风险预算：衰减下限0.3
                （三类折扣叠加总下限0.15，触底审计告警）

【双通道设计说明】40(long)→29(short) 的约束经两条通道：
  ① 弹性参数通道（流转2）：直接生效，不经矛盾结论消费；
  ② 矛盾结论通道（本流转4）：跨两档不生效——为设计意图（防止
     长期矛盾压制短期脉冲策略），非缺陷。
```

### 流转 5：回退降级流（42故障 → 子系统独立运行）

```
协调层异常（进程终止/文件损坏/状态过期）
        │
        ▼
子系统适配器检测：params_active.json 缺失/损坏/超TTL(72h)
        │
        ▼
回退本地默认参数（行为等同协调层不存在，无交易中断）
        │
        ├── StateStore损坏 → 每日快照恢复
        ├── 快照亦不可用 → 全新初始化（本地默认参数兜底）
        └── 单子系统退出 → registry注销，其余不受影响

协调层恢复后：立即重算风险预算（不等下一个7d再平衡周期）
```
