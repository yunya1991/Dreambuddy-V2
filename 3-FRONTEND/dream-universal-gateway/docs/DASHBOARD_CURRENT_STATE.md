# Dashboard Current State

> 状态：active
> 更新日期：2026-06-07

## 定位

- `/chat` 是用户主入口。
- `/dashboard` 不是对外主入口，而是中台能力的调试、展示与联调页面。
- 后续对外能力仍以对话窗为主，`/dashboard` 主要服务以下场景：
  - 中台状态观察
  - 配置联调
  - 能力可视化
  - 研发阶段快速验收

## 当前口径

为避免后续协作产生歧义，统一使用以下表达：

- `Dream Universal Gateway` 的主入口：`/chat`
- `Dashboard` 的角色：`internal console / debug surface`
- `Dashboard` 不承担长期对外产品首页职责
- 若某项能力未来进入正式用户流，应优先回到 `/chat` 的对话式承接，而不是继续堆叠在 `/dashboard`

## 当前页面职责

当前 `/dashboard` 页面承担的是“研发态中台能力总览”，主要用于：

- 展示策略、监控、记忆、LLM 等中台状态
- 暴露调试所需的状态卡片与视图模型
- 验证中台输出是否已经具备被 `/chat` 承接的条件

因此，`/dashboard` 当前可以继续演进，但目标应是：

- 帮助研发看清系统状态
- 为 `/chat` 提供可复用的能力块
- 不把它继续演化成最终用户主工作台

## 后续文档约束

后续涉及前端入口的文档，应遵守以下约束：

1. 若描述用户主入口，统一写 `/chat`
2. 若描述调试展示、内部观察、能力联调，统一写 `/dashboard`
3. 若某项设计同时涉及两者，必须明确：
   - 用户入口在哪
   - 调试入口在哪
   - 最终对外承接是否回收到 `/chat`

## 与 UI-Map 的关系

- `ui-map` 负责中台结构表达与能力关系透视
- `/dashboard` 负责中台运行态的调试展示
- `/chat` 负责用户主交互与最终承接

三者不是互相替代关系，而是：

- `/chat` = 用户入口
- `/dashboard` = 中台调试展示
- `ui-map` = 中台结构地图
