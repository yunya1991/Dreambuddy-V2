## 0. 一句话

**先 L1 后 L2，先 explain 后 resolve；统计只作事实，不作方向；实盘与热路径永不走 MCP。**

## 2. 入口速查

| 层 | 用途 | 入口 |
|---|---|---|
| **L1 HTTP** | 金融分析主入口（统计/相关性/事件/风险/横截面） | `POST http://127.0.0.1:3001/api/visual/capabilities`，`op=explain\|resolve` |
| **L1 MCP** | 只读观察交易状态 | `l1.trading.mcp`：`get_signal_state` / `get_bus_state` / `get_constraint_state` / `get_cycle_state` / `get_strategic_extension` / `get_decision_diagnostics` / `get_training_status` / `get_positions` |
| **L1 MCP** | 意图识别与执行 | `l1.intent.mcp`：`list_intents` / `classify_intent` / `execute_intent` |
| **L1 MCP** | 策略与审批只读 | `l1.strategy.mcp`：`list_strategies` / `get_strategy_version` / `get_approval_state` / `list_signal_triggers` |
| **L0 网关** | 认知/语义/REA/数据/评测 | `python3 47-MCP管理系统/mcp_shells/l0_gateway/server.py --role <role>`；或 `mcpctl.py profile --role <role> --gateway --out .mcp.json` |
| **L2 HTTP** | 深度推理与编排 | `POST http://127.0.0.1:8000/api/v1/intent`、`/run`、`/run/async` + `GET /result/<cycle_id>` |
| **L2 MCP** | 编排/辩论/涌现/训练 | `l2.dreamos.mcp`（`submit_run` 需 Mandate）、`l2.debate.mcp`、`l2.emergence.mcp`、`l2.train.mcp` |
| **DSH 插件** | 工具扩展 | 白名单 + `dsh plugin --profile sandbox add <pkg>`，校验 `check_whitelist.py` |

**L1 调用最小示例**

```bash
# 1) 查参数 schema
curl -s -X POST http://127.0.0.1:3001/api/visual/capabilities \
  -H 'Content-Type: application/json' \
  -d '{"op":"explain","capability_id":"D-E15"}'

# 2) 按 schema 执行（示例为 D-A11 滚动相关）
curl -s -X POST http://127.0.0.1:3001/api/visual/capabilities \
  -H 'Content-Type: application/json' \
  -d '{"op":"resolve","capability_id":"D-A11",
       "payload":{"symbol":"BTC","benchmark":"US500","freq":"1d","days":750}}'
```

## 4. 八个方法型场景

> 每个场景只给「何时用 → 调什么 → 怎么判读」，具体 payload 一律先 `explain` 取 schema。

### 4.1 单标的现状体检

- **何时**：拿到一个标的，先判断「现在处于什么状态」，不做方向。
- **调用**：`D-E15`（趋势）→ `D-A04`（分位）→ `D-A06`（年化波动）→ `D-A07`（回撤）。
- **判读**：趋势看斜率与 R² 同向；分位看 `percentile` 与 `lookback`；波动与回撤看 `sample_n` 是否过门槛（30/250）。
- **禁止**：把 `D-E15` 的统计事实直接写成「看多/看空」。

### 4.2 多资产相关与领先滞后

- **何时**：判断联动、分散化、传导顺序。
- **调用**：`D-E05`（矩阵 TopK）→ `D-E06`（CCF）→ `D-A11`（滚动相关）→ 必要时 `D-G25`（尾部）。
- **判读**：先看 `n` 与 BH-FDR `p_adj`；`best_lag` 只说明同期样本内的领先关系，不是因果。
- **降级**：`partial` 表示样本被截断或尾部事件不足，结论只能作描述。

### 4.3 因子有效性验证

- **何时**：拿到一个因子，验证是否有横截面区分度。
- **调用**：`D-E08`（IC）→ `D-G20`（分位单调）→ `D-G19`（IC 衰减）→ `D-G22`（HAC/DSR）。
- **判读**：IC 均值、ICIR、单调性、`spread` 四项同向才进入候选；`h>1` 必须看 `D-G22`，不能用朴素 t。
- **禁止**：`spread` 是描述统计，不是策略收益；不得据此直接生成买卖指令。

### 4.4 事件研究

- **何时**：宏观事件、财报、政策、节假日前后的效应。
- **调用**：`D-E04`（事件窗/CAR）→ `D-G23`（Patell/BMP 显著性）→ `D-J02`（季节分解，可选）。
- **判读**：事件数 `<30` 只能 `partial`；事件日按价格轴对齐，缺交易日取首个不早于事件日的交易日。
- **禁止**：把事件后平均收益当作可交易 alpha，除非成本与样本外已单独验证。

### 4.5 组合风险

- **何时**：多资产组合的风险度量与仓位前置检查。
- **调用**：`D-G16`（VaR/CVaR）→ `D-G14`（EWMA 协方差）→ `D-G25`（尾部共振）。
- **判读**：损失为正数口径；历史法/参数法并列看；尾部样本 `<30` 只作描述。
- **禁止**：风险度量只描述样本内结构，不构成交易信号。

### 4.6 横截面比较

- **何时**：一篮子标的的相对位置、宽度、分化。
- **调用**：`D-G01`（z/pct）→ `D-G04`（离散度/宽度）→ `D-G03`（分位桶）→ `D-G05`（同向率）。
- **判读**：只讲相对位置与分化程度；`D-G03` 的价差不是多空建议。

### 4.7 只读信号与发现

- **何时**：看系统已有结论，不重算。
- **调用**：`D-K02`（最近一期发现）→ `D-K03`（gate_pass 信号）→ `D-K01`（关系推荐）。
- **判读**：`status=candidate` 表示候选，不是已采纳；`blocked` / `conflicts` 必须原样披露。
- **禁止**：这三项都不写库、不下单；`D-K03` 输出禁止出现 order/position/仓位字段。

### 4.8 深度推理与编排（L2）

- **何时**：跨域综合、需要生成式推理、需要多 Agent 编排。
- **调用**：
  - 同步：`POST /api/v1/run`（可带 `phase` 渐进档）
  - 异步：`POST /api/v1/run/async` → `GET /api/v1/result/<cycle_id>`
  - 只识别意图：`POST /api/v1/intent`
  - 对抗评审：`l2.debate.mcp` 的 `start_debate` → `get_debate_result`
- **判读**：看 `L2Envelope` 的 `ok/quality/trace`；token 与预算看 `get_budget`。
- **硬约束**：`submit_run` 需 Mandate；L2 对 L1 只读，不得反向触发交易。

## 5. 返回契约与降级

`resolve` 统一信封：

```json
{"ok": true, "capability_id": "D-A11", "code": "ok",
 "data": {}, "quality": {"status": "ok|partial", "n": 730, "as_of": "YYYY-MM-DD"},
 "visual": {}, "meta": {"elapsed_ms": 812, "cache": "hit|miss"}}
```

| 字段 | 判定 |
|---|---|
| `code=ok` | 可读结果；`quality=partial` 仍需披露截断原因 |
| `missing_args` / `invalid_params` | 调用方修参数，不重试 |
| `unsupported` / `product_missing` / `no_signal` | 数据或产物缺失，禁止编造 |
| `sample_insufficient` | 样本不足，结论降级为描述 |
| `not_found` / `unauthorized` / `rate_limited` | 路由/鉴权/限流问题 |

- 限流：`resolve` 60 次/分钟/用户；结果缓存 60s（只缓存 `ok`）。
- 样本门槛：能力级 `min_n` 在 manifest；方法级门禁由 `l1agg.methods.registry` 独立执行。
- PIT：任何「当时可见」的判断走 `D-J30`，避免前视。

## 6. 认知写入门槛

所有写入（`record` / MCP `record` / 批量回填）必须过 `gate()`：

| 字段 | 取值 | 作用 |
|---|---|---|
| `subclass` | `code` / `config` / `runtime` / `D-tech` / `D-policy` | 决定治理规则；拿不准归 `D-policy` |
| `form` | `M1` / `M2` / `M3` | 指针/联想/零记忆；M1 必须带 `source_anchor` |
| `source_anchor` | `file:symbol` / 配置键 / 记录 id | 复核「事实是否仍成立」 |
| `verify_state` | `fresh` / `stale` / `degraded` | 失效但保留，不物理删除 |

- 模式：`COGNITIVE_ADMISSION_MODE=shadow|enforce_n3|enforce`（默认 `enforce_n3`）。
- 硬拦：N3 轨迹（`rag-bridge` / `l0.scheduler` / `l1_router`）在 `enforce_n3` 即拒。
- 全量准入：切 `enforce` 后，N1/N2/N4 与敏感内容一并拒；先在 shadow 观察误拦率。
- **禁止**：把检索轨迹、统计结果、会话摘要写入记忆；这些属于 L0 现算或 git 可复原内容。

## 7. 禁止清单

1. 实盘下单走 MCP（`place_order` 仅限 paper，或显式 Mandate + 非实盘）。
2. L2 通过 `l1.trading.mcp` 写信号或改参数。
3. 把 `partial` / `sample_insufficient` 的结果当确定结论。
4. 用记忆库存行情、指标值、回测结果（应走 18/19/21）。
5. 未 `explain` 直接猜 payload。
6. 将 `D-K03` 的只读信号改写为买卖指令。
