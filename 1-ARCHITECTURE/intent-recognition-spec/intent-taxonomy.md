## 0. 架构定位

### 0.1 DreamOS 操作系统中的位置

本意图分类体系属于 **DreamOS 操作系统内核 S 层（感知层）** 的**通用对话意图识别**，是操作系统的核心能力之一。

```
DreamOS 金融领域操作系统
├── 操作系统内核 (dreamos/core/)
│   └── S 层 意图识别 ← 本规范定义的 6×30 对话意图体系
│       ├── 对话意图分类（6大类 × 25+ 二级意图）
│       ├── 槽位提取（stock/quantity/price/...）
│       ├── 风险等级判定（low/medium/high）
│       ├── 能力路由决策（知识库/认知/索引/数据库/交易/Harness）
│       └── 能力范围判断（in_scope → 是否降级 Harness）
├── 能力域层 (dreamos/capabilities/trading/)
│   └── 策略意图（7种：TREND_FOLLOWING/MEAN_REVERSION/...）
│       └── 由对话意图 + 市场数据映射而来，决定编排链（A/C/F）
└── 四大基础能力
    ├── 知识库 (2-KNOWLEDGE/)
    ├── 认知系统 (4-MEMORY/)
    ├── 索引系统 (2-KNOWLEDGE/0-SCHEMA/)
    └── 数据库
```

### 0.2 两层意图体系的区分

| 层次 | 内容 | 位置 | 职责 |
|------|------|------|------|
| **对话意图**（本规范 6×30） | 用户想干什么 | `core/sense/` 内核层 | 通用对话理解，领域无关，路由到系统能力 |
| **策略意图**（7 种） | 用什么交易策略 | `capabilities/trading/` 能力域层 | 交易领域特化，决定 A/C/F 编排链 |

**关键区分**：
- 对话意图回答"用户想做什么"（查询/分析/交易/策略/风险/对话）
- 策略意图回答"该用什么交易策略"（趋势跟随/均值回归/突破...）
- 对话意图是内核通用能力，策略意图是交易能力域的映射结果

### 0.3 意图识别的完整职责

意图识别不仅是分类，还包括**能力路由决策**：

1. **对话意图分类**（6×30）— 理解用户需求
2. **槽位提取**（stock/quantity/price/timeframe/...）— 提取关键参数
3. **风险等级判定**（low/medium/high）— 决定校验流程
4. **能力范围判断**（in_scope）— 是否在 DreamOS 能力范围内
5. **能力路由决策**（capability_route）— 路由到对应能力：
   - `knowledge_base` → 知识库查询（`2-KNOWLEDGE/`）
   - `cognitive_memory` → 认知系统/记忆（`4-MEMORY/`）
   - `index_system` → 索引检索（`2-KNOWLEDGE/0-SCHEMA/`）
   - `database` → 直接数据查询
   - `trading_nodes` → 交易节点编排（核心护城河，见下方核心能力域）
   - `harness` → 超出范围，交 Harness 驱动外部 agent 调研

### 0.4 Harness 降级路径

当意图识别判定 `in_scope=False` 或 `capability_route=harness` 时：

```
[S 层] 判定超出 DreamOS 能力范围
    ↓
[Harness] agent loop 启动，调用外部工具调研分析
    ↓
[DreamOS] 调研结果回流，结合系统能力（知识库/交易节点）给出最终回答
```

## 1. 设计原则

1. **两级结构**：一级意图（6大类）用于快速路由，二级意图（25+）用于精确处理
2. **互斥性**：同一输入在一级意图层面唯一归属，避免歧义
3. **完备性**：覆盖交易系统 95% 以上常用交互场景
4. **可扩展**：新增意图通过补充二级类目实现，不破坏一级体系
5. **风险驱动**：按风险等级分层，高风险意图走严格校验流程
6. **可映射**：每个二级意图可映射到 S 链的 Objective 类型
7. **内核通用**：对话意图属于操作系统内核，不绑定交易领域，可复用于其他能力域
8. **能力路由**：意图识别输出必须包含能力路由决策，驱动四大基础能力 + 交易节点

## 2. 完整意图体系

### 2.1 查询类（query）- 低风险

| 二级意图 | 英文标识 | 说明 | 风险等级 | S链映射 |
|---------|---------|------|---------|---------|
| 行情查询 | `market_query` | 查询标的实时行情、涨跌、走势 | 低 | market_query |
| 持仓查询 | `holding_query` | 查询当前持仓、盈亏、成本 | 低 | portfolio_review (simple) |
| 订单查询 | `order_query` | 查询委托、成交、撤单记录 | 低 | — |
| 账户查询 | `account_query` | 查询资金、总资产、收益率 | 低 | portfolio_review (simple) |
| 大盘查询 | `market_overview` | 查询大盘指数、板块涨跌 | 低 | market_query (broader) |

#### 行情查询 (market_query)
- **定义**：查询单个或多个标的的实时/历史行情数据
- **触发词**：多少钱、价格、行情、走势、涨了、跌了、现在、当前、最新价
- **用户示例**：
  - "茅台现在多少钱？"
  - "BTC今天涨了还是跌了？"
  - "看看宁德时代的走势"
- **必填槽位**：`stock` 或 `stock_code`
- **可选槽位**：`timeframe`（时间周期）、`market_type`（市场类型）
- **输出示例**：调用行情API返回价格数据

#### 持仓查询 (holding_query)
- **定义**：查询用户当前的持仓情况
- **触发词**：持仓、我有什么、手里有、仓位、盈亏、赚了、亏了、成本
- **用户示例**：
  - "我现在有什么持仓？"
  - "看看我的盈亏"
  - "茅台的成本价是多少？"
- **必填槽位**：无（查询全部持仓）或 `stock`（查询单只持仓）
- **可选槽位**：无
- **输出示例**：返回持仓列表或单只持仓详情

#### 订单查询 (order_query)
- **定义**：查询委托单、成交记录、撤单记录
- **触发词**：订单、委托、成交、撤单、今天、历史、记录
- **用户示例**：
  - "今天的成交怎么样？"
  - "看看我今天的委托"
  - "那单撤了吗？"
- **必填槽位**：无（查询全部）
- **可选槽位**：`order_type`、`time_range`、`stock`
- **输出示例**：返回订单列表

#### 账户查询 (account_query)
- **定义**：查询账户资金、总资产、收益率等
- **触发词**：总资产、账户、资金、余额、收益率、收益、赚了多少
- **用户示例**：
  - "我总资产多少？"
  - "看看账户余额"
  - "今年收益率怎么样？"
- **必填槽位**：无
- **可选槽位**：`time_range`
- **输出示例**：返回账户概览

#### 大盘查询 (market_overview)
- **定义**：查询大盘指数、板块行情等宏观数据
- **触发词**：大盘、指数、上证指数、创业板、板块、市场、今天
- **用户示例**：
  - "今天大盘怎么样？"
  - "新能源板块涨了吗？"
  - "看看创业板指数"
- **必填槽位**：无（默认大盘）或 `sector` / `index_name`
- **可选槽位**：`time_range`
- **输出示例**：返回大盘/板块数据

### 2.2 分析类（analysis）- 中风险

| 二级意图 | 英文标识 | 说明 | 风险等级 | S链映射 |
|---------|---------|------|---------|---------|
| 个股技术分析 | `technical_analysis` | 单只标的的技术面分析 | 中 | trend_analysis |
| 持仓股诊断 | `holding_analysis` | 对持有标的的分析建议 | 中 | deep_analysis (holding-focused) |
| 深度综合分析 | `deep_analysis` | 多维度综合分析（技术+基本面+情绪） | 中 | deep_analysis |
| 三屏交易分析 | `three_screen_analysis` | Elder三屏交易体系分析 | 中 | three_screen_trade |
| 板块/大盘分析 | `sector_analysis` | 板块或大盘的整体分析 | 中 | trend_analysis (broader) |

#### 个股技术分析 (technical_analysis)
- **定义**：对单只股票/标的进行技术面分析
- **触发词**：分析、怎么样、走势、技术面、指标、看涨、看跌、突破
- **用户示例**：
  - "茅台走势怎么样？"
  - "帮我分析一下BTC"
  - "ETH有没有突破迹象？"
- **必填槽位**：`stock` 或 `stock_code`
- **可选槽位**：`timeframe`、`indicator`
- **隐含判断**：需判断用户是否持有该标的（影响分析角度）
- **输出示例**：技术分析报告（趋势、支撑阻力、指标信号等）

#### 持仓股诊断 (holding_analysis)
- **定义**：对用户持有的标的进行诊断，给出持有/卖出建议
- **触发词**：还能拿吗、要不要卖、持仓、手里的、怎么办、要不要走
- **用户示例**：
  - "茅台还能拿吗？"
  - "我手里的宁德时代怎么办？"
  - "这个票要不要卖？"
- **必填槽位**：`stock` 或 `stock_code`
- **可选槽位**：无
- **隐含判断**：`implied_holding = true`（需校验用户是否真的持有）
- **输出示例**：持仓诊断报告（持仓分析、离场建议、风险提示）

#### 深度综合分析 (deep_analysis)
- **定义**：从多个维度（技术面、基本面、资金面、情绪面）综合分析
- **触发词**：深度分析、全面分析、详细分析、研究一下、好好看看
- **用户示例**：
  - "深度分析一下BTC"
  - "帮我好好研究一下茅台"
  - "全面分析宁德时代"
- **必填槽位**：`stock` 或 `stock_code`
- **可选槽位**：`analysis_dimensions`（指定分析维度）
- **输出示例**：多维度综合分析报告 + 综合结论

#### 三屏交易分析 (three_screen_analysis)
- **定义**：使用 Elder 三屏交易体系进行分析（周线→日线→日内）
- **触发词**：三屏、三屏交易、周线、日线、日内、screen
- **用户示例**：
  - "用三屏法看看ETH"
  - "三屏交易分析一下BTC"
  - "按周线日线日内看看茅台"
- **必填槽位**：`stock` 或 `stock_code`
- **可选槽位**：无
- **输出示例**：三屏交易分析结果（Screen1/2/3 + 门禁结论）

#### 板块/大盘分析 (sector_analysis)
- **定义**：对某个板块或大盘整体进行分析
- **触发词**：板块、大盘、市场、新能源、AI、半导体、整体
- **用户示例**：
  - "新能源板块现在什么情况？"
  - "大盘还能涨吗？"
  - "AI板块有机会吗？"
- **必填槽位**：`sector` 或 `index_name`
- **可选槽位**：无
- **输出示例**：板块/大盘分析报告

### 2.3 交易类（trade）- 高风险

> **硬约束**：所有交易类意图必须二次确认 + 风控校验，禁止直通执行。

| 二级意图 | 英文标识 | 说明 | 风险等级 | S链映射 |
|---------|---------|------|---------|---------|
| 买入/建仓 | `buy` | 买入标的，建立新仓位 | 高 | trading_decision (buy) |
| 加仓/补仓 | `add_position` | 在已有持仓上加仓 | 高 | trading_decision (buy-more) |
| 卖出/减仓 | `sell` | 卖出部分或全部持仓 | 高 | exit_evaluation (sell) |
| 清仓/止盈/止损 | `close_position` | 全部清仓或触发止盈止损 | 高 | exit_evaluation (full-exit) |
| 条件单设置 | `conditional_order` | 设置条件单（止盈/止损/网格等） | 高 | — |
| 订单管理 | `order_manage` | 撤单、改单等订单操作 | 高 | — |

#### 买入/建仓 (buy)
- **定义**：买入标的，建立新的仓位
- **触发词**：买、买入、建仓、进场、做多、开多、梭哈、抄底
- **用户示例**：
  - "帮我买100股茅台"
  - "建仓BTC 0.5个"
  - "进场ETH"
- **必填槽位**：`stock`、`quantity`
- **可选槽位**：`price`（限价）、`order_type`（市价/限价）
- **校验规则**：
  - 数量必须 > 0
  - 价格必须在合理范围内
  - 资金充足性检查
- **确认话术**："确认以市价买入贵州茅台(600519) 100股？"

#### 加仓/补仓 (add_position)
- **定义**：在已有持仓的基础上增加仓位
- **触发词**：加仓、补仓、再加、多买、加码
- **用户示例**：
  - "茅台再加50股"
  - "BTC补仓0.3个"
  - "给ETH加点仓"
- **必填槽位**：`stock`、`quantity`
- **可选槽位**：`price`、`order_type`
- **隐含判断**：`implied_holding = true`
- **校验规则**：同买入，且需校验用户是否持有该标的
- **确认话术**："确认对贵州茅台(600519)加仓50股？当前持仓xxx股"

#### 卖出/减仓 (sell)
- **定义**：卖出部分持仓
- **触发词**：卖、卖出、减仓、出掉、走了、止盈一部分、砍
- **用户示例**：
  - "把宁德时代卖了"
  - "BTC减仓0.5个"
  - "茅台出一半"
- **必填槽位**：`stock`、`quantity`（"卖了"默认全卖）
- **可选槽位**：`price`、`order_type`
- **隐含判断**：`implied_holding = true`
- **校验规则**：
  - 卖出数量 ≤ 持仓数量
  - 可卖数量检查（T+1 等规则）
- **确认话术**："确认卖出贵州茅台(600519) 100股？当前持仓xxx股"

#### 清仓/止盈/止损 (close_position)
- **定义**：全部清仓，或触发止盈/止损后全平
- **触发词**：清仓、全卖、全部走、止盈、止损、平仓、all out
- **用户示例**：
  - "全部清仓"
  - "把茅台全卖了"
  - "止损BTC"
- **必填槽位**：`stock`（清仓全部时无）
- **可选槽位**：无
- **隐含判断**：`implied_holding = true`
- **校验规则**：
  - 必须有持仓
  - 高风险操作，需特别确认
- **确认话术**：⚠️ "确认全部清仓？这将卖出所有持仓。请再次确认。"

#### 条件单设置 (conditional_order)
- **定义**：设置条件订单（价格触发、止盈止损、网格等）
- **触发词**：条件单、止盈单、止损单、网格、到xx就、跌到xx就、涨到xx就
- **用户示例**：
  - "跌到1800帮我止损"
  - "BTC到7万提醒我并止盈"
  - "设置一个网格策略"
- **必填槽位**：`stock`、`price`、`action`（触发后的动作）
- **可选槽位**：`quantity`、`order_type`、`condition_type`
- **校验规则**：
  - 价格条件合理
  - 条件单类型支持
- **确认话术**："确认设置条件单：当贵州茅台(600519)价格≤1800时触发止损卖出？"

#### 订单管理 (order_manage)

- **触发词**：撤单、取消、改单、修改订单、把刚才那单
- **用户示例**：
  - "把刚才那单撤了"
  - "取消刚才的买入"
  - "把价格改一下"
- **必填槽位**：`order_id` 或上下文引用
- **可选槽位**：`modify_field`（修改的字段）
- **校验规则**：订单存在且可撤销/修改
- **确认话术**："确认撤销订单 #xxxx（买入茅台100股）？"

### 2.6 对话管理类（dialog）- 系统级 / 低风险

| 二级意图 | 英文标识 | 说明 | 风险等级 | 处理方式 |

#### 确认/同意 (confirm)
- **定义**：用户确认之前的提议或操作

- **用户示例**：
  - "好的"
  - "确认"
  - "可以，买吧"
- **处理方式**：根据当前对话状态推进（CONFIRM → EXECUTE 等）

#### 取消/否定 (cancel)
- **定义**：用户取消操作或否定之前的提议
- **触发词**：算了、不要、不用、取消、不、不对、不是、否定、放弃
- **用户示例**：
  - "算了"
  - "不要了"
  - "取消吧"
- **处理方式**：根据当前对话状态回退或终止（→ CANCELLED）

#### 修改/补充 (modify)
- **定义**：用户修改参数或补充缺失信息
- **触发词**：改成、换成、改为、调整、不对、是xx不是yy、补充、再加
- **用户示例**：
  - "改成200股"
  - "不是茅台，是五粮液"
  - "价格改成1800"
- **处理方式**：更新对应槽位，重新校验，回到确认状态

#### 重复/换一个 (repeat)
- **定义**：用户要求重复之前的内容，或换一个结果
- **触发词**：再说一遍、重复、换一个、再来一个、还有吗、其他的
- **用户示例**：
  - "再说一遍"
  - "换一只股票"
  - "还有其他推荐吗？"
- **处理方式**：重复上一条回复，或生成新的结果

#### 澄清 (clarify)
- **定义**：用户请求澄清问题，或系统对模糊输入发起澄清
- **触发词**：什么意思、没听懂、解释一下、再说清楚、哪个、什么
- **用户示例**：
  - "你说的是什么意思？"
  - "哪个板块？"
  - "没听懂，再说一遍"
- **处理方式**：状态机驱动，进入澄清流程，等待用户补充信息

#### 闲聊/帮助 (chitchat)
- **定义**：闲聊、问候、询问系统能力、帮助信息
- **触发词**：你好、你是谁、你能做什么、帮助、怎么用、谢谢
- **用户示例**：
  - "你好"
  - "你能做什么？"
  - "怎么用你交易？"
- **处理方式**：模板回复 + 功能引导，不进入主流程

## 4. 风险等级与处理流程

### 4.1 风险分级定义

| 等级 | 标签 | 意图类型 | 处理流程 |
|-----|------|---------|---------|
| 低 | 🟢 低风险 | 查询类、对话管理类 | 直接执行，无需确认 |
| 中 | 🟡 中风险 | 分析类、策略类、风控类 | 置信度≥0.85直接执行，否则确认 |
| 高 | 🔴 高风险 | 交易类（所有买卖操作） | 必须二次确认 + 风控前置校验 |

### 4.2 高风险意图处理流程

```
用户输入 → NLU识别（交易类） → 槽位完整？ → 否 → 追问缺失参数
                                ↓ 是
                            回显确认
                                ↓ 用户确认？ → 否 → 取消/修改
                                ↓ 是
                            第一道：意图风险校验通过
                                ↓
                            第二道：参数合规校验 → 不通过 → 返回错误
                                ↓ 通过
                            第三道：风控引擎校验 → 不通过 → 返回风控建议
                                ↓ 通过
                            生成交易指令 → 执行
                                ↓
                            返回执行结果 + 审计日志
```

## 7. 多意图处理策略

当用户输入包含多个意图时（如"茅台该卖吗，还有哪些新能源值得买"），按以下策略处理：

1. **识别所有意图**：使用多标签分类，识别出所有意图及对应参数
2. **优先级排序**：交易类 > 风控类 > 分析类 > 策略类 > 查询类
3. **串行处理**：按优先级依次处理，处理完一个再问下一个
4. **用户选择**：如果两个意图优先级相同，询问用户先处理哪个

### 多意图输出格式
```json
{
  "multi_intent": true,
  "intents": [
    {
      "intent_primary": "analysis",
      "intent_secondary": "holding_analysis",
      "slots": { "stock": "贵州茅台" },
      "priority": 2
    },
    {
      "intent_primary": "strategy",
      "intent_secondary": "stock_recommendation",
      "slots": { "sector": "新能源" },
      "priority": 3
    }
  ]
}
```
