2. 资金流分析（本文主体）
   - 目标：把外生资金/内生杠杆/链上与场内行为统一到可分层统计的状态机（regime），输出 bias/filter/risk-off 的研究信号。
   - 关键输出：`FlowTrend/FlowImpulse/FlowStress` 与分状态统计报告（见第 6/7/10 节）。
3. 加密叙事与情绪分析（规划，方法与字段契约先行）
   - 目标：将叙事强度作为“软资金流”，用于过滤与 stress 预警，不作为单独方向主因子。
   - 关键输出：`CommunityEffective`（热度衰减后有效强度）与 `NarrativeStress`（极端拥挤预警），并显式披露证据等级与缺失降级。
   - 评估结论（传统金融口径）：当前定位正确（更接近 sell-side sentiment index 的“过滤器”角色），但需补足“可交易性与可审计性”约束，避免把噪声当因子。
   - 优化 1（信号拆分）：除 `CommunityEffective` 水平值外，新增 `CommunityImpulse`（变化率/加速度）用于识别情绪二阶拐点；研究与面板必须区分“高热但降温”与“低热但升温”。
   - 优化 2（拥挤确认）：`NarrativeStress` 触发建议采用“双确认”——叙事拥挤 + 仓位/杠杆脆弱性（如 OI 分位、资金费率分位、基差分位）同时满足，降低误报。
   - 优化 3（证据加权）：证据等级不只看来源可信度，还应纳入 `source_diversity`、`concentration_risk`、`bot_suspect_ratio` 与 `latency_sec`，形成可复算 `EvidenceScore`。
   - 优化 4（阈值与状态）：默认使用滚动分位阈值（按 regime 自适应）替代固定阈值，并增加 `NarrativeRegime`（calm/heated/euphoric/panic）便于跨周期比较。
   - 优化 5（风控映射）：明确 `NarrativeStress` 仅映射为降风险动作（reduce/hedge/slowdown），禁止直接放大风险；缺失或冲突证据时 fail-closed。
   - 字段契约补充（建议最小集）：`CommunityImpulse`、`EvidenceScore`、`NarrativeRegime`、`source_diversity`、`concentration_risk`、`bot_suspect_ratio`、`latency_sec`、`trigger_confirmations[]`。
4. 基本面交易（规划，建议层）
   - 目标：将 1/2/3 的输出映射为可消费的“偏置/过滤/风控动作建议”，默认只读；未来如需触达配置/执行，必须走审批/审计链路。
5. Web3 行情汇总（已具备能力，复用并入）
   - 目标：汇总 Binance Web3 榜单、代币详情、地址洞察与 LLM 线程产物，输出可复核的市场状态、候选池与风险约束。

### 0.2 Level 2 真独立迁移方案（不改代码版）

目标：

- 保持现有 Prod 架构与交易主链路稳定，不在迁移初期引入生产不确定性。
- 为基本面系统建立独立代码目录、独立发布节奏与独立运行态，逐步完成与 Prod 的硬隔离。
- 在可回滚前提下完成切换：先并行验证，再灰度切流，最后下线 Prod 基本面重服务。

建议方案（不改代码版）：

- 阶段1：并行新系统
  - 保持现有 Prod 架构不变（8092/3001）。
  - 新建 Fundamental 独立代码目录与独立发布流水线，使用独立端口（如 8095/3005）与独立运行态目录。
- 阶段2：镜像观测
  - 新系统与 Prod 同期运行，采集同一批基本面接口结果与耗时，做一致性和稳定性对比。
- 阶段3：灰度切流
  - 先把少量用户或仅基本面入口导向新系统，Prod 继续保留基本面作为回退。
- 阶段4：正式切换
  - 当新系统达到门槛后，禁止 Prod 基本面服务，仅保留跳转或只读说明入口。
- 阶段5：收口治理
  - 固化“Prod 不承载基本面重任务”的制度与运维告警，防止流量与任务回流。

切换门禁（建议硬指标）：

- 稳定性：新系统 7–14 天无 P0，`/health` 可用率 ≥ 99.9%。
- 性能：P95/P99 接口耗时不劣于 Prod 同期基线。
- 一致性：关键输出字段一致率 ≥ 99%（允许时间戳类差异）。
- 隔离性：新系统与 Prod 的密钥、配置、outbox、日志目录完全独立，执行口径遵循隔离门禁要求（参考 [交易AI Agent 技术文档2.0.md:L1663-L1675](file:///Users/zhangjiangtao/ft_userdata/经典指标机器学习系统/交易AI%20Agent%20技术文档2.0.md#L1663-L1675)）。
- 回滚性：切流后可通过 1 条运维命令回退至 Prod 入口。

主要风险与对策：

- 风险：双系统结果漂移 → 固定版本窗口，按日产出 diff 报告并追踪偏差来源。
- 风险：运维复杂度上升 → 复用现有 launchd 多实例模板统一托管（见 [README.md](file:///Users/zhangjiangtao/ft_userdata/经典指标机器学习系统/ops/launchd/README.md)）。

## 1. 目标与适用边界

目标：

- 为 BTC/主流币提供一套可复用的“基本面/资金流”研究框架，用于方向偏置（bias）、触发过滤（filter）与事件风控（risk-off）。
- 明确每类“资金流”的定义、可置信度、滞后假设、可交易性边界，避免口径漂移与因果倒置。
- 将“外生资金 + 内生杠杆资金 + 链上行为”统一到可分层统计的状态机（regime）下，支持多周期一致性研究。

适用边界（重要）：

- 加密市场的“资金流”往往与价格强反身性耦合：上涨会吸引资金（追涨/被动配置），下跌会触发资金流出与强制卖出（爆仓/保证金）。因此本框架默认把资金流分为“外生驱动”与“内生反馈”，并在研究中显式处理滞后与分状态统计。
- 资金流研究优先服务中低频（周/日/4H）偏置与风控；1H 更偏执行与风险过滤，不建议用作“宏观方向”的主要依据。

## 2. 三层基本面框架（传统金融口径 → 加密适配）

### 2.1 外生资金（Exogenous）

定义：来自加密系统外部或弱相关内部的净增量资金，具有相对明确的“源头”和更稳定的口径。

典型来源：

- 机构资金：现货 ETF 申赎净额、托管余额变化。
- 宏观资金：美元流动性、风险偏好（股债汇/信用利差）、真实利率变化。
- 稳定币：USDT/USDC 等净发行/净赎回、交易所端稳定币余额变化（更贴近“可用购买力”）。

### 2.2 内生杠杆与仓位（Endogenous Positioning）

定义：由衍生品杠杆、做市对冲与强制交易机制驱动的资金/仓位变化，常表现为“压力指数”与“脆弱性指标”，在极端行情中主导短期价格路径。

典型来源：

- 永续资金费率、基差（现货-永续/期货）、合约持仓量（OI）变化。
- 清算数据（多空清算额、清算密度）、保证金压力与强平瀑布。
- 期权隐含波动率（IV）、偏度（skew）、gamma/vanna 暴露变化（对冲买卖压力）。

### 2.3 链上与交易所行为（Onchain & Venue Behavior）

定义：链上转账、交易所净流入流出、矿工/长期持有者行为等；可解释性较强，但口径易混入“搬砖/归集/地址迁移”等非交易行为。

典型来源：

- 交易所净流入/净流出（BTC/稳定币）、交易所余额。
- 大额地址/巨鲸转账（需做实体聚类与标签过滤）。
- 矿工余额、长期持有者（LTH/STH）成本区与供给释放。

### 2.4 社区与叙事驱动（Narrative & Sentiment）

定义：社交媒体情绪、搜索趋势与叙事强度所形成的“软资金流”，可作为外生资金与风险偏好变化的领先观测，用于 bias/过滤与 stress 预警。

适用边界：

- 该层高度反身性与可操纵（刷量/机器人/KOL 带货），默认不作为单独方向主因子，优先用于过滤与风控。
- 对 BTC 更多体现为事件预热与波动放大器；对主题与山寨更可能体现为短期叙事驱动，但尾部风险显著更大。

典型来源：

- 社交情绪：X（Twitter）提及量与互动、情绪评分、关键词热度；LunarCrush 类聚合指标。
- 搜索趋势：Google Trends（如 “BTC ETF”“halving”“regulation”）。
- 社区活跃：Reddit/GitHub 活跃度、Discord/Telegram 成员增长（偏生态/项目级）。
- 叙事强度：AI 情绪分类（positive/negative/neutral）+ 主题词频与共现（如 “AI”“RWA”“L2”“meme”）。

纳入资金流定义（建议）：

- 类型：`narrative`
- 可信度初始：2–3（取决于是否具备去机器人、去重复主体、多源一致性校验）
- 滞后假设：0–48h（牛/主题行情更短，熊市更不稳定）
- 用途：作为 `OverallFlowImpulse`（热度变化）与 `FlowStress`（极端拥挤）组件；或作为 bias 的过滤条件

## 3. 资金流定义规范（必须统一的字段契约）

每一类资金流都必须给出以下 6 项定义，才允许进入“整体资金流”合成：

1. 名称与类型：exogenous / endogenous / onchain / narrative
2. 原始指标：例如 `etf_net_inflow_usd`、`exchange_btc_netflow`、`perp_funding_rate`
3. 单位与量纲：USD、BTC、bps、百分比；是否需要除以市值/成交额做归一
4. 采样频率与时间戳：日频/小时频；使用事件时间还是入库时间
5. 修订与延迟：是否会回填/修订；最短可用延迟（latency）
6. 交易含义：更接近“方向因子”还是“压力因子”（risk）

### 3.1 数据字典字段命名模板（建议统一）

目的：把“同一指标”的原始值、标准化值、平滑值、变化量与质量标记统一命名，便于合成、回测与排障复现。

命名约定：

- 指标基名（base，强约束）：`{metric}__{asset}__{venue}__{chain}`
  - `{metric}`：指标语义与单位（建议用 `_usd/_btc/_bps/_pct/_count/_ratio/_index` 等收尾）
  - `{asset}`：研究对象/目标资产（前期以 `btc` 为主；后期可扩展 `eth/alt/all/<symbol>`）
  - `{venue}`：交易场所/数据口径来源（如 `binance/okx/bybit/cme/all/na`；跨场所差可用 `cme_vs_binance`）
  - `{chain}`：链/生态（如 `btc/eth/sol/arb/op/bsc/all/na`；跨链可用 `eth_to_sol` 或 `all`）
- 维度分隔符约束：
  - `__` 仅用于分隔 `{metric}/{asset}/{venue}/{chain}` 四段
  - `{metric}` 内部用 `_` 分词

#### 3.1.1 枚举表与校验规则（强制约束，防口径漂移）

适用原则：

- 前期研究对象以 BTC 为主：所有新增指标默认以 `__btc__*__*` 落地；其它资产维度先保留接口与命名规范，不要求在研究阶段产出全量数据。
- 后期扩展到 Alt：不新增独立模块，依赖既有“代币池/聚类一致性”产出候选集合；接口与命名必须提前约束，确保可直接调用与复现。

`{asset}` 允许值（建议固定为小写）：

- `btc`：仅 BTC（前期主对象）
- `eth`：仅 ETH（可选）
- `alt`：Alt 池（默认定义：非 BTC 且不包含 ETH；由系统的代币池/聚类一致性结果提供集合）
- `non_btc`：所有非 BTC（包含 ETH 与 Alt）
- `all`：全市场聚合口径（不区分资产，适用于稳定币总量、DeFi TVL、总体情绪等）
- `<symbol>`：单一币种符号（小写，建议使用统一标准符号；例如 `sol`）

`{venue}` 允许值：

- `na`：不适用（链上/宏观/非交易所口径）
- `all`：聚合（跨交易所/跨数据源合并后的口径）
- 交易所/场所枚举（可扩展但需登记）：`binance`、`okx`、`bybit`、`deribit`、`cme`
- 跨场所差分口径：`<venue1>_vs_<venue2>`（例如 `cme_vs_binance`），用于表达“结构差/参与者分层”

`{chain}` 允许值：

- `na`：不适用（交易所衍生品、宏观、纯舆情）
- `all`：跨链聚合（如跨链 TVL、跨链桥聚合等）
- 主链/生态枚举（可扩展但需登记）：`btc`、`eth`、`sol`、`bsc`、`arb`、`op`
- 跨链迁移口径：`<chain1>_to_<chain2>`（例如 `eth_to_sol`），用于桥流与迁移解释

命名校验规则（建议）：

- base 必须严格符合：`{metric}__{asset}__{venue}__{chain}`
- 建议字符集：
  - `{metric}`：`[a-z0-9_]+`
  - `{asset}/{venue}/{chain}`：`[a-z0-9_]+`
- 禁止在任一段使用额外的 `__`，避免解析歧义

Alt 扩展的接口约束（预留，必须保留）：

- 当 `{asset}=btc/eth/<symbol>`：集合解析为单资产
- 当 `{asset}=alt`：集合由系统既有“代币池/聚类一致性”解析，默认不含 BTC/ETH
- 当 `{asset}=non_btc`：集合由系统既有代币池解析，包含 ETH 与 Alt
- 若集合解析失败或为空：指标质量标记为 `missing` 并触发 3.3 的整体降级策略（整体输出趋于保守）

推荐（BTC 优先、可扩展）：

- 对交易所/衍生品类：`{metric}__btc__{venue}__na`
- 对链上/生态类：`{metric}__{asset}__na__{chain}`
- 对宏观类：`{metric}__{asset}__na__na`（通常 `{asset}=btc 或 all`）
- 对全市场状态类：允许 `{asset}=all`（例如稳定币与 DeFi 总量类）
- 统一后缀：
  - `_raw`：原始值（尽量保持原口径与原单位）
  - `_z`：滚动标准化（z-score 或 robust z）
  - `_ema`：对 `_z` 或 `_raw` 的平滑（需在数据字典声明平滑对象与 span）
  - `_delta`：变化量（默认对 `_ema` 做差分；需在数据字典声明）
  - `_pctl`：滚动分位数（0–1）
  - `_pctl`：滚动分位数（0–1）
  - `_rank`：横截面排名（0–1），仅在多币种/多交易所场景使用
  - `_source`：数据源标识（字符串或枚举）
  - `_quality`：质量枚举（见 3.3）
  - `_latency_sec`：本条数据相对事件时间的延迟秒数（可选）
  - `_rev_id`：修订版本号/批次（可选，用于回填修订追踪）

推荐组合（最小集合）：

- `{base}_raw`（事实）
- `{base}_z`（同量纲可比）
- `{base}_ema`（稳健趋势）
- `{base}_delta`（变化冲量）
- `{base}_quality`（缺失与回填可追踪）

### 3.3 缺失与降级策略模板（建议统一）

目标：保证研究可复现与线上可用性，避免“缺数据→指标跳变→策略行为抖动”。

质量枚举（建议）：

- `ok`：数据按期到达且未被修订
- `stale`：超过最大允许延迟仍未更新（使用上一个值或降级值）
- `missing`：当前窗口缺失且无可用历史值
- `backfilled`：发生回填修订（用于标记该段数据不适合做实时信号）
- `suspect`：疑似异常（尖峰/断崖/口径突变），需要 winsorize 或剔除

每条指标的缺失处理（按优先级）：

1. 原始缺失（`*_raw`）
   - 若允许短期持平：`raw := last_observation` 并标记 `stale`
   - 若不允许持平：直接标记 `missing`
2. 标准化与平滑（`*_z/_ema`）
   - `raw=missing` 时：`z/ema/delta` 全部标记 `missing`
   - `raw=stale` 时：允许 `ema` 继续用持平值，但 `delta` 置 0，并标记 `stale`
3. 回填修订（`backfilled`）
   - 研究可用：允许重算全量序列
   - 实时信号：在回填窗口内禁用该指标的方向贡献，仅保留风险提示或直接剔除

整体合成的缺失降级（用于 `OverallFlowTrend/Impulse/Stress`）：

- 覆盖率门槛：若在合成时 `Σ w_i（quality=ok 或 stale） < w_min_coverage`，则整体输出为 `neutral`，并将整体质量标记为 `missing`
- 风险优先：`FlowStress` 缺失时宁可保守（输出不降低风险），不因缺失而放松风控
- 备选路径：当主指标缺失时，允许在“同类型、同含义”的备选指标中替换（例如 `oi_binance_usd` 缺失时用 `oi_okx_usd`），替换必须在条目内写明并继承更低的可信度与更严格的滞后假设

## 5. 滞后假设（Lag Hypothesis）

原则：不同资金流的“领先/滞后”不同，且在不同 regime 下会改变；必须在研究中显式建模，不能统一用同一窗口或直接求导。

建议做法：

- 为每一类资金流定义一个“基础滞后区间”（例如 0–24h、1–3d），并在分状态统计中验证其稳定性。
- 对“可能同步解释但不预测”的变量，仅允许其作为风控或过滤变量，不允许作为方向预测主因子。

验证建议（研究用）：

- 领先/滞后稳定性：滚动窗口的相关、分位数组合收益差（quantile spread），并按 regime 分桶验证。
- 因果检验：Granger 作为候选筛选工具即可，结论以分状态 out-of-sample 稳定性为准。
- 防信息泄漏：严格按事件时间对齐，采用时间序列 walk-forward；若做模型训练，使用 purged/embargo 处理相邻样本泄漏。

参考滞后假设（需用历史数据验证并允许更新）：

- ETF 申赎净额：对日线价格可能同步或 0–1 日滞后；对 4H 以内不建议做方向预测主因子。
- 稳定币净发行/净赎回：偏 1–7 日；更适合做周/日偏置与风险偏好状态输入。
- 资金费率/基差：偏 0–12 小时，且在杠杆拥挤与趋势延续阶段更有效。
- 清算额/清算密度：偏同步或 0–6 小时；主要用于“去杠杆阶段的风险管理/反转确认”。
- 交易所净流入（BTC）：偏 0–3 日；更多用于“供给压力”与风险过滤。
- 叙事/情绪热度：偏 0–48 小时；在主题行情下更可能领先，在熊市更不稳定

## 6. 标准化与“整体资金流”合成（Overall Flow）

### 6.1 不建议直接使用“流速/加速度”的原因

- 对原始序列求导会放大噪声与采样误差，尤其是链上与交易所类数据。
- “加速度”在不同频率下不可比，且容易被数据缺口与回填造成伪信号。

### 6.2 推荐的稳定合成方法（研究版）

对每条资金流序列 `x_t`：

- 先做缺失与异常处理：winsorize、缺口标记、回填标记
- 再做滚动标准化：`z_t = (x_t - median_{W}) / MAD_{W}` 或滚动 z-score
- 再做平滑与变化：`z_smooth_t = EMA(z_t, span)`，并计算 `Δz_t = z_smooth_t - z_smooth_{t-1}`

合成：

- 方向因子（bias）：`FlowTrend_t = Σ w_i * z_smooth_{i,t}`
- 变化因子（impulse）：`FlowImpulse_t = Σ w_i * Δz_{i,t}`
- 风险压力（risk）：将“内生压力类”（清算/费率极端/OI spike/IV spike）单独合成 `FlowStress_t`，不与 bias 等权混合

权重 `w_i` 的初始值建议与“可信度评分”成正比，并在分状态统计后允许做小幅调整。

可选增强（第二阶段，谨慎引入）：

- 去冗余：对高度同源的流（例如多个交易所 OI）可先做 PCA/聚类压缩，再进入合成，避免重复计票。
- 非线性组合：把 `FlowTrend/FlowImpulse/FlowStress` 以及关键交互项输入到随机森林/梯度提升树，用于识别“脆弱状态”或做风险分类；默认不直接替代可解释的方向合成。

## 7. 分状态（Regime）分层统计（必须）

把同一套因子在不同市场状态下分别统计，避免平均后得到“看似有效但不可用”的结论。

建议至少 3 个维度：

1. 趋势/区间：基于周/日趋势强弱与波动结构（例如趋势强度 + 波动分位数）
2. 杠杆拥挤/去杠杆：基于费率分位数、OI 分位数、清算强度
3. 宏观 risk-on/off：基于股市风险偏好、美元流动性代理、真实利率方向

可选第四维（强烈建议在加密加入）：

4. 流动性 regime：基于市场深度/冲击成本/价差等（缺盘口数据时可用成交额与高频波动代理）

输出口径：

- 每个 regime 下分别计算：胜率、期望收益、尾部损失分位数、最大回撤、信号覆盖率（coverage）。
- 做领先/滞后检验：`FlowTrend_t` 与未来 `k` 期收益的相关、分位数收益差、以及在不同 regime 的稳定性。
- 增加传统金融口径：信息比率（IR）与 Calmar（用于回撤调整后的稳健性对比）

## 8. 多周期研究职责划分（周/日/4H/1H）

- 周线：确定宏观与周期位置，决定风险预算上限（是否允许加仓、最大暴露）。
- 日线：形成方向偏置与仓位管理规则（顺势/逆势、允许的持有期）。
- 4H：结构与触发区（关键位、回撤/反弹、杠杆压力过滤）。
- 1H：执行与风控（降低滑点、避免事件窗口、避免高拥挤时追价）。

可选补充：实时监控层（<1H）

- 定位：用于告警与风险熔断（risk-off），不用于常态方向预测。
- 典型触发：清算额短时激增、费率/基差极端跳变、OI spike、交易所异常价差与流动性骤降。

## 9. 消息面（事件）研究：以风控为主的量化方案

定位：事件在系统中以风控优先级参与，而非作为主要方向预测因子。

### 9.1 事件分类（建议）

- 地缘风险：战争升级、制裁、黑天鹅冲击
- 货币政策：FOMC、议息会议、点阵图、主席讲话
- 美国经济数据：CPI/PPI/NFP/失业率/零售等（以“预期差”为核心）
- 加密政策与监管：SEC/法院判例、税务、稳定币与交易所监管、ETF 相关审批进展
- 协议/技术事件：主网升级、硬分叉、BTC 减半等
- 黑客/安全事件：交易所被盗、桥攻击、协议漏洞导致的挤兑与恐慌迁移
- 文化与 meme 事件：社区集体行动、主题轮动、短期挤压

### 9.2 事件研究方法（事件窗口 + 预期差分桶）

- 事件窗口：`[-48h, +48h]`、`[-24h, +24h]`、`[-6h, +6h]`、`[0, +4h]` 分层评估（用于覆盖预热/泄露/谣言）
- 分桶：按“实际-预期（surprise）”分为偏鹰/符合/偏鸽或利多/中性/利空
- 可选补充：加入“市场预期共识”作为辅助分桶依据（如 X 舆情与预测市场），用于刻画预期差的基线
- 输出：每桶的收益分布、胜率、尾部风险、波动与滑点放大倍数

### 9.3 风控联动建议（可执行）

- 高等级事件：只允许减仓/平仓，不允许加仓；或将仓位上限按比例下调
- 公布前：降低杠杆与挂单密度，扩大保护（避免跳空滑点）
- 公布后：等待价格与 `FlowStress` 回落或确认，再恢复常规执行

仓位缩放（示例口径）：

- 仓位上限 = 基线仓位上限 × clamp(1 − q(surprise), min_scale, 1)
- `q(surprise)`：surprise 在历史分布中的分位数映射（分位越极端，缩放越大）
- `min_scale`：建议大于 0（避免频繁归零导致行为抖动）

- 内生杠杆：OI/费率/基差/清算（按交易所分层，至少区分 `cme` vs `binance|okx`）。
- 链上与场内：交易所净流与余额（先做强过滤与质量标记，宁缺毋滥）。

Step 2：强制缺失与降级（不可绕过）

- 采用第 3.3 节的 `ok/stale/missing/backfilled/suspect` 质量枚举与整体 coverage 门槛。

- 任一指标若发生修订/回填：必须标记 `backfilled/suspect`，并在 `confidence/filter` 上做惩罚与降级。

Step 3：合成与分状态统计（验收口径）

- 合成方法以第 6.2 节为准：`FlowTrend/FlowImpulse/FlowStress` 分开维护。
- 分状态统计以第 7 节为准：至少三维（趋势/区间、杠杆拥挤/去杠杆、宏观 risk-on/off），并建议增加第四维（流动性/冲击成本）。
- 验收统计必须包含 coverage 与尾部风险分位数，并显式披露“固定阈值 vs 分位数触发”的口径差异，默认采用分位数与稳健标准化版本。

## 13. FAQ（实施经验沉淀）

### Q1：为什么会出现“BTC 当前价有值，但 MA20 显示数据暂不可用”？

A：

- 常见原因不是行情源故障，而是“字段回填链路断裂”：
  - BTC 当前价来自 `market_snapshot.crypto.btc.price_usd`（实时快照）。
  - MA20 来自 `_compute_market_trend_state(...)` 的 `market_trend_meta.ma20`（趋势计算）。
- 当模板只读取 `market_snapshot.crypto.btc_ma20/ma20`，但未把 `market_trend_meta.ma20` 回填到 `market_snapshot.crypto` 时，就会出现“现价正常、MA20 缺失”的不一致现象。

### Q2：MA20 的单一事实来源（SSoT）应如何定义？

A：

- 计算口径以 `historical_data/btc_daily_prices.json + 当前 BTC 价格` 的 20 日窗口均值为准。
- 展示口径统一读取 `market_snapshot.crypto.btc_ma20`（兼容字段 `market_snapshot.crypto.ma20`）。
- 生成简报前必须执行“计算 → 回填 → 渲染”三步闭环，避免模板直接访问未回填字段。

### Q3：如何用最小步骤快速验证修复是否生效？

## 14. 传统金融标准补充：拐点判定与图表验收清单（新增）

目标：

- 将“连续观测 → 转折识别 → 风险动作”固化为统一研究口径，避免仅靠离散事件做主观判断。
- 以传统金融 buy-side 常用的“水平 + 斜率 + 压力”框架，约束资金流、叙事、交易建议三层输出。

### 14.1 拐点判定理论框架（Level-Slope-Stress）

核心定义：

- `Level`：状态水平（高/中/低），使用滚动分位数表达相对位置（推荐 20/50/80 分位）。
- `Slope`：状态斜率，一阶变化（可用 `_delta` 或短窗 EMA 差）。
- `Stress`：脆弱性压力（清算、拥挤、流动性冲击、事件强度），与方向信号分开维护。
- `Quality`：数据可用性与可信度门槛（`ok/stale/missing/backfilled/suspect` + coverage）。

标准原则：

- 方向判断不等于风险判断：`FlowTrend/CommunityEffective` 负责方向，`FlowStress/NarrativeStress` 负责脆弱性。
- 拐点必须满足“变化 + 确认”而非单点阈值击穿，避免噪声触发。
- 任何 `Quality` 不达标的拐点结论，默认降级为 `unknown`，并执行 fail-closed。

### 14.2 拐点状态机（Turning Point State Machine）

状态集合（建议最小集）：

- `expansion`：Level 高且 Slope 正，Stress 低到中。
- `overheat`：Level 高且 Slope 放缓或转负，Stress 上升。
- `distribution`：Level 高位回落，Slope 负且 Stress 高。
- `contraction`：Level 低且 Slope 负，Stress 中到高。
- `repair`：Level 低位企稳，Slope 转正，Stress 回落。
- `unknown`：质量不足或覆盖不足，无法判定。

转移判据（建议）：

- `expansion -> overheat`：`Level>=P80` 且 `Slope` 连续转弱，或 `Stress` 升至中高分位。
- `overheat -> distribution`：`Slope<0` 且 `Stress>=P80`，并满足双确认窗口。
- `contraction -> repair`：`Level<=P20` 后 `Slope` 转正且 `Stress` 下行。
- 任意状态 -> `unknown`：`coverage < coverage_min` 或关键源 `missing/backfilled/suspect`。

### 14.3 双确认机制（防误报的硬约束）

触发规则（建议固定）：

- 条件 A（方向变化）：`Slope` 发生符号切换或连续衰减/增强达到阈值。
- 条件 B（风险确认）：`Stress` 或拥挤代理（费率/OI 分位/流动性冲击）同步确认。
- 条件 C（质量确认）：`quality in {ok, stale}` 且 `coverage >= coverage_min`。

生效条件：

- A 与 B 同时满足，并在 `confirm_bars`（建议 2–3 个观测点）内持续，才写入“有效拐点”。
- 若仅满足 A 不满足 B，则只输出“候选拐点”，不得直接升级风险动作。

### 14.4 多周期分工与拐点层级

- 周线（战略层）：识别周期级拐点，决定风险预算上限与杠杆上限。
- 日线（战术层）：确认趋势转折，决定 bias 与持仓结构调整。
- 4H（执行层）：验证短期冲量与拥挤变化，决定 filter/slowdown。
- 1H（监控层）：用于告警与熔断，不作为主方向判定。

冲突处理（建议）：

- 大周期与小周期冲突时，以大周期方向为主，小周期仅可降低风险，不可逆向放大风险。
- 当周/日线未确认时，4H/1H 仅允许输出 `observe/slowdown/hedge` 类建议。

### 14.5 图表输出规范（像图表一样持续输出）

每个模块的最小图表包（必须）：

1. 主指标时序图（至少 180 天窗口）
   - 资金流：`FlowTrend/FlowImpulse/FlowStress`
   - 叙事：`community_effective_score/community_impulse/narrative_stress`
2. 分位阈值带
   - 显示 P20/P50/P80 与当前点位，禁止仅显示原始值。
3. 拐点标记层
   - 标记 `expansion/overheat/distribution/contraction/repair/unknown` 与触发时间戳。
4. 质量与覆盖率副图
   - 显示 `quality` 分布与 `coverage` 时间序列，显式标记缺失/回填段。
5. 动作映射时间线
   - 展示每次 `bias/filter/risk-off` 建议及其证据链引用。

总览页（/fundamental）额外要求：

- Regime 迁移图：最近 30 天状态转移路径与停留时长。

用途：一屏回答“现在能不能做、偏向哪边、信号强不强”。

字段：

- `signal.buy_sell_signal`
- `signal.trend_direction`
- `signal.trend_speed`
- `signal.signal_confidence`
- `execution_gate`
- `generated_at`

展示要求：

- 信号方向与动作颜色一致（buy/up 正向；sell/down 负向；hold/neutral 中性）
- 置信度采用 0–1 或百分比统一口径

#### Card-2：交易动作卡（Action Card）

用途：把研究结论翻译成可执行前的“建议动作语义”。

字段：

- `advice.bias_dir`
- `advice.execution_filter`
- `advice.risk_action_proposal`
- `advice.position_scale`
- `advice.ttl|valid_until`

展示要求：

- `execution_filter` 为 `block|slowdown` 时显著提示
- `risk_action_proposal` 与 `position_scale` 同行展示

#### Card-3：轻量信号时间线卡（Signal Timeline）

用途：展示最近窗口内信号演化，不做复杂图。

字段（序列）：

- `ts_ms`
- `composite_or_score`
- `signal_confidence`
- `trend_direction`
- `execution_filter`
- `risk_action_proposal`

展示要求：

- 主线：`composite_or_score`
- 副线：`signal_confidence`
- 点标：`execution_filter/risk_action_proposal`

#### Card-4：贡献拆解卡（Contribution）

用途：解释当前交易信号由哪些模块驱动。

字段：

- `module`（flows/news/narrative/web3）
- `module_score|contribution`
- `module_quality`
- `module_coverage`
- `rule_hits[]`（可选）

展示要求：

- 按绝对贡献排序（TopN）
- 缺失模块需保留占位并标注原因

#### Card-5：质量与风控门禁卡（Quality & Gate）

用途：先看“可不可信”，再看“可不可以动”。

字段：

- `quality_summary.overall_quality`
- `quality_summary.coverage`
- `quality_summary.missing_data[]`
- `execution_gate`
- `advice.execution_filter`

展示要求：

- `missing/suspect/backfilled` 高亮
- 门禁动作与质量状态同屏显示

#### Card-6：证据链卡（Evidence Chain）

用途：支持复核与审计，不让结论“黑盒化”。

字段：

- `evidence_chain[].module`
- `evidence_chain[].metric`
- `evidence_chain[].value`
- `evidence_chain[].direction`
- `evidence_chain[].source_ref`
- `evidence_chain[].source_time`
- `evidence_chain[].evidence_grade`

展示要求：

- 默认显示最近/最高等级前 N 条
- 支持按模块过滤（flows/news/narrative/web3）

## 17. 基本面页面逐模块改造实施（信号传递版）

### 17.1 本轮改造范围

- 纳入改造：
  - `/fundamental/overview`
  - `/fundamental/news`
  - `/fundamental/flows`
  - `/fundamental/narrative`
  - `/fundamental/trading`
- 明确不改：
  - `/fundamental/web3-digest`（Web3 行情汇总）
  - `/fundamental/automation`（自动化决策与执行）

### 17.2 页面级目标结构

每个纳入页面都按同一交易语义输出首卡：

- `buy_sell_signal`
- `trend_direction`
- `trend_speed`
- `signal_confidence`
- `execution_gate`

每个纳入页面都按同一动作语义输出次级字段：

- `bias_dir`
- `execution_filter`
- `risk_action_proposal`
- `position_scale`
- `quality/coverage/missing_data`
- `evidence_count|evidence_chain`

### 17.3 模块逐个改造清单

#### A. `/fundamental/overview`

- 目标：由治理总览改为交易总览入口。
- 首卡：汇总信号卡（四元组 + 门禁）。
- 次级：交易动作摘要、轻量时间线、模块诊断区（降级为次级）。

#### B. `/fundamental/news`

- 目标：将事件账本与风险动作聚合成新闻交易信号。
- 首卡：新闻模块信号卡（由 latest run + turning state 生成）。
- 次级：保留 Anchor/Delta、评估历史、分类视图与证据复核。

#### C. `/fundamental/flows`

- 目标：将三层状态机与 explain 分类收敛成资金流信号。
- 首卡：资金流模块信号卡（bias/filter/置信度/速度）。
- 次级：三层分解、仓位建议、新鲜度、可解释明细。

#### D. `/fundamental/narrative`

- 目标：将叙事情绪、冲量、质量披露收敛成叙事信号。
- 首卡：叙事模块信号卡（方向/速度/置信度）。
- 次级：时间序列、状态机、质量审计、证据链与原始简报。

#### E. `/fundamental/trading`

- 目标：统一消费各模块信号，输出最终交易建议语义。
- 首卡：交易模块汇总信号卡（四元组 + bias/filter/risk-off）。
- 次级：保留原 `Bias / Filter / Risk-off` 明细与触发原因。

### 17.4 统一降级规则（页面强制）

- 任一页 `coverage` 不足：降级到 `hold + slowdown|block`
- 任一页 `missing_data` 非空：显示缺失披露并触发保守语义
- 任一页 `evidence` 不足：不得输出风险放大建议
- 所有页面保持 `execution_gate=readonly_advisory`
