一、当前策略结构概览

1. 时间框架与方向
- 主时间框架：5m（策略 timefrime）
- 信息时间框架：1h / 1d / 1w
- 支持多空（can_short = True）

2. 入场结构（当前已实现）
- 经典三屏为主：
  - 周线（1w）：MACD 直方图判断大级别趋势，生成：
    - btc_trend_1w：方向（1 多 / -1 空 / 0 中性）
    - btc_trend_1w_strong_long / btc_trend_1w_strong_short：强趋势标记（直方图同向放大）
  - 日线（1d）：多振荡器 ANY 回调信号：
    - RSI / Stoch / Williams%R / CCI 四类经典振荡器
    - osc_long_1d / osc_short_1d：满足任一振荡器条件记为 1
  - 1h：趋势 + 突破：
    - btc_trend_1h：ema20/ema50 趋势方向
    - btc_break_long_1h / btc_break_short_1h：10 根 high/low 突破
- 三屏入场条件（populate_entry_trend）：
  - 多头：
    - btc_trend_1w == 1
    - btc_trend_1h == 1
    - osc_long_1d_1d == 1
    - btc_break_long_1h == 1
  - 空头：
    - btc_trend_1w == -1
    - btc_trend_1h == -1
    - osc_short_1d_1d == 1
    - btc_break_short_1h == 1

3. 反转入场通道（当前已实现）
- 使用已有日线强反转模块：
  - btc_reversal_long / btc_reversal_short：日线层强反转信号（条件本身较严）
- 使用 regime + 1h 波动过滤：
  - regime_zone_1d_1d == 3：强多头反转区
  - regime_zone_1d_1d == -3：强空头反转区
  - vol_regime_1h_1h == 2：1h 成交量高潮环境
- 无仓时反转入场候选：
  - reversal_long_candidate = btc_reversal_long == 1 且 regime_zone == 3 且 vol_regime_1h == 2
  - reversal_short_candidate = btc_reversal_short == 1 且 regime_zone == -3 且 vol_regime_1h == 2
- 入场优先级：
  - 先判断三屏 long_signal / short_signal；
  - 若三屏无信号，再考虑 reversal_long_candidate / reversal_short_candidate；
  - 确保反转通道是三屏的补充，而非与之冲突。

4. 出场与四档动作（当前已实现）
- exit_trend（日线趋势退出）：
  - trend_regime_1d + trend_dir_1d 组合，检测：
    - 趋势 → 震荡 的 regime 切换
    - 趋势方向反转
  - 结合 bullish_alignment / bearish_alignment 给出 exit_trend（平多 / 平空）
- 四档动作（_classify_exit_action）：
  - scale_out_tight_sl：减仓 + 收紧止损
  - close：平仓
  - close_cooldown：平仓并冷却一段时间（ban martingale）
  - close_and_reverse：平仓并进入“等待反向入场窗口”
- 触发依据：
  - 日级 z-score_ema20_rt
  - 日级 volume ratio / volume z-score
  - 日级 Donchian / Keltner 极端
  - 日级长影线 candle 模式

5. 反转单专用止盈止损（当前已实现）
- custom_stoploss：
  - 若 pair 在 reversal_trade_end_time 中：
    - 用 ATR×reversal_sl_multiplier 设定基准 SL（相对开仓价的比例）；
    - 用 ATR×reversal_tp_multiplier 得到目标 TP；
    - 当前利润达到 activation_profit 后激活 trailing，基于 ATR 滚动调整；
- custom_take_profit：
  - 若 pair 在 reversal_trade_end_time 中：
    - 基于 ATR×reversal_tp_multiplier 设定 TP；
    - 若出现 vol_climax_against（反向高潮量），提高 TP 目标系数；

6. 马丁格尔加仓与风控（当前已实现）
- adjust_trade_position：
  - 最小加仓时间间隔（min_add_position_interval_seconds）；
  - BTC / Alt 分别的价格不利方向阈值（price_drop_threshold_*）；
  - 资金费率过滤（避免在费率极不利时加仓）；
  - 限制加仓层数与单笔资金规模；
- 动态杠杆（自定义逻辑）：
  - 根据 atr_pct 与最大杠杆限制调整实际杠杆；
- custom_stoploss（常规部分）：
  - 根据 regime_zone_1d_1d / vol_regime_1h_1h / btc_trend_1d / btc_trend_1h 调整 stoploss 因子。


二、总体升级路线规划

总体原则：
- 先确保 1h 层面的三屏 + 反转在“信号数量 × 质量”上达到可接受水平；
- 在此基础上，再使用 5m 微结构做精细择时；
- 出入场共享统一动作引擎，避免规则碎片化；
- 再叠加策略级风控覆层，控制连续亏损和极端 drawdown。

规划分为四个阶段（Phase 0 + A + B + C）：

1）Phase 0：1h 信号数量与质量提升（当前进行中，部分已落地）
2）Phase A：5m 微结构择时层（只在 1h 成熟后启用）
3）Phase B：统一动作引擎 2.0（ENTRY / EXIT 共用评分 + 动作映射）
4）Phase C：策略级风控覆层 2.0（冷却 / 熔断）


三、Phase 0：1h 层信号数量与质量提升（已部分落地）

目标：
- 在“周 / 日 同向、日振荡 ANY”基础上，
  提高 1h 入场机会数量，同时避免明显降低信号质量。
- 未来衡量标准（待有回测后）：
  - 每月交易次数（单品种）≥ 15–30 笔；
  - 胜率 45–55% 以上，盈亏比 ≥ 1.2，Profit Factor ≥ 1.3–1.5；
  - 不同市场阶段下表现不过于极端失衡。

Phase 0 的主要方向：

1）丰富 1h 入场形态（当前只做标记 + 日志，不参与决策）

- 已新增 1h 形态标记（在 populate_indicators 中计算）：
  1. 1h 均线回调形态：
     - btc_ema_pullback_long_1h：
       - 条件：
         - btc_trend_1h == 1（ema20 > ema50 且 ema20 向上）
         - 上一根 K 收盘在 ema20 下方，本根收盘重新站上 ema20
       - 含义：上涨趋势中回踩 ema20 后重新拉起。
     - btc_ema_pullback_short_1h：
       - 条件：
         - btc_trend_1h == -1
         - 上一根在 ema20 上方，本根收盘跌回 ema20 下方
       - 含义：下跌趋势中反弹至 ema20 后重新回落。

  2. 1h 通道回调形态（基于 BBANDS 20）：
     - btc_chan_pullback_long_1h：
       - 条件：
         - btc_trend_1h == 1
         - bb_lower_20 有效
         - 本根 low 刺破下轨，但 close 收在下轨之上
       - 含义：多头趋势中打到布林下轨的深回调 + 收盘企稳。
     - btc_chan_pullback_short_1h：
       - 条件：
         - btc_trend_1h == -1
         - bb_upper_20 有效
         - 本根 high 刺破上轨，但 close 收回上轨之下
       - 含义：空头趋势中冲到布林上轨的极端反弹 + 收盘回落。

  3. 1h 短周期盘整后的突破：
     - 计算最近 5 根 1h 的 high/low 窗口：window_high / window_low；
     - range_pct = (window_high - window_low) / close < 1% 视为窄幅盘整；
     - btc_consol_break_long_1h：
       - 条件：
         - btc_trend_1h == 1
         - 前一根处于盘整窗口（consolidation == True）
         - 当前收盘价 > 上一窗口高点
       - 含义：多头趋势中的盘整后向上突破。
     - btc_consol_break_short_1h：
       - 条件：
         - btc_trend_1h == -1
         - 前一根处于盘整窗口
         - 当前收盘价 < 上一窗口低点
       - 含义：空头趋势中的盘整后向下突破。

- 当前状态：
  - 以上 6 个 1h 形态列已通过 merge_informative_pair 加入主 5m DataFrame：
    - btc_ema_pullback_long_1h / btc_ema_pullback_short_1h
    - btc_chan_pullback_long_1h / btc_chan_pullback_short_1h
    - btc_consol_break_long_1h / btc_consol_break_short_1h
  - 目前三屏入场逻辑仍然只依赖：
    - btc_trend_1w, btc_trend_1h, osc_long_1d_1d / osc_short_1d_1d, btc_break_long_1h / btc_break_short_1h
  - 新 1h 形态只在日志中展示，不参与 enter_long/enter_short 判定。

2）利用周线强趋势分层放宽日线振荡条件（设计已预留变量）

- 周线强趋势标记：
  - btc_trend_1w_strong_long / btc_trend_1w_strong_short
  - 当前仅用于日志，不参与逻辑判断。

- 日线温和振荡器信号（当前只做标记）：
  - 基于 rsi_1d：
    - osc_rsi_long_1d：RSI <= 30（深回调多头）
    - osc_rsi_short_1d：RSI >= 70（深超买空头）
    - osc_rsi_long_mild_1d：RSI <= 45（温和偏多回调）
    - osc_rsi_short_mild_1d：RSI >= 55（温和偏空回调）
  - 聚合信号：
    - osc_long_1d / osc_short_1d：深回调 ANY
    - osc_long_mild_1d / osc_short_mild_1d：温和回调 + 其它振荡器 ANY
- 设计预期（尚未落地到入场逻辑）：
  - 当周线强趋势（btc_trend_1w_strong_* == 1）时：
    - 可以在未来版本中允许：
      - 用 osc_long_mild_1d / osc_short_mild_1d 替换或补充深振荡信号，增加顺势延伸入场机会；
      - 并配合更紧风控（更紧 SL、减仓条件等）。
  - 当周线仅一般趋势（非 strong）时：
    - 继续使用当前较严格的深振荡 + 1h 条件。
- 当前状态：
  - osc_rsi_long_mild_1d / osc_rsi_short_mild_1d / osc_long_mild_1d / osc_short_mild_1d
    已经在 5m DataFrame 中可见（*_1d_1d），但不参与任何实盘决策，只在日志中展示。

3）日志扩展用于实盘观察

- populate_entry_trend 的日志输出现包含：
  - weekly：btc_trend_1w
  - weekly_strong：btc_trend_1w_strong_long / btc_trend_1w_strong_short
  - 1h 趋势：btc_trend_1h
  - osc_any：osc_long_1d_1d / osc_short_1d_1d
  - osc_mild：osc_long_mild_1d_1d / osc_short_mild_1d_1d
  - rsi 深/温和：osc_rsi_long_1d_1d / osc_rsi_short_1d_1d / osc_rsi_long_mild_1d_1d / osc_rsi_short_mild_1d_1d
  - stoch / wr / cci 各自的长短向标记
  - break：btc_break_long_1h / btc_break_short_1h
  - 1h_patterns：
    - ema_pb：（btc_ema_pullback_long_1h, btc_ema_pullback_short_1h）
    - chan_pb：（btc_chan_pullback_long_1h, btc_chan_pullback_short_1h）
    - consol_brk：（btc_consol_break_long_1h, btc_consol_break_short_1h）
  - reversal_candidate：多空反转候选标记
  - signals：long_signal / short_signal 最终三屏信号布尔值

- 实盘观察建议：
  1. 在实际触发入场的 K 线上，统计：
     - 哪些 1h_patterns 同时为 1；
     - 在周线 strong 环境下，osc_mild 为 1 的频率如何；
  2. 在“只出现 osc_mild / 1h_patterns，但未触发三屏入场”的点：
     - 手工浏览行情，判断这些点位是否具备较好的盈亏比；
     - 作为未来扩展入场形态的候选集合。


四、Phase A：5m 微结构择时层（仅在 1h 成熟后启用）

设计原则：
- 5m 微结构择时是“锦上添花”，只在 1h 级三屏/反转已经达到“信号较多且质量中上”的前提下才启用；
- 初期以“记录与评分”为主，不直接影响入场行为。

规划思路：

1）指标来源（全部使用当前策略已有模块）：
- 5m 层面的 z-score（相对 1h/日均线偏离）；
- 5m 层面的 volume ratio / volume z-score；
- 5m / 1h 通道位置（相对布林 / Keltner / Donchian）；
- 5m K 线形态（锤头线、吞没等）。

2）构建微结构评分：micro_timing_score_5m
- 每个模块给出一个离散评分：[-2, -1, 0, +1, +2]；
- 设定权重：w_z / w_vol / w_chan / w_candle 等；
- 合成：micro_timing_score_5m = Σ(score_i × w_i)；
- 初始阶段：w_* 全部设为 0，仅记录各模块得分和总分，不影响入场。

3）未来参与决策的方式（待 1h 成熟后再落地）：
- 对三屏入场：
  - 在 long_signal / short_signal 为真时，要求 micro_timing_score_5m ≥ 某个阈值；
  - 先只过滤掉明显最差的微结构（例如追高长上影 + 放量顶）；
- 对反转入场：
  - 设置更高阈值，要求在“价位和微结构都足够极端”的情况下才真正反转入场；
- 所有逻辑通过参数开关控制，便于在回测与实盘中逐步开启。


五、Phase B：动作引擎 2.0 统一（未来阶段）

目标：
- 将当前分散在各处的“模块计数 + 权重 + 阈值 → 动作”逻辑，统一为一个 ActionEngine；
- 让 ENTRY / EXIT / SCALE-OUT / REVERSE 使用同一套评分语言。

核心思路：

1）统一输入：
- 当前方向（long / short）；
- 当前持仓状态（无仓 / 持有顺势仓 / 反转仓）；
- 各时间框架上的模块评分：
  - z-score, volume, candle, Donchian/Keltner 等；
- Regime / 波动环境：regime_zone_1d_1d / vol_regime_1h_1h。

2）统一输出动作：
- NONE / ENTRY_OK / ENTRY_DELAY；
- SCALE_OUT_TIGHT_SL / CLOSE / CLOSE_COOLDOWN / CLOSE_AND_REVERSE；
- 后续可扩展更多细分动作。

3）与现有逻辑的迁移路径：
- 第一步：将现有 _classify_exit_action 的规则映射为“评分 + 阈值”的形式；
- 第二步：让三屏 / 反转入场产出“候选动作 ENTRY_OK”，再交由 ActionEngine 根据微结构评分做二次筛选；
- 第三步：统一参数化所有模块权重，便于批量调参与对比。


六、Phase C：策略级风控覆层 2.0（未来阶段）

目标：
- 在单笔风控（动态止损、动态杠杆）之上，增加策略级别的冷却 / 熔断机制，限制连续亏损和极端 drawdown。

设计方向：

1）滚动绩效监控：
- 跟踪最近 N 笔交易的：
  - 总收益 / 平均收益；
  - 最大连续亏损；
- 跟踪当日 / 本周的累计收益。

2）冷却机制：
- 若最近 N 笔总收益低于某个阈值（例如 -X%），进入冷却模式：
  - 暂停新建仓，仅允许平仓和风险控制；
- 冷却期结束后，根据最新绩效恢复正常模式。

3）熔断机制：
- 若当日 / 本周亏损超过预设上限：
  - 触发熔断：停止所有新入场（可保留强制出场）；
  - 防止策略在错误 Regime 或技术问题下不断放大亏损。

4）实现方式（Freqtrade 框架内）：
- 使用策略内部状态（如 self.custom_info 或自建状态字典）记录绩效和模式；
- 在 populate_entry_trend / custom_entry 中统一检查当前模式（正常 / 冷却 / 熔断）；
- 在 custom_exit / custom_stoploss 里更新绩效统计。


七、当前阶段的实盘观察重点

在 Phase 0 部分落地的基础上，当前阶段实盘观察的重点包括：

1）三屏入场点附近的 1h 新形态
- 在日志中筛选 signals=(L1, S0) 或 (L0, S1) 的 K 线：
  - 统计这些入场点上：
    - ema_pb / chan_pb / consol_brk 中各自为 1 的频率；
  - 观察是否存在“某类形态更常对应优质盈亏比”的现象。

2）仅有 1h 新形态但未触发三屏的区域
- 找到 osc_any=0 但 1h_patterns 有触发的情况：
  - 手动复盘行情，判断这些点位是否存在较好的顺势或反转机会；
  - 作为未来“扩展 1h 入场形态”的候选样本池。

3）周线强趋势 + 日线温和振荡
- 在 weekly_strong 为 1 的阶段：
  - 比较 osc_any 与 osc_mild 的触发频率；
  - 评估：如果未来在强趋势阶段用 osc_mild 部分替代 osc_any，是否有望在不过度降质的前提下增加入场次数。


八、后续优化节奏建议

1）当前阶段（已开始）：
- 只观察，不改变入场行为：
  - 使用现有三屏 + 反转 + 四档动作运行实盘；
  - 通过日志和图表观察 1h 新形态和日线温和振荡的分布情况。

2）下一阶段（有一定样本后）：
- 针对观察到的“高质量场景”，将其固化为：
  - 强周趋势 + 日线温和振荡 + 某类 1h 形态 → 新的顺势入场分支；
  - 或对现有三屏条件做参数化放宽（附加风控约束）。

3）再下一阶段：
- 在有回测条件时，开始逐步接入：
  - 5m 微结构择时（Phase A）；
  - 动作引擎统一（Phase B）；
  - 策略级风控覆层（Phase C）。

上述规划文档供后续几轮迭代对照使用：
- 看每轮改动是否符合原始设计意图；
- 避免在局部优化中偏离整体框架；
- 为回测和实盘表现提供统一解释视角。
