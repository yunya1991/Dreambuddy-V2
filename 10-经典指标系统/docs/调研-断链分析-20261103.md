# 10-经典指标系统 断链调研分析

> 版本 v1.0 | 日期 2026-11-03 | 范围：代码调用链 / 模块职责 / 数据链路 / 前端契约 / 文档链接 / 部署形态
> 方法：静态引用扫描 + 运行时导入验证 + 模块测试 + 部署脚本核对 + 文档链接解析（只调研，未改动代码）

## 0. 结论摘要

1. **拆分实际是“复制式分叉”，不是 Strangler 委托**：`ml_trade_service.py`（187,255 行）仍是唯一生产单体，内部 **0 处引用 classic_pipeline、0 处调用 8093/8094/8095/8096**；M25-M28 是平行新服务，旧单体没有委托出去。
2. **classic_pipeline 是空壳**：`classic_pipeline/app.py` 注册 5 个 Blueprint，其中 4 个是 8 行空文件（0 路由），唯一有 21 条路由的 `strategy_factory/blueprint.py` **未被注册**；实测 `classic_pipeline.app` 业务路由数 = **0**。
3. **存在静默断链**：DreamOS C2 节点 `import classic_pipeline.signals.quant_signal`，但进程内无 10 目录路径注入，导入必失败并被 `except` 吞掉，长期走简化 fallback；M27 Gate 懒加载 `ml_trade_service`，PM2 以 27 目录为 cwd 且无 PYTHONPATH，回测指标固定返回 `backtest_import_failed`。
4. **前端仍有 3 处活跃调用旧 8092**（trading-mode 策略库上下文、execute 完成回调、planner chains），而云端启动脚本不启动 8092 → 云端必然降级；另有 1 个 8092 客户端 `classic-system-api.ts` 完全无人引用。
5. **数据双源 + 文档失联**：10 与 26 的 `strategy_registry.json` 当前哈希一致（迁移成功），但单体仍在写自己那份，未切单写；10 文档共 **730 条绝对路径链接全部失效**（其中当前文档 128 条，archive 602 条），`TECHNICAL_DESIGN v2.0 (2026-07-31)` 完全没有 M25-M28/拆分内容。

## 2. 断链清单

### P0-1 主服务与新模块双轨（核心根因）
- 证据：`grep "classic_pipeline" 10-经典指标系统/*.py` = 0；`grep "8093|8094|8095|8096" ml_trade_service.py` 无端口调用（唯一命中是配置值）。
- 单体仍保留 139 个策略/治理/执行相关路由与 8 个 registry 写函数。
- 后果：10 与 M26/M27 各写各的策略注册表/审批日志；Spec FR-7“单体 HTTP 委托新模块”未落地。

### P0-2 classic_pipeline 骨架不可用
- `classic_pipeline/app.py` 注册 c1/signals/backtest/risk/plan 五个 Blueprint；前四个 `blueprint.py` 均为 8 行、0 路由。
- `strategy_factory/blueprint.py` 有 21 路由、2,099 行，但未在 `app.py` 注册 → 整个 app 业务路由为 0。
- 全仓外部引用仅：10 自身 tests（6 个文件）+ DreamOS C2（路径缺失）+ 文档。
- `classic_pipeline/api/*`（quant_adapter/three_screen_adapter/universe_adapter/s1_s2_mapper）除包内自引用外 **0 外部引用**。

### P0-3 DreamOS C2 静默断链
- 位置：`1-ARCHITECTURE/dreamos/capabilities/trading/nodes/c2_signal_detect.py:176-206`
- 在仓库根目录实测 `import classic_pipeline` → `ModuleNotFoundError: No module named 'classic_pipeline'`（包位于 `10-经典指标系统/` 下，未安装、未注入路径）。
- `except Exception: return None` 吞掉错误 → C2 永远使用简化 trend/rsi 逻辑，Spec FR-24“C2 复用真实信号纯函数”实际未生效。

### P0-4 M27 Gate 回测指标断链
- 位置：`27-策略治理审批系统/governance/gate/evaluator.py:59-67`，懒加载 `from ml_trade_service import ...`。
- 部署：`31-分布式计算部署/phase2/05-deploy-classic-modules.sh` 使用 `pm2 --cwd <module_dir>`，无 `PYTHONPATH=10-经典指标系统`。
- 后果：导入失败被捕获 → `_backtest_report_from_zip` 固定返回 `{"ok": false, "error": "backtest_import_failed"}`，Gate 无法使用真实 pf/dd/trades/winrate。

### P0-5 前端 8092 残留 vs 云端未部署
- 活跃调用：
  - `3.1-FRONTEND/src/lib/trading-mode.ts:103` → `classic-system-client.ts` → 8092（classic 模式策略库上下文）
  - `3.1-FRONTEND/src/lib/strategy/steps/execute.ts:618` → `classic-system-hooks.ts` → 8092（策略执行完成回调）
  - `3.1-FRONTEND/src/lib/planner/chains-registry.ts:30` → 8092（Planner 五条链，均带 fallback 文案）
- 死代码：`3.1-FRONTEND/src/lib/classic-system-api.ts` 0 处引用。
- 部署证据：`37-一键启动脚本/start-cloud-all.sh` 无 8092/10 单体；`status-cloud.sh` 端口清单不含 8092。

### P1-1 新模块间代码级耦合（绕过 HTTP 契约）
- `26-策略管理模块/app.py:49,399,425`：`sys.path` 注入 M25，直接 import `strategy_gen.backtest_engine` / `paramopt`。
- `28-策略信号触发模块/app.py:371-424`：同样注入 M25，直接 import `strategy_gen.backtest_engine`（show_trades/download_data/plot_profit）。
- `27-策略治理审批系统/governance/changeset/builder.py:43-48`：直接 import 26 的 `strategy_lib.services.registry`。
- 理由（代码注释）是“代理回测/参数优化”，但代价是：任一模块单独部署/升级都会牵动其他模块进程，违背 Spec AC-9 的模块独立性精神。

### P1-2 数据双源与迁移未收口
- `10/user_data/strategy_registry.json` 与 `26/data/registry/strategy_registry.json` SHA256 **完全一致**（说明复制迁移成功），但 mtime 分别为 10-04、10-02；10 单体仍有 8 个写函数，未来会分叉。
- 审批/审计未对齐：10 `approvals.jsonl` 9 行、`audit_actions.jsonl` 37 行；27 `outbox/prod` 1+4 行、`outbox/explore` 2+11 行。
- Spec FR-6 要求的“原位置软链 30 天 + 双写验证 + 切单写”未见落地痕迹。
- M25/M26/M28 仍硬编码 `_CLASSIC_ROOT = .../10-经典指标系统`，共享其 `user_data/strategies` 与行情数据 → **10 无法下线**。

### P1-3 模块职责复制/漂移
- 26 registry（与 10 registry 函数名完全一致，仅多 3 个本地路径辅助函数）＝整体复制。

- 两份 `carry_service.py`（10 与 9-基本面分析）哈希不同，属并行演化副本。

- 失效原因：链接指向旧工程路径 `/Users/zhangjiangtao/ft_userdata/经典指标机器学习系统/{技术文档规范.md, 交易AI Agent 技术文档2.0.md, 技术文档.md}`，该目录现存仅 `models/ user_data/ user_data_prod/`，目标文件全部缺失；`absolute_ok = 0`。

## 4. 建议处理顺序（仅建议，待决策后实施）

**P0（先止血）**
1. 决策 10 单体的最终定位：A) 上云继续承载 8092；B) 本地保留、云端仅 M25-28；C) 整体退役。此决策决定后面所有清理边界。
2. 修 M27 Gate：把回测指标来源改为 M25 的回测产物/HTTP 接口，或给 M27 部署补 `PYTHONPATH=10-经典指标系统`（推荐前者，彻底解耦）。
3. 前端 3 处 8092 活跃调用改为 M25-M28 对应接口；删除未使用的 `classic-system-api.ts`；Planner 明确 fallback 策略。
4. DreamOS 增加统一路径 bootstrap（或把 signals/indicators 抽为独立可安装包），修 C2 静默断链。

**P1（收口架构）**
5. 确定数据唯一写入方：10 侧策略注册表/审批/审计停写或委托；完成 approvals/audit 差异核对与迁移，再删旧副本。
6. 清理 `classic_pipeline` 已迁出部分（strategy_factory/c1_universe/backtest/api/空壳 blueprint/app.py）；保留 signals/indicators 需先有真实消费方。
7. 新模块解耦：26→25、28→25、27→26 的直接 import 改 HTTP 或抽共享库；26/27 补 tests。

**P2（文档与契约）**
8. 批量修复 730 条绝对链接（当前 128 条优先；archive 602 条可统一改纯文本/归档说明）；更新 `TECHNICAL_DESIGN`/`API_SPEC`/一页式操作手册，补 M25-M28 现状、端口表、10 单体定位。
9. 统一端口契约（Spec 修正 M28=8096），并在 ENGINEERING_INDEX 标注 classic_pipeline 真实状态（空壳/待清理）。
