# 数据资产治理与硬盘应用 SPEC

- 版本：v1.0
- 日期：2026-10-17
- 状态：待实施
- 负责推进目录：38-数据库管理系统

## 1. 背景与目标

对全系统数据资产（数据中心、广义认知、前端应用训练、语义训练、交易数据等）完成盘点后，制定治理方案。目标：

1. 清理冗余备份，回收磁盘空间
2. 控制日志无限增长
3. 为持续增长的认知库建立冷归档机制
4. 治理基因演化数据
5. 建立统一冷数据归档区，与代码目录分离

## 2. 盘点结论（2026-10-17 实测）

- 磁盘 178G 用 31G（19%），空闲 140G，无容量压力
- 真实业务数据约 4.5G；依赖包 2.2G；环境 3.7G；冗余备份约 766M
- 增长最快：L4 案例库（已有 60 天自动归档）、cognitive_memory.db（157M，无归档机制）
- 可立即回收：PG 迁移备份 507M + sync-snapshots 冗余快照 175M + DAL 历史备份 84M

## 3. 实施方案

### 阶段 1：冗余备份清理（回收约 766M）
- 删除 38-数据库管理系统/archive/data_center.db.bak-20261017（507M，PG 已稳定运行，数据已完整迁移并验证）
- 清理 /home/luke/sync-snapshots/ 中的旧快照（保留最新一份）
- 清理 19-数据访问层/data/backups 中超过 30 天的历史备份
- 执行前逐项确认清单，删除后验证各系统运行正常

### 阶段 2：日志轮转
- 为 /home/luke/logs/yijing（174M，最大）配置 logrotate 策略：按周轮转、保留 8 份、zstd 压缩
- 其余日志目录（cognitive/datacenter/training 等）统一纳入轮转策略

### 阶段 3：认知库冷记忆归档
- 为 4-MEMORY/data/cognitive_memory.db 增加归档机制：90 天前的记忆导出为压缩归档
- 复用每日 4:30 自动归档框架（auto_archive_cold_data.sh 增加 Part 3）
- 归档前校验行数一致，不通过则中止

### 阶段 4：基因数据治理
- 盘点 gene_data（759M）的代际结构，评估淘汰代际的压缩归档
- 本阶段先调查后实施，不盲目删除

### 阶段 5：统一归档区（长期）
- 冷数据归档统一集中于 38-数据库管理系统/archive/
- 后续新系统的冷数据归档均遵循此约定

## 4. 风险与约束

- 删除备份前确认 PG 迁移稳定（已运行 3 小时+，回填链路验证通过）
- 认知库归档操作前备份数据库文件
- 日志轮转不影响正在写入的进程（copytruncate 模式）
- 基因数据治理需先理解演化系统的读取逻辑，避免删除在用数据

## 5. 验收标准

- 磁盘回收 ≥ 700M
- 日志目录大小受轮转策略控制
- 认知库归档机制上线且每日自动执行
- 各系统（采集、回填、认知守护、交易）运行正常
