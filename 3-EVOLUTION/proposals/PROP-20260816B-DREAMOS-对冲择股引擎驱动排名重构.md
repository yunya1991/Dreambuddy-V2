## 一、背景与问题

PROP-20260816 上线后实证核查（真实 Hyperliquid 行情复测）发现**择股选择权错位**——当前设计由周报池排名预选 top1，易经引擎仅做准入盖章：

| # | 问题 | 实证 |
|---|---|---|
| 1 | 引擎只见1个币，无比较无从择优 | 长腿=long_merged[0]、短腿=short_merged[0]，各跑1次 |
| 2 | 无行情数据的币照选不误 | 空池top1 KPEPE 行情拉取失败 → degenerate conf 0.2975（全默认值） |
| 3 | 0.62 门禁实证不可达 | ACE 24h **-24.5%** 极端空头仅 conf 0.5272；强多头 NIL +6.7% 仅 0.5704，双双被拒 → 对冲对永远开不了仓 |
| 4 | 周报静态分压过引擎实时判断 | merged=0.7×weekly+0.3×dyn 决定选谁，引擎沦为验证器 |

**conf 语义核查结论**（用户质疑验证）：conf 是方向无关的信号清晰度（base×变爻罚×trend×一致性），**不是**多头维度分数，不存在"越低空头越强"的反转；但 capital_flow/sentiment 两维钉死中性 0.5，对空头信号有系统性稀释。低 conf 是真弱，门禁标定也是真错。

## 二、用户确认的设计方向（2026-08-16）

> "信号应该由易经推理引擎推导，然后按排名选择最优才对"

**参数确认**：
1. 候选范围：多池/空池各 **Top8**
2. 分工：**大模型取前八**（周报池 hermes-weekly 已是大模型排序产出，切 Top8 即粗选，无需新增 LLM 调用），**剩下按引擎排名**（引擎对8候选逐个推导信号，按 conf 择优）

## 三、设计（Z链）

### 核心翻转

```
现状: 周报排名 → 取top1 → 引擎盖章(验证1个)
重构: 周报切Top8(粗选) → 引擎逐个推导 → 按引擎conf排名 → 择优(精选)
```

周报降级为**候选供给**（圈定谁值得看），排名权交还引擎。

### 模块1：候选供给（大模型粗选）

- `long_cands = long_pool[:8]`（周报已排序）
- `short_cands = short_pool[:8]`

### 模块2：引擎推导

- **长腿**：V15 路径已对多池 top6 跑过引擎（results 复用），仅对第7-8位补跑
- **短腿**：对8个空头候选逐个 `enrich_market_data + orch.run_cycle`（新增≤8次）
- **数据可用性预检**：`close_price ≤ 0`（行情拉取失败）的候选自动淘汰，不参与排名 ← 根治 KPEPE 类问题
- 引擎为纯本地计算（无 LLM/无外部调用），新增成本 = 每周期≤10次行情拉取，有界

### 模块3：排名择优（scheduler 对冲路径）

- `best_long` = long_cands 中 direction=LONG 且 conf 最高者
- `best_short` = short_cands 中 direction=SHORT 且 conf 最高者
- 任一腿无方向匹配候选 → 本周期跳过对冲入场（宁缺毋滥，与现行为一致）
- 排名指标：**纯引擎 conf**（不设周报分 tiebreaker，彻底贯彻引擎说了算）

### 模块4：门禁重标定

- `MIN_LEG_CONF`: 0.62 → **0.45**
  - 实证依据：极端空头 0.5272 / 强多头 0.5704 应可过；XMR 类横盘噪音 0.0796 仍被滤除
  - 相对择优为主选机制，绝对底线仅作安全网
- 其余全部继承 PROP-20260816 不动：regime=RANGE_BOUND 门禁、每腿150U、1:1、合并+4%TP/-6%熔断、孤儿腿保护、并发上限1对

### 模块5：动态分回写扩展

- 8+8 候选的引擎结果全部 `record_dynamic_score` 回写（原仅回写被选中的1+1）
- 运行时动态层数据密度提升，为后续周报融合提供更厚依据

## 四、代码变更点

| 文件 | 变更 |
|---|---|
| `cli/scheduler.py` 对冲路径 | top1→Top8 候选循环；短腿补跑8次引擎；数据预检；排名择优函数；动态分回写扩展 |
| `capabilities/trading/hedge_executor.py` | MIN_LEG_CONF 0.62→0.45（一行）；evaluate_entry 契约不变（scheduler 传入已择优的 best 对） |
| 测试 | 更新 conf 门禁用例；新增：多候选择优/方向过滤/无数据淘汰/无候选跳过 |

**职责划分不变**：scheduler 负责候选循环+引擎调用+择优，HedgeExecutor 负责门禁+开平仓。

## 五、风险与缓解

| 风险 | 缓解 |
|---|---|
| 0.45 底线可能放进中等信号 | 相对择优已选最强；-6% 熔断兜底；paper 期观察胜率 |
| 行情拉取成本增加（≤10次/周期） | 有界；失败候选直接淘汰不阻塞 |
| 短腿候选方向全为 LONG（无匹配） | 跳过本周期，宁缺毋滥（与现行为一致） |

## 六、验收标准

2. 全回归绿（含 V15 存量用例）
3. 生产完整性：V15 路径行为逐字节不变（scheduler_data md5 核验）
4. paper 观察：对冲对入场率从 0（永不可达）恢复为正常水平
