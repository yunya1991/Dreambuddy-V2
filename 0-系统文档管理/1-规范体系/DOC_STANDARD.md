# DreamBuddy-V2 文档编写规范

> **版本**: v2.0 | **更新日期**: 2026-07-25

> **权威性**: 所有子系统文档必须遵循本规范
> **迁移自**: PROJECT_DOC_STANDARD.md v1.1（根目录保留重定向链接）
> **参照标杆**: [14-V15经典马丁策略/docs/](../../14-V15经典马丁策略/docs/)

## 1. 目标与范围

本规范用于统一 DreamBuddy-V2 各子系统的文档体系，覆盖：

- **文档目录结构**：每个子系统必须建立的 docs/ 目录结构
- **文档类型与模板**：各类型文档的标准章节与格式（模板见 [TEMPLATES/](./TEMPLATES/)）
- **文件级索引规范**：ENGINEERING_INDEX.md 的文件级索引标准
- **变更维护流程**：文档与代码同步更新的规则

### 1.1 不覆盖

- 交易系统生产侧行为边界：以各子系统 TECHNICAL_DESIGN.md 为准
- Skills 能力契约规范：以 10-经典指标系统/skills/SKILLS_技术文档规范.md 为准
- 运营闭环规范：以 10-经典指标系统/系统运营技术文档.md 为准

### 1.2 文档分类

详见 [DOC_CLASSIFICATION.md](./DOC_CLASSIFICATION.md)。本规范主要约束 L2 子系统级文档。

## 2. 文档目录结构（强制）

每个子系统必须包含以下目录结构：

```
NN-系统名称/
├── docs/                        # 文档目录（强制）
│   ├── ENGINEERING_INDEX.md     # 工程索引（强制）
│   ├── TECHNICAL_DESIGN.md      # 技术设计文档（强制）
│   ├── API_SPEC.md              # 接口规格文档（有对外接口时强制）
│   └── CHANGELOG.md             # 变更日志（强制）
├── README.md                    # 用户文档（强制）
├── core/ 或 src/                # 核心代码
├── lib/ 或 utils/               # 工具层
├── config/                      # 配置文件（如有）
├── tests/                       # 测试套件
└── data/                        # 数据目录（如有）
```

### 2.1 目录约束

- `docs/` 下文件必须使用大写+下划线命名（如 `ENGINEERING_INDEX.md`）
- 根目录的 `README.md` 面向用户，`docs/` 下的文档面向开发者
- 已有成熟文档的子系统（如10-经典指标系统）可保留原有文档结构，但应补充 `docs/ENGINEERING_INDEX.md` 作为文件级索引入口
- **禁止**在 `docs/` 外放置技术文档（如 `技术文档2.0.md` 应迁移到 `docs/TECHNICAL_DESIGN.md` 或建立软链接）

## 3. 文档类型与模板

> 所有模板位于 [TEMPLATES/](./TEMPLATES/) 目录，新增文档必须从模板开始。

### 3.1 ENGINEERING_INDEX.md（工程索引）

**定位**：子系统的文件级工程索引，是开发者进入子系统的第一个入口。

**模板**: [ENGINEERING_INDEX_TEMPLATE.md](./TEMPLATES/ENGINEERING_INDEX_TEMPLATE.md)

**必须包含的章节**：
1. 模块定位（属性表）
2. 目录地图（完整目录树）
3. 文件清单与职责（按层分组，含函数数和关键函数）
4. 核心流程索引（每步标注对应函数和文件）
5. 配置参数索引（含加载优先级）
6. 测试体系
7. 技术债务
8. 快速导航

### 3.2 TECHNICAL_DESIGN.md（技术设计文档）

**定位**：子系统的技术架构设计，面向开发者理解系统内部实现。

**模板**: [TECHNICAL_DESIGN_TEMPLATE.md](./TEMPLATES/TECHNICAL_DESIGN_TEMPLATE.md)

**必须包含的章节**：
1. 概述 — 系统定位、设计目标
2. 架构设计 — 分层架构图、模块关系
3. 核心算法 — 关键算法说明（含公式、伪代码）
4. 数据流 — 输入→处理→输出的完整链路
5. 接口设计 — 内部接口和对外接口
6. 状态管理 — 状态文件、状态机
7. 配置管理 — 配置项说明
8. 错误处理 — 异常场景与处理策略
9. 扩展性设计 — 如何添加新功能

### 3.3 API_SPEC.md（接口规格文档）

**定位**：子系统的对外接口规格，有 HTTP/RPC/CLI 接口时必须提供。

**模板**: [API_SPEC_TEMPLATE.md](./TEMPLATES/API_SPEC_TEMPLATE.md)

**必须包含的章节**：
1. 接口概览 — 接口列表
2. 认证方式 — 鉴权说明
3. 接口详情 — 每个接口的请求/响应格式
4. 错误码 — 错误码定义
5. 版本管理 — 接口版本策略

### 3.4 README.md（用户文档）

**定位**：面向使用者的快速上手文档。

**模板**: [README_TEMPLATE.md](./TEMPLATES/README_TEMPLATE.md)

**必须包含的章节**：
1. 概述 — 一句话描述系统
2. 目录结构 — 简要目录树
3. 快速开始 — 安装、配置、运行步骤
4. 核心功能 — 功能列表
5. 配置说明 — 关键配置项
6. 测试 — 测试命令
7. FAQ — 常见问题

### 3.5 CHANGELOG.md（变更日志）

**定位**：记录每次变更的原因、内容、验证方式。

**模板**: [CHANGELOG_TEMPLATE.md](./TEMPLATES/CHANGELOG_TEMPLATE.md)

**格式**：

```markdown
## [vX.X] - YYYY-MM-DD

### 变更类型（新增/修改/修复/删除）
- **变更内容**: 具体描述
- **影响范围**: 哪些文件/功能受影响
- **验证方式**: 如何验证
- **回滚策略**: 如何回滚
```

## 4. 文件级索引规范

### 4.1 文件清单格式

每个文件必须标注：

| 字段 | 说明 | 示例 |
|------|------|------|
| 文件 | 相对路径 | `core/v15_signal.py` |
| 函数数 | 主要函数数量 | `~25` |
| 职责 | 一句话描述 | 信号引擎：16项指标+16层决策 |
| 关键函数 | 核心函数名列表 | `v15_decision()`, `calc_fibonacci()` |

### 4.2 入口锚点规范

入口索引必须使用 `文件路径 → 函数/路由名` 格式：

```
V15信号生成: `14-V15经典马丁策略/core/v15_signal.py` → `v15_decision()`
经典指标决策: `10-经典指标系统/ml_trade_service.py` → `_decision_entry_impl()`
```

### 4.3 配置索引规范

配置文件必须标注加载优先级和关键参数：

```
config/.env.common (全局公共)
    ↓ 覆盖
config/.env.v15 (V15专属)
    ↓ 覆盖
代码默认值
```

## 5. 变更维护流程

### 5.1 文档同步规则

| 变更类型 | 必须更新的文档 |
|----------|----------------|
| 新增文件 | ENGINEERING_INDEX.md 文件清单 |
| 新增/修改函数 | ENGINEERING_INDEX.md 关键函数列 |
| 新增/修改配置项 | ENGINEERING_INDEX.md 配置参数索引 |
| 架构变更 | TECHNICAL_DESIGN.md |
| 接口变更 | API_SPEC.md |
| 任何变更 | CHANGELOG.md |

### 5.2 变更检查清单

每次变更后必须检查：

- [ ] ENGINEERING_INDEX.md 文件清单是否更新
- [ ] ENGINEERING_INDEX.md 关键函数是否更新
- [ ] CHANGELOG.md 是否追加变更记录
- [ ] 如有架构变更，TECHNICAL_DESIGN.md 是否更新
- [ ] 如有接口变更，API_SPEC.md 是否更新
- [ ] 顶层 [INDEX.md](../INDEX.md) 是否需要同步更新

## 6. 文档质量标准

### 6.1 必须做到

- 每个文件都有对应的职责描述
- 每个关键函数都有函数名列示
- 配置文件标注加载优先级
- 流程索引标注每步对应的函数和文件
- 变更日志记录每次变更的原因和验证方式

### 6.2 禁止出现

- 文件清单缺少函数数或关键函数
- 配置参数缺少默认值说明
- 流程描述缺少文件锚点
- 变更日志缺少回滚策略
- 文档内容与代码不一致
