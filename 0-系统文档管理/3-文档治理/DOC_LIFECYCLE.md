## 1. 生命周期阶段

文档生命周期分为 5 个阶段：

```
创建 → 评审 → 发布 → 维护 → 归档
  ↑                              │
  └──────── 重启（归档文档重新激活）┘
```

### 1.1 创建阶段

**触发**：新子系统/新模块/新功能开发

**流程**：
1. 从 [TEMPLATES/](../1-规范体系/TEMPLATES/) 选择对应模板
2. 填充内容，遵循 [DOC_STANDARD.md](../1-规范体系/DOC_STANDARD.md) 规范
3. 标注版本号 v1.0 和创建日期
4. 更新 [INDEX.md](../INDEX.md) 添加新文档索引

**检查清单**：
- [ ] 使用了正确的模板
- [ ] 文档头部标注版本和日期
- [ ] 文件命名符合 [DOC_CLASSIFICATION.md](../1-规范体系/DOC_CLASSIFICATION.md) §3
- [ ] 已更新 INDEX.md

### 1.2 评审阶段

**触发**：文档创建后、重大修订后

**评审要点**：
- 内容准确性：是否与代码一致
- 规范符合性：是否符合 DOC_STANDARD
- 完整性：必须章节是否齐全
- 可读性：结构是否清晰

**评审方式**：
- L0/L1 文档：需技术负责人评审
- L2 文档：子系统负责人评审
- L3 文档：创建者自审

### 1.3 发布阶段

**触发**：评审通过

**发布动作**：
1. 文档版本号确定（如 v1.0）
2. 更新 CHANGELOG.md（如果是子系统文档）
3. 更新 [INDEX.md](../INDEX.md) 版本号
4. 更新 [RELEASE_NOTES.md](./RELEASE_NOTES.md)（如果是 L0 文档）

### 1.4 维护阶段

**触发**：代码变更、功能迭代

**维护规则**（见 [DOC_STANDARD.md](../1-规范体系/DOC_STANDARD.md) §5）：

| 变更类型 | 必须更新的文档 |
|----------|----------------|
| 新增文件 | ENGINEERING_INDEX.md |
| 修改函数 | ENGINEERING_INDEX.md + API_SPEC.md |
| 架构变更 | TECHNICAL_DESIGN.md |
| 任何变更 | CHANGELOG.md |

**版本递增规则**：
- 内容增补/修订：次版本号 +1（如 v1.0 → v1.1）
- 重大结构变更：主版本号 +1（如 v1.0 → v2.0）

### 1.5 归档阶段

**触发**：文档不再活跃使用（如子系统废弃、文档被新版本完全替代）

**归档动作**：
1. 在文档头部添加 `> ⚠️ 已归档` 标记
2. 移动到 `docs/archive/` 目录（如有）
3. 在 [INDEX.md](../INDEX.md) 中标注"已归档"
4. 在 [DOC_DEBT_INDEX.md](./DOC_DEBT_INDEX.md) 中记录归档原因

**归档不等于删除**：归档文档仍可访问，但不再维护。

## 2. 文档状态定义

| 状态 | 标记 | 说明 |
|------|------|------|
| 草稿 | 📝 草稿 | 创建中，未评审 |
| 活跃 | ✅ 活跃 | 已发布，正常维护 |
| 过时 | ⚠️ 过时 | 内容与代码不符，待更新 |
| 归档 | 📦 已归档 | 不再维护，仅保留历史 |
| 废弃 | ❌ 已废弃 | 内容错误，不应再参考 |

## 3. 定期审计

### 3.1 月度审计

每月最后一周执行：
1. 扫描所有 L2 子系统文档版本号
2. 对比代码变更记录，识别"文档过时"项
3. 更新 [DOC_DEBT_INDEX.md](./DOC_DEBT_INDEX.md)
4. 生成审计报告

### 3.2 季度审计

每季度末执行：
1. 评估 L3 辅助模块是否需要升级为 L2（补全 5 文档）
2. 评估 L2 子系统文档是否需要重大修订
3. 清理已归档文档（超过 1 年的归档文档可考虑删除）
4. 更新 [INDEX.md](../INDEX.md) 覆盖率统计

---

## 4. 文档与代码同步原则

### 4.1 同 PR 原则

文档变更与代码变更**必须在同一个 PR/Commit** 中完成。

**禁止**：
- 先合并代码，后补文档
- 文档变更单独 PR（纯文档修正除外）

### 4.2 检查清单

每次代码变更合并前必须确认：

- [ ] 新增文件已加入 ENGINEERING_INDEX.md
- [ ] 修改的函数签名已更新到 API_SPEC.md
- [ ] 架构变更已反映到 TECHNICAL_DESIGN.md
- [ ] CHANGELOG.md 已追加变更记录
- [ ] [INDEX.md](../INDEX.md) 版本号已同步（如需要）

---

## 5. 异常处理

### 5.1 文档与代码不一致

**发现方式**：
- 文档-代码对齐检查（如 S1 阶段 Step3）
- 用户/AI 反馈
- 月度审计

**处理流程**：
1. 记录到 [DOC_DEBT_INDEX.md](./DOC_DEBT_INDEX.md)
2. 评估优先级（P1/P2/P3）
3. 纳入最近迭代偿还

### 5.2 文档丢失

**处理**：
1. 从 git 历史恢复（如有）
2. 无法恢复则重新编写，标注 v1.0
3. 记录丢失原因到 DOC_DEBT_INDEX.md
