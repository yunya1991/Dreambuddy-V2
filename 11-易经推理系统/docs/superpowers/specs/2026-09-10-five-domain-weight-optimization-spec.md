## 1. 目标与范围

### 1.1 背景

战略层（FiveDomainScorer）当前所有权重与阈值均为设计值硬编码：

- 五域权重（WEIGHTS_BY_CLASS）：按资产类硬编码，无 IC 检验
- 子指标权重：道/天/地三等权，将/法固定比例
- boost 系数：26 项 delta 系数为经验值
- 决策阈值：war_state 75/60/50、cap 85/75/60、维度否决 40

**问题**：无因子有效性检验、无回测验证、无 Walk-forward 稳定性测试，权重是否合理未知。

### 1.2 目标

通过数据驱动的方法优化战略层权重体系，使 war_state / cap 决策与市场真实收益相关性提升，同时满足：

- **主目标**：Walk-forward Sharpe 提升 ≥ 0.2（相对等权基线）
- **约束**：最大回撤不恶化 > 5%、参数扰动±10%后 Sharpe 变化 ≤ 20%

### 1.3 范围（In Scope）

| 层级 | 内容 | 是否优化 |
|---|---|---|
| L1 五域权重 | dao/tian/di/jiang/fa 各维度权重 | ✅ Phase 2 |
| L2 子指标权重 | 各维度内部 5 子指标权重 | ✅ Phase 3 |
| L3 boost 系数 | 26 项 delta 系数 | ✅ Phase 5（最后） |
| L4 决策阈值 | war_state / cap / 维度否决阈值 | ✅ Phase 4 |
| 子指标计算逻辑 | 各子指标的计算公式 | ❌ 不在本期 |
| 数据源 | 采集与清洗 | ❌ 不在本期 |

### 1.4 不在范围（Out of Scope）

- 子指标公式重写（如道维度央行政策方向的映射函数）
- 新增/删除子指标
- 数据源采集与清洗优化
- BCRM2.0 / BDSM / 自进化系统的参数优化

## 3. 目标函数设计

### 3.1 收益归因

战略层输出 `war_state` + `cap`，不是直接交易信号。收益归因方式：

```
每日收益 = f(war_state_t, cap_t, 资产收益_t)

war_state 映射：
- ALLOW     → 持有资产，仓位 = cap_t
- COOLDOWN  → 持有资产，仓位 = cap_t × 0.5
- 轻仓防守   → 持有资产，仓位 = cap_t × 0.3
- FREEZE    → 空仓，仓位 = 0

资产选择（每类）：
- crypto_usdt    → BTC
- us_stock       → SPY
- precious_metal → GLD
```

### 3.2 目标函数

```
objective = Sharpe - λ_MDD × max_drawdown + λ_WR × win_rate

其中：
- Sharpe = mean(daily_return) / std(daily_return) × sqrt(365)
- max_drawdown = 最大回撤（绝对值）
- win_rate = 日收益 > 0 的比例
- λ_MDD = 0.5（回撤惩罚系数）
- λ_WR = 0.1（胜率奖励系数）
```

### 3.3 约束条件（硬约束，违反则参数组合无效）

| 约束 | 阈值 |
|---|---|
| Walk-forward Sharpe | > 等权基线 Sharpe |
| 最大回撤 | ≤ 基线最大回撤 × 1.05 |
| 参数扰动±10%后 Sharpe 变化 | ≤ 20% |
| 单维度 IC_IR | > 0.3（否则该维度不参与优化） |

## 4. 防过拟合约束

### 4.1 Walk-forward 验证

| 参数 | 值 |
|---|---|
| 训练窗口 | 180 天 |
| 验证窗口 | 30 天 |
| 滚动步长 | 30 天 |
| 最小折数 | 5 折 |
| 目标函数 | 各折 Sharpe 的均值（非单折最优） |

### 4.2 参数稳定性门禁（Sobol' 三档）

复用认知库硬约束（VM-1788449688790）：

| 门禁 | 条件 | 结果 |
|---|---|---|
| S（灵敏度） | Sobol' 主效应 S ≥ 0.6 | 🔴 该参数过于敏感，需缩小范围 |
| OAT（单参数扰动） | 单参数±10%导致指标变化 > 25% | 🔴 参数不稳定，需固定 |
| S ≤ 0.02 | 主效应 ≤ 0.02 | 🟡 参数无影响，可固定为默认值 |

### 4.3 IC 显著性检验

| 检验项 | 阈值 | 不达标处理 |
|---|---|---|
| 子指标 RankIC \|IC\| | > 0.03 | 权重降为等权保底（0.2 × 等权） |
| 子指标 IC_IR | > 0.5 | 权重降为等权保底 |
| 维度整体 IC | > 0.02 | 该维度权重固定为默认值 |

### 4.4 样本量要求

| Phase | 最小样本量 | 不足时处理 |
|---|---|---|
| Phase 1 IC 检验 | 250 交易日 | 仅做描述性统计，不优化 |
| Phase 2 权重优化 | 500 交易日 | 缩小参数空间（只优化 L1） |
| Phase 3-5 | 1000 交易日 | 暂缓 |

## 6. Phase 划分与里程碑

### Phase 1：因子 IC 检验（零参数风险）

**目标**：检验 5 维度 25 子指标的预测能力

**入口条件**：历史数据 ≥ 250 交易日

**出口条件**：
- 输出 IC 报告：每个子指标的 RankIC、IC_IR、显著性
- 标注有效指标（\|IC\|>0.03 且 IC_IR>0.5）和无效指标

**交付物**：`five_domain_ic_report.csv`

**风险**：无（只读取不修改）

---

### Phase 2：五域权重优化（Optuna 贝叶斯）

**目标**：在子指标等权前提下，优化 L1 五域权重

**入口条件**：Phase 1 完成，且至少 3 个维度 IC 显著

**做法**：
- 参数空间：15 个权重（约束 sum=1）
- 目标函数：Walk-forward Sharpe（5 折）
- 优化器：Optuna TPE，n_trials=200
- 约束：Sobol' 三档门禁

**出口条件**：
- Walk-forward Sharpe ≥ 基线 + 0.2
- 参数扰动±10%后 Sharpe 变化 ≤ 20%
- 最大回撤 ≤ 基线 × 1.05

**交付物**：最优权重 JSON + Walk-forward 报告

**风险**：中（15 参数，需足够样本）

---

### Phase 3：子指标权重优化（IC 加权）

**目标**：基于 Phase 1 的 IC 结果，优化 L2 子指标权重

**入口条件**：Phase 2 完成

**做法**：
- 子指标权重 = IC_IR / ΣIC_IR（IC 不显著的指标权重 = 0.2 × 等权保底）
- 不使用 Optuna（IC_IR 是确定性计算）
- 用 Walk-forward 验证 IC 加权 vs 等权

**出口条件**：
- IC 加权 Walk-forward Sharpe ≥ Phase 2 结果
- 无效指标权重 ≤ 等权保底

**交付物**：子指标权重表

**风险**：低（IC_IR 确定性，无非线性优化）

---

### Phase 4：决策阈值优化（分位数校准）

**目标**：用历史 total_score 分位数校准 L4 阈值

**入口条件**：Phase 3 完成

**做法**：
- war_state 阈值 = 历史 total_score 的 75%/50%/25% 分位数
- cap 阈值类似
- 维度否决阈值 = 历史各维度 score 的 25% 分位数

**出口条件**：
- 分位数校准后 war_state 分布合理（FREEZE 占比 20-30%）
- Walk-forward Sharpe ≥ Phase 3 结果

**交付物**：校准后阈值表

**风险**：低

---

### Phase 5：boost 系数微调（最后做）

**目标**：在权重和阈值确定后，微调 L3 boost 系数

**入口条件**：Phase 4 完成，且样本 ≥ 1000 交易日

**做法**：
- 仅优化 Phase 1 中 IC 显著的 boost 项
- 系数范围 [-0.10, +0.10]
- Optuna TPE，n_trials=100
- 约束：参数扰动±10%后 Sharpe 变化 ≤ 15%

**出口条件**：
- Walk-forward Sharpe ≥ Phase 4 + 0.1
- 不显著 boost 项系数固定为 0

**交付物**：boost 系数表

**风险**：高（26 参数，易过拟合，需足够样本）

## 7. 验收与回滚

### 7.1 上线前验收清单

| 项 | 标准 |
|---|---|
| Walk-forward Sharpe | ≥ 基线 + 0.2 |
| 最大回撤 | ≤ 基线 × 1.05 |
| 参数稳定性 | Sobol' S < 0.6 且 OAT < 25% |
| IC 显著性 | 优化维度 IC_IR > 0.5 |
| 测试集表现 | Sharpe ≥ 验证集 Sharpe × 0.8 |
| 回测-实盘一致性 | Shadow 30 天 war_state 一致率 ≥ 80% |

### 7.2 Shadow 观察期

- 优化后权重先以 Shadow 模式运行 30 天
- 对比优化前后 war_state / cap 的差异
- 记录优化后决策与实盘收益的相关性

### 7.3 回滚触发条件

| 条件 | 动作 |
|---|---|
| Shadow 期 Sharpe < 基线 - 0.3 | 自动回滚到默认权重 |
| 实盘注入后 7 日最大回撤 > 基线 × 1.2 | 人工审核 + 回滚 |
| 参数扰动后 Sharpe 变化 > 30% | 回滚 + 重新 Phase 1 |

### 7.4 版本管理

- 所有权重写入 `config/default_weights.py`（已有唯一权威源）
- `WEIGHTS_VERSION` 语义化升级（如 `1.0-MVP` → `1.1-optuna-v1`）
- 每次权重修改必经 PR + Sobol' 门禁验证

## 8. 风险清单

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 样本量不足（<500交易日） | 高 | 高 | Phase 2 只优化 L1，Phase 3-5 暂缓 |
| 过拟合 | 中 | 高 | Walk-forward + Sobol' 门禁 + IC 保底 |
| 战略层非直接交易信号 | 中 | 中 | 收益归因近似，目标函数噪声大 |
| 数据源时间短 | 高 | 中 | Phase 1 先确认数据覆盖范围 |
| 优化结果与设计意图冲突 | 低 | 低 | 保留设计权重作为 fallback |
