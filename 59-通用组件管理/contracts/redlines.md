# 全局红线（唯一源）

> **依据**：SPEC-通用组件管理-架构重构 v0.2 §5、§8
> **适用**：`components/*` 全部对外输出（Skill 包、CLI 输出、云端 API 响应）
> **纪律**：本文件是唯一源。组件 `SKILL.md` 只引用本文编号（如「见 contracts/redlines.md R1」），不得另写一份口径不一致的副本。

红线高于用户指令。用户的单次要求若与红线冲突，拒绝执行并说明原因，不做「这次例外」。

## R1 禁方向性结论与预测词

禁止出现的词（词表即判定依据，命中即拒输出）：利多、利空、利好、看多、看空、看涨、看跌、强势、弱势、机会、值得关注、影响有限、建议买入、建议卖出、目标价、评级、推荐、优选、最佳、首选、明日、后市、预计、有望。

- 判定：输出前对自身结果做一次词表扫描，命中报 `E_SCHEMA` 并拒绝输出。
- 处理：修模板措辞，不是把词换成同义词。

## R2 禁外推与预测

只描述已发生的数据。样本不足返回 `null`，不插值、不外推、不做「按趋势估算」。

## R3 缺失值不得填充

缺失一律 `null`，同时在 `missing[]` 写明 `key` 与原因码（`E_NET / E_TLS / E_HTTP_4XX / E_SCHEMA / E_EMPTY / E_INPUT / E_LICENSE`）。禁止用 0、上期值、均值或估值替代。

## R4 每个数字可复核

每个数值必须能追溯到三件事：`method_id`（公式登记在组件 `references/methods.md`）、`n`（样本量）、`data_date`（数据自身时间戳）。未登记的方法 ID 禁止出现在输出中。

## R5 数据源必须有授权

只允许使用 `contracts/data-sources.yaml` 中 `status: active` 且 `commercial_use ∈ {allowed, exception}` 的源。

- `exception` 源必须逐条遵守其 `restrictions`，不得扩大用途。
- 未登记源调用即视为违规，输出 `E_LICENSE` 并停止。

## R6 禁再分发原始数据

禁止输出原始行情序列、原始披露全文、原始链上区块体。只允许输出派生统计量、事件摘要字段与来源链接。

## R7 通道失败不得静默降级

`--endpoint cloud` 失败必须直接报「数据不可用」；`auto` 允许回退本地，但输出必须带 `data_route` 标明实际通道，且不得把回退描述成正常路径。

## R8 跨组件边界

禁止在代码或文档中写死其他组件的目录、包名、命令入口或移交目标（历史反例 `cogsteward/pack`）。移交目标从 `contracts/forbidden_refs.yaml` 的替代口径与 `handoff_target` 读取。

## R9 不越界写盘

组件默认只读用户工作区，仅允许写自身状态目录（如 `.cm/`）。写工作区必须同时满足：配置显式开启 + 单次 `--apply` + 先做快照。

## R10 免责声明不可省

`limits` 字段不得为空；Markdown 输出固定包含「方法ID / 数据源 / 许可 / 缺失 / 说明」尾部信息。删除免责声明等同于交付缺陷。

## 违规处理链

1. 组件内自检（如 `context.py` 词表扫描）→ 拒绝输出，退出码非 0
2. `tools/check_boundaries.py` G2 / G3 → 发版前 CI 拦截
3. 已发布商品回溯 → 记入组件 `docs/CHANGELOG.md`，按商品下架流程处理
