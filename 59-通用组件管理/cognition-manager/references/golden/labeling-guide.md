# 黄金集标注指南

> 目的：让两个标注者在同一口径下判断「这条信息应归到 skill / doc / memory / session」，并给出可复算的分歧裁定。

## 1. 标注前准备

- 每个样本只给 `id` 与 `content`，不显示现有路由结果；
- Dev / Office 各自独立标注，不共用标签；
- 标注者 A 与 B 不得互相查看对方结果，直至双方完成全量。

## 2. 四类判定口径

| 标签 | 判定问题 | 典型反例 |
|---|---|---|
| `skill` | 这段信息是否可被反复执行成固定流程？ | 一次性排查记录不算 |
| `doc` | 是否是稳定事实 / 规范 / 接口说明？ | 临时会议结论不算 |
| `memory` | 是否是经验、教训、取舍，且必须过准入四问？ | 可从现有文档推导的内容不算 |
| `session` | 是否只对本次对话有效？ | 能被落成文档的长期约定不算 |

判定顺序：`skill` → `doc` → `memory` → `session`，前者命中即停止，不并列。

## 3. 双人标注

1. A 完成全量 → 生成 `labeler: "A"` 的行；
2. B 独立完成 → 生成 `labeler: "B"` 的行，`id` 与 A 对齐；
3. 同一 `id` 的两行构成一对，用于 Cohen's κ；
4. 只标一人的样本不进入 κ，但仍进入 P/R/F1 的参考集。

## 4. 分歧裁定

| κ | 处理 |
|---|---|
| ≥ 0.60 | 可接受；按 A 的标签作为参考，记录分歧样本 |
| 0.40–0.60 | 需要第三人对分歧样本复核，并更新本指南 |
| < 0.40 | 暂停评估，先统一判定口径再重标 |

分歧样本必须保留原始两方标签，不允许只保留胜出方。

## 5. 质量红线

- 不得用模型输出代替人工标签；
- 不得为了让指标达标而挑选样本；
- 样本 `content` 应是真实用户表达，不是为命中关键词而构造的句子；
- 每类样本 ≥20 条，否则该类 P/R/F1 不具解释力。
