## 三、本轮新增 Major

### R7 — `confidence` 公式与 D1 / `high` 阈值未联调，多归属场景被双重惩罚

按 §5.5.1 公式：

```
confidence = 0.35·evidence + 0.30·consistency + 0.20·history + 0.15·(1−conflict)
```

取 D1 刚满足的场景（executions = 2，`history = 2/5 = 0.4`，`evidence = 1.0`）：

| 场景 | consistency | conflict | confidence | 是否达 `high=0.80` |
|---|---|---|---|---|
| 单一命中 | 1.0 | 0 | **0.88** | ✅ |
| 多归属（M1 的核心场景） | 0.6 | 0.5 | **0.685** | ❌ |
| 多归属，executions = 5 | 0.6 | 0.5 | **0.805** | 勉强 ✅ |

问题：
- D1 宣称「executions ≥ 2 即可判为 skill」，但多归属内容实际要 **5 次执行**才达到 `high`；
- `consistency` 与 `conflict` 对同一事实（多命中）重复扣分；
- 这恰好是 M1 要解决的场景，却是最难自动执行的场景。

**要求**：二选一并写入 SPEC——
- (a) `conflict` 只反映「候选互斥未决」，不再对 attachments 扣分；`consistency` 单独承担多命中惩罚；
- (b) 给出「公式 → 阈值 → D1」的联调表，明确每种场景从第几次执行起可达 `high`；
- 无论哪种，`history` 的分母（5）需与 D1 门槛（2）对齐或说明差异理由。

### R8 — 「默认 apply」与 V12 门禁互相否定

- §3 / §5.5.2：**Dev 默认 `apply`**；
- §12 V12：`plan` 抽检误判 ≤5% 才允许对该工作区**开启 `apply`**。

若 Dev 默认就是 `apply`，V12 门禁永远不会被执行，等于没有门禁。

**要求**：默认值统一为 `plan`；`apply` 必须**逐工作区显式开启**，开启前置条件即 V12。若希望 Dev 开箱即用，可保留「fixture/演示工作区默认 apply」，但用户工作区一律 `plan`。

### R9 — 缺 `confidence` 校准验收，阈值仍不可证伪

V4 只验最终分类的 P/R/F1。即使把阈值定成 0.75 也能通过 V4，但无法证明「0.82 确实比 0.61 更可信」。公式权重（0.35/0.30/0.20/0.15）目前是拍定的，没有任何验证。

**要求**：新增 **V13 置信度校准**，满足其一：
- 按 `<low / low–high / ≥high` 三档统计实际精确率，需**单调递增**且高分组 ≥ 0.90；
- 或期望校准误差 **ECE ≤ 0.15**。
