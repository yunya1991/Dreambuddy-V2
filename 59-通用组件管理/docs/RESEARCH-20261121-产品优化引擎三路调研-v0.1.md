## 2. GitHub / 论文成熟项目

| 来源 | 关键发现 | 对本引擎的影响 |
|---|---|---|
| RAG-MCP（arXiv 2505.03275） | 全量工具描述入 prompt 时选择准确率 13.62%，先检索再给模型升到 43.13% | 目录越大，"可被检索到"比"描述更详细"更重要 → 设 `retrievability` 维度为最高权重 |
| MCP-Zero（arXiv 2506.01056） | 主动工具发现可降约 98% token | 工具数量增长后必须分族/分入口，不能一个 skill 塞全部意图 |
| SCOUT 企业 MCP 网关 | `tool_search` 用 BM25 + dense + RRF 混合检索 | 评分同时看字面实体（BM25 类）与语义覆盖，不只关键词堆砌 |
| Semantic Tool Discovery（arXiv 2603.20313） | 描述语义区分度决定检索精度（GitHub 97.1% vs Time/Weather 80%） | 设 `distinctiveness` 维度，检查同族工具名与边界声明 |
| aurelio-labs/semantic-router（MIT） | 用向量路由替代慢速 LLM 决策 | `ab` 只做真值验证，日常用离线代理分快速迭代 |
| OpenBMB/ToolBench | 16k API 规模下的检索式工具使用基准 | 验证"检索层 + 选择层"分离的必要性 |

## 3. 传统行业推流/引流最佳实践

| 实践 | 原始场景 | 迁移到 Skill 商品 |
|---|---|---|
| ASO 字段权重（名称 > 副标题 > 关键词字段） | App Store | `displayName` 权重最高，`summary` 次之，`tags` 第三；三者**不重复用词**（`CON002`） |
| ASO 关键词纪律：单数、去停用词、不浪费字符 | App Store 100 字符关键词 | tags 去停用词、中英双语、每个词只出现一次 |
| JTBD 定位：先说替代什么旧做法 | B2B 定位 | 描述前 80 字写"用户什么场景 + 得到什么"，不写内部术语（`CON003`） |
| 差异化只选一个主打（category / feature / experience） | 品牌定位 | 一个 skill 覆盖一类意图；同族用命名与 `not_for` 划边（`DIS001`/`DIS003`） |
| 落地页转化结构：可复制示例 + 输出样例 + 更新日志 | 增长/转化 | `examples ≥ 2`、`output_sample`、`changelog`（`RET004`/`TRU001`/`TRU002`） |
| 社会证明与清晰定价 | 电商 | 商品页展示价格/模式/试用，买断与订阅语义写清（`CON004`） |

## 4. 综合结论

1. **先解决"被检索到"，再解决"被选中"**：实体与意图词是可离线判断的硬信号，权重最高。
2. **区分度是可离线判断的第二信号**：同族工具名重叠、没有 `not_for`，都是可自动检测的。
3. **离线分只能做代理**：真实选择率必须走 `run_bench`，且要检查 headroom 与复跑稳定性。
4. **传统营销的可迁移部分是"字段纪律"而不是"文案创意"**：ASO 的不重复词、前 80 字、示例可复制，都能变成规则。
5. **门禁必须收窄 blocker**：只挡"0 实体 / 空描述 / 收费缺价"这类硬缺陷，其余先告警，避免存量商品被历史问题卡死。
