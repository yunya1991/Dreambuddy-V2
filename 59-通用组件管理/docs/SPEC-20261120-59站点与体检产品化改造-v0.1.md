## 1. 背景与问题

调研确认底子强、表达弱。下列问题均有代码证据，不是主观判断。

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P1 | **页面承诺多于代码实现**：页面写「示例可执行、触发词覆盖、描述长度、九项检查」，`auditSkill` 未做这些检查 | [index.html L107-L131](../platform/site/index.html#L107-L131)、[guide.html L62-L74](../platform/site/guide.html#L62-L74)、[audit.js L23-L158](../platform/services/skillhub-audit-api/src/audit.js#L23-L158) | 用户按报告修复后仍被平台退回，信任一次性透支 |

| P3 | **额度状态不持久**：内存 `Map`，重启归零；按 UTC 分日，与页面「今日」相差 8 小时 | trial.js L68-L111 | 行为不可预期，无法对账 |
| P4 | **402 订单可被刷**：无凭证每次调用都 `createPending`，无频率限制、无过期清理 | [app.js L259-L294](../platform/services/skillhub-audit-api/src/app.js#L259-L294)、[store.js L38-L48](../platform/services/skillhub-audit-api/src/store.js#L38-L48) | 订单库被灌水，履约与对账失真 |
| P5 | **站点与数据脱节**：首页组件卡硬编码；`registry.json` 又被 Basic Auth 保护，公开页无法读取 | index.html L82-L105、site.conf L29-L33 | 新增组件必须手改 HTML，正是本模块反对的「手工双写」 |
| P6 | **商品结构不可读**：8 个 SKU（含同名 `cogsteward-pro`）、19.9/月 与 2.99/次 混排，无详情页、无选择指引、无直达链接 | [INDEX §3.1](../INDEX.md) | 用户不知道买哪个，转化流失在决策环节 |
| P7 | **零度量零线索**：无事件、无归因、无出站链接统计 | 站点无相关代码 | 无法判断哪一页带来下载 |
| P8 | **信任缺前置**：上传自有源码但无隐私声明；后台仅 HTTP + Basic Auth | index.html、site.conf L22-L42 | 上传意愿低；后台口令明文传输 |
| P9 | **三套规则各自维护**：`audit.js`、`check_boundaries.py`、`skill_lint.py` 互不复用 | 三个文件独立 | SKILL.md 规则改一处漏两处，P1 会反复出现 |

**根因**：站点被当作静态物料，而体检规则、商品事实、展示文案三处各自维护，缺少「数据 → 页面」的生成链路与「规则 → 页面」的单一源。

## 2. 目标与非目标

### 2.1 目标（可验收）

| # | 目标 | 判定 |
|---|---|---|
| G1 | **承诺可验证**：页面上展示的检查项 100% 由规则数据渲染，每条规则有正/负测试 | 页面 DOM 的检查项数量 == 规则文件 `public: true` 条数 |
| G2 | **报告回答「上架风险」**：给出规范性实测分 + 安全子项分，并明确标注未覆盖维度 | 报告含 `dimensions.coverage`，且不输出五维加权总分 |
| G3 | **额度与订单不可轻易刷穿**：IP 取值正确、额度持久化、无凭证调用限流、过期订单清理 | 诈骗式用例（伪造 XFF、重启、21 次匿名调用）全部被拦 |
| G4 | **站点数据单一源**：组件/商品/版本/价格由构建生成，禁止手写 | 首页卡片与 `data/public.json` 一致，`--check` 通过 |
| G5 | **漏斗可度量**：最小事件集，无第三方脚本、无 PII | 事件落 JSONL，字段白名单测试通过 |
| G6 | **信任前置**：隐私声明、安全响应头、后台不裸奔 | 隐私页可达；8081 不再暴露后台；安全头存在 |

### 2.2 非目标

- 不做账号体系、在线支付页、邮箱收集（隐私合规成本高于当前收益）
- 不做多语言、自建搜索、组件安装器
- 不改 Skill 包内容、输出契约、商品 ID 与价格
- 不引入前端框架与构建链；生成器仅用 Python 标准库
- 不把 AST 类边界检查迁入 YAML（`check_boundaries.py` 保持代码形态）
- 本轮不部署；所有验收在本地完成，部署动作另立清单

## 4. 方案总览

```
contracts/skill-quality-rules.yaml         ← 规则单一源（仅声明式规则）
        │  tools/sync_rules.py --write/--check
        ├──────────────► platform/services/skillhub-audit-api/src/rules.generated.js
        └──────────────► platform/site 生成块（检查项列表）

platform/site/catalog.yaml                 ← 仅展示文案与入口链接（无版本/价格）
products/*.yaml + components/*/component.yaml
        │  platform/site/scripts/build_site.py --write/--check
        ├──────────────► platform/site/data/public.json      （公开）
        ├──────────────► platform/site/data/registry.json    （后台，受保护）
        ├──────────────► index.html 组件卡生成块
        └──────────────► platform/site/p/<family>.html       （商品详情页）
```

三条链路各自单一源：**规则**来自 `contracts/`，**商品事实**来自 `products/`，**展示文案**来自 `catalog.yaml`。三者由生成器拼接，页面不手写事实数据。

## 5. 详细设计

### 5.1 规则契约（`contracts/skill-quality-rules.yaml`）

```yaml
version: 1
updated_at: "2026-11-20"
score:
  formula: v2
  weights: { blocker: 15, warn: 5, info: 1 }
dimensions:
  convention: { label: 规范性 }
  trust: { label: 可信任度（安全子项） }
rules:
  - id: DOC001
    title: SKILL.md 内容
    severity: blocker
    dimension: convention
    applies_to: [free, pay]
    public: true
    weight: 15
    check:
      type: text_length
      source: skill_md
      min: 200
      max_bytes: 204800
    messages:
      pass: 长度正常
      fail: 正文过短（<200 字符）或超过 200KB
      hint: 保留触发条件、命令、一条示例，其余拆到 references/
```

**支持且仅支持 6 种声明式 `check.type`**：

| type | 参数 | 用途 |
|---|---|---|
| `text_length` | `source`(skill_md/description)、`min`、`max`/`max_bytes` | 正文、描述长度 |
| `frontmatter` | `field`、`required`、`pattern`、`max_len` | slug/version/displayName/name/description |
| `regex_absent` | `patterns[]`、`scan`(skill_md/files) | 绝对路径、密钥、敏感文件 |
| `regex_present` | `patterns[]` | 收费协议五要素 |
| `files` | `max_count`、`max_total_bytes`、`risky_patterns[]` | 包结构与体积 |
| `section_present` | `headings[]`、`require_code_block` | 使用/示例/限制段落、示例存在性 |

**禁止**把需要上下文推理的规则塞进 YAML。下列规则以 `code_only: true` 登记元数据，实现仍在 `audit.js`：

- `FM008` name 与包内目录名一致（依赖 zip 路径；粘贴模式降级为 `warn`）
- `EX002` 示例中的命令是否指向包内真实入口（依赖 files 清单）

**新增规则清单**（补齐 P1 的承诺缺口，依据 Anthropic Skill 规范）：

| id | 检查 | 级别 | 维度 |
|---|---|---|---|
| FM001 | slug kebab-case，2–128 | blocker | convention |
| FM002 | version SemVer | blocker | convention |
| FM003 | displayName 存在 | blocker | convention |
| FM004 | summary/description 非空 | warn | convention |
| FM005 | license 声明 | warn | convention |
| FM006 | `name` ≤64、kebab-case、无保留词（anthropic/claude） | blocker | convention |
| FM007 | `description` 1–1024 且含触发短语（当用户/用于/use when/触发） | warn | convention |
| FM008 | name 与目录名一致（code_only） | warn | convention |
| DOC002 | 正文含「使用/示例/限制」结构 | warn | convention |
| EX001 | 存在代码块或命令示例 | warn | convention |
| FAQ001 | `references/faq.md` 或 FAQ 段存在 | info | convention |
| SEC001–003 | 敏感文件、绝对路径、密钥 | blocker | trust |
| PKG001–002 | 文件数、包体积 | blocker/warn | convention |
| PAY001–005 | 402 协议五要素 | blocker（仅 pay） | trust |

> 规则 ID 一旦发布不复用；废弃规则保留 id 并标 `deprecated: true`，不参与计分。

### 5.2 评分与报告

- **只评可判定的维度**：`convention` 全量实测；`trust` 仅安全子项（文件/路径/密钥/付费协议）。
- **不评** `reliability / applicability / effectiveness`，报告标记 `not_assessed`，并输出 `coverage = 已评维度/5`。
- **禁止输出五维加权总分**，页面文案不得出现「TRACE 分数」「官方评分」；统一称「上架风险体检」。
- `score` 保留 0–100，但语义固定为「结构合规分」，报告新增 `score_formula_version: 2`；旧分数不再与新版横向比较。

免费报告裁剪规则（修复隐藏阻断项）：

1. 所有 `severity=blocker` 的检查项**必出**，不参与截断；
2. `warn` 按权重降序取前 6；
3. `pass` 折叠为计数；
4. `hidden_checks` 只统计被折叠的 `pass`。

### 5.3 站点数据生成（`build_site.py`）

替换现有 `build_registry.py`（站点尚未部署，无兼容包袱），所有引用同步更新（README、admin.html、INDEX）。

输入：

- `platform/site/catalog.yaml`：按商品族维护 `category / pitch / highlights[] / icon / links{free,pro,pro-pay} / order`；**不得写 version/price**
- `products/*.yaml`：variant 集合、名称、渠道、价格、product_id
- `components/*/component.yaml`：版本、生命周期、入口、摘要

输出：

| 产物 | 用途 | 鉴权 |
|---|---|---|
| `data/public.json` | 首页/详情页渲染数据（schema v1.1） | 公开 |
| `data/registry.json` | 后台组件清单（保留原结构） | Basic Auth |
| `index.html` 内 `<!-- GEN:COMPONENT-CARDS -->` 块 | 静态卡片，保 SEO | 公开 |
| `p/<family>.html` | 4 个商品详情页（模板 `templates/product.html`） | 公开 |
| `trial.html`/`guide.html` 内 `<!-- GEN:RULES-SUMMARY -->` 块 | 检查项列表由规则渲染 | 公开 |

`--check` 校验：

1. `catalog` 的族集合 == `products/*.yaml` 的族集合；
2. 每个 variant 都有 catalog 文案；`catalog` 不出现 `version/price` 键；
3. 组件版本与 `products` 声明一致、`lifecycle` 合法；
4. 生成块与磁盘逐字节一致。

> 选择静态生成而非客户端渲染：商品页需要可被搜索与分享（OG 卡），4 个页面用 Python 模板即可，不引入前端框架。

### 5.4 商品详情与选择器

`p/<family>.html` 结构：

1. 一句话定位 + 所属分类 + 当前版本/价格（来自 products）；
2. 能力清单与输入输出样例（catalog 文案）；
3. **三问选择器**（纯 HTML/JS，无后端）：要不要付费 → 按次还是订阅 → 是否需要纯本地运行；
4. variant 卡：价格、渠道、安装命令、SkillHub 深链（catalog `links`）；
5. 「先体检再购买」CTA → `trial.html`。

首页组件卡改为链接到对应详情页，替代当前的「一段描述 + 无入口」。

### 5.5 免费额度与防刷

| 项 | 设计 |
|---|---|
| IP 取值 | 只信 `X-Real-IP`（nginx `$remote_addr`），缺省用 `socket.remoteAddress`；**删除 XFF 解析** |
| 隐私 | 入库只存 `sha256(ip + TRIAL_IP_SALT)` 前 16 字节 hex；IPv6 先归一到 /64 再哈希 |
| 分日 | 固定 UTC+8（中国无夏令时）：`new Date(ts + 8h).toISOString().slice(0,10)` |
| 存储 | 新表 `trial_usage(ip_hash TEXT, day TEXT, count INTEGER, PRIMARY KEY(ip_hash, day))`，与订单同库 |
| 上限 | 单 IP `TRIAL_DAILY_QUOTA`（默认 5）+ 全局 `TRIAL_GLOBAL_DAILY`（默认 200） |
| 429 | 返回 `remaining: 0`、`retry_after` 秒（到次日 00:00）+ `daily_quota` |
| 清理 | 保留 30 天，启动时与每 24h 清理一次 |
| 盐管理 | `TRIAL_IP_SALT` 放 env 文件；轮换会使旧哈希失效，靠 30 天 TTL 自然收敛 |

### 5.6 订单防刷与清理

- 匿名（无 `Payment-Proof`）调用 `/api/audit|data|cogsteward`：按 `ip_hash` 滑动窗口 20 次/小时，超限 `429 RATE_LIMITED` + `retry_after`；
- **带凭证的请求不参与限流**（避免误伤真实付费用户与重试）；
- 新增索引 `idx_orders_pending(order_status, fulfill_status, created_at)`；
- 每 24h 清理：`order_status='PENDING_PAYMENT' AND fulfill_status='UNFULFILLED' AND created_at < now-7d`；
- **已支付/已履约订单永不删除**（财务留痕）。

### 5.7 信任与部署硬化

| 项 | 内容 |
|---|---|
| 隐私页 | 新增 `privacy.html`：上传内容仅内存处理、不落盘、不训练；日志不含正文；额度仅存 IP 哈希；30 天清理 |
| 安全头 | `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`X-Frame-Options: DENY`、`Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:` |
| 后台 | 新增 `127.0.0.1:8082` server 块承载 admin/registry/health/stats；8081 删除后台 location |
| TLS | 公网域名启用前必须 HTTPS；本条写入部署清单，本轮不执行 |
| 部署清单 | 标注「待部署执行」，验收以本地 `curl 127.0.0.1:8082` 可复现为准 |

### 5.8 最小埋点

- `POST /api/beacon`，`Content-Type: application/json`，体积 ≤2KB；
- 事件白名单：`page_view / trial_submit / trial_success / trial_quota_exceeded / cta_skillhub / guide_view`；
- 字段：`{event, page, ref_host, ts}`；`page` 去掉 query；`ref_host` 只保留出站域名；
- 不记录 IP、UA、正文；`Origin`/`Referer` 必须匹配 `SITE_ORIGIN`，否则 403；
- 落 `/var/lib/skillhub-audit/beacon-YYYYMMDD.jsonl`，保留 30 天；
- 前端用 `navigator.sendBeacon`，失败静默。

### 5.9 管理后台增强

`/api/stats`（经 8082 Basic Auth 反代）返回：

```json
{
  "trial": {"today": 12, "limit": 200, "unique_ips": 9},
  "events": {"page_view": 240, "trial_submit": 31, "cta_skillhub": 18},
  "orders": {"total": 40, "fulfilled": 12, "pending_7d": 3},
  "build": {"public_json": "2026-11-20T...", "rules_version": 1, "registry_check": "pass"}
}
```

后台页只展示聚合值，不展示任何买家信息。

### 5.10 样例试跑与报告导出

- `assets/samples/` 放 3 个 SKILL.md（合规 / 有告警 / 有阻断），自带 `license: MIT` 与「示例样本」声明；体检页「一键填入」；
- 报告支持「下载 JSON」与「复制 Markdown 摘要」，纯前端；**不做服务端短链**（零存储，避免保存用户源码）。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 借 TRACE 权威做营销，分数对不上官方 4.5 反噬 | 不输出五维总分、不写「TRACE 分数」；只报实测维度与覆盖度 |
| 新增规则使存量 Skill 分数下降 | 基线存档 + 逐项 diff + 人工确认（§8 基线保护） |
| 静态生成破坏现有设计 | 只替换标记块与新增 `p/`，页面结构与样式不动 |
| SQLite 额度表在并发下写冲突 | 单实例 + WAL + `busy_timeout`；`INSERT ... ON CONFLICT DO UPDATE` 原子自增 |
| 生成物与源码漂移 | 所有生成器均提供 `--check` 并进 `make check` |
| 埋点被当作追踪 | 白名单事件、无 IP/UA、Origin 校验、30 天清理、隐私页明示 |

## 12. 偏差与不做清单

- 不做「上传即评分 TRACE 五维」：单文件无法判定可靠性/适用性/有效性，强行给分会重演 P1。
- 不做邮箱收集与线索 CRM：涉及个人信息合规与存储，当前引流目标是 SkillHub 下载，不需要。
- 不做本地浏览器体检：规则集先稳定，P2 再评估纯前端实现。
- 不做服务端报告存储：避免保存用户源码，分享能力降级为本地导出。
- 不合并 `audit.js` 与 `check_boundaries.py`：前者是文档/包检查，后者是 AST 与依赖方向，语义不同。
