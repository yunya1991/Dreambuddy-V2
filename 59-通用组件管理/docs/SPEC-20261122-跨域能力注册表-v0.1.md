## 1. 背景与问题

59 域与手机AGENT 域是上下游：59 域提供通用组件与统一入口，手机AGENT 域提供手机执行能力。两域必须保持隔离（禁止互相 import，跨域只走子进程），但需要「共用一张能力注册表，任一 CLI 都能跨域调度」。

改造前实测到的结构性问题：

| 问题 | 证据 |
|---|---|
| 手机动作契约有 4 份副本 | 主仓 `component.yaml`（18 动作）、59 副本 `component.yaml`（26 动作）、`capabilities.MOBILE_READ`、`dreambuddy.MOBILE_COMMANDS` + 安全级表 |
| 副本已分叉 | `carpool*`/`twitter*` 只在主仓；`dispatch/xhs*/douyin*` 只在 59 侧；`mra.py` 实际 27 个顶层子命令 |
| 分叉是结构性的 | `sync_mobile.py` 明确不同步 `component.yaml`，59 侧手工维护 |
| 安全级靠字符串规则推算 | `mobile_safety()` 用子命令名 + 裸 flag 判断，新增子命令默认放行 |
| 跨域只有单向 | 59→手机有代理壳；手机→59 只有文档约定 `$DREAMBUDDY_CLI`，代码未使用 |

结论：问题不是「缺注册表」，而是「缺唯一源 + 缺合并产物 + 缺反向通道」。

## 2. 目标与非目标

目标：

1. 手机动作元数据只有一个源（主仓 `component.yaml`），59 侧动作块由脚本生成，禁止手改。
2. 发布一份合并索引 `dreambuddy.capabilities.v2`，两域 CLI 与 MCP 共用。
3. 任一 CLI 可按 `capability_id` 跨域调度；写动作由执行侧复核，调用方不可降级。
4. 漂移可机器判定：同步检查、索引校验、doctor 闸门。

非目标：

- 不做注册表服务/数据库；不引入运行时网关联邦作为目录源。
- 不把 59 域实现复制进手机仓，也不把手机实现复制进 59 仓。
- 不改 AutoJS 与手机端执行协议。

## 3. 目标架构

```
59: components/*/component.yaml ──┐
                                   ├─► tools/capabilities.py ─► ~/.local/share/dreambuddy/registry/capabilities.json
手机: mobile-reservation-assist/ ──┘        (schema v2 + sources 指纹 + generated_at)
      component.yaml（唯一动作源）
                                          │
                 ┌────────────────────────┼────────────────────────┐
           59 CLI / doctor            MCP 投影壳               手机 mra
           (run/mobile/caps)      (l0_components, 索引优先)   (caps/cross)
                 │                        │                        │
                 └──────────── capability_id → 子进程 argv ───────┘
```

调度方向：

- 59 → 手机：`dreambuddy mobile <cmd>`，经 59 侧代理壳转发主仓 `mra.py`；写动作在 59 侧按注册表 + `escalate` 拦截。
- 手机 → 59：`mra cross <capability_id> [--allow-write]`，翻译为 `dreambuddy run/dal/workflow/schedule` 子进程；手机侧先按索引复核，59 侧再复核一次。

## 4. 契约

### 4.1 动作字段（component.yaml actions[]）

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 组件内唯一动作名（kebab-case） |
| `args` | 是 | 实际 CLI 参数前缀，如 `[twitter, post]`；用于最长前缀匹配 |
| `safety` | 是 | `read` / `write` / `ui`（`irreversible` 保留） |
| `escalate` | 否 | `{"--flag": "write"}`；argv 命中即升权，只升不降 |
| `aliases` | 否 | 跨域短别名，如 `[mobile.jobs]`，展开为 `kind=mobile` 兼容入口 |
| `params` | 否 | MCP/CLI 参数契约（`flag` / `type` / `required` / `enum` / `default`） |
| `mcp` | 否 | `{expose, tier, name}`，`expose` 才投影为 MCP 工具 |
| `output` | 否 | `json` 才允许 MCP 投影 |

### 4.2 合并索引（dreambuddy.capabilities.v2）

```json
{
  "schema": "dreambuddy.capabilities.v2",
  "generated_at": "2026-11-22T01:08:57+08:00",
  "summary": {"total": 89, "by_kind": {"run": 67, "mobile": 8, "data": 3, "trading": 9, "workflow": 1, "schedule": 1}},
  "sources": [{"id": "cogsteward", "path": "components/cogsteward/component.yaml", "sha256": "..."}],
  "capabilities": [{"id": "mobile-reservation-assist.twitter-post", "kind": "run", "...": "..."}]
}
```

字段约定：

- `id`：`<component>.<action>`；`kind=mobile` 的别名 id 为 `mobile.<command>`，带 `alias_of`。
- `kind`：`run`（组件动作）/`mobile`（兼容别名）/`data`（19-DAL）/`trading`（交易只读）/`workflow`/`schedule`；新增 kind 必须同步本 SPEC 与 `mra cross` 的翻译分支。
- `sources`：每个 `component.yaml`、`workflows/*.yaml`、`data_bridge.py` 的内容指纹，用于判断索引是否陈旧。
- 索引是**产物**，不是手写文件；改动源后必须重新 `caps sync`。

### 4.3 安全模型

1. `effective_safety = max(cap.safety, cap.escalate[命中 flag])`。
2. 谁执行谁校验：59 调手机写动作，59 按注册表拦截；手机调 59 写动作，手机按索引拦截且 59 再拦截一次。
3. 未登记子命令按 `write` 兜底（fail-closed），并在 CLI 提示补登记。
4. `--allow-write` 是执行侧授权，不进入注册表；跨域时由 `cross` 给 59 侧补传。

### 4.4 命名决策

- 保留既有 `<component>.<action>`，不新增 `59.` / `mobile.` 域前缀（避免破坏路由提示词与已有夹具）。
- `mobile.*` 仅作兼容别名，执行时仍回到 `mobile-reservation-assist.*` 的 `safety` 与 `escalate`。

## 7. 边界与不变量

1. 两域禁止互相 import；所有跨域调用是子进程。
2. 写动作必须显式授权，且由执行侧判定；调用方不能降级。
3. 状态目录独立：59 在 `59-通用组件管理`，手机在自身 `state_dir`；索引是唯一共享读产物。
4. 59 侧 `components/mobile-reservation-assist/skill/scripts/mra.py` 是代理壳，`sync_mobile` 不得覆盖。
5. 索引只存静态元数据，不存运行态、不存凭证。

## 8. 决策记录

- **选 B（每域自持契约 + 生成合并索引）**，不选 A（单一手写共享文件）与 C（运行时网关联邦）：A 的归属不清且仍需生成器；C 让只读列表依赖网关存活。
- **不引入域前缀 id**：改 id 会破坏路由提示词、计划文件与测试夹具，收益小于破坏面。
- **未登记子命令 fail-closed 为 write**：宁可多要一次 `--allow-write`，也不让 `publish`/`phone` 之类漏过门禁。
- **索引缺失时 MCP 回退 yaml**：保证新机器未 sync 也能用，漂移由 doctor 负责发现。
- **59 副本测试指向主仓实现**（2026-11-22 决策）：新增 `tools/run_mobile_tests.py`，主仓存在时把主仓 `mra.py` 以模块 `mra` 预加载、其余依赖模块仍从副本 `skill/scripts` 解析；主仓缺失时显式 SKIP。选此方案而非「副本只保留契约测试」，以保留 356 项测试覆盖且不把实现复制回副本。
