# 59 域全生命周期 · 框架与操作流程（SPEC-B）v0.1

> **日期**：2026-11-21 ｜ **版本**：v0.2（对齐手机 AGENT 唯一架构依据）｜ **状态**：设计稿，已按主仓修订 ｜ **上游**：[SPEC-A 现状与缺口](./SPEC-20261121-59域全生命周期-现状与缺口-v0.1.md)
> **对齐依据**：`~/Documents/顺风车业务`《手机 AGENT 业务 · 架构总览》v1.1（组件 v0.14.0 / schema 7）；主仓文档为架构唯一口径，本 SPEC 只定义 59 操作台如何编排它。
> **目标**：让 6 个通用组件具备"开发→创建→测试→优化→发布→维护→使用"完整闭环，并支持 `CLI（操作台）+ 大模型` 读写、分发、执行、定时与业务闭环（数据→研究→博文→手机内容执行→人工发布→回流）。
> **不变量**：`component.yaml` 是 59 侧唯一源；手机能力以主仓为唯一源；只读默认、写入需审批；数字必须可追溯；`publish_note` 永不自动化。

## 1. 目标架构

```text
┌──────────────────────────────────────────────────────────────────┐
│ L6 交互面   CLI(dreambuddy)          MCP(l0_components)   定时/工作流 │
├──────────────────────────────────────────────────────────────────┤
│ L5 编排面   workflow runner（YAML→步骤→run ledger→人工闸门）          │
│             每日市场简报 / 内容生产 / 巡检                          │
├──────────────────────────────────────────────────────────────────┤
│ L4 执行面   job scheduler（SQLite + launchd/systemd）→ run-due       │
│             plan/approve/execute · 子进程执行 · 审计 JSONL           │
├──────────────────────────────────────────────────────────────────┤
│ L3 能力面   6 组件 26 动作（market-data / event-context / facts /    │
│             cogsteward / mobile-reservation-assist / reservation）  │
├──────────────────────────────────────────────────────────────────┤
│ L3.5 下游执行面  手机 AGENT 唯一主仓（顺风车业务 v0.14.0 / schema 7） │
│   mra xhs|douyin：scout→memo→trends→collect→data→compose→cover→post │
│   L3 工具注册表 + 12 个 L4 适配器；publish_note 为禁止工具（人工终态） │
├──────────────────────────────────────────────────────────────────┤
│ L2 契约面   component.yaml + workflow.yaml + output.schema +         │
│             product-scorecard + skill-quality-rules                 │
├──────────────────────────────────────────────────────────────────┤
│ L1 治理面   make verify / gate / bench / release ledger / patrol     │
└──────────────────────────────────────────────────────────────────┘
```

| 平面 | 职责 | 现有 | 本期新增 |
|---|---|---|---|
| 交互面 | 人/模型怎么调 | CLI、MCP | `workflow/schedule/audit/release` 子命令 |
| 编排面 | 多步怎么串 | 无 | workflow runner |
| 执行面 | 何时跑、能否重入 | launchd（仅预约）、patrol | 通用 scheduler + plan/approve |
| 能力面 | 做什么 | 6 组件 | 不新增业务能力 |
| 下游执行面 | 手机 App 上做什么 | 主仓 xhs/douyin/预约/顺风车已实现 | 59 按版本+hash 同步主仓副本，并声明内容动作为契约 |
| 契约面 | 什么算合法 | component/output/rules/scorecard | workflow schema、job schema、content schema |
| 治理面 | 什么算通过 | make check/release、optimizer | `make verify`、release ledger |

**架构决策**：编排中枢放在 59 域本地 CLI，不引入 Temporal/Airflow；调度只做"单机 launchd + 云端 systemd timer 调同一个 `run-due`"（对标结论：当前规模用队列/DAG 引擎过重）。SkillHub 只做分发与在线执行，不承担编排。

## 2. 契约扩展

### 2.1 `component.yaml`（增量，保持 `additionalProperties: false`）

```yaml
lifecycle: active            # draft | beta | active | deprecated | retired
deprecated:                  # 仅 deprecated/retired 需要
  since: "2027-01-01"
  sunset_at: "2027-07-01"    # 保留 6 个月，只读可用
  replacement: market-data-v2
permissions:                 # 运行时最小权限，CLI/MCP 双端拦截
  read: true
  write: false
  network: true
  exec: false
actions:
  - name: dispatch
    safety: write
    output: json
    compensate: "scripts/mra.py pause"   # 回滚/补偿命令（可选）
    params: [...]
```

校验：`tools/check_contracts.py` 比对 `actions[].script` 的真实 argparse（`--help` 解析或 AST），
`params[].flag` 必须存在；`safety: write` 必须有 `compensate` 或显式 `compensate: none`。

  - id: social

### 2.4 手机执行端：同步与内容动作

**唯一源**：`~/Documents/顺风车业务`（v0.14.0 / schema 7）。59 内 `components/mobile-reservation-assist/` 只是分发副本，**禁止在副本上做业务修改**；当前副本为 604 行旧桩，必须先同步。

```bash
python3 tools/sync_mobile.py --check   # 比对 component.version + mra.py/registry.py/adapters 的 sha256
python3 tools/sync_mobile.py --write   # 主仓 → 59 副本（仅复制，不改写）
```

`make check` 增加 `sync_mobile --check`：主仓版本或关键文件 hash 变化但副本未同步 → 失败。

**内容动作声明**（写入 59 副本 `component.yaml`，只投影白名单）：

| 动作 | side_effect | 是否暴露 | 说明 |
|---|---|---|---|
| `xhs scout` / `douyin scout` | ui（浏览/点赞/收藏） | 是，需 `--allow-write` | 只读页面 + 有限互动，不评论 |
| `xhs trends` / `compose` / `cover` | read（千问/生图，外部调用） | 是 | 产出 JSON，不碰手机 UI |
| `xhs post` / `douyin post` | ui | 是，需 `--allow-write` | 填到发布前即 `stop`，`stop_before=publish` |
| `memo add` | ui | 是，需 `--allow-write` | 写手机笔记本 |
| `publish_note` / `pay` / `submit_order` / `lock_seat` | irreversible | **否**（禁止） | 永不进工具表；构建/调用即拒绝 |

**契约不重复定义**：指令与回执沿用主仓 `Command` / `mra.receipt.v1`（必备 `trace_id/stage/screenshot/page_text/order_id`），本 SPEC 只规定 59 workflow 如何调用，不另立 schema。

**大模型交互契约**：`chat` 增加两段式——先返回 `plan`（component/action/args/风险/是否需要审批），用户确认后才执行；多步需求直接路由到 `workflow run`。MCP 侧保持"工具调用即执行只读；写工具返回 proposal，带 `plan_id` 再执行"。

### 3.2 写动作安全（propose → approve → execute）

```text
propose : 生成 plan.json {plan_id, action, argv, args_hash, expires_at(15m), risk}
approve : dreambuddy run ... --approve <plan_id>  (校验 args_hash 一致)
execute : 写审计 → 执行 → 失败按 compensate 回滚 → 记 outcome
```

- `principal`：`--principal` 或 `DREAMBUDDY_PRINCIPAL`，缺失即 `E_MANDATE`。
- 参数一变（hash 不符）plan 立即失效；过期即拒绝。
- MCP 写工具沿用 `--allow-write` + `principal` + `confirm`；P1 把 `confirm` 升级为 `plan_id`，兼容旧调用一版。
- 所有写动作必须有 dry-run（`dispatch --dry-run`、`ask --dry-run`、`pause --dry-run`）。
- **安全三态对齐主仓**：`read`（只读）/ `ui`（手机 UI 副作用，需 `--allow-write`）/ `irreversible`（支付、提交、锁座、发布，永不暴露）。59 的 `MOBILE_WRITE` 必须扩到 `xhs|douyin post/scout/memo add`，否则 UI 动作会被误当只读。
- `publish_note` 不提供任何 CLI/MCP 入口；用户要发布只能在手机上看草稿后自己点（或显式 `--publish` 且记录"人工授权"审计）。

## 4. 调度设计

| 项 | 设计 |
|---|---|
| 存储 | SQLite `jobs.db`（单文件，可备份，可查询） |
| 触发 | 本机：`com.dreambuddy.jobs.plist`，每 60s 调 `dreambuddy schedule run-due`；云端：`systemd timer` 调同一命令 |
| 幂等 | `run_key = job_key + scheduled_at` 唯一约束；`flock` 防重入 |
| 补跑 | 停机错过 → 只补最近一次（`catch_up: latest`），不雪崩 |
| 可观测 | `schedule list` 显示 next_run_at、last_status、连续失败次数；连续 3 次失败 → 走 `patrol` 同一通知通道 |
| 开关 | `pause/resume` 只改 DB，不改 plist；停用不卸载 |

**为什么不是 GitHub Actions**：schedule 只在默认分支、公共库 60 天无活动自动禁用，不适合作为生产调度（对标结论）。

## 5. 业务闭环（数据 → 研究 → 博文 → 社媒）

| 段 | 输入 | 产物 | 自动 | 人工闸门 | 验收 |
|---|---|---|---|---|---|
| S0 数据快照 | 组件只读动作 | `facts.json`：`schema_version/generated_at/source_ids/facts[]`，每条含 `fact_id/value/unit/period/method_id/sample_size/source` | ✅ 全部 | 无 | 所有数字有 `fact_id`；缺数据写 `null` 不猜 |
| S1 研究文档 | facts + 模板 | `report.md` + `claim_map.json`（claim→fact_id） | ✅ 渲染；LLM 仅写叙述 | **A：口径与结论** | 文档中每个数字都能回指 fact；存在未映射数字 → 阻断 |
| S2 博文 | report | `blog/posts/<slug>.md`（front matter：title/date/summary/tags） | ✅ 生成草稿 | **B：点击发布** | `build_site --check` 通过；部署后 200 |
| S3 社媒物料 | report | `pack.json`：3 个标题、正文、话题、封面提示词、6 图脚本、合规检查表 | ✅ 生成 | **C：物料与人设口径** | 无"荐股/收益/导流二维码" |
| S3.5 手机填稿 | pack.json | 手机端已填好标题/正文/配图的草稿页（停在发布前） | ✅ `mra xhs|douyin post`（主仓） | **D：人工点发布** | `stop_before=publish`；回执含截图/page_text |
| S4 回流 | 平台后台 + 手机数据面板 | `ops/metrics.csv`：`content_id,platform,url,published_at,impressions,likes,saves,comments,clicks` | ✅ 汇总 | 人工补录 | T+1/T+7 两行；周报对比 7 日均值 |

**合规边界（v0.2 修正）**：
- **不做**：服务端/云端逆向签名、多账号矩阵、批量代发；这类做法封号且触碰导流红线。
- **允许**：手机 AutoJS 按主仓 L3 白名单把内容填到发布前；`publish_note` 是主仓禁止工具，59 也不提供入口。
- 用户明确说"发出去"时，才允许 `post --publish`（记录人工授权审计）；默认永远停在发布前。
- 主仓红线继续有效：不代抢、不转售、不破解验证码、不锁座、不托管支付、敏感信息不上云。

**合规闸门（内容发布前硬校验）**：出现"目标价/买卖点/胜率/稳赚/翻倍/内幕/二维码/加微信"任一即阻断；免责声明缺失即告警。

### 6.2 端到端验收（离线优先）

| # | 场景 | 命令 | 通过标准 |

| E5 | 写动作审批 | propose → approve → execute | 无 plan_id/参数变更/过期 全部拒绝 |
| E6 | 定时任务 | `schedule add` → `run-due` ×2 | jobs.db 只有 1 条 run；第二次 no-op |
| E7 | 工作流 dry-run | `workflow run daily-market-brief --dry-run` | 产出 facts/report 草稿，不写站点、不发任何外部请求 |
| E8 | 内容闸门 | report 含未映射数字 / 正文含"目标价" | S1/S3 阻断，退出 1 |
| E9 | 发布台账 | `release status` | 每个 SKU 有版本/渠道/状态/时间 |
| E10 | 维护巡检 | `patrol.py` + `doctor --full` | 服务与组件均 ok；失败走 incident |
| E11 | 内容执行 | `dreambuddy mobile xhs compose --article a.json` → `post --dry-run` | 步骤含 `stop`、无 `publish_note`；默认停在发布前 |
| E12 | 主仓同步 | `python3 tools/sync_mobile.py --check` | 59 副本版本/hash 与主仓一致；漂移即退出 1 |

> 联网用例单独标记 `make verify-live`，CI/离线默认跳过；断言只依赖 fixture 与契约。
