## 0. 结论

**七段生命周期不是"缺失"，而是"强弱不均"**：

| 阶段 | 完备度 | 一句话判断 |
|---|---|---|
| 开发 | 🟡 中 | 契约、kernel、边界闸门齐全；缺脚手架与"契约 vs 脚本"漂移校验 |
| 创建 | 🟡 中 | 登记靠 `gen_index --write` + 手工 SPEC；缺 `new` 命令与生命周期状态机 |
| 测试 | 🟢 强 | 4 层测试齐全（组件单测 / 沙箱 / Node 规则 / 优化器），但**未统一进 make** |
| 优化 | 🟢 强 | 评分卡 + 路由基准 + 15 轮对照实验；缺结果归档与线上回流 |
| 发布 | 🟢 强 | 构建、双门禁、SkillHub/SkillPay、402 后端齐全；缺发布台账与回滚 |
| 维护 | 🟡 中 | 付费服务有巡检/部署/回滚；**组件本身无健康检查、无弃用流程** |
| 使用 | 🟡 中 | CLI + MCP（12 只读 + 2 写）已可用；**缺通用定时任务与跨域编排** |

**业务闭环现状**：数据（强）→ 研究文档（无）→ 博文（半：有渲染与部署，无生成与审核）→ **手机执行端（强）**：唯一主仓已有 `xhs / douyin` 内容流水线（侦察→采集→千问写稿/生图→填到发布前）与 12 个平台适配器；但 **59 CLI 调用的 mobile 组件是 604 行旧桩（schema 1.0、5 个动作）**，内容能力没有接进操作台，且安全分类会把 xhs/douyin 误判为只读。

**结论**：可以支撑"装一个 Skill 用一条命令"，但还支撑不了"每天自动跑一条数据→研究→内容→回流的作业"。缺口集中在 **编排层、调度层、研究/内容生成层** 三处，不需要重写现有能力层。

## 2. 七段生命周期逐段盘点

### 2.1 开发

已有：契约 schema + G1–G7 边界 + kernel 依赖单向 + 组件内 `tests/` 非空门禁 + 传输层零依赖约定。

缺口：
- **无脚手架**：新建组件仍靠 INDEX §4 的人工步骤（建目录、写 yaml、跑 `gen_index`）。
- **动作漂移无自动校验**：`actions[].name/script/args` 与脚本真实 argparse 之间没有比对；历史已发生"`reservation-assist` 动作清单写了不存在的 `show/check/lint`"（RESEARCH §7.2 已手工修）。
- **无设计模板**：组件级 SPEC 结构不统一（cogsteward 有 4 份文档，其余组件没有）。

### 2.2 创建

已有：`component.yaml` 登记 → `gen_index --write`；`build_site --write`；INDEX §3.1 手工维护商品状态。

缺口：
- **生命周期状态机缺规则**：`lifecycle` 只有 `active/draft`，没有 `beta → deprecated → retired` 的晋级/弃用判据与保留期。
- **登记不完整**：商品 ID、审核状态、价格只写在 INDEX 表格（人工），机器不可读，发布台账无法自动生成。

### 2.3 测试

已有 4 层：
| 层 | 命令 | 规模 |
|---|---|---|
| 组件单测 | 手动 `python3 -m unittest discover -s components/<c>/tests` | 24 个测试文件 |
| 沙箱 | `make test` | 16 场景 |
| 规则/服务 | `node --test platform/services/skillhub-audit-api/test/*.test.js` | 93 |
| 优化器 | `python3 -m unittest discover -s platform/optimizer/tests` | 25 |
| 路由基准 | `make bench-dry` / `make bench` | 45 条意图 |

缺口：
- **组件单测未进 make**：`make test` 只跑沙箱；组件 24 个测试文件不在任何统一命令里，回归靠人记得跑。
- **无端到端契约测试**：CLI / MCP / 输出 `data.v1` 三者没有同一条链路断言；已知 `market-data quotes` 缺 `data.v1` 字段而门禁仍绿（RESEARCH §7.2 待修）。
- **写动作审计无测试**：principal/confirm/审计 JSONL 只有手工实测，没有自动化。

### 2.4 优化

已有：5 维 20 规则评分卡；`score/advise/gate/report/ab`；路由基准 R1–R15 对照实验（覆盖 36.4%→100%，越界 0）。

缺口：
- **结果不归档**：bench 只有 stdout，没有"版本 × 指标 × 日期"的历史表，无法看趋势或回滚描述。
- **无线上回流**：曝光/安装/激活/订单靠人工抄进 `ops/metrics.csv`（skill-ops D0），没有采集脚本。
- **优化→改写→复跑未成环**：`advise` 给建议，改文件与复跑靠人。

### 2.5 发布

已有：`build_product.py`（8 变体）、`skillhub-publisher`、`skillpay-workflow`、站点部署脚本、402 后端、`make release` 双门禁。

缺口：
- **无发布台账**：哪个版本在哪个渠道/状态（审核中/已上架/被拒）只写在 INDEX §3.1，发布动作本身不落库。
- **无回滚**：publisher 只有发布；没有"回退到上一版本/撤回上架"的命令。
- **供应链校验未进门禁**：`skillhub verify` 存在但没接进 `make check`。
- **无 CI**：仓库内无 `.github/workflows`，所有门禁靠本地记得跑。

### 2.6 维护

已有：`patrol` 每 5 分钟巡检付费入口 + incident 事件 + RUNBOOK（备份→部署→回归→回滚）+ systemd `Restart=always`。

缺口：
- **维护对象只覆盖付费服务**：6 个组件本身的"能不能跑"没有健康检查（MCP 工具、CLI 入口、输出契约）。
- **无弃用/兼容策略**：没有 `deprecated`、`sunset_at`、旧参数兼容窗口的约定。
- **无依赖与体积看板**：`kernel_deps`、包体、文件数只在构建时校验，没有趋势。

### 2.7 使用

已有：
- CLI：`dreambuddy run|data|59 <组件> <动作>`、`mobile` 业务域（doctor/jobs/report/patrol/ask/token/ingest/dispatch/pause/resume）、`chat` 自然语言、`domains`、`doctor`。
- MCP：12 个只读工具（8 热）+ 2 个写工具（mandate）。
- 手机：AutoJS 脚本部署在 `/sdcard/脚本/顺风车助手/autojs/`，经 `mra.py` 与本地 HTTP 网关通信；上游由 `reservation-assist` 提供命中。**主仓已实现**顺风车抢单、预约购买、xhs/douyin 内容流水线（`xhs chain` / `douyin chain`，含 `post --publish` 人工授权），但 59 CLI 的 `MOBILE_COMMANDS` 仍是旧 12 条，且 `MOBILE_WRITE` 不含 xhs/douyin（UI 副作用会被当只读放行）。

缺口：
- **操作台与主仓脱节（P0）**：59 内 mobile 组件是旧桩，`dreambuddy mobile xhs ...` 不存在；两份代码各自维护，违反主仓"唯一架构口径"。
- **内容动作未进契约**：主仓 `xhs/douyin` 只在 mra CLI，未在 `component.yaml` 声明为动作，也没有 MCP/CLI 的统一安全等级（read/ui/irreversible）。
- **无通用定时任务**：用户无法"按要求设置定时任务"，只能改 plist；没有 `schedule add/list/pause/rm/run-now`。
- **无跨域编排**：`数据 → 研究 → 博文 → 手机内容执行` 没有 workflow runner；每一步都要人手工串。
- **`chat` 只做单步**：自然语言 → 一个动作；不支持多步计划预览与逐步审批。
- **写动作只有"确认即执行"**：没有 plan_id 绑定、过期、参数变更失效等审批语义（对标 Microsoft 最小控制层）。

## 3. 业务闭环现状

```text
[数据]  ✅ 6 组件可查：行情/宏观/披露/事件/事实日报/链上
   │
[研究文档] ❌ 无生成器；只有 facts JSON 与自由文本
   │
[博文]   🟡 有 posts/*.md → build_site 渲染 → 部署脚本；缺"从研究文档生成草稿"和发布审批
   │
[手机内容执行] 🟢 主仓已实现 xhs/douyin 流水线：scout→memo→trends→collect→data→compose→cover→post（停在发布前）
   │            ⚠ 未接入 59 CLI / workflow；59 内副本是旧桩
[人工发布] ✅ 主仓设计：publish_note 为禁止工具，仅用户明确授权 --publish 才点发布
   │
[效果回流] ❌ 无采集；skill-ops 要求人工记 metrics.csv；主仓已有数据面板可复用
```

**合规边界（已按主仓口径修正）**：
- **服务端/云端禁止批量代发**：不得做逆向签名、浏览器多账号矩阵、服务器端批量发帖。
- **手机端允许确定性草稿执行**：AutoJS 按 L3 白名单工具把内容填到发布前，`publish_note` 永不入工具表；只有用户明确说"发出去"时上游置 `publish_authorized` / `--publish`，属人工授权终态。
- 主仓红线继续有效：不代抢、不转售、不破解验证码、不锁座、不托管支付、敏感信息不上云。
