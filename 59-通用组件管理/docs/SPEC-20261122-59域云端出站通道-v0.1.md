## 1. 背景

59 域 CLI 已统一 89 项能力（run 67 / mobile 8 / data 3 / trading 9 / workflow 1 / schedule 1），但「云端」只有一条受限数据通道：

| 现状事实 | 证据 |
|---|---|
| 只有 6 个动作声明了 `--endpoint`，可透传 cloud | `components/{event-context,market-data}/component.yaml`；未声明动作指定 cloud 直接 `E_UNSUPPORTED`（`tools/dreambuddy.py#apply_endpoint`） |
| cloud 指向 Partner 数据网关，不是生产云 `43.160.201.117` | `components/market-data/skill/scripts/_kernel/endpoint.py#DEFAULT_BASE` |
| 本地令牌未配置，cloud 实际不可用 | `cloud_status()` → `~/.local/share/dreambuddy/partner.env` 不存在（2026-11-22 实测） |
| 生产云能力无任何出站客户端 | `tools/data_bridge.py` 只读本地 DAL 副本；`mcp_shells/l0_components/http_server.py` 是入站网关 |
| 云端运维仍靠 SSH | `deploy/CLOUD-OPS.md`（SSH `dreambuddy-remote`、`/home/luke/dreambuddy`） |

结论：当前是「入站有门、出站无路」，云端全部能力无法通过 59 CLI 统一调用。

## 2. 目标与非目标

### 2.1 目标

1. 数据面补全：声明式 endpoint 覆盖数据类动作，令牌可管理、状态可探活。
2. 控制面新建：59 作为**出站客户端**，通过标准化协议访问云端已登记能力（先只读）。
3. 执行面受控：写动作保持「本地 plan → 本地 approve → 云端审计」双门，`publish` 类终态永不自动。
4. 统一入口：能力注册表新增 `cloud` 类，CLI / chat / 工作流使用同一套 id 与安全级。

### 2.2 非目标

- 不直连云端生产库写数据（DAL 写入口唯一在云端，见 CLAUDE.md 硬约束）。
- 不替代 SSH 运维（部署、重启、构建仍走 `deploy/CLOUD-OPS.md`）。
- 不做多租户/公网开放（云端网关默认仅白名单来源）。
- 不把 Partner 数据网关与生产云混为一谈。

## 3. 目标架构

```
┌────────────────────────── 本地（59 域操作台） ──────────────────────────┐
│ CLI / chat ──► capabilities(registry) ──► execute_plan                  │
│                  │                    │                                 │
│                  │ kind=run/mobile/…  │ kind=cloud                      │
│                  ▼                    ▼                                 │
│          组件脚本（本地执行）   cloud_client.py（新增，只读优先）        │
│                  │                    │                                 │
│        --endpoint cloud / local       │ HTTPS + Bearer + X-Principal   │
└──────────────────┼────────────────────┼─────────────────────────────────┘
                   ▼                    ▼
        Partner 数据网关         云端 MCP HTTP 网关（http_server.py 上云）
        www.neodrm.com          43.160.201.117:127.0.0.1:<port>（Nginx 反代）
        （订阅数据，只读）         → 只读工具集 / 白名单写（P5-4）
                                        │
                                        ▼
                              云端运行时：交易状态、DAL 只读查询、
                              审计日志（append-only）
```

四层职责：

| 层 | 组件 | 说明 |
|---|---|---|
| 数据面 | `--endpoint` + `partner.env` | 订阅数据，只读；`auto` 回退必须标 `data_route` |
| 控制面 | `tools/cloud_client.py`（新增） | HTTP MCP 客户端；只读白名单；超时/重试/降级 |
| 执行面 | 云端 `http_server.py` + `plan/approve` | 写动作双门；irreversible 永不投影 |
| 治理 | 能力注册表 + 审计 | `kind=cloud`；调用审计本地 JSONL + 云端日志 |

## 4. 接口契约

### 4.1 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `DREAMBUDDY_CLOUD_BASE` | 是 | 云端网关地址（Nginx 反代，例如 `https://cloud.example/api/mcp`） |
| `DREAMBUDDY_CLOUD_TOKEN` / `DREAMBUDDY_CLOUD_TOKEN_FILE` | 是 | Bearer token，≥16 字符；文件权限 600 |
| `DREAMBUDDY_CLOUD_PRINCIPAL` | 是 | 调用主体（进入云端审计） |
| `DREAMBUDDY_CLOUD_TIMEOUT` | 否 | 默认 30s，长任务单独声明 |
| `DREAMBUDDY_CLOUD_CA` | 否 | 自签/IP 证书场景的固定 CA；缺省用系统根证书并强制校验 |

### 4.2 CLI

```bash
dreambuddy cloud status                  # 探活 + 版本 + 工具数（不泄露 token）
dreambuddy cloud tools [--json]          # 云端已登记只读工具
dreambuddy cloud call <tool> --args '{}' # 单次只读调用（信封输出）
dreambuddy cloud sync --out <dir>        # 拉取 DAL 只读快照（P5-3）
dreambuddy cloud catalog                 # 合并本地 registry 的云端视图
```

`--endpoint` 语义扩展（三通道判定，命中即停）：

1. 动作声明 `--endpoint` → 透传 `cloud|local|auto`（现状不变）。
2. 未声明但云端注册了同名能力 → 由 `cloud_client` 执行，并在 `_meta.route=cloud` 标注。
3. 都没有 → `E_UNSUPPORTED`；`auto` 回退本地时必须输出 `data_route=local`。

### 4.3 输出信封与错误码

- 成功：沿用 `l0.*.mcp` 信封，追加 `_meta.route`、`_meta.latency_ms`、`_meta.cloud_version`。
- 错误码：
  - `E_CLOUD_AUTH`：token 缺失/错误/过期
  - `E_CLOUD_UNAVAILABLE`：连接超时、TLS 失败、5xx
  - `E_CLOUD_DENIED`：principal 无该工具权限（403）
  - `E_UNSUPPORTED`：本地与云端都没有该能力
- 只读调用最多 3 次指数退避；写调用**不重试**。

## 5. 安全与红线

1. token 只存本地 600 文件或环境变量，不入 git、不入日志、不出现在 `status` 输出。
2. TLS 强制校验；不复用「跳过校验」开关。
3. 云端网关默认仅绑定 `127.0.0.1`，由 Nginx 反代并限来源 IP。
4. 写动作双门：本地 `plan.py` 生成 sha256 参数指纹 + 15 分钟 TTL → 本地 approve → 云端 principal 白名单校验 + 审计。
5. `irreversible` 永不投影；`publish_note`、社媒发布保持人工终态。
6. DAL 写入口只在云端；59 本地只读快照，任何写工具不注册。
7. 云端写失败必须**显式报错**，不得静默降级为本地执行。

## 6. 能力矩阵

| 云端能力 | 通道 | 阶段 | 备注 |
|---|---|---|---|
| Partner 订阅数据（宏观/披露/链上/事件） | `--endpoint cloud` | P5-1 已有，补声明与令牌 | 不是生产云 |
| A 股行情（quotes） | 本地直连数据源 | 不纳入 | 如后续上云，再补声明 |
| 云端 MCP 只读工具（交易状态、诊断、持仓、余额） | `cloud_client` | P5-2 | 与本地 `trading` 域同名时以 route 区分 |
| DAL 只读快照 | `cloud sync` | P5-3 | 替代手工 rsync；幂等、带版本指纹 |
| 云端白名单写（入队/触发巡检） | `cloud call` + plan/approve | P5-4 | 逐工具审批开放 |
| 前端部署 / 服务重启 / 构建 | SSH（CLOUD-OPS） | 非目标 | 不进入 CLI 路由 |

## 7. 实施路线与验收

### P5-1 数据面补全（先做）

- 给需要云端的动作补 `--endpoint` 声明（quotes/facts/context/handoff 按数据源核实后决定，不盲目加）。
- 新增 `dreambuddy cloud token status|set --file <path>`（写入 600；仅提示是否已配置）。
- `cloud status` 做真实探活（HEAD/轻量 GET），区分「未配置令牌」「网络不可达」「网关 5xx」。
- 验收：未配置时明确报 `E_CLOUD_AUTH` 而不是笼统失败；配置后 6 个动作 `--endpoint cloud` 成功且信封含 `data_route=cloud`。

**落地状态（2026-11-22，已验收）**

- endpoint 审计结论：具备真实云端能力的仍是 6 个动作；`market-data.quotes` 的 `--endpoint` 仅允许 `local`，`market-facts-daily.facts` 与 `market-data.context/handoff` 脚本没有 endpoint 参数。**未新增声明**，避免出现「声明了但脚本不支持」的死开关。
- 新增 `tools/cloud_channel.py` 与 `dreambuddy cloud status|probe|token status|set`：令牌写入 600 文件、输出不回显；探活按 DNS → TCP/TLS → HTTP 分段，5xx/401/403 分别归类。
- 实测：`partner.env` 已配置；`cloud status` 探活 `stage=http`；`market-data macro --endpoint cloud` 返回云端数据（输出「通道：云端」，JSON 信封 `data_route=cloud`）；`event-context events --endpoint cloud` 路由 200。
- 网关路由口径：market-data 使用 `market-data-hub`，event-context 使用 `event-context`（`*-hub` 对 event-context 会 `unknown_route`）。
- 已知抖动：首轮调用曾遇 5s 连接超时（kernel `CONNECT_TIMEOUT=5`），重试成功；P5-2 的 `cloud_client` 需按错误类型区分「超时」与「不可用」。

### P5-2 只读出站控制面

- 新增 `tools/cloud_client.py`：HTTP MCP `initialize/tools/list/tools/call`，Bearer + `X-Principal`。
- 能力注册表新增 `kind=cloud`（来源 `cloud_client.tools()`，缓存签名含 base+版本）。
- chat 路由可命中 `cloud.<tool>`；写工具不进入云端只读白名单。
- 验收：断网/错 token/403 分别返回三个错误码；`cloud tools` 与云端 `tools/list` 一致；调用审计落 JSONL。

**落地状态（2026-11-22，本机验证通过；云端网关待 P5-3 部署）**

- 新增 `tools/cloud_client.py`：`initialize` → `tools/list` → 只读 `tools/call`；Bearer + `X-Principal`；写工具按 `annotations.readOnlyHint/destructiveHint` 过滤，不进入本地白名单。
- 缓存：`~/.local/share/dreambuddy/cloud_tools.json`（可用 `DREAMBUDDY_CLOUD_CACHE` 覆盖），能力注册表只读缓存、构建期不联网。
- 审计：`~/.local/share/dreambuddy/cloud_calls.jsonl`，记录 ts/tool/principal/args_sha256/ok/error/latency_ms，不落令牌。
- 错误码：401→`E_CLOUD_AUTH`、403→`E_CLOUD_DENIED`、5xx/超时→`E_CLOUD_UNAVAILABLE`、未知方法→`E_UNSUPPORTED`；CLI 退出码 2/3/1。
- 注册表：新增 `kind=cloud`（`cloud.<tool>`），chat 可路由；`apply_endpoint` 之外的云端能力统一走此出口。
- 验证：与 `mcp_shells/l0_components/http_server.py` 真机对跑 11 个测试（tools/list 一致、错 token、写工具 403、审计落盘、注册表投影）。

### P5-3 云端网关部署与快照

- 云端部署 `mcp_shells/l0_components/http_server.py`（systemd + Nginx 反代 + 来源 IP 白名单）。
- `cloud sync --out` 拉取 DAL 只读副本：临时目录 → 校验 sha256 → 原子替换；失败保留旧副本。
- 验收：本地 `dal read` 可切换读快照；快照清单含云端 HEAD 与生成时间；断点失败不污染现有副本。

**落地状态（2026-11-22，云端已部署并验收）**

- 云端服务：`/etc/systemd/system/dreambuddy-mcp-http.service`（User=luke，127.0.0.1:8785，profile=all，只读，无 `--allow-write`），`enable --now` 已生效；`GET /healthz` 返回 12 个工具。
- 入口：Nginx 在 `43.160.201.117` 站点新增 `location = /api/mcp` 与 `/api/mcp/healthz`（反代 8785，超时 180s），配置备份在 `/home/luke/deploy-backups/`，`nginx -t` 通过后 reload。
- 鉴权：`/etc/dreambuddy-mcp.env`（root:luke 640）保存 `DREAMBUDDY_MCP_TOKEN`（随机 48 hex）与 `DREAMBUDDY_MCP_PRINCIPALS=dreambuddy-cli`；本地 `~/.local/share/dreambuddy/cloud.env`（600）只存客户端令牌。
- TLS：该 IP 使用自签证书（CN/SAN=`43.160.201.117`），客户端通过 `DREAMBUDDY_CLOUD_CA` 固定证书（`~/.local/share/dreambuddy/cloud-ca.pem`，600）；不关闭校验。
- 依赖注入：云端仓库的 `scripts/_kernel` 是构建产物，部署后执行 `tools/sync_kernel.py --write`，否则组件动作报 `ModuleNotFoundError: _kernel`。
- 验收实测：`dreambuddy cloud tools --refresh` 拉到 12 个只读工具；`cloud call market_data_macro --args '{"series":"DGS10","window":30}'` 返回 `ok:true`，审计落 `cloud_calls.jsonl`。
- 快照：复用既有 `31-分布式计算部署/phase7/08-local-mirror.sh`（LaunchAgent `com.dreambuddy.dbsync`，10 分钟周期）；**不在 P5-3 另建第二套镜像**。CLI 封装已落地：`tools/cloud_sync.py` 提供 `dreambuddy cloud sync [--check] [--timeout]`，负责触发、超时、清单与新鲜度判定（30 分钟阈值），不重复实现同步逻辑。
- 已知阻塞：本机 dbsync 曾因 `No space left on device` 失败（rsync 写 `shadow_rl_samples.jsonl` 时报错，日志 `mirror.log`），镜像因此过期；`cloud sync --check` 会如实返回「不新鲜」退出 1。清理磁盘后重跑即可，勿删除 live DB。

### P5-4 白名单写（最后）

- 逐工具登记：工具名 + principal + 参数指纹 + 审计字段。
- 写动作走本地 plan/approve，云端二次校验；失败不重试、不降级。
- 验收：未 approve 的写计划云端拒绝；approve 后审计含 plan_id 与 principal；回放可复现。

**落地状态（2026-11-22，云端已启用白名单写）**

- 双层门禁：本地 `cloud write` 只创建计划（TTL/参数指纹/principal），`apply --allow-write` 才签发 HMAC；云端校验 principal 白名单 + `X-Plan-Id` + `X-Args-Sha256` + `X-Plan-Signature = HMAC(key, plan_id\ntool\nargs_hash)`，任一不符返回 403 `E_PLAN`。
- 白名单：云端 `DREAMBUDDY_MCP_WRITE_TOOLS=market_data_handoff,event_context_handoff`；未登记写工具**不投影**（`project_tools`），即便开启 `--allow-write`。
- 密钥：`DREAMBUDDY_MCP_SIGNING_KEY`（云端 root:luke 640）与本地 `DREAMBUDDY_CLOUD_SIGNING_KEY_FILE`（600）成对；审计不落密钥。
- 实测：`cloud tools` 14 项（12 read + 2 write）；`cloud call market_data_handoff` → `E_CLOUD_DENIED`(3)；未 `--allow-write` 的 `apply` → `E_GUARD`(3)；`cloud write` → `apply --allow-write` 执行成功，`_meta.plan_id` 回显，云端 journal 记录 `WRITE principal=... plan=...`。
- 注意：`cloud write` 默认要求显式 `--confirm`（自动注入 `confirm=true`）；缺少时本地直接 `E_CONFIRM` 退出 2，避免走到云端才被组件拒绝。

## 9. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| VPN/路由把云端 IP 黑洞（历史已发生） | 误判为云端宕机 | `cloud status` 先探活并区分 DNS/TCP/TLS/HTTP 四段 |
| IP 证书不受信 | TLS 校验失败 | 固定 CA（`DREAMBUDDY_CLOUD_CA`）或改用域名证书 |
| token 泄露 | 未授权只读/写 | 600 权限、不入日志、可轮换；`status` 只报「已配置」 |
| 云端网关暴露面扩大 | 被扫描/爆破 | 仅 127.0.0.1 + Nginx 白名单 + 限流 + 审计 |
| 读写语义混淆 | 误执行写动作 | 注册表安全级 + 双门审批 + irreversible 不投影 |

回滚：`cloud_client` 能力可通过注册表开关摘除；云端网关停服务即可回到「仅本地 + Partner 数据」现状，不影响既有 89 项本地能力。

## 10. 待评审决策

- DR-1：出站协议选 HTTP MCP（复用 `http_server.py`），不新增 SSH 包装层。
- DR-2：先只读后写；P5-4 前云端不开放任何写工具。
- DR-3：Partner 数据网关与生产云在注册表中分属 `data` 与 `cloud` 两类，禁止混称「云端」。
- DR-4：`cloud sync` 只拉 DAL 只读副本，不拉运行期数据库文件。
