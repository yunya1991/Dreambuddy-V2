**源/产物分离**：产物头部固定（放在 doctype 之后、`<html>` 之前，避免 quirks mode）：


手写页面仅 `admin.html`、`privacy.html`。`build_site --check` 逐字节比对，检测手改产物。

## 5. 详细设计

### 5.1 规则契约

```yaml
version: 3
updated_at: "2026-11-20"
changelog:
  - version: 3
    summary: "FM006 改 enforce；必填项禁止灰度；新增 patchable/patches；结构校验"
    changed: ["FM006 enforce", "FM001/002/003/006 required_by_platform", "新增 patches 交付"]
score:
  formula: v2
  weights: { blocker: 15, warn: 5, info: 1 }
dimensions:
  convention: { label: 规范性 }
  trust: { label: 可信任度（安全子项） }
rules:
  - id: FM000
    title: Frontmatter
    type: frontmatter_parse
    severity: blocker
    stage: enforce
    required_by_platform: true
    dimension: convention
    applies_to: [free, pay]
    public: true
    group: frontmatter
    on_fail: skip_group
    patchable: false
    messages:
      pass: 已解析 frontmatter
      fail: 缺少合法 frontmatter（首行 --- 起始块）
      fix: 在 SKILL.md 首行补 --- 包裹的 frontmatter，至少含 name/description/version
  - id: FM006
    title: name 字段
    severity: blocker
    stage: enforce          # 平台发布必填，禁止灰度
    required_by_platform: true
    dimension: convention
    applies_to: [free, pay]
    public: true
    group: frontmatter
    depends_on: [FM000]
    patchable: true
    patch: { kind: frontmatter_field, field: name }
    check:
      type: frontmatter
      field: name
      required: true
      pattern: "^[a-z0-9]+(?:-[a-z0-9]+)*$"
      max_len: 64
    messages:
      pass: name 合法
      fail: name 必须 ≤64、kebab-case，且不含 anthropic/claude
      fix: 将 name 改为小写连字符形式，例如 my-skill
```

**字段语义**

| 字段 | 说明 |
|---|---|
| `type` | 仅 `frontmatter_parse` 用；其余走 `check.type` |
| `stage` | `enforce` / `gray`；`gray` 有效严重度降为 `warn` |
| `required_by_platform` | 平台发布硬性字段；**为 true 时禁止 `stage: gray`**，`sync_rules` 直接失败 |
| `group` / `on_fail: skip_group` | 前置失败后同组规则置 `skipped` |
| `depends_on` | 显式前置；前置非 pass 则本规则 `skipped` |
| `patchable` / `patch` | 付费报告的 `patches[]` 生成声明；`patchable: false` 必须在 `messages` 中说明不可 patch 的原因 |
| `messages.fix` | blocker/warn 必填 |

**支持 6 种 `check.type` + 1 个顶层 `frontmatter_parse`**：`text_length`、`frontmatter`、`regex_absent`、`regex_present`、`files`、`section_present`、`frontmatter_parse`。

**求值顺序**：按声明顺序 → 组前置失败则 `skipped` → `skipped` 不计分、不进 `next_actions` → 计入 `counts.skipped`。

**灰度白名单（B1 关闭）**：仅以下启发式规则允许 `stage: gray`——`FM007`、`DOC002`、`EX001`、`FAQ001`、`FM008`。`FM001/002/003/006` 一律 `enforce`。

**规则清单**

| id | 检查 | 级别 | 阶段 | 平台必填 | 可 patch |
|---|---|---|---|---|---|
| FM000 | frontmatter 可解析（组短路） | blocker | enforce | ✅ | ❌ |
| FM001 | slug kebab-case，2–128 | blocker | enforce | ✅ | ✅ |
| FM002 | version SemVer | blocker | enforce | ✅ | ✅ |
| FM003 | displayName 存在 | blocker | enforce | ✅ | ✅ |
| FM004 | summary/description 非空 | warn | enforce | ❌ | ✅ |
| FM005 | license 声明 | warn | enforce | ❌ | ✅ |
| FM006 | name ≤64、kebab、无保留词 | blocker | **enforce** | ✅ | ✅ |
| FM007 | description 1–1024 且含触发短语 | warn | gray | ❌ | ✅ |
| FM008 | name 与目录名一致（code_only） | warn | gray | ❌ | ❌ |
| DOC002 | 使用/示例/限制结构 | warn | gray | ❌ | ❌ |
| EX001 | 存在代码块或命令示例 | warn | gray | ❌ | ❌ |
| FAQ001 | FAQ 文件或段落 | info | gray | ❌ | ❌ |
| SEC001–003 | 敏感文件、绝对路径、密钥 | blocker | enforce | ✅ | ❌ |
| PKG001–002 | 文件数、包体积 | blocker/warn | enforce | ❌ | ✅（结构建议） |
| PAY001–005 | 402 协议五要素（仅 pay） | blocker | enforce | ✅ | ❌ |

**`sync_rules.py` 结构校验（M6 关闭）**，任一失败退出非零：

1. `id` 唯一，且符合 `^(FM|DOC|EX|FAQ|SEC|PKG|PAY)[0-9]{3}$`；
2. `depends_on` 指向存在且无环（拓扑排序检测）；
3. `check.pattern` / `patterns[]` 可被 `new RegExp` 编译；
4. `required_by_platform && stage == gray` → 失败；
5. `severity ∈ {blocker,warn,info}`，`stage ∈ {enforce,gray}`，`weight` 为正整数；
6. `messages.fix` 对 blocker/warn 必填；`patchable: false` 必须有 `messages.no_patch_reason`；
7. `changelog` 末条 `version == version`；规则/阶段/权重任一变化必须 bump 版本（n1）；
8. 生成物头部 sha256 == 源文件 sha256。

### 5.2 评分与报告

**求值矩阵**：`free` → `applies_to ∈ {free, all}`；`pay` → `{pay, all}`；`auto` → 先按 `PAY_MARKERS` 推断并写 `inferred_target`。

**计分**：`score = max(0, 100 - Σ effective_weight)`；blocker 15 / warn 5 / info 1 / skipped 0；`gray` 按 warn。独立输出 `blockers: n`。`score_formula_version: "v2"` 在报告、`/health`、beacon、`public.json.build` 四处一致。

**维度**：`convention` 全量；`trust` 安全子项；其余 `not_assessed` + `coverage`；禁止五维总分与「TRACE 分数」字样。

**免费 / 付费增量（B3 关闭）**

| 内容 | 免费 | 付费 |
|---|---|---|
| 全部 blocker | ✅ | ✅ |
| warn | 前 6 条 | ✅ 全部 |
| `patches[]` 可粘贴修复 | 仅计数 | ✅ 完整 |
| `remediation_plan.items[].fix` | 前 3 条标题 | ✅ 全文 |
| `skipped[]` 明细 | 仅计数 | ✅ 明细（M7） |
| `code_only` 明细、包级建议 | ❌ | ✅ |

**`patches[]` 契约**：

```json
{
  "rule_id": "FM006",
  "target": "SKILL.md",
  "kind": "frontmatter_field",
  "before": null,
  "after": "name: my-skill",
  "apply_hint": "粘贴到 frontmatter 的 name 位置"
}
```

首批必须支持三类（其余 `patchable: false` 并说明原因）：

1. `frontmatter_field`：按缺失字段生成可粘贴片段（FM001/002/003/006）；
2. `description_rewrite`：给原文与建议版本（FM007）；
3. `package_tree`：PKG/结构失败时给目标 `tree` 与移动命令（PKG001/002）。

`patches[]` 只出现在付费报告；免费报告给 `patch_count`。

**修复计划统一（n3 关闭）**：`remediation_plan = {version, items: [{rule_id, severity, order, title, fix, visible_in_free}]}` 为唯一源；`next_actions` 由它派生（前 3 条标题），保留旧字段仅为兼容。

**裁剪规则**：blocker 必出；warn 按有效权重降序、同权重按 `id`；pass 折叠计数；`skipped` 单列；`hidden_checks` 只统计被折叠的 pass。

**存量迁移（M3 关闭）**：报告带 `rules_version`、`rules_changed`（changelog 末条）、`score_notice`；触发条件为「verdict 变化」**或**「score 下降 ≥10」（n11）；新增 blocker 必须先灰度（白名单内），`required_by_platform` 例外。

### 5.3 站点数据生成

替换 `build_registry.py`。**调用点**：`platform/site/README.md`、`admin.html` 运维块、`INDEX.md` §4 规则 1、`Makefile`、`docs/` 非历史引用。

输入：`catalog.yaml`（展示文案 + 链接，禁止 version/price）、`products/*.yaml`、`components/*/component.yaml`。

输出：

| 产物 | 说明 |
|---|---|
| `data/public.json` | 公开；`build` 块含 `rules_version/score_formula_version/generated_at`；字段白名单，断言不含 `/Users/`、`/opt/`、`/home/`（n7） |
| `data/registry.json` | 后台清单（受保护） |
| `index.html` / `trial.html` / `guide.html` | 模板产物 |
| `p/<family>.html` | 商品详情页产物 |

`--check` 校验：

1. catalog 族集合 == products 族集合；catalog 出现 `version/price` 或未知键 → 失败；
2. 每个 variant 有展示文案；**链接按渠道校验（n9）**：`skillhub-*` 必填且匹配 `^https://skillhub\.cn/`，`workbuddy-local` 可空；
3. 组件版本与 products 一致、`lifecycle` 合法；
4. 产物逐字节一致；含 `AUTO-GENERATED` 头的文件与渲染结果不同 → 报「手改产物」；
5. `p/` 页引用的 `../assets/*` 必须存在（n8）。

**文案生成清单（B2 关闭）**

| 位置 | 生成内容 |
|---|---|
| `index.html` | 组件卡；CTA `了解 {{public_rule_count}} 项检查` |
| `guide.html` | 「检查项说明」整表（类别 / 检查内容 / 不通过后果） |
| `trial.html` | 侧栏「检查什么」列表（最多 5 条 + 共 N 项） |
| 断言 | 页面不得出现硬编码「九项 / 9 项 / 七项」；命中即 V6 失败 |

### 5.4 商品详情与选择器

`p/<family>.html`：定位 + 版本/价格（来自 products）→ 能力与样例 → 三问选择器（无 JS 时保留静态内容）→ variant 卡（价格/渠道/安装命令/深链）→ 体检 CTA。首页卡片直达详情页。

### 5.5 免费额度与防刷

| 项 | 设计 |
|---|---|
| IP | 只信 `X-Real-IP`，缺省 `socket.remoteAddress`；删除 XFF 解析 |
| 隐私 | `sha256(ip + TRIAL_IP_SALT)` 前 16 字节 hex；IPv6 归一 /64 |
| 盐 | 启用 trial 时必填（≥16 字符），缺失启动失败 |
| 分日 | 固定 UTC+8；`dayKey()` 单函数复用（n4） |
| 存储 | `trial_usage(ip_hash, day, count, updated_at, PK(ip_hash, day))`，`day` 建索引 |
| **全局上限原子性（M3 关闭）** | `db.transaction(() => { sum; check; upsert; }).immediate()`，求和与自增必须同事务 |
| 429 | `remaining: 0`、`daily_quota`、`retry_after`（秒，复用 `dayKey` 计算）+ `Retry-After` 头 |
| 全局阈值 | `TRIAL_GLOBAL_DAILY` 默认 200；触发写 `trial_global_cap` 事件 |
| 清理 | 30 天保留；启动延迟 30s，`DELETE ... LIMIT 500` 循环 |
| 本地调试 | README 注明 `TRIAL_DAILY_QUOTA=0`；本地无 `X-Real-IP` 时同 IP |
| 网段说明 | IPv6 按 /64、IPv4 按单 IP；误伤可申诉 |

### 5.6 订单防刷与清理

- 匿名调用限流：`ip_hash` 滑动窗口 20 次/小时，`429 RATE_LIMITED` + `retry_after` + `Retry-After`；
- 带凭证请求不限流；
- 内存滑窗仅在 §3 单实例约束下有效；`/health.rate_limit_mode = "memory"`；
- 索引 `idx_orders_pending(order_status, fulfill_status, created_at)`；
- 每 24h 清理 7 天前 `PENDING_PAYMENT + UNFULFILLED`，`LIMIT 500` 分批；已支付/已履约永不删除。

### 5.7 信任与部署硬化

| 项 | 内容 |
|---|---|
| 隐私页 | 内存处理、不落盘、不训练；日志无正文；IP 哈希 30 天删除；网段计额度说明 |
| 安全头 | `nosniff`、`strict-origin-when-cross-origin`、`DENY`、CSP（`style-src 'unsafe-inline'` 记入偏差） |
| 后台 | `127.0.0.1:8082` 承载 admin/registry/health/stats；8081 删除后台 location |
| **stats 隔离 + token（n6）** | admin 监听 `127.0.0.1:8789`（`ADMIN_PORT`）；`/stats` 要求 `X-Admin-Token == ADMIN_TOKEN`，nginx 8082 反代时注入并叠加 Basic Auth；未设 token 则 admin 监听不启动 |
| TLS | 公网启用前必须 HTTPS；写入部署清单，本轮不执行 |
| 部署清单 | 环境变量补全（n13）：`ADMIN_PORT`、`ADMIN_TOKEN`、`SITE_ORIGIN`、`SITE_ORIGIN_ALLOW`、`TRIAL_IP_SALT`、`TRIAL_GLOBAL_DAILY`、`DB_PATH` |

### 5.8 最小埋点

- `POST /api/beacon`，JSON ≤2KB；
- 事件：`page_view / trial_submit / trial_success / trial_quota_exceeded / trial_global_cap / cta_skillhub / guide_view`；
- 字段：`{event, page, ref_host, ts, rules_version, rules_changed}`（n2）；
- `page` 取 pathname，仅保留白名单 `family`；总长 ≤120；
- `Origin/Referer` 必须匹配 `SITE_ORIGIN` 或 `SITE_ORIGIN_ALLOW`（默认含 `http://127.0.0.1:8099`，n5）；
- 不记 IP/UA/正文；JSONL 保留 30 天；`sendBeacon` 失败静默。

### 5.9 管理后台

`/api/stats` 由 8789 + token 提供，经 8082 反代；30 秒缓存。

```json
  "events": {"page_view": 240, "trial_submit": 31, "cta_skillhub": 18},

  "reports_by_rules_version": {"3": 18, "2": 5},
  "build": {"public_json": "2026-11-20T...", "rules_version": 3, "score_formula_version": "v2", "registry_check": "pass"},

}
```

`reports_by_rules_version` 用于灰度升级决策（n14）。`/health` 保留基础状态与 `rules_version`，移除订单统计。

### 5.10 样例与导出

- `assets/samples/` 3 个 SKILL.md（合规/告警/阻断），自带 license 与「示例样本」声明；
- 断言按**规则 id 集合**而非 `verdict`（n12），避免灰度升 enforce 后测试漂移；
- 报告支持下载 JSON、复制 Markdown 摘要；不做服务端短链。
