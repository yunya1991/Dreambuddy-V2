## 1. 背景与问题

调研确认底子强、表达弱。下列问题均有代码证据。

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P1 | **页面承诺多于代码实现**：页面写「示例可执行、触发词覆盖、描述长度、九项检查」，`auditSkill` 未做这些检查 | [index.html L107-L131](../platform/site/index.html#L107-L131)、[guide.html L62-L74](../platform/site/guide.html#L62-L74)、[audit.js L23-L158](../platform/services/skillhub-audit-api/src/audit.js#L23-L158) | 用户按报告修复后仍被平台退回，信任一次性透支 |

| P3 | **额度状态不持久**：内存 `Map`，重启归零；按 UTC 分日，与页面「今日」相差 8 小时 | trial.js L68-L111 | 行为不可预期，无法对账 |
| P4 | **402 订单可被刷**：无凭证每次调用都 `createPending`，无频率限制、无过期清理 | [app.js L259-L294](../platform/services/skillhub-audit-api/src/app.js#L259-L294)、[store.js L38-L48](../platform/services/skillhub-audit-api/src/store.js#L38-L48) | 订单库被灌水，履约与对账失真 |
| P5 | **站点与数据脱节**：首页组件卡硬编码；`registry.json` 又被 Basic Auth 保护，公开页无法读取 | index.html L82-L105、site.conf L29-L33 | 新增组件必须手改 HTML，正是本模块反对的「手工双写」 |
| P6 | **商品结构不可读**：8 个 SKU（含同名 `cogsteward-pro`）、19.9/月 与 2.99/次 混排，无详情页、无选择指引、无直达链接 | [INDEX §3.1](../INDEX.md) | 用户不知道买哪个，转化流失在决策环节 |
| P7 | **零度量零线索**：无事件、无归因、无出站链接统计 | 站点无相关代码 | 无法判断哪一页带来下载 |
| P8 | **信任缺前置**：上传自有源码但无隐私声明；后台仅 HTTP + Basic Auth | index.html、site.conf L22-L42 | 上传意愿低；后台口令明文传输 |
| P9 | **三套规则各自维护**：`audit.js`、`check_boundaries.py`、`skill_lint.py` 互不复用 | 三个文件独立 | SKILL.md 规则改一处漏两处，P1 会反复出现 |

**根因**：站点被当作静态物料，而体检规则、商品事实、展示文案三处各自维护，缺少「数据 → 页面」的生成链路与「规则 → 页面」的单一源。

## 2. 目标与非目标

### 2.1 目标（可验收）

| # | 目标 | 判定 |
|---|---|---|
| G1 | **承诺可验证**：页面上展示的检查项 100% 由规则数据渲染，每条规则有正/负测试 | 页面 DOM 的检查项数量 == 规则文件 `public: true` 条数 |
| G2 | **报告回答「上架风险」**：给出规范性实测分 + 安全子项分，并明确标注未覆盖维度 | 报告含 `dimensions.coverage`，且不输出五维加权总分 |
| G3 | **额度与订单不可轻易刷穿**：IP 取值正确、额度持久化、匿名调用限流、过期订单清理 | 诈骗式用例（伪造 XFF、重启、21 次匿名调用）全部被拦或按已知限制记录 |
| G4 | **站点数据单一源**：组件/商品/版本/价格由构建生成，源文件与产物分离 | `build_site.py --check` 通过，且生成文件带 `AUTO-GENERATED` 头 |
| G5 | **漏斗可度量**：最小事件集，无第三方脚本、无 PII | 事件落 JSONL，字段白名单与 Origin 校验测试通过 |
| G6 | **信任前置**：隐私声明、安全响应头、后台与统计接口不裸奔 | 隐私页可达；8081 不再有后台 location；stats 只在独立 loopback 监听 |

### 2.2 非目标

- 不做账号体系、在线支付页、邮箱收集（隐私合规成本高于当前收益）
- 不做多语言、自建搜索、组件安装器
- 不改 Skill 包内容、输出契约、商品 ID 与价格
- 不引入前端框架与构建链；生成器仅用 Python 标准库
- 不把 AST 类边界检查迁入 YAML（`check_boundaries.py` 保持代码形态）
- 本轮不部署；所有验收在本地完成，部署动作另列清单

## 4. 方案总览

```
contracts/skill-quality-rules.yaml         ← 规则单一源（声明式规则 + 灰度阶段）
        │  tools/sync_rules.py --write/--check
        ├──────────────► platform/services/skillhub-audit-api/src/rules.generated.js（入库，带 sha256）
        └──────────────► platform/site/templates/*.html 的规则摘要块

platform/site/templates/*.html             ← 页面源文件（唯一可手改的 HTML）
platform/site/catalog.yaml                 ← 仅展示文案与入口链接（无版本/价格）
products/*.yaml + components/*/component.yaml
        │  platform/site/scripts/build_site.py --write/--check
        ├──────────────► platform/site/data/public.json      （公开）
        ├──────────────► platform/site/data/registry.json    （后台，受保护）
        ├──────────────► index.html / trial.html / guide.html（产物，AUTO-GENERATED）
        └──────────────► platform/site/p/<family>.html       （商品详情页产物）
```

**源与产物分离（M2）**：凡含生成块或由模板渲染的页面，源文件放 `templates/`，根目录同名文件为产物，头部固定：

```html
<!-- AUTO-GENERATED from templates/index.html — 禁止手改，改模板后跑 build_site.py --write -->
```

手写页面仅 `admin.html`、`privacy.html`。`make check` 中 `build_site.py --check` 逐字节比对，任何手改产物都会失败。

三条链路各自单一源：**规则**来自 `contracts/`，**商品事实**来自 `products/`，**展示文案**来自 `catalog.yaml`。

## 5. 详细设计

### 5.1 规则契约（`contracts/skill-quality-rules.yaml`）

```yaml
version: 2
updated_at: "2026-11-20"
changelog:
  - version: 2
    summary: "新增 name/description/示例/FAQ 检查；frontmatter 组短路；灰度机制"
    changed: ["FM006 新增（gray）", "FM007 新增（gray）", "EX001 新增（gray）", "FAQ001 新增（info）"]
score:
  formula: v2
  weights: { blocker: 15, warn: 5, info: 1 }
dimensions:
  convention: { label: 规范性 }
  trust: { label: 可信任度（安全子项） }
rules:
  - id: FM000
    title: Frontmatter
    type: frontmatter_parse
    severity: blocker
    stage: enforce
    dimension: convention
    applies_to: [free, pay]
    public: true
    group: frontmatter
    on_fail: skip_group
    messages:
      pass: 已解析 frontmatter
      fail: 缺少合法 frontmatter（首行 --- 起始块）
      fix: 在 SKILL.md 首行补 --- 包裹的 frontmatter，至少含 name/description/version
  - id: FM006
    title: name 字段
    severity: blocker
    stage: gray          # 灰度：本轮按 warn 计分与展示
    dimension: convention
    applies_to: [free, pay]
    public: true
    group: frontmatter
    depends_on: [FM000]
    check:
      type: frontmatter
      field: name
      required: true
      pattern: "^[a-z0-9]+(?:-[a-z0-9]+)*$"
      max_len: 64
    messages:
      pass: name 合法
      fail: name 必须 ≤64、kebab-case，且不含 anthropic/claude
      fix: 将 name 改为小写连字符形式，例如 my-skill
```

**规则字段语义**

| 字段 | 说明 |
|---|---|
| `type` | 仅 `frontmatter_parse` 用；其余规则走 `check.type` |
| `stage` | `enforce` / `gray`；`gray` 时有效严重度降为 `warn`，报告中标 `stage: gray` |
| `group` | 同组规则共享前置；前置 `on_fail: skip_group` 失败后，同组后续规则置 `skipped` |
| `depends_on` | 显式声明前置规则 id；前置非 `pass` 时本规则 `skipped` |
| `weight` | 可覆盖 `score.weights` 的默认值 |
| `messages.fix` | **blocker/warn 必填**，用于付费报告的修复示例 |

**支持 6 种 `check.type`，外加 1 个顶层 `frontmatter_parse`**：

| type | 参数 | 用途 |
|---|---|---|
| `text_length` | `source`(skill_md/description)、`min`、`max`/`max_bytes` | 正文、描述长度 |
| `frontmatter` | `field`、`required`、`pattern`、`max_len`、`enum` | slug/version/displayName/name/description/license |
| `regex_absent` | `patterns[]`、`scan`(skill_md/files) | 绝对路径、密钥、敏感文件 |
| `regex_present` | `patterns[]` | 收费协议五要素 |
| `files` | `max_count`、`max_total_bytes`、`risky_patterns[]` | 包结构与体积 |
| `section_present` | `headings[]`、`require_code_block` | 使用/示例/限制段落、示例存在性 |
| `frontmatter_parse` | — | frontmatter 是否存在且可解析（组短路入口） |

**规则求值顺序（M1 关闭）**

1. 按 YAML 声明顺序求值；
2. `frontmatter_parse` 失败 → 同组 `depends_on` 或同 `group` 的后续规则置 `skipped`，**不计分、不进 `next_actions`**；
3. `skipped` 计入 `counts.skipped`，报告显示「N 项因前置失败跳过」；
4. `stage: gray` 的规则按 `warn` 权重计分，`checks[].stage` 保留原值。

**禁止**把需要上下文推理的规则塞进 YAML。下列规则以 `code_only: true` 登记元数据，实现仍在 `audit.js`：

- `FM008` name 与包内目录名一致（依赖 zip 路径；粘贴模式降级为 `warn`）
- `EX002` 示例中的命令是否指向包内真实入口（依赖 files 清单）

**规则清单**（新增项默认 `stage: gray`，一个发版周期后升 `enforce`）：

| id | 检查 | 级别 | 阶段 | 维度 |
|---|---|---|---|---|
| FM000 | frontmatter 可解析（组短路） | blocker | enforce | convention |
| FM001 | slug kebab-case，2–128 | blocker | enforce | convention |
| FM002 | version SemVer | blocker | enforce | convention |
| FM003 | displayName 存在 | blocker | enforce | convention |
| FM004 | summary/description 非空 | warn | enforce | convention |
| FM005 | license 声明 | warn | enforce | convention |
| FM006 | `name` ≤64、kebab-case、无保留词（Anthropic 规范） | blocker | **gray** | convention |
| FM007 | `description` 1–1024 且含触发短语 | warn | **gray** | convention |
| FM008 | name 与目录名一致（code_only） | warn | **gray** | convention |
| DOC002 | 正文含「使用/示例/限制」结构 | warn | **gray** | convention |
| EX001 | 存在代码块或命令示例 | warn | **gray** | convention |
| FAQ001 | `references/faq.md` 或 FAQ 段存在 | info | gray | convention |
| SEC001–003 | 敏感文件、绝对路径、密钥 | blocker | enforce | trust |
| PKG001–002 | 文件数、包体积 | blocker/warn | enforce | convention |
| PAY001–005 | 402 协议五要素（仅 pay） | blocker | enforce | trust |

> 规则 ID 一旦发布不复用；废弃规则保留 id 并标 `deprecated: true`，不参与计分。
> `gray → enforce` 条件：自家 8 个 SKU 基线 diff 无误报 + 外部报告 ≥20 份且相关反馈误报率 <5% + 至少一个发版周期。

### 5.2 评分与报告

**求值矩阵（M9 关闭）**

| `target` | 执行规则 |
|---|---|
| `free` | `applies_to` 含 `free` 或 `all`；`PAY000` 展示为 pass |
| `pay` | `applies_to` 含 `pay` 或 `all`；`PAY001–005`/`PAY100` 参与 |
| `auto` | 先按 `PAY_MARKERS` 推断，报告写入 `inferred_target`，再按上表执行 |

**计分（M10 关闭）**

- `score = max(0, 100 - Σ effective_weight)`；`effective_weight`：blocker 15 / warn 5 / info 1 / skipped 0；`gray` 按 warn；
- 独立输出 `blockers: n`，不依赖 `score` 表达严重度；
- 报告、`/health`、beacon、`public.json.build` 四处统一携带 `score_formula_version: "v2"`。

**维度与覆盖（G2）**

- `convention` 全量实测；`trust` 仅安全子项；
- `reliability / applicability / effectiveness` 标 `not_assessed`，输出 `coverage`；
- **禁止输出五维加权总分**，页面不出现「TRACE 分数」「官方评分」，统一称「上架风险体检」。

**免费 / 付费增量（M4 关闭）**

| 内容 | 免费 `/api/trial` | 付费 `/api/audit` |
|---|---|---|
| 全部 blocker | ✅ | ✅ |
| warn | 前 6 条 | ✅ 全部 |
| pass | 仅计数 | ✅ 全量 |
| `messages.fix` 修复示例 | ❌ | ✅ |
| `remediation_plan`（按阻断→告警排序的修复步骤） | 仅标题级前 3 | ✅ 完整 |
| `code_only` 规则明细（FM008/EX002） | ❌ | ✅ |
| 包级建议（结构/拆分/付费协议补法） | ❌ | ✅ |

`remediation_plan` 生成规则：blocker 在前、warn 在后；同权重按 `id` 升序；免费版只输出前 3 条标题，付费版输出 `fix` 全文。

**裁剪规则（修复隐藏阻断项）**

1. 所有 `severity=blocker` 必出，不参与截断；
2. `warn` 按有效权重降序取前 6，同权重按 `id` 升序（n7）；
3. `pass` 折叠为计数；`skipped` 单列计数；
4. `hidden_checks` 只统计被折叠的 `pass`；
5. `next_actions` 优先 blocker，其次 warn，最多 3 条；超出时追加「还有 N 条阻断」（n8）。

**存量用户迁移（M3 关闭）**

- 报告新增 `rules_version`、`rules_changed`（取 YAML `changelog` 最新条目的 `changed`）；
- 规则变更导致 `verdict` 变化时，报告顶部输出 `score_notice`：「评分口径已更新至 v2，历史分数不可直接比较」；
- 新增 blocker 一律先 `stage: gray`，避免外部用户「昨天通过、今天阻断」。

### 5.3 站点数据生成（`build_site.py`）

替换现有 `build_registry.py`。**替换调用点清单（n6）**：

1. `platform/site/README.md` 的维护命令；
2. `admin.html` 的运维命令块；
3. `INDEX.md` §4 维护规则 1；
4. `Makefile` 的 `check`；
5. `docs/` 内引用 `build_registry.py` 的文档（本 SPEC 与 REVIEW 除外，历史文档不改）。

输入：

- `platform/site/catalog.yaml`：按商品族维护 `category / pitch / highlights[] / icon / links{free,pro,pro-pay} / order`；**不得出现 `version/price`**
- `products/*.yaml`：variant 集合、名称、渠道、价格、product_id
- `components/*/component.yaml`：版本、生命周期、入口、摘要

输出：

| 产物 | 用途 | 鉴权 |
|---|---|---|
| `data/public.json` | 公开渲染数据（schema v1.1，`build` 块含 `rules_version/score_formula_version/generated_at`） | 公开 |
| `data/registry.json` | 后台组件清单（保留原结构） | Basic Auth |
| `index.html` / `trial.html` / `guide.html` | 由 `templates/` 渲染，带 `AUTO-GENERATED` 头 | 公开 |
| `p/<family>.html` | 4 个商品详情页（模板 `templates/product.html`） | 公开 |

`--check` 校验：

1. `catalog` 族集合 == `products/*.yaml` 族集合；
2. 每个 variant 都有 catalog 文案；`catalog` 出现 `version/price` 直接报错（n9：未知键也报错）；
3. `links` 必须匹配 `^https://skillhub\.cn/`（可由 `SITE_LINK_HOSTS` 扩展），且 variant 与链接一一对应（M8）；
4. 组件版本与 `products` 声明一致、`lifecycle` 合法；
5. 所有产物与磁盘逐字节一致；含 `AUTO-GENERATED` 头的文件若与模板渲染结果不同，报「检测到手改产物」。

> `catalog.yaml` 解析器只支持「扁平键 + 行内数组 + 一层列表」，禁止嵌套；未知键一律失败。
> 可选 `--check-links`：对 4 个族的链接做 HEAD 探测（3s 超时），离线时跳过，默认关闭。

### 5.4 商品详情与选择器

`p/<family>.html` 结构：

1. 一句话定位 + 分类 + 当前版本/价格（来自 `products/`）；
2. 能力清单与输入输出样例（catalog 文案）；
3. **三问选择器**（原生 HTML/JS，无后端，无 JS 时保留完整静态内容）：要不要付费 → 按次还是订阅 → 是否需要纯本地运行；
4. variant 卡：价格、渠道、安装命令、SkillHub 深链；
5. 「先体检再购买」CTA → `trial.html`。

首页组件卡改为链接到对应详情页，替代当前「一段描述 + 无入口」。

### 5.5 免费额度与防刷

| 项 | 设计 |
|---|---|
| IP 取值 | 只信 `X-Real-IP`（nginx `$remote_addr`），缺省用 `socket.remoteAddress`；**删除 XFF 解析** |
| 隐私 | 入库只存 `sha256(ip + TRIAL_IP_SALT)` 前 16 字节 hex；IPv6 归一到 /64 再哈希 |
| **盐（M5）** | `TRIAL_IP_SALT` 在启用 trial 时**必填**（长度 ≥16），缺失则启动失败（fail-fast）；轮换会使旧哈希失效，靠 30 天 TTL 收敛 |
| 分日 | 固定 UTC+8（中国无夏令时）：`new Date(ts + 8h).toISOString().slice(0,10)` |
| 存储 | `trial_usage(ip_hash TEXT, day TEXT, count INTEGER, updated_at TEXT, PRIMARY KEY(ip_hash, day))`，`day` 建索引供全局求和（n5） |
| 上限 | 单 IP `TRIAL_DAILY_QUOTA`（默认 5）+ 全局 `TRIAL_GLOBAL_DAILY`（默认 200） |
| 429 | `remaining: 0`、`daily_quota`、`retry_after`（秒）+ 响应头 `Retry-After`（n3） |
| 全局上限（n4） | 触发时写 `trial_global_cap` 事件到 JSONL，并在 `/api/stats` 显示当日是否触发 |
| 清理 | 保留 30 天；启动后延迟 30s 执行，`DELETE ... LIMIT 500` 循环（n15） |
| 本地调试（n1） | 无反向代理时 `X-Real-IP` 缺失，所有请求同 IP；README 注明本地用 `TRIAL_DAILY_QUOTA=0` |
| 网段说明（n2） | 隐私页与 FAQ 写明：IPv6 按 /64、IPv4 按单 IP 计额度；误伤可邮件申诉 |

### 5.6 订单防刷与清理

- 匿名（无 `Payment-Proof`）调用 `/api/audit|data|cogsteward`：按 `ip_hash` 滑动窗口 20 次/小时，超限 `429 RATE_LIMITED` + `retry_after` 秒 + `Retry-After` 头；
- **带凭证的请求不参与限流**（避免误伤真实付费用户与重试）；
- 限流实现为进程内存滑窗，**仅在 §3 单实例约束下有效**；`/health` 暴露 `rate_limit_mode: "memory"`，重启后计数清零属已知行为（M6）；
- 新增索引 `idx_orders_pending(order_status, fulfill_status, created_at)`；
- 每 24h 清理：`order_status='PENDING_PAYMENT' AND fulfill_status='UNFULFILLED' AND created_at < now-7d`，`LIMIT 500` 分批；
- **已支付/已履约订单永不删除**（财务留痕）。

### 5.7 信任与部署硬化

| 项 | 内容 |
|---|---|
| 隐私页 | 新增 `privacy.html`：上传内容仅内存处理、不落盘、不训练；日志不含正文；额度仅存不可逆 IP 哈希（30 天删除、不用于识别个人）；IPv6 网段计额度说明 |
| 安全头 | `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`X-Frame-Options: DENY`、`Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:` |
| 后台 | 新增 `127.0.0.1:8082` server 块承载 admin/registry/health/stats；8081 删除后台 location |
| **统计鉴权（M11）** | 服务新增**独立 admin 监听** `127.0.0.1:8789`（`ADMIN_PORT`），仅暴露 `/stats` 与 `/admin/health`；主监听 8788 **不挂载** stats 路由；nginx 8082 反代 8789 并加 Basic Auth。接口隔离 + 鉴权双层 |
| TLS | 公网域名启用前必须 HTTPS；本条写入部署清单，本轮不执行 |
| 部署清单 | 标注「待部署执行」，验收以本地 `curl 127.0.0.1:8082` 可复现为准 |

### 5.8 最小埋点

- `POST /api/beacon`，JSON，体积 ≤2KB；
- 事件白名单：`page_view / trial_submit / trial_success / trial_quota_exceeded / trial_global_cap / cta_skillhub / guide_view`；
- 字段：`{event, page, ref_host, ts, rules_version}`；
- **`page` 规则（M7）**：取 pathname；仅保留白名单参数 `family`（值必须在 4 个族内），其余 query 全部丢弃；总长 ≤120；
- `ref_host` 只保留出站域名；不记录 IP、UA、正文；
- `Origin`/`Referer` 必须匹配 `SITE_ORIGIN`，否则 403；
- 落 `/var/lib/skillhub-audit/beacon-YYYYMMDD.jsonl`，保留 30 天；
- 前端用 `navigator.sendBeacon`，失败静默。

### 5.9 管理后台增强

`/api/stats` 由 **admin 监听 8789** 提供，经 nginx 8082 + Basic Auth 反代；**30 秒内存缓存**（n13）。

```json
{
  "trial": {"today": 12, "limit": 200, "unique_ips": 9, "global_cap_hit": false},
  "events": {"page_view": 240, "trial_submit": 31, "cta_skillhub": 18},
  "orders": {"total": 40, "fulfilled": 12, "pending_7d": 3},
  "build": {"public_json": "2026-11-20T...", "rules_version": 2, "score_formula_version": "v2", "registry_check": "pass"},
  "limits": {"rate_limit_mode": "memory"}
}
```

后台只展示聚合值，不展示任何买家信息。`/health` 保留基础状态与 `rules_version`，**订单统计迁到 `/api/stats`**，避免业务量外泄。

### 5.10 样例试跑与报告导出

- `assets/samples/` 放 3 个 SKILL.md（合规 / 有告警 / 有阻断），自带 `license: MIT` 与「示例样本」声明；
- 样例入库前必须通过体检断言（n11）：合规样本 `verdict=pass`、告警样本 `needs_work`、阻断样本 `fail`；断言写在 `test/samples.test.js`；
- 报告支持「下载 JSON」与「复制 Markdown 摘要」，纯前端；**不做服务端短链**（零存储，避免保存用户源码）。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 借 TRACE 权威做营销，分数对不上官方 4.5 反噬 | 不输出五维总分、不写「TRACE 分数」；只报实测维度与覆盖度 |
| 新增规则使存量 Skill 分数下降 | 灰度规则 + 基线存档 + `rules_changed` + 口径变更提示 |
| 静态生成破坏现有设计 | 只渲染模板，页面结构与样式不动；产物可逐字节比对 |
| SQLite 额度表并发写冲突 | 单实例 + WAL + `busy_timeout`；`INSERT ... ON CONFLICT DO UPDATE` 原子自增 |
| 限流重启清零 / 多实例失效 | 写入 §3 部署硬约束；`/health` 暴露 `rate_limit_mode`；后台展示已知限制 |
| 生成物与源码漂移 | 所有生成器 `--check` 进 `make check`；生成物带 sha256 与 `AUTO-GENERATED` 头 |
| 埋点被当作追踪 | 白名单事件、无 IP/UA、Origin 校验、30 天清理、隐私页明示 |
| 统计接口暴露业务量 | stats 只在 8789 loopback 监听，主监听不挂载；`/health` 移除订单统计 |

## 11. 决策点（评审建议已采纳，可按需推翻）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 商品页渲染方式 | **静态生成**（SEO/分享/零运行时依赖） |
| D2 | TRACE 相关表达 | **只报实测维度 + 覆盖度**，不输出五维总分 |
| D3 | 后台暴露方式 | **独立 `127.0.0.1:8082`** + admin 监听 8789 |
| D4 | 报告分享 | **下载 JSON + 复制摘要**（零存储） |
| D5 | 规则统一范围 | **仅声明式规则**，AST 检查留代码 |
| D6 | `build_registry.py` 处置 | **替换为 `build_site.py`**（站点未部署，无兼容包袱） |

## 12. 偏差与不做清单

- 不做「上传即评分 TRACE 五维」：单文件无法判定可靠性/适用性/有效性，强行给分会重演 P1。
- 不做邮箱收集与线索 CRM：涉及个人信息合规与存储，当前引流目标是 SkillHub 下载，不需要。
- 不做本地浏览器体检：规则集先稳定，P2 再评估纯前端实现。
- 不做服务端报告存储：避免保存用户源码，分享能力降级为本地导出。
- 不合并 `audit.js` 与 `check_boundaries.py`：前者是文档/包检查，后者是 AST 与依赖方向，语义不同。
- CSP 暂留 `style-src 'unsafe-inline'`（页面存在内联 style），P2 抽离到 `style.css` 后收紧。
