## 三、本轮新增 Major

### R1 — 自动执行缺少 dry-run 与回滚（Devil's Advocate 5 分）

§5.5 阈值表规定：`confidence ≥ high` 且无需确认时**直接执行 `next_action`**。`next_action` 包含 `create_skill` / `update_doc`，即直接写用户仓库。

问题：
- 没有 `patch` / `dry_run` 字段，调用方无法先看后写；
- 没有回滚点，误判一次就改动用户文件；
- 在 Skill 沙箱中若写入受限，该路径会直接失败且状态不一致。

**这是产品级红线**：一个"治理工具"如果自己会误改文件，用户第一次误伤就会卸载。

**要求**：契约增加 `apply_mode: "plan|apply"`，默认 `plan`；`plan` 只输出变更清单与 diff 摘要，`apply` 才落盘；每次 `apply` 写入前生成 `.cm/backup/<run_id>/` 快照，`cm rollback <run_id>` 可撤回。

### R2 — `runs` 计数循环依赖，M2 的修复实际失效

§5.3：`runs` 记录"每次路由"；P1 判定又依赖"历史同指纹 `runs` ≥ 2"。

循环链条：**没有 route 就没有 runs → 没有 runs 就判定 P1 不成立 → 永远不会自动判为 skill。**

真实用户第一次遇到可复用流程时，系统必然要求确认；确认后写入 `intent_confirms`，但 `intent_confirms` 并不增加 `runs` 计数。第二次、第三次如果没有再次调用 `route`（用户通常会直接执行，不会来路由），计数依然为 0。

**要求**：把计数来源改为**执行为准，而非路由为准**：
- 记录 `executions(intent_signature, executed_at, source)`，来源可以是 `route` 确认、`cm record`、或用户手动 `cm mark-done`；
- P1 判定使用 `executions` 计数，`runs` 仅作诊断；
- 明确声明：**未接入执行记录时，P1 永远走用户确认**——这是可接受的降级，但不能假装能自动判断。

### R3 — `confidence` 没有计算定义，三档阈值不可审计

§5.5 给出 `high/low` 阈值，但全篇没有说 `confidence` 怎么产生。没有算法就无法：
- 复核某次路由为何是 0.82；
- 调参（阈值表变成装饰）；
- 通过 V4 证明阈值有效（V4 只验最终结果，不验校准）。

**要求**：定义最小可审计公式。建议线性加权并公开权重：

```
confidence = w1·证据强度 + w2·判定树命中一致性 + w3·历史同指纹确认率 − w4·多归属冲突数
```

各项取值域 `[0,1]`，权重写入 `modes/*.yaml` 可调；每次路由把四项分量写入 `evidence`，供复核。不要求最优，但必须**可解释、可复算**。

### R4 — V4 缺标注规范与一致性门槛，双标注仍可能流于形式

§12 V4 要求"双人独立标注 + 第三人裁定"，但未定义：
- 标注规范（Labeling Guide）——两人对"什么算 skill"的理解必须一致；
- 一致性指标——没有门槛，双标注只是两份互不相干的意见；
- 裁定记录格式——裁定的理由必须可回溯到 SPEC 条款。

**要求**：`assets/golden/labeling-guide.md` 为必交付物；双标注一致性 **Cohen's κ ≥ 0.70** 才进入统计；每条裁定记录 `{case_id, labeler_a, labeler_b, final, reason, spec_ref}`。

### R5 — M0 前测与 V11 的定义冲突，里程碑不可判定

§14：M0 退出条件写"V11 预演完成"；§12：V11 要求"3 个真实工作区试用 ≥7 天、重复摸索下降 ≥30%"。

- 7 天试用无法"预演"；
- 若 M0 就要完成 V11，则 M0 从"评审阶段"变成了"完整产品验证阶段"；
- 若 M0 只做定性访谈，则"V11 预演"是空话。

**要求**：拆成两个指标——M0 只做**定性前测**（3 个工作区访谈，确认分类心智是否成立，产出问题清单）；V11 的定量试用保留在 M4 前，作为上架门槛。§14 同步改写。

### R6 — `intent_signature` 归一化未定义，跨语言场景几乎不可用

§5.3：`hash(动词 + 对象 + 约束)`，"同义动词归一"。但：
- 未定义同义词表来源与维护方式；
- 未处理中英混杂（"部署 deploy 脚本"）；
- 未处理语序、量词、否定；
- 未定义哈希算法与截断长度。

结果是：同一件事换个说法，指纹完全不同，计数永远为 1。

**要求**：给出可执行的最小规范——分词（中文按字 bigram + 英文小写词）、停用词表、动词归一映射表（首批 50 条，放 `references/`）、`sha256` 取前 16 位十六进制；并在 V4 中增加"同义表述召回率"子项（≥0.80）。

## 七、决议

**修改后接受。** M0 的退出条件修订为：

1. R1–R6 全部关闭；
2. M2 用 `executions` 重新设计，并在 SPEC 中给出"未接入执行记录"时的降级声明；
3. `confidence` 公式与 `intent_signature` 规范落到 `references/` 可执行文件；
4. V4 增加同义表述召回率与 κ ≥ 0.70 门槛；
5. §14 拆分为「M0 定性前测」与「M4 定量试用」。

复审通过前，M1 不得开工。
