# 常见问题与排错

## 1. 返回 402 后怎么付款？

按输出的金额/订单号/截止时间，用支付宝 AI 按量付费完成支付；凭证通过 `--proof` 回传：

```bash
python3 scripts/pay.py --cmd macro --series DGS10 --proof <Payment-Proof>
```

凭证来源：支付结果、平台订单页、或支付回调/邮件（让 Agent 读取）。

## 2. 提示「支付凭证无效或已过期」

订单已超时、凭证与订单不一致或凭证被截断。重新下单获取新凭证；**同一凭证重试不会重复扣费**，可放心先用旧凭证验证。

## 3. HTTP 502「履约确认失败」

结果可能已生成，只是履约回执失败。用**同一** `--proof` 重试即可，服务端命中幂等直接返回首次结果。

## 4. 断网 / 超时

- 客户端已把网络错误映射为 `E_NET` / `E_TIMEOUT` / `E_SSL`，不会抛 Python 栈；
- `--timeout` 调整单次超时（默认 60 秒）；
- 只有**带凭证**的调用会自动重试（默认 2 次）；无凭证调用重试会生成新订单，因此不自动重试。

## 5. 参数报错

| 提示 | 原因 | 处理 |
|---|---|---|
| 未知参数：--seris | 拼写错误 | 改 `--series`；用 `--help` 查看可用参数 |
| 缺少必填参数 --series | 未提供必填参数 | `--cmd macro --series DGS10` |
| 参数 --ticker 不适用于 cmd macro | 参数与命令不匹配 | 按 `--cmd filings --ticker AAPL` 使用 |
| --limit 必须是正整数 | 取值为 0、负数或非数字 | 改为 `--limit 5` |

参数错误在本地拦截，不会发出请求。

## 6. 返回「数据不可用」

上游数据源暂时不可用时，`missing` 会列出缺失项，并在 `sources` 标明来源。不估算、不编造；稍后重试同一命令（已支付订单用同一凭证不会重复扣费）。

## 7. 能否用于预测或给出买卖建议？

不能。本技能只返回可复核的历史统计事实，历史分布不等于未来走势，也不提供评级、目标价或方向判断。

## 8. 如何确认没有重复扣费？

- 同一凭证重复提交返回 `already_fulfilled` 与首次结果；
- 输出末尾会提示「幂等重放，未重复扣费」；
- 订单号可在平台订单页核对状态。
