# 变更记录

## 0.6.1 — 2026-11-20

**类型**：修复（`health` 统计口径）｜ **兼容性**：字段不变，存在代码-文档异常时 `health` 会从 `good` 降为 `attention` / `poor`

### 为什么发这个版本

v0.6 新增 `anchor_out_of_range` / `code_without_doc` / `doc_drift` 三项指标后，`health` 仍只按原六项统计，导致只有代码-文档异常的工作区仍显示 `good`，与报告内容自相矛盾。现改为九项统一统计，并与 Pro 版口径对齐。

### 变更

- `core/report.py`：抽出 `health_of(metrics)`，统计 `PROBLEM_KEYS` 九项；缺失指标按 0 处理，不再依赖 `metrics[key]`
- `scripts/tests/test_core.py`：新增 `HealthCase` 四项用例（干净 / 单项 / 三项 / 缺键）

## 0.6.0 — 2026-11-20

**类型**：功能新增（`cm map`）｜ **兼容性**：新增指标字段，不影响现有 `.cm/` 数据

### 为什么发这个版本

`doctor` 目前只用 `edges` 表算断链，没有回答「代码和文档是否对得上」。用户实际关心的是反向缺口与失效引用，因此补四类代码-文档对应检查：

| # | 检查 | 判定口径 | 新增指标 |
|---|---|---|---|
| 1 | 文档 → 代码有效 | 链接目标文件存在 | `broken_links`（复用） |
| 2 | 锚点/行号越界 | `#L起-L止` 落在目标文件实际行数内，且起 ≤ 止 | `anchor_out_of_range` |
| 3 | 代码 → 文档缺口 | 核心模块源码未被任何已索引文档引用 | `code_without_doc` |
| 4 | 文档漂移 | 被引用文件内容哈希晚于文档最后更新 | `doc_drift` |

- [x] `cm map [--gaps] [--json]` 子命令

## 0.5.1 — 2026-11-19

**类型**：文档修正（内核未改）｜ **兼容性**：完全兼容 0.5.0，`.cm/` 数据结构不变

### 为什么发这个版本

实测发现 4 处"文档描述与真实行为不一致"，都会让首次使用者误判功能失效，因此只改文档、不改代码，先把预期对齐：

| # | 问题 | 用户会怎么误解 | 修正 |
|---|---|---|---|
| 1 | `--root` 实际必须写在子命令之前 | 照抄示例执行 → `unrecognized arguments` → 认为工具坏了 | 补示例与显式说明 |
| 2 | `pack` 只按标题与关键词匹配，不读正文 | 正文里明明有该词却 0 命中 → 认为索引不全 | 命令表与限制说明写明口径 |
| 3 | `apply` 需要置信度 ≥ `high_threshold` | 已开 `apply=on` 且带 `--apply` 仍只输出 plan → 认为无法落盘 | 补门槛说明与两种解法（补 facts 或调阈值） |
| 4 | `orphan_files` = 磁盘有、索引无 | 没有任何文档引用的文件却报 0 → 认为检测失灵 | 明确语义与"执行 scan 即归零" |

### 验证

- 自带 70 个用例全部通过（2 项跳过）
- 在模拟工作区（7 文件 / 2 技能）实测：断链 2、孤儿 1、技能冲突 2 均被正确识别
- 实测 `apply` 在 `high_threshold=0.6` 下正常落盘，`rollback` 可完整删除
