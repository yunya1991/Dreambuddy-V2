# PRETEST — 三工作区定性前测（桌面研究）

> **日期**: 2026-11-19
> **目的**: 关闭 M0 阻塞项「3 个工作区定性前测」，验证「主载体 + 从属引用」的必要性与双版本差异
> **方法**: 桌面研究（文档结构统计），**不是用户访谈**
> **结论**: 核心假设在 Dev 侧成立；Office 侧证据不足，仍缺真实访谈

---

## 1. 方法与限制（先声明）

- 语料 A（真实）：本仓库 `dreambuddy-v2`，共 4951 个 Markdown，随机抽 200 个
- 语料 B（构造）：办公代理工作区，20 个文件（会议/模板/流程/制度/方案/清单/笔记/汇报）
- 语料 C（构造）：混合代理工作区，23 个文件（办公 + 代码文档 + ADR + SKILL）
- 统计口径：同一文档同时命中「流程信号 / 事实信号 / 经验信号」≥2 类，记为**多归属**
- **限制**：B/C 由本报告作者构造，存在确认偏差；结果为方向性证据，不能替代真实用户访谈

## 2. 结果

| 语料 | 样本 | 流程信号 | 事实信号 | 经验信号 | 多归属 | 多归属率 |
|---|---|---|---|---|---|---|
| A 开发仓库（真实） | 200 | 78.0% | 57.5% | 71.0% | 144 | **72.0%** |
| B 办公代理（构造） | 20 | 50.0% | 30.0% | 30.0% | 4 | **20.0%** |
| C 混合代理（构造） | 23 | 52.2% | 30.4% | 30.4% | 5 | **21.7%** |

## 3. 发现

| # | 发现 | 对设计的影响 |
|---|---|---|
| P1 | 开发仓库 **72%** 内容多归属，四路互斥会系统性丢信息 | 证成 M1：Dev 版必须保留主载体 + 从属引用 |
| P2 | 办公代理语料多归属仅 **20%**，绝大多数是单载体 | Office 版可简化：主载体 + 一句话备注，不必暴露 attachments 概念 |
| P3 | 办公语料中「流程」与「模板」高度重叠（检查清单、周报模板） | Office 词表应把「套路」与「模板」合并解释，减少一个认知负担 |
| P4 | 开发语料经验信号 71%，但多数是「决策/原因」同时属于文档 | 印证「记忆只存指针」的准入设计（A2） |
| P5 | 办公语料中出现 2 条纯临时信息（无任何信号） | SESSION 分支确实存在，但占比低（10%） |

## 4. 结论

1. **Dev 版**：主载体 + 从属引用的复杂度是必要的，且有量化依据（72%）。
2. **Office 版**：多归属不是主要矛盾（20%），应优先降低概念负担，而不是复用 Dev 的完整模型。
3. **双版本差异应从「换词表」升级为「换分流模型」**：Office = 单载体 + 备注；Dev = 主载体 + 最多 3 条从属。
4. 原 SPEC 假设「办公用户也需要多载体」缺乏证据，属于过度设计。

## 5. 仍未完成的部分

M0 要求的是**用户访谈**，本报告只完成桌面研究。上线前仍需：

- 3 位真实用户（至少 1 位非技术）各 20 分钟访谈
- 核心问题：
  1. 你平时怎么决定一个东西"放哪"？
  2. 有没有同一份内容既当资料又当流程用？举例。
  3. 「资料 / 套路 / 要点 / 本次」这四个词能对上你的习惯吗？
  4. 如果 AI 帮你自动归类，你最怕它做错什么？
  5. 你愿意为"少找东西"付多少钱？
- 产出：访谈记录 + 词表修订 + Office 模型确认
