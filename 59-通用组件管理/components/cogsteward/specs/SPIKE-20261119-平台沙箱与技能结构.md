# SPIKE — WorkBuddy 平台沙箱与技能结构能力

> **日期**: 2026-11-19
> **目的**: 关闭 M0 阻塞项「平台是否允许 Skill 携带多文件 Python 包并写 SQLite」
> **方法**: 官方文档取证 + 本地运行时实测
> **结论**: **条件通过**（本地安装模式可行；云端执行模式不可行）

---

## 1. 取证事实

| # | 事实 | 来源 |
|---|---|---|
| S1 | Skill 标准目录只有 `SKILL.md`、`references/`、`scripts/`、`templates/`，**没有 `assets/`** | 官方技能文档 |
| S2 | `scripts/` 由 AI 通过 **Bash 工具**执行，支持 `.py` / `.js` / `.sh` | 官方技能文档 |
| S3 | Frontmatter 必填：`name`、`display_name`、`display_name_en`、`description`、`description_zh`、`description_en`、`version`、`author`；`allowed-tools` 可选 | 官方技能文档 |
| S4 | 默认权限以**工作空间**为边界，工作空间内常规文件写入通常可直接执行 | 权限模式文档 |
| S5 | **执行脚本/命令、访问网络、写入敏感路径会触发确认** | 权限模式文档 |
| S6 | 沙箱可配置文件/命令/网络策略（`extraAllowWrite`、`excludedCommands` 等） | 安全沙箱文档 |
| S7 | 付费技能存在「加密 + 云端执行」形态，与本地文件写入可能互斥 | 公开报道（二级来源） |

## 2. 本地运行时实测

| 项 | 结果 |
|---|---|
| Python | 3.12.7 |
| SQLite | 3.45.3 |
| FTS5 虚拟表 | ✅ 可用（`unicode61` 分词器） |
| 工作区内建库并写入 | ✅ 成功 |
| 第三方依赖 | 不需要（均标准库） |

> 该实测证明「零依赖 + SQLite + FTS5」在技术上成立；沙箱边界由 S4/S5 决定，不由运行时决定。

## 3. 结论与决策

**结论：`cm` 的本地内核成立，但必须按平台结构改造，并采用本地安装分发。**

| 决策 | 内容 |
|---|---|
| D-S1 | 分发形态锁定 **本地安装 Skill**，不使用云端执行；否则无法读写用户工作区 |
| D-S2 | 目录从 `assets/` 改为 `templates/`；黄金集与 fixture 放 `references/golden/` |
| D-S3 | Frontmatter 补齐平台 8 个必填字段 |
| D-S4 | 所有写操作默认 `plan`；`apply` 需用户确认（与 S5 一致），并在被沙箱拦截时自动降级 |
| D-S5 | 减少 Bash 调用次数：`cm` 单入口、一次命令完成多步，避免默认权限下反复确认 |

## 4. 对 SPEC 的强制修正（S1–S5）

1. §7 包结构：`assets/` → `templates/`，`fixtures/`、`golden/` → `references/golden/`
2. §10.1 Frontmatter：补 `display_name`、`display_name_en`、`description_zh`、`description_en`、`version`、`author`
3. §11 商业化：明确「仅本地安装分发」，云端执行形态列为不可用
4. §5.5.2：新增「沙箱拦截 → 自动降级 `plan`」的运行时分支
5. §9：首次使用流程合并为单次 Bash 调用（`cm init --scan --doctor`）

## 5. 剩余未知

| # | 未知 | 影响 | 处理 |
|---|---|---|---|
| U1 | 付费技能的云端执行是否强制 | 若强制，本地文件方案失效 | 上架前向平台确认；MVP 先按本地安装验证 |
| U2 | Bash 确认频率（每次调用 vs 每次会话） | 影响日常体验 | 用一个含 3 次命令的最小技能实测确认次数 |
| U3 | 只读沙箱下的写行为细节 | 影响降级路径 | M1 用 fixture 复现 |
