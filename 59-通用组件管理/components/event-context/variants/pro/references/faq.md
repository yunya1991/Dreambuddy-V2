# 常见问题与排错

## 1. 402 之后如何完成支付并重试

按输出的金额/订单号/截止时间，用支付宝 AI 按量付费完成支付，再用 `--proof` 重试同一命令。凭证来源：支付结果、平台订单页、支付回调或支付结果邮件。

## 2. 「支付凭证无效或已过期」

订单超时、凭证与订单不一致或凭证不完整。重新获取凭证；同一凭证重试不会重复扣费。

## 3. HTTP 502「履约确认失败」

结果可能已生成，履约回执失败。用同一 `--proof` 重试即可命中幂等结果。

## 4. `--latest` 怎么写

`--latest` 是布尔开关：

```bash
python3 scripts/pay.py --cmd event-context --subject AAPL --latest
```

写成 `--latest true` 会报「未知参数/参数错误」。旧版本该参数会被静默丢弃、查询条件不生效，1.0.1 起已在请求体中断言 `latest=true`。

## 5. 参数报错速查

| 提示 | 原因 | 处理 |
|---|---|---|
| 缺少必填参数 --subject | events 未给主体 | `--cmd events --subject AAPL --since 30` |
| 缺少必填参数：--subject 或 --event-id | event-context 两者都没给 | 二选一 |
| --since 必须是正整数 | 传了 0、负数或非数字 | 改为 `--since 30` |
| --types 取值不合法 | 表单类型格式错误 | `--types 8-K,10-Q` |

参数错误在本地拦截，不会发出请求。

## 6. 断网 / 超时

网络错误映射为 `E_NET` / `E_TIMEOUT` / `E_SSL`，不会抛 Python 栈；`--timeout` 可调超时，只有带凭证的调用才自动重试。

## 7. 「数据不可用」代表什么

上游官方源暂时不可用，`missing` 会列出缺失项。不估算、不编造，稍后重试即可。

## 8. 是否提供影响判断

不提供。仅装配已发生的官方事实与同类事件计数，不含影响判断、方向判断或建议。
