# 同赛道基线与升级门禁

> 目的：把"感觉竞品做得好"变成"哪条指标被超过、超了多少、能不能复现"。
> 原则：**先定基线，再谈借鉴；没有对比数据，不许发版本。**

---

## 1. 赛道定义

`cogsteward` 落在三条赛道的交叉处，调研时分开看，不要混成"AI 工具"：

| 赛道 | 解决的问题 | 典型形态 |
|---|---|---|
| 上下文治理 | 工作区该给 AI 看什么、不该给它看什么 | 扫描 + 体检 + 打包 |
| 记忆层 | 记什么、记在哪、什么时候失效 | 向量库 / 记忆图 / 会话摘要 |
| 技能管理 | 技能重复、版本漂移、触发词冲突 | Skill 注册表 + lint |

**我们的差异化**：只做"判断与指针"，不存正文、不做向量检索、不联网。

## 2. 竞品分层（首版为空壳，靠每周采集填充）

| 层 | 代表 | 观察点 | 数据状态 |
|---|---|---|---|
| 平台内同类 | SkillHub 上 memory / context / workspace 类 Skill | 安装量、榜单名次、更新频率 | 待采 |
| 通用记忆产品 | mem0 / cognee / Letta 类 | 是否宣称"零配置"、如何处理冲突 | 待采 |
| 技能框架 | superpowers 类技能集合 | 技能组织方式、触发词设计 | 待采 |
| 编辑器内置 | IDE / Agent 自带的 context 管理 | 是否抢占"无需安装"的优势 | 待采 |

> 只记录**可核对的公开数字**（安装量、版本号、更新时间）；拿不到就写"未公开"，禁止估算。

## 3. 采集节奏

| 频率 | 动作 | 耗时 | 产出 |
|---|---|---|---|
| 每日 | 看平台榜单/搜索前 5 名有无新面孔，记一行 | 5 min | `ops/competitors.csv` |
| 每周 | 选 1 个竞品，读完它的 SKILL.md，写 1 条可借鉴点 | 30 min | 借鉴条目（含"我们是否要做"） |
| 每两周 | 基线对比：我们的指标 vs 上次 + 竞品 | 20 min | 升级决策 |

`ops/competitors.csv`：

```csv
date,name,platform,installs,version,updated_at,note
2026-11-19,cogsteward,skillhub,0,0.5.1,2026-11-19,本家
```

## 4. 基线指标（只认这四条）

| 指标 | 定义 | 采集方式 | 当前基线 |
|---|---|---|---|
| 首跑成功率 | 安装后首次执行 `init --scan --doctor` 成功出报告的比例 | 用户反馈 / 自测 | ≥ 95% |
| 首跑耗时 | 到出报告的时间 | 实测 | 0.89s |
| 诊断准确率 | 人工注入 N 个问题，被正确识别的比例 | 构造样例 | 待测 |
| 周活跃安装 | 一周内至少调用 1 次的安装数 | 平台后台 | 0（未上架） |

**不做**：把"安装量"当唯一指标——它只能说明曝光，不能说明有用。

---

## 5. "回测"怎么做（运营侧）

Skill 运营没有严格意义的反事实回测，用下面三种替代，且必须写清局限：

1. **前后对比**：改动前 7 天 vs 改动后 7 天，同一指标；n < 30 时只记绝对值。
2. **同期对照**：两个渠道/两个 SKU 同期对比，控制外部因素。
3. **样例回放**：用固定的问题工作区重跑 `doctor`，验证识别结果不退化（这是可复现的真回测）。

**结论表述模板**：

```text
改动：<一句话>
证据：<指标> 从 <a> 到 <b>（n=<样本>，窗口 7 天）
局限：<未控制的因素>
决策：继续 / 停止 / 再观察 7 天
```

---

## 6. 升级门禁（发版本前逐条打勾）

**必须满足**

- [ ] 至少 1 条可复现的改进（样例回放或文档修正）
- [ ] 无回归：自带用例全过；关键路径手测通过
- [ ] 版本号按语义化递增（修文档 = patch，加能力 = minor）
- [ ] `CHANGELOG.md` 写明"为什么发"，而不是"改了什么"
- [ ] 文档与真实行为一致（命令示例可原样执行）

**允许跳过**

- [ ] 无新增功能时，不必等数据显著

**禁止**

- 改动未验证就发版本
- 为了"让看起来活跃"而发空版本（平台与用户都会很快识别）
- 借鉴竞品时直接抄其文案与结构

---

## 7. 升级后的运营动作

| 动作 | 说明 |
|---|---|
| 版本说明写成"用户能感知的收益" | 例：不再出现"照抄命令报错" |
| 在免费款结尾提示可升级 | 一句，不重复 |
| 向已安装用户群体发一次更新提示 | 只在有实质改进时发 |
| 观察 7 天：复访率 / 升级率 | 不达标就停止继续追版本 |
