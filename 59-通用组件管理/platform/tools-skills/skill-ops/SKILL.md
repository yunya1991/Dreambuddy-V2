# 技能运营台（Skill Ops）

## 0. 一句话

**每天 30 分钟，只做三件有证据的事：把数据记下来、把内容发出去、把上一个实验的结论写下来。没有数据就不下结论。**

---

## 1. 何时使用 / 反触发

**使用**：每日运营值班、写引流内容、调商品标题/简介/分类、设计定价与转化路径、判断某个渠道值不值得继续投时间、生成日报/周报。

**不调用**：写业务代码、做投研分析、发布/上架操作（那是 `skillhub-publisher` 与 `skillpay-workflow` 的职责，本技能只做运营决策与内容生产）。

## 3. 两条运营线

### 3.1 A 线：免费引流（`cogsteward`）

目标不是赚钱，是**拿到可触达的人**：安装量、复访、以及"愿意装第二个 Skill"的信号。

平台内四个杠杆（按投入产出来排序）：

| 杠杆 | 动作 | 判定 |
|---|---|---|
| 分类与标签 | 一级分类 1 个 + 二级类目 1–3 个；如实标注"是否需要 API Key" | 能被对应分类筛选命中 |
| 标题与简介 | 标题写"解决什么"，简介前 60 字含使用场景关键词 | 搜索自己品类词时能出现 |
| 榜单位 | 提升"最近上新 → 飙升 → 推荐"的转化信号（安装、收藏、真实使用） | 周环比排名变化 |
| 合集/大赛/精选 | 主动申报专题合集、参加平台大赛；关注每月精选榜单 | 是否入榜 |

平台外（详见 `references/research-引流方案.md`）：GitHub README 当落地页、公众号长文、小红书高频垂直内容、即刻/掘金开发者社区。**一次只开一个渠道**，7 天后按数据决定去留。

### 3.2 B 线：付费转化（`market-facts-daily`）

漏斗只有四段，任何一段掉得厉害就只修那一段：

```text
看到 (曝光) → 装上免费款 (安装) → 第一次跑出结果 (激活) → 买付费款 (付费)
```

- **免费款里要有一条明确的桥**：结尾给"想每天自动出这份事实表 → 市场事实日报 ¥0.99"，不夸大、不承诺收益。
- **付费款的页面卖点是"方法可复核"**：方法ID + 样本量 + 数据源，而不是"AI 预测"。
- 定价与阶梯见 `references/research-付费方案.md`（个人主体硬约束：单笔 ≤50 元、日流水 ≤1000 元、无发票）。

## 4. 每日循环（D0–D3）

| 步 | 动作 | 时间 | 产出 |
|---|---|---|---|
| D0 采数 | 读平台后台：SkillHub「我的 Skill」下载/收藏；SkillPay「订单管理」订单/销售额；商品审核状态；顺手扫一眼同赛道榜单前 5 | 10 min | 一行数据写入 `ops/metrics.csv` + `ops/competitors.csv` |
| D1 生产 | 三选二：①优化一个商品字段 ②写一条站外内容 ③写一条付费卖点卡 | 20 min | 今日内容草稿 |
| D2 分发 | 发布/提交；记录渠道与发布时间 | 5 min | 渠道记录 |
| D3 复盘 | 与 7 日均值比较，只写一句结论 | 5 min | `ops/YYYY-MM-DD.md` |

**硬规则**：数据没采到就写 `null`，禁止用"感觉还行"代替数字；同一天最多改一个变量。

## 5. 指标定义（只认这几个）

| 指标 | 定义 | 采集方式 |
|---|---|---|
| 曝光 `exposures` | 商品/技能在分类页、搜索结果、榜单中的可见次数；不可测时用"列表页名次"替代 | 后台/人工观察 |
| 安装 `installs` | SkillHub 后台累计安装数 | 后台 |
| 激活 `activations` | 首次成功执行且产出符合模板的次数 | 后台 + 用户反馈 |
| 订单 `orders` | SkillPay 已支付订单数 | 订单管理 |
| 收入 `revenue` | 已结算金额（元） | 订单管理 |
| 退款 `refunds` | 退款单数 | 订单管理 |
| **北极星** | 周「激活→付费」转化率 = 周订单 / 周激活 | 计算 |

单量 <30 时不做百分比结论，只记绝对值 + 一句假设。

## 6. 实验规则

1. 一次只改一个变量（标题 / 简介 / 分类 / 价格 / 渠道 / 内容形式）。
2. 窗口固定 7 天，前后各留 1 天缓冲，避免周末效应。
3. 记录：假设 → 改动 → 观测指标 → 结果 → 决策（继续/停止/改造）。
4. 单渠道连续 14 天无新增安装 → 停投，换下一个渠道。
5. 不做 A/B 平台测试时，用"时间前后对比"，但必须写明混杂因素。

### 6.1 同赛道维护与版本升级（周节奏，不做日频）

**为什么不做每日**：调研的边际收益第 3 天就接近零；每天发版会让用户把"更新"当噪声，反而降低信任。

| 频率 | 动作 | 产出 |
|---|---|---|
| 每日 5 分钟 | 只看榜单/搜索前 5 有无新面孔 | `ops/competitors.csv` 一行 |
| 每周 30 分钟 | 读 1 个竞品的 SKILL.md，写 1 条"借鉴 or 不借鉴" | 1 条结论 + 理由 |
| 每两周 20 分钟 | 基线对比：首跑成功率 / 首跑耗时 / 诊断准确率 / 周活跃安装 | 升级决策 |

**升级门禁**（详见 `references/竞品基线与升级门禁.md`）：有可复现改进 + 无回归 + 版本号语义化 + CHANGELOG 写"为什么" + 文档示例可原样执行。**禁止为空版本而发版**。

**回测口径**：样例回放（固定问题工作区重跑 `doctor`，看识别是否退化）是可复现的真回测；前后对比只能作为参考，n < 30 时不下百分比结论。

## 7. 合规红线（高于增长目标）

| 禁止 | 原因 |
|---|---|
| 付费内容出现买卖点、目标价、涨跌预测、标的推荐、胜率 | 构成荐股软件，无牌即违法 |
| 承诺收益、"稳赚""翻倍""内幕" | 违反投顾与广告规范 |
| 刷安装/刷收藏/买榜/批量小号 | 平台风控封号，且数据失真 |
| 用脚本自动批量发布到小红书等社媒 | 触发风控限流，账号不可逆受损 |
| 把内部数据接口、密钥、客户信息写进内容 | 泄露与合规风险 |

允许：公开数据的事实描述、方法与样本量、使用教程、失败复盘。

## 8. 定时任务契约（每日自动运营）

后期用调度器每天跑一次，输入输出固定：

```text
输入：昨日 metrics 行 + 当前 SKU 清单 + 本周实验变量
输出：ops/YYYY-MM-DD.md，含
      ① 数据表（缺失写 null）
      ② 3 条今日待办（每条含验收标准）
      ③ 1 条实验建议（假设 + 观测指标 + 窗口）
      ④ 1 条风险提示（合规/平台规则）
降级：无数据 → 只出内容与待办，不出结论；审核中被拒 → 优先生成申诉/修改清单
```

周报（每周一）：7 日趋势 + 渠道 ROI 排序 + 下周唯一主线。
