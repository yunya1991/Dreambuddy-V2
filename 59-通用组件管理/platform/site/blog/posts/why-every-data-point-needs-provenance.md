# 一个数字什么时候算"可信"

研究里最常见的争论不是结论对错，而是"你这个数从哪来的"。

如果一份输出只给了 `5.07`，它至少缺了五件事：**哪一天的数据、用哪个方法算的、样本量多少、缺失了什么、数据源是否允许这样使用**。缺任何一项，这个数字都无法被复核，也无法被引用。

我们把数据链路拆成五道检查，每一道都对应输出里的一个字段。这套检查现在跑在所有对外数据组件上。

# 检查一：数据日期，不是生成时间

最容易混淆的两个时间戳是"脚本运行时间"和"数据日期"。前者只能说明你什么时候跑过，后者才决定结论是否过期。

我们的输出同时给出 `generated_at`（生成时间）与 `data_date`（数据日期）。对宏观序列，`data_date` 是该序列最后一个有效观测；对行情，它是最后一根日线。

一个真实教训：某次取 SEC 财务字段，概念名用了旧的 `Revenues`，多数公司 2019 年后不再申报，取回来的是多年前的数据。字段能取到、结构也合法，但结论已经失去意义。**能取到不等于新鲜**，所以数据日期必须显式输出，陈旧数据在输出里注明。

# 检查二：方法 ID，让口径可以对齐

同一个"20 日涨跌幅"，至少有三种算法：收盘价对比、复权价对比、对数收益累加。不做标注，跨报告比较就是灾难。

我们的每个统计量都挂方法 ID，输出末尾统一列出：

```
方法ID：M11 区间变动 / M12 序列分位 / M13 年化波动 / M14 最大回撤
```

这样一来，"分位数 60%" 不再是模糊描述，而是可以逐条复算的口径。方法 ID 同时是测试锚点：改算法必须改 ID，否则校验不通过。

# 检查三：样本量，与缺失标注

统计量本身不带样本量，是一个隐藏的陷阱：`n=20` 的分位数和 `n=250` 的分位数，可信度完全不同。

我们的规则是**统计量与样本量成对输出**：

| 字段 | 示例 | 含义 |
|---|---|---|
| pctile | 0.60 | 当前值在窗口内的分位 |
| pctile_n | 60 | 实际参与计算的样本数 |
| observations | 16205 | 该序列的历史总观测数 |
| missing | 无 | 未取到的标的与原因码 |

缺失绝不静默。取数失败时输出 `missing: ["sz000001(E_NET)"]`，而不是悄悄少一行。**"少了一行"比"报错"更危险**，因为读者会默认结果完整。

# 检查四：数据源许可，先于技术接入

技术上能抓，不等于允许商用再分发。这条线如果模糊，整个产品的合规基础都会动摇。

我们维护一份数据源授权台账，只有登记过的源才允许接入。默认不接的包括：禁止商用再分发的行情源、需要信息经营许可的交易所行情、以及未核实条款的统计数据。

低成本公开接口也一样要写清许可与限制，例如公开日线数据会明确标注"仅限本服务内部使用"。许可不是法务的附录，它是输出契约的一部分。

# 检查五：双通道与熔断，失败要可解释

数据服务有两种部署形态：本地直连数据源，或经云端网关统一取数。我们让同一个组件支持三种通道：

- `auto`：云端优先，失败自动回退本地
- `cloud`：只走网关
- `local`：只本地直连

工程上有两个细节值得抄：

1. **连接超时与读取超时分开计时**。TLS 握手抖动不该被误判成"数据源不可用"，否则会触发不必要的回退。
2. **同进程连续失败即熔断**。网关连续失败两次后，本次调用不再尝试云端，避免每个数据集都等一遍超时。

失败时必须给出原因（如 `no_token / E_NET / E_TLS`），而不是笼统的"获取失败"。可解释的失败，才能被运维定位，也才能被读者判断结论是否可信。

# 五道检查的落地方式

我们没有靠"评审时记得检查"，而是把它写进输出契约和闸门：

- 统计量必须成对输出样本量，缺失必须有原因码
- 方法 ID 变化必须伴随算法版本变化
- 数据源未登记在台账中，构建期直接失败
- 通道回退必须有显式字段（`data_route`）记录实际走了哪条路

对使用者来说，最终看到的是一份可复核的输出：

```json
{
  "generated_at": "2026-11-21T04:35:12",
  "data_date": "2026-11-18",
  "data_route": "cloud",
  "rows": [{ "series": "DGS10", "latest": 5.07, "pctile": 0.6, "pctile_n": 60 }],
  "missing": [],
  "method_ids": ["M11", "M12", "M13", "M14"]
}
```

# 小结

数据可信不是一个形容词，而是一组必须存在的字段：**日期、方法、样本量、缺失、许可**。

当这五项成为输出的硬性结构，研究结论才具备两个能力：别人能复算，自己敢引用。这也是我们把数据链路做成组件而不是脚本的原因——脚本可以随意省略字段，组件不行。
