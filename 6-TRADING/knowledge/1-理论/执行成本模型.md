# 交易执行成本模型 (理论 — 风控方法)
> **来源**: dream-multiskill-v2/1-TRADE/dream-execution-cost-model/SKILL.md
> **类别**: 理论 — 执行前成本评估方法

---

## 输入
- `symbol`, `side`, `ord_type_candidate` (market/limit)
- `notional_usdt`
- `market_snapshot`: best_bid/ask, spread_bps, depth_1pct, orderbook_imbalance, volatility_regime
- `fee_bps`: taker_bps, maker_bps

## 输出
```
costs:
  fee_bps_est          手续费估算
  slippage_bps_est     滑点估算
  total_cost_bps_est   总成本
  worst_case_slippage_bps  最坏滑点

execution_recommendation:
  allow_market          是否允许市价单
  preferred_ord_type    优选 order type
  atomic_bracket_required 是否需要原子保护单
  fallback_on_protection_fail: immediate_reduce_only_exit | cancel_and_flatten | skip
```

## 估算逻辑
1. **手续费**: 优先已知 taker_bps，否则保守默认+标注假设
2. **滑点**: 用名义/深度估算冲击 + 半个点差为基础 + imbalance极端时加惩罚
3. **最坏情形**: worst_case_slippage > 30~80bps → 禁止市价单
4. **原子性保护**: 若策略要求开仓后立即保护单，保护单失败必须回退

## 理由码
- `HARD_FAIL_NO_LIQUIDITY_DATA` — 缺少流动性数据
- `HARD_FAIL_WORST_SLIPPAGE_TOO_HIGH` — 最坏滑点过高
- `HARD_FAIL_PROTECTION_ORDER_NOT_CONFIRMED` — 保护单未确认
- `SOFT_WARN_HIGH_SPREAD` — 点差过高
- `SOFT_WARN_HIGH_VOLATILITY` — 高波动
- `ASSUMPTION_FEE_DEFAULTED` — 费率默认值假设

## 约束
- 关键数据不可得 → 倾向 fail-closed 或强制降级为限价单
