## 核心概念

### 权重中心化接口 (Weight-Centric Interface)

**目标组合权重向量 `w_t ∈ ℝⁿ`** 是策略逻辑与下游模块之间的**唯一接口契约**。

```
w_t = ℛ_t(𝒯_t(𝒜_t(𝒮_t(𝒳_≤t))))
```

其中：
- `𝒮` = 标的筛选 (Stock Selection) → 构建候选集 𝒞_t ⊆ 𝒰_t
- `𝒜` = 组合配置 (Portfolio Allocation) → 映射到基础权重 w_t_base
- `𝒯` = 时机调整 (Timing Adjustment) → w_t_base → w_t_timing
- `ℛ` = 风险叠加 (Risk Overlay) → 波动率感知的敞口缩放

### 四大优势

1. **解耦策略构造与执行实现** — 策略只输出权重向量，不关心broker细节
2. **可组合转换** — 异构模块可自由组合（如RL配置器 + LLM信号 + VIX风险叠加）
3. **部署一致性** — 回测和实盘用同一个权重表示，避免语义漂移
4. **可测试性** — 每个组件独立可测，输入输出类型明确

## 四层架构设计

```
┌─────────────────────────────────────────┐
│            Execution Layer               │  ← Broker API (实盘/模拟)
│  订单管理 · 成交模拟 · 崩溃恢复 · 日志   │
├─────────────────────────────────────────┤
│           Backtesting Layer              │  ← 离线评估
│  回测引擎 · 交易成本 · 滑点 · 报表       │
├─────────────────────────────────────────┤
│            Strategy Layer                │  ← 权重向量输出
│  𝒮(筛选) → 𝒜(配置) → 𝒯(时机) → ℛ(风险) │
├─────────────────────────────────────────┤
│              Data Layer                  │  ← 统一数据管道
│  结构化(行情/基本面/宏观) + 非结构化(新闻)│
└─────────────────────────────────────────┘
```

## 部署差距 (Deployment Gap)

FinRL-X 识别了两类关键差距，我们的系统同样面临：

### Gap 1: 回测→模拟交易
- ❌ 过度简化的执行逻辑（bar价格即时成交）
- ❌ 不现实的交易成本建模
- ❌ 无市场冲击模拟
- ❌ 幸存者偏差和数据源不一致

### Gap 2: 模拟→实盘交易
- ❌ 成交不确定性（延迟/部分成交/滑点）
- ❌ 流动性效应
- ❌ API行为差异
- ❌ 基础设施脆弱性（崩溃/断连）
- ❌ 真实资本约束（保证金/结算）

### 我们的现状
- 6-TRADING尚无回测→实盘的一致性接口
- A4验证与A5执行之间的数据传递依赖文件系统，非统一协议
- **建议**: 引入权重向量作为A3→A4→A5的统一接口

## 可操作建议

1. **标准化A系列输出**: A4验证报告应输出标准化的权重向量 + 风险参数，而非自由文本
2. **部署差距检测**: 在A5执行层增加成交质量跟踪（预期vs实际滑点）
3. **回测一致性**: 贝叶斯优化的回测环境应与模拟交易共享同一执行代码路径
4. **风险叠加层独立化**: 将熔断/回撤/VIX缩放从各模块中抽出为独立的 ℛ 层
