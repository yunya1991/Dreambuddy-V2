# 索引系统最佳实践（2026-06-12 外部学习）

来源：Index Ops 每日审计外部研究

## 核心发现

### 1. INDEX.md 优先于 README.md
MkDocs 等文档工具规定：当同一目录下同时存在 `index.md` 和 `README.md` 时，优先使用 `index.md`，`README.md` 被忽略。
- 建议：每个目录只保留 INDEX.md（系统索引），README.md 留给 GitHub 展示用。
- 若必须有 README，建议用 INDEX.md 作为导航入口，README.md 作为简介。

### 2. 目录扁平化
- 单文件夹建议 ≤ 200 个对象（文件+子目录），超过会影响 UI 性能和可导航性
- 最佳实践：每层 100-200 个条目，层级深度 ≤ 4

### 3. 索引覆盖率三档分级
- **有INDEX**：有 INDEX.md 文件，导航完整
- **覆盖不全**：仅有 README.md 或其他文件，但缺少 INDEX.md
- **无INDEX**：完全无索引文件

### 4. 路径体系一致性
- 索引 Base 的「目录路径」应全程使用同一根路径（避免 Dreambuddy-V2 vs 6-TRADING/ 混用）
- 路径体系不匹配会产生噪音差异，降低审计信噪比

## 应用建议
1. 对 30 个「覆盖不全」目录：将 README.md 转换为 INDEX.md，或创建 INDEX.md 引用 README.md
2. 对 55 个新目录：优先注册顶层目录，代码级别的 src/ 子目录可暂不注册
3. 统一路径体系：以 Dreambuddy-V2-main 为根，修正 Feishu Base 中的路径记录
