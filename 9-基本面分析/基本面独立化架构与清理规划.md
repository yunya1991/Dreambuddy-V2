# 基本面独立化架构与清理规划（V1）

## 1. 目标与边界

### 1.1 目标
- 建立“基本面独立项目”的前后端边界，避免与综合/生产版 UI 串味。
- 将新闻页改为“双视图”：`简报视图` 与 `数据化研究视图`，并作为其他基本面子页可复用模式。
- 输出可执行的清理清单，逐步移除与基本面无关的代码与资产。

### 1.2 本轮边界
- 仅在目录 `/Users/zhangjiangtao/ft_userdata/基本面分析_fundamental` 内规划与后续执行。
- 本文先做架构分析与清单，不在本文中直接执行批量删除。

---

## 2. 现状架构（As-Is）

### 2.1 前端入口与路由
- 当前前端入口已指向 `AppFundamental`，技术上是“基本面独立入口”。
- 当前基础路由是 `/fundamental/news|flows|narrative|trading|web3-digest|automation`，具备基本面子域拆分。
- 同时仓库内仍保留 `App.tsx` 及大量非基本面页面组件，造成“仓库形态上仍像综合版项目”。

### 2.2 串味风险来源
- 开发代理存在“动态探测 + 自动切换目标后端”机制；当本机存在多个同类后端进程时，可能切到非预期实例。
- 新闻页当前内容是纵向堆叠，简报区域在页面中不够突出，用户体感容易变成“看不到简报”。

### 2.3 后端现状
- `ml_trade_service.py` 为大一体服务，含基本面与非基本面能力。
- 基本面功能虽已按 `/fundamental/*` 命名空间暴露，但代码组织层面仍未完全子域化。

---

## 3. 目标架构（To-Be）

## 3.1 前端独立化
- 固定基本面前端入口：`main.tsx -> AppFundamental.tsx`。
- 明确“仅基本面导航”的 Shell，不承载非基本面菜单与鉴权面板。
- 引入页面级双视图容器（可复用）：
  - `简报视图`：以文本与关键结论为主（快速决策）
  - `数据化研究视图`：以指标、时间序列、事件对比为主（深入分析）

## 3.2 新闻页信息架构
- 顶层改为 Tabs：
  - Tab A：`简报视图`
    - 最新简报标题/时间/数据窗口
    - 08:00 Anchor 与 Latest 关键差异摘要
    - 原文内容折叠/展开
  - Tab B：`数据化研究视图`
    - Coverage 时间序列
    - Quality 时间带
    - 动作时间线
    - 事件账本与风险动作对照
- “简报”与“数据研究”互不遮挡，减少长页面认知负担。

## 3.3 后端边界演进
- 保持 `/fundamental/*` 作为唯一前端消费前缀。
- 后续将基本面相关路由与聚合逻辑按模块拆分（news/flows/narrative/trading/automation）。
- 对非基本面路由建立“冻结 + 迁移/删除”清单，避免继续污染基本面项目。

## 4. 清理策略与清单（仅规划）

## 4.1 清理原则
- 原则一：先断引用，再删除实体。
- 原则二：优先清理“明确未被基本面入口使用”的前端页面与脚本。
- 原则三：高风险资产先归档（archive），确认无依赖后再物理删除。

## 4.2 建议清理分组

### A 组（优先清理：综合版 UI 遗留）
- `frontend/src/App.tsx`
- `frontend/src/components/*` 中非基本面页面（如 Arena/Strategy/Universe/ModelEvaluation/AgentConsole/CarryTrade/Orders/Signals 等）

### B 组（按依赖评估后清理：非基本面后端与脚本）
- `carry_service.py`
- `tools/` 下与参数优化、交易执行、策略资产同步、非基本面实验相关脚本
- `test_*.py` 中与基本面无关测试

### C 组（按是否仍需运行环境决定）
- `agent_client/`
- `ops/launchd` 中与综合版部署绑定的脚本与 plist
- `币安Skill/` 第三方技能包与压缩文件（已改为保留白名单，不纳入清理）

### D 组（数据资产）
- `user_data/` 下非基本面历史数据、与当前基本面流程无关的数据集

## 10. 三层治理框架（不改代码版，恢复统一口径）

### 10.1 第一层：持续观测（Monitoring）
- 每模块固定 3 个时钟：
  - 更新频率（update_frequency_sec）
  - 最大容忍延迟（max_tolerated_delay_sec）
  - 回填冻结窗口（backfill_freeze_window_sec）
- 每次产出强制字段（硬验收）：
  - `generated_at`
  - `coverage`
  - `quality`
  - `missing_data`
- 验收门槛：
  - 字段缺失即判定为 `quality=missing`，默认降级为只读告警，不进入动作建议。

### 10.2 第二层：转折点（Turning Point）
- 统一判据：`Level + Slope + Stress`。
- 统一契约字段：
  - `turning_point_state`
  - `trigger_reason[]`
  - `confirm_bars`
  - `turning_point_detail.level`
  - `turning_point_detail.slope`
  - `turning_point_detail.stress`
- 统一解释模板：
  - 上行衰减拐点：Level 高位 + Slope 转负 + Stress 上升。
  - 修复拐点：Level 低位 + Slope 转正 + Stress 回落。

### 10.3 第三层：图表化（Chart Pack）
- 每模块最小交付“四宫格”：
  - 主指标时序
  - 分位阈值带
  - 拐点标记
  - 质量/覆盖率条
- 总览页最小交付：
  - 跨模块热力图
  - regime 迁移图
  - 当日门禁动作时间线

### 10.4 跨模块治理一致性
- 将新闻模块“固定模板 + 守卫 + latest 口径”复制到：
  - `flows`
  - `narrative`
  - `trading`
- 图表输出提升为“最小交付物”而非可选项，确保连续观测可形成团队共同语言。
