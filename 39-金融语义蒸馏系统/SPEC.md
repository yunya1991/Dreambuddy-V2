# 39-金融语义蒸馏系统

> **定位**: 金融领域知识的自动化生产基础设施（SSoT）——将代币名、技术指标、交易策略、交易理论等金融术语蒸馏为机器可读的语义字典/知识图谱，供全系统消费
> **版本**: v1.7（§9.10 新增：P-案例——子交易系统真实开单案例+维度快照+盈亏跟踪）
> **日期**: 2026-10-20
> **状态**: 阶段一已落地（语义原型修复项经用户决策暂缓，保持 n-gram 降级，待 API Key 配置后激活）；四层事件流运行中；P-快讯已落地；L1/L2 已完成（L2 含五维量变画像）；P-案例（§9.10）实施中
> **关联**: 34-前端应用训练系统（下游消费方）、SPEC-v1.5-entity-resolution-slot-filling.md（第一个知识产物接管点）

---

## 1. 问题背景

- 交易池扩容（15→19 标的）后，手工维护别名表出现覆盖空窗，badcase（以太坊→BTC）证实手工方式赶不上需求
- 未来知识范围不止代币名：技术指标（MACD/金叉/背离）、交易策略（马丁/网格/趋势跟踪）、交易理论（威科夫/道氏/缠论）均需语义解析
- 34 训练系统已有语义原型机制但断点未激活（prototypes=0 运行 238 轮）

## 2. 模块边界与系统分工契约

### 2.1 模块边界

| 模块 | 职责 | 关系 |
|------|------|------|
| **39 蒸馏系统** | 蒸馏**生产知识**：别名表、术语映射、语义地图 | 上游 |
| 34 训练系统 | **训练学习**：喂入样本、模型迭代、语义原型 | 下游消费 39 产出的知识字典 |

**禁止**：39 不做模型训练，34 不做知识生产——避免职责重复。

### 2.2 知识获取分工契约（v0.2 核心架构：LLM 仅提供线索）

**原则：金融语义知识不全靠大模型。大模型只提供链接/书名/检索关键词等线索，知识内容由系统内零 token 基础设施获取。**

| 角色 | 职责 | token 消耗 |
|------|------|------------|
| LLM | 仅提供链接/书名/检索关键词（线索源），不产出知识内容 | 极低（按次计费） |
| 18-数据获取中心 | 抓取链接内容、清洗、入库 | 零 |
| 33-逆向解析工程 | 结构化解析、术语抽取 | 零 |
| 39-蒸馏系统 | 中心扩散调度、术语蒸馏、权威校验、入库 | 零（除线索调用） |
| 34-训练系统 | 消费术语样本做语义训练 | 零 |

**线索质量闭环**：LLM 提供的链接若抓取失败或内容无关，回流给 LLM 换线索（携带失败原因），设置最大重试次数避免死循环。

### 2.3 中心扩散知识拓展模型（三圈）

以现有系统为核心，由内向外按需扩散——**能用内部资产解决的绝不花 token**：

| 圈层 | 知识源 | 成本 | 触发条件 |
|------|--------|------|----------|
| 第一圈（核心） | 仓库内部金融模块文档（10-经典指标、9-基本面、6-TRADING、23 系统 SPEC 等） | 零 | 阶段二启动即提取 |
| 第二圈（内部数据） | 18 中心已采集的行情/链上/宏观数据 + 交易日志，逆向归纳术语实操语义 | 零 | 第一圈未覆盖时 |
| 第三圈（外部定向） | LLM 提供链接 → 18 中心抓取 → 33 解析 → 39 蒸馏入库 | 仅线索费 | 内部两圈均未覆盖时 |

**扩散触发信号**：澄清追问日志中未识别的术语（用户缺什么才扩散什么，按需拓展，禁止全量预跑）。

## 3. 两阶段规划

### 阶段一：代币别名蒸馏 + 语义原型修复（当前）
1. **语义原型断点修复**【暂缓，用户决策 2026-10-17】：根因已确认（DEEPSEEK_API_KEY 为空 + 嵌入模型名配置错误 deepseek-chat 应为专用嵌入模型）；按用户决策暂不配置密钥，保持 n-gram 降级模式，待 API Key 配置后激活
2. **字典自动蒸馏管线**：
   - 蒸馏源：交易所 API 币种列表（权威源校验：代号必须真实存在）
   - 蒸馏方式：LLM 批量生成中英文别名（含俗称/错拼变体）
   - 产出物：entity_aliases.json（接管 SPEC v1.5 的手工别名表）
   - 触发：扩容事件自动触发 + 每日增量蒸馏
3. **验收**：扩容新标的后 24h 内别名表自动覆盖；蒸馏产物经权威源校验零幻觉代号

### 阶段二：全领域术语蒸馏（v0.2 按中心扩散架构修订）

**目标术语域**：技术指标（MACD 金叉/死叉/背离/超买超卖…）、交易策略（马丁格尔/网格/趋势跟踪/事件驱动…）、交易理论（威科夫累积期/道氏趋势/缠论中枢…）

**实施步骤（按三圈扩散顺序）**：
1. **第一圈提取**：从仓库内部金融模块文档批量提取术语与定义，产出 indicator/strategy/theory_terms.json 雏形（零 token，可立即启动）
2. **第二圈归纳**：从 18 中心已采集数据与交易日志逆向归纳术语的实操语义（如从 BCRM 交易记录归纳『连续性背离』实操含义）（零 token）
3. **第三圈外采**：内部未覆盖的术语，LLM 提供链接/书名线索 → 18 中心抓取 → 33 解析 → 39 蒸馏入库（仅线索费，需 DEEPSEEK_API_KEY）
4. **质量分级**：A 级（内部文档佐证）直接入库；B 级（外部单一来源）抽检后入库；C 级（推断）仅进候选池

**启动条件**：澄清追问日志出现该类术语解析需求（按需扩散，不全量预跑）

**验收标准**：
- 第一圈提取零 token 完成三大术语域雏形表
- 第三圈外采的每条术语带出处链接，抓取失败率 <30%（超限回流换线索）
- 蒸馏产物经权威校验零幻觉代号/术语

## 5. 子交易系统：蒸馏、训练与优化（v0.4，核心能力）

子交易系统（BCRM2.0/BDSM/战略层/事件驱动/自进化等）不仅是蒸馏知识的消费方，其本身也是蒸馏与优化的对象——这是 39 模块的核心能力延伸。

### 5.1 子交易系统知识蒸馏

| 蒸馏对象 | 知识产出 | 来源 |
|----------|----------|------|
| 策略语义 | 各子交易系统的策略术语、参数语义、信号含义 | 内部 SPEC/文档（第一圈）+ 交易日志逆向归纳（第二圈） |
| 决策语义 | 信号→裁决→下单的决策链语义（如 ElasticGate3L、BCRM 连续性） | 交易日志 + 23 系统管线日志 |
| 风控语义 | 风控规则、仓位约束、熔断条件的语义化 | 13-通用风控模块 + 16-调控系统文档 |

### 5.2 子交易系统模型训练

- 蒸馏产出的策略/决策/风控语义样本进入 34 训练系统的 S 层训练流
- 训练目标：意图识别与槽位提取覆盖子交易系统查询（如『BCRM 连续性怎么样』『马丁策略当前仓位』）
- 训练数据源：交易日志（每轮 Trading 采集器 10 条）+ 蒸馏术语样本

### 5.3 优化上线门禁（严格三步，禁止跳步）

子交易系统的任何优化（参数调整/策略变更/模型迭代）上线必须依次通过：

| 步骤 | 门禁 | 通过标准 |
|------|------|----------|
| **1. 回测验证** | 历史数据回测 | 关键指标（收益/回撤/夏普）**高于当前基线**，未达标禁止进入下一步 |
| **2. 影子模式** | 实盘并行影子运行（不产生真实订单） | 影子期 ≥7 天，信号与基线偏差在预期范围内，无异常行为 |
| **3. 灰度放量** | 小资金比例实盘 | 从试错仓（如 0.10）起步，按表现逐级放量，任一级异常立即回滚 |

**回滚保障**：每级放量前自动快照（沿用 23 系统基因版本快照机制），异常触发回滚至上一稳定版本。

### 5.4 逆向重构能力（终极形态）

系统成熟后，可基于 33-逆向解析工程对子交易系统进行**重构级优化**：

- 33 逆向解析子交易系统的真实运行行为（信号质量、决策链效率、风控有效性）
- 发现架构级缺陷（如决策链冗余、信号冲突未裁决）时，产出重构方案
- 重构方案同样必须通过 §5.3 三步门禁（回测→影子→灰度）后方可替换现有子交易系统
- 重构后的子交易系统语义回流 39 知识中心，完成『蒸馏→训练→优化→重构→再蒸馏』的完整闭环

## 7. 时序语义扩展（v0.7：广泛对应 + 复杂语义衍生）

### 7.1 术语-语义广泛对应（P2）

现状缺口：第一圈 1454 条术语，第二圈仅 6 条实操语义（受限于手工模式枚举）。

对应路径：
1. **模式扩展**：归纳脚本匹配模式从 6 个扩展至五大术语域核心术语（BCRM/BDSM/EV雷达/卦象/置信度/仓位类术语在日志中均有稳定格式化输出）
2. **反向活跃度统计**：对第一圈术语做日志全文检索，标注每条术语的实操活跃度——高频实操（优先深化）/文档术语（仅理论存在）/零活跃（候选清理）
3. **产出**：`term_semantic_map.json`——每条术语挂接文档定义 + 实操语义 + 活跃度分层

### 7.2 语义事件流（P1，复杂语义的数据基础）

术语出现记录升级为**语义事件**：

```
语义事件 = {术语, 时间戳, 标的, 取值, 市场上下文(价格/波动率/情绪指标), 后续结果(N小时后涨跌)}
```

- 产出：`semantic_events.jsonl`（持续追加流）
- 价值：为 34 训练系统 S 层提供时序训练样本（DataQueryIntent 目前仅静态问答对，语义事件流补足时序维度）

### 7.3 复杂语义衍生（P3，事件流积累 ≥7 天后启动）

在语义事件流基础上衍生的描述性复杂语义（金融价值高）：

| 语义类型 | 描述 | 示例 |
|----------|------|------|
| 时序共现语义 | 术语倾向同时/先后出现 | 『BCRM背离』后 2h 内『反向软权重』触发率 |
| 状态语义 | 取值分布随市场状态切换 | 恐惧贪婪 >75 时 DIVERGE_BASIC 占比 vs <25 时 |
| 术语-结果时间关联 | 触发后 N 小时标涨跌分布 | 描述性统计，非交易信号 |
| 语义演化 | 取值分布漂移检测 | 与 23 系统 drift 检测能力衔接 |

### 7.4 边界红线（强制）

1. **描述/决策边界**：39 产出的复杂语义是**观察性知识**（发生了什么/如何分布/如何关联），不直接产生交易信号；决策语义归 23 系统。任何描述语义升级为决策输入，必须走 §5.3 三步门禁（回测→影子→灰度）
2. **统计有效性边界**：衍生语义必须标注样本量与证据强度——n<30 的关联仅进候选池标注『弱证据』；防范多重检验伪发现（术语×状态×时间窗口组合爆炸中的假相关）

**实际执行状态（2026-10-18 更新）**：P1 / P1a / P1b / P3 均已完成并自动运转（P3 因回填数据跨度 31 天直接通过阈值门禁，首轮已产出共现 21 对/状态 2 分区/因果候选 6 项）；**P2（term_semantic_map.json 广泛对应）待排期**，计划于 P-快讯实施后启动，验收标准：产出 1454 条术语的实操活跃度三层分层（高频实操/文档术语/零活跃），作为 algorithm 域 1078 条噪声治理（人工抽检清理）的定位输入——**P2 与术语表噪声治理绑定推进**

## 8. 分层语义事件流架构（v0.8：生物学式四层构建）

### 8.1 四层架构

```

   ↓ 组合
分子层（P1，已运行）：术语判断事件（BCRM连续性/弹性门控/置信度信号等，持续增长中，以 semantic_events.jsonl 实际文件为准）
   ↓ 聚合
细胞层（P1b）：聚合语义事件（单因子时间序列 / 跨因子聚合状态 / 多因子聚合离散度）
   ↓ 衍生
组织层（P3）：复杂描述语义（时序共现 / 状态语义 / 结果关联 / 语义演化）
```

- **原子层（P1a）**：18 中心数据（资金费率/恐惧贪婪/持仓量/多空比/TVL 等）与 10 系统技术指标（MACD/RSI/ATR/布林带等）的**状态变化事件**——变化驱动（越线/转正负/分位跃迁才记录），非全量取值记录，控制数据量
- **分子层（P1）**：当前已运行的术语事件流（判断级事件）
- **细胞层（P1b）**：按时间窗口（如 1h）聚合——单因子时间序列、跨因子聚合状态、因子间离散度（Transformer 式：单因子时间=head 独立编码，聚合体时间=多头融合，多因子离散度=注意力熵/冲突度量）
- **组织层（P3）**：复杂描述语义衍生（§7.3）

### 8.2 描述性定位（与 23 系统的职责分界，强制）

**本模块是客观观察系统：只记录、统计、描述系统与市场数据『发生了什么、如何分布、如何关联』。**

| 维度 | 39 本模块 | 23 自进化系统 |
|------|-----------|---------------|
| 定位 | 描述性客观观察 | 决策性因子裁决 |
| 产出 | 观察性知识（事件流/分布/关联统计） | 维度力量/矛盾裁决/交易信号 |
| 因子聚合 | 记录离散度的分布与演化（描述） | DimensionForce 聚合参与决策 |
| 门禁 | 无需交易门禁（不产生信号） | 回测→影子→灰度三步门禁 |

数据可互通（39 的离散度事件流可作为 23 维度力量的观测镜像），但职责不重叠。

### 8.3 因果对应体系与 23 优化反哺闭环（核心价值）

当本模块的统计性因子与结果呈现**一致趋势性**（类因果对应）时，为 23 自进化提供优化基础：

```
39 描述层：统计『因子 X 触发后 N 小时标的结果分布』
   ↓ 呈现一致趋势（如某因子触发后 70% 概率同向，n≥30）
因果对应登记：该因子-结果对进入因果候选池（带样本量/置信度/时间窗口标注）
   ↓ 反哺
23 自进化层：因果候选作为进化提案输入（WalkForward 验证）
   ↓ 通过 §5.3 三步门禁（回测→影子→灰度）
23 系统优化落地（维度权重/裁决规则调整）
```
**反哺边界**：39 只提供『因果候选证据』（描述性统计），不直接改 23 的决策参数；23 按其既有治理流程（提案→WalkForward→门禁）消化证据。这保证了优化有据可依，且决策责任仍在 23 的门禁体系内。

### 8.4 实施顺序

P1a 原子事件采集（零 token，变化驱动模式）→ P1b 聚合层（零 token，窗口聚合）→ P3 组织层复杂语义（三层事件流积累 ≥7 天后启动）

## 9. 实时快讯外部训练（v0.9：真实场景语义能力）

数据基础已就绪：18 中心已有星球日报快讯采集（newsflash 记录），每条含 description（正文）、tickers_hit（命中代币）、od_event_type（事件类型标注）、published_ms（时间戳）——od_event_type 提供天然训练标签，样本近乎零成本获得高质量标注。

   - tickers_hit → 实体关联样本（快讯↔代币语义关联）
3. 验收：快讯样本进入 S 层训练流，事件类型识别准确率可度量

### 9.3 P-术语：新术语表族扩展

|--------|-----|--------|

### 9.4 P-权重：内外样本权重机制

核心矛盾：本地知识有序高质量 vs 外部快讯无序但鲜活。权重机制：

1. **初始权重分层**：本地蒸馏样本（quality=A/B）初始权重高；快讯样本初始权重低
2. **动态可信度调整**：快讯事件被后续行情/其他快讯印证 → 权重上调；被证伪 → 降权
3. **来源可信度画像**：按媒体/事件类型统计历史可信度，系统自动学习外部信息源的可信分布

### 9.5 P-矛盾：矛盾体语义识别（认知层，与 23 系统哲学同构）

语义识别的两层价值：
- **识别层（首要）**：快讯实体/事件/情感的准确解析——P-快讯与 P-术语解决
- **矛盾层（深层）**：主要矛盾与次要矛盾的发展变化关系识别——宏观与微观（美联储加息 vs 单币利好）、个体与整体（某项目暴雷 vs 板块情绪）、短期与长期（恐慌快讯 vs 长期趋势）

实现路径：快讯事件作为新原子类型接入四层事件流（§8），与内部因子事件的共现/冲突统计经 P3 复杂语义自动衍生『内外矛盾』描述性知识——矛盾体识别不新建机制，复用分层事件流架构自然生长。

**依赖关系**：P-术语是 L2 规则聚类的词典基础；P-权重/P-矛盾/L3 被同一时间约束阻塞（快讯数据积累 ≥7 天，提频 2026-10-18 生效，最早 10-25 达标）。

**整体优先级（时间轴排序，等待期无空转）**：

### 9.7 事件语义递进服务（v1.2：前端交互侧的三级递进能力）

**定位**：四层事件流架构在前端交互侧的价值出口——用户查询『最近货币政策等事件』时，系统按三级递进提供语义能力，与 34 训练形成闭环（查询越多，事件语义训练样本越丰富）。

| 级别 | 能力 | 对应架构层 | 实现要点 |
|------|------|------------|----------|
| **L1 罗列整理** | 按类型/时间罗列事件 | 分子层事件 | 前端事件查询意图 + 执行器按 event_type 过滤快讯，按时间倒序罗列（标题/时间/关联代币/情绪） |
| **L2 语义聚合+变化描述** | 同主题事件一致聚合，叠加时间标签，描述事件语义演变 | 细胞层聚合 + P3 状态/演化语义 | 第一步规则聚类（事件类型+关键词重叠+关联代币）产出事件线与统计变化（频次/情绪均值）；第二步（API Key 后）语义嵌入聚类升级为语义口径变化描述 |

**设计原则（强制）**：
1. **递进不跳级**：每级验证通过后升级，L1 准确性是 L2 聚合基础，L2 事件线质量是 L3 综合输入
2. **描述/判断边界贯穿**：L1/L2 纯描述；L3 的『判断』仍是观察性结论（矛盾状态/背离程度/演化方向），交易决策归 23 门禁体系（§8.2/§8.3）
3. **复用不新建**：三级全部消费现有四层事件流与 P3 框架，前端只增加查询意图与展示层

**实施路径**：
- L1 事件罗列服务（1 天）：立即可实施【✅ 已完成 2026-10-18】
- L2 事件线聚合（2-3 天）：规则聚类先行，API Key 后语义增强【✅ 已完成 2026-10-18，含量变统计分布增强】
- L3 多因子矛盾综合（快讯事件流积累 ≥7 天 + P-权重落地后）：窗口对齐综合，产出描述性复杂语义结论

**层间建议式引导钩子（v1.3 新增）**：

借鉴 ChatGPT 后续建议 / Perplexity 相关问题 / 渐进式披露等成熟模式，在执行器响应中增加 `next_layer_hint` 可选字段：

2. **动态生成**：基于当前响应实际内容生成（如 L1 罗列中哪类事件最多，就引导该主题的 L2），非固定文案
3. **信号驱动优先**：L2 检出量变加速积累/情绪转向等信号时，钩子从泛建议升级为精准提示（『该主题量变正在加速积累，是否深入观察？』）
4. **训练闭环**：用户点击钩子的行为回流 34 训练，优化引导策略
5. **L2→L3 钩子留接口暂不展示**（L3 未上线）

**量变统计分布（v1.3 新增，L2 增强）**：

量变引发质变是矛盾转化的关键。每条事件线新增量变字段：

| 量变积累→释放 | 自组织临界性（沙堆模型） |
| 质变预警 | 临界慢化（相变前方差/自相关上升） |
| 稳定孕育不稳定 | 明斯基时刻（金融不稳定假说） |
| 板块叙事周期 | 叙事经济学（Shiller，S 曲线传播） |
| 矛盾转化 | Regime Shift（状态突变检测） |

### 9.9.2 四项加固改进

1. **补『度』的概念**：为每个观测量定义历史正常区间（度），量变信号增加『距度边界的距离』维度——黑格尔逻辑学中量变观测的完整形态
2. **增加临界慢化指标**：quantity_signal 之外增加窗口方差趋势与自相关趋势——复杂科学验证的相变前兆，比单纯频次加速更接近关节点
3. **阈值经验校准**：回测历史量变信号与后续行情关系，用数据校准『2 倍/z1.5』先验阈值，并预注册（禁止事后调整）
4. **叙事纪律（强制原则）**：每个哲学命题必须映射到一个预注册统计量——凡不能映射的哲学表述只留在文档理念部分，不进入代码

### 9.9.3 实施状态

- 改进 1/2（度区间 + 临界慢化）：随 §9.8 第一/二批实施落地
- 改进 3（阈值校准）：待事件流积累后回测执行
- 改进 4（叙事纪律）：即刻生效，作为后续所有 SPEC 增补的准入原则

## 9.10 P-案例：子交易系统真实开单案例 + 维度快照 + 盈亏跟踪（v1.7）

### 9.10.1 定位与价值

将子交易系统（BCRM2.0 / BDSM / 宏观战略层 / 事件驱动策略 / 自进化）的**真实开单案例**接入本系统观察体系：每笔开单在决策时刻挂接五维量变快照（量/情/时/空/频）与决策上下文（七维矛盾/置信度/卦象/regime），并全生命周期跟踪盈亏结果。

- **本质**：§7.2 语义事件『后续结果』字段的实证升级——从行情涨跌升级为真实盈亏，理论与实践结合的标注体系
- **架构归属**：开单案例作为新事件类型接入分子层事件流（复用不新建，§9.7 原则）
- **护城河**：真实决策数据是 §11.8.2 定义的最稀缺训练资产，案例+快照+盈亏直接增厚护城河

### 9.10.2 案例快照结构

```
开单案例 = {
  trade_id, coin, direction(long/short), strategy_source(子系统标签),
  entry_time, entry_price, exit_time, exit_price,
  决策上下文: confidence, hexagram, contradiction_list(C1~C7), regime_pred, market_snapshot,
  五维快照(开单时刻窗口对齐原子事件流): 量维(放量/缩量) / 情维(极值状态) / 时维(盘整+周期) / 空维(斐波那契) / 频维(事件线量变信号),
  全生命周期结果: pnl, pnl_pct, exit_reason, 持仓时长, reduce_count,
  质量等级: A(字段完整) / B(部分缺失) / C(关键字段缺失，仅候选)
}
```

### 9.10.3 统计口径（描述性，强制边界）

1. **分组统计**：按 方向 × 子系统 × 维度状态 分组统计胜率/均盈亏/盈亏比
2. **证据强度**：n≥30 出正式描述性结论；n<30 仅进因果候选池标注『弱证据』（沿用 §7.4）
3. **边界红线（强制）**：本系统只输出描述性统计（『历史 n 笔案例中，某维度状态下 long 胜率 X%』），**不输出『看多/看空更有利』的方向性建议**；统计作为因果候选证据反哺 23 自进化系统，是否据此调整开单方向归 23 门禁体系（回测→影子→灰度，§5.3/§8.3）
4. **数据质量标注**：早期记录部分字段为空（contradiction_list 空/非真实卦象），回填时标质量等级，低质量样本不进入正式统计

### 8.2 护城河定义（大模型厂商无法复制）

1. **领域知识资产**：39 蒸馏中心持续积累的金融语义字典（含真实交易归纳的实操语义）
2. **自我进化闭环**：33 逆向解析 → 39 蒸馏修正 → 34 重训练 → 前端改善的零 token 数据飞轮
3. **真实决策数据**：子交易系统的真实信号、裁决、盈亏记录（最稀缺训练资产）
4. **严格门禁体系**：回测→影子→灰度上线门禁（金融级风控纪律）

护城河厚度 = 知识字典厚度 × 自进化迭代次数 × 真实交易数据量（随时间复利增长）

## 12. 附录：传统金融 AI 训练方法对照评估（v1.0）

### 12.1 业界成熟方法体系

| 项目/方法 | 核心方法 | 训练范式 |
|-----------|----------|----------|
| FinGPT（AI4Finance） | 金融大模型微调框架 | 数据源分层（新闻/公告/社交媒体）→ LoRA 高效微调 → 情绪分析等下游任务 |
| FinBERT（ProsusAI 等） | 金融领域 BERT | 金融语料继续预训练 → 金融情绪三分类基准（正/负/中性） |
| FinRL（AI4Finance） | 金融强化学习 | 市场环境建模 → DRL 智能体 → 内置回测框架 |
| Qlib（微软） | 量化投资平台 | 数据→因子→模型→回测全流程，因子注册-评估-淘汰流水线 |
| FinNLP 研究共识 | 金融 NLP 任务族 | 情绪分析、事件抽取、实体识别、文本相似度、风险预警 |

### 12.2 对照评估结论

**已对齐或领先**：
1. 数据源分层（对标 FinGPT）：34 训练 29 个采集器，分层粒度更细
2. 领域自适应（对标 FinBERT）：五大术语表+实操语义持续蒸馏，优于一次性预训练
3. 事件抽取与实体识别（对标 FinNLP）：快讯 od_event_type 天然标注 + 实体别名表
4. 回测门禁（对标 FinRL/Qlib）：回测→影子→灰度三步门禁更严格

**存在差距、可借鉴的三点**：
1. **金融情绪分类基准缺失**（借鉴 FinBERT）：缺标准三分类基准与情绪标签维度
2. **因子工程化不足**（借鉴 Qlib）：P3 因果候选池缺因子注册表与统一评估口径
3. **模型资产未沉淀**（借鉴 FinGPT LoRA）：S 层为轻量统计模型，语义原型因 API Key 未配置处于降级，无自有模型资产

### 12.3 优化路线（按优先级）

| 优先级 | 优化项 | 内容 | 时机 |
|--------|--------|------|------|
| 短期 | 情绪标签维度 | 快讯样本增加情绪三分类标签（正/负/中性），与事件类型标签并行。**标注口径**：初期用规则+关键词词典标注，FinBERT 类模型预标注作为中期增强（需 API/模型资源），人工抽检校准贯穿 | 随 P-快讯实施 |
| 中期 | 因子注册表 | P3 因果候选池升级为因子注册表（名称/口径/样本量/历史表现/状态），Qlib 式生命周期管理，与 23 进化提案规范衔接 | P3 稳定运行后 |
| 中期 | LoRA 微调小模型 | 密钥配置后评估 LoRA 微调 1-3B 开源模型承载金融语义理解，替代纯 API 嵌入——一次微调长期复用，模型资产沉淀为护城河 | API Key 配置后 |
