## 3. 影响力评分（零 token、可解释）

### 3.1 公式

```
importance = 100 × ( 0.30·T + 0.25·S + 0.20·R + 0.15·Src + 0.10·C )
```

| 项 | 含义 | 取值 |
|---|---|---|
| `T` 类型权重 | 事件类型的基础量级 | 见 §3.2 |
| `S` 情绪强度 | `abs(sentiment.score) × confidence`，缺失=0 且打 `sentiment_missing` | [0,1] |
| `R` 时效衰减 | `0.5 ** (age_h / half_life_h)`，half_life 取事件行自带值（24/48） | (0,1] |
| `Src` 来源权重 | 一手/官方源高，聚合门户低 | 见 §3.3 |
| `C` 多源印证 | `min(1, 0.5 + 0.5·log2(1+source_count)/log2 3)`；单源 0.5 / 双源 0.815 / 三源 1.0 | [0.5,1] |

> **对初稿的修正（评审点 R-1）**：初稿第 5 项为「新颖度」，与「多源交叉验证提升可信度」方向相反——重复转载本身不产生新信息，但**多源同时报道是可信度信号**。故改为「多源印证 C」，去重收益另以 `stats.dedup_saved` 观测，不混入公式。

### 3.2 类型权重 T（读 18 的 `event.type`，不改枚举）

| type | T | type | T |
|---|---|---|---|
| rate_decision | 1.00 | regulatory | 0.80 |
| fomc / cpi / nfp | 0.95 | legal / mna | 0.75 |
| earnings / guidance | 0.85 | buyback / dividend | 0.60 |
| product | 0.50 | macro_other | 0.40 |
| 未知/缺失 | 0.40 | | |

### 3.3 来源权重 Src（18 的 `source`）

| source | Src | source | Src |
|---|---|---|---|
| sec_edgar / fed_calendar | 1.00 | cls | 0.75 |
| macro_calendar | 0.90 | sina_finance | 0.70 |
| jin10 / wallstreetcn | 0.80 | 其他/缺失 | 0.60 |

> 权重集中定义为 39 脚本顶部常量 `TYPE_WEIGHT / SOURCE_WEIGHT`，不散落在函数里；改权重不需要动公式。

### 3.4 分档与展示口径

| importance | 档位 | 前端样式 |
|---|---|---|
| ≥ 70 | 高影响 | 红/橙徽标 |
| 50–70 | 关注 | 黄徽标 |
| < 50 | 一般 | 灰徽标 |

情绪标签：`score > 0.15` 利好、`score < -0.15` 利空、其余中性（阈值写成常量 `SENTIMENT_THRESHOLD`，与前端标签解耦——前端只读 39 给出的 `label`）。

### 3.5 已知局限（必须在文档与 UI 中如实呈现）

1. **情绪项半数为 0**：P-H6 实测 P50=0，中性标题得 0 分。因此排序主要由 T/R/Src/C 决定，情绪只做「同类型内加分」。这也是影子阶段要校准的主因（§8）。
2. **类型项偏科**：`macro_other` 占 80% 且 T 只有 0.40，会让大量宏观快讯被系统性压低。缓解：主题簇兜底 + P1.5 扩词表（§7）。
3. **不含正文深度**：`title.80 + body` 已是 FinBERT 输入，但榜单标题只展示标题；正文不作为评分输入之外的内容展示，避免版权与体积问题。
4. **单源上限 95 分**：`C` 单源取 0.5，故单源事件满分 0.95×100=95；这是刻意的（独家未被印证，不给满分）。
5. **confidence 区分度低**：实测 confidence 集中在 0.98–0.999，`S≈|score|`；保留乘积仅为对齐 9 域口径，不构成额外信号。

## 4. 主题簇与去重

### 4.1 主题簇 `topic`（39 自有，不改 18 type）

|---|---|---|

| inflation | 通胀 | CPI/PCE/通胀/物价/核心通胀 |

| crypto_reg | 加密监管 | 加密/比特币/以太坊/稳定币/ETF/SEC/币安/Coinbase/哈里斯 |
| geopolitics | 地缘政治 | 战争/袭击/制裁/胡塞/俄乌/中东/关税/贸易战/停火 |
| earnings | 财报业绩 | 财报/业绩/营收/净利润/EPS/指引/预警 |
| capital_action | 资本运作 | 收购/并购/回购/分红/减持/增持/IPO/私有化/评级 |

- 命中多个 → 取表中**最靠前**的一个（保证簇计数可加、总和=总数）。
- `topic` 与 `type` 正交：`type` 回答「是什么事件」（18 定义），`topic` 回答「属于哪个叙事」（39 定义）。

### 4.2 去重规则（同源内 + 跨源）

> **v0.9→v1.0 修订（评审 C1）**：初稿只做「去标点 + 4-gram Jaccard≥0.82」，实测会漏掉大量跨源镜像。同一快讯经门户转载时常带前缀/代码后缀（`财联社11月13日电，` / `金十数据整理：` / `据纽约时报：` / `英伟达(NVDA.O)`），这些噪声把真重复的 Jaccard 压到 0.55–0.77（实测样本）。

1. **Boilerplate 归一化**（必须，先于相似度计算）：
   - `NFKC` → 去 `【…】` 标记 → 去源前缀 `^(财联社.{0,6}电[，、,]?|金十数据整理[：:]|市场消息[：:]|快讯[：:]|据[^，。：:]{2,14}[：:])` → 去证券代码后缀 `\([A-Z0-9.]{2,12}\)` → 小写 → 去空白/标点。
   - 归一化后保留数字（`2.5亿` 与 `3亿` 必须区分）。
2. **相似判定（双条件或）**：
   - 字符 4-gram Jaccard ≥ **0.78**，或
   - `difflib.SequenceMatcher.ratio() ≥ 0.90`（覆盖「正处于 / 正处在」这类改写）。
   - 第二守卫：二者 `event.type` 相同且 `symbols` 有交集，才允许合并（防跨主题误合并）。
3. 聚类窗口 48h（榜窗口 24h，留缓冲避免跨日重复）；仅比较 `source=="events.jsonl"` 的行。
4. 簇代表：簇内 importance 最高者；`source_count` = 簇内不同 `origin` 数；`dup_count` = 成员数−1。
5. **实测边界（2026-11-13，最后 400 行 events 源）**：真重复归一化后 Jaccard 0.85–1.00；「美联储戴利」不同表态 0.03–0.19；同句改写 Jaccard 0.60 / ratio 0.95。阈值必须用这批真实样本做回归（§9）。
6. 性能：24h ≤ 500 行，两两比较（≤12.5 万次小集合运算）< 1s；不引入 SimHash/向量。

### 4.3 为何不改 18 的 type（边界声明）

`type` 是 18 事件流的对外契约（[SPEC-EMERGENCE](../../48-涌现架构/) 口径），39 侧改词表会造成「同一事件两种类型」。`macro_other` 过粗的根治属于 18（扩词表 / 细分枚举），列为 **P1.5 跨域变更**，需单独确认（§10 Q2）。

### 4.4 39 事件行新增字段（向后兼容，旧行不重写）

| 字段 | 类型 | 说明 |
|---|---|---|
| `origin` | str | 18 原始来源（jin10/sina_finance/…），补上 P-H5 丢失的信息 |
| `source_url` | str\|null | 原文链接（来自 18 `source_url`） |
| `topic` | str | §4.1 主题 |
| `importance` | float | 0–100，保留 1 位 |
| `importance_parts` | obj | `{type,sentiment,recency,source,corroboration}` 各 0–1，保留 3 位 |
| `cluster_id` | str | 簇代表 `trace_id`；代表自身也填自己 |
| `sentiment_missing` | bool | 仅当 `sentiment` 缺失时置 true；**禁止用 0 冒充已打分** |

未打分（`sentiment=null`）的事件：仍计算 importance（S=0）但**不进榜**，计入 `stats.unscored`，并让 `degraded` 可观测。

### 4.5 旧行补算（评审 M4）

`semantic_events.jsonl` 存量 21550 行不会重写，新字段只出现在新行。若只看新行，上线首日 24h 窗口内几乎全是「无 topic/importance」的旧行，榜单会稀疏。

规则：聚合时对 24h 窗口内的 events 源行做**只读补算**——
- `topic` / `importance` / `importance_parts` 用同一纯函数现场算（输入齐全：`event.type`、`sentiment`、`timestamp`、`half_life_h`）；
- `origin` 缺失时 `Src` 兜底 0.60、`C` 兜底 0.5，并在产物中标记 `recomputed: true`；
- 不修改 `semantic_events.jsonl`（保持 append-only 契约）。

## 8. 验收指标与影子运行

| 编号 | 指标 | 判定方式 | 目标 |
|---|---|---|---|
| A-1 | Top10 相关性 | 连续 3 天、每天人工抽检 10 条（是否「值得关注」二元判断） | 相关率 ≥ 70% |
