## 1 · Major 问题

### M1: 数据口径陈旧不一致 ⚠️

SPEC 多处数字停留在旧版本：§6 产出物契约写『五大术语表 1434 条』『finance 156 / algorithm 1068』，实际当前为 1454 条（finance 166 / algorithm 1078，种子术语补充后）；§8.1 写『分子层 14090 条』，实际持续增长中（事件流为动态数据，写死数字必然过时）。

**影响**：SSoT 文档自身数字失真，后续按 SPEC 验收会误判。

**修订要求**：动态数据（事件流条数）改为『持续增长，以实际文件为准』；静态产出（术语表）更新为当前值并注明统计时点；建议在 §6 增加一行『数据口径以 2026-10-18 快照为准，动态数据不写死』。

### M2: 阶段一遗留项与状态声明不符 ⚠️

§3 阶段一含『语义原型断点修复』任务，状态行写『阶段一已落地』，但实测语义原型仍为 0（DEEPSEEK_API_KEY 为空 + 嵌入模型名配置错误，用户已决定暂不配置密钥保持 n-gram 降级）。§12.2 也承认『语义原型因 API Key 未配置处于降级』。

**影响**：『阶段一已落地』的表述与语义原型未修复的事实矛盾，状态口径不严谨。

**修订要求**：状态行改为『阶段一已落地（语义原型修复项经用户决策暂缓，保持 n-gram 降级，待 API Key 配置后激活）』；§3 阶段一对应任务标注暂缓状态与决策依据。

### M3: P2（术语-语义广泛对应）规划悬空 ⚠️

§7.5 实施顺序为 P1→P2→P3，但 P3 已于 10-17 提前完成首轮（因回填数据跨度 31 天直接过阈值），P2（term_semantic_map.json，模式扩展+反向活跃度统计）至今未实施且无排期。P3 的共现/因果统计实际只消费了分子层术语事件，未覆盖 P2 规划的『1454 条术语活跃度分层』。

**影响**：规划顺序与实际执行顺序脱节；术语表噪声治理（algorithm 1078 条含泛词）依赖 P2 的活跃度分层来定位清理目标，P2 悬空导致治理无抓手。

**修订要求**：①§7.5 更新为反映实际执行（P1/P1a/P1b/P3 已完成，P2 待排期）；②明确 P2 排期与验收（活跃度三层分层产出，作为术语表人工清理的输入）；③algorithm 域噪声治理与 P2 绑定。

## 2 · Minor 问题

### m1: 维度二/三（认知语义/架构语义）无实施路径
§4.1 定义了 cognitive_terms.json 与 architecture_terms.json，但全文无对应实施步骤与排期。建议标注『长期规划，待维度一成熟后启动』，避免读者误认为在建。

### m2: 快讯采集提频的执行主体未明确
§9.2 写『18 中心快讯采集频率提升至 5-10 分钟』，但未指明改哪个采集器/调度配置（18 中心为 datacenter-scheduler 统一调度）。实施时需先定位快讯采集器的调度项，建议补充配置路径。

### m3: 情绪标签的标注口径未定义
§12.3 短期项『快讯样本增加情绪三分类标签』未定义标注方式（人工/规则/模型预标注+抽检）。建议明确：初期规则+关键词词典标注，FinBERT 类模型预标注作为中期增强。

### m4: MCP 工具清单与实际注册存在表述差
§11.3 列四工具为『规划』，实际 mcp_server.py 已实现并注册。建议状态更新为已落地，与 §0 核验表一致。
