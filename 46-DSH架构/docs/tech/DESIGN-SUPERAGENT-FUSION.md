## 一、融合总纲:借壳灌芯,A→B 两步走

**一句话:用它的壳(事件驱动骨架),灌我们的芯(L0 供给 + A 层验收 + 45 门禁)。**

Super-agent 原型是标准 Harness bundle,而我们的 DSH 就是 DeepSeek Harness——这意味着它的 Router/Worker/Watchdog 骨架可以**原样装入独立 profile 运行**,不需要移植。

> ⚠️ **可行性前置(评审 M1)**:"灌芯"假设 bundle 存在上下文注入 hook 点,但 Inline&Spill 是 prototype 内部实现而非 Harness 标准接口。**SPEC#2 G0 先核实 store.py/session.py;若 hook 点不存在,本章"灌芯"降级为:A 步仅借壳观察,灌芯改走 B 步自研。**它真正的"空心"处在三处,恰是我们的长板:

| 它的"空心" | 灌入我们的"芯" |
| --- | --- |
| 上下文只有会话历史(Inline & Spill) | L0 fetchContext 六维供给(实时数据/SKILL/知识/经验/案例/REA) |
| 验收靠 Worker 自报 done | A 层 OKR verify + 45 评测门禁(Evidence Bundle) |
| 沉淀只有 Session 历史 | settle → **广义认知系统五系统**(认知经验/SKILL 可复用流程/调研知识(后期含 REA+做梦器路径寻优训练)/文档/索引)→ 下次 recall 命中(自进化) |

**两步走**:
- **A 步·借壳验证**(= SPEC#2 P0):bundle 装入独立 profile,跑通"它的骨架+我们的芯"最小闭环,验证价值;
- **B 步·机制吸收**(= SPEC#3 + SPEC#2 P1/P2):验证有效的机制,自研内化进 L1/A/C 层内核,壳退役。

A 步回答"值不值得",B 步回答"怎么长在我们身上"。

## 二、融合原则(红线)

| # | 原则 | 含义 |
| --- | --- | --- |
| P1 | **单向依赖,可卸载** | Super-agent 机制只以 bundle/profile/开关形式存在;DreamOS 内核永不依赖它 |
| P2 | **FAIL-OPEN** | 融合层任何异常 → 回到现有行为,等价"融合不存在" |
| P3 | **不双写状态** | 状态只落 L0(PG/认知库),不维护第二套 Store;它的 Store 仅作运行时缓存 |
| P4 | **自吃狗粮** | 融合模块自身的开发验收也走 45 评测门禁 |

## 三、十个融合点(F1–F10)

| # | 它的优点 | 嫁接位置 | 融合机制(巧妙点) | 归属 |
| --- | --- | --- | --- | --- |
| F1 | Trigger 统一抽象 | L1 事件网关入口 | 事件契约直接落在零 token 层,它的两级过滤升级为我们的**三级梯度**(过滤→确定性闭环→L2) | SPEC#3 P0 |
| F2 | Thread 订阅直通(省 30% 决策) | L1 黏性路由 | **直通判据独立设计:thread_id 亲和表 + TTL**(评审 M2 修正:route_confidence 是"L1/L2 分流置信度",与会话亲和是不同函数,不可复用,仅作降级参考输入) | SPEC#3 P1 |
| F3 | Ticket 双内核 | A 层 OKR 节点 | Mandate=objective/criteria 直译;**Budgets 资源账单补我们预算契约空白**(token/时间/成本上限+扣减) | SPEC#2 P0 |
| F4 | Router 批处理(1.6s/决策) | L1 批合并+冷却窗口 | 复用开仓冷却同构机制;我们 L1 零 token,批处理只为**削峰**而非省费 | SPEC#3 P0 |
| F5 | Inline & Spill 引用链 | L0 fetchContext | 把 Trigger/Thread 引用作为**第七维**挂进现有六维供给,不另起上下文系统 | SPEC#3 P1 |
| F6 | 投机执行 | L1 预判预取 | 事件到达时 L1 零 token **预取 L0 上下文**(投机取数),升级 L2 时零等待;预取未命中则静默丢弃(对齐其"没找到结果就保持安静") | SPEC#3 P1 |
| F7 | Watchdog 独立监督 | C-drive 反思器外化 | 反思器语义从链内提取为独立巡查会话,巡查 L2 执行;**判定标准复用 A 层 verify 分派表** | SPEC#2 P2 |
| F8 | 三级状态生命周期 | A 层 OKR 节点状态机 | live/paused/waitsForPerson/ended 四态嫁接到 OKR 节点;waitsForPerson 接飞书通知(**注意力预算落地到我们的 IM**) | SPEC#2 P1 |
| F9 | Store 持久化 | L0 PG | 它的 Store 仅作运行时缓存,持久态统一落 L0——**状态层不新建**(P3 红线) | SPEC#2 P0 |
| F10 | 24h 在线/离线续跑 | 本地 daemon 化 | 37-一键启动分层管理已有雏形;会话级续跑为缺口,**先抄它的断点重连协议**再内化 | 后续 SPEC |

**巧妙之处集中在三点**:① F5/F6 **复用我们已有机制**(fetchContext/L0 信封),它的思想做"触发器",我们的机制做"执行体"(F2 直通判据经评审修正为独立设计);② F3 它的 Ticket 恰好**双向填空**——它补我们预算契约,我们补它验收标准;③ F9 状态层合一,避免融合最常见的"两套状态腐烂"病。

## 七、后续调研深化:广义认知框架护城河(用户定调 2026-11-02)

**判断:C1-C4 四层实质具备进化潜质,本质是完整广义认知框架,是我们的护城河,需着重调研深化。**

权威口径(35 号域 SPEC-CognitiveSystem-Evolution v0.2,已开发完成 P0-P3 24/24):

| 层 | 内容 | 进化潜质 |
| --- | --- | --- |
| C1 基础层 | 五系统:认知(4-MEMORY)+SKILL管理+知识库(2-K)+文档管理+索引,+33-REA/PoE/ReverseDeriver | 骨架已接通 |
| C2 记忆层 | 三层记忆(working/recall/archival)+双时序知识图+ACT-R 激活+FSRS 遗忘+Evidence Ledger | 类脑记忆动力学 |

| C4 元认知 | GWT Workspace Bus 全局广播等(当前为研究探索项) | 自我意识雏形 |

对 Super-agent 的意义:它完全没有等价物(其"记忆"只是会话引用链)。**融合越深,护城河越厚**——它的事件驱动骨架最终是给我们认知框架"喂事件"的入口。

调研深化方向(后续单独立项):
1. C4 元认知从研究探索项升级为工程项的路径(GWT bus ↔ Watchdog 外化天然契合);
2. 调研知识线:REA 逆向解析 + 做梦器路径寻优训练的 settle 通道设计;
3. PoE 信任传递 × 45 Evidence Bundle 的统一证据理论;
4. 预测编码在事件网关价值分预估中的应用。
